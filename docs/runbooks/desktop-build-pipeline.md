# Runbook: Desktop build pipeline (Android APK on `droid` → Pixel 6 Pro)

**Why this exists.** This Linux box cannot build Android APKs (2012 Ivy Bridge CPU; no
local emulator either). All Android builds run on the owner's Windows desktop **`droid`**
over SSH/Tailscale, and the APK is installed on the wired **Pixel 6 Pro**. This runbook is
the proven procedure — **do not improvise a different pipeline.** It was proven end-to-end
for FND-01 (plan 01-05).

> Transport is **rsync/scp/tar-over-ssh — NEVER `git push`** (global deny; CLAUDE.md).
> Source only; the build host runs `npm ci` + `expo prebuild` itself.

## 1. One-time FND-01 standalone proof (RELEASE APK, embedded JS bundle)

A `release` APK embeds the JS bundle at build time, so it launches **standalone** with no
Metro / `adb reverse` — the cleanest "it installs and opens" evidence, with this Linux box
removed from the runtime path. (A `debug` APK ships NO bundle and shows the RN
"could not connect to development server" red screen without Metro — see §2 and
quest-board `apps/mobile/ANDROID_BUILD_GUIDE.md:213-222`.)

### 1a. Probe transport + classify the destination (before any sync)

```bash
# Does droid have rsync? (It does NOT — recorded here; the answer drives the transport.)
ssh -o BatchMode=yes droid 'rsync --version'      # -> "not recognized" ⇒ use tar-over-ssh

# Classify the destination so a sync never clobbers the wrong tree:
ssh -o BatchMode=yes droid 'if exist "C:\Users\bwales\projects\orbit-app" (dir /b "C:\Users\bwales\projects\orbit-app") else (echo __ABSENT__)'
```

- **ABSENT or EMPTY** → first-ever sync → create the dir and proceed (nothing to clobber).
- **NON-EMPTY** → assert a repo marker (`HANDOFF.md` or `package.json`) is present. Marker
  found ⇒ proceed. **NON-EMPTY and UNMARKED ⇒ STOP and ask the owner** (never sync onto a
  populated tree that is not this repo).

> **If `rsync` were present** the receiver + Windows-path form MUST be proven with a
> non-destructive dry-run BEFORE the first `--delete` mirror, trying both path forms:
> `rsync -az --dry-run --exclude node_modules --exclude android --exclude ios --exclude .git --exclude .expo ./ droid:'C:\Users\bwales\projects\orbit-app/'`
> (native form) vs `droid:/cygdrive/c/Users/bwales/projects/orbit-app/` (Cygwin/MSYS form).
> Use the form that connects and prints a plausible plan; that exact form goes in every later
> `rsync`. On this host rsync is absent, so we use tar-over-ssh (below), which is source-only
> and does **not** mirror-delete — the `--delete` bootstrap-marker risk does not apply.

### 1b. Transport source → droid (tar-over-ssh; source only)

For a guaranteed-clean tree, wipe + recreate the dest first (safe: marker-confirmed as this
repo, on the owner's own machine). `node_modules` and `android/` are **excluded** — native
binaries differ per-OS and `android/` is regenerated by prebuild.

```bash
DEST='C:\Users\bwales\projects\orbit-app'
ssh -o BatchMode=yes droid "rmdir /s /q \"$DEST\" & mkdir \"$DEST\""     # optional clean reset

tar -czf - \
  --exclude=./node_modules --exclude=./android --exclude=./ios \
  --exclude=./.git --exclude=./.expo --exclude=./.planning \
  . | ssh -o BatchMode=yes droid "tar -xzf - -C \"$DEST\""
```

(`scp -r` of the source tree is an equally valid source-only fallback. Both are NEVER
`git push`. For an incremental re-sync of just changed files, re-run the same `tar` pipe
without the `rmdir` — extraction overwrites the archived files and leaves `node_modules`/
`android` intact.)

### 1c. Build on droid (cmd.exe; flat repo — no monorepo subdir, no patch-build-gradle)

```bash
DEST='C:\Users\bwales\projects\orbit-app'

# npm ci — installs the EXACT rsync'd package-lock.json tree (NOT npm install; no drift).
ssh -o BatchMode=yes droid "cd /d \"$DEST\" & npm ci"

# Prebuild: regenerates android/ from app.config.ts.
#   FIRST run: android/ does not exist yet ⇒ --clean is a harmless no-op.
#   LATER runs: android/ exists ⇒ --clean PROMPTS to overwrite, and over non-TTY SSH that
#   prompt HANGS. Run it non-interactively with  set "CI=1"  (see gotcha below).
ssh -o BatchMode=yes droid "cd /d \"$DEST\" & set \"CI=1\" & npx expo prebuild --platform android --clean --no-install"

# Standalone RELEASE build (Windows batch script). APK embeds the JS bundle.
ssh -o BatchMode=yes droid "cd /d \"$DEST\\android\" & gradlew.bat assembleRelease --console=plain"
# -> BUILD SUCCESSFUL ; artifact: android\app\build\outputs\apk\release\app-release.apk
```

> **Gotcha — `set CI=1 &` captures a trailing space.** `set CI=1 & cmd` sets `CI` to `"1 "`
> (with the space), and Expo's `getenv` then throws `GetEnv.NoBoolean: 1  is not a boolean`.
> Always quote: **`set "CI=1"`** (no trailing space). `yes | npx expo prebuild …` is not
> available on cmd.exe; use the quoted `set` form.

Release signing: `assembleRelease` on an Expo-prebuilt project is signed by the
prebuild-generated **debug keystore** by default, so it installs with no extra keystore
setup. (Production signing is a separate, later concern.)

### 1d. Pull the APK back (scp; forward-slash remote path)

```bash
scp -o BatchMode=yes \
  "droid:C:/Users/bwales/projects/orbit-app/android/app/build/outputs/apk/release/app-release.apk" \
  ./app-release.apk
```

(OpenSSH `scp` on Windows accepts forward slashes; this avoids the `C:` being read as a host
separator.)

### 1e. Install on the physical Pixel + assert the themed shell

```bash
emu-connect                       # picks the phone if attached, else the desktop emulator
~/.local/bin/adb devices -l       # READ the serial here — never hardcode emulator-5554
S=1A071FDEE002BU                  # the Pixel 6 Pro (resolve yours from the line above)

~/.local/bin/adb -s $S install -r ./app-release.apk        # -> Success  (no adb reverse needed)
~/.local/bin/adb -s $S shell monkey -p com.bwales.orbit -c android.intent.category.LAUNCHER 1
~/.local/bin/adb -s $S shell sleep 5

# Assert the rendered shell (NOT the red "could not connect" screen):
~/.local/bin/adb -s $S shell uiautomator dump /sdcard/ui.xml
~/.local/bin/adb -s $S pull /sdcard/ui.xml ./ui.xml
grep -q 'Orbit' ./ui.xml && echo "PASS: Orbit title rendered"     # PRIMARY assertion
grep -q 'home-shell-root' ./ui.xml && echo "home-shell-root present"  # SECONDARY (a11y-tree
                                                                      # pruning can drop testIDs;
                                                                      # the visible title is the
                                                                      # reliable gate)
~/.local/bin/adb -s $S shell pm list packages | grep com.bwales.orbit
~/.local/bin/adb -s $S exec-out screencap -p > ./orbit-home.png   # visual evidence
```

**FND-01 pass criteria:** the app opens to the themed Orbit home shell (space-dark
background + "Orbit" title + "Your people, in orbit." subtitle, all from theme tokens) on the
**physical Pixel** — not the red screen. Confirmed 2026-08-14.

**Emulator = weaker smoke test only.** If the Pixel is unavailable, run the SAME build on
droid and `adb install` the APK **on droid** directly onto the desktop emulator (per
`ANDROID_BUILD_GUIDE.md:179`, do NOT `adb install` from this Linux box over the emu-connect
tunnel). That is a launch-only smoke test (no perf/native-render claims) and **does NOT close
FND-01** — FND-01 stays OPEN until the physical Pixel proof.

## 2. Day-to-day DEBUG + Metro iteration loop (later phases)

For iterating on JS/UI, a debug APK + live Metro is faster than rebuilding a release APK.

```bash
# One-time (or when native deps change): build + install the DEBUG APK.
ssh -o BatchMode=yes droid "cd /d \"C:\\Users\\bwales\\projects\\orbit-app\\android\" & gradlew.bat assembleDebug --console=plain"
scp -o BatchMode=yes "droid:C:/Users/bwales/projects/orbit-app/android/app/build/outputs/apk/debug/app-debug.apk" ./app-debug.apk
~/.local/bin/adb -s $S install -r ./app-debug.apk

# Every session: Metro runs on THIS box; the phone reaches it via adb reverse.
npx expo start                                   # Metro bundler on this box (port 8081)
~/.local/bin/adb -s $S reverse tcp:8081 tcp:8081 # phone -> this box; RESET after reboot/replug
```

- **A debug APK needs Metro live or it shows the RN "could not connect to development server"
  red screen** (`ANDROID_BUILD_GUIDE.md:213-222`). Start Metro + set `adb reverse` before
  launching.
- **Rebuild rule:** if `app.config.ts`, `package.json`, or **any native dep** changed →
  re-run `npx expo prebuild --platform android --clean --no-install` (with `set "CI=1"`) then
  `assembleDebug`. **JS-only changes need no rebuild** once Metro is live — fast-refresh
  handles them.
- `adb reverse` does **not** survive a device reboot, an emulator restart, or **replugging
  the USB cable** — re-run `emu-connect` and the `adb reverse` line when anything looks
  disconnected.

## 3. Caveats

1. **The `app-release.apk` is NOT `run-as`-debuggable.** CLAUDE.md's data-layer inspection
   (`adb exec-out "run-as com.bwales.orbit cat /data/data/…"`) works **only on a DEBUG APK**.
   The release APK is the standalone launch proof only. Any on-device DB/data inspection in
   later phases must use the `assembleDebug` + Metro build.
2. **`adb` / `emu-connect` are not in the allow-list** (`.claude/settings.local.json` allows
   `rsync`/`scp`/`ssh` only). Outside YOLO mode they prompt at the human checkpoint; the owner
   approves. Do not silence this by editing settings — owner's call.

## 4. Build gotchas discovered while proving FND-01 (fixed in-repo; documented so they don't recur)

These were latent since the scaffold and only surfaced at the **first real metro bundle**
(tsc/vitest/biome never invoke metro):

- **`babel-preset-expo` must be a direct devDependency.** `babel.config.js` references it as
  a top-level preset, but it installed only nested under `expo/node_modules` and never
  hoisted, so it did not resolve from the project root — `expo export:embed` (the
  `createBundleReleaseJsAndAssets` gradle task) failed with `Cannot find module
  'babel-preset-expo'`. Fixed by declaring `babel-preset-expo: ~57.0.7` (expo's own range) in
  `package.json`.
- **`app.config.ts` must not pull in the `tsx/cjs` global loader hook.** Importing a `.ts`
  runtime module from the config forced `import "tsx/cjs"`, whose global
  `Module._resolveFilename` patch then broke metro's own `require('babel-preset-expo')` during
  the embedded bundle. Fixed by making the display name a **JSON single-source**
  (`src/constants/app-name.json`) that Node/Expo, metro, and tsc all load natively — no hook.
  `src/constants/app.ts` re-exports `APP_NAME` (typed) for the app; `app.config.ts` imports
  the JSON directly.

**Rename the app** = one-line edit in `src/constants/app-name.json` (`APP_NAME`). It is
**decoupled** from `android.package` (`com.bwales.orbit`), which is install-locked and must
not track the display name.
