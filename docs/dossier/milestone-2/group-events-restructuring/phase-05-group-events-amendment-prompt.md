# Phase 5 — Dashboard Control Surface
## Group Events Amendment Brief + Paste-Ready Session Prompt

## Why Phase 5 needs amendment

A newer, fully settled **Phase 12 — Group Interaction Logging** subsystem has elevated Group Events from a Dashboard-overflow management destination into a first-class Orbit feature.

Phase 5 currently gives **Your Week** the only first-class Dashboard-header destination and keeps other management routes in overflow. That contract is now materially incomplete.

## Required amendment

### Dashboard header

Add a prominent **Group Events** entry to the Dashboard header using the same high-level discoverability tier as Your Week:

- icon + short label when space permits,
- icon-only fallback when responsive constraints require it,
- semantic icon registry + accessible name,
- canonical route to the Phase 12 Group Events browse/management page.

This does **not** mean Group Events becomes a permanent Dashboard content module.

### Dashboard overflow

Keep **Group Events** in Dashboard overflow as a redundant discovery/management route.

### Navigation boundary

For this milestone:

- Group Events does **not** receive a permanent bottom-nav destination,
- the Dashboard bottom-nav tab does **not** become a radial/menu launcher,
- the current Dashboard is not renamed/rebuilt into Mission Control,
- Phase 5 does not own Group Event browse-page contents or Group Log domain behavior.

Those larger shell/IA ideas are explicitly deferred.

### Header composition implication

Phase 5 should revisit only enough header composition to support both high-priority Dashboard-owned destinations cleanly:

- Your Week
- Group Events

Do not reopen Population / Filters / Sort, Search/List-Card layout, or unrelated Dashboard control decisions unless the two header actions expose a real responsive conflict.
