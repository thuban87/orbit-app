<objective>
Build the launch-sweep skeleton (DATA-06): a `runLaunchSweep()` + `registerSweepHook()` registry that
runs once per REAL foreground launch — cold start and every RN `AppState` background→active transition
— and NEVER on module import or a headless widget/notification tap (which load the JS bundle inside a
30-second budget). Phase 2 ships the runner and an EMPTY registry; Phases 3/4/11/15/16 register their
responsibilities later. Then wire `App.tsx` to gate first render on `openAndMigrate()` and install the
sweep trigger from an effect.

The pure sweep logic takes `AppState` by dependency injection so the whole module is node-testable
(and so `App.tsx` owns the one react-native import). The load-bearing rule is negative: importing the
module must do nothing, and a headless tap must never reach the sweep.

Purpose: one sweep entry point, correctly gated, that later phases hang responsibilities on.
Output: `src/services/launch-sweep.ts`, its test, and the App.tsx wiring.
</objective>
