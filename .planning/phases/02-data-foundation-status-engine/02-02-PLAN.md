## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app code → SQLite schema/seeds | Migration DDL defines the permanent data model on unreachable devices |
| OS sandbox → DB file | Third-party PII (phone/email/notes about others) lives in the app-private SQLite file |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-03 | Tampering / integrity | ON DELETE CASCADE foreign keys | high | mitigate | `PRAGMA foreign_keys=ON` set in bootstrap BEFORE any transaction (P1); every child FK declares ON DELETE CASCADE so a contact delete removes children — asserted node-side (Task 2) and on-device (Plan 06). |
| T-02-04 | Tampering (SQL injection) | seed INSERTs | low | mitigate | Seed values bound with `?`; category names + display_order are code literals, uid via newUid(), timestamps via formatLocalDate() — no user input at migration time. |
| T-02-05 | Denial of service | indexing contact_custom_values | medium | mitigate | No index/UNIQUE on any VALUE column (would break Phase-3 DROP COLUMN quarantine expiry) — the ban is VALUE-column-scoped (HANDOFF §14.11), so the merge-key `uid` UNIQUE autoindex is exempt and correct; enforced by the value-column-scoped PRAGMA index_list assertion in Task 2. |
| T-02-SC | Tampering (supply chain) | npm/pip/cargo installs | low | accept | No package installs — uid is dependency-free; expo-sqlite pre-exists. No `[ASSUMED]`/`[SUS]` packages. |
</threat_model>
