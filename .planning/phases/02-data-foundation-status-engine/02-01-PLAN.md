<objective>
Build the crash-safe `PRAGMA user_version` migration runner (DATA-01) and the node-side
SQL test harness that every later Phase-2 plan verifies against.

This is the irreversible-safety core: on unreachable devices a half-applied migration wedges the
install permanently, so the runner must advance `user_version` and its DDL in one atomic step and
re-throw the ORIGINAL error on failure. The runner is written against a tiny `SqlExecutor` interface
(not the expo API directly) so its control flow is unit-testable node-side with `node:sqlite`.

Purpose: get the three verified platform hazards right once, in code the rest of the phase reuses.
Output: `src/db/types.ts`, `src/db/migrations/runner.ts`, the `node:sqlite` testkit, the runner test,
and a `test` script in package.json.
</objective>

    Implement RESEARCH §Code Example 1's loop against `SqlExecutor` (not the expo db): read current
    `user_version` via `getFirstAsync`, sort migrations ascending by version, then for each pending
    version up to targetVersion run a HAND-ROLLED transaction — `execAsync('BEGIN')`; inside a try call
    `migration.apply(exec, deps)` then `execAsync('PRAGMA user_version = ' + next)` (integer literal,
