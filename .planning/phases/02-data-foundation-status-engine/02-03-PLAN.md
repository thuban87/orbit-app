<objective>
Build the single-writer recency spine (DATA-04): the ONLY module that writes `contacts.last_contact`,
recomputing it as `MAX(occurred_at)` over the contact's current interaction rows after every
insert/edit/delete, inside a hand-rolled transaction, behind a module-level promise-chain mutex shared
with the headless widget/notification writers that arrive in Phases 11/12.

The invariant is load-bearing across the whole project (ROADMAP cross-phase constraint). Two subtle
correctness rules: recompute is a MAX over CURRENT rows (last-write-wins on the touched row is wrong —
correcting a non-newest row must not move recency), and for "Rarely responds" contacts the MAX is over
CONNECTED rows only. The mutex prevents transaction capture — a headless write landing inside a
foreground transaction and being rolled back with it.

Purpose: one correct, serialized recency writer every touchpoint route reuses.
Output: `src/db/mutex.ts`, `src/db/recency-dao.ts`, and their tests.
</objective>
