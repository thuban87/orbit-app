# Phase 25 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase nature: this is a NONVISUAL state/query foundation.** Phase 25 owns the shared Dashboard
query/state engine (populations, filters, sort, scoped semantic search, dedupe, persistence,
navigation-state restoration). The visual RENDERING of results lives in Phase 26 (Control Surface),
Phase 27 (List View), and Phase 28 (Card View). This UI-SPEC therefore locks only the contracts those
render phases *bind to*:

- **State-shape contracts** — the empty / loading / error states each population and query produces,
  shared semantically across List and Card.
- **Copywriting contract** — population/filter/sort labels, empty-state and error-state copy, the
  search match-explanation / snippet presentation contract, and settings labels this phase introduces
  or retires.
- **Search-result presentation contract** — the match-descriptor data shape renderers bind to
  (prioritized highlighted snippets + `+N more`), and relevance-primary ordering while search is active.

Where a contract is genuinely owned by a downstream render phase (row/card composition, status ring vs
border treatment, snippet visual styling, swipe actions), it is explicitly deferred below — no List/Card
visual styling is invented here.

## Design System

Established in Phase 23 (theme-visual-system) and Phase 22 (app shell). This phase invents **no new
tokens** — it references the existing system. All colours resolve through `useTheme().colors.*`; no
hardcoded colour literals anywhere (project non-negotiable, enforced by `npm run check:colors`).

| Property | Value |
|----------|-------|
| Tool | none (React Native / Expo — shadcn is web-only, not applicable; no `components.json`) |
| Preset | not applicable |
| Component library | none (bespoke RN primitives + centralized semantic icon registry, Phase 22/23) |
| Icon library | project semantic icon registry (Phase 23) — glyphs referenced by semantic name, never raw |
| Font | Space Grotesk (display/heading) + Inter (body/label/caption), loaded via `AppText` |
| Theme axes | Package (Galaxy / Standard) × Mode (Light / Dark / Follow System) — independent axes |

**Portrait-locked, Android-first. Reduced-motion-aware. The Dashboard read path is offline —
no blocking network call on any read (local-first, non-negotiable).**

## Typography

Existing `TYPOGRAPHY` roles (`src/theme/tokens/typography.ts`): 5 semantic roles over exactly **4 sizes**
(28 / 20 / 16 / 14) and exactly **2 weights** (Regular 400, SemiBold 600). Screens consume roles, never
raw sizes. This phase adds no new roles.

| Role | Size | Weight | Line Height | Colour token |
|------|------|--------|-------------|--------------|
| Display | 28px | 600 | 34 (1.2) | textPrimary |
| Heading | 20px | 600 | 25 (1.25) | textPrimary |
| Body | 16px | 400 | 24 (1.5) | textPrimary |
| Label | 14px | 600 | 20 (1.4) | textPrimary |
| Caption | 14px | 400 | 20 (1.4) | textSecondary |

Contract for render phases: empty-state headings use **Heading**; empty/error bodies and `+N more` use
**Caption** or **Body**; population/filter/sort chip labels use **Label**. Text must reflow under OS
scaling (line heights are absolute px, not clamps).

## Color

No new tokens. Relevant existing tokens (all in `ThemePalette`, `src/theme/theme-types.ts`):

| Role | Token | Usage in this phase's contracts |
|------|-------|--------------------------------|
| Dominant (60%) | `background` | Dashboard surface |
| Secondary (30%) | `surface` / `surfaceElevated` | Rows/cards/controls (render phases) |
| Accent (10%) | `accent` / `onAccent` / `accentText` | Active chip fill, primary CTA, search-highlight emphasis pairing |
| Destructive | `danger` / `onDanger` | Not used by this phase (no destructive action here) |
| Status (state, not action) | `statusStable` / `statusWobble` / `statusDecay` / `rogue` | Consumed by render phases for status; never by this foundation |
| Never-contacted | neutral (`textSecondary` / `border` opacity, no status hue) | Not-Contacted / All-Contacts never-contacted rows read NEUTRAL |

Accent reserved for: active population/filter/sort selection (filled-accent chip idiom), the primary
empty-state CTA ("Add your first contact"), the pull-to-refresh spinner tint, and search-match highlight
emphasis. **Never** applied to all interactive elements.

**Colour-alone is prohibited (project + dossier §P):** every state this phase defines must carry a
**redundant non-colour channel** the render phases honour — a status glyph + same-weight border (never a
bare colour band), a text label, and an `accessibilityLabel`. Search highlight must pair colour with a
second channel (weight/underline), not colour alone. Snoozed neutralizes visible health treatment
(a state, signalled structurally). This is an exported constraint on Phases 26–28, verified there.

### Empty states — cause-aware (shared across List & Card)

The empty-state gate (`src/logic/dashboard-empty-logic.ts`) resolves ONE cause by explicit precedence:
`rowCount>0 → none` → `hasTerm → search-empty` → `activeFilter≠default → filter-empty` → population fallback
(`firstrun` vs `hidden`). This phase EXTENDS that gate from the old filter enum to the population model;
per-population empties below are new and must fold into the same single gate (no parallel arithmetic in
render screens).

| Cause | Heading | Body / next step |
|-------|---------|------------------|
| First run (all populations empty) | — | Primary CTA: `Add your first contact` |
| Hidden (people exist only in hidden buckets) | `Everyone's tucked away` | `{N} not yet contacted →` · `{N} snoozed` · `{N} archived` (only non-zero lines) |
| Search-empty | — | `No matches for "{term}"` |
| Filter-empty — Favourites | `No favourites yet` | `Tap the star on a contact's profile to add them here.` |
| Filter-empty — generic (category / battery / needs-attention) | — | `Nothing here right now.` |
| Population empty — Birthdays *(default — owner confirm)* | `No birthdays coming up` | `No birthdays in the next 30 days.` |
| Population empty — Not Contacted *(default — owner confirm)* | `Everyone's been contacted` | `No one is waiting for a first interaction.` |
| Population empty — Snoozed *(default — owner confirm)* | `Nothing snoozed` | `Snoozed contacts stay out of Needs Attention until their snooze ends.` |
| Population empty — Active (has hidden-bucket people) | reuses `Everyone's tucked away` | (as Hidden above) |

## Search-Result Presentation Contract

The shared result model carries, per deduplicated contact, a stable presentation shape both renderers
bind to (dossier §K–L, §O). Exact numeric scoring weights are Claude's discretion (tuned with fixtures);
the *shape and ordering rules* below are authoritative.

**Per-result descriptor shape (data contract, not styling):**
- `contactId`
- opaque relevance `score` (ordering only; not user-visible)
- `matches`: ordered array of match descriptors, each with:
  - `sourceKind` — one of `identity` | `relationship` | `memory-or-custom-field` | `note-or-body`
  - user-facing `fieldLabel` (e.g. "Name", "Memory", relationship label) sourced from semantic
    knowledge metadata, not a Dashboard-only hardcoded list
  - `snippet` text
  - `highlights`: ranges `{start, length}` into `snippet` marking matched substrings
  - `priority` rank
- `totalMatchCount`

**Ordering / selection rules (locked):**
- Up to **three** highest-priority match descriptors are surfaced; the remainder collapse to `+{N} more`.
- Priority order: `identity` → `relationship` → `memory-or-custom-field` → `note-or-body`.
- A direct name/identity match does **not** suppress useful secondary knowledge matches.
- While search is active, **relevance is the primary order**; the current Dashboard sort is only a
  tie-breaker. Term coverage ranks a contact matching more query terms above one matching fewer; exact
  identity/name matches get strong priority.
- Search is scoped to the current **Population + Filters** universe; it never surfaces Archived or
  Unbound contacts.

**Deferred to render phases (26/27/28):** the visual treatment of highlights and snippets, how the
match-explanation replaces the row's normal secondary content, and card-vs-row snippet density. This
phase defines only the data the renderers consume. Highlight rendering must use a non-colour channel in
addition to colour (see Color section).

## Notes for Planner / Executor (foundation-specific trip-wires)

These are recorded decisions the render phases and this phase must not silently reverse (owner's bucket
if they must change — flag as BLOCKER, do not "fix"):

- **Favourites are binary membership (ADR-075).** No ranked-favourites UX, no sort by `favourite_rank`;
  the Favourites population renders in Default order. Do **not** drop the `favourite_rank` column without
  a decided fate for its picker/sun/merge/widget reads.
- **Active excludes never-contacted (ADR-011).** Keep `BASE_WHERE`; build `All Contacts` as an explicit
  `Active ∪ Not Contacted` union — never by weakening `BASE_WHERE`.
- **Birthdays via population only (ADR-076).** No permanent Dashboard banner/module; the 30-day Birthday
  population + entry point is the whole Dashboard surface. If Your Week is still unplanned, note the
  coverage gap — don't silently drop the surface.
- **Unbound retrieval must survive (ADR-062, R-11).** Removing Unbound from Dashboard search requires a
  replacement retrieval path (Unbound child-route search or picker explicit-search), coordinated with
  Phase 26's R-11. Removing it without a replacement is a trip-wire, not a cleanup.
- **No FTS5 / no new index (ADR-031, D-08).** Typo tolerance = TS scoring (prefix/substring + edit
  distance ≤ 1 per term, ≤ 2 for 6+ char terms) over the already-filtered eligible set. FTS5 would
  reverse ADR-031 → stop and ask.
- **Durable prefs live in `app_settings` columns**, added to `PORTABLE_SETTINGS_KEYS` (population
  multi-select, view mode, sort mode incl. Default-vs-explicit) — never AsyncStorage. Search text,
  scroll, and session nav-state are ephemeral (do not persist across fresh launch); Dashboard→Profile→Back
  restores the working session including search/scroll.
