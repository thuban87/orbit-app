<objective>
Tracer slice for Phase 25. Prove the whole nonvisual foundation's vertical architecture on ONE path before any expansion: land the durable-preference migration (019), and prove that a single durable axis persists through the app-settings DAO, hydrates into the shared query-state store, drives the pure query-logic to resolve the Active universe (the three ADR-011 segregation clauses, snooze-clause excluded per D-12), and returns rows from a new additive dashboard-read entry — end-to-end, with passing node:sqlite tests.

Purpose: Migration 019 is a one-way door (irreversible in production; no server, no remote DB, no backup). Proving the schema→DAO→store→query contract on the tracer's best early-context tokens catches an architectural dead-end after one commit instead of after all six populations, five filter families, sort, and search are already built on top of it.

Output: migration 019 (+ TARGET_VERSION=19), the four `app_settings` dashboard-pref columns wired into the DAO accessor/patch/validation with PORTABLE_SETTINGS_KEYS allowlisting (emission deferred), `dashboard-query-logic.ts` (population/sort model with the Active predicate + Default resolution + Reset transition), `dashboard-query-store.ts` (the four durable axes mirrored to `app_settings`), and a new additive `dashboard-read` population entry returning the Active universe.
</objective>

<assumption_delta_decision>
This phase makes a singular→plural transition: the app moves from a single active population (legacy `orbit-dashboard-prefs` single filter+sort) to a **multi-select OR-union population set** with a **population-aware Default sort**, read by BOTH the List and Card renderers.

- **Now-primary noun:** the shared **Dashboard query state** (`DashboardQueryState` — the population SET + filters + sort + view mode), owned by `dashboard-query-store.ts` and mirrored to `app_settings`.
- **Decision:** PROMOTE — one shared durable query state that both views read (per D-10; the query architecture is NOT coupled to exactly two renderers).
- **Rationale:** a single source of truth for the eligible universe keeps List/Card from drifting into separate population/filter/sort selections and lets each axis be independently cleared + globally reset (Reset Dashboard View).
</assumption_delta_decision>
