<objective>
Wire the built-but-unwired Phase 24.2 knowledge search into a scoped, descriptor-emitting Dashboard search: scope the corpus read to the eligible id set (so archived/unbound never appear), reuse the existing typo-tolerant scorer, and add a pure module that turns matched entries into the UI-SPEC's match-descriptor shape (≤3 prioritized highlighted snippets + `+N more`, relevance-primary with the Dashboard sort as tie-breaker only).

Purpose: DASHQ-08/09/10 are the search half of the shared result model the render phases bind to. The scorer and corpus already implement D-08/D-09's matching exactly; the real work is (a) scoping the corpus to eligible ids and (b) emitting descriptors the scorer does not yet produce — NOT re-implementing scoring, and NOT adding any index.

Output: `knowledge-search-read.ts` gains an eligible-id scope; `knowledge-search.ts` emits per-entry match info; `dashboard-search-match.ts` (new, pure) builds descriptors + composes the scoped search over an eligible-id set.
</objective>
