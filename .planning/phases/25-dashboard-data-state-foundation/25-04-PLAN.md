<objective>
Wire the built-but-unwired Phase 24.2 knowledge search into a scoped, descriptor-emitting Dashboard search: scope the corpus read to the eligible id set (so archived/unbound never appear), reuse the existing typo-tolerant scorer, and add a pure module that turns matched entries into the UI-SPEC's match-descriptor shape (≤3 prioritized highlighted snippets + `+N more`, relevance-primary with the Dashboard sort as tie-breaker only).

Purpose: DASHQ-08/09/10 are the search half of the shared result model the render phases bind to. The scorer implements D-08/D-09's matching; the real work is (a) scoping the corpus to eligible ids, (b) COMPLETING the corpus to the §J first-class fields sourced from the correct tables (phone/email from `contact_methods`, not the removed `contacts` columns), (c) WIDENING entry provenance (memory type + part; relationship relation_type + note) and adding an offset-preserving match surface so the descriptor's sourceKind/fieldLabel/highlights are buildable in this foundation, and (d) emitting descriptors — NOT re-implementing scoring, and NOT adding any index (ADR-031 / D-08).

Output: `knowledge-search-read.ts` gains an eligible-id scope + completed/widened corpus; `knowledge-search.ts` emits per-entry match info + raw-text offsets + a coverage-aware aggregator; `dashboard-search-match.ts` (new, pure) builds descriptors + composes the scoped search over an eligible-id set.
</objective>
