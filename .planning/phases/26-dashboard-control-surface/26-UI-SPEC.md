# Phase 26 — UI Design Contract

> Visual and interaction contract for the Dashboard Control Surface. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.

**Platform note (carried from Phases 22/23/25):** orbit-app is React Native / Expo, Android-first,
local-first, portrait-locked. There is **no shadcn / no Tailwind / no web DOM** — the shadcn gate and
the registry gate are N/A. The design system is the on-disk **theme-token** system in `src/theme/`
(CLAUDE.md: *all* colours resolve through `useTheme().colors.*`; `theme-presets.ts` is the single file
where a hex may appear, incl. inside Skia; `npm run check:colors` enforces it). This phase invents
**no new tokens** — it references the Phase 23 primitives and renders the Phase 25 query state.

**Scope reminder (CONTEXT D-01…D-11 / dossier):** Phase 26 owns the Dashboard's **visible control
shell** — top hierarchy, the Population/Filters/Sort control row and its anchored floating panels
(live-apply), header destinations (Your Week **and** Group Events at one tier), the collapsible search +
List/Card toggle row, the Dashboard overflow, and the **refactor** of the existing Archived/Unbound
management screens into origin-aware Dashboard child routes. It does **not** own query/filter/sort/search
*semantics* (Phase 25), List row composition (Phase 27), Card grid composition (Phase 28), Group Event
domain behavior (Phase 33 Group Logging), or bulk mutations (Phase 28). No migration of its own (D-03).

## Design System

Established in Phase 22 (shell), Phase 23 (theme/tokens/icon registry/status glyphs), Phase 25 (query
state). This phase adds **no** tokens, fonts, or icon dependencies.

| Property | Value |
|----------|-------|
| Tool | none (React Native / Expo — shadcn is web-only; no `components.json`) |
| Preset | not applicable |
| Component library | none — hand-built RN primitives (`Pressable`, `Modal`/`BaseOverlay`, `FlatList`, Reanimated) over theme tokens; **one new** reusable `AnchoredPanel` control-surface primitive (below) |
| Icon library | project **semantic icon registry** (`src/components/icons/icon-registry.ts`) — Ionicons via `@expo/vector-icons`, referenced by semantic name only, never a raw glyph. New semantic names this phase may need (`filter`, `swap-vertical`/`sort`, `list`, `grid`, `calendar`/`your-week`, `people`/`group-events`, `chevron-down`) are added **at the registry map only** (D-05 icon-registry rule) |
| Font | Space Grotesk (Display/Heading) + Inter (Body/Label/Caption), via `AppText`/theme roles |
| Theme axes | Package (Galaxy / Standard) × Mode (Light / Dark / Follow System) — panels honour both via the semantic surface API (`GlassSurface`), never a parallel per-theme component family (dossier §G) |

**Portrait-locked. Reduced-motion-aware (Phase 23 `useReducedMotion`). Offline read path — no blocking
network call on any Dashboard read (local-first, non-negotiable).**

## Spacing Scale

Existing `SPACING` tokens (`src/theme/tokens/spacing.ts`). All multiples of 4 except the intentional,
already-shipped `md = 12` (documented dense-row exception — not new here). This phase adds no values.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-label gap in header/control chips, summary inline gap |
| sm | 8px | Control-row inter-control gap, panel option gap, search↔toggle gap |
| md | 12px | Panel option-row inner padding, dense control padding |
| base | 16px | Screen gutters, panel content padding, control-row horizontal padding |
| lg | 24px | Separation between conceptual groups (control row ↔ search row ↔ collection) |
| xl | 32px | Major layout gaps |
| 2xl | 48px | Major section breaks |

Exceptions (established, not new):
- **Minimum touch target 44×44px** — a floor, not a spacing token. Every control-row trigger, panel
  option row, header destination, overflow row, search-toggle, and List/Card segment satisfies it (use
  `hitSlop` where the visual is smaller). Dossier §Q + Phase 22/23 precedent.
- **Bottom content clearance:** the Dashboard list clears the tab bar + safe area via
  `useBottomClearance()` — never hardcoded bottom padding (existing HomeScreen pattern).

## Typography

Existing `TYPOGRAPHY` roles (`src/theme/tokens/typography.ts`): 5 semantic roles over exactly **4 sizes**
(28 / 20 / 16 / 14) and exactly **2 weights** (Regular 400, SemiBold 600). No new roles.

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| Display | 28px | 600 | 1.2 | (not used — Dashboard root title is Heading-tier) |
| Heading | 20px | 600 | 1.25 | Dashboard root title ("Orbit"); child-route titles (Archived / Unbound); panel section headings where a heading is warranted |
| Body | 16px | 400 | 1.5 | Panel option-row labels; overflow row labels; management-route row names; search input text |
| Label | 14px | 600 | 1.4 | Control-row control labels (Population / Filters / Sort); active-state emphasis; List/Card segment labels; filter-family section labels |
| Caption | 14px | 400 | 1.4 (textSecondary) | Control summary text ("Active Contacts", "Family, Friends +2", "Default"); `+N` overflow; count headers; the `Unbound` marker; search placeholder |

Text must **reflow (wrap/grow/truncate-to-`+N`), never shrink below role size**, under OS font scaling
(THEME-07). Control summaries truncate to `+N` (dossier §C) rather than ellipsizing mid-word; header
destination labels fall back to **icon-only** rather than shrinking (D-04).

## Color

No new tokens. Relevant existing tokens (`ThemePalette`, `src/theme/theme-types.ts`), resolved via
`useTheme().colors.*`:

| Role | Token | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `background` | Dashboard surface; panel scrim (`background` at opacity — the codebase idiom, never a raw `rgba()`) |
| Secondary (30%) | `surface` / `surfaceElevated` | Control-row triggers, anchored-panel body (via `GlassSurface`: Galaxy glass-forward / Standard flat, §G), overflow sheet, management-route rows |
| Accent (10%) | `accent` / `onAccent` (`background` as on-accent per existing idiom) | **See reserved list** |
| Destructive | `danger` / `onDanger` | Only the pre-existing Archived-route "Delete permanently" purge (refactor preserves it verbatim — ADR-018 gate untouched). This phase introduces **no new** destructive action |
| Status (state, not action) | `statusStable`/`statusWobble`/`statusDecay`/`rogue` + status glyphs | Consumed only by the contact rows (Phase 27/28) — the control shell **never** repurposes a status hue for a control/nav affordance (Phase 22 rule) |

**Accent reserved for (explicit — never "all interactive elements"):**
- The **active/non-default** state of a Population/Filters/Sort control (restrained treatment — accent
  border or accent-tinted fill + accent label, dossier §C "restrained additional active visual
  treatment"); a control at its default reads neutral (`surface`/`border`/`textSecondary`).
- The **selected** option row inside a panel (filled-accent idiom `accent` fill + `background` label, or
  accent check-affordance — matching the shipped `FilterChipRow` active idiom).
- The **active** List/Card segment in the view toggle.
- The **primary empty-state CTA** ("Add your first contact") and the **pull-to-refresh** tint (existing).
- The **pressed/focused** state of a header destination (Your Week / Group Events).

**Not accent-driven:** ordinary control labels at rest, summaries, overflow rows, the search box border,
management-route chrome, the Group Events header glyph at rest (`textSecondary`).

**Colour-alone is prohibited (project + dossier §Q, inherited from Phase 25).** Every selected/active
state carries a **redundant non-colour channel**: a check/selected affordance or filled-vs-outline shape
on panel option rows, `accessibilityState={{ selected }}`/`{{ checked }}`, and a text label. The active
List/Card segment carries `accessibilityState.selected` + the filled icon variant, not colour alone.

## Control Row & Summary Contract (phase-specific — dossier §C)

Row 2 of the top hierarchy: **three equal controls in one row** — `Population`, `Filters`, `Sort` — each
a `Pressable` trigger that opens its own anchored panel (below). They are **visually and functionally
separate** (different query axes); they are **never** combined into a single "Manage View" modal
(dossier §C, [REJECTED]).

| Control | Label (Label role) | Summary source | testID (trigger) |
|---------|--------------------|----------------|------------------|
| Population | `Population` | current `populations[]` from `dashboard-query-store` | `dashboard-population-control` |
| Filters | `Filters` | current `filters{}` selections | `dashboard-filters-control` |
| Sort | `Sort` | current `sort` mode | `dashboard-sort-control` |

**Summary text rules (dossier §C):** each control shows its current state beneath/inside its label.
- Show meaningful names while they fit; collapse the overflow to **`+N`**.
- Population examples: `Active Contacts` (default, nothing selected) · `Favourites` · `Favourites, Birthdays` · `Favourites +2`.
- Filters examples: `Filters` (none) · `Family` · `Family, Friends +2`.
- Sort examples: `Default` · `Least recent` · `Name A–Z`.
- User-facing option labels are **Phase 25's Copywriting Contract** (Populations / Filter families /
  Social Battery / Sort options / Reset) — this phase does not re-author them, only renders them and the
  `+N` collapse. (British `Favourites` per Phase 25's locked spelling.)

**Active treatment:** a control whose axis is at its default reads neutral; a non-default control gets a
**restrained** active treatment (accent border or accent-tinted trigger + accent label + a non-colour
cue) — not a full filled-accent block (dossier §C). Exact accent/border/fill is theme-resolved.

## Anchored Floating Panel Pattern (phase-specific — dossier §D–H, THE core deliverable)

**One reusable primitive — `AnchoredPanel`** (working name) — with **size variants**, not three
unrelated popovers (dossier §D [DERIVED]). It is a **floating panel anchored to its invoking control**,
**not** a full-screen modal and **not** a bottom sheet (bottom-sheet variants are [REJECTED], dossier
§D / Deferred). It may reuse the `overlay-base` lifecycle (scrim tap-dismiss, Android Back, focus) but
is **top-anchored below the control row**, not bottom-anchored like `Sheet`/`Modal`.

| Variant | Consumer | Size (discretion — grounded in tokens) |
|---------|----------|----------------------------------------|
| compact | Sort | width ≥ anchor width, content-height, cap ~6 rows then scroll |
| medium | Population | ~ 280–300px wide, cap ~60% viewport height, scroll beyond |
| large | Filters | ~ 320px / near-gutter-to-gutter, cap ~70% viewport height, scroll beyond |

**Placement (discretion):** anchor top edge just below the control row; align the panel's leading edge to
the invoking control, **clamped** to the `base` (16px) safe horizontal gutter so it never bleeds off
screen in portrait. Corners `RADII.lg` (16). Surface via `GlassSurface` (Galaxy glass / Standard flat,
§G) — dense content → more opaque, readability wins. Scrim = `background` at opacity, theme-dependent
strength (§G: Galaxy subtler dim + glass; Standard quieter light scrim). Content behind the scrim stays
**readable** so live updates are perceptible.

**Live apply (dossier §E, locked):**
- Population / Filter / Sort changes apply **immediately** while the panel is open — **no Apply/Done**
  step. Do not add confirmation buttons unless on-device testing exposes a genuine a11y blocker.
- Dashboard results **remain visible and visibly update behind** the open panel.
- Underlying contact content is **interaction-inert** while a panel is open (no accidental navigation
  into a contact) **and removed from accessibility focus** (dossier §Q) — only panel + scrim are
  focusable.
- A live selection producing **zero results does not auto-close** the panel (§F); the collection behind
  shows the Phase 25 cause-aware empty state.

**Dismissal & switching (dossier §F, locked):**
- Tapping the **active** control again closes its panel.
- Tapping **outside** the panel dismisses it.
- **Android/system Back** dismisses the open panel **before** any route navigation (wire through the
  existing `shellTransientStore` / `resolveBackIntent` topmost-transient rule — the shell already owns
  this).
- With one panel open, tapping **another** control switches directly to that panel in one interaction.
- **Only one** Dashboard panel is open at a time.
- A reopened panel **begins at its top** (no restored transient scroll).

**Panel internals:**

*Population panel* (`dashboard-population-panel`) — tap the **row itself** to toggle (no conventional
checkbox chrome required, but a clear accessible selected treatment is required — §H). Rows:

| Row | Population key | testID | Notes |
|-----|----------------|--------|-------|
| All Contacts | `all-contacts` | `dashboard-population-option-all-contacts` | Selectable (D-07 / ADR-076) |
| Favourites | `favourites` | `dashboard-population-option-favourites` | binary membership (ADR-075) |
| Birthdays | `birthdays` | `dashboard-population-option-birthdays` | 30-day population; **no** permanent banner (ADR-076) |
| Not Contacted | `not-contacted` | `dashboard-population-option-not-contacted` | |
| Snoozed | `snoozed` | `dashboard-population-option-snoozed` | |

Active Contacts is the **implicit, unlisted default** (not a selectable row). Deselecting the **last**
explicit population immediately returns to Active Contacts (§H / D-07). No ranked-favourites affordance
anywhere (D-06 / ADR-075).

*Filters panel* (`dashboard-filters-panel`, largest) — one section per Phase 25 filter family
(`Category` · `Social Battery` · `Needs Attention` · `Gravity` · `Contact Frequency`), family label in
the Label role (`dashboard-filter-family-{family}`), options toggle live
(`dashboard-filter-option-{family}-{value}`), and a **Clear filters** affordance within the panel
(`dashboard-filters-clear`, §I). Detailed semantics are Phase 25's.

*Sort panel* (`dashboard-sort-panel`, compact) — the Phase 25 sort modes incl. an explicit **Default**
reset choice (`dashboard-sort-option-{mode}`, §J). Single-select.

## Presentation Seam — HUD Swappability (phase-specific — dossier §P, D-11, a design constraint)

Captured as a **hard architectural constraint**, not prose: separate three layers so a later branded
Orbit HUD replaces only the presentation container, with **zero** change to query behavior or
persistence (dossier §P [DERIVED]).

| Layer | Owner | Rule |
|-------|-------|------|
| 1. Query/state logic | Phase 25 (`dashboard-query-store`, `dashboard-query-logic`, `app_settings`) | Phase 26 **consumes**, never forks it |
| 2. Option-content components | **Phase 26 (new)** — `PopulationPanelContent`, `FilterPanelContent`, `SortPanelContent` | Presentation-agnostic; take state + change callbacks as props; **no knowledge** of *how* they are floated. Render identically inside `AnchoredPanel` today or a HUD overlay later |
| 3. Transient control-surface container | **Phase 26 (new)** — `AnchoredPanel` | The swap point. A future HUD replaces this container only |

**Contract:** option-content components must not import or reference `AnchoredPanel` internals
(positioning, scrim, animation). The trigger→container→content→state chain is the only coupling. This
seam is a checker/review verification target: a HUD swap must not require editing layer 1 or 2.

## Search Affordance & List/Card Toggle Row (phase-specific — dossier §K–L)

Row 3, **below** the control row (reads as scoped to the selected Dashboard universe, not global search):

- **Search** (`dashboard-search-input`, placeholder `Search people and notes` — existing copy) is
  **collapsible/expandable** (`dashboard-search-toggle`), not permanently consuming max vertical space
  (§K). Expand/collapse uses **restrained branded motion** (`MOTION.base`, `easing.decelerate`) and
  **respects reduced motion** (collapse to instant). Search text is **ephemeral session state**
  (`dashboard-session-store`), restored on Dashboard→Profile→Back, cleared on fresh launch (Phase 25).
  `dashboard-search-clear` clears the term. Do **not** add a separate permanent results-heading row (§K).
- **List/Card toggle** (`dashboard-view-toggle`) lives on the **same row as search, right-aligned**
  (§L). Search receives most of the row width; the toggle keeps a **real 44px touch target** (never tiny
  icons). Segments `dashboard-view-toggle-list` / `dashboard-view-toggle-card` set `viewMode` in the
  query store; the active segment shows the **filled** icon variant + `accessibilityState.selected`
  (non-colour redundancy). **No fourth Population/Filters/Sort-style presentation control** (§L
  [DECIDED]). The row/grid **rendering** the toggle switches between is owned by Phase 27 (List) /
  Phase 28 (Card); Phase 26 ships the control + persisted state.

## UI Considerations

> Shape-rooted UI *state* coverage for the control-shell surfaces. Empty/error **copy** lives in the
> Copywriting Contract (and Phase 25's); rows here cover *state* and reference that copy. `🧪 backstop`
> items carry an on-device visual check on the physical Pixel at this phase's UAT (per the repo's
> verify-UI-on-the-Pixel rule) — never a silent pass in the render-free vitest env.

Applicable state considerations resolved: **21 covered (explicit), 6 backstop, 0 unresolved** over 7
probed surfaces: S1 control row + summaries · S2 anchored panel (Population/Filters/Sort) · S3 header
destinations · S4 overflow menu · S5 search + List/Card row · S6 Archived child route · S7 Unbound child
route + search.

**Probe reconciliation (post-verification, 2026-09-05).** The `ui-consideration-probe` engine, run with
broad element-kind unions per surface, proposed **44** applicable considerations; the 27 rows above cover
every one a user can reach. The remaining 17 are **dismissed with reason** (no silent drop) — all trace to
the same two architectural facts, not to a missing state:

- **`loading` / `error` on S1 control row, S2/S4 menus, S3 header, S5 search** — dismissed: these surfaces
  hydrate **synchronously from local `app_settings` / SQLite with no network on any read path** (CLAUDE.md
  local-first; Phase 25 contract). There is no in-flight or failure state to render; a preference write
  failure is a settings concern, not a control-shell state (mirrors Phase 25 E3).
- **`empty` / `populated` / `zero-one-many` on S4 overflow** — dismissed: the overflow is a **fixed 5-row
  set** (§M amendment) that never varies in count, so data-volume states do not apply.
- **`overflow` on S1 summaries / S3 header** — dismissed: covered by the `+N` collapse and the D-04
  icon-only fallback already rowed above (not a separate scroll/clip state).
- **`partial` / `overflow` / `zero-one-many` on S6/S7 lists beyond the rows above** — dismissed: rows are
  complete contact records (no partial-field state) and list scroll is native `FlatList` behavior; the
  meaningful volume states (empty / populated / long-name) are already rowed.

Every proposed consideration is therefore **resolved or dismissed-with-reason** — 0 silently dropped.

|----------|------------|--------|---------------------|
