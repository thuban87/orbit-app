<objective>
Wire the installed `expo-share-intent` into the app with ONE deterministic owner of the pending share (A4): wrap the tree in `ShareIntentProvider` (the sole consumer of the native pending-share singleton), add a `navigationRef` + a ready-gated `<ShareIntentGate/>` that navigates to `Capture` when the provider's `hasShareIntent` context flag is set, and add the `Capture` route to the param list. This turns a system share into a mounted picker screen without two consumers racing on cold start.

Purpose: The library provides no auto-navigation. Because the provider consumes the native pending share on mount (and Orbit delays the navigator behind the migration `ready` gate), driving navigation from a linking `getInitialURL` would race the provider's consumption — two reviewers disagreed on whether the prior draft resolved this, which is itself the tell that it was under-specified. So this plan makes the PROVIDER'S CONTEXT STATE the single source of truth and reacts to it in a ready-gated gate — deterministic for both cold start and background.
Output: `src/navigation/linking.ts` (navigationRef + `<ShareIntentGate/>`), the `Capture` route type, and the App.tsx wiring.
</objective>
