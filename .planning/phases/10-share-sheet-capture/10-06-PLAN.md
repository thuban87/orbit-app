<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shared payload → N writes / inline-created contact | Untrusted payload fans out to N rows and can create a contact. |
| capture flow → status engine | Inline-create + multi-attach must not mark a touchpoint. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Tampering / Info-disclosure | note recompose + inline-create name | medium | mitigate | All writes are `?`-bound via `editFuel`/`addFuel`/`createContactFull`; the note recompose keeps the url canonical/separate (never overwritten). The name is stored as data. |
| T-10-06 | Tampering (status corruption) | inline-create + multi-attach | high | mitigate | Inline-create omits `firstInteraction` (last_contact stays NULL, never-contacted); multi-attach uses only `addFuelCore`; neither writes a touchpoint — DATA-04 single-writer invariant intact. |
| T-10-04 | Denial (data loss) | multi-select / note timing | medium | mitigate | The row(s) are written on pick (single) or on Done (multi) before the note; the note is a text-only patch afterward; the flow stays in-app so a background can't lose a committed row. |
</threat_model>
