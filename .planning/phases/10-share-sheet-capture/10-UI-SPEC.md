# Phase 10 — UI Design Contract

> Visual and interaction contract for **Share-Sheet Capture** (CAP-01/02/03/04):
> the Android `text/plain` share-target flow — a grid-of-faces contact picker,
> single-tap commit + long-press multi-select, an optional note, an inline
> name-only create, and a confirmation toast that returns the user to the source app.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase adds NO new visual language.** The capture surfaces must read as
> native to an app with 9 shipped phases. Every token, spacing step, and type role
> below is lifted verbatim from `src/theme/theme-presets.ts` (`space-dark`), the
> shipped `Avatar` / `ContactCard` primitives, and the approved 08/09 UI-SPECs.
> Reuse; invent nothing. All colours resolve through `useTheme().colors.*` —
> `check:colors`-gated, zero hex literals outside `src/theme/theme-presets.ts`.
> No new colour token is required this phase.

## Spacing Scale

The shipped system is **4px-based with a few 2px-granular exceptions that already
exist in production** (grounded in `ContactCard.tsx` + the 08/09 UI-SPECs). Reuse
these exact values — do not "normalise" 10/14 to the nearest 8-multiple (that would
silently restyle shipped screens).

| Token | Value | Usage (as shipped) |
|-------|-------|--------------------|
| xs | 4px | Tile trailing gaps, badge inset |
| sm | 8px | Grid-tile name↔avatar gap, chip padding, bar inner gaps |
| — | 10px | Input vertical padding, card radius (**shipped exception, keep**) |
| md | 12px | Grid gap, card/row/sheet inner padding, control gaps (the shipped default) |
| — | 14px | Back-pill horizontal padding (**shipped exception, keep**) |
| lg | 16px | Screen content padding, sheet padding, section gap |
| xl | 24px | Screen title / avatar-glyph size, modal inset |

**Border radius (shipped):** 8px (buttons/inputs), 10px (cards/tiles/rows), 12px (sheets/panels), 999px (pills), `size/2` (circular avatars/badges).
**Touch-target minimum:** `minHeight: 44` (and `minWidth: 44` for icon-only) on every `Pressable` — a hard, shipped invariant. Every face tile (avatar 64 + label) clears it; the ＋ tile, search affordance, "Done · N" bar, note "Done", and inline-create submit each carry the floor.
**Grid metrics (this phase):** face tile avatar `size: 64` (the shipped profile/compose avatar size, `Avatar` verbatim); grid `gap: 12`; **3 columns** in portrait (owner-adjustable layout call — the *content* contract is locked, the column count is a design-pass tunable, HANDOFF §12.4). Multi-select checkmark badge `18×18`, `borderRadius: 9`, top-right, inset `-2` (mirrors `ContactCard`'s status-ring badge geometry).

No new spacing values are introduced this phase.

**Accent (`#6C8CFF`) reserved for — explicit list, nothing else:**

3. The **selected-tile emphasis** — `borderColor: borderStrong` outline plus the accent badge (the badge, not a full-tile accent wash, carries the state; mirrors the dashboard active-chip idiom).
4. The **"Done · N"** bottom-bar fill (filled-accent primary: `backgroundColor: accent`, label `background`).
5. The **"Add a note"** affordance and the note-sheet **"Done"** — accent text/label (secondary-action idiom).

## Screen Layout — Capture Picker

Root: `FlatList` (recycling grid), `numColumns: 3`, `backgroundColor: colors.background`,
`contentContainerStyle: { padding: 16 }`, item `gap: 12`. `headerShown:false`; owns
its Back/close chrome. testID `capture-picker-root`.

Top-to-bottom:

1. **Header row** (`flexDirection: row, alignItems: center, gap: 12`, padding 16)
   - **Close** pill — `border` outline, radius 8, `paddingH 14 / paddingV 8`, label `textSecondary`. testID `capture-close`, `accessibilityLabel: "Cancel"`. **Cancels capture without writing** and `finish()`es back to the source app (Android system Back does the same).
   - **Title** — "Save to…" (24/700 `textPrimary`), `flex: 1`. testID `capture-title`.
   - **Search reveal** — an icon-only `Pressable` (🔍, `minWidth/Height: 44`), `textSecondary`. testID `capture-search-reveal`, `accessibilityLabel: "Search contacts"`. **Not autofocused; the keyboard stays closed until tapped** (CAP-01, the keyboard-in-the-fast-path hazard, dossier F-CAP-11).

2. **Payload preview strip** — `surfaceElevated` bg, `border`, radius 10, padding 12, one line. Shows the best-available label for what is being captured (the same text that becomes the fuel display text — see *Payload → display text*), `numberOfLines={1}`, 15/400 `textPrimary`; when a `url` is also present, a second `textSecondary` 13/600 line shows the host. testID `capture-payload-preview`. Confirms *what* is being filed before *who*.

3. **Revealed search field** (hidden by default) — appears only after the search reveal is tapped: a `TextInput`, `surface` bg, `border`, radius 8, `paddingH 12 / paddingV 10`, 15/400 `textPrimary`, placeholder "Search people" (`textSecondary`), live-filters the grid by name. Autofocuses **only when explicitly revealed**. testID `capture-search-input`; a `capture-search-clear` (`✕`) restores the full grid.

4. **Grid of faces** — the `FlatList` body. Order: **favourites → capture-MRU → rest** (CAP-01; capture-MRU derived from `fuel.created_at` + `contact_id`, no new column). Includes never-contacted, **excludes archived**. Each cell = a **face tile**:
   - `Avatar` — `photo` + `name` + `contactId` + `cacheBust={modified_at}` + `size={64}`, **used verbatim**. The `recyclingKey`/`cacheBust` anti-face-flash pattern is a **correctness requirement** in the recycling grid (a recycled cell must not flash the previous face), exactly as on the dashboard — not an optimisation.
   - Name below — 13/600 `textPrimary`, `numberOfLines={1}`, tail ellipsis, centered.
   - Tile is a full `Pressable` (see Interaction). testID `capture-face-{contactId}`.

5. **＋ New contact tile** — a first-class grid cell matching the face-tile footprint, rendered as the **final** cell (preserving favourites-first muscle memory for real faces). Accent-outline (`borderColor: accent`, radius 10), a large accent "＋" glyph (24) where the avatar sits, label "New contact" (13/600 `textPrimary`). **Always present.** At 0–1 contacts it naturally dominates the grid — no separate empty screen is needed. testID `capture-new-contact-tile`, `accessibilityLabel: "New contact"`.

## Interaction Contract

### Single-tap (the 95% path — exactly one tap)

1. **Tap a face** → the fuel row is **written immediately** to that contact (kind `topic`, `source='share'`, display text per *Payload → display text*, `url` canonical). Writing before any prompt is load-bearing: `useShareIntent` defaults `resetOnBackground: true`, so an un-written payload dies on background (dossier, binding).
2. The **confirmation + optional-note surface** appears (see below) showing **"Saved to {name}"**.
3. **If the user does nothing**, after a short window (`AUTO_RETURN_MS`, default ~1500ms — a top-of-file tunable per CLAUDE.md) Orbit `finish()`es back to the source app. This is the "brief toast → return, no Undo" lock, and keeps the common case at **one tap total**.
4. **If the user touches the surface / taps "Add a note"**, the auto-return timer is **cancelled**, the note field takes focus, and there is no timer thereafter — the note is never rushed. On note **"Done"**, the just-written row's display text is updated to the *note — title* composition, then the toast shows and Orbit `finish()`es.

> Design note (interaction taste, flagged for the owner, not a token): merging the
> "Saved to {name}" toast and the optional-note entry into one auto-returning
> surface is the only reading that satisfies **both** locked decisions at once —
> "single tap commits and closes" (dossier Cluster 1) *and* "optional, skippable
> note" (dossier Cluster 1) *and* "brief toast ~1.5s then return" (CONTEXT #3). The
> alternative — a mandatory note sheet with a Skip button — costs a second tap on
> every single capture and contradicts "exactly one tap." `AUTO_RETURN_MS` is a
> single-number tunable if the owner wants a longer grace window.

### Long-press → multi-select (CAP-02)

- **Long-press any face** enters multi-select mode (long-press is otherwise unused on this screen, so it is free — unlike the dashboard card, where long-press is reserved for the action menu, 08-UI-SPEC).
- Each **selected** face shows a filled-`accent` **corner checkmark badge** (top-right, ✓ in `background`) plus a `borderStrong` tile outline. testID `capture-face-check-{contactId}`.
- **Tap toggles** a face in/out of the selection. The long-pressed face is selected on entry.
- A **persistent bottom bar** overlays the grid: filled-accent, label **"Done · N"** (16/700, `background`), where N is the live selection count. testID `capture-multiselect-bar` / `capture-multiselect-done`.
- **Back** (or the Close pill) exits multi-select **without writing** (returns to normal picker if a selection exists; a second Back cancels capture). **Done** commits.
- On **Done**: **N independent fuel rows** are written (one per selected contact, each owning its copy — never a join table, dossier binding; the N-in-one-transaction mechanism is a planner call). The confirmation surface then shows **"Saved to N contacts"** with the same optional-note affordance; a supplied note is applied to **all N** rows' display text. Then `finish()`.
- The payload survives multi-select because the user stays in-app (no background); durability is preserved.

### ＋ New contact → inline name-only create (CAP-04)

- Tapping the ＋ tile opens the **inline-create surface**: a sheet with a single **name** `TextInput` (`surface`, `border`, radius 8, 15/400, **autofocused — this is the one place typing is the point**), placeholder "Name", and a filled-accent **"Create & save"** primary (`minHeight 44`). testID `capture-inline-create` / `capture-inline-name-input` / `capture-inline-submit`.
- On submit: create the contact **name-only** (`last_contact` NULL → never-contacted, opposite of the standard create form's "today"; `createContactFull` name-only path, dossier/06-crud binding), then **write the fuel row** to the new contact, then the standard confirmation surface → `finish()`.
- **No "add detail now?" prompt** (CONTEXT #5) — contact detail is refined later on the profile. The standard optional-note affordance still applies (the note is capture prose, not contact detail); auto-return handles the skip so no extra tap is forced.
- The captured fuel appears on **no main dashboard surface** until first contact, but IS visible on the never-contacted screen, which already renders fuel (08-05 / DASH-04 / F-CAP-13, satisfied).

### Confirmation + optional-note surface (shared by all three paths)

- A bottom surface: `surface` bg (or `surfaceElevated`), radius 12, padding 16.
- Line 1: **"Saved to {name}"** / **"Saved to N contacts"** — 13/600 `textPrimary`. testID `capture-confirmation-toast`.
- An **"Add a note"** accent affordance (16/600) that, on tap, expands to a multiline **note** `TextInput` (`surface`, `border`, radius 8, `paddingH 12/paddingV 10`, 15/400, `minHeight ≥ 88`, placeholder "Add your words — e.g. \"for Dad, he asked about this\"", `textSecondary`), keyboard closed until engaged. testID `capture-note-input`.
- A note **"Done"** (accent, 16/600, testID `capture-note-done`) commits the note; the surface may also carry a subtle **"Skip"** (`textSecondary`, testID `capture-note-skip`) for users who opened the note but changed their mind.
- The surface is dismissed and the auto-return armed exactly as described in the single-tap flow. **Show/hide is a single `setState` + `setTimeout`, NEVER a per-frame animation driven by React state** (CLAUDE.md; mirrors 09's "Copied" pattern).

## Payload → display text (drives the preview, the row, and the toast)

The `url` column is **always canonical and separate**; user prose (the note) never
overwrites it (F-CAP-6 / F-CAP-15, binding). Display text is the best-available
label and is what the preview strip and the written row show:

| Share shape | Display text | `url` column |
|-------------|-------------|--------------|
| Bare URL (Chrome) + `EXTRA_SUBJECT` | the page **title** | the URL |
| Bare URL, no `EXTRA_SUBJECT` | the **bare URL** (fallback) | the URL |
| Plain text selection | the **text** | null |
| Prose containing a URL | the **prose** | first `http…` match |

**When the user adds a note**, display text is recomposed as **`note — title`**
(note leads, `" — "`, then the shared title/label appended). Note-only → the note;
title-only → the title; the `url` column is untouched in every case (CONTEXT #2).

## Loading / Empty / Error States

| State | Trigger | Contract |
|-------|---------|----------|
| Loading | first contacts query in flight (cold-start share) | Calm inline state; the query is local SQLite and fast at HANDOFF-§10 scale. No blocking network on any read path. |
| Near-empty | 0–1 contacts | **Not a separate screen** — the ＋ New contact tile is always present and naturally dominant; it is the effective path (CAP-04, CONTEXT #4). Optionally a one-line `textSecondary` hint "Add someone to save this to." above the grid. |
| Empty payload | the share yields no usable text (defensive; `text/plain`-only registration makes this rare) | An error state "Nothing to save" + a Close that `finish()`es. `danger` emphasis. testID `capture-error-state`. |
| Write failure | the fuel/contact write throws | Native `Alert`: **"Couldn't save"** / *"Please try again."* The payload still lives in `useShareIntent` (until background), so retry is possible. `danger`. |
