# Phase 27 — Dashboard List View — UI Design Contract

## Spacing Scale

Uses the existing `src/theme/tokens/spacing.ts` `SPACING` set (all multiples of 4). Consume tokens, never raw px.

| Token | Value | List-row usage |
|-------|-------|----------------|
| xs | 4px | Gap between adaptive-line leading icon and text; favourite/status glyph inset nudge |
| sm | 8px | Gap between the three text lines; category chip inner padding |
| md | 12px | Row inner padding; gap between avatar and text block |
| base | 16px | Row horizontal padding / list side gutter |
| lg | 24px | Empty-state block padding |
| xl | 32px | Empty-state vertical breathing room |
| 2xl | 48px | Major empty-state separation |

Exceptions:
- `md = 12` is a deliberate grid-aligned token (documented in `spacing.ts`), not an 8-point violation.
- **44×44 minimum touch target** (a floor, not a spacing token) applies to the tappable favourite star and to each accessibility row action. The star's *glyph* may be smaller; its *hit area* must be ≥44.
- Exact row height / avatar size / gesture thresholds are **[DEFERRED] to device testing** (dossier §U); this spec fixes the classes, device UAT fixes the pixels.

## Typography

Row text consumes the five semantic roles from `src/theme/tokens/typography.ts` (4 sizes: 28/20/16/14; 2 weights: 400/600). Screens consume **roles**, never raw sizes.

| Row element | Role | Size | Weight | Line Height | Colour token |
|-------------|------|------|--------|-------------|--------------|
| Line 1 — contact name (identity) | body | 16px | 400 | 24 | textPrimary |
| Line 2 — recency + category | caption | 14px | 400 | 20 | textSecondary |
| Line 3 — adaptive context / completeness prompt | caption | 14px | 400 | 20 | textSecondary |
| Category chip label | caption | 14px | 400 | 20 | textSecondary |
| Search: line 2 match explanation | caption | 14px | 400 | 20 | textSecondary |
| Search: highlighted matched run (within line 3 snippet) | label | 14px | 600 | 20 | textPrimary |
| Empty/error heading | heading | 20px | 600 | 25 | textPrimary |
| Empty/error body | caption | 14px | 400 | 20 | textSecondary |

- Line 1 is single-line, `numberOfLines={1}` ellipsize tail. Lines 2 and 3 are single-line, ellipsize tail (overflow handling below).
- Matched-text highlight (LISTV-06) is expressed by rendering the matched run at **label weight (600) on textPrimary** inside an otherwise-caption line — no highlight background colour, no hex.
- OS text scaling must reflow (increase row height), never clamp (dossier §C/§Q, LISTV-09). Do not set a fixed row height that truncates scaled text.

## Color

60/30/10 discipline over the theme palette (`src/theme/theme-types.ts`). **Status hues are a separate semantic system, NOT part of the 10% accent budget.**

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `background` | List backdrop / scroll surface |
| Secondary (30%) | `surface` (rows), `surfaceElevated` (category chip) | Row card fill, chip fill |
| Accent (10%) | `accent` | See reserved-for list below |
| Destructive | `danger` | **Not used in this phase** — there are no destructive swipe actions (D-09). Listed for completeness only. |

**Status / state colours (separate semantic channel, resolved via `ringVisual().color` + `StatusGlyph` tone — never invented, never a fifth status):**

| State | Border colour token | Glyph (via `statusGlyph()`) |
|-------|--------------------|-----------------------------|
| Stable | `statusStable` | `status-stable` |
| Wobble | `statusWobble` | `status-wobble` |
| Decay | `statusDecay` | `status-decay` |
| Rogue | `rogue` | `status-rogue` |
| Never-contacted / no evaluation (`null`) | `border` (neutral) | **none** — no glyph rendered (D-07/§J; do NOT mount `StatusGlyph`, do NOT show `status-neutral`) |
| Snoozed (override) | `border` (neutral) | `status-snoozed` (moon) |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The **filled favourite star** (marked state).
2. The empty-state **primary CTA** ("Add your first contact").
3. Active/selected control states inherited from the shared control surface.

Accent is **never** used for: status/relationship signalling, row body text, borders on ordinary rows, or the swipe action surfaces (those use their own semantic tokens).

## Copywriting Contract

Empty/error state **causes and copy are shared with Card View** and already implemented on the dashboard host (`src/screens/HomeScreen.tsx`, `src/logic/dashboard-empty-logic.ts`). List View reuses the shared semantic content; only layout/presentation may be renderer-specific (dossier §T, LISTV-10). Strings below are the on-disk canon — reuse verbatim, do not re-author.

| Element | Copy |
|---------|------|
| Primary CTA (first-run empty) | `Add your first contact` |
| Empty — no search matches | `No matches for "{term}"` |
| Empty — filtered population zero | shared filtered-empty copy (population-labelled, e.g. `Nothing in {population}.`) |
| Empty — everyone hidden/snoozed/archived | heading `Everyone's tucked away` + pointer lines (`{n} not yet contacted →`, `{n} snoozed`, `{n} archived`) |
| Error state | heading `Couldn't load your contacts` + body `Pull down to try again.` |
| Destructive confirmation | **none** — no destructive action exists in List View (D-09) |

**Row line copy (List-specific, deterministic):**

| Element | Copy pattern |
|---------|--------------|
| Line 2 recency + category | `18d ago · Friend` / `Today · Family` / `Yesterday · Work` |
| Line 2 never-contacted | `No interactions yet` (neutral phrase; row presentation only, NOT an Active-predicate change — D-08/E-02) |
| Line 3 adaptive context | deterministic item from existing structured/user-authored knowledge (priority: imminent/time-sensitive → pinned/high-value → other useful knowledge). **No AI-generated copy. Birthdays excluded** (D-11, §F). |
| Line 3 completeness prompt (no useful context) | one of ~10 stable-per-contact prompts, e.g. `Add something to remember about {name}` / `What should you remember about {name}?` / `Add a detail about {name}` / `What's useful to know about {name}?` / `Nothing remembered about {name} yet`. Selection is **deterministic per contact** (stable across re-render; not random). Not a completeness score/gamification. |
| Search line 2 match explanation | `3 matches · Memory, Relationship` (count + strongest match categories; `+N more` has no inline action) |
| Favourite success | **no snackbar** (D-04/§H) — silent optimistic fill/unfill only |
| Favourite persistence failure | revert the optimistic state + error notification, e.g. `Couldn't update favourite. Try again.` |

## Row Anatomy & Layout Contract (dossier §B/§C, LISTV-01)

Full-width, medium-compact row. Target ~5–6 complete rows visible at default text size (a design target, **not** an accessibility invariant — large text may reflow to fewer rows).

```
┌───────────────────────────────────────────────┐  ← thin status-coloured border (SAME weight, all states)
│  ┌──────┐   Contact name (line 1)          ★   │  ← favourite star, upper-right, tappable
│  │Avatar│   18d ago · Friend (line 2)          │
│  │64–72 │   ⌂ Adaptive context (line 3)     ◐  │  ← status glyph, lower-right, non-tappable
│  └──────┘                                       │
└───────────────────────────────────────────────┘
```

| Region | Contract |
|--------|----------|
| Avatar | Left; circular; **64–72 logical-px class** (exact resolved by device UAT). Reuse `Avatar` with `contactId` recyclingKey + `cacheBust=modified_at` — the anti-face-flash correctness requirement in the virtualized list (dossier §U). |
| Text block | Three-line stack, fixed geometry, flex-fill between avatar and trailing indicators. |
| Favourite star | Upper-right, always visible, directly tappable (≥44px hit area). Icon via registry `favorite`. Filled = `accent`; unfilled = `textSecondary`. See Flag F-4 (star vs heart). |
| Status glyph | Lower-right, non-interactive/informational (a11y-hidden at the glyph; state exposed via the row description). Via `StatusGlyph` at `ICON_SIZE.md` (20). Absent for never-contacted. |
| Row border | Surrounds the whole row; carries status **colour** at a **fixed weight** (see Status contract). |
| Corner radius | `RADII.lg` (16) — Orbit's rounded language; exact resolved by device UAT. |
| Row surface | `surface`. |

## Status Presentation Contract (dossier §I/§J/§K, D-07, LISTV-05)

Two **redundant** channels for unsnoozed relationship state, never colour alone:
1. **Border** — status-coloured (via `ringVisual(status, colors).color`) at a **single fixed weight for every status** (recommend `2px`). **Severity does NOT increase border thickness** (§I).
2. **Lower-right status glyph** — distinct celestial silhouette via `StatusGlyph`.
3. (Non-visual third channel) the accessible row description names the state textually.

> **Executor contract — border weight (not a reversal, a scoping note):** `ringVisual()` returns an *escalating* `width` (2/3/4/3). That escalation governs the **legacy DASH-03 avatar-corner ring only**. For the List View **row border**, use `ringVisual(status, colors).color` but a **constant width** — do **not** wire `ring.width` into the row border, or you break §I's same-weight rule.

> **Executor contract — never-contacted glyph (D-07/§J):** For `state === null`, render the neutral `border` colour and **no status glyph** — do not mount `StatusGlyph` and do not display the `status-neutral` silhouette. Do not fabricate a fifth "Unknown" status.

**Snooze override (§K):** while snoozed, suppress the status border to neutral `border` and replace the status glyph with `StatusGlyph state="snoozed"` (moon). Underlying status is unchanged domain state — this is renderer presentation only. The consumer composes `"snoozed"` onto the computed `ProfileStatus` (`StatusDisplayState`); snooze is `contacts.snooze_until`, not a query-time status.

## Swipe & Gesture Contract (dossier §M/§N/§O/§P, D-09, LISTV-07/08)

| Gesture | Action |
|---------|--------|
| Tap (closed row) | Open Contact Profile |
| Tap (partially swiped row) | **Close the swipe first**, do not navigate |
| Swipe **right** | Execute the **configured** logging action (global preference: Quick Log \| Log Contact, default **Quick Log**) — executes on gesture commit, no second tap on a revealed button |
| Swipe **left** | Route to Edit Contact — executes on gesture commit |

- **Exactly one row swipe-revealed at a time**; opening another closes the previous (D-09).
- **No destructive swipe actions**, no multi-button drawers, no per-contact swipe config, no additional actions (hard boundary — `27-CONTEXT.md` `<deferred>`).
- Progressive reveal language: row translates with finger → action surface appears behind → semantic action icon becomes visible → optional short label → threshold/resistance communicates commit → sub-threshold release returns the row (§P).
- Swipe action icons via registry semantic names (logging action → `message`/`add`/`sparkle` per the configured action's semantics; Edit → `edit`). Action surfaces use their own semantic tokens, **not** `accent`.
- **No permanent in-List gesture tutorial** — gesture education belongs to onboarding (Phase 17).
- Right-swipe preference **storage & read** are owned here (an `app_settings` column added to `PORTABLE_SETTINGS_KEYS`, backup-portable, never AsyncStorage — R-16). Migration numbered head+1 verified against `src/db/migrations/` + `TARGET_VERSION` at plan time, or folded into Phase 25's migration — **decide once** (D-03). The **Settings UI** for it is Phase 15's; the **onboarding early choice** is Phase 17's.
- Gesture velocity/distance thresholds and spring curves are **[DEFERRED]** to device testing (dossier §U). Gestures use Reanimated worklets — **never drive animation from React state** (CLAUDE.md).

## Accessibility Contract (dossier §Q, D-10, LISTV-09)

- **Row description** (composed, colour-independent) covers: name, category, recency phrase, favourite state, and relationship-or-snooze state. Reuse the state-naming labels already defined in `StatusGlyph` (`Stable` / `Wobbling` / `Decaying` / `Rogue` / `Snoozed` / `Not yet contacted`).
- **Row accessibility actions** mirror the gestures: **Log Interaction** and **Edit Contact** (assistive-tech users never need to perform the swipe).
- The favourite star exposes an accessible toggle with its membership state; the status glyph is decorative at the glyph level (state carried by the row description), so it is not double-announced.
- Status meaning must survive with **no colour perception**: glyph + textual label are the redundant channels.
- Large accessibility text **reflows / increases row height** rather than shrinking below readable sizes; normal-density row-count is not an a11y invariant (§C).

## Motion Contract (dossier §R/§S, LISTV-10)

- Fast local Population/Filter/Sort/Search updates **keep current content visible** and update in place — no skeleton flash on every query change.
- **Skeleton/loading rows** are reserved for initial load or a meaningfully delayed load.
- Result transitions are **short, restrained** (brief position change + fade). Tokens: `MOTION.fast` (120ms) / `MOTION.base` (200ms), easing `EASING.decelerate` for enter. Understated, never orbital/cinematic.
- **Reduced motion:** gate via `useReducedMotion()` — when enabled, simplify or remove the transitions (instant apply, no position animation).
