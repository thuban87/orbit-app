## H1 — the closed allowlist (owner-visible)

`PromptContext` enumerates exactly these fields; the DAO may read NOTHING else off a contact:
- `contactName: string` and `category: string` — the two direct contact identifiers, needed to address a warm check-in and tune tone (matches the legacy template's `{{name}}`/`{{category}}`). **`category` is the category NAME, not a `contacts` column (C2-H1):** `contacts` has `category_id INTEGER REFERENCES categories(id)` (001-initial.ts:66) — there is no `category` text column. Resolve the name via a narrow `LEFT JOIN categories ON categories.id = contacts.category_id`, selecting `categories.name AS categoryName` (empty string when `category_id` is NULL). These are the ONLY direct-contact fields permitted; every other `contacts` column (phone, email, birthday, photo, links, snooze, archived, raw `last_contact`, `category_id` itself) is prohibited from egress. (Owner: this is the one direct-identifier egress decision — it is shown in the exact-prompt inspector/acknowledgement before the first send per provider, so it is owner-vetoable at that gate.)
- `rankedFuel: ReadonlyArray<{ text; kind; label?; ageDays }>` — via `getRankedFuel` only (off_limits, unconfirmed-`source='ai'`, and blank rows already excluded in SQL).
- `gravityTier: string`, `intensity` (neutral rate/cadence aggregate), `quality` aggregate, `cadenceCount` aggregates, `newestChannel: string` with explicit `"unspecified"`.
- `sharedFields: ReadonlyArray<{ label; value }>` — live `share_with_ai=1` custom values only, looked up by validated `col_name`, displayed by label.
Prohibited and covered by exclusion fixtures: interaction `note`/`detail`, `off_limits`/unconfirmed-AI fuel, unflagged/quarantined/dropped/null/blank custom fields, and any non-allowlisted `contacts` column.
