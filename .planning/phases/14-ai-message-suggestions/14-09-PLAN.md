<objective>
Replace the flat `MAX_OUTPUT_TOKENS` stopgap with a per-provider, thinking-aware token budget. Thinking models (Gemini 2.5/3.x) spend `maxOutputTokens` on internal reasoning BEFORE any message — measured 364-886 THINKING tokens for a ~20-60 token reply (14-06 UAT) — so a single flat number is fragile. Cap Gemini's reasoning with a `thinkingBudget` and give a modest output allowance on top; keep OpenAI/Anthropic on a tuned output allowance.

Purpose: close the 14-06 device-UAT model-handling gap — empty drafts and mid-sentence truncation caused by reasoning tokens exhausting a flat budget.
Output: a node-tested per-provider budget policy, a Gemini adapter that caps reasoning, Compose wired to the policy, and AI-SPEC §4 formally updated.
</objective>

<design_decisions>
Owner reviewed these defaults and said to proceed; they are ENCODED below. Redline any before execution — each names its alternative.

- **D-01 — Per-provider thinking-aware budget policy replaces the flat cap.** A pure `resolveTokenBudget(provider, model)` returns the output allowance and an optional reasoning cap. *Alternative (rejected):* keep bumping the flat `MAX_OUTPUT_TOKENS` (already raised 120 → 1024 → 2048) — fragile; still truncated richer prompts on device.
- **D-02 — Gemini gets a `thinkingConfig.thinkingBudget` cap plus a modest output allowance.** Measured on device: `thinkingBudget ≈ 256` → ~500 thinking tokens + a complete message, faster and cheaper. Exact numbers are tunable constants at the top of the policy file; the executor confirms/keeps the measured values. *Alternative (rejected):* rely on `maxOutputTokens` alone — reasoning crowds out output.
- **D-03 — The neutral contract stays provider-agnostic.** `GenerationInput` gains an optional `thinkingBudget?: number | null` — a NEUTRAL concept ("cap on internal reasoning tokens; null = provider default"), NOT a provider field name (mirrors how `maxOutputTokens` already maps to `max_tokens`/`max_completion_tokens`/Gemini config per adapter). Adapters that lack the concept ignore it. *Alternative (rejected):* leak `thinkingConfig` into the neutral input.
- **D-04 — OpenAI/Anthropic get a tuned output allowance, no reasoning cap (for the curated frontier chat models).** The curated OpenAI (gpt-4o/4.1-class) and Anthropic (Sonnet/Haiku non-thinking) frontier models are not thinking-by-default, so a modest `maxOutputTokens` suffices. The policy branches per provider; a documented note says to add a reasoning control if a reasoning model is ever curated. Verify each provider's current reasoning-control field against official docs at execution time before wiring anything beyond Gemini. *Alternative (rejected):* apply Gemini's mechanism blindly to every provider — the field names differ and change.
- **D-05 — AI-SPEC §4's 120-token ceiling is formally superseded, not silently reversed.** Append an ERRATA entry (§0) recording the new thinking-aware budget and add a pointer in §4. The separate 1,200-code-point post-parse draft ceiling in `AiService.parseSuggestionOutput` is UNCHANGED. *Alternative (rejected):* change the number in place with no record.
</design_decisions>
