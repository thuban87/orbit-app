<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| settings database → app UI/export | Persistent non-secret configuration must remain separate from credentials. |
| key repository → native SecureStore | A provider key crosses only into device-backed secret storage. |
| Custom URL input → settings persistence | A user-supplied endpoint is validated (URL-literal layer) before it is stored. |
| npm install → build | A new dependency enters the supply chain. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-14-01 | Information disclosure | migration + settings DAO | high | mitigate | Migration/DAO tests prove no key column/property exists and only typed non-secret fields persist. |
| T-14-02 | Information disclosure | ai-key-store | high | mitigate | Provider-scoped SecureStore item names plus a narrow injected repository prevent bulk key serialization. |
| T-14-03 | Tampering | settings writes | medium | mitigate | Typed provider/config/ack validation + `validateCustomEndpoint` on the endpoint write + single-row guarded path reject malformed settings. |
