# Phase 8 — UI Design Contract

> Visual and interaction contract for the dashboard (home), the Not-yet-contacted
> sibling screen, the Snoozed segment, the Archived entry, the profile favourite
> star, and the shared Manage-favourites reorder screen. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of authority.** This contract LOCKS the *content contract*, spacing,
> typography, colour-token mapping, interaction states, loading/empty/error
> states, accessibility (a11y labels + `testID`s), and copy DIRECTION. It does
> **not** lock the exact card/grid pixel layout, sizes, or styling — those are the
> owner's design pass (HANDOFF §12.4; dossier 08 repeats this). A reference layout
> is proposed and explicitly marked owner-adjustable. Genuinely-open new-token and
> taste questions are gathered in **§ Owner Decisions Required** — the executor
> must not invent hex values or binding taste calls to close them.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (React Native / Expo — shadcn is a web/DOM library, not applicable) |
| Preset | not applicable |
| Component library | none (RN primitives: `View`, `Text`, `Pressable`, `FlatList`, `TextInput`, `RefreshControl`) |
| Icon library | none in `src/` yet — see § Owner Decisions Required (favourite/star, chevron, search glyphs). Prefer a vector set already in the Expo SDK (`@expo/vector-icons`) or a text glyph; no raw colour. |
| Font | System default (no custom font shipped; RN platform font). Not changed this phase. |
| Colour source | `useTheme().colors.*` ONLY — the `space-dark` preset in `src/theme/theme-presets.ts` is the single file where a hex literal may appear. `check:colors` gate enforces this everywhere else. |

**Established conventions this phase MUST follow (grounded in shipped code):**

- Every screen root carries a `testID` and `backgroundColor: colors.background`.
- Native-stack shell, `headerShown:false` — each screen owns its own Back chrome
  (a bordered `Back` Pressable, `colors.textSecondary`, radius 8), mirroring
  `SettingsScreen` / `ContactProfileScreen`.
- Rows/cards: `backgroundColor: colors.surface`, `borderColor: colors.border`,
  `borderWidth: 1`, `borderRadius: 10`, `padding: 12` (the shipped row idiom).
- Reads use the **async** expo-sqlite API only (never `...Sync`) — HANDOFF §3.
- All dates via `formatLocalDate()` / `date('now','localtime')` — never
  `toISOString().split()`.

## Spacing Scale

Declared canonical values (multiples of 4). The shipped components already center
on `8 / 12 / 16 / 24`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/label gaps, inline padding |
| sm | 8px | Compact stacked spacing (list gaps) |
| md | 12px | Row/card inner padding, control gaps (the shipped default) |
| lg | 16px | Screen content padding (`ScrollView`/`FlatList` contentContainer) |
| xl | 24px | Section breaks, hero spacing |
| 2xl | 32px | Major layout gaps / hero title block |

Exceptions (pre-existing, carried unchanged):
- **2px** — the tight name↔snippet stacked gap in `FuelSearchResultRow` (reused on the card's name↔fuel stack).
- **10px** — the standard `borderRadius` on rows/cards/buttons (a radius, not a spacing step).
- **44px** — minimum touch-target height for every tappable row/chip/star (Android a11y). `FuelSearchResultRow` already uses `minHeight: 44`; every card, chip, sort control, and star toggle inherits this floor.

## Typography

Grounded in the shipped scale (no new sizes introduced this phase).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display (hero) | 32 | 700 | ~1.2 | First-run empty-state title only (existing `HomeScreen` hero) |
| Heading (screen title) | 24 | 700 | ~1.2 | Screen titles: "Not yet contacted", "Manage favourites" (matches Settings 24/700) |
| Body / control label | 16 | 600 | ~1.4 | Row labels, button text, chip labels, contact-count header |
| Body | 15 | 400 | ~1.5 | Contact name on the card, banner text, search input text |
| Small / meta | 13 | 600 | ~1.4 | Fuel snippet, category label, section/segment sub-labels, counts |

**Weights.** Two text weights are the contract: **400 (regular)** for body/names,
**600 (semibold)** for labels/emphasis/counts. **700** is a pre-existing exception
reserved ONLY for screen titles and the avatar-initials glyph (`size * 0.4 / 700`
inside `Avatar`) — not introduced by this phase, not to be spread further.

Card name renders `numberOfLines={1}` tail-ellipsis (matches `RankedFuelLine` /
`FuelSearchResultRow`). Fuel preview renders `numberOfLines={1}` tail-ellipsis.

## Color

Values from the `space-dark` dark palette (`src/theme/theme-presets.ts`). Reference
tokens **by name**; never inline a hex.

| Role | Token (hex) | Usage |
|------|-------------|-------|

| Secondary (30%) | `surface` (#141828) / `surfaceElevated` (#1D2235) | Cards, chips, banner, sort control, search box, category-label chip |
| Accent (10%) | `accent` (#6C8CFF) | See reserved list below |
| Destructive | `danger` (#E5484D) | Not used this phase (no destructive action here) — reserved for future |
| Status (rogue) | `rogue` (#E0904A) | The rogue card's status-ring visual (see § Status Ring) |
| Text primary | `textPrimary` (#E6E9F5) | Names, titles, primary body |
| Text secondary | `textSecondary` (#8B93B0) | Fuel snippet, category label, counts, sub-labels, inactive chips, Back |
| Borders | `border` (#2A3048) / `borderStrong` (#3C4568) | Row/card outlines; `borderStrong` for the active/selected chip + fuel-match emphasis |
| Avatar fallback | `avatarSwatches[8]` + `avatarSwatchText` | Initials avatar (deterministic per contact) |
| Gravity ramp | `gravityTiers[4]` | **Profile-only — NEVER on the card** (nothing log-derived on the card) |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The first-run primary CTA ("Add your first contact") — filled `accent`, `background` text (the shipped `HomeScreen` primary-entry idiom).
2. The active/selected filter chip's fill (or its label — owner's design pass picks fill vs outline; both use `accent` + `borderStrong`).
3. The "N not yet contacted →" pointer in the cause-aware empty state and the count-carrying hidden-population entries' emphasis.
4. The favourite star marker — **provisional**; owner may substitute a dedicated favourite token (see § Owner Decisions Required).
5. Links / "Manage" affordance text.

The search-box active/focus state and pull-to-refresh spinner use `accent`
sparingly; do not accent every chip or every card.

## Status Ring — card status visual (DASH-03)

The card MUST carry a status ring that encodes the contact's query-time
`OrbitStatus` (`stable` | `wobble` | `decay`) plus the derived **rogue** state.
Status is DERIVED-NEVER-STORED, computed via `getContactStatus` at query time
(same source the profile uses).

**Token gap (must be resolved by the owner before pixel implementation).** Only
`rogue` exists as a status token today. There is **no** `stable` / `wobble` /
`decay` ring colour in the palette, and the profile screen renders only a *text*
rogue label, not a coloured ring. The three band colours are net-new,
owner-approved tokens — the executor must NOT invent hexes (`check:colors` bars
it). See § Owner Decisions Required item 1.

**Rogue inheritance.** The card's rogue rendering **inherits domain 9's (orrery)
definitive rogue visual** — the dashboard MUST NOT invent its own rogue treatment.
For this phase, the rogue ring uses the existing `rogue` token; the full rogue
visual language is domain 9's to define and the card adopts it when domain 9 lands.
Rogue contacts are **not** hidden from the dashboard; they sort at the far end of
the status band (exact rogue-vs-decay ordering is domain 9's threshold call).

Contract regardless of final colours: the ring is a per-card element keyed to the
band, reads through `colors.*`, and carries `testID="dashboard-card-status-<contactId>"`
plus an `accessibilityLabel` naming the status (e.g. "Needs attention", "Stable",
"Rogue") so uiautomator UAT can assert it without colour inspection.

## Card Content Contract (DASH-03) — LOCKED

Every dashboard/never-contacted card MUST be able to carry exactly these elements.
This fixes WHAT the card carries, not HOW it is arranged (arrangement = owner's
design pass).

| Element | Source | Rules |
|---------|--------|-------|
| Avatar | `Avatar` component (Phase 5) | Photo → themed-swatch+initials fallback, deterministic per contact. **`recyclingKey={contactId}` is a CORRECTNESS requirement** (prevents a recycled row flashing the previous face) — pass `contactId` and the contact's `modified_at` as `cacheBust`. |
| Status ring | `getContactStatus` (query-time) | Band colour (stable/wobble/decay) + rogue inherits domain 9. See § Status Ring. |
| Name | `contacts.name` | `numberOfLines={1}`, tail ellipsis, Body 15/400 `textPrimary`. |
| Fuel preview | `getRankedFuel` → `RankedFuelLine` | The single top-ranked line; `off_limits` + unconfirmed `source='ai'` already excluded in-query. **Required one line.** When no rankable fuel exists, `RankedFuelLine` renders nothing (no placeholder). Reuse the component unchanged. |
| Category label | `categories` table (single-select FK) | Small chip/label, Small 13/600 `textSecondary` on `surfaceElevated`; hidden when the contact has no category. Category is contact data, **not** log-derived. |
| Favourite marker | `contacts.favourite_rank IS NOT NULL` | A subtle star/pin marker so favourites are recognizable inline. Provisional `accent`; see Owner Decisions. |

**Forbidden on the card (nothing log-derived — 04-log D/G):** no recency string,
no "N days ago", no channel glyph, no gravity bar, no intensity, no quality. Those
are profile-only.

**Search-match variant.** When the list is filtered by a search term and a card
matched on **fuel text** (not name), the card shows the matching fuel snippet so
the user sees *why* it matched — reuse `FuelSearchResultRow`'s snippet idea
(`textSecondary`, `numberOfLines={1}`). A name-only match renders the normal card
(normal ranked-fuel preview). The dashboard search is a **live in-place filter** of
the flat list (not a distinct results view).

## Loading / Empty / Error States (DASH-07)

Cause-aware empty states are **behavior** (decided), not styling; the copy/visuals
are owner-tunable. Recommended copy in the Copywriting Contract.

| State | Trigger | Contract |
|-------|---------|----------|
| Loading | first query in flight | A calm inline state (spinner or nothing on a fast local query). No blocking network — reads are local SQLite. Keep minimal; the query is fast at this scale. |
| Empty — first run | zero contacts total | Prominent "Add your first contact" CTA (filled `accent`) → `Create`. `testID="dashboard-empty-firstrun"`. |
| Empty — hidden populations | default list empty only because everyone is never-contacted / archived / snoozed | Point the user there: "N not yet contacted →", "N snoozed", "N archived". Distinguishes "you have nobody" from "everybody's in another bucket". `testID="dashboard-empty-hidden"`. |
| Empty — search no match | search term matches nothing | "No matches" + the term. `testID="dashboard-search-empty"`. |
| Empty — never-contacted screen | no never-contacted contacts | Calm "you've reached everyone" state. `testID="never-contacted-empty"`. |
| Empty — favourites filter | no favourites yet | "No favourites yet" + pointer to the profile star. |
| Error | query throws | "Couldn't load your contacts" + "Pull down to try again." `testID="dashboard-error-state"`. Never a raw exception string. |

## Image / Loading Contract

- Cards render avatars via the existing `Avatar` component. **`recyclingKey`
  (fed `contactId` + `cacheBust`) is a correctness requirement** in the scrolling
  `FlatList` — it blanks a recycled row before the new source loads, preventing a
  face-flash of the previous contact. This is non-negotiable, not an optimization
  (dossier F2).
- Pass the contact's `modified_at` as `Avatar`'s `cacheBust` so a photo change
  refreshes the decode.
- `expo-image` makes zero network calls for a local `file://` source; the read
  path stays offline. `search`/list projections that omit a photo pass
  `photo={null}` (the intended initials state), as `FuelSearchResultRow` does.

## Reference Layout (owner-adjustable — NOT binding)

A sensible starting point the owner may freely redesign (HANDOFF §12.4):

- **Dashboard:** vertical stack — birthday banner (when non-empty) → count header
  + search box → horizontal scrollable chip row → sort control → `FlatList` of
  cards → footer entries ("Not yet contacted (N)", "Archived").
- **Card (list row, full-width):** avatar left (≈48–56px), a middle column with
  name (top) + one-line fuel preview (below), status ring around/beside the
  avatar, category label + favourite star in a trailing/top-right region. One tap
  target = the whole row.
- **Never-contacted screen:** same card component, its own sort control
  (defaulting to Oldest-added), its own Back chrome.
- **Manage favourites:** a simple reorderable list of avatar + name + drag handle.

Exact sizes, arrangement, ring rendering, chip shape, banner styling, and the
favourite marker glyph/placement are the owner's to set.

## Owner Decisions Required (owner's bucket — new tokens / taste)

These are genuinely open and in the owner's bucket (visual taste + new-token risk
posture). The executor must NOT close them by inventing hex values or binding
taste. Surface at plan review.

1. **Status-ring band tokens (blocks pixel implementation of the ring).** The card
   needs a status colour for `stable`, `wobble`, and `decay`. Only `rogue`
   (#E0904A) exists. Options: (a) owner approves three new hexes seeded into
   `space-dark` (like `rogue`/`gravityTiers`), or (b) owner defers the coloured
   ring and the card ships a text/shape status indicator using existing tokens
   until domain 9 defines the full status/rogue visual language. Recommend (a) —
   three attention-graded hues (calm→warm) harmonised with `#0B0E1A`, distinct
   from `accent` and `danger`.
2. **Favourite marker.** Provisional = an `accent` star. Owner may want a dedicated
   favourite token (e.g. a warm gold) and/or a specific glyph (star vs pin) and
   placement. Confirm the icon source (a vector set vs a text glyph) — no icon lib
   ships in `src/` yet.
3. **Rogue card visual.** Confirmed to **inherit domain 9's** definitive rogue
   rendering; this phase uses the `rogue` token as a placeholder. Owner/domain 9
   own the final treatment — flag any expectation that the dashboard finalise it.
4. **Category-label chip styling.** Recommended: `surfaceElevated` background +
   `textSecondary` label (no new token). Confirm, or approve a distinct
   category-accent token if the owner wants categories colour-coded (that WOULD be
   a new token set, one per category — flag as owner decision if desired).
5. **Exact card/grid layout, sizes, spacing arrangement, banner + chip styling.**
   Owner's design pass (HANDOFF §12.4).
6. **Drag-reorder library** for Manage favourites — a planning decision that adds a
   dependency; owner confirms at plan review (risk/posture is the owner's bucket).
