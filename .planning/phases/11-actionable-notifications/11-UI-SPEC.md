# Phase 11 — UI Design Contract

> Visual and interaction contract for the in-app surfaces Phase 11 adds. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope reminder.** The notification shade is **system-rendered — NOT app UI**; its copy is fixed in CONTEXT.md and reproduced here as reference only (§ "Fixed upstream"). This phase's *designed* surfaces are: (1) Settings → Notifications section, (2) the Edit-form "Mute reminders" toggle, (3) Profile in-app snooze presets, (4) the `POST_NOTIFICATIONS` value-moment + denial-degraded state. All four match existing screen idioms — this contract prescribes tokens/copy/states/testIDs, not new visual language.

## Design System

| Property | Value |
|----------|-------|
| Tool | **none** (React Native / Expo — not a web/shadcn stack; the shadcn gate is not applicable) |
| Preset | not applicable |
| Component library | none — hand-rolled RN primitives (`Pressable`, `Switch`, `Modal`, `ScrollView`, `Text`, `View`). No new UI dependency is justified for this phase. |

| Time/date picker | `@react-native-community/datetimepicker` (already registered in `app.config.ts`, Phase 4) — reused for the new delivery-hour and quiet-window controls with `mode="time"`. No new dep. |

**Hard constraints inherited (CLAUDE.md):** no hardcoded colours anywhere (incl. Skia); changing the theme profile must restyle every new control; portrait-locked; `formatLocalDate()` / `date('now','localtime')` for all local-date math; single-writer recency via the shared mutex.

## Spacing Scale

The project's established scale (read from `SettingsScreen`, `EditContactScreen`, `ContactProfileScreen`, `OverflowMenu`). New Phase-11 controls use the 4-multiple values below.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | hairline / inline nudges |
| sm | 8px | compact spacing; toggle-row internal, button vertical padding |
| md | 12px | default gap between setting rows / form fields (`content.gap`, `field` spacing) |
| lg | 16px | screen `content` padding; row inner padding; sheet option horizontal padding |
| xl | 24px | header/title block, section separation, modal horizontal inset |
| 2xl | 48px | (available, unused this phase) |
| 3xl | 64px | (available, unused this phase) |

**Exceptions (inherited, do NOT re-specify or "fix"):** existing shared chrome uses `10px` (settings `row.gap`) and `14px` (Back-button `paddingHorizontal`, `OverflowMenu` option `paddingVertical`). These live inside already-shipped components the new controls sit *inside* or *beside* — leave them untouched. New controls this phase introduces use only 8 / 12 / 16 / 24.

Corner radius (inherited): rows `10`, buttons/back `8`, sheets/modals `12`. Touch targets: interactive glyph/row min `44px` (established in `OverflowMenu.trigger`), `Switch` is platform-native size.

## Typography

Three sizes, two primary weights (matches the existing screens). RN styles set no `lineHeight` on single-line labels; the ratios below are the contract for any **multi-line** text this phase adds (helper lines, the degraded note).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Screen title (heading) | 24px | 700 | 1.2 |
| Row / toggle label · body | 16px | 600 (label) · 400 (body) | 1.5 |
| Helper · caption · status | 13px | 400 | 1.4 |

**Weights:** two primary — **regular 400** and **semibold 600**. `700` is reserved for **screen-title headers only** (inherited chrome: `title`, `OverflowMenu.glyph`), not applied to any per-control text this phase adds.

Colour-by-role: titles/labels → `textPrimary`; helper/caption/status/section-heading → `textSecondary`; accent text (links, "Add details", selected-preset label on filled accent uses `background`).

## Color

60/30/10 read against the shipped `space-dark` dark palette. Every value below is a **token**, never a literal.

| Role | Token (value) | Usage |
|------|---------------|-------|
| Dominant (60%) | `background` (#0B0E1A) | screen background (`ScrollView`), scrim base |
| Secondary (30%) | `surface` (#141828) · `surfaceElevated` (#1D2235) | setting rows / cards / form fields (`surface`); modal sheets, `Switch` thumb (`surfaceElevated`) |
| Accent (10%) | `accent` (#6C8CFF) | see reserved-for list |
| Destructive | `danger` (#E5484D) | **not used this phase** — no destructive action exists here (mute and snooze are both reversible) |

**Accent (`colors.accent`) reserved for — this phase, exhaustively:**
1. The **on/true track** of every `Switch` (master, decay, birthday, lock-screen, mute) — `trackColor={{ false: colors.border, true: colors.accent }}`, `thumbColor={colors.surfaceElevated}` (established `EditContactScreen` contract; do not deviate).
2. The **selected** in-app snooze preset (filled-accent idiom, per `FilterChipRow` active state: fill `accent`, border `accent`, label `colors.background`).
3. Accent **text** on the tappable delivery-hour / quiet-window value and any inline "Turn on in settings" link affordance (`textPrimary` label + `accent` value/link), matching the "Add details" accent-text idiom.

**Never** apply `accent` to: static row backgrounds, inactive toggles, section headings, helper text, or as a blanket "all interactive" colour. Borders use `border` / `borderStrong`; disabled/off states use `border` + `textSecondary`. No status colours (`rogue`, `gravityTiers`, `danger`) appear on any Phase-11 surface — notifications and their settings are state-neutral.

## Component Inventory (Phase-11 surfaces)

Prescriptive per-surface contract. All controls are token-only, `testID`-carrying, and `accessibilityLabel`-carrying (on-device uiautomator asserts against these).

### 1. Settings → Notifications section

Container `View` at the top of `SettingsScreen`'s scroll content (above the existing rows), each control a `styles.row` (surface bg, `border`, radius 10, padding 16). Reuse the section idiom already in the file.

| Control | testID | Widget | States |
|---------|--------|--------|--------|
| Section container | `settings-notifications-section` | `View` | — |
| Master toggle | `settings-notifications-master` | `Switch` | on / off / undetermined-permission (off appearance) |
| Decay reminders | `settings-notifications-decay` | `Switch` | on / off · **disabled + dimmed when master off** |
| Birthday alerts | `settings-notifications-birthday` | `Switch` | on / off · **disabled + dimmed when master off** |
| Lock-screen visibility | `settings-notifications-lockscreen` | `Switch` | on (public) / off (private, **default**) · disabled when master off |
| Reminder time | `settings-notifications-time` | `Pressable` row → native time picker (`mode="time"`) | shows formatted value; opens picker on tap; disabled when master off |
| Quiet-hours start | `settings-notifications-quiet-start` | `Pressable` → time picker | shows start value; disabled when master off |
| Quiet-hours end | `settings-notifications-quiet-end` | `Pressable` → time picker | shows end value; disabled when master off |
| Degraded note | `settings-notifications-degraded` | `Text` | visible only when master-on requested but OS permission denied |

**Disabled/dimmed convention:** disabled sub-controls keep `surface` bg with label in `textSecondary` and `Switch` `disabled` (no accent track). No new token needed.

### 2. Edit form → "Mute reminders" toggle

The `reminders_off` `Switch` **already exists** at `EditContactScreen.tsx:679-693` (testID `edit-contact-reminders-off`), beside "Rarely responds", already wired to `form.remindersOff`. **This phase's UI change is copy-only:** relabel the visible `Text` and `accessibilityLabel` from "Turn off reminders" → **"Mute reminders"**, and add the helper line "Keep them in Orbit, but never get reminders about them." Keep testID, position (immediately after the "Rarely responds" `field`), token styling, and the on/off `Switch` contract unchanged. Do **not** rebuild the control (CONTEXT code_context: verify-don't-rebuild). Phase 11's real work is wiring `reminders_off` into the decay-suppression predicate — out of UI-SPEC scope.

### 3. Profile → in-app snooze presets

A `Snooze reminders` block on `ContactProfileScreen`, placed with the action buttons (near "Message" / "Log contact"). Three preset `Pressable`s in a row using the **`FilterChipRow` filled-accent idiom** (selected = `accent` fill + `background` label; unselected = `surface` + `border` + `textSecondary`), plus a status line and a clear affordance when a snooze is active.

| Control | testID | Notes |
|---------|--------|-------|
| Section container | `contact-profile-snooze` | label "Snooze reminders" (`textSecondary` section-heading idiom) |
| 3 days preset | `contact-profile-snooze-3d` | writes `snooze_until` = today + 3d (`date('now','localtime')` math) |
| 1 week preset | `contact-profile-snooze-1w` | today + 7d |
| 1 month preset | `contact-profile-snooze-1m` | today + 1 month |
| Active status | `contact-profile-snooze-status` | "Snoozed until {date}", `textSecondary`, shown only when `snooze_until` is in the future |
| Clear snooze | `contact-profile-snooze-clear` | NULLs `snooze_until`; shown only when snoozed |

**Distinct from the notification's fixed +1-week headless snooze** — these are the in-app presets (CONTEXT). Reversible, non-destructive, no confirmation. The `snooze_until` storage contract is already documented at `dashboard-read.ts:33` (compare against `date('now','localtime')`); this is that contract's first writer.

### 4. Permission value-moment + denial-degraded state

- **Trigger:** the system `POST_NOTIFICATIONS` prompt is requested at a **value moment** — when the user flips **Allow notifications** on, or on first-contact-added (dossier Cluster D). Never a cold first-launch ask. No custom pre-prompt modal is designed; the master toggle *is* the in-app affordance.
- **Granted:** master + sub-controls become active per §1.
- **Denied:** master toggle returns to off; the `settings-notifications-degraded` note renders **once, inline, calm** with the "Notifications are off" copy. No repeat prompt, no red/danger styling, no blocking dialog. Dashboard/orrery remain the source of truth (CONTEXT pick 6).

## Interaction States Summary

| Surface | States to implement |
|---------|--------------------|
| Master toggle | undetermined → on (→ system prompt) → granted / denied(→degraded) → off |
| Per-type + lock-screen + time + quiet controls | enabled (master on) / disabled-dimmed (master off) |
| Lock-screen toggle | default **off** = private; on = public (maps to the second/public channel) |
| Mute toggle | off (default) / on — reversible, no confirm |
| Snooze presets | none-selected / snoozed-until-{date} (+ clear) — reversible, no confirm |
| Degraded note | hidden / visible-once (permission denied) |

## Accessibility & testID Register

Every interactive control carries `accessibilityRole` + a human `accessibilityLabel` matching its visible copy, and a stable kebab `testID` (register above). Toggles expose on/off via `Switch` value (uiautomator reads `checked`). `Pressable` picker rows use `accessibilityRole="button"` with the label naming the current value (e.g. "Reminder time, 9:00 AM"). Disabled controls set `accessibilityState={{ disabled: true }}`. These labels are the on-device UAT contract (adb `uiautomator dump`), per the project's "verify UI on the Pixel" mandate.
