<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| notification action tap → DB write | headless/foreground taps write to contacts/interactions/events |
| notification data payload → handler | data.contactId drives which contact is written |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-MUTEX | Tampering | headless/foreground action writes | high | mitigate | Mark → recordTouchpoint (single-writer mutex); snooze → snooze-dao (mutexed). No raw UPDATE anywhere in the action path; the headless task cannot reach the launch reconcile (Pitfall 5). |
| T-11-DUP | Tampering | duplicate action delivery (warm double + cold replay) | high | mitigate | Deterministic `actionUid()` uid → a re-delivered/replayed tap collides on UNIQUE(uid) (interactions/events) and is swallowed as a benign no-op; an in-process `handledSet` short-circuits warm double-delivery; 11-12 clears the last response after handling. No fresh `newUid()` (the defeated-constraint H2 bug). Proven by the exactly-once unit test + the A2 Pixel-UAT single-row assertion. |
| T-11-BOOT | Denial of service | killed-app DB access | high | mitigate | The shared handler `await openAndMigrate()` (idempotent) before `getExecutor()`, so a headless launch (no React mount) has a live migrated DB instead of throwing "getDb() called before openAndMigrate() completed" and silently dropping the write (review H1). |
| T-11-SPOOF | Spoofing | data.contactId | medium | mitigate | data.contactId is app-minted at schedule time (not user-supplied); recordTouchpoint/snooze-dao assert the row exists (changes===1) so a stale/missing id fails loudly rather than corrupting another contact. |
</threat_model>
