# Phase 38.9 Plan 06: Settings/backup/import/Systems Alert sweep and app-wide contract Summary

**The last native `Alert.alert` sites (backup, restore, archived contacts, the Settings children, custom fields, import, duplicate review, reconcile and Systems) are now themed `confirm()` / `notice()` dialogs or snackbars. A source contract now fails the build if any file other than `HomeScreen.tsx` (one snooze dialog, D-10) reaches React Native's Alert in any import form. "Export readable JSON?" cannot be dismissed, because both of its buttons run an export. ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Leave import? keeps its hold through the Leave path**
- **Found during:** Task 2
- **Issue:** The plan says to clear `promptPendingRef` when the confirm settles, true or false. On Leave, `discardUnresolvedSession` is async, so clearing on settle would let a Back during the discard open a second "Leave import?" prompt.
- **Fix:** The hold clears at once on Stay. On Leave, it is cleared in a `finally` after `leave()` has dispatched; `leaving.current` is true by then. The plan's required behaviour still holds: one confirm per double Back, and asking again after Stay.
- **Files:** src/screens/use-import-leave-guard.ts

## Out-of-scope findings (for owner)
- **Dedupe stops the second dialog, but not the second action.** With the dedupe as specified, a fast double tap on, say, Merge shows one dialog. Both taps' handlers then receive the same answer, so on "Merge" the merge is still attempted twice. The second attempt fails safely, as Plan 05 found ("both contacts must be live"), and is shown as the failure message. Turn off encryption and Delete System behave the same way: a repeat that fails, or does nothing. **Recommendation:** for the few irreversible handlers, add a per-handler in-flight guard (the pattern `runSingleFlight` already uses on Duplicate review), or have the store give duplicate callers `false`. The second option changes the planned semantics, so it is your call; I would take the per-handler guard as a phase code-review nit.
- **`src/navigation/tabs/BackupStack.tsx` is still dead code** (found by 38.9-03). The new background listener is per-mount and shares the one controller, so it is safe even if that stack were mounted. **Recommendation:** delete it in a cleanup chore. This is unchanged from Plan 03's note.
