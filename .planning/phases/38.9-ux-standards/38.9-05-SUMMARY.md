# Phase 38.9 Plan 05: Everyday-surface Alert sweep Summary

**Every native `Alert.alert` on Profile, the Profile editors, Edit Contact, Edit interaction, Off Limits, Merge, Crop, Links, Capture, Compose, the assist banner and pending sheet, the reach-out handoff, the contacts-permission helper and widget linking is now a themed `confirm()`, a themed one-button `notice()`, or an error snackbar. The irreversible actions use non-dismissable destructive confirms, and the existing copy is kept.**

- **Confirms (C):** Delete off-limits item, Unbind (labels kept: "Keep contact bound" / "Unbind contact"; D-09, D-32, ADR-150), Reset Profile presentation, Merge contacts and Delete background template are `destructive: true`, so Back and the scrim cannot dismiss them (D-06, ADR-086). ## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Background discard used a stale state snapshot**
- **Found during:** Task 2
- **Issue:** The discard handler read `managerState` from the closure taken when the prompt opened. If a crop finished while the (now async) prompt was open, Discard would miss the freshly written pending derivative file and leave it behind. The native Alert closure had the same weakness.
- **Fix:** A `managerStateRef` holds the latest state, and the handler reads it when the prompt resolves.
- **Files:** src/components/profile/ProfileBackgroundManager.tsx
- **Commit:** 44aa2ad4

## Out-of-scope findings (for owner)
- **A double tap queues two of the same confirm.** `confirm()` queues FIFO, so tapping e.g. "Merge" twice quickly shows "Merge contacts?" twice. If the second is also confirmed, the merge is tried again. It fails safely ("both contacts must be live", caught and shown as the failure message), so no data is at risk. The same applies to any confirm opened from a tap. **Recommendation:** have confirm-store ignore a request identical to one already queued (a small Plan 01-area follow-up). Fold it into Plan 06 if that plan touches confirm-store; otherwise make it a nit for the phase code review.
- **Stale comment:** `src/services/assist-commit.ts:45` still says "Content-free Alert copy". It is a comment only and the AST contract ignores it. **Recommendation:** reword it when Plan 06 adds the app-wide contract.
- **Discard prompt copy change (intended, flagged for visibility):** the three Profile editors lose their own second line ("Your layout/template/background changes have not been saved.") and show the shared "Your unsaved changes will be lost." **Recommendation:** none (this is D-13/D-52); include one of them in the plan-17 screenshots.
