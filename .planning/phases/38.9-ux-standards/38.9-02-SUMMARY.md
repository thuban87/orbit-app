# Phase 38.9 Plan 02: Unsaved-Work Guards Summary

**The route guard now has a sub-editor variant: Back closes the innermost open editor first, and a "Discard changes?" prompt appears only when typed text would be lost. Every editor Cancel and every Memories/Key People fold goes through the same `requestClose`. The guard is wired into Add Contact, Log Interaction, + → Memory, AI Writing Style, Update Contact, Custom fields, and the open drafts on Add Contact and Edit Contact.**

## Accomplishments
- **Guard core** (`discard-keep-guard.ts`):
  - `decideGuardOnRemove` returns `allow`, `prompt-leave`, `close-sub-editor` or `prompt-close-sub-editor`, and `actionType` is now required. Bypass is checked first.
  - The sub-editor outcomes apply only to `GO_BACK` and `POP`. Any other action (RESET, NAVIGATE, …) proceeds at once unless typed work would be lost. In that case Discard dispatches that same action (C6-H1).
  - `useDiscardKeepGuard` takes an optional `subEditor` and returns `requestClose(close, dirty)`. It shares the pending-prompt ref, so no second prompt can be queued.
  - The doc comment records why Android needs no `usePreventRemove` (review M5).
- **Add Contact (E-01):**
  - Every seeded `useState` starts from `createFormSeedState()`. The baseline is a module constant built from that seed, so the guard is on from the first render.
  - The bypass is set on the line before `navigation.replace("Profile")` and reset if the write throws.
  - Duplicate-name now uses `confirm` (dismissable), a load failure shows `notice`, and a save error shows an error snackbar. No `Alert` remains in the file.
- **Log Interaction (F-01):** the guard compares against a snapshot taken inside `seed()` (both the try and the catch path). It is off while the picker shows, and the bypass is set right before the save `goBack()`.
- **+ → Memory (G-12):**
  - `MemoryEditor` gains optional `onDraftStateChange`, `onCancelRequest` and a `closeDraft` ref, plus pure `isMemoryDraftDirty` / `memoryDraftState`.
  - `MemoryScreen` uses the sub-editor variant and routes Cancel through `requestClose`. The savedTick save sets the bypass.
- **AI Writing Style (D-34):**
  - The dirty check compares all four fields. Loads and saves go through the token-gated `applyStyleLoad` / `applyStyleSave` (C4-M4, C5-L1, C6-L5).
  - Section drafts count too (`hasSectionDraftChanges`; `SectionEditor.onDirtyChange`).
  - A save now shows a "Saved" snackbar instead of the inline message.
- **Update Contact (E-09):**
  - Each focused editor reports dirty against its own seed through `isRowDraftDirty`: text, methods, frequency (C4-M2, C5-L6) and custom field. Off Limits re-seeds per edit (C4-M3).
  - The Custom Fields chooser's selection moved up into the screen (`genericSelectedDefId`). The key-person form is the inner level.
  - `resolveUpdateEditorClose` + `closeLevel` handle Back and every Cancel.
  - `FrequencyPicker` gains an optional `onDraftChange`.
- **Custom fields (G-04):** `FieldDefForm.onDirtyChange` + `isFieldDefDraftDirty`. Both FieldDefForm Cancels go through `requestClose(closeEditor, editorDirty)`. Successful create/edit still closes directly.
- **Add Contact and Edit Contact drafts (C5-M1, D-13, D-68):**
  - Both screens pass `onDraftStateChange` and a `closeDraft` ref to their MemoryEditor and RelationshipEditor, plus a `subEditor` from `pickCreateSubEditor`.
  - Folding Memories or Key People goes through `requestClose`.
  - Edit Contact's `hasUnsavedChanges` and its save bypass are unchanged.
- **D-55:** the fab-clearance contract now pins `useBottomClearance()` on both FieldDefForm instances, applied as `paddingBottom`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Edits typed and then erased read as untouched**
- **Found during:** Tasks 2 and 3
- **Issue:** MemoryEditor and RelationshipEditor seed optional text as `null`, and typing then erasing leaves `""`. A strict comparison would keep a cleared draft "dirty" and prompt for nothing.
- **Fix:** `isMemoryDraftDirty`, `isRelationshipDraftDirty` and the custom-field comparator compare optional text blank-equivalently. Off Limits and current-state text compare exactly, as the plan's seeds specify.
- **Commits:** 4cec455e, 593c1526

**2. [Rule 1 - Bug prevention] FieldDefForm seed normalisation**
- **Found during:** Task 3
- **Issue:** The form rebuilds `options` through `buildOptions`, which trims and de-duplicates. A stored dropdown whose options are not already in that form would read as dirty with no user change.
- **Fix:** The seed is compared after the same `buildOptions(parseOptions(...))` pass.
- **Commit:** 593c1526

**3. [Process] Contract-test adjustments after RED.** Two things changed between the RED commit and GREEN, both in test code:
- The editor-cancel contract's AccordionSection slicer was replaced with a balanced-brace extractor, so formatter line breaks cannot break it.
- The Update Contact "raw onCancel" check now targets `renderActiveEditor` instead of every `onCancel={onCancel}`. The editors legitimately pass their own prop through to `EditorFrame`.
- Separately, the method-groups test builds its data through a helper. This avoids a TypeScript excess-property error.

**4. Tracer feedback gate.** The config is interactive (`auto_advance: false`). Under the owner's standing preference (memory execution-autonomy-only-serious-stops), I re-ran the tracer's automated `<verify>` after Task 1 (3 files + tsc, all passing) and continued.

**Total deviations:** 2 auto-fixed (correctness) plus 2 process notes. **Impact:** none on scope. No recorded decision was touched, and there is no schema or migration change (D-12).
