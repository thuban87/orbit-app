# Phase 38.9 Plan 13: One Date Formatter, One Empty State, Two Date Pickers Summary

**Dates now read the same everywhere: "Oct 13" this year, "Jun 2, 2025" otherwise, and "Tue, Oct 13" where the day matters. A stored birthday always shows its year when it has one. Contacts' no-match, Events and History share one empty state, each with one action. A Memory's meaningful date and a custom Date field are now picked with the phone's date picker and stored as YYYY-MM-DD. A stored value that is not a date stays visible as written, marked "Not a date", until you pick or clear.**

## Accomplishments

- `src/utils/dates.ts` now has the one date-only display formatter (`formatDisplayDate`, `formatDisplayDateOrFallback`), `formatMonthDay`, `formatStoredBirthdayForDisplay` (D-70), and the four shared month and weekday tables. `formatLocalDate` stays the storage function. A source contract (`display-date-contract.test.ts`) guards all of this: no `toISOString().split`, no display formatter in `src/db`, `edit-contact-logic.ts`, `picked-contact-map.ts`, `reconcile-diff.ts` or `compose-research-read.ts`, none assigned to a key or testID, and `buildBirthdayForStorage` output unchanged.
- Converted sites: the Digest day detail (weekday form), the Digest birthday tag (Today/Tomorrow kept, otherwise "Sep 25", with a separate `dateKey` in storage form), the last-spoke date segment (shown and announced), "Snoozed until", Recently Deleted (date part), the week heatmap's cell labels, custom Date values on the Profile and on Things to Remember (after the same `parsers.date` parse), and History's day headers and empty-day note ("Nothing logged on Tue, Oct 5"; D-53, D-57). History and the activity heatmap no longer keep their own month/weekday arrays.
- All five stored-birthday displays (Edit Contact label, Things to Remember, Merge conflicts, Research, Reconcile) go through `formatStoredBirthdayForDisplay`. This is render only: Merge's `differs()`, the merge and reconcile resolutions, Research's item value and the reconcile diff stay raw.
- `EmptyState` (icon in a bordered disc, heading, one help line, one primary action, truncated search echo). It calls `useTheme()` itself, so it reads the glass palette inside the ChromeScrim. It is used by the Contacts no-match state ("Clear search"), the three Events states ("Try again", "Clear search", "Log an event", which opens Group Log with no params) and History ("Log interaction", with its testID, layout signal and refresh notice kept).
- Native pickers: MemoryEditor's free-text "Meaningful date" is now a labelled tap-to-pick row with Clear. Every change goes through `update(...)`, so Plan 02's draft guard sees it. `DateFieldWidget` is a picker row with Clear (emits `""`). It never calls `onChange` on render, so a stored custom-field value is never rewritten. Neither picker sets a date range or offers "year unknown". Memory cards and the Profile memory line show the formatted date, or the raw value if it is not a date.
