# Phase 38.9 Plan 03: Overlay, Capture and Backup-Schedule Guards Summary

**The unsaved-work rule now also covers the surfaces that are not plain routes. On the pending-confirmations sheet, Back or a scrim tap asks "Discard changes?" while a typed note would be lost. On Capture, Back closes the innermost surface first and protects a typed name or note. The Backup schedule saves each day field when it is left, so the "Save schedule" button is gone.**

## Accomplishments

- **Pending confirmations (J-07; D-13/D-14 overlay variant):**
  - `AssistConfirmation` gets an optional `onNoteDirtyChange`. The inline banner passes nothing and is unchanged.
  - The sheet keeps a set of dirty uids. Both close paths (`onRequestClose` and the scrim) go through one `requestSheetClose`. It prunes the set against the live queue and calls `confirmDiscard()` only if a typed note remains.
  - A failed confirm leaves the item and its note in the queue, so closing still prompts. An item that leaves the queue stops counting.
  - The set is cleared on every real close, and whenever `visible` turns false.
  - A second close request while the prompt is pending gets false from the single-flight `confirmDiscard()`.
- **Capture (D-33, with D-14 enforced inside it):** `resolveCaptureBack` decides in this order: New-contact surface, search, multi-select, note, cancel.
  - A typed name prompts before the New-contact surface closes.
  - A typed note prompts before the capture is cancelled. Discard cancels as before: the rows are already written, only the note is lost.
  - An empty name or note closes at once. The handler always returns true.
- **Backup schedule (D-34):** `createBackupDayController` is a pure factory with an injected `write`. It holds:
  - per-field versions;
  - at most one write in flight per field;
  - drain requests tagged with their origin (blur or leave);
  - `leaveAttemptedVersion`, so each leave tries a given version at most once;
  - a read sequence, so no refresh overwrites newer or pending typing and no read reverts a later commit;
  - an idle-field reset on attach and on each focus gain.

  The screen uses one module-scoped instance and only forwards events to it: keystroke, blur, submit, focus, focus-effect cleanup, `beforeRemove` (never `preventDefault`), unmount, and read start and land. A failed write shows the error snackbar "Couldn't save backup settings" (D-27). The "Save schedule" button, `saveDays` and the native Alert it used are removed, which also completes Plan 06's BackupSettingsScreen :212 row.

- **Backgrounding the app does not save a typed day count.** The schedule saves on blur, submit, focus loss, Back and unmount. Pressing Home with the field still focused triggers none of these. If Android then kills Orbit in the background, the typed number is lost. Recommendation: add an `AppState` "background" leave-flush to the controller. It is a few lines, and Plan 06 already touches BackupSettingsScreen. I did not add it because the plan names exactly three leave sites.
- **The inline assist banner's note is not guarded.** `AssistBanner` renders `AssistConfirmation` keyed by the newest assist. If that changes (a new handoff arrives, or the item expires), a note typed in the banner is dropped. The plan explicitly leaves the banner unchanged, and it is not an overlay. Recommendation: none now. Revisit only if 38.10/38.11 rework the banner.
- **`src/navigation/tabs/BackupStack.tsx` is dead code.** It registers BackupSettingsScreen but nothing imports it. Harmless. If anything ever mounted both stacks, the shared day controller would still be correct, since it supports several listeners. Recommendation: delete it in a cleanup chore.
