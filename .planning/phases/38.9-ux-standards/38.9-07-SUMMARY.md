# Phase 38.9 Plan 07: Shell navigation — history Back, + over the current tab, Settings Add Contact, focused Research Summary

**Tab Back now follows visit history (`backBehavior="history"`) and always exits from Digest, using an in-place reset. The + opens its forms over whichever tab you are on. An Add Contact started from Settings finishes on a live Contacts-tab Profile. ComposeResearch is a focused route.**

## Accomplishments
- D-35 / D-54: `backBehavior="history"` on the tab navigator. In the root `hardwareBackPress` listener, when tab history is exhausted on a non-launch tab whose stack is at its root, `switchTabWithoutHistory(nav, "DigestTab")` runs and the press is consumed. The next Back exits from Digest. The helper is also the Phase 39 Orient hop.
- D-38: `FAB_ROUTES` lists the five + targets. All five are registered (and their params typed) in all five stacks. `resolveFabTarget`, the contact-picker flow and `resolveFabContactContext` keep the focused tab, so no `"DashboardTab"` literal is left in the + resolution paths. A test checks registration in every stack. A type-level check fails `tsc` if a + screen is added to `FabNavigateIntent` without a `FAB_ROUTES` entry.
- D-50: Settings registers `Create` through `SettingsCreateHostRoute` (`host="settings"`). On Save, Create sets the guard bypass, pops the Settings stack with `goBack()`, then calls `openProfileInContactsTab`. That opens the Profile in Contacts with `navigateIntoTab` when the Contacts stack is not mounted, or focuses the tab and pushes the Profile onto a mounted stack, so an existing top Profile is never overwritten (T-38.9-18). Every other tab still does `replace("Profile")` (D-08).
- D-18: `ComposeResearch` is in `FOCUSED_WORKFLOW_ROUTES`. Its screen no longer calls `useBottomClearance`. The FAB-clearance contract now lists it as focused-only.
- D-11 / D-36 / D-37: no change to FAB visibility on browse surfaces, the mid-scroll clearance or the Contacts control panel.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Settings Contacts row-route type exceeded TypeScript's union limit**
- **Found during:** Task 2
- **Issue:** Adding four param-less + routes to `SettingsStackParamList` grew `settings-contacts-model.ts`'s `SettingsStackRoute` union from 24 to 28 members. TypeScript stops decomposing unions past 25 when it matches against `navigate`'s per-route overloads, so `SettingsContactsScreen.tsx:235` `navigation.navigate(row.route)` failed `tsc`.
- **Fix:** `SettingsStackRoute` now excludes `FAB_ROUTES`. Contacts rows never open + forms; only the + does.
- **Files modified:** src/screens/settings-contacts-model.ts
- **Committed in:** 6222d616

**2. [Rule 1 - Bug] JSX comment broke the D-31 dial accessibility source contract**
- **Found during:** Task 3's full-suite gate
- **Issue:** Task 1 placed a `{/* D-35 … */}` JSX comment between `<AssistBanner />` and `<Tab.Navigator>`. `universal-fab-contract.test.ts` pins that adjacency with a regex, and two of its tests failed.
- **Fix:** moved the note into the `<Tab.Navigator>` tag as a line comment above `backBehavior`.
- **Files modified:** src/navigation/RootNavigator.tsx
- **Committed in:** 6af91e81

**3. [Plan fact correction] ComposeScreen does not pad the bottom with the safe-area inset**
- The plan said to "pad the bottom with the safe-area inset the way ComposeScreen does". ComposeScreen (`styles.content` = `padding: 16, gap: 16`) uses no inset, and neither does any other focused screen (Create, Edit, LogInteraction, Memory, GroupLog, SystemBuilder, EditInteraction). ComposeResearch now matches Compose: it keeps its own `styles.content` padding and adds no inset.

**4. [Plan line drift, informational]** `UpdateContactScreen`'s props are at :952 (the plan said :813). `CreateContactScreen`'s save `replace` is at :476. The behaviour matched the plan.
