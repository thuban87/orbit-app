# Phase 38.9 Plan 04: Inline Validation (FieldError + Scroll-to-First-Error) Summary

**Validation errors now show directly under the field they belong to. Save scrolls to that field and focuses it, and Save stays pressable. This covers Add/Edit Contact's name, the Group Log title, the System builder name, the Contacts bulk-frequency sheet and the Photo URL field. The scroll measures against the ScrollView's content view, not a numeric `findNodeHandle`, so it no longer fails silently. Remove photo is now a themed destructive confirm that Back and scrim taps cannot dismiss.**

## Accomplishments

- **The primitive (D-19):**
  - `FieldError` is caption text in `colors.danger` with `accessibilityLiveRegion="polite"`. It renders nothing when there is no message.
  - `useFirstErrorReveal()` returns `scrollRef`, `contentRef` and `reveal(node, focus?)`. The reveal waits one frame, measures against the ScrollView's `innerViewRef` content view, scrolls to `y - 16` and focuses the field.
  - `field-error-logic.ts` holds the pure helpers: `firstBlockingField`, `clearFieldError` (returns the same record when the field had no error) and `toFieldErrors`.
- **Add Contact and Edit Contact (E-02, E-X01, D-03):**
  - Pressing Save with an empty name shows "Enter a name to save." under Name. Identity expands, the Name field scrolls into view and it takes focus.
  - Typing clears the error. Save stays pressable.
  - `findNodeHandle` is gone from both files, and a source assertion keeps it out.
- **Group Log (F-12):**
  - The title error is its own `titleError` state, shown under Title and cleared by typing.
  - An empty-title Save reveals and focuses Title and writes nothing.
  - A save failure stays in `error`, above Log group, and typing does not clear it.
- **System builder (K-08, D-69):**
  - The name error is its own `nameError` state, shown under Name. Load, save and reset failures stay in `error`, in the header area, and stay visible on the Members page.
  - Save System pressed in Preview with no name leaves Preview, sets the page to Definition and shows the name error. The Name reveal runs only once the Definition page is mounted. Nothing is saved.
- **Contacts bulk-frequency sheet (A-13, D-40):** an invalid number shows the error inline under the field inside the sheet, not as a snackbar behind it. The announcement stays, and the error clears when the value changes or the sheet reopens.
- **PhotoSourcePicker (D-40, D-27, D-30):**
  - URL validation errors appear inline under the URL field.
  - Library, remove, fetch and unusable-image failures show error snackbars with the existing words.
  - Remove photo is `confirm({ destructive: true })`, which cannot be dismissed (ADR-086).
  - The `Alert` import is removed.
