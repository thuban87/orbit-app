# Phase 38.9 Plan 12: Themed Option Sheet Summary

**One themed `OptionSheet`, generalised from the category sheet, now handles every single choice in the app. That covers category, social battery, channel, direction, tone, contact-method label and custom-field dropdowns, at every list length. No native picker import is left, and a contract keeps it that way.**

## Performance

- **Duration:** 24 min
- **Started:** 2026-10-11T11:20:47Z
- **Completed:** 2026-10-11T11:44:55Z
- **Tasks:** 3
- **Files modified:** 23 (6 created, 17 modified)

## Accomplishments
- `OptionSheet<T>` is a BaseOverlay sheet, so it registers as open and hosts snackbars (D-24). Its selected row uses the D-05 top tier: `accent` fill and `onAccent` label. It also has `accessibilityState.selected` and a filled `select` glyph in `onAccent`, so selection never depends on colour alone (RG-030). Search appears only above the category threshold.
- `OptionSelectRow` is the trigger at every site. It is 44dp tall, shows a chevron, and announces the field name plus the current value through `selectorAccessibilityValue`.
- `CategoryChoiceSheet` is now a wrapper over the shared sheet. All its behavioural tests still pass: search starts at 13 categories, not 12; the no-match copy is unchanged; a stale selection is kept; a pick selects and closes; the query resets.
- All nine native picker sites now use the sheet. "No selection" is the null option. A stored value outside the option set (a legacy channel, an unexpected social battery value) appears raw on the trigger and is never rewritten.
- `DropdownFieldWidget` ("Met via") builds its list through `selectorItems(selected, options)`. An out-of-list stored value stays listed first and selected, and is never cleared or coerced (CLAUDE.md custom-field invariants). Its RegisteredModal is gone.

## Decisions Made
- **The plan said expanded, and I kept it.** The 92% expanded sheet is the shape already proven on a device. The mockup's reference panel shows a shorter sheet over a dimmed form. A compact variant for short lists would need a bounded FlatList that only a device can confirm. See the out-of-scope findings.
- **`useUnscopedTheme()` in OptionSheet.** The old CategoryChoiceSheet used `useTheme()`, which could pick up a glass card's palette for the opaque sheet surface. ConfirmDialog uses the unscoped theme for the same reason.
- **Search is decided once.** Screens no longer import `CATEGORY_SEARCH_THRESHOLD`. CategoryChoiceSheet decides search from the eligible real categories (the same > 12 rule as `shouldSearch`), and other OptionSheet callers default to `shouldSearch(options.length)`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Re-picking "Other" would have wiped a custom contact-method label**
- **Found during:** Task 1
- **Issue:** The native spinner fires only on change, but the sheet calls `onSelect` on every tap. With the plan's "Other → empty label" mapping, re-picking "Other" on a row labelled e.g. "Pager" would have cleared the typed label.
- **Fix:** `methodLabelChoice` and `nextMethodLabel` in the pure editor model. A no-change pick returns null and the editor skips the update.
- **Files modified:** `src/components/contact-methods-editor-model.ts` (+ test), `src/components/ContactMethodsEditor.tsx`. The model files were not in the plan's file list.
- **Verification:** `contact-methods-editor-model.test.ts` "method label option sheet rule" (3 tests)
- **Committed in:** `6640acb5`

**2. [Rule 2 - Missing critical] Behaviour test for dropdown data preservation**
- **Found during:** Task 3
- **Issue:** The only checks on the rebuilt widget were source-text contracts. Out-of-list preservation is a data-loss risk (T-38.9-30).
- **Fix:** New `DropdownFieldWidget.test.tsx`. It shallow-renders the widget and checks that the stored value is first and selected, is not duplicated, and that only a pick reaches `onChange`.
- **Committed in:** `2e48aae4`

**3. [Rule 3 - Blocking] The no-native-picker contract timed out under full-suite load**
- **Found during:** Task 3 wave gate (load average about 10)
- **Fix:** It now parses only files that spell the specifier, and has a 30 s timeout, matching `no-native-alert-contract` and `orbit-switch-contract`. Its self-tests still prove every load form is caught.
- **Committed in:** `2e48aae4`

**4. [Plan wording] `sheet-consumers-contract.test.ts` unchanged**
- The plan listed it "only if a new `<Sheet` block requires it". OptionSheet's block is expanded and CategoryChoiceSheet's block moved into it, so no change was needed. The contract passes as is.

## Out-of-scope findings (for owner)
1. **Short lists open a tall sheet.** Channel (3–5 items), Tone, Direction, social battery and the method label all open the 92% expanded sheet, as the plan specifies. The mockup's D-28 panel shows a shorter sheet over a dimmed form. *Recommendation:* include one short-list sheet in the Plan 17 D-28 mockup-match screenshots. If it looks too heavy, the fix is a compact variant for lists without search: a small change in `OptionSheet` plus a `sheet-consumers-contract` opt-out entry. It needs a device check of the bounded list.
2. **Category order changed on short lists.** The native spinner put "Uncategorized" first. The themed sheet, as it always did for more than 12 categories, puts it last (`buildCategoryChoices`). *Recommendation:* accept this. It now matches the existing sheet everywhere.
3. **Direction options still read in lowercase** ("outbound", "inbound", "mutual"), unchanged from the spinner. *Recommendation:* if you want plain-word labels ("I reached out", "They reached out", "Both"), it is a copy change for the D-41 wording pass (Plan 15) or 38.11. The labels are not changed here.
4. **Re-picking the same option counts as a touch on two import screens.** Import review's `setEdited(true)` and Bulk setup's `markEdited()` now also run when the current category is re-picked. Before, this only happened above 12 categories, where the themed sheet already behaved this way. *Recommendation:* no action; the stored value does not change.
5. **The `@react-native-picker/picker` dependency is still installed** (deliberately, per the plan, because removing it changes native autolinking). *Recommendation:* uninstall it in Plan 17, where native builds happen anyway, and rebuild the dev client.
