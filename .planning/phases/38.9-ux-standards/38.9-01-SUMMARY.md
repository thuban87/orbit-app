# Phase 38.9 Plan 01: Overlay and Dialog Foundation Summary

**An open-overlay registry with no close API, a `RegisteredModal` wrapper that every RN Modal window now goes through (each window carries its own snackbar host, and only the topmost one renders), and an imperative `confirm()`/`notice()` queue drawn by one `DialogHost`. The route guard prompt is now the themed, non-dismissable "Discard changes?" / "Keep editing" dialog.**

## Accomplishments
- `overlay-registry-store` (D-24): open overlay windows in open order, kinds sheet/dialog/modal, selectors `selectAnyOverlayOpen` (the Phase 39 D-58/D-97 signal) and `selectTopOverlayId`. It has no dismiss/close function, and a test checks that `shellTransientStore.dismissTop()` cannot reach a registered overlay.
- `RegisteredModal` registers its window while visible and renders `<Snackbar host={id} />`. BaseOverlay (Sheet, ConfirmDialog, CardContextMenu) renders through it, with the host as the last child of its root View inside `GestureHandlerRootView`. The ADR-086 `onRequestClose={dismissable ? onRequestClose : noop}` and the inert scrim are unchanged.
- Snackbar `host` prop (D-40/D-51): the root host renders only when no overlay is open, keeping its 112 dp tab-bar/+ clearance. An overlay host renders only when its window is on top, at `insets.bottom + 16`. ADR-173 rules kept: one `shellTransientStore(selectFabDialOpen)` call above the early return, one `fabDialBackgroundA11y` spread, a `collapsable={false}` box-none root. snackbar-store is unchanged, so the 6000 ms timeout still applies (D-04).
- `confirm-store` + `DialogHost` (D-24): FIFO queue; `effectiveDismissable = !destructive && (dismissable ?? true)` (D-06, ADR-086); `<ConfirmDialog key={id}>` per request (Pitfall 2); notice variant.
- ConfirmDialog: 2 dp `borderStrong` card (D-43); `dismissable` prop that BaseOverlay only ever receives through `effectiveDismissable(...)`; `headingGlyph` (defaults to `destructive`, D-52); `variant="notice"`. All 9 declarative consumers compile unchanged.
- Route guard (D-13/D-52): themed "Discard changes?" with "Keep editing" / "Discard changes". It is destructive (cannot be dismissed) and has no glyph above the title; the ⚠ stays on the button. A second Back while the prompt is open is blocked but opens no second prompt. `confirmDiscard()` is single-flight, reading the queue's `discard` marker; there is no module-level flag.
- All 20 raw RN Modal sites (19 files) now use `RegisteredModal` with their props unchanged. ContactPicker keeps its `"contact-picker"` shellTransientStore registration. The dead `ui/Modal.tsx` and its barrel export are removed.

## Decisions Made
- Host placement mechanism: a render prop (the plan offered a render prop or context). Context could not work: BaseOverlay renders RegisteredModal, so a context RegisteredModal provides is not readable in BaseOverlay's own body.
- Resolutions are bound to the request id (`resolveCurrent(value, id?)`, `dismissCurrent(id?)`). See deviation 1.
- `overlayKind` defaults to "sheet" on BaseOverlay. Only ConfirmDialog passes "dialog". Sheet.tsx was not edited for this.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Stale double-tap could resolve the next queued dialog**
- **Found during:** Task 2
- **Issue:** As specified, `resolveCurrent(value)` always resolves the queue head. A rapid double-tap on "Delete" would resolve the dialog, and the second tap would then resolve the *next* queued confirm before the user saw it.
- **Fix:** Added an optional `id` to `resolveCurrent` and `dismissCurrent`. They do nothing when the id is not the head. DialogHost binds every handler to the request id.
- **Files:** src/stores/confirm-store.ts, src/components/ui/DialogHost.tsx
- **Verification:** confirm-store.test.ts "ignores a stale resolution…", dialog-host.test.tsx "a stale press…"
- **Commit:** 4f41a4bc

**2. [Rule 2 - Test coverage] Added `src/components/ui/dialog-host.test.tsx`** (not in the plan's file list). It pins the DialogHost wiring: per-request key, destructive Back is a no-op, Cancel resolves false, the notice defaults to "OK". Commit 4f41a4bc.

**3. [Rule 3 - Blocking] Five render tests failed to load after the Modal swap.** They mock `react-native`'s `Modal` and call components as functions, so `RegisteredModal`'s `useId` and Snackbar's store hooks broke them. The fix mocks `@/components/ui/RegisteredModal` as the same `"Modal"` element, so their assertions are unchanged. Commit d52247e2.

**4. [Rule 3 - Blocking] Registered-modal contract timed out (5 s) under full-suite load.** The fix skips the TypeScript parse for files that cannot match (they lack either "react-native" or "Modal") and gives the test a 30 s timeout. Commit d52247e2.
