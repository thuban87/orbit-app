## Summary

The phase is large but mechanically regular. Most of it is "build one shared piece, then sweep N sites". There are three foundations everything else depends on: (1) an **overlay foundation**, a registry plus a snackbar host that renders inside the topmost RN `Modal`; (2) an **imperative dialog host**; and (3) a **`ShellAppBar` upgrade** (chevron Back, person line, `onBack` override). After those land, the conversions sweep: 24 decision Alerts and 76 error/info Alerts; about 31 header conversions; 9 pickers; 30 switches; 7+ date sites; and the glossary strings. The shell-navigation work (D-35, D-38, D-18) is independent of the overlays and can be planned separately.

Code reading settled several of the dossier's open engineering questions. **On Android nothing renders above an RN `Modal` from the main window.** `FullWindowOverlay` is iOS-only (it warns and falls back to a `View` on Android, `react-native-screens/src/components/FullWindowOverlay.tsx`). A portal into a main-window host stays under the Modal's window. So the snackbar must render inside the topmost overlay's own window. **React Navigation 7's `backBehavior="history"` de-duplicates its history.** After Digest → Contacts → Digest, Back goes to Contacts and then exits from Contacts, not from Digest. I confirmed this by running the installed `TabRouter`. Meeting D-35's "exits on the launch tab" therefore needs a small fallback. **The `pick-then` FAB flow is confirmed:** it resolves in `UniversalFab.tsx:311`, which also hardcodes `"DashboardTab"`. **D-38 per-tab hosting has one product consequence the owner must see.** An Add Contact started from the Settings tab would land on a *Settings-hosted* Profile, where hero Message is disabled by design (ADR-166 / 38.3 D-25).

**Primary recommendation:** Build the overlay registry, the in-window snackbar host and the imperative confirm/notice host as one foundation plan first. Register the + routes in every tab stack (not a root modal stack). Use `backBehavior="history"` plus an "in-place tab switch" helper. That helper serves both the launch-tab exit fallback and Phase 39's untracked tab hops.

### Pattern 1: Imperative confirm/notice host (D-24, D-27, D-43)

**What:** A Zustand store holds a FIFO queue of requests. `confirm(req): Promise<boolean>` and `notice(req): Promise<void>`. `DialogHost`, mounted once in `App.tsx`, renders the head of the queue through the existing `ConfirmDialog` (or a one-button notice variant of it).

**Verified facts it must respect:**
- `ConfirmDialog` today: hairline `border` and `surfaceElevated` card `[VERIFIED: src/components/ui/ConfirmDialog.tsx:109-110, 217 "borderWidth: StyleSheet.hairlineWidth"]`. D-43 changes **all** themed dialogs (including the 9 declarative consumers) to a 2dp `borderStrong` border. That edits `ConfirmDialog` itself.
- `dismissable={!destructive}` `[VERIFIED: ConfirmDialog.tsx:94 "dismissable={!destructive}"]`. This is pinned by `confirm-dialog-contract.test.ts:20-24` ("passes dismissable={!destructive}").
- `ConfirmActions` measures its layout once per mount (`useState<ActionsLayout>("measuring")`, and `measure` returns early unless `layout === "measuring"`) `[VERIFIED: ConfirmDialog.tsx:166-174]`.
- **Android native `Alert` is NOT cancelable by default**: `cancelable: false` is the default config `[VERIFIED: node_modules/react-native/Libraries/Alert/Alert.js:90]`. Only `ArchivedContactsScreen.tsx:68`, `CustomFieldsScreen.tsx:91` and `RestorePreviewScreen.tsx:57` pass `cancelable: true` + `onDismiss: resolve(false)` `[VERIFIED: grep of those blocks]`.

**Recommended shape (this research only):**
```ts
// src/stores/confirm-store.ts  — React-free, unit-testable
type ConfirmRequest = {
  title: string; message?: string;
  confirmLabel: string; cancelLabel?: string;   // cancel defaults "Cancel"
  destructive?: boolean;                        // → warning glyph + non-dismissable (ADR-086)
  dismissable?: boolean;                        // default !destructive; set false when Cancel has a side effect
};
type NoticeRequest = { title: string; message?: string; acknowledgeLabel?: string }; // default "OK"
// queue entries: { id: number; kind: "confirm"|"notice"; req; resolve }
export const confirm = (req: ConfirmRequest) => Promise<boolean>; // Back/scrim (when dismissable) → false
export const notice  = (req: NoticeRequest)  => Promise<void>;
```
- `DialogHost` renders `<ConfirmDialog key={current.id} … />`. **The `key` is required** so `ConfirmActions` remounts and re-measures for each queued request (Pitfall 2).
- Mount `<DialogHost />` inside `NavigationContainer` after `<Snackbar />` (`App.tsx:441` is the Snackbar today `[VERIFIED: App.tsx:439-441]`). This requires classifying it in `fab-dial-shell-overlays-contract.test.ts`: that contract fails on any unclassified component rendered in `NavigationContainer` `[VERIFIED: src/components/fab-dial-shell-overlays-contract.test.ts:67-85]`. Its `SEPARATE_WINDOW_MODALS` check asserts a direct `<Modal` from react-native, so add a new class ("BaseOverlay window hosts") instead of reusing it.
- Notice = `ConfirmDialog` with a single primary button (add a `variant: "notice"` or a sibling `NoticeDialog` sharing the card styles). The mockup draws the notice with one primary "OK" `[VERIFIED: 38.9-WORKPAPER-mockup/ux-standards-mockup.html:181-183]`.
- The guard prompt (D-13) goes through the same host: `destructive: true`, `cancelLabel: "Keep editing"`, `confirmLabel: "Discard changes"`. See Open Question 4 on the heading glyph.

### Pattern 5: History Back + untracked tab switch (D-35)

**Router facts** (installed `@react-navigation/routers@7.6.4`, source read and executed this session):
- The default `backBehavior` is `'firstRoute'` `[VERIFIED: node_modules/@react-navigation/routers/src/SwitchRouter.tsx:183]`, which matches today's C-01 bug. Docs: "`history`: return to last visited screen… the older entries are dropped" `[CITED: https://reactnavigation.org/docs/bottom-tab-navigator (7.x)]`.
- With `history`, the initial history is just the initial route `[VERIFIED: SwitchRouter.tsx:116-120]`. Every NAVIGATE/JUMP_TO removes the target's older entry and appends it (de-dupe) `[VERIFIED: :133-166]`. `GO_BACK` returns `null` when `history.length === 1` `[VERIFIED: :488-491]`. `null` bubbles, `NavigationContainer`'s Back handler returns false, and Android backgrounds the app.
- **Simulation with the installed router** (`TabRouter({initialRouteName:"DigestTab", backBehavior:"history"})`):
  ```
  init                     DigestTab               Back → null (exit)          ✓ D-35
  nav Contacts             Digest>Contacts         Back → Digest               ✓
  nav Contacts, nav Digest Contacts>Digest         Back → Contacts, Back → EXIT (on Contacts, not Digest)
  ```
  The last row conflicts with D-35's text "exits on the launch tab". It also happens after any external reset (`reset-intents.ts` builds partial tab states `[VERIFIED: src/navigation/reset-intents.ts:12-48]`, rehydrated to a one-entry history `[VERIFIED: SwitchRouter.tsx:248-271]`).
- **In-place switch** (a reset of the tab state with `history` = previous entries minus the current entry, plus the target), simulated: `Digest>Contacts` → in-place Orrery → `Digest>Orrery`; → in-place Digest → `Digest`; Back → exit ✓. `BaseRouter` RESET keeps a non-stale state as given `[ASSUMED from the simulation result; BaseRouter source not opened]`.

**Recommendation (this research's reading of D-35):**
```ts
// src/navigation/tab-history.ts (pure + thin dispatcher)
export function inPlaceTabState(state: TabNavigationState<…>, target: keyof TabParamList) {
  const index = state.routes.findIndex((r) => r.name === target);
  const key = state.routes[index].key;
  const prior = state.history.slice(0, -1).filter((h) => h.key !== key);
  return { ...state, index, history: [...prior, { type: "route" as const, key }] };
}
export function switchTabWithoutHistory(tabNav, target) {
  const state = tabNav.getState();
  tabNav.dispatch({ ...CommonActions.reset(inPlaceTabState(state, target)), target: state.key });
}
```
- `RootNavigator`: add `backBehavior="history"` to `<Tab.Navigator>` (:240 `[VERIFIED]`).
- **Launch-tab fallback:** in the existing `hardwareBackPress` listener (`RootNavigator.tsx:169-182`; it already runs before the container's because it registers after it `[VERIFIED: comment :166-168 and setTimeout registration]`), after the transient branch: if the focused tab's stack is at its root, `tabState.history.length === 1`, and the focused tab ≠ `INITIAL_TAB`, then `switchTabWithoutHistory(…, INITIAL_TAB)` and return `true`. The in-place switch matters here; a plain navigate would make `X>Digest` and loop Back.
- Screen-level BackHandlers registered later still run first (Home bulk-select `[VERIFIED: HomeScreen.tsx:1601-1612]`, Compose, Capture). No conflict.
- Phase 39 Orient uses `switchTabWithoutHistory` for its hops (D-35 helper).
- Tests can drive `TabRouter` directly in vitest. The ESM build is at `node_modules/@react-navigation/routers/lib/module/index.js`, and it ran under plain `node` this session `[VERIFIED]`.

## Common Pitfalls

### Pitfall 1: Themed confirm makes some dialogs dismissable that never were
**What goes wrong:** Back or a scrim tap on the converted "Export readable JSON?" resolves `false`, which runs `runExport(false)`, an encrypted export the user never chose. **Why:** Android `Alert` defaults to `cancelable: false` (`Alert.js:90`), while `ConfirmDialog` non-destructive is dismissable. **Avoid:** a `dismissable` option on `confirm()`; set it `false` wherever Cancel has a side effect (`BackupScreen.tsx:246`). **Warning sign:** a "cancel" button with an `onPress` that does more than return.

### Pitfall 2: Queued dialogs keep the previous layout
`ConfirmActions` decides row vs stacked once per mount. A host that swaps requests while `visible` stays true reuses the old layout. **Avoid:** `key={request.id}`.

### Pitfall 3: `dismissTop()` and the overlay registry get merged
D-24 forbids it. Keep the two stores separate. The registry has no close callbacks.

### Pitfall 4: The Alert source contract misses the dynamic import and the comment
`widget-linking.ts:308` destructures `Alert` from a dynamic import. `theme-types.ts:98` mentions `Alert.alert` in a comment. Strip comments and scan for `\bAlert\b` usage from react-native in any import form. Allowlist only `HomeScreen.tsx` (snooze).

### Pitfall 5: The snackbar renders under the sheet that fired it
Raw RN Modals that are not swapped to `RegisteredModal` keep hiding snackbars (PendingConfirmationsSheet's assist outcomes are S-class). Land the overlay foundation **before** converting Alerts that fire from inside a Modal.

### Pitfall 6: The Create guard fires on its own successful save
`navigation.replace("Profile")` triggers `beforeRemove`. Set the bypass right before `replace`. Do it after the awaited duplicate confirm, because that confirm can return without saving.

### Pitfall 7: The Log Interaction guard prompts on picker dismissal or before seeding
The guard must be off while `contactId === null`, and the snapshot must be taken after `seed()` resolves (D-15).

### Pitfall 8: Backup schedule blur-save writes both fields or neither
`buildBackupSettingsPatch` validates both together. A per-field save needs a per-field patch, or one invalid field blocks the other.

### Pitfall 9: Contract tests pin current shapes
Contracts to update in the same commit as the change: `fab-dial-shell-overlays-contract.test.ts` (App.tsx classification; resume prompts must `return ( <Modal`); `overlay-base.contract.test.ts` (GestureHandlerRootView inside RNModal); `confirm-dialog-contract.test.ts` (`dismissable={!destructive}`; hairline/border assertions if any); `sheet-consumers-contract.test.ts` (new `<Sheet` consumers); `settings-chrome-contract.test.ts` (lists); `focused-route-classification.test.ts` + `fab-clearance-contract.test.ts` (ComposeResearch); `universal-fab-logic.test.ts:56-93` (asserts `tab: "DashboardTab"` in every `resolveFabTarget` case `[VERIFIED]`); `shell-contract.test.ts` (route lists).

### Pitfall 10: The chevron loses glass-foreground colour
`ShellAppBar` colours its text from `barColors` (glass scope). `Icon`/`Button` read `useTheme()`. Wrap the glyph in `GlassForegroundScope` when `scrim.scoped`.

### Pitfall 11: Removing opaque fills puts text on art (D-17)
Readability over art is a device and mockup check. Use the existing glass and scrim surfaces, not new colours.

### Pitfall 12: The date formatter hides invalid custom-field values
`knowledge-presentation.ts` must format only parseable dates. Invalid values keep their error state (CLAUDE.md custom-field invariants).

### Pitfall 13: Worklets in OrbitSwitch
Define any worklet helper above its caller (memory `worklet-forward-ref-hazard`; a Hermes-only crash that vitest cannot catch).

### Top-host snackbar selection (shape)
```ts
// Snackbar.tsx: one component, many hosts
export function Snackbar({ host = "root" }: { host?: string }) {
  const top = overlayRegistry((s) => s.entries.at(-1)?.id ?? "root");
  const snackbar = snackbarStore((s) => s.snackbar);
  if (!snackbar || top !== host) return null;
  return <View collapsable={false} pointerEvents="box-none" …>…</View>; // ADR-173
}
```
