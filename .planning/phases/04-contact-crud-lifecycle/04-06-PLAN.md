## Phase Goal

**As a** person tending my relationships, **I want to** edit any of a contact's details and toggle how it behaves, **so that** the app keeps matching the real relationship.

**This slice (Plan 06):** the EditContactScreen — the always-show form wired to `updateContactFull` (Plan 05). After this plan a user reaches Edit from the profile's "Add details", changes any field or toggle, and saves.

<objective>
Build the edit form: every non-quarantined field (fixed widgets + reused custom block) plus dedicated phone/email, birthday with a year-unknown affordance, and the "Rarely responds" / "Turn off reminders" toggles — seeded by `getContactForEdit` and saved through `updateContactFull`.

Purpose: CRUD-03. Note the scope boundary: last-spoke is a single-writer/interaction concern (Phase 6 logging), so it is NOT on the edit form — the create form owns first-contact; the edit form owns metadata + toggles + links (links land in Plan 07).
Output: EditContactScreen, wired to the profile's "Add details".
</objective>
