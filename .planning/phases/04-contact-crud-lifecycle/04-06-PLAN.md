## Phase Goal

**As a** person tending my relationships, **I want to** edit any of a contact's details and toggle how it behaves, **so that** the app keeps matching the real relationship.

**This slice (Plan 06):** the EditContactScreen — the always-show form wired to `updateContactFull` (Plan 05). After this plan a user reaches Edit from the profile's "Add details", changes any field or toggle, and saves.

<objective>
Build the edit form: every non-quarantined field (fixed widgets + reused custom block) plus dedicated phone/email, birthday with a year-unknown affordance, and the "Rarely responds" / "Turn off reminders" toggles — seeded by `getContactForEdit` and saved through `updateContactFull`.

Purpose: CRUD-03.

**Owner ruling (2026-08-14, CONTEXT Area 3 — SUPERSEDES this plan's prior blanket "no last-spoke control"):** the edit form DOES surface a tri-state last-spoke control, but ONLY for never-contacted contacts (`getContactForEdit`'s `contact.last_contact IS NULL`). Setting it writes a FIRST interaction through `updateContactFull`'s single-writer first-interaction path (Plan 05 — `source='manual'`, `direction=null`, future dates rejected), NOT a direct `last_contact` write. This closes the never-contacted dead-end (a "Not yet"/captured contact can record its first contact without waiting for Phase 6) while preserving the single-writer invariant. For a contact whose `last_contact` is ALREADY set, NO last-spoke control renders — correcting an existing recency timeline stays Phase 6 (interaction log). So the edit form owns metadata + toggles + links (Plan 07) + the never-contacted first-contact affordance; it does not own timeline correction.
Output: EditContactScreen, wired to the profile's "Add details".
</objective>
