## Phase Goal

**As a** person tending my relationships, **I want to** correct and enrich a contact's details, **so that** the app reflects reality as it changes.

**This slice (Plan 05):** the edit data layer. TDD, headless. After this plan `updateContactFull` edits metadata atomically (recomputing recency only when the rarely-responds flag flips), and `getContactForEdit` assembles the form's initial values.

<objective>
Add the contact-metadata edit writer (every column except `last_contact`) with the mandatory `rarely_responds`→recompute path, plus the edit-form initial-values assembly. Both reuse the composed-core pattern and reads built in Plan 02.

Purpose: CRUD-03 requires editing every field; the subtle correctness rule is Pitfall 2 — flipping `rarely_responds` changes which interactions count toward recency, so a metadata-only UPDATE that skips the recompute silently corrupts status math. The metadata writer must NOT write `last_contact` itself (single-writer DATA-04); it routes the recompute through the single writer instead.
Output: `updateContactFull` in `contacts-dao.ts`, `getContactForEdit` in `contact-read.ts`, with tests.
</objective>
