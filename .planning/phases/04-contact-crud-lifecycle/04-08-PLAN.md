## Phase Goal

**As a** person tending my relationships, **I want to** put a contact away without losing it and bring it back if needed, **so that** my orbit stays uncluttered but nothing is deleted by accident.

**This slice (Plan 08):** archive + restore + the Archived home. After this plan a user archives from the profile ⋯ menu (contact disappears from live surfaces) and restores from Settings → Archived contacts — the reversible half of the two-stage lifecycle.

<objective>
Add archive/restore metadata writers + the `listArchived` inverse read, the profile overflow (⋯) menu whose sole action this phase is Archive, and the real ArchivedContactsScreen (list + Restore) replacing the Plan 01 placeholder.

Purpose: CRUD-05. The two-stage design (archive on profile, restore+purge only on the Archived list) makes permanent deletion a deliberate two-step act by construction — the irreversible action (Plan 09) never sits one tap from the reversible one.
Output: archive/restore/listArchived DAO ops, OverflowMenu, ArchivedContactsScreen.

**Phase obligations & deferrals (reviews-mode — recorded so /gsd-verify-work sees rationale, not silent gaps):**

The `launch-sweep` registry names an "archived-purge" responsibility (launch-sweep.ts:7) and ROADMAP:47 nominally tags it Phase 4, but an auto-expiry sweep would CONTRADICT the indefinite-retention copy. RESOLUTION: do NOT register a `registerSweepHook` archived-purge in Phase 4; retention is indefinite; auto-expiry is a deferred, non-Phase-4 mechanism to revisit only if the owner later wants time-boxed archive retention. Note it, do not implement.
- **Restore does not write an `events` row (DEFERRED, not dropped).** RESEARCH A3 / dossier 06-crud say "restore writes an events row and must merge, not replace." Verified against the code: there is NO events writer or event-`type` vocabulary in `src/` yet (only the table exists, migration 001:115-125), and 04-log's "merge not replace" is a backup-RESTORE concern, not archive-restore. Writing an ad-hoc events row now would invent an unspecified `type` vocabulary (missing-information — planner may not fabricate it). Archive/restore this phase is a reversible `archived_at` flag flip; the lifecycle-events row is deferred to when the events writer/vocabulary is established. Recorded so the dropped contract is a documented deferral.
- **Archived-read reconciliation (codex HIGH vs claude verified-correct).** codex flagged that getContactHeader/getContactForEdit load archived contacts by id; claude verified this is CORRECT (profile/edit are reached FROM this Archived list to restore/edit). RESOLUTION (also in Plan 05): keep the by-id seeks archived-reachable; do NOT blanket-filter them; the must_have above asserts no NEW live/list surface reads contacts unfiltered. Settled here since this plan owns the archived surfaces.
