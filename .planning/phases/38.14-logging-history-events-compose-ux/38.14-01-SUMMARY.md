# Phase 38.14 Plan 01: One "Did you send it?" per record Summary

**Compose's panel now claims its assist record in the store (banner and list skip it), answers Yes, log it / No, don't log / Later. Later stays quiet until the next return to Orbit, through an in-memory set with no timer. The banner and pending list show "Text to 555-0101 · 2:14 PM", put Yes on the right in a ConfirmActions row, confirm every answer with a named snackbar, and the list is a sized bottom Sheet with Close.**

## Accomplishments

- **Defect #1 removed (D-23).** `assist-store` keeps `rawQueue`, `panelOwnedUid` and `laterUids`. Every publication derives the visible queue through `applyAssistSkips`, reading the skip state at publish time, so a claim or a Later made during an in-flight read is not lost. Compose claims and releases through one `useFocusEffect` keyed on `confirm`.
- **Defect #9 removed (D-77, D-78, D-43).** "Not yet" is gone. Later defers the uid, then closes, then exits `"later"`. `releaseDeferred()` runs only on background → active and at launch, and never publishes; the refresh after it publishes. No re-ask happens on a publication or the Settings toggle (Q17-A/B stay rejected). No dismisses through the one runner and keeps the draft. Yes confirms "Logged Message with <name>" and exits.
- **D-74 / D-79 destination.** `listEligiblePendingAssists` returns `endpoint_display`. It comes from a read-only correlated subquery on the same contact's method with `canonical_value = endpoint_value` and the channel-matching `method_type`, ordered primary first, then display order. It falls back to the stored endpoint. I confirmed that every `performReachOut` caller (Compose, Profile `launchMethod`, ReachOutRouter) hands off `canonical_value`, and that `createPendingAssist` is the only writer of `endpoint_value`.
- **D-73 / D-80.** `AssistConfirmation` uses `ConfirmActions` with Don't log, [No answer], Yes in that order, and `pending` disables all three. The plain `flexWrap` row is gone.
- **D-74 sheet.** `PendingConfirmationsSheet` is a `<Sheet>`, sized by `pendingSheetVariantFor` → `sizedSheetVariantFor` (ADR-255) and held from open until the next open. It has `scrollBody={false}` on compact / detail, a glossary `CLOSE` button and the dirty-note guard on every close path.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `ConfirmActions` could not carry the panel's testIDs**
- **Found during:** Task 2
- **Issue:** The plan requires `compose-confirm-yes/-dismiss/-later` testIDs, but `ConfirmActions` draws its own Buttons and had no testID passthrough.
- **Fix:** Added an optional `testIDs?: { cancel, secondary, confirm }` prop, purely additive. Existing consumers are unchanged and `confirm-dialog-contract.test.ts` stays green.
- **Commit:** `cb3d8e2f`

**2. [Rule 1 - Bug] Sized-sheet block swap would remount the open sheet**
- **Found during:** Task 3
- **Issue:** The variant was computed every render. Answering rows, or the close animation, could flip between the `expanded` and compact/detail `<Sheet>` blocks, which remounts the Sheet, drops a typed note and cuts the animation.
- **Fix:** The variant is decided on open and held until the next open (ADR-255 "decided when it opens").
- **Commit:** `e3e27de9`

- **Commit:** `768092db`
