# Phase 38.14 Plan 03: One-tap logging channel, feedback and bulk re-channel Summary

**Every one-tap log (Quick Log, bulk, widget, notification) records the user's resolved Default Interaction Channel through one never-rejecting read. Quick Log's snackbar names the channel and person, and its Undo confirms. Bulk Quick Log gains Undo · Edit, which re-channels the batch by receipt through the per-row edit core in one transaction. The More… row reads Group Log for 2+ people, selection keeps its order, and the + picker opens clean.**

## Accomplishments
- New `readResolvedInteractionChannel(exec)` in `src/services/resolved-interaction-channel.ts`. It reads `getAppSettings`, applies `resolveInitialChannel`, and falls back to Message with a content-free log. It never rejects and is called before any write transaction.
- `bulkQuickLog` takes the channel. The widget Mark and the notification Mark read it before `recordTouchpoint`. Direction stays outbound on every route; nothing writes `unspecified` any more.
- Quick Log: `runQuickLog(deps, contactId, personName)`. HomeScreen passes the name from `rowsByIdRef` (its deps are still `[]`). UniversalFab passes a lazy `getContactHeader` read that the command resolves inside its guard, so `logContact` stays synchronous.
  - The label comes from `loggedInteractionSnackbar`.
  - Undo success shows "Undid <Channel> with <Name>" as a warning snackbar with no action.
- Bulk snackbar: "Logged <Channel> with <N> people", or the person's name for one, with Undo · Edit.
  - Edit opens an OptionSheet with Message / Call / In Person and runs `rechannelBulkQuickLog`, guarded by a single-flight ref.
  - Success confirms "Changed N interactions to <Channel>"; failure takes the existing bulk-failure path with Retry.
- `rechannelBulkQuickLog` reads each receipt row by id and contact_id. It skips rows that are gone or now carry a `group_event_id` (D-82) and calls `editTouchpointFullCore` with only the channel replaced. It bumps the data revision once, only when a row changed, and is all-or-nothing.
- BulkActionSurface: the More… log row reads Group Log (label, a11y label, `group-events` icon) with 2+ selected, and Log Interaction with the call icon for one. Routing is unchanged.
- `orderRowsByFrozenUniverse` drives the selection-mode `cardRows`. I checked the store: `frozenUniverse` is captured in on-screen order at entry, so the store needed no change.
- `nextPickerResetKey` makes the modal `ContactPicker` pass a new `searchResetKey` on every open, so the + picker opens with an empty search.
- `docs/systems/interaction-log.md` and `docs/systems/widget.md` no longer say one-tap logs write `unspecified`, and each has a 38.14 Changelog row. The interaction-log doc also describes the bulk Edit re-channel.

## Decisions Made
- **The linked-note blank case cannot happen, so the re-channel needed no extra handling.** I checked every writer that could leave a note-linked interaction with a blank note:
  - Links are created only with non-blank text equal to the note (`insertLinkedEntryCore`).
  - Every note edit goes through `editTouchpointFullCore`, which refuses a blank note while linked. That covers Edit interaction, `editInteractionNoteCore` (the memory and Last Talked About editors), the group cascades and the knowledge-move AI lock.
  - Undo restore relinks only to a non-blank note (`resolveUndoLinkCore`).
  - Backup restore detaches a note link whose interaction note is blank (`repairKnowledgeLinks`, `restore-apply.ts:668`).
  - Other `UPDATE interactions` writers (`group-events-dao` follow flags and group_event_id, `ai-permissions-dao` / `linked-entry-dao` allow_ai) never touch `note`.

  The finding is written in `rechannelBulkQuickLog`'s doc comment. No checkpoint was needed, and D-62 / D-82 are kept exactly.
- **No future-date guard in the re-channel.** It passes `occurred_at` through unchanged, so it never writes a new date. The reasoning is in the doc comment.
- **Wording (Claude's Discretion, CONTEXT):**
  - Undo confirmation: "Undid <Channel> with <Name>"
  - Re-channel confirmation: "Changed N interactions to <Channel>"; an all-skipped batch shows "No logged interactions left to change"
  - Edit sheet title: "Change channel"
  - Edit a11y label: "Change the channel of N logged interactions"
  - Naming one person on the bulk snackbar is this plan only, as the plan says.
