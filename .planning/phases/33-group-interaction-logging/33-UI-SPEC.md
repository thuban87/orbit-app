# Phase 33 — UI Design Contract

> Visual and interaction contract for Group Interaction Logging. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase invents no new visual language.** Every token, primitive, and interaction pattern below already ships (built across Phases 22–32). The contract's job here is to bind Phase 33's *new surfaces* (Group Log form, Group Event Detail, Edit Group Event, Group Events browse page, participant cards, multi-select picker mode) to the existing system and to activate the dormant seams Phase 32 planted (`InteractionDetail` group block, `GroupScopePrompt`). Ground truth is `docs/dossier/milestone-2/phase-12-group-interaction-logging-dossier.md` (§A–AG) and its planning-notes sibling; nothing here reverses a `[DECIDED]`/ADR/HANDOFF entry.

## Spacing Scale

Orbit's established scale (`src/theme/tokens/spacing.ts`). Reuse the tokens — do not introduce raw pixel values.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner padding, override-chip gaps |
| sm | 8px | Compact element spacing, button gaps, participant-card inner gaps |
| md | 12px | Dense row inner padding (grid-aligned intentional exception) |
| base | 16px | Default element spacing, screen horizontal padding, form field spacing |
| lg | 24px | Section padding, action-row top margin |
| xl | 32px | Layout gaps, empty-state horizontal padding |
| 2xl | 48px | Major section breaks |

Exceptions: `md = 12px` is a deliberate, already-shipped 8-point exception (dense row inner padding where 8 is too tight and 16 too loose — documented in the token file). The **44×44px minimum touch target** (`MIN_TOUCH_TARGET`) is a target-size floor, not a spacing token — every participant overflow trigger, picker row, and icon-only control honours it.

## Typography

Orbit ships exactly FOUR sizes and TWO weights over FIVE semantic roles (`src/theme/tokens/typography.ts`). Consume `<AppText role=…>` — never a raw `fontSize`.

| Role | Size | Weight | Line Height | Phase-33 usage |
|------|------|--------|-------------|----------------|
| display | 28px | 600 (SemiBold) | 34 (1.2) | Not expected on these dense surfaces; reserve |
| heading | 20px | 600 (SemiBold) | 25 (1.25) | Group Log / Edit / Detail sheet titles ("Group Log", "Group Event"), scope-prompt title |
| body | 16px | 400 (Regular) | 24 (1.5) | Group Note text, participant note, field values, event title on Detail |
| label | 14px | 600 (SemiBold) | 20 (1.4) | Field labels, participant name on cards, "Group Note" label, button labels |
| caption | 14px | 400 (Regular) | 20 (1.4) | Override summaries ("Follows event · Tone: Negative"), date/time subline, match snippets, empty/error copy on textSecondary |

`label` and `caption` share the 14px step and diverge by weight + colour token (label = SemiBold/textPrimary, caption = Regular/textSecondary) — keep that separation; do not add a fifth size. Line heights are absolute px derived from the multiplier so OS text scaling reflows (THEME-07); large text may grow participant-card height rather than truncate critical semantics (dossier §AE).

## Color

**Every value is a `ThemePalette` token key resolved at render via `useTheme().colors[key]` — NO hex literals in Phase 33 code** (`npm run check:colors` enforces this; the only colour-literal file is `theme-presets.ts`). Values below are the *roles*, not fixed colours: each resolves per active package (Galaxy/Standard) × mode (Light/Dark) and per the user's chosen accent overlay.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `background` | Screen background behind every Phase-33 surface (backgrounds fixed while content scrolls per THEME-04) |
| Secondary (30%) | `surface` / `surfaceElevated` | Group Log form fields, participant cards, Group Event Detail cards, sheet body, picker rows |
| Accent (10%) | `accent` (fill) / `onAccent` (on-fill fg) / `accentText` (link tone) | See reserved-for list below |
| Destructive | `danger` (fill) / `onDanger` (fg) | Destructive controls + `warning` glyph ONLY |
| Structure | `border` / `borderStrong` | Card/field hairline borders, participant-card separators, group-context block border |
| Text | `textPrimary` / `textSecondary` | Primary content vs. captions/labels/override summaries |

**Accent reserved for (explicit — never "all interactive elements"):**
1. The single **Primary** button per surface — `accent` fill + `onAccent` label (the Save/Create/primary confirm action; e.g. "Log group", "Save changes").
2. **Selected state** in the multi-select participant picker (selection check + selected-count treatment) — `accent`.
3. **`accentText` (link tone) only** for tertiary text actions: **"View Group Event"**, and the **"Follow event …"** clear-override affordance. Never a filled accent for these.

Everything else (secondary buttons, cards, borders, participant rows) uses `surface`/`border`/`textPrimary` — restrained, per Orbit's "compact within, generous between" and THEME-05 (Galaxy glass-forward, Standard flatter). **State is never colour-alone** (THEME-08/dossier §AE): override state, group membership, and the Allow-AI sparkle each read by icon + text label as well as colour.

## Copywriting Contract

All copy below is prescriptive. Destructive confirmations mirror the shipped `InteractionDetail` delete idiom (name the consequence, name the action on the confirm button).

| Element | Copy |
|---------|------|
| Primary CTA — create/save Group Event | **"Log group"** (create) / **"Save changes"** (edit) |
| Secondary CTA — add participants | **"Add participants"** |
| Clear an override (per field) | **"Follow event tone"** / **"Follow event channel"** / **"Follow event duration"** / **"Follow event direction"** / **"Follow event connected"** (dossier §G/§L — explicit `Follow event …` wording, never a bare "Reset") |
| Group Note label (shown beside a participant interaction) | **"Group Note"** (participant's own note carries no special label — dossier §H) |
| Empty state heading — Group Events browse page, none yet | **"No group events yet"** |
| Empty state body — browse page | **"Log a get-together with several people at once from the + button, or from Group Log on any contact."** |
| Empty state — zero-participant event (valid, dossier §C) | Participant area shows **"No participants yet"** + body **"Add the people who were there — or save now and add them later."** (never an error; zero-participant is valid) |
| Search no-results (browse page) | **"No group events match "{term}"."** (searches title + participant name — dossier §T) |
| Error state — save/fan-out failure (atomic rollback) | **"Couldn't save this group event. Please try again."** — form stays open with all input intact, nothing committed (dossier §AA; GRP-11) |
| Error state — participant recency fan-out failed on date edit | **"Couldn't update the group event. Your changes weren't saved."** (whole transaction rolled back) |
| Destructive confirmation — Dissolve | Title **"Dissolve this group event?"** · Body **"Each participant's interaction is kept as an individual interaction. The group and its shared note are removed. The Group Note is not copied into anyone's note."** · Confirm **"Dissolve group event"** |
| Destructive confirmation — Delete Group Event & Interactions | Title **"Delete this group event and all its interactions?"** · Body **"This permanently deletes the group event and every participant's interaction. This can't be undone and may change each contact's Status, Gravity, and Intensity."** · Confirm **"Delete group & interactions"** |
| Remove-participant three-way prompt (dossier §N — a `Sheet compact`, NOT a binary ConfirmDialog) | Title **"Remove {name} from this group?"** · Options: **"Delete interaction"** (destructive; permanently deletes their child) · **"Keep as individual interaction"** (detaches, materializes resolved values, keeps their note, does NOT copy the Group Note) · **"Cancel"** |
| Convert ordinary interaction → Group Event (entry from Interaction Detail overflow, dossier §P) | Action label **"Make this a group interaction"** (preserves the original interaction's identity/UID; seeds shared defaults) |
| Future-date rejection (dossier §AB / GRP-12) | **"Group events can't be in the future."** (reuse the shipped `rejectFutureOccurredAt` locked-copy idiom) |

## UI Considerations

> Shape-rooted UI *state* coverage for Phase 33's surfaces. Empty/error COPY lives in the Copywriting Contract above; rows here reference it rather than restate it. Coverage computed by the UI-consideration probe over the 7 described surfaces (Group Log/Edit form, participant override editor, multi-select picker, Group Event Detail, browse page, destructive/lifecycle confirmations, child-edit scope prompt); resolutions deduplicated across surfaces where one state answer applies.

Applicable state considerations resolved: 11 covered (explicit), 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Group Events browse page (no events) | ✅ covered | Renders the documented "No group events yet" heading + body; deep-link-ready seam already routed |
| empty | Group Log form with zero participants | ✅ covered | Zero-participant is a VALID saved state (dossier §C); shows "No participants yet" prompt, never an error; Save remains enabled |
| empty | Search no-results on browse page | ✅ covered | Documented "No group events match "{term}"" over title + participant search |
| loading | Multi-select participant picker; browse-page list; Group Event Detail fetch | ✅ covered | Reuse `ContactPicker`'s existing `ActivityIndicator` load state; list/detail render a spinner only on initial/meaningfully-delayed load (mirrors LISTV-10 idiom) |
| error | Group Event save / fan-out failure | ✅ covered | Atomic rollback (GRP-11); documented error copy; form stays open with input intact, nothing committed, control re-enabled — no optimistic vanish |
| error | Participant recency fan-out failure on date edit | ✅ covered | Whole transaction rolled back; documented "Couldn't update the group event. Your changes weren't saved." (dossier §AA); form state preserved |
| populated | Group Event Detail with participants | ✅ covered | Presentation-first; participant compact cards open child Interaction Detail (dossier §R/§S) |
| partial | Mixed inherit/override participants (Detail cards + override editor) | ✅ covered | Each participant card + the override editor shows a concise inherit-vs-override summary by text + icon (e.g. "Follows event" vs "Tone: Negative · 45m"); state never colour-alone; explicit "Follow event …" clear affordance |
| zero-one-many | Participant count fan-out (0 / 1 / many) | ✅ covered | 0 = valid no-op; each participant = exactly one canonical child via the recency cores; parent never counts (GRP-02, dossier §B/§AD) |
| confirmation / destructive | Dissolve · Delete Group Event & Interactions · three-way Remove-participant | ✅ covered | Fully specified in the Copywriting Contract: each names the consequence and the confirm action; Dissolve/Delete are `ConfirmDialog` destructive (danger fill + `warning` glyph, no scrim-dismiss), Remove-participant is a three-option `Sheet compact` not a binary dialog (dossier §N). *(Probe returned this surface `unclassified` — a data-shape classifier miss on an action-confirm surface, not a gap; resolved by reference to the copy contract.)* |
| scope-select | Child-edit scope prompt (`GroupScopePrompt`) | ✅ covered | Static two-option `Sheet compact` ("Edit individual interaction" / "Edit Group Event") with fixed labels — no data load, so empty/loading/error/partial/long-text are n/a by shape; routes `onEditGroup` to the real Edit Group Event form (dossier §S) |
| overflow | Large participant sets (no cap) | 🧪 backstop | No product cap (dossier §K); picker + participant list must virtualize (`FlatList`) and stay searchable — needs a device UI-state check at a realistic large count (Phase-18/40 reflow seam). *Verification: backstop (held-out device UI-state check).* |
| long-text | Long event title / long Group Note / long contact names | 🧪 backstop | `body`/`label` reflow (never truncate critical semantics; large text grows card height — dossier §AE); needs a held-out long-content visual check. *Verification: backstop (held-out device visual check).* |
