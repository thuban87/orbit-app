# Phase 38 — UI Design Contract

> Visual and interaction contract for the Digest & Navigation Restructure. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase recomposes existing surfaces; it does not introduce a new design language.** The Orbit theme-token system (`src/theme/`) is the design system of record and is already complete. This SPEC's job is to (1) pin the five-tab shell/IA contract, (2) pin how the three Digest modules present and interact, and (3) name the exact existing tokens/components/copy the executor must reuse — so no parallel styling, no hardcoded colour, and no new schema creep in.
>
> **Authoritative product contract:** `docs/dossier/milestone-2/phase-38-digest-navigation-restructure-dossier.md` (§A–§S) + `docs/decisions/ADR-076`. Where this SPEC and the dossier ever disagree, the dossier wins — flag the conflict, do not design around it.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (React Native / Expo — shadcn gate not applicable; shadcn is a web/React-DOM tool) |
| Preset | not applicable |
| Component library | none — Orbit's own primitives (`src/components/ui/`, `src/components/`) over React Native core |
| Icon library | Ionicons via `@expo/vector-icons`, routed through the semantic `Icon` + `TAB_ICON`/`ICON_MAP` registry (`src/components/icons/`). Never import a raw glyph name outside the registry. |
| Font | Space Grotesk (display/heading) + Inter (body/label/caption), loaded via `src/theme/fonts.ts`; consumed only through `AppText` roles, never raw `fontSize` |

**Colour rule (non-negotiable, CLAUDE.md / `check:colors`):** every colour resolves through `useTheme().colors.*`. No hex, no named literal, anywhere — including Skia. This SPEC names only existing tokens; it introduces **no new colour token**. The theme-merge into a single Dark/Light switch is PARKED — design against today's Galaxy/Standard art-tone + light/dark theme-store model on disk, and per dossier §P both packages share identical IA/interaction and differ only presentationally.

## Spacing Scale

Declared values (Orbit `SPACING` tokens, `src/theme/tokens/spacing.ts` — all multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon-to-label gaps, chip inner padding |
| sm | 8px | Compact intra-row spacing; gap between a module label and its first row |
| md | 12px | Dense row inner padding (Up Next / Horizon rows, reached rows); avatar-to-text gap |
| base | 16px | Default screen padding; Digest root padding; gap between rows |
| lg | 24px | Gap **between** the three Digest modules (Up Next → Horizon → Your Week) |
| xl | 32px | Reserved for major vertical breaks if a module grows; not required at baseline |
| 2xl | 48px | Not used in this phase |

Exceptions: **44×44px minimum touch target is a floor, not a spacing token** — every tappable row (Up Next contact, Birthday row, Overlooked/Never-Contacted preview, heatmap day cell, tab, FAB) meets it or compensates with `hitSlop` (the `ActivityHeatmap` dense-cell pattern). Existing `DigestScreen` inline literals (`padding: 16`, `gap: 12/24`) map onto `base`/`md`/`lg`; when this phase rewrites that screen, migrate them to `SPACING` tokens rather than re-introducing literals.

## Typography

Orbit `TYPOGRAPHY` roles (`src/theme/tokens/typography.ts`) — exactly 4 sizes, 2 weights. Consume via `<AppText role=...>`, never raw sizes. The legacy `DigestScreen` uses raw `fontSize`/`fontWeight` in its StyleSheet; the rewrite MUST move to roles.

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| display | 28px | 600 (SemiBold) | 34 | The Digest screen title only ("Digest") |
| heading | 20px | 600 (SemiBold) | 25 | Module headings: **Up Next**, **Horizon**, **Your Week** |
| body | 16px | 400 (Regular) | 24 | Contact/birthday row names; Your Week metric values; day-detail rows; empty-state body |
| label | 14px | 600 (SemiBold) | 20 | Horizon subgroup labels (Birthdays / Overlooked / Never Contacted); Your Week metric captions; "why present" context line emphasis; period toggle labels |
| caption | 14px | 400 (Regular) | 20 | Secondary context (day tags, relative dates "Today"/"Tomorrow", overflow "+N more", muted supporting text) |

OS text scaling must reflow (no `allowFontScaling={false}`, no fixed row heights that clip) — the `AppText` reflow contract holds; long names/labels wrap or ellipsize deliberately (see UI Considerations long-text row).

## Color

Roles mapped to existing Orbit tokens (`src/theme/theme-types.ts`). No new tokens.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `colors.background` | Digest screen background; all five tab-stack roots |
| Secondary (30%) | `colors.surface` | Bottom tab bar; module cards/scrims (`ChromeScrim`/`GlassSurface`); Your Week metric tiles; heatmap container |
| Secondary (raised) | `colors.surfaceElevated` | Elevated cards / expanded inline day-detail panel where separation from `surface` is needed |
| Accent (10%) | `colors.accent` (focused-tab tint via existing tab bar; `onAccent`/`accentText` for text on accent) | See reserved-for list below |
| Destructive | `colors.danger` (+ `onDanger`) | Not expected in this phase — Digest has no destructive/inline write actions (§D/§M). Present only if the reused FAB speed-dial surfaces one; if a destructive control appears in Digest, that is scope drift (flag it). |

Accent reserved for: **(1)** the active/focused bottom-tab tint and its icon (existing `tabBarActiveTintColor` behaviour); **(2)** the Your Week period-toggle selected state (Rolling 7 Days / Calendar Week, via the existing `SegmentedControl` selected treatment); **(3)** drill-through / "+N more →" affordance text in Horizon (matches the legacy Digest `moreText` accent). Accent is **never** applied to whole rows, module backgrounds, or every interactive element.

**Status hues (state, not action — never `danger`):** Up Next and Horizon-Overlooked rows carry orbit status through the **shared `ContactCard` status ring only** (`colors.rogue` / `colors.statusDecay` / `colors.statusWobble` / `colors.statusStable`). The Digest adds **no status colour of its own** — it inherits the ring exactly as the current `DigestScreen` does. Up Next ordering is driven by canonical status/progress semantics (§D), not by a Digest-local colour scheme.

**Heatmap:** Your Week reuses the `ActivityHeatmap` `colors.heatmapScale` ramp verbatim — no second ramp, no Digest-specific saturation. Day selection is indicated **structurally** (border/outline + accessible selected state), not by colour/intensity alone (§P, HIST-18).

## Copywriting Contract

Voice: calm, non-guilt, no streaks/scoreboards (§H "Inactive periods remain visible with neutral language"). Matches the shipped Digest voice ("All quiet this week … Enjoy the calm."). Copy below is prescriptive; the executor uses these strings.

| Element | Copy |
|---------|------|
| Screen title | `Digest` (sourced from a lightweight canonical product-label constant per §B, so a later rename is one edit — not scattered string literals) |
| Module heading — Up Next | `Up Next` |
| Module heading — Horizon | `Horizon` |
| Module heading — Your Week | `Your Week` |
| Horizon subgroup labels | `Birthdays` · `Overlooked` · `Never Contacted` |
| Birthday temporal tags | `Today` (today's birthday, lightweight prominence) · `Tomorrow` · else a formatted local date via `formatLocalDate()` (never `toISOString().split('T')[0]`) |
| Your Week metric captions | `People reached` · `Interactions` · `Events` |
| Your Week period toggle | `Rolling 7 Days` (default) · `Calendar Week` |
| Overflow / drill-through | `+{n} more →` (Overlooked/Never-Contacted compact preview → Contacts population/filter) |
| Primary CTA | **None.** Digest has no inline Call/Message/log control and no required "View All" (§D). The only action affordance on Digest is the reused global `UniversalFab` with its existing Contacts actions (§M) — do not add Digest-specific FAB actions. |
| Empty state — Up Next | Heading: `You're all caught up` · Body: `No one needs a nudge right now.` |
| Empty state — Horizon | Heading: `Nothing on the horizon` · Body: `No birthdays or overlooked people to flag right now.` |
| Empty state — Your Week | Heading: `A quiet week` · Body: `No logged activity in this period yet.` (neutral — no guilt) |
| Error state (a read throws) | Heading: `Couldn't load your Digest` · Body: `Try opening it again in a moment.` (mirrors the shipped calm error sentinel; re-runs on next focus) |
| Destructive confirmation | Not applicable — no destructive action in Digest. |

Empty-state model per §C/§P: the three **major modules stay visible when empty** with these neutral states; empty **Horizon subgroups disappear** (a subgroup with zero rows renders nothing rather than an empty label).

## Navigation & Interaction Contract

> The load-bearing structural contract for this phase. Verified against `src/navigation/` on disk (today: 4 tabs — `DashboardTab`/`OrreryTab`/`BackupTab`/`SettingsTab`; `Digest` and `GroupEvents` are pushed screens inside `DashboardStack`; `initialRouteName="DashboardTab"`).

**Five-tab shell — left→right, all equal visual peers (§A):**

| Position | Tab (user-facing) | Underlying root | Proposed `TAB_ICON` (existing registry — owner may override) |
|----------|-------------------|-----------------|--------------------------------------------------------------|
| 1 | **Contacts** | current Dashboard root (`HomeScreen`) relabelled | `dashboard` (home) — or a `people`/`list` glyph; owner taste |
| 2 | **Events** | current Group Events root (`GroupEventsScreen`) promoted to a tab root | `group-events` (people) |
| 3 | **Digest** (center, default launch, root) | `DigestScreen` promoted from pushed screen to tab root | `your-week` (calendar) — Digest is the home; owner taste |
| 4 | **Orrery** | existing `OrreryStack` | `orrery` (planet) |
| 5 | **Settings** | existing `SettingsStack` | `settings` |

- Digest is the **centered** tab and the **default/root launch destination** on a fresh app/navigation launch — but it is a **plain equal tab, NOT a raised/oversized special center button** (§A).
- **Background/resume preserves current navigation state** — returning to Orbit must not reset to Digest (§A). Only a fresh launch lands on Digest.
- Each tab owns an **independent stack**; switching tabs preserves other stacks for the session; **reselecting the active tab returns it to its root** (the existing `handleActiveTabPress` popToTop behaviour must extend to all five tabs).
- **Backup tab is removed** (§K) — Backup & Restore already lives in Settings (Phase 37). Do not relocate or rebuild it; just drop the bottom-tab exposure. Verify the Settings Backup route resolves before removing (§S.4).
- **Origin-aware Profile Back is preserved** (§L): Digest→Profile→Back→Digest; Contacts→Profile→Back→Contacts; Orrery→Profile→Back→Orrery; Events/detail→Profile→Back→originating Events context. Up Next / Birthday / Overlooked row tap → Profile; Back → Digest.
- **Global FAB** (`UniversalFab`) remains a shell affordance and appears on Digest with the **same actions currently available from Contacts** (§M) — audit mounting/visibility across the new roots so promotion doesn't create inconsistent FAB behaviour.
- **Notifications/deep links** route to the **new Digest root** (§N); the Digest notification opens/selects Digest. Audit and repoint the old Dashboard→Digest and nested Group-Events routing (§S.13). No legacy-navigation migration machinery — there are no production users (§N planning note).
- **Terminology:** user-facing "Dashboard"→**Contacts**, "Group Events"→**Events** everywhere the shorter term is natural (§B). Internal `GroupEvent`/route names need not be mechanically renamed. Remove the Contacts-header "Your Week" and "Group Events" shortcuts and add no replacement clutter (§K). No repository-wide terminology cleanup (§Q).

**Module interaction specifics:**
- **Up Next** — at most 3 contacts; rows expose enough existing orbit/relationship context to explain *why* present (status ring + a `label`/`caption` context line); no inline Call/Message; row tap → Profile (§D).
- **Horizon** — awareness, not an action queue. Fixed subgroups Birthdays / Overlooked / Never Contacted as **separate labeled groups** (never one ranked feed). Birthdays: forward 7-day window (independent of Your Week period), all matches soonest-first, row tap → Profile. Up Next takes first claim on its 3 contacts; Horizon **dedups** the same condition for those contacts (§E). Never Contacted is **conditional** (hidden when zero), not a permanent statistic (§G).
- **Overlooked & Never Contacted scaling** — compact preview + count with **drill-through to the canonical Contacts population/filter** (reuse existing filtering, no Digest-only browser) rather than dumping large lists (§G).
- **Your Week** — retrospective summary: **People reached / Interactions / Events** metrics (informational, not buttons/filters) + reused Profile-style `ActivityHeatmap`, scoped to the selected period; selecting a day **expands that day's activity inline beneath the heatmap** via the shared `DateDetailSheet`/day-detail presentation — **no Profile calendar rotary / long-range navigation** (§J). Group Events appear as **one event record**, never fake per-participant interaction rows (§J). Period = Rolling 7 Days (default) / Calendar Week (locale first-day-of-week); the preference lives in Settings via the existing persistence path and consistently controls metrics + heatmap + day detail; it does **not** affect the birthday window (§I).

**Reuse guardrails (§O / §R):** Digest is derive-only — **no new relationship-domain schema, no persisted Digest snapshot/cache** (a migration need here is a stop-and-confirm, not a licence — D-02). Reuse existing Digest reads, canonical status/progress, birthday reads, Group-Event reads, Phase 32/Profile heatmap aggregation, navigation-origin machinery, the FAB, and Settings preference conventions. Verify exact execution-time ownership before planning (§S) — do not create one service per module. Do **not** decompose into one-plan-per-tab/module or redesign Contacts/Events/Settings.

## UI Considerations

> Shape-rooted UI *state* coverage. Empty/error COPY lives in the Copywriting Contract above; rows here reference it rather than restating.

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | Digest reads (async, on focus) | ✅ covered | Reuse the shipped null-vs-loaded sentinel: modules render blank bodies until reads resolve; the "empty" states never flash pre-resolution. Reads are async-only, no `...Sync`, no network, no writer. |
| empty | Up Next / Horizon / Your Week modules | ✅ covered | Major modules stay visible when empty with the documented neutral empty-state copy; empty Horizon subgroups disappear entirely (§C/§P). |
| error | any Digest read throws | ✅ covered | Calm error sentinel with the documented copy; re-runs on next focus (shipped pattern). |
| populated | Up Next (≤3) · Horizon subgroups · Your Week metrics + heatmap | ✅ covered | Up Next hard-capped at 3; Birthdays show all matches soonest-first; heatmap renders supplied window/counts. |
| zero-one-many | Never Contacted (conditional) · metric counts · birthday tags | ✅ covered | Never Contacted hidden at zero; counts use singular/plural copy (cf. shipped `backlogLabel`); today's birthday gets `Today`, else `Tomorrow`/date. |
| overflow | Overlooked / Never Contacted large populations | ✅ covered | Compact preview + `+{n} more →` drill-through to canonical Contacts population/filter — no arbitrarily large list dumped into Digest (§G). |
| partial | Up Next present but Horizon empty (or vice-versa) | ✅ covered | Each module resolves its own empty/populated state independently; modules never depend on a sibling being populated. Up Next↔Horizon dedup prevents double-surfacing the same contact/condition. |
| long-text | contact/birthday/event names; metric captions | 🧪 backstop | Names use `AppText body` with single-line ellipsis in dense rows (shipped `numberOfLines={1}` reached-row pattern); module headings/labels reflow under OS text scaling. Verify no clip of the day tag or status ring at large font scale on the Pixel — held to physical-device UAT (§S.15). |
