# 31.1-05 Corrective UAT — backgrounds visibly present, chrome readable

**Date:** 2026-09-11 · **Target:** physical Pixel 6 Pro (`1A071FDEE002BU`, cardinality 1)
· **Build:** DEBUG dev client, Metro `:8082`, reverse `tcp:8081 -> tcp:8082`.

## Root cause (source + device agreed)

`BackgroundHost` painted the selected asset then overlaid a full-screen
`colors.surface` scrim at the **card** density opacity (`surface.ts`: galaxy
0.88/0.93/0.97, standard 0.97/0.99/1.00), leaving 0–12% of the art — every
selection looked identical on regular screens. The Settings picker swatches render
raw art (no scrim), which is why only Settings looked correct. Selection and
persistence were confirmed working (swatches render; store+DAO write-path intact) —
**not** the fault. The AA text-contrast guarantee lives at the card level
(`surface.test.ts` composites text over card-tint-over-asset, never over the host
scrim), so the host scrim was redundant with the cards.

## Fix (plan 31.1-05, D-31.1-05-A)

1. Decoupled the host **veil** from card opacity (new `BACKGROUND_VEIL_OPACITY`,
   consumed only by `BackgroundHost`; cards untouched). Tuned lighter twice per owner
   for stronger colour pop: galaxy 0.05/0.15/0.30, standard 0.08/0.20/0.38.
2. Local **chrome scrim** (`ChromeScrim`, `CHROME_SCRIM_OPACITY` = card opacity, the
   AA floor) behind bare-on-background chrome: app bar (app-wide), dashboard count +
   empty states, GroupEvents, Digest, ThingsToRemember, Archived, Unbound, Compose.
