# 31.1-05 SUMMARY — Corrective: selected backgrounds visibly present (readability-safe)

**Status:** complete — owner-approved. **Type:** corrective (phase was paused by the owner's production-release failure).

## Problem
The shipped 31.1 `BackgroundHost` painted the selected asset then overlaid a full-screen
`colors.surface` scrim at the **card** density opacity (galaxy 0.88–0.97, standard 0.97–1.0),
leaving 0–12% of the art. Every selection looked identical on regular screens; only the
Settings picker swatches (rendered with no scrim) looked right. Selection + persistence were
verified working — not the fault. Diagnosed at source and on-device.

## Change (commits `5f2ea38` → `df8f5d2`)
- **Decoupled the host veil from card opacity** — new `BACKGROUND_VEIL_OPACITY`, consumed only
  by `BackgroundHost`; card opacity untouched so the AA proof stays valid (D-31.1-05-A).
- **`ChromeScrim`** — a token-only local backing behind bare-on-background chrome (app bar
  app-wide, dashboard count/empty states, GroupEvents, Digest, ThingsToRemember, Archived,
  Unbound, Compose) so text stays AA-readable over the lightened veil.
- **Guards** — a visibility-floor test (fails if any package/density art contribution regresses
  toward 0 — the shipped bug) + per-asset chrome-scrim AA.
- Veil tuned lighter twice per owner (final in `31.1-06`).
