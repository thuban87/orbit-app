Ordered by name.
    - off_limits fuel NEVER contributes a match and NEVER appears as a snippet, for any term.
    - Archived contacts (archived_at IS NOT NULL) NEVER appear.
    - The term is `?`-bound (the %…% wrapper built in JS and bound); a term containing % or _ is treated as data (no interpolation); an empty/whitespace term returns [] (or the caller guards — decide and document).
    - Each contact appears at most once (DISTINCT / grouped).
  </behavior>
  <action>
    Extend src/db/fuel-read.ts with searchFuel(exec, term): a pure read (no transaction, no network). Build like = '%' + term + '%' in JS and bind it; SELECT c.id AS contactId, c.name, and a correlated snippet subquery (SELECT f.text FROM fuel f WHERE f.contact_id = c.id AND f.kind != 'off_limits' AND f.text LIKE ? LIMIT 1) FROM contacts c WHERE c.archived_at IS NULL AND (c.name LIKE ? OR EXISTS(SELECT 1 FROM fuel f2 WHERE f2.contact_id = c.id AND f2.kind != 'off_limits' AND f2.text LIKE ?)) ORDER BY c.name. Every `?` bound to the same `like`; off_limits excluded in BOTH the snippet subquery and the EXISTS predicate; archived excluded. Export a FuelSearchResult interface { contactId: number; name: string; snippet: string | null }. Guard an empty/whitespace term by returning [] before querying. Document: ASCII-only case folding is expected (ICU absent) — do not "fix" it; consider (optional) an ESCAPE clause note for literal % / _ but binding already prevents injection.
