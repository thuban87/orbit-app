<objective>
## Phase Goal

**As a** person maintaining relationships, **I want to** save per-item conversational fuel on each contact — across recent / topic / fact / gift / off-limits, with optional labels and links — and see the single most-relevant line surface everywhere I glance, while private off-limits notes structurally never leave the device, **so that** I always have something real to say and never accidentally raise a forbidden topic.

*(Derived from ROADMAP Phase 7's 3 success criteria + dossier `docs/dossier/03-fuel.md`; the ROADMAP `**Goal:**` line is task-shaped, so the story is framed from the success criteria, not invented.)*

## This plan (slice 1 of 4)

Deliver the thinnest end-to-end fuel path: a user can **add, edit, and delete** per-item fuel across all 5 kinds + optional label/url on a contact's profile, and see it listed. This is FUEL-01 (writer + editor + mount) and FUEL-02 (the 5 kinds + optional label; off_limits editable and marked). The ranked line, age, AI-unconfirmed state, and search land in Plans 02–04.

Purpose: establishes the `fuel-dao` writer (the `*Core` + mutexed split every later fuel write and Phase-10 multi-attach compose on) and the shared `fuel-read` module (the single choke point every projection will extend), then mounts the editor so the capability is user-visible.

Output: `fuel-dao.ts` (+test), `fuel-read.ts` (+test) with the editor-list read, `FuelEditor.tsx`, and the "Conversational Fuel" section on `ContactProfileScreen`.

**No new migration.** The `fuel` table (uid, contact_id, kind, label, text, url, created_at, source, modified_at) already shipped in migration 1 (`src/db/migrations/001-initial.ts:167-179`). Never edit migration 1. No ranking index this phase (tens-of-rows scale; an index would require a forbidden migration 2 — owner locked "no new migration").
</objective>
