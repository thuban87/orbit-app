<objective>
Build the two Wave-1 pure modules at the heart of type semantics: the 7 target-type parsers (FLD-04)
and the single `sortExpr()` helper (FLD-06). Both are pure string functions with no DB or UI coupling.

Purpose: Storage is TEXT forever (CLAUDE.md invariant). The parsers are READ-TIME validators that decide
whether a stored string is valid under a field's current type (clean → renders/sorts; unconvertible →
flagged tap-to-fix) — they never rewrite bytes. `sortExpr()` is the ONE place the TEXT-storage decision
is allowed to be observable; every sort and filter routes through it so numbers do not sort as `"10" <
"9"`.

Output: `src/db/field-parsers.ts` (`parsers` record + `ParseResult`), `src/db/field-sort.ts`
(`sortExpr`), each with pure/node Vitest coverage.
</objective>

      sortExpr's CAST sorts correctly.
    - photo: identity pass-through (the native widget is deferred to Phase 5; keep the parser so the
      7-type set is complete).
