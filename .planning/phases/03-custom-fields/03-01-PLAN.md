<objective>
Build the two Wave-1 leaf modules that make `col_name` safe by construction (FLD-02): the reserved
fixed-column whitelist and the slugifier that is the *single producer* of every custom-field
`col_name`. Also land the shared `CustomFieldDef` DB-row type consumed by every later module.

Purpose: `col_name` is the ONE identifier this whole phase ever interpolates into SQL. Making it
whitelist-CONSTRUCTED (never escaped) at a single chokepoint is the primary security control for the
subsystem (CLAUDE.md invariant; RESEARCH Security Domain V5). A co-located drift test guarantees the
whitelist can never silently fall out of sync with the real schema.

Output: `src/db/field-types.ts` (shared `CustomFieldDef`), `src/db/reserved-columns.ts`
(`RESERVED_COLUMN_NAMES`), `src/db/col-name.ts` (`slugify` / `makeColName` / `isSafeColName`), and
`src/db/transaction.ts` (the single `inWriteTransaction`, extracted from recency-dao), each with
node:sqlite / pure Vitest coverage.

This plan now also lands the shared write-transaction primitive (Task 3, addressing review LOW/HIGH-1):
`inWriteTransaction` currently lives as a private copy inside `recency-dao.ts` and every Phase-3 writer
was slated to re-copy it verbatim. Four copies is four places to forget the no-nesting rule — which is
exactly how the sweep-deadlock (HIGH-1) arose. Extracting it to one file with a non-reentrancy header,
in Wave 1, means every later plan IMPORTS it (never copies) and the warning lives where it is read.

Ownership note: these are LEAF modules owned by Phase 3. Phase 4 imports `RESERVED_COLUMN_NAMES` and
`makeColName`; nothing here imports back into a later phase (breaks the ROADMAP circular-dep concern).
`transaction.ts` depends only on Phase-2's `mutex.ts` + `types.ts`, so it is a genuine Wave-1 leaf that
Plans 03/04/05/07 all consume.
</objective>
