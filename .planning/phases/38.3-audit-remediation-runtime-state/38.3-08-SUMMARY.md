# Phase 38.3 Plan 08: Coherent Profile Snapshot and History Summary

**The Profile snapshot load is now latest-request gated. Each successful publication bumps a History revision, and History re-reads on it, so the metrics and History refresh from one trigger. An interaction delete publishes the shell tick. History's "today" follows the local date on the current window (D-12) with no timer.**

## Accomplishments

- **Snapshot loader.** `createProfileSnapshotLoader` sits on `createLatestRequestAuthority`. `publish`, `fail` and `settle` run only for the current token, and the revision goes up once per current successful publication. `ContactProfileScreen` loads on focus, on the shell tick, and on the post-sweep foreground tick (D-14). It invalidates the loader on unmount and passes `historyRevision` down.
- **History reads.** `HistorySection` no longer has its own focus read. It reads in a `useEffect` keyed on `[load, revision]`, which also runs on mount, so collapsing and re-expanding reads fresh data. The read has its own latest-request authority.
  - A first-read failure shows "Couldn't load history" with Retry, instead of an endless "Loading history…" and an unhandled rejection.
  - A failed re-read keeps the rows and shows a "Couldn't refresh history" notice with Retry.
  - Open card, sheet and detail selections are never reset by a refresh.
- **Delete.** `InteractionDetail` calls `notifyWidgetDataChanged()` and then `bumpShellRefresh()` (once each) before `onDeleted()`. History's `onDeleted` only closes the detail. The shell tick reloads the Profile, which bumps the revision, which re-reads History.
- **Day rollover.** One `HistoryDayState` replaces the memoized `today` and the `refDate` state. It is advanced with `formatLocalDate(new Date())` on mount and on every revision. Lens change, Prev and Next go through pure transitions. Everything that depends on today reads from this state: `canGoNext`, `cycles({ now })`, the Rolodex `today`, the empty-state and card `log(...)`, and the window.
- **Docs.** `docs/systems/profile.md` and `docs/systems/interaction-history.md` describe the revision contract, the delete shell tick and D-12. `interaction-history.md` gains a new Gotcha #13, and each doc has a 38.3 Changelog row.

- **Found during:** Task 1
- **Issue:** The plan named only `historyReadStateOnFail` and `historyReadStateOnPublish`. Without a start transition, a Retry from the error state would keep showing the error while the retry was in flight.
- **Fix:** Added `initialHistoryReadState` and `historyReadStateOnStart`. From `error`, a start moves to `loading`; a loaded view is kept as is. Both are unit-tested.
- **Files:** `src/components/history/history-section-logic.ts` and its test.
