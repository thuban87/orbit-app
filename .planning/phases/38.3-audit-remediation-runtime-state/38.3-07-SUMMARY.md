# Phase 38.3 Plan 07: Read tri-states for BackupSettings, ReconcileComplete and Memory Summary

This plan adds a shared `ReadPhase<T>` type and an authority-gated `runGatedRead` that never rejects. Three screens now tell loading, error and success apart. BackupSettings never shows a known "Off", folder or passphrase-setup state from settings it could not read. ReconcileComplete shows a real loading state. MemoryScreen never opens the editor over a failed read.

## What was built

- **`src/logic/read-phase.ts`** (pure, no imports):
  - The `ReadPhase<T>` union, plus the `readLoading`, `readLoaded` and `readFailed` constructors, `readStarted` (a loaded view is kept during a re-read), and `loadedData`.
  - A structural `ReadGate` that matches `LatestRequestAuthority`.
  - `runGatedRead`: it publishes only for the current token, calls `onLoaded` only for the current request, logs every failure through `onError`, and never rejects.
- **BackupSettings:**
  - Read ownership now lives in an awaitable `readSettings()`. The old one returned a cancel function from a detached IIFE, so every `await reload()` awaited nothing.
  - The focus effect invalidates the authority on blur.
  - `backupSettingsPresentation(phase)` decides whether the groups, the encryption summary and the folder flags render.
  - While settings are loading the screen shows a spinner (`colors.accent`). If the read fails it shows "Couldn't read backup settings" with an explanation and a Retry button.
  - `chooseFolder`, `saveDays` and `saveFuturePassphrase` go through `commitThenRefresh`. `enableEncryption`, `changeEncryption` and `disableEncryption` await `readSettings()` directly. That is safe because it never rejects, and those handlers have no catch that could mislabel a failure.
  - Write paths, SAF calls and the encryption lifecycle are unchanged.
- **ReconcileComplete:** a `ReadPhase` plus an authority.
  - Loading shows a spinner and "Loading check summary…".
  - Error shows "Couldn't load the check summary." with a Retry that only re-reads.
  - Loaded shows the same summary and actions as before.
- **MemoryScreen:**
  - Loading shows a spinner.
  - Error shows "Couldn't load memories" with a Retry button, and `MemoryEditor` does not render.
  - Loaded shows the editor over `memoriesPhase.data`.
  - In `restore`, `remove` and `setAllowAi`, the write's catch now covers only the write. After a committed write, a failed re-read goes to the error phase and is not logged as a write failure.
  - The snackbar with Undo, the single-flight `add`/`edit`, and `returnToChooser` are unchanged.
- **Docs:** 38.3 Changelog rows in `backup-restore.md`, `contact-reconciliation.md` and `contact-knowledge.md`.
