<objective>
Persist explicit participant override value edits (RG-019: `reliability-testing/AUD-REL-006`). Root cause (verified): `ParticipantOverrideEditor.changeValue` (:78-84) only flips follow to false when a value changes; both patch builders (`EditParticipantScreen.tsx:74-96`, `EditGroupEventScreen.tsx:200-231`) emit a field ONLY when its follow boolean changed, so a false→false value edit sends nothing and `saveParticipantEdits` no-ops on the empty patch.

One pure builder, used by both editors, emits `{ follow: false, value }` whenever both the initial and draft states are overridden and the value differs, and keeps the follow-changed rule for everything else — never inferring follow from equality (ADR-125).

This plan changes ONLY how the participant patches are built. Draft preservation and commit-vs-refresh separation in `EditGroupEventScreen` (REL-007/008) are Plan 06.

Plan against the dossier (D-01); packet-qualified IDs (D-02). The RG-019 planning note — "test actual coordinator sequences rather than source-string presence" — applies: the proof is a DAO round-trip, not a grep.
Spec-less probe fallback: skipped (visible) — ROADMAP requirement IDs were TBD; ADR-125's rejected alternative is authored as a descriptor-less prohibition.
</objective>
