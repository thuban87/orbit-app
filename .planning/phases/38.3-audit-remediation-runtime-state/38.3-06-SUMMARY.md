# Phase 38.3 Plan 06: Draft-Preserving Participant Refresh and Commit-vs-Read Recovery Summary

**A new pure module, `src/screens/group-event-refresh.ts`, separates participant commits from event readback on both saved-event screens. The parent draft is seeded once and never reseeded by participant work (D-17). Following participants resolve against the saved event (D-18). A committed add whose readback fails closes the picker as a success and shows "Couldn't refresh this event" with a Retry that only re-reads. It is never replayed, and until a successful refresh the committed ids stay out of the picker (D-19, D-04; reliability-testing/AUD-REL-007, reliability-testing/AUD-REL-008).**

## Accomplishments

- `groupEventEditReducer` over `{ event, draft, baseline, loadError, refreshError, committedPendingIds }`. `initialLoaded` is the only seed. `eventRefreshed` replaces `event` only and clears the refresh error and pending ids. `isGroupEventDraftDirty` compares the draft with the untouched baseline.
- `createGroupEventRefreshController` uses the Plan 01 latest-request authority. Only the newest read publishes, whether it succeeds or fails. `invalidate()` runs on unmount.
- `runParticipantAdd` awaits `addParticipants` alone. A rejected write propagates, so the picker keeps its ADR-127 retry error. After a commit it records the committed ids and runs the refresh detached.
- EditGroupEventScreen now runs on the reducer. It has a mount-only `loadInitial`, `draftChanged` dispatches, and `refreshEvent()` after add, remove and participant Save, plus an inline refresh-error row with Retry. The reseeding `load()`, `baselineRef` and `throwOnFailure` are gone.
- GroupEventDetailScreen reads through the same controller on focus and after writes. It keeps the "Couldn't load" view when there is no event yet, and shows an inline refresh row with a read-only Retry once an event is on screen. It now shows remove, dissolve and delete write failures inline; before, they were invisible whenever an event was loaded. It uses `runParticipantAdd` with committed-id exclusion.
- The orphaned `contact-picker-multiselect.test.ts` batch-and-reload case was rewritten to assert the new owner contract on both screens. The ContactPicker source case is unchanged.
- `docs/systems/group-events.md`: updated How It Works steps, a new key-file row, Gotchas 11 and 12, and a 38.3 changelog row.
