# Phase 38.3 Plan 02: Dashboard Panel Dismissal Single-Owner Fix Summary

**The Dashboard panel store now owns panel open state. `dismissDashboardPanel` captures the request before `close()`, so the owner's handler runs exactly once, and Home derives its background inertness with `selectPanelOpen`. Home is interactive again after every scrim, Back or re-tap dismissal (react-native/AUD-RN-001).**

## Accomplishments

- **Root cause removed.** The host dismissal called `close()` and only then read `getState().request?.onDismiss()`. That read always returned null, so `onPanelOpenChange(false)` never ran and Home's local `panelOpen` stayed `true`. The new `dismissDashboardPanel()` captures the request first, then closes, then invokes the captured handler.
- **One owner.** Home's `useState` mirror is gone. `const panelOpen = dashboardPanelStore(selectPanelOpen)` means presentation and inertness read the same store, so they cannot desync, including across a tab switch and return.
- **`DashboardControlRow` simplified.** The `onPanelOpenChange` prop is removed, along with its three `true` calls and its `false` call. The owner dismissal (trigger re-tap and `request.onDismiss`) is a plain `close()`.
- **Node proof.** `dashboard-panel-store.test.ts` has 5 cases: single invocation with a null request; a no-op when nothing is open; replacement during content refresh (only the latest handler fires); open/closed across all three panel ids; and an owner handler that itself calls `close()`, which still fires exactly once.
- **Contract documented.** `docs/systems/dashboard.md` gets Gotcha 18 (single owner, `selectPanelOpen`, capture-before-clear, and the D-05 hold on `accessible` grouping), a Key Files row and a 38.3 Changelog row.
