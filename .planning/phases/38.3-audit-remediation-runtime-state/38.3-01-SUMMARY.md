# Phase 38.3 Plan 01: Freshness Primitives Summary

**This plan adds four pieces:**
- **Foreground tick.** The owning launch-sweep run publishes it once, after all of its hooks have settled. It is a second counter in the existing Zustand shell-refresh store, and `App.tsx` wires it.
- **Latest-request authority.** A shared guard (`createLatestRequestAuthority`) that stops an older read from publishing its rows or its error over a newer one.
- **Fault registry.** A dev-only way to inject failed or delayed reads, armed from the dev menu.
- **Warm notification refresh.** A notification Mark or Snooze handled in a live process now bumps the shell tick.

## Accomplishments
- **`onSweepSettled(listener)` in `launch-sweep.ts`.** It fires only from the owning run's `finally`, after the `do/while` loop, including any coalesced follow-up pass. Rules:
  - A re-entrant early return publishes nothing.
  - Each listener is isolated with `try/catch` and logs content-free.
  - `__resetSweepForTest` clears the listeners.
  - The module still has no react-native or store import.
- **Foreground tick in the shell-refresh store.** It adds `foregroundRevision`, `publishForegroundRefresh()`, `useForegroundRefresh()` (same skip-initial-revision idiom) and `readRefreshRevisions()`. The existing `useShellRefresh` and `bumpShellRefresh` behave exactly as before.
- **`App.tsx` wiring.** It registers `onSweepSettled(publishForegroundRefresh)` before `installSweepTrigger`, so the cold-start sweep publishes too, and removes it in the effect cleanup.
- **`createLatestRequestAuthority()`.** The util has no imports. Its module doc spells out the contract: gate every publication, including data, counts, errors and loading settles.
- **`uat-faults.ts` and dev-menu items.** The registry is one-shot and does nothing outside `__DEV__`. `uat-probes.ts` gains three items: fail next Digest day read, delay next Digest day read (5s), and fail next assist queue refresh.
- **Warm notification actions.** `handleNotificationAction` calls `bumpShellRefresh()` exactly twice in the source: after a committed Mark (after the widget publish) and after a committed Snooze.
- **Docs.** `app-shell.md` and `persistence-core.md` document both refresh signals, the `onSweepSettled` contract and the consumer rule. Each gained a 38.3 Changelog row.

## Decisions Made
- Listeners are delivered from a snapshot, so an unsubscribe during delivery cannot skip a sibling listener.
- The shell bump sits inside the existing `try`, after the DAO write and before the decay-notification cancel. If the cancel fails after the write commits, the tick is still (correctly) published.
- The Task 2 non-dev tests go further than the plan asked. They arm a fault while `__DEV__` is off, then turn it on and apply the fault. That proves arming stored nothing; it does more than show that applying the fault was a no-op.
