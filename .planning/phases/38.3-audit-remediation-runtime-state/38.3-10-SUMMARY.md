# Phase 38.3 Plan 10: Settings-hosted Profile and Message Eligibility Summary

**Settings now registers every route a Profile can offer except Compose and ComposeResearch, and a test keeps those two out. The FAB preselects a Settings-hosted Profile's contact. The hero Message button is disabled, with a reason, for archived contacts in every host and for any Profile hosted in Settings.**

## Accomplishments

- `PROFILE_REACHABLE_ROUTES` moved from the test into `shell-contract.ts`. Added `SETTINGS_HOST_EXCLUDED_PROFILE_ROUTES = ["Compose", "ComposeResearch"]` with a D-09/D-25/RG-021 doc comment.
- `SettingsStack` registers `RecentlyDeleted`, and `SettingsStackParamList` gains `RecentlyDeleted: { contactId: number }`. Settings → Archived → Profile → Things to Remember → Recently Deleted now resolves; before this it was a silent no-op in release.
- New `settings-routes.test.ts` describe "Settings-hosted Profile route family". It checks that every non-excluded Profile route is registered and that Compose/ComposeResearch are not. A temporary edit registering both made 2 tests fail; the edit was reverted before commit.
- `getFocusedContactContext` allowlists `SettingsTab`, so the FAB preselects the contact in all five Profile hosts.
- `profileHeroActionState(methods, { archived, settingsHosted })` checks archived first, then the Settings host, then available methods. Call is unchanged.
- `ProfileHero` takes a `messageContext` prop. The Message button always renders, disabled with its reason caption when blocked. `ContactProfileScreen` takes `host?: "settings"` and passes `archived: snapshot.identity.archivedAt !== null`.
- `SettingsProfileHostRoute` renders `<ContactProfileScreen {...props} host="settings" />` and is registered as `<Stack.Screen name="Profile" …>`.
- `docs/systems/profile.md` gains a "Message eligibility (38.3, RG-021)" section, Gotcha 16 (do not fix Settings messaging by registering Compose), and a Changelog row.
