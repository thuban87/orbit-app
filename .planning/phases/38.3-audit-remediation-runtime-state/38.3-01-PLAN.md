<objective>
Build the three freshness primitives every later 38.3 consumer depends on, and wire the one missing producer:

1. A post-sweep **foreground tick** — `runLaunchSweep()` publishes `onSweepSettled` exactly once per owning run, `App.tsx` forwards it to a new `publishForegroundRefresh()` counter in the existing shell-refresh store, and consumers subscribe with `useForegroundRefresh` (D-14: resume reads are ordered after the sweep's purge/expiry writes).
2. A generic **latest-request authority** (`createLatestRequestAuthority`) generalizing the `use-category-catalog-refresh.ts:15-36` generation idiom, gating rows, counts AND errors (D-23; react-native/AUD-RN-010).
3. **Warm notification action publication** — a foreground-process Mark/Snooze success bumps the shell tick so a visible Digest/Home/Profile converges (D-13).

Plus a debug-only fault registry (`uat-faults.ts`) with dev-menu items so Plan 16 can inject delayed/rejected reads on the Pixel (RG-026 and RG-023 DEVICE expectations). Inert in release (38.2-16 precedent: `__armUatSweepFault`).

Purpose: RG-022/024/026 consumer fixes (Plans 08, 12, 14, 15) all need a sweep-ordered resume signal and a shared stale-result guard; building them once avoids per-screen `cancelled` closures (the RN-010 root cause).
Output: sweep settled listener, foreground tick, authority util, fault registry, warm-action publication, doc sync.

Plan against the dossier (D-01); preserve packet-qualified IDs (D-02); D-03 (no bus/library/snapshot) and D-22 (no timers) are the binding constraints here.
Spec-less probe fallback: skipped (visible) — ROADMAP requirement IDs were TBD at planning, so there was nothing to probe; the D-03/D-22 "do not introduce" constraints are authored above as descriptor-less `must_haves.prohibitions`.
</objective>
