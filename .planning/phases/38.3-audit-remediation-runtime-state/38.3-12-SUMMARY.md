# Phase 38.3 Plan 12: Dashboard Refresh Scheduler Summary

**Home now has one refresh scheduler and one gated publication seam (RG-022, D-23, D-14).** Every Home read is issued by `createDashboardRefreshScheduler` and published only through `publishDashboardRead`. So an older read can no longer overwrite newer rows, counts, errors or settles. Home also no longer reads when animation or lifecycle state changes, or while it is hidden. Its resume read runs after the sweep, and each bulk commit or Undo triggers exactly one read.

## Accomplishments

- **Scheduler and seam.** `src/screens/dashboard-refresh-scheduler.ts` is pure: no React and no timers.
  - `request(source)` returns a latest-request token. For `shell` or `foreground` while Home is hidden it returns `null`.
  - `isCurrent` and `invalidate` are the authority checks.
  - `publishDashboardRead` covers every write a read makes today, including the `resultProgress` fade start through the `setFadeStart` sink and the refreshing/initial-load settle. It calls no sink at all for a stale token.
- **HomeScreen read path.**
  - `reload(source)` is now just `scheduler.request(source)`.
  - The read body lives in `readRef.current`, reassigned every render so it reads the current `debouncedSearchText` and `query`.
  - A superseded read skips its line-3 enrichment read.
  - The fade start is computed from `isFocusedRef`, `appActiveRef` and `reducedMotionRef`.
  - Deps are `[debouncedSearchText, query, scheduler]`, with a `biome-ignore` explaining why.
  - The pull canceller ref and its unmount effect are gone. Unmount invalidates the scheduler.
- **Hidden deferral and resume.**
  - `useShellRefresh(onShellRefresh)` and `useForegroundRefresh(onForegroundRefresh)` route through the scheduler, which defers them while Home is hidden.
  - The unconditional `AppState` "active" reload listener is deleted. Resume now comes from the post-sweep foreground tick (D-14).
  - The animation-only `setAppActive` listener stays.
- **Single bulk refresh.** `commitBulkOutcome` and `performBulkQuickLog` no longer call `reload` directly. The `bumpShellRefresh()` they already emit is the one read. `refreshAfterSnooze` now calls `reload("snooze")`.
- **Debug marker.** Each issued read logs `Logger.debug("dashboard-home", "dashboard read bundle", source)`, which is content-free, so the Plan 16 device run can count reads.
- **Docs.** `docs/systems/dashboard.md` gains:
  - a "Refreshing the Dashboard" contract
  - scheduler rows in the layer and key-file tables
  - Gotcha 19
  - a Changelog row: "38.3 | Refresh scheduler + latest-result ownership (RG-022)"
