# Phase 38.3 Plan 09: Cross-tab entry keeps semantic roots Summary

**Every cross-tab nested entry now goes through one `navigateIntoTab` helper that sends `initial: false`. A tab visited for the first time therefore starts at its declared root, with the target screen on top. A repository guard fails if any source file navigates into a tab directly (RG-021, react-native/AUD-RN-002).**

## Accomplishments

- `src/navigation/tab-entry.ts`: `navigateIntoTab(nav, tab, screen, params?)` calls `nav?.navigate(tab, { screen, params, initial: false })`. `nav` is a structural type, so the container ref, `getParent()` results and `useNavigation()` results all satisfy it. Screens and params are typed per tab stack.
- Root cause confirmed in the installed `@react-navigation/core` 7.21.13. `useNavigationBuilder` `getStateFromParams` builds a single-route state from `params.screen` unless `initial === false`. With `initial: false`, the first initialization uses the stack's `initialRouteName` (Home / GroupEvents / Digest / Orrery / Settings, all verified in `src/navigation/tabs/*`) and then dispatches NAVIGATE to the target. A mounted stack takes the unchanged `!isNestedParamsConsumed` NAVIGATE branch. Root-screen targets such as Digest → Contacts Home are harmless: StackRouter NAVIGATE to the focused route only updates params.
- Converted all 17 call sites. The `DashboardTab|EventsTab|DigestTab|OrreryTab|SettingsTab` grep from the plan now matches only a doc comment in `tab-entry.ts`.
- Guard test: it walks every non-test `.ts`/`.tsx` file under `src`, excluding `tab-entry.ts`. Twelve self-tests cover the flagged forms (double, single and backtick quotes; multi-line; push/replace; `intent.tab`; the object form) and the allowed forms (`reset` routes, non-tab navigate, the helper itself). On failure it reports `src/…:line`.
- `docs/systems/app-shell.md`: added a Key Files row, a "Moving through the shell" step 5, the required Gotcha, and a 38.3 Changelog row.

## Decisions Made

- Helper typing uses an explicit tab → stack param list map rather than `infer` through `NavigatorScreenParams`. The inferred form kept screen names but let `{ sessionId: "x" }` through; I checked both forms with a throwaway tsc probe. A tab added to `TabParamList` without a row in the map fails to compile.
- The guard covers bare tab navigation, not only nested payloads, as the plan's behavior bullet specifies. There are currently no bare tab navigations in `src`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] The helper checks screen and param types per tab**
- **Found during:** Task 1
- **Issue:** The plan's signature typed only `tab` (keyof TabParamList). An `infer` over `NavigatorScreenParams` checks screen names but silently accepts wrong param shapes, which would have hidden a param-shape regression at every converted call site (the old calls were partly `as never`-cast).
- **Fix:** Added an explicit `TabStackParamLists` map with generic `Screen`/`params` constraints. All 17 call sites typecheck with no casts.
- **Files modified:** src/navigation/tab-entry.ts
- **Commit:** 69ac7b0

**2. [Scope, docs] app-shell.md got a Key Files row and a "Moving through the shell" step 5 in addition to the required Gotcha and Changelog row**, so the living doc shows the helper where readers look for navigation owners. Commit dbea547.
