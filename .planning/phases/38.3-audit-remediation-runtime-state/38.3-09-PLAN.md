<objective>
Preserve each tab's semantic root on first nested entry (RG-021: `react-native/AUD-RN-002`, S1). Verified root cause: installed `@react-navigation/core` 7.21.13 `useNavigationBuilder.tsx:308-316` builds a single-route state from nested `params.screen` unless `params.initial === false`; with lazy tabs (default) a fresh Digest launch followed by FAB Add Contact initializes Contacts as `[Create]`, then `CreateContactScreen.tsx:394` `replace("Profile")` leaves `[Profile]` and reselect (`RootNavigator.tsx` popToTop only when index > 0) cannot recover Home. The documented fix is `initial: false` (reactnavigation.org/docs/nesting-navigators).

One helper, every caller, and a guard test so the bug class cannot return. Call sites verified by grep on 2026-09-25: `UniversalFab.tsx:253,275`, `linking.ts:63,67`, `ComposeScreen.tsx:946-950`, `ResumeImportPrompt.tsx:27,42,48,56,62`, `ResumeReconcilePrompt.tsx:85`, `OrreryScreen.tsx:1298`, `ImportCompleteScreen.tsx:322,341`, `HomeScreen.tsx:195,1475`, `DigestScreen.tsx:143`.

Plan against the dossier (D-01); packet-qualified IDs (D-02); D-03 / ADR-146 (independent histories, Digest landing, no broad resets); D-26 (resume prompts via the helper). Settings host parity (`react-native/AUD-RN-004`) is Plan 10; History destinations (`architecture/AUD-ARCH-008`) are Plan 13.
Spec-less probe fallback: skipped (visible) — ROADMAP requirement IDs were TBD; the ADR-146/D-03 "do not introduce" constraints are authored as descriptor-less prohibitions.
</objective>
