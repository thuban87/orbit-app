## Summary

Every audited defect is still present on disk. I re-read each anchor this session; line numbers have drifted only slightly from CONTEXT.md. The phase splits cleanly along **state ownership**:

1. **Producer publication.** This means the shell-refresh tick, a new post-sweep foreground tick, and the assist publisher.
2. **Consumer subscription with latest-request authority.** The consumers are Home, Digest/Your Week, Profile/History and notification ingress.
3. **Commit-vs-read outcome separation.** This covers Group Event participants, import, and several read screens.
4. **Navigation contract fixes.** These are the `initial: false` tab entry, Settings host parity, the History reveal, and archived Message.

The single most important shared mechanism is `src/stores/shell-refresh-store.ts`. It is a 31-line Zustand revision counter whose `useShellRefresh(cb)` fires `cb()` from an effect on each revision change and **discards any return value**, so callers' cancellers are lost. It also fires regardless of focus or AppState.

No sweep-completion signal exists today. `runLaunchSweep()` publishes nothing when it finishes, so D-14 ("ordered after the sweep") needs a new, small hook in `launch-sweep.ts`, wired once in `App.tsx`.

The codebase already has the latest-request idiom: `createCategoryCatalogRefreshCoordinator` in `src/hooks/use-category-catalog-refresh.ts` (a generation counter plus invalidate on blur/unmount). It is node-testable and should be generalized into one small util, not re-invented per screen.

**The test harness cannot mount components.** Vitest runs in `environment: "node"` with no renderer. The house pattern is recorded in `src/theme/use-reduced-motion.ts`: "the repo has Vitest but no react-test-renderer, so a hook cannot be mounted/unmounted in a node test". The rule is: extract the lifecycle and ordering logic into plain controllers, test them with deferred promises, and prove the wiring on the Pixel 6 Pro.

**Primary recommendation:**
- Add one generic latest-request authority util and one post-sweep foreground publication, both in Wave 1.
- Then fix each consumer against those primitives, with a pure-controller test per ordering rule.
- End with a device-UAT integration plan. That plan includes the D-05 TalkBack gate, which runs after RN-001 is fixed.

### Pattern 1: Latest-request authority (reuse the existing idiom)

**What:** A monotonic generation counter. `begin()` returns a token, `isCurrent(token)` gates every publication (rows, counts **and** errors), and `invalidate()` runs on blur/unmount.

**Precedent:** `[VERIFIED: src/hooks/use-category-catalog-refresh.ts:15-36]`. It is quoted here verbatim:
- `let generation = 0;`
- `const requestGeneration = ++generation;`
- `if (requestGeneration === generation) input.commit(categories);`
- `invalidate(_reason: "blur" | "unmount"): void { generation += 1; }`

**When to use:** Home reload (RN-010), Digest outer read, Your Week period read and day read (D-16 "request-scoped, not date-only"), Profile snapshot load, HistorySection load, and the assist-store queue refresh.

### Pattern 2: Publication after the sweep, by the owning run only

`runLaunchSweep()` returns early for a re-entrant call: `if (running) { pendingRerun = true; return; }` `[VERIFIED: src/services/launch-sweep.ts:107-111]`. A listener attached to *each call's* promise would therefore fire **before** the in-flight pass finishes. Fire the settled listeners only from the owner path, after the `do { … } while (pendingRerun)` loop `[VERIFIED: launch-sweep.ts:114-150]`, in `finally` after `running = false`. Catch listener errors.

### Pattern 3: Controller extraction for "mounted" verification

The existing precedents are:
- `createReducedMotionController`
- `createCategoryCatalogRefreshCoordinator`
- `subscribeToWidgetUrls` in `widget-linking.ts:204-230`
- `quick-log-command.ts` (dependency-injected)
- `edit-contact-save-coordinator.ts` (38.2 RG-018 commit → failed read → retry)

Each ordering rule becomes a plain function or factory with injected `read`, `publish` and `isVisible`. It is tested with hand-controlled deferred promises. The screen becomes thin wiring, verified on device.

### Anti-Patterns to Avoid

- **Reseeding a draft from a refresh.** `load()` in `EditGroupEventScreen` writes `baselineRef` and `setDraft`. Never call it after participant work (REL-007).
- **One `try` around commit + readback.** It maps a read failure to "not saved" and invites replay (REL-008, D-04).
- **Inferring follow state from value equality.** This is REJECTED in ADR-125 ("Infer follow state from value equality — rejected because an explicit equal-valued override must stay detached").
- **Reading a Zustand field after clearing it.** This is the RN-001 bug.
- **Adding a component to reload `useCallback` deps for animation purposes.** This is PERF-002; use refs instead.
- **A timer to detect midnight** (D-22).
- **Registering Compose under Settings** (D-09, owner).
- **Replacing panels with native modals, or dropping `no-hide-descendants`** (ADR-095, owner).

## Don't Hand-Roll

| Problem | Don't build | Use instead | Why |
|---------|-------------|-------------|-----|
| Latest-request gating | Per-screen `cancelled` closures (the RN-010 root cause) | One `createLatestRequestAuthority()` util, modelled on `use-category-catalog-refresh.ts:15-36` | Cleanup of one effect is not cancellation of all sources. A shared token is. |
| Nested-tab first entry | Hand-built `state: { routes: [...] }` payloads or `reset` | `initial: false` via one helper | Documented contract. Avoids broad resets (ADR-146). |
| Double-tap latch | React `useState` flag | `beginInFlight`/`endInFlight` (`src/utils/single-flight.ts`) | Synchronous. Already node-tested. |
| Cold/warm ordering | A new generation scheme | The `widget-linking.ts` "warm received ⇒ drop cold" rule | Already reviewed. Same semantics. |
| Midnight detection | `setTimeout` to midnight | Recompute `formatLocalDate(new Date())` on focus/resume/revision | D-22 and the "nothing watches a timestamp" rule. |
| Post-sweep ordering | Polling or delay | A `onSweepSettled` listener fired by the owning run | The sweep already coalesces and serializes. |

**Key insight:** every defect here is a *missing contract between correct parts*. SQLite writes, DAO guards, the reducer and the navigator are each correct. Fix only the seams, and leave the DAOs untouched.

## Common Pitfalls

### Pitfall 1: The publisher throws after commit
**What goes wrong:** `await refresh()` rejects after `markAssistLogged` committed. The new Alert then says "Couldn't log", and the user retries.
**How to avoid:** The publisher is fire-and-forget with internal catches. Test "write resolves, queue refresh rejects ⇒ no onError".

### Pitfall 2: Sweep publication attached to the wrong promise
**What goes wrong:** An `installSweepTrigger`-level `.finally` fires for a re-entrant early-returning call before the real pass ends, so Digest reads pre-purge data.
**How to avoid:** Fire only from the owning run after the `do…while` loop. Test with an overlapping second trigger.

### Pitfall 3: Resume latency behind the backup hook
**What goes wrong:** D-14 orders Digest and Home after the **entire** sweep, which includes backup (SAF write) and notification reconcile. A slow backup delays the resume refresh.
**How to avoid:** Measure on the Pixel. The existing debug probe "UAT: slow next sweep pass (8s)" (`src/__dev__/uat-probes.ts:23-29`) exercises the ordering. If latency is unacceptable, raise it with the owner, because D-14 is an owner ruling. See A3.

### Pitfall 4: Orphaned source-string tests
`contact-picker-multiselect.test.ts:61-76` (RG-019), `DigestDayDetail.test.tsx`, `YourWeekSection.test.tsx` and `settings-routes.test.ts` / `SETTINGS_REGISTERED_ROUTES` all assert current contracts.
**How to avoid:** grep every consumer, including tests, and change each in the plan that changes its contract (memory `orphaned-test-consumer-build-breaker`).

### Pitfall 5: Losing the Your Week toggle write
**What goes wrong:** A refresh that adopts `settings.yourWeekPeriod` while `pendingPeriod !== null` reverts an in-flight toggle.
**How to avoid:** Skip adoption while pending, and add a test for it.

### Pitfall 6: Worklet forward reference (Hermes crash that vitest can't catch)
Any new list-transition or scroll helper marked `"worklet"` must be defined **above** its caller (memory `worklet-forward-ref-hazard`).

### Pitfall 7: `tsc` not run
vitest in node does not typecheck. `navigateIntoTab` typing over `TabParamList` is the likely TS2322/TS2345 site. Run `npx tsc --noEmit` in every wave gate.

### Pitfall 8: Hidden-screen refresh accidentally removed for Profile/Digest
If only Home gets deferral, that is fine. But do not gate **Profile** shell reloads on focus without adding focus reload parity. Profile already reloads on focus, so gating is optional.

### Pitfall 9: Device UAT false negatives
Account for the following:
- The LogBox toast eats tab taps.
- Small Pressables miss `adb input tap`; use `uiautomator` bounds.
- Use a touchscreen tap for FAB/buttons.
- Metro runs on 8082 with the device 8081 remap.
- Destructive runs go on `com.bwales.orbit.uat`.

These come from the memories `logbox-toast-blocks-tab-taps`, `adb-tap-false-negatives`, `adb-input-source-taxonomy` and `isolated-uat-package`.

### Pitfall 10: Colour literals in new states
The loading indicator and error rows must use `colors.*` tokens. `AssistBanner` already uses tokens; keep to that pattern. Run `npm run check:colors`.

export interface LatestRequestAuthority {
  begin(): number;
  isCurrent(token: number): boolean;
  invalidate(): void;
}
export function createLatestRequestAuthority(): LatestRequestAuthority {
  let generation = 0;
  return {
    begin: () => ++generation,
    isCurrent: (token) => token === generation,
    invalidate: () => {

type Field = "channel" | "quality" | "duration";
export function buildFollowPatch(initial: ParticipantEditDraft, draft: ParticipantEditDraft) {
  const out: Partial<Record<Field, { follow: true } | { follow: false; value: string | number | null }>> = {};
  for (const f of ["channel", "quality", "duration"] as const) {
    const followChanged = draft.follow[f] !== initial.follow[f];
    const overrideValueChanged = !initial.follow[f] && !draft.follow[f] && draft.value[f] !== initial.value[f];

    }
  }
  return out; // never infers follow from value equality (ADR-125 rejected alternative)
}
