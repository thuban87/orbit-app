# Phase 38.3 Plan 11: Truthful Import Stop and Review Read Errors Summary

**If import setup or session access fails, ImportProgress now shows "Import stopped" and offers the import summary (or Back when the session can't be read). It releases the resume hold and never re-runs the import. Import Complete now shows Retry when rows are still pending. DuplicateReview shows "Couldn't load matches" with a Retry that only re-reads. If finalize or the re-read fails after a committed write, the user is never asked to redo the write.**

## Retry invariant (writers read)

`runImportBatch` only takes rows whose status is in `eligibleStatuses` (Import Complete passes `["pending","failed"]`), and it skips any row with a non-null `contactId`. `importRowAsNew` → `importContactRecord(..., resolveRow)` creates the contact and resolves the row in one transaction. `linkExistingContactToRow` does its row writes inside `inWriteTransaction`. So a committed contact cannot be re-imported by Retry. The other writers (`markRowStatus`, `finalizeSessionIfTerminal`, `discardSession` in the leave guard, resume prompt and stale sweep, plus ImportReview and source-consolidation) were read. No DAO or driver behaviour changed.
