# Phase 38.3 Plan 14: Live Digest Refresh Summary

**Digest now re-reads in place.** It refreshes on focus, on the shell tick and on the post-sweep foreground tick, and one latest-request authority decides which read publishes. Your Week follows a signal that Digest owns. On a new local day it keeps the chosen period and shifts its window. Up Next and Horizon rows now use the standard list transition, which is off under reduced motion.

## Accomplishments

- **`src/screens/digest-refresh.ts`** adds `createDigestRefreshController<T>`.
  - A focus request always reads.
  - A shell or foreground request while Digest is hidden reads nothing. The next focus read covers it.
  - `publish` and `fail` both go through `createLatestRequestAuthority`, and `invalidate()` runs on unmount.
  - The pure reducers work like this:
    - loading + fail → error
    - loaded + fail → still loaded, with `refreshError`
    - publish → loaded, and the error is cleared.
- **DigestScreen** runs the same five reads inside `read`.
  - `useIsFocused` is held in a ref and used for `isVisible`.
  - `useShellRefresh` issues a `shell` request (D-13), `useForegroundRefresh` a `foreground` request (D-14), and the focus effect a `focus` request.
  - A refresh never sets the phase back to `loading`.
  - If a refresh fails after the body has loaded, the body stays mounted. A compact "Couldn't refresh Up Next and Horizon" notice with Retry appears above it.
  - `onAccepted` bumps `yourWeekSignal`, which reaches `<YourWeekSection refreshSignal>` through `DigestContent` → `DigestLoadedBody`. The drill-through via `navigateIntoTab` (Plan 09) is unchanged.
- **YourWeekSection** no longer has a focus effect. A `useEffect` keyed on `refreshSignal` does the work, and it also runs on mount. Each refresh:
  1. Reads settings.
  2. Runs `resolveYourWeekRefreshPeriod`, passing the generation captured before the settings read began.
  3. Builds the window from `formatLocalDate(new Date())`. There is no timer.
  4. Runs `retainYourWeekDay` and commits the result.
  5. Re-reads the retained day, if one was kept.
  6. Runs the period read through the shared reader.

  `onPeriodChange` now uses `beginYourWeekPeriodWrite`.
- **`your-week-section-logic.ts`** gains:
  - the `writingPeriod` marker, cleared on a generation-matched accept or reject;
  - `beginYourWeekPeriodWrite`, `resolveYourWeekRefreshPeriod`, `isYourWeekDayInWindow` and `retainYourWeekDay`;
  - `createYourWeekPeriodReader`, which is the single authority for refresh, toggle and rollback period reads. Generation stays as the check on period intent.

  `selectYourWeekPeriod` is still exported.
- **`DigestListTransition.tsx`** adds two components:
  - `DigestListGroup` wraps a list in `LayoutAnimationConfig skipEntering` and reads reduced motion once.
  - `DigestListItem` wraps a row in an `Animated.View` with `LinearTransition(MOTION.base)` and `FadeIn`/`FadeOut(MOTION.fast)`. All three are `undefined` under reduced motion.

  Up Next rows and Horizon's three groups are wrapped, with each key moved to the wrapper.
- **`docs/systems/digest.md`** is updated:
  - "Opening Digest" step 2 is rewritten; it no longer describes focus-only reads.
  - Your Week gains steps 5–6.
  - A "List transitions" section is added.
  - There is a new gotcha: no Digest trigger outside `DigestScreen`.
  - The owners, layer and key-file tables are updated.
  - A 38.3 Changelog row is added.

### Implementation choices within the plan (not rule deviations)

- **Period-read authority.** It is `createYourWeekPeriodReader` in the logic file rather than inline in the component. The plan asked for a "logic/test case" of the refresh vs manual-switch ordering, and this makes it a real node test.

- **DigestScreen.test.tsx resolver.** It now expands local function components, so `DigestContent` → `DigestLoadedBody` can be asserted in one tree.
