### Restated from the dossier and audit synthesis (pre-discuss shim)

- **D-01:** The authoritative contract is the 38.3 dossier.
  - Per-group detail: `docs/audits/2026-09-pre-release/synthesis/REMEDIATION-GROUPS.md` (the RG sections listed above).
  - Finding evidence: the linked `*/DOMAIN-AUDIT.md` packets.
- **D-02:** Preserve RG and **packet-qualified** finding IDs in every plan. A bare `AUD-REL-00N` is
  ambiguous.
  - Organize plans around state ownership and end-to-end workflows, not audit domains.
  - Integration verification must prove convergence from user action to visible state.
- **D-03:** Preserve these existing behaviours:
  - independent tab histories (five tabs: Contacts/Dashboard, Events, Digest, Orrery, Settings; ADR-146)
  - Digest as the initial landing surface
  - transient-first Back and reselect (ADR-080/095)

  - a universal event bus
  - a new state library
  - a persistent Digest cache or snapshot
  - a broad navigation reset (ADR-146)
  - a new top-level tab
- **D-04:** A committed write must never replay because a later read or presentation step failed.
  Pending, failed, empty, and successful outcomes stay distinguishable wherever the audit flagged them.
- **D-05:** Investigation gate: the **RG-020 accessibility subset**
  (`ui-accessibility/AUD-UIA-022`) needs on-device Contacts/TalkBack traversal before it is treated

  - Fixing RN-001 makes `accessible={!panelOpen}` grouping persistent. At present the bug leaves `panelOpen` stuck
    `true` after the first panel. So the UIA-022 device traversal must run **after** the RN-001 fix.
- **D-06:** RG-035 fixes the five uncontested branches only. The ContactPicker read-error empty-state

### Profile History (owner, 2026-09-25)

- **D-10 (owner) — History actions scroll to the in-Profile History section (ARCH-008).**
  - This covers both the **Last Interaction** overview tile and the Orbit Status sheet's **View history**.
  - The sheet closes first if open. The Profile then scrolls to the `HistorySection` (ADR-123) and expands it if collapsed.
  - No new route and no standalone timeline screen (a timeline would contradict ADR-123).
  - The History view's current period/selection is **not** reset by the action.
- **D-11 (owner) — If the Profile module layout omits History, those actions are not offered.**
  - The Last Interaction tile stays as information only, with no tap action and no button semantics.
  - The sheet's `history` route is omitted.
  - No temporary reveal and no layout mutation.
- **D-12 (owner) — History day rollover (RN-009): follow today only when viewing the current period.**
  - If the mounted History is showing the current window when the local date changes, it advances to the new
    today.
  - A past date the user picked stays put. This needs an explicit "following today" state distinct from
    `refDate`.
  - The today-bound limits (next-window navigation, Rolodex max day, empty-state Log prefill) always
    update.
  - Date checks run on app resume, tab return, and Profile focus. There is no timer (D-22).
  - Use `formatLocalDate()`, never UTC slicing.

### Digest live refresh (owner, 2026-09-25)

- **D-13 (owner) — Digest refreshes immediately on committed writes (RN-006/REL-013).**
  - Triggers: Quick Log, Undo, headless widget/notification logs, and assist confirmations. On these, Digest
    (Up Next, Horizon, Your Week counts/heatmap) re-reads and recomposes right away. The logged person
    drops out and others shift, using the standard list transition (none under reduced motion).
  - Digest subscribes to the existing shell-refresh signal. No new bus (D-03).
- **D-14 (owner) — Digest refreshes on every foreground resume, ordered after the launch/foreground
  sweep.**
  - This way it reads the sweep's writes (purges, expiry).
  - The same ordering concern applies to Home's resume read. Planner: apply it there too (RG-022).
- **D-15 (owner) — New local day while Your Week is shown: keep the period, re-window.**
  - The chosen period (e.g. Rolling 7) is kept and the window shifts to the new today.
  - A selected day survives if it is still inside the new window; otherwise it clears.
- **D-16 (owner) — Day-detail states (REL-014, closes Phase 38 WR-01 at
  `.planning/phases/38-your-week/38-REVIEW.md:74`).**
  - Use explicit `idle | loading | loaded | error` states.
  - **Loading:** a small inline indicator in the detail area. Never an empty "No activity".
  - **Error:** "Couldn't load this day" with Retry.
  - "No activity on this date." appears only after a successful empty read.
  - Keep a stale-result guard that is request-scoped, not date-only.

### Group Event and import (owner, 2026-09-25)

- **D-17 (owner) — Participant actions preserve the unsaved parent Group Event draft silently
  (REL-007).**
  - Add, remove, and participant-edit commit on their own.
  - The parent draft fields and the dirty/baseline state stay intact, and still go through Save or the Discard/Keep guard.
  - Refreshing participant state must not reseed parent fields. Per the RG-019 planning note, "a reload that reseeds every field is not
    safe draft preservation".
- **D-18 (owner) — While the parent is dirty, following participants show the *saved* event's
  values.**
  - This matches what the database will give them.
  - They update once the event is saved. No preview of unsaved draft values.
- **D-19 (owner) — Committed participant add, failed refresh (REL-008) is treated as success.**
  - The picker closes as a successful add.
  - The event screen then shows its own "Couldn't refresh this event" error with Retry, and that Retry only re-reads.
  - Never re-add, and never show "Couldn't add" or "Your changes weren't saved" for a committed add.
  - Applies to both `EditGroupEventScreen` and `GroupEventDetailScreen`.
  - The DAO duplicate-participant guard is unchanged.
- **D-20 (owner) — Import fatal state (RG-035 branch 1).**
  - When import setup or session access fails, `ImportProgressScreen` leaves "Importing… X of Y" and shows "Import stopped".
  - It offers a button to Import Complete, which already separates committed contacts from unfinished photos
    and hosts 38.2's Retry and "Skip remaining photos" (38.2 D-14). Nothing re-runs automatically.
  - Planner handles the case where the session itself is unreadable: show the error with Back rather
    than a broken Import Complete.
  - Release the open-import-session hold (`useOpenImportSession`) on fatal exit, so the resume sweep can
    offer the session again.

### Recorded calls (planner bucket, 2026-09-25; owner did not object)

- **D-21 — Assist publication contract (RG-023).**
  - One shared post-commit publisher serves Compose, AssistBanner, and PendingConfirmationsSheet: widget notify, assist-queue
    refresh, and `bumpShellRefresh()`.
  - Compose currently omits queue and widget (ARCH-006). Banner and sheet omit shell refresh (RN-007).
  - The **Post-Log Note save** is the same missing-signal class, so it also publishes the shell refresh (grounding find, routed here).
- **D-22 — No timers for date freshness.** Day changes are detected only on lifecycle/focus/refresh events
  (resume, tab return, focus, shell refresh), per the "nothing watches a timestamp" rule. There is no
  midnight timer, even while in the foreground.
- **D-23 — Dashboard refresh ownership (RG-022).**
  - A refresh requested while Home is hidden (shell bump, foreground) is deferred until Home focus, not run in the background.
  - One latest-request authority decides publication: an older result never overwrites newer rows, counts, or errors.
  - Animation-only and lifecycle state (`appActive`, `isFocused`, `reducedMotion`) must not trigger reads.
  - Bulk paths issue one refresh, not a shell bump plus a direct reload.
- **D-24 — Remaining RG-035 / RG-021 / RG-042 / RG-025 presentation.**
  - **Error states:**
    - ReconcileComplete gets a real loading branch.
    - MemoryScreen gets a loading state and a "Couldn't load memories" error with Retry, and does not open an editor over a failed read.
    - BackupSettings with unreadable settings shows "Couldn't read backup settings" with Retry. It never shows a known "Off", folder or passphrase-setup state.
    - DuplicateReview read failure shows an error with Retry, never "Nothing to review".
  - **Settings host:** register `RecentlyDeleted` under the Settings host (a legitimate Profile child route) and add SettingsTab to the FAB context allowlist.
  - **RG-042:** a stale cold notification result is dropped, and logged at debug level only.
  - **RG-025:** the fix settles only the selector that was retried, reusing the normal submit settlement.
  - **Wording:** exact copy is at planner/UI discretion within these rules.

### Plan-phase rulings (2026-09-25)

- **D-25 (owner) — OD-1: Message is disabled on every Settings-hosted Profile.**
  - A non-archived Profile is reachable inside the Settings stack: Settings → Archived → Profile → History →
    interaction → View group event → participant → Profile (`GroupEventDetailScreen.tsx:258`,
    `SettingsStack.tsx:237-259`). There, `onMessage` → `navigate("Compose")` (`ContactProfileScreen.tsx:401`)
    is unhandled, a silent no-op in release.
  - Message renders **disabled with a short reason line** whenever the Profile is hosted in the Settings stack,
    via the same `profileHeroActionState` disabled mechanism as D-09 (archived).
  - Compose/ComposeResearch stay **unregistered** under Settings (RG-021 constraint unchanged). No cross-tab jump.
- **D-26 — Recorded planner calls (research open questions).**
  - After a fatal import, Import Complete's Retry condition includes pending rows (fits D-20).
  - The import/reconcile resume prompts route through the shared cross-tab entry helper (RN-002).
  - Whether a selected Your Week day survives a tab return is planner discretion within D-15.
