## Phase Goal

**As a** person keeping people in orbit, **I want to** see my favourites on a home-screen widget with their status colours and act on them in one tap, **so that** I can mark contact or open someone without launching the app.

> This plan is the native-enablement gate. It installs the one net-new dependency behind a mandatory owner legitimacy checkpoint and registers its Expo config plugin, so the native-surface slices (12-05/12-06/12-07/12-08) can build against the library's types. No RemoteViews render exists yet — that is a later slice.

<objective>
Gate and perform the single net-new native dependency install (`react-native-android-widget@0.22.0`) and register its Expo config plugin in app.config.ts, unblocking every file that imports the library.

Purpose: The library was flagged `[SUS]` (too-new 0.22.0 bump, ~46k weekly downloads, real repo — a false-positive on publish date, not a slopsquat) in RESEARCH § Package Legitimacy Audit. Per the legitimacy protocol AND the project's risk-posture rule (CLAUDE.md: security posture is the owner's bucket), the install is gated behind a blocking-human checkpoint, mirroring the Phase-8 drag-library (08-08) and Phase-9/10 native-dep discipline.
Output: the dependency installed at the SDK-57-aligned version; a `widgetConfig` plugin entry appended through the deduped plugins() builder.
</objective>
