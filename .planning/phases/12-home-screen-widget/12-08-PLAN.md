## Phase Goal

**As a** person keeping people in orbit, **I want to** see my favourites on a home-screen widget with their status colours and act on them in one tap, **so that** I can mark contact or open someone without launching the app.

> Final MVP slice: make the widget real on the device. Prebuild the first custom dev client on the desktop, harden the regenerated manifest, add the boot/force-stop re-push receiver, then verify the device-only behaviours on the physical Pixel — including the killed-app headless mark bundled with the deferred Phase-11 check.

<objective>
Enable and verify the widget on the physical device: prebuild the first custom dev client on the desktop, assert manifest hardening, add a CONCRETE native BOOT_COMPLETED re-push receiver (a real Kotlin/Java BroadcastReceiver emitted + registered by a config plugin — a JS plugin cannot BE a receiver), and run the device-only UATs.

Purpose: The library forces the project's first committed native change. The regenerated manifest must keep every hardened attribute (Pitfall 6). Android 15 distinguishes cold-boot from force-stop recovery and greys a force-stopped widget until a manual launch, so a boot re-push receiver is mandatory (WDG-03) — a SEPARATE native path from the foreground sweep, and NOT a duplicate of any receiver the library already registers. The RemoteViews render, grid-capacity ceiling, killed-app mark, both recovery paths, and requestPinWidget are all device-only.
Output: a config plugin that writes + registers a concrete native boot receiver (or reduces to a manifest assertion if the library already provides one), a hardened prebuilt manifest, and passed Pixel UATs.
</objective>
