<objective>
The Profile shows a person's birthday as a Relationship Overview tile, and tapping it opens a Birthday
sheet that edits it in place (D-53, D-55, D-80, D-56, D-59, with D-61's Year-unknown rule).

Decided here ("this plan only"): the Android date picker is a native dialog, so the sheet shows the date
as a row that opens the native picker on the stored date; the sheet closes after Clear because the tile
hides. Snackbar copy (Claude's discretion, CONTEXT): "Birthday saved" / "Birthday cleared"; error
"Couldn't save the birthday. Try again.". The tile shows the date only (no countdown; none was decided).
Clear and a Year unknown ON that drops a stored year are reversible data losses, so per the 38.9
destructive-action rule (38.9 D-30: a reversible action happens at once with an Undo snackbar;
`docs/systems/ux-standards.md` "Destructive actions") and D-59 (saves at once, no confirm) they save at
once and their snackbar carries Undo, which restores the previous stored value through the same setter
(review T-09). Undo copy (Claude's discretion): "Birthday restored" (38.9 D-39: Undo shows its own
confirming snackbar).
Output: registry id + factory placement + read-time completion, header/identity birthday read, tile,
single-column DAO writer, sheet, tests.
