<objective>
Add Contact offers Photo in Identity (D-77). The photo is cropped and held in a durable staging
namespace until Save, promoted through the normal 38.6 photo path after the create commits, and cleaned
up on discard, removal or app kill.

Decided here ("this plan only", within D-77 and CONTEXT Claude's Discretion "How Links and Photo compose
with the create write"): a `create-staging/` namespace cloned from `reconcile-staging/` (RESEARCH
section 1 recommendation, the durable option, chosen over the cache-only alternative because of R4/R5);
one staging file per pick named with the form's session token plus a fresh pick token, so a re-pick never
reuses a path (no stale preview, per the 38.6 lesson in ADR-180); CropPhoto gets a hold mode through its
route params instead of a new target kind; PhotoSourcePicker gets a hold mode so Add offers the same
Add / Change / Remove and paste-URL surface as Edit; a held photo counts as unsaved work for the discard
guard (D-77 "discarding the form deletes the held image" implies a discard decision). Photo placement:
Identity beside Name (ledger, "DERIVED at planning: Identity, beside Name"). Failure copy (Claude's
discretion): "Contact saved, but the photo wasn't added. Add it from Edit Contact."

Output: staging namespace, hold-mode crop and picker, promote service, sweep, Add wiring, tests, `photos.md` synced.
</objective>
