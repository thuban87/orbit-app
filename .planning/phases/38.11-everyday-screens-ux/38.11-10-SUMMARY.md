# Phase 38.11 Plan 10: Shared Snooze Sheet Summary

**One `SnoozeSheet` now serves the Profile Snooze tile, the Profile ⋯ "Snooze…", the Contacts card and Contacts bulk. Choose date starts tomorrow. Single-contact changes confirm by name with Undo. Bulk Unsnooze lives in the sheet and acts on the people the database says are snoozed. The last native Alert is gone.**

## Accomplishments

- `SnoozeSheet` (new) has the presets, Choose date (a date row that reopens the native picker, minimum tomorrow), Set snooze, Cancel, Unsnooze when allowed, and Close. It handles pending, the existing error copy and Retry through the shared runner. Close, Back and the scrim are ignored while a save runs.
- On the Profile, the Overview tile's sheet is hosted in `ProfileModuleHost` and the ⋯ "Snooze…" sheet in `ContactProfileScreen`. Both are wired to the screen's one `snooze` / `unsnooze` pair. The snooze section has left `ProfileRelationshipSheets`, and ⋯ no longer has an instant Unsnooze.
- The Contacts card menu entry reads "Snooze…" in both states and opens the sheet for the contact captured at tap time. Writes go through `snoozeProfileContact` / `unsnoozeProfileContact`, followed by a list refresh and a reminder reconcile. The `Alert.alert` call, the `Alert` import, `toggleCardSnooze`, `snoozeContactWithPreset` and `CARD_SNOOZE_PRESETS` are deleted.
- The bulk bar's Snooze always opens the sheet. `readCurrentlySnoozedIds` decides whether Unsnooze shows, and bulk Unsnooze writes and counts only that subset. The bar's Unsnooze button and `onBulkUnsnooze` are removed. Bulk Choose date writes through the new `bulkSnoozeUntil`. Every bulk write runs through `runClaimedBulkWrite`: the sheet stays open while it runs, and a failure shows the sheet's error and Retry, which takes a fresh claim over the same captured ids.
- Single-contact success shows one snackbar from the sheet: "Snoozed {name} for 1 week", "… until {date}" or "Unsnoozed {name}". It carries Undo, which restores the previous effective state. Expiry is re-checked when Undo is tapped. Undo then confirms with "Snooze undone for {name}".
- The no-native-alert contract now pins zero production `Alert.alert` calls. `ux-standards.md`, `dashboard.md` and `contacts.md` are synced, each with a Changelog row.

## Decisions Made

- `SnoozeSheet` reuses `createRelationshipSheetRunner` with the `"snooze"` owner (it reuses the reducer semantics and the error copy). `ProfileRelationshipSheets` submits only `"frequency"`.
- Choose date opens straight into the native picker on a sheet with a visible "Until {date}" row, so the chosen date stays visible and can be changed. The old sheet showed no chosen date.
- If `runClaimedBulkWrite` cannot consume a claim, it rejects without releasing it, because a consumed claim belongs to a writer already in flight.
- The future-local-date check lives once, in `snooze-dao` (`assertFutureLocalSnoozeDate`). Both custom-date writers call it before any transaction. Its error text is now "snooze: until must be a future local date"; existing tests match `/future local date/`.
