**The Profile's Background sheet now only chooses a background for this person. It has compact two-column cards whose Assign applies at once, Choose photo, a "Manage global backgrounds" link to the Settings page, "Reset to default" with Undo, and the chevron header Back. Global and Category controls and Delete are gone from the sheet.**

## Accomplishments
- **Choose-only sheet (D-58.2, D-58.3).** The "Background assignment" section (Clear global, Clear category, Inherit) is gone. So are the assign page's "Set as global default" and "Choose category", the `CategoryChoiceSheet` and the card Delete. The sheet now uses only the library load from `useProfileBackgroundLibrary`.
- **Compact cards (D-58.4).** Each card has two columns. The picture is on the left (96 wide, stretched to the card's height, so it spans both rows). The name sits top-right and "Assign" bottom-right, both centred. Assign writes this person's background through `assignContactBackgroundTemplate`, reloads the Profile, and shows "Background set for {name}". The card for the person's own background is `selected` (the GlassSurface selected border, plus `selected` and a "Current background" hint on its Assign button).
- **"Manage global backgrounds" (D-58.2).** It calls `onRequestClose()` and then `navigation.navigate("ProfileBackgrounds")`. 38.11-06 registered that route in all five Profile-hosting stacks.
- **Choose photo stays (D-79).** After a new background is named, the sheet shows only "Use for {name}" and "Not now". Not now returns to the list, which includes the new card.
- **Reset to default (D-65, background half).** It shows only when `contactBackgroundTemplateUid !== null`. It captures the previous uid and writes `templateUid: null`. The person's layout and open/closed sections are untouched, because `upsertContactPresentation` keeps every column it is not given (ADR-108). It then reloads and shows "Background reset to default" with Undo. Undo writes the previous uid back through the same contact-scoped writer, reloads, and shows "Background restored" (38.9 D-30, D-39). If Undo fails, it logs and shows "Couldn't restore the background. Try again." If the reset fails, it shows the error snackbar with no Undo. The Undo closure holds only the writer (`contactId` plus the screen's `onCommitted`) and the previous uid, so it still works after the sheet closes. Reset replaces the old "Inherit … for {name}" and "Use inherited background" actions.
- **Header Back (D-43).** The heading now starts with `<Button role="iconOnly" icon="back" accessibilityLabel="Back" onPress={closeOrGuard} />`, so the discard guard is kept. The crop header was already converted by 38.11-06. `grep 'label="Back"'` over both files prints nothing.
- `ContactProfileScreen` passes `contactBackgroundTemplateUid={snapshot.presentation.contact.backgroundTemplateUid}`.

## Decisions Made
- **Logic in the model, behind an injected writer.** Assign and Reset/Undo are pure async functions over `{ write, onCommitted, notify, logError }`. The manager builds `write` from `assignContactBackgroundTemplate(getExecutor(), { contactId, templateUid, now })`. This lets the Undo path (the captured uid is re-assigned, then "Background restored") be tested by behaviour, not only by grepping the source.
- **Card row on `contentStyle`.** `GlassSurface` renders children inside an inner content View, so `flexDirection: "row"` on `style` never reached the children. The old sheet card was really a vertical stack (thumbnail, then name, Assign, Delete). The new row sits on `contentStyle`. The card is about 80dp tall, against roughly 180dp before. That is a little under half, which is within D-58.4's "about half".
- **One write at a time.** A `busyRef` guards Assign, Use for {name} and Reset against double taps. This is the same pattern as the Settings page.
