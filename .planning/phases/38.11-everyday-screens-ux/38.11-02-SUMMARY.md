# Phase 38.11 Plan 02: Four-action +, Update Contact archived, FAB clearance margin Summary

**The + now offers four actions (Add Contact, Quick Log, Log Interaction, Group Log). Update Contact's route is unregistered everywhere and its code is kept in `docs/archive/update-contact/`. Memory stays registered in all five stacks as a Profile-reachable route. Scroll content ends a tunable `FAB_CLEARANCE_MARGIN` above the +, and the history page's add field has a placeholder.**

## Accomplishments

- **D-62, D-66:** the + dial dropped Update Contact and Memory. `FAB_ROUTES` is now `["Create", "GroupLog", "LogContact"]`, and the pick-then intent is `LogContact` only.

The new pure `bottomClearanceFor` returns `tabBarHeight + FAB_SIZE + FAB_EDGE_GAP + margin`, and `useBottomClearance` returns it. All 29 consumers use the value only as scroll `paddingBottom`. The snackbar and section Add FAB compute from the FAB constants and do not move.

- **System docs:** `app-shell.md`, `custom-fields.md`, `contact-knowledge.md` and `ux-standards.md` now say Update Contact was retired and Edit Contact is the single contact form. Each got a 38.11 Changelog row.
