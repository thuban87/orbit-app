# Phase 38.11 Plan 03: Relationship Overview truth Summary

**What the Profile now shows:**

- A Bound contact who has never been contacted reads "Never Contacted", with no progress bar.
- Unbound and no-frequency contacts each get an honest reason.
- Archived contacts show exactly what they showed before.
- Empty Gravity reads "No interactions yet".
- Each stat sheet opens with a plain definition, checked against the code.
- The Last Interaction tile shows only the date.
- Message and Call say whether a number or email is missing or saved but unusable.
- The Frequency sheet has a Custom… row with a days box and an Apply button.

## Accomplishments

- **Status (D-05, D-23, D-24):** `resolveProfileStatus` has a new `archived` input, read only inside the unavailable branch. The availability gate is the same as before. An unavailable result now carries a `reason`, classified in this order: archived (old literal), Unbound, no frequency, not contacted. A not-contacted result uses the glossary's `NEVER_CONTACTED`, with no visualValue and no factors. `profile-read.ts` passes `archived: header.archived_at !== null`. `getContactStatus` and `contact-status-read.ts` were not changed (D-20).
- **Gravity, definitions, Last Interaction (D-74, D-75):** Gravity with no interactions reads "No interactions yet" / "Gravity builds as you log interactions." `RelationshipExplanation.definition` is rendered first, under the sheet title. The history summary text is now just the formatted date.
- **Hero (D-27, ADR-109):** `savedMethodKinds(snapshot.methods)` reaches `profileHeroActionState` through the Hero.
  - Call says "Add a phone number…" when there is no phone, and "This phone number can't be used to call…" when the saved phone is unusable.
  - When nothing is usable, Message names only the kinds the contact has: the number, the email, or both.
  - The archived and Settings-host reasons still take precedence.
- **Custom… frequency (D-54, D-14, D-11, D-36):**
  - The Custom… row is selected (filled glyph, accent border, "Every N days" caption) when the current value is not a preset. Tapping it opens a number-pad days box, prefilled with the current custom value.
  - `parseCustomInterval(raw, "days")` validates the entry. Apply stays disabled while the entry is invalid, and the error caption appears only after the user types.
  - Apply goes through the existing runner, so pending, error and Retry match the presets. Presets still apply on tap.
- **Dead tracer (D-38):** `ProfileOverviewTracer.tsx` deleted. No importers anywhere (code, tests, scripts, docs).
- **System docs:** the `status-engine.md` Gotcha and the `profile.md` "Unbound is Not tracked" sentence are amended, and each has a 38.11 Changelog row.

## Deviations from Plan

**1. [Rule 1 - Accuracy] Gravity and Intensity definition drafts corrected against the code**
- **Found during:** Task 2
- **Gravity:**
  - **Issue:** "One busy week moves it less than a steady habit over months" is false. `computeGravity` sums per-interaction recency weights with no per-day or per-week cap, so a busy recent week can outweigh months of history.
  - **Fix:** that sentence is gone. In its place: "Old history never fades away completely" (`FLOOR_W`), and "It shows as a tier (Thin, Building, Solid or Deep), not a score", with the names taken from `GRAVITY_TIERS`.
- **Intensity:**
  - **Issue:** the draft said "this month when there is no frequency". Unbound contacts that have a frequency also use the month window.
  - **Issue:** the draft said "compares that with how often you meant to". That comparison only exists for Bound contacts.
  - **Fix:** the copy now names Unbound contacts, says the comparison applies only "with a frequency", and states that interactions they started don't count. Inbound rows are excluded by `intensity-logic.ts`.
- **Commit:** `516c8ac9`

**2. [Test fixture] Overview render test gravity module size**
- Adding a Gravity tile to the overview render fixture needed size `1x1`, the only size the registry supports.

**Total deviations:** 2 (copy accuracy; test fixture). No scope growth.
