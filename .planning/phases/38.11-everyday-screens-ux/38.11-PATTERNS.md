## Pattern Assignments

### `src/db/contacts-dao.ts` new `setContactBirthday` (D-59)

**Analog:** same file, `setContactPhotoCore` / `setContactPhoto` (`:1090-1124`) and `clearContactPhotoCore` (`:1153-1182`).

```ts
export async function setContactPhotoCore(exec: SqlExecutor, id: number, relative: string, now: string): Promise<void> {
  assertSafeRelative(relative);            // validate before the UPDATE
  const result = await exec.runAsync(
    "UPDATE contacts SET photo = ?, modified_at = ? WHERE id = ?",
    [relative, now, id],
  );
  if (result.changes !== 1) {
    throw new Error(`setContactPhoto: no contact matched id=${id} (changed ${result.changes})`);
  }
  await bumpDataRevisionCore(exec);
}
export function setContactPhoto(exec, id, relative, now): Promise<void> {
  return inWriteTransaction(exec, () => setContactPhotoCore(exec, id, relative, now));
}
```

- Validate with `isValidStoredBirthday` (`src/logic/birthday-logic.ts`) in place of `assertSafeRelative`. A null value clears.
- Do **not** route through `updateContactMetadataCore`, which rewrites every column (RESEARCH §4) **[this mapping only]**.
- After a sheet save or clear, call `reconcileSchedule` and `notifyWidgetDataChanged`. The caller pattern is in `ContactProfileScreen.tsx` around `:595-620`.

### new `src/services/photos/create-photo.ts` (promote after commit)

## Shared Patterns

### Write composition (all DAO edits)
**Source:** `contacts-dao.ts:9-11` (mutex comment), `:268-403`, `:1090-1182`. Applies to every DAO change in this phase.
- `*Core` writers never open transactions. Only the wrapper calls `inWriteTransaction`. Each composed write bumps exactly once with `bumpDataRevisionCore`.
- Writes are `?`-bound and guarded by `changes === 1`.
- Queries live only in `src/db/` DAOs (CLAUDE.md Conventions).

### Post-write OS side effects
**Source:** `EditContactScreen.tsx` `afterMetadataCommit` (around `:1083-1099`, per RESEARCH). Applies after any birthday or photo write: call `reconcileSchedule(exec)` (fire-and-forget with a `Logger` catch) and `notifyWidgetDataChanged()`.

### Dialogs and feedback
**Source:** `@/stores/confirm-store` (`confirm`, `notice`) and `@/stores/snackbar-store` (`showSnackbar`), as imported at `ArchivedContactsScreen.tsx:42-43`. Applies to the Bin confirm (D-71), the photo-not-added message (D-77) and the Birthday snackbar (D-59). Never use RN `Alert` (`no-native-alert-contract.test.ts`).

### Route registration
**Source:** `shell-contract.ts:56-84` (`PROFILE_REACHABLE_ROUTES` + RG-021 comment). Any route a Profile can open must be registered in all five stacks.

### Theme and colours
All colours go through `useTheme()` tokens, and `check:colors` runs in the post-merge gate (CLAUDE.md Conventions; CONTEXT `<verification>`).
