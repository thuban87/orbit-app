## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Layout reset leaves no all-null presentation row**
- **Found during:** Task 2
- **Issue:** The plan's `upsertContactPresentation({ layoutTemplateUid: null, freeformLayoutJson: null, clearCollapse: true })` leaves an all-null row when the person has no background. It means nothing for rendering, but still counts as a presentation row (capture-dao's share-Undo ownership check blocks on any row).
- **Fix:** With no background the reset deletes the row; with a background it upserts as planned. Both are presentation-only, one bump.
- **Files modified:** src/db/profile-presentation-dao.ts, src/db/profile-presentation-dao.test.ts
- **Verification:** "leaves no presentation row when there is no background" test
- **Committed in:** 81aeef51

**2. [Rule 1 - Bug prevention] Reset closes the sheet; error cleared on entering the editor**
- **Found during:** Task 2
- **Issue:** If the chooser stayed open after Reset, its draft (taken when the sheet opened) would be the old layout, so "Edit layout" would start from stale data. A Reset error would also carry onto the editor page.
- **Fix:** Reset calls `onCommitted()` then `onRequestClose()` like Save; "Edit layout" clears `saveError`. `onCommitted`'s layout argument is now optional (the only screen consumer ignores it; the template-editing consumer passes none).
- **Committed in:** 81aeef51

**3. [Doc sync] profile.md updated** (not in the plan's file list; system docs are living per CLAUDE.md). Commit 0aa9e585.
