# Phase 38.11 Plan 04: Profile & Contact Forms (Add Contact full record, shared Birthday control) Summary

**What changed for the user:**

- Add Contact's Show More now opens with a "Birthday, social battery & links" section, below Contact Methods.
- One Save creates the contact, birthday, social battery and links together. If any part fails, nothing is saved.
- A birthday set on Add gets its reminder scheduled straight away, not at the next launch.
- On Add and Edit, turning Year unknown off opens the date picker to choose the year. Cancel leaves Year unknown on. The year 2000 is never stored unless the user picks it.
- The birthday picker cannot go past today.
- Edit Contact can clear a birthday.

  - `BirthdayField` renders the logic and owns no DAO. It keeps the `edit-contact-birthday*` testIDs on Edit and uses `create-contact-birthday*` on Add.
  - Edit's inline birthday UI and `onBirthdayChange` are gone. Edit no longer imports the date picker.

## Deferred / out-of-scope items

- **A stored birthday dated in the future opens the capped picker oddly.**
  - **What happens:** `isValidStoredBirthday` accepts a future `YYYY-MM-DD`, for example an imported typo like 2030-01-01. With the new today cap, Edit's date row opens on that value, and Android may show the picker clamped to today.
  - **Why it's rare:** Add and Edit can no longer create such a value. It can only arrive through import or restore.
  - **Recommendation:** leave it. If the 38.11-14 device pass shows a confusing picker for such a contact, clamp `dateRowSeed` to today. That is a one-line change in `birthday-field-logic.ts`.
