# Phase 28 — Dashboard Card View — UI Design Contract

> Visual and interaction contract for the Dashboard **Card View** renderer — Orbit's compact, avatar-first grid, and its multi-select bulk/contact-management surface. Generated by gsd-ui-researcher; to be verified by gsd-ui-checker.
>
> **Ground truth:** `docs/dossier/milestone-2/phase-07-dashboard-card-view-dossier-v0.2.md` (the 2026-09-01 amendment sections override older text) + `.../planning-notes/phase-07-planning-notes.md` (binding appendix) + `28-CONTEXT.md` D-01..D-12 + `REQUIREMENTS.md` CARDV-01..12 + ADR-018 / ADR-075 / ADR-010 / ADR-024 / ADR-071 / ADR-025. This spec restates those decisions as prescriptive tokens; it does **not** add, weaken, or reverse any `[DECIDED]` / `[REJECTED]` item. Where a decision collides with a recorded one, it is raised in **Flags for Owner / Planner**, never silently chosen.
>
> **All colour resolves through theme tokens (`src/theme/`). No hex literal appears anywhere in card, grid, selection, or bulk-surface rendering (CLAUDE.md, `check:colors`). Status hues are a separate semantic channel, never part of the 10% accent budget.**
>
> **Card View is a sibling renderer of List View (Phase 27), not a richer feed.** It presents the *same* shared Dashboard contacts with a visual/presentational difference only (dossier §A). It reuses the exact primitives Phase 27 consumes; it must not fork a second source of status, icons, favourite writes, or query logic.

## Spacing Scale

Uses the existing `src/theme/tokens/spacing.ts` `SPACING` set (all multiples of 4). Consume tokens, never raw px.

| Token | Value | Card / grid usage |
|-------|-------|-------------------|
| xs | 4px | Gap between adaptive-line leading icon and text; glyph/ring inset nudge |
| sm | 8px | Gap between the three text rows; inter-card grid gap; scrim inner padding (compact) |
| md | 12px | Card inner padding; gap between avatar and text block; grid column gutter |
| base | 16px | Grid outer side gutter / screen padding |
| lg | 24px | Empty-state block padding; bulk-surface section padding |
| xl | 32px | Empty-state vertical breathing room |
| 2xl | 48px | Major empty-state separation |

Exceptions:
- `md = 12` is a deliberate grid-aligned token (documented in `spacing.ts`), not an 8-point violation.
- **44×44 minimum touch target** (a floor, not a spacing token) applies to: the tappable favourite star, the selection control, each long-press-menu row, each bulk-action control, and each accessibility action. A control's *glyph* may be smaller; its *hit area* must be ≥44 (`hitSlop` where needed, mirroring `ListRow`'s star).
- **Exact card dimensions, gaps, avatar diameter, corner radius, and the grid breakpoint numbers are `[DEFERRED]` to device testing** (dossier "Explicitly Deferred", §B). This spec fixes the *classes and tokens*; device UAT on the Pixel fixes the pixels.

## Typography

Card text consumes the semantic roles from `src/theme/tokens/typography.ts` (4 sizes: 28/20/16/14; 2 weights: 400/600) via `AppText` roles — screens consume **roles**, never raw sizes. Card text is denser than List (three rows in a narrow column), so the name uses **label** rather than **body**.

| Card element | Role | Size | Weight | Line Height | Colour token |
|--------------|------|------|--------|-------------|--------------|
| Row 1 — contact name (identity) | label | 14px | 600 | 20 | textPrimary |
| Row 2 — recency | caption | 14px | 400 | 20 | textSecondary |
| Row 3 — one adaptive context item / completeness prompt | caption | 14px | 400 | 20 | textSecondary |
| Search: row 2 matched field/type label | caption | 14px | 400 | 20 | textSecondary |
| Search: row 3 strongest highlighted match run | label | 14px | 600 | 20 | textPrimary (highlight run only) |
| Selection count (control-area) | body | 16px | 400 | 24 | textPrimary |
| Bulk-action / menu row label | body | 16px | 400 | 24 | textPrimary |
| Empty/error heading | heading | 20px | 600 | 25 | textPrimary |
| Empty/error body | caption | 14px | 400 | 20 | textSecondary |

- Every card text row is **single-line, `numberOfLines={1}`, ellipsize tail** — the grid's compactness bias (§D/§I): row 1 name, row 2 recency, row 3 adaptive/prompt/snippet. Row 3 longer context "truncates to one line at normal text sizes" (§I).
- The matched-text highlight (§K) is expressed by rendering the matched run at **label weight (600) on textPrimary** inside an otherwise-caption line — no highlight background colour, no hex (reuse `ListRow`'s `HighlightedSnippet`).
- OS text scaling must **reflow** (grow card height and/or drop to 2 columns), never clamp (dossier §AF, CARDV-01). Do not set a fixed card height that truncates scaled text; normal density is not an accessibility invariant.

## Color

60/30/10 discipline over the theme palette (`src/theme/theme-types.ts`). **Status hues are a separate semantic system, NOT part of the 10% accent budget.**

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `background` | Grid backdrop / scroll surface |
| Secondary (30%) | `surface` / `surfaceElevated` via `GlassSurface` | The floating card scrim under each avatar; category/adaptive affordances |
| Accent (10%) | `accent` | See reserved-for list below |
| Destructive | `danger` (+ `onDanger`) | The Destructive `Button` confirm in a `destructive` `ConfirmDialog` **only if** a destructive confirmation is ever shown. **No destructive action exists in Card View** — bulk Delete is removed (D-07/§AA); Archive is a *reversible* lifecycle op and is **not** styled destructive. Listed for completeness. |

**Status / state colours (separate semantic channel, resolved via `ringVisual().color` + `StatusGlyph` tone — never invented, never a fifth status):**

| State | Avatar-ring colour token | Ring weight | Glyph (via `statusGlyph()`) |
|-------|--------------------------|-------------|-----------------------------|
| Stable | `statusStable` | `ringVisual().width` = 2 | `status-stable` |
| Wobble | `statusWobble` | 3 | `status-wobble` |
| Decay | `statusDecay` | 4 (thickest — "act now") | `status-decay` |
| Rogue | `rogue` | 3 | `status-rogue` |
| Never-contacted / no evaluation (`null`) | `border` (neutral, opacity 0.5) | 2 (thin) | **none** — no glyph rendered (D-11/§J; do NOT mount `StatusGlyph`, do NOT show `status-neutral`) |
| Snoozed (override) | `border` (neutral) | 2 | `status-snoozed` (moon) |

> **Card ring uses the escalating `ringVisual().width` (unlike List View's row border).** The avatar ring **is** the legacy planet-ring the `ringVisual().width` escalation was designed for (see `ContactCard.tsx`), so Card wires both `.color` **and** `.width`. This is *not* the List View §I "constant weight" rule — that rule governed List's full-row border, a different surface. The glyph remains the primary colour-independent channel; ring weight is the redundant CVD channel.

**Accent reserved for (explicit — never "all interactive elements"):**
1. The **filled favourite star** (marked state).
2. The **selection control checked state** (selected card) and Select All active state.
3. The empty-state **primary CTA** ("Add your first contact").
4. The single `accent` **action label in the Snackbar** (Undo) — inherited from the shared `Snackbar`.
5. Active/selected control states inherited from the shared control surface (chips, primary `Button`).

Accent is **never** used for: status/relationship signalling, card body text, the card scrim border on ordinary cards, the status glyph, or the long-press/bulk action surfaces (those use `surfaceElevated`/`textPrimary`/`textSecondary`).

| Empty — filtered population zero | shared filtered-empty copy (population-labelled) |

If the compact column cannot fit it at normal text size, the width-adapted shorter form is Claude's discretion (device UAT) — never invent a *different* semantic. |

Compactness is a bonus, not the sole criterion — a trivial short fact must not displace much more useful context. **Birthdays excluded** (§I). **No AI-generated copy.** A small leading semantic `Icon` may precede it when the source/type has a meaningful icon. The row is **not separately tappable** (§I). |

## Grid & Card Anatomy Contract (dossier §B/§C/§D/§F/§H, CARDV-01/02/03)

**Grid (CARDV-01):** a virtualized, avatar-first grid over `background`.
- **Normal portrait phone: 3 columns**, cards compact enough that **~9 contacts** are visible in a typical portrait viewport (subject to device height and system text size). This is a target, **not** an invariant.
- **2 columns** on very narrow devices and large accessibility text (reflow, not clamp — §AF).
- **More columns** on wider devices/tablets/landscape — increase column count responsively rather than producing overly wide cards. **Portrait-locked app**: "responsive" means column count as a function of available width and text scale, **never** a landscape layout (CLAUDE.md).
- Column count is derived from measured width + text scale at runtime; exact breakpoint px are `[DEFERRED]` to device UAT.

**Card = a floating avatar bubble over a translucent scrim (§C), not a boxed-card grid.**

```
   ┌─────────────┐        ← selection circle (top-left) — ONLY in selection mode
   │◉         ★  │        ← favourite star (top-right of scrim, always visible in normal mode)
   │    ╭────╮   │
   │    │Avat│◐  │        ← status glyph attached to / overlapping the avatar edge
   │    │ ar │   │           (thin status-coloured ring around the circular avatar)
   │    ╰────╯   │
   │  Name       │        ← row 1 (label, 1 line)
   │  18d ago    │        ← row 2 (caption, 1 line)
   │  ⌂ Context  │        ← row 3 (caption, 1 line — optional leading icon)
   └─────────────┘        ← GlassSurface scrim (Galaxy=luminous, Standard=flat)
```

| Region | Contract |
|--------|----------|
| Avatar | **The dominant visual element** (§C). Circular (§C). Large diameter class (~72–96 logical px — exact by device UAT). Reuse `Avatar` with `contactId` recyclingKey + `cacheBust=modified_at` — the anti-face-flash correctness requirement in a virtualized grid (a correctness req, not an optimization). |
| Scrim | `GlassSurface` beneath/around the text, preserving readable card-like text layout (§C). Galaxy = luminous/glass; Standard = calmer/flat — **identical information hierarchy** (§C DERIVED). Corner radius `RADII.lg`/`RADII.xl` (exact by UAT). `density` drives opacity for readability. |
| Status ring | Thin status-coloured ring around the **avatar** (§F). Colour via `ringVisual(status,colors).color`; weight via `ringVisual().width`. Snooze → neutral `border`; never-contacted → faint neutral. |
| Status glyph | A small distinct glyph that **attaches to / overlaps the avatar edge** (§F) — it does **not** occupy one of the three text rows. Via `StatusGlyph` at `ICON_SIZE.sm`/`md`. **Absent for never-contacted** (D-11/§J). Snooze → `status-snoozed` (moon). Decorative at the glyph level; state carried by the card a11y description. |
| Favourite star | Top-right of the scrim, **always visible** in normal mode, directly tappable (≥44px hit area) (§H). Icon via registry `favorite`; filled = `accent`, unfilled = `textSecondary`. Immediate optimistic feedback + **restrained haptic** (§H). Reuse `favourites-dao` mark/clear (binary; **no rank** — D-09). **Becomes non-interactive (but visually readable) during selection mode** (§Q). |
| Selection control | Top-left; **rendered only in selection mode** (§P/§Q). Unselected = empty circle; selected = checked/`accent` state. See Flag F-1 (registry needs a `select` pair). |
| Text block | Three single-line rows beneath the avatar (§D): name / recency / one adaptive-or-prompt line. Category and literal status text are **omitted** to protect compactness (§D). |
| Category | **Omitted from the normal card** (§D) — unlike List View. Bulk *Set Category* still exists as an action; the card just does not display the chip. |

## Status Presentation Contract (dossier §F/§G/§J, D-11, CARDV-02)

Two **redundant** channels for unsnoozed relationship state, never colour alone:
1. **Avatar ring** — status-coloured via `ringVisual(status,colors).color`, weight via `ringVisual().width`.
2. **Status glyph** attached to the avatar edge — distinct celestial silhouette via `StatusGlyph`.
3. (Non-visual third channel) the card accessibility description names the state textually (reuse `buildRowAccessibilityDescription` from `list-row-content.ts`).

> **Never-contacted glyph (D-11/§J):** For `state === null`, render the faint neutral `border` ring and **no status glyph** — do not mount `StatusGlyph`, do not display the `status-neutral` silhouette, do not fabricate a fifth "Unknown" status.

> **Snooze override (§G):** while snoozed, the status ring becomes neutral `border`, the status glyph is **replaced** by `StatusGlyph state="snoozed"` (moon), and the literal underlying status is visually suppressed. Underlying status is unchanged domain state — this is renderer presentation only. Compose `"snoozed"` onto the computed `ProfileStatus` via `StatusDisplayState` exactly as `ListRow` does (`isSnoozed(snooze_until, now)`); snooze is `contacts.snooze_until`, not a query-time status.

## Interaction Contract — Normal Mode (dossier §L/§M, CARDV-04)

| Gesture | Action |
|---------|--------|
| **Tap** a card | Open the contact **Profile** (canonical route; Card stays presentational — caller wires nav) |
| **Long-press** a card | Open the per-contact **context menu** (below) |
| Tap the favourite star | Toggle binary favourite membership (optimistic + haptic) |
| Swipe | **No swipe gestures.** Card View does **not** mirror List View swipe accelerators (§L). Its power interactions are long-press + multi-select. |

**Long-press context menu (§M) — order is locked:**
1. View Profile
2. Quick Log
3. Log Interaction
4. Message
5. Edit Contact
6. Favorite / Unfavorite (label reflects current membership)
7. Snooze / Unsnooze (label reflects current snooze state)
8. Select (fast entry into multi-select)

- The menu is intentionally powerful; it need not be artificially sparse (§M).
- **Delete, Archive, and other high-impact bulk operations are NOT in the long-press menu** (§M).
- Quick Log uses the existing immediate-write contract; Log Interaction routes into the canonical **individual** detailed Log Interaction flow (single contact); Message/Edit/Profile reuse their canonical routable flows (§M DERIVED, App Shell). Card owns only the menu + routing, never the form/business rules.
- Reuse the `OverflowMenu` / `Sheet` action-sheet pattern (`surfaceElevated` sheet over a `background` scrim; each action a `Pressable` row ≥44px). Menu actions must also be reachable **without long-press dexterity** — expose them as card accessibility actions too (§AF).

## Multi-Select / Bulk-Management Contract (dossier §N–§AC, CARDV-05..12)

**Multi-select IS Orbit's Dashboard bulk/contact-management surface** (§N). Do **not** build a separate standalone bulk-management screen (§N, `28-CONTEXT.md` `<deferred>`).

**Entering (§P, CARDV-05):**
- long-press context menu → **Select**, or
- Dashboard overflow → **Select Contacts** / bulk management (switches to Card View if needed, then enters selection mode).
- Normal Card View shows **no** persistent selection controls before selection mode starts (§P).

**Selection visual state (§Q, CARDV-05):**
- Every card shows a **top-left** selection control once selection mode starts: unselected = empty circle, selected = checked state (see Flag F-1).
- **Tapping anywhere on a card toggles its selection** (not Profile nav) (§Q/§AC).
- Favourite stars remain **visually readable but non-interactive** (§Q).
- The selected-contact **count is clearly displayed** (§Q) and announced on change (§AF).

**Control-area replacement (§R, CARDV-06):**
- Dashboard query controls (Population / Filters / Sort **and Search**) are **locked and cease to function** while selection is active (§R).
- Multi-select **reuses/replaces the existing Dashboard control area** (`DashboardControlRow` region) with the selection actions + selection-state controls — it does **NOT** add a new bottom bulk-action bar (§R). This reuses otherwise-defunct screen real estate and prevents ambiguous selection surviving a changing result set.

**Select All (§S, CARDV-06):** selects all contacts in the **current eligible Dashboard result universe**, respecting the Population/Filters/Search state that existed when selection mode **began** — the universe is **frozen** until selection mode exits.

**Normal bulk actions (§T/§U, CARDV-07/08/09):**
- Quick Log · Log Interaction · Add to Favorites / Remove from Favorites · Snooze / Unsnooze · Set Category · Archive · **More / Sensitive Operations** entry.
- **Bulk Edit is NOT offered; multi-recipient Message is NOT in the initial set** (§T).
- Favourite & snooze bulk actions are **explicit** (`Add to Favorites` / `Remove from Favorites`, `Snooze` / `Unsnooze`) — **never an ambiguous "toggle all"** (§U, D-09).
- **Bulk Quick Log (CARDV-08):** writes one generic current-time interaction per selected contact; immediate + Undo for small selections, confirmation for large (§V). **Implementation trip-wire (D-05, ADR-010/024/071):** compose `insertInteractionCore` + `recomputeLastContactCore` inside **one** `inWriteTransaction`; the write mutex is **non-reentrant** — compose the cores, never loop top-level writers; a bulk `INSERT INTO interactions` leaves `last_contact` wrong; `rejectFutureOccurredAt` applies to every logged interaction. *(A build-correctness constraint the executor must honour; surfaced here because it shapes the Undo/feedback UX.)*
- **Detailed Log Interaction — count-aware routing (§T, D-10, CARDV-09):** **1 selected → canonical individual detailed Log Interaction flow; 2+ selected → Phase 12/33 Group Log with the selected contacts preloaded as participants.** Card owns only the action, the count routing, and multi-select UX preservation — **all Group Event domain behavior belongs to the Group Interaction Logging phase.** Layout must stay compatible with that phase's Dashboard header **Group Events** entry + overflow entry (do not collide).

**Archive (§X, CARDV-10):** directly available in multi-select; **outside** Sensitive Operations (reversible lifecycle op). Requires the confirmation above (archived contacts leave the Dashboard universe). **Implementation trip-wire (D-06, ADR-025):** compose **N immutable lifecycle-event writes** — a bare `UPDATE contacts SET archived_at=…` silently skips the event trail; do not do it.

**Sensitive Operations (§Y/§Z/§AA, CARDV-11):**
- A distinct Sensitive Operations menu/subsurface. **Initial contents: Change Contact Frequency only.**
- Bulk **Delete is not offered** (removed — D-07/§AA); **Gravity is never a bulk action** (derived-never-stored — §Y).
- Bulk Frequency applies one chosen frequency to all selected contacts and requires the confirmation above (§Z).

**After a bulk operation (§AB, CARDV-12):**
- Ordinary successful bulk ops **preserve selection mode and the selected contacts** so the user can perform multiple cleanup actions without reselecting (Quick Log → stay selected + Undo/error feedback; Favorite/Snooze/Category/Frequency → stay selected; Archive → archived cards disappear, remaining eligible selections stay selected).
- The user **explicitly exits** selection mode when finished.

**Exit / navigation (§AC, CARDV-12):**
- **Back exits multi-select before normal route navigation.**
- Selection mode **owns card taps** — Profile navigation does not occur while selection mode is active.
- Entering/leaving selection preserves the pre-selection Dashboard query state so normal browsing resumes where appropriate.

**Boundary (§O, `<deferred>`):** contact **import** is NOT part of Card/Grid multi-select — it belongs to Backup/Restore; the overflow entry is "Select Contacts", never an import surface.

## Accessibility Contract (dossier §AF, CARDV-01/02)

- **Card description** (composed, colour-independent) covers: name, recency phrase, favourite state, relationship-or-snooze state, adaptive/search context as appropriate, and (in selection mode) **selection state**. Reuse `buildRowAccessibilityDescription` + the `StatusGlyph` state labels (`Stable` / `Wobbling` / `Decaying` / `Rogue` / `Snoozed` / `Not yet contacted`).
- **Relationship status remains available to a11y semantics even though no literal status label is shown** on the card (§D DERIVED).
- Status meaning must survive with **no colour perception**: ring + glyph + textual label are the redundant channels (§AF, CARDV-02).
- **Context-menu and selection actions must be reachable without relying exclusively on long-press dexterity** (§AF) — expose the context-menu actions and Select as card accessibility actions; expose bulk actions as reachable controls in the replaced control area.
- Selection mode exposes appropriate a11y roles/states and **clear announcements for selection count and bulk-operation outcomes** (§AF DERIVED).
- Large system text **increases card height and/or reduces column count** — normal density targets are not accessibility invariants (§AF).

## Motion Contract (dossier §AD, CARDV-12)

- Ordinary fast local Population/Filter/Sort/Search re-querying **keeps existing cards visible** and does **not** flash loading skeletons (§AD).
- Initial or meaningfully delayed loads may use **compact, renderer-appropriate placeholders** matching the card geometry (§AD).
- Result appearance/disappearance/reordering may use **short, restrained** transitions. Tokens: `MOTION.fast` (120ms) / `MOTION.base` (200ms), easing `EASING.decelerate` for enter. Understated — never orbital/cinematic.
- **Reduced motion:** gate via `useReducedMotion()` — when enabled, simplify/remove nonessential transitions (instant apply) (§AD DERIVED).
- Any card/bubble animation must **not** be driven from React state (`setState`-per-frame re-renders the tree on the JS thread) and must **pause on `useIsFocused === false` and `AppState` background** (CLAUDE.md). Grid enter/exit/reorder here are short RN/Reanimated transitions, not a Skia render loop — but the no-setState-per-frame and pause-when-unfocused rules still hold for any continuous motion.
