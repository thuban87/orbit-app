## Typing strategy (planner discretion — minimizes consumer churn while staying correct)

`types.ts` gains four per-tab param lists + `TabParamList` (via `NavigatorScreenParams`) + per-tab `CompositeScreenProps` helpers. **`RootStackParamList` is retained as a back-compat combined alias** (the four per-tab lists merged) so the 38 existing `RootStackScreenProps<T>` / `NativeStackNavigationProp<RootStackParamList>` consumers keep compiling and working for intra-stack navigation — they are NOT force-migrated. Only the CROSS-TAB / container-level navigate sites (N1–N5) are rewritten to the nested `navigate("<Tab>",{screen,params})` form with correct composite typing (Plan 03). Each per-tab stack is `createNativeStackNavigator<ThatTabStackParamList>()` and registers only its subset (react-navigation permits registering fewer screens than the list declares).
