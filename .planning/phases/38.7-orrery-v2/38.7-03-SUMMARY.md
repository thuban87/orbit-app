# Phase 38.7 Plan 03: D-52/D-53 Orrery freeze and per-frame cost fixes Summary

**The Orrery frame worklet no longer captures the scene or switch runtime, and the runtime and empty props are stable, so an unrelated screen render stops restarting the frame mapper (the likely Choose System ANR mechanism). Switch setup is O(N). Every per-frame body lookup is O(1). The projection basis is computed once per frame. The label allocator runs on a spatial hash. All of it is bit- or deep-equal to the old code, proved against frozen copies.**

## Performance

- **Duration:** ~22 min
- **Started:** 2026-10-03T12:25Z
- **Completed:** 2026-10-03T12:47Z
- **Tasks:** 3 of 3
- **Files modified:** 16 (10 source, 6 test)

## Accomplishments

- **Task 1 (tracer): the freeze.**
  - **Captures.** OrreryWorld destructures `transition`, `progress`, `cameraFrom` and `cameraTo`, plus a primitive `generation`. It passes memoised `{id, uid}` member identities to `deriveSatelliteBodies`. The compiled frame closure is exactly: `transition, progress, cameraFrom, cameraTo, pose, reorder, generation, satellites, memberIdentities, level, viewport` plus module functions.
  - **Stable props.** `EMPTY_IDS`, `EMPTY_RELATIONS` and `EMPTY_SATELLITES` are now the defaults. OrreryScreen memoises `clusterIds`. `useOrrerySwitchRuntime` returns a `useMemo`'d object. `publish` ships only `world` and `generation` to the UI thread.
  - **Stale camera.** New `displayedSwitchCamera(from, to, progress, live)`. `publish` and the reduced-motion reaction start from `pose.value` once settled. `sampleOrrerySwitchCamera` sits directly below `interpolateCamera` and is the one sampler used by drawing, the snapshot and `sampleOrrerySwitchRuntime`.
- **Task 2: O(N) setup and O(1) lookups.**
  - **Keyed setup.** `beginSwitchChoreography`, `beginWorldTransition` and `mergeResources`/`pruneOrreryResources` are keyed. `settledWorld` is the fast path, deep-frozen under `__DEV__`.
  - **Frame indexes.** `AnimatedFrame.keyIndex`/`idIndex` are built in the projection pass and read through `frameBodyByKey`/`frameBodyById`. The readers are `billboardPose`, the rings, the focus card, the reorder ghost, the label candidates and the focused-moon reaction.
  - **Labels and rows.** An `allocationIndex` derived value feeds `OrreryLabel`. Member and contact rows resolve through a per-array id map.
- **Task 3: projection and labels.**
  - **Projection basis.** `projectionBasis` and `projectWithBasis` are defined above `projectWorldPoint`, which is now basis + project. Validation and throw precedence are the same as before. `projectFrame` computes one basis per call and accepts `options.ringPaths`.
  - **Label allocator.** `allocateLabels` uses a uniform-grid spatial hash for the obstacle, candidate and placed-label collision tests. The ranking comparator is now the single `compareRankedLabels`, ready for Plan 05.
- D-32 is unchanged: `NORMAL_SWITCH_DURATION_MS = 2100`, `REDUCED_SWITCH_DURATION_MS = 180`, `INTERACTION_READY_PROGRESS = CAPTURE_END` (0.82), and the land-at-Home `finish` all stay as they were.

## Deviations from Plan

### Auto-fixed / scope-adjacent changes (all behaviour-preserving, all tested)

**1. [Rule 2 - D-52 capture] The north-tap gesture worklet captured the whole `scene`.**
- **Found during:** Task 1, while listing every compiled OrreryWorld closure.
- **Issue:** `onNorth` read `scene.extent`, so the gesture worklet captured and serialised the full scene snapshot.
- **Fix:** It now uses a primitive `sceneExtent`, which is also used for `cameraExtent(...)` and the gesture deps.
- **Files:** `src/components/orrery/OrreryWorld.tsx`. **Commit:** `c9d54dc8`

**2. [Rule 2 - D-53 settled fast path] Extended to the non-switch publish path.**
- **Found during:** Task 2.
- **Issue:** The plan placed `settledWorld` only on `settleSwitchChoreography` (after a switch completes). Every scene load or refresh publishes a settled choreography via `beginSwitchChoreography(world, world, …)`, which would still allocate N bodies per frame while panning at rest.
- **Fix:** New `beginSettledSwitchChoreography(world, generation, reducedMotion)`. `settleSwitchChoreography` and the non-switch `publish` branch both use it. It is tested equal to the intensity-0 self-choreography plus the fast path.
- **Files:** `orrery-switch-choreography.ts`, `use-orrery-switch-runtime.ts`. **Commit:** `249ebd45`

**3. [Rule 2 - D-52 O(N²) render path] Per-body `scene.contacts.find` in `ProjectedBody` and the ring styles.**
- **Found during:** Task 2.
- **Issue:** The plan named only the labels-memo `members.find`. The same per-body scan ran in every `ProjectedBody` render and for every ring's style on each OrreryWorld render. That is O(N²) on the JS thread for large Systems.
- **Fix:** A module-level `rowById` builds one first-match id map per row array, keyed weakly. The labels memo, `ProjectedBody` and the ring styles all use it.
- **Files:** `OrreryWorld.tsx`. **Commit:** `249ebd45`

**4. The focused-moon reaction in OrreryWorld (per frame) uses the key index.**
- Keys are unique within a frame, and a non-interactive hit still counts as absent, exactly as before. **Commit:** `249ebd45`

**5. ProjectedOrbitRing does two direct O(1) lookups** instead of "one lookup feeding both derived values".
- A shared intermediate derived value would add one mapper per ring per frame. The acceptance grep (no `.find(`) holds.

**6. Test-harness changes.**
- `orrery-switch-runtime.test.ts`'s React/Reanimated mocks are now slot-based, so they survive re-renders and compare deps. A runtime-identity test needs that. All existing tests pass unchanged.
- `orrery-frame-mapper.test.ts` now matches captures by exact name (previously a fuzzy `endsWith`) and also forbids `camera`.

**7. Tracer gate.**
- Task 1 is `type="tracer"`. Its `<verify>` is fully automated and was re-run end-to-end: 5 files / 35 tests plus tsc, all passing. Per the owner's standing direction (run autonomously; internal checkpoints are not stops) and `autonomous: true`, execution continued to Tasks 2-3 without a human-verify stop.

## Deferred / surfaced items (plain language, with recommendations)

1. **Reorder drag preview is still O(bodies × ring members) every frame.** `previewReorder` (`src/logic/orrery-reorder-logic.ts:133-134`) calls `reorderedVisibleIds.indexOf(body.id)` for every body on every drag frame, which is about a million comparisons per frame at All Contacts scale. `captureReorder` (`:64-66`) does a similar scan once per long-press. **Recommendation:** index both, using an id→position map built once per call, in the D-23 reorder plan. It is the same pattern as this plan and a few lines of code.
2. **The tap gesture worklet still captures the full member rows.** `resolveTap` in OrreryWorld captures `members` and `identities`, which are serialised whenever the gesture is rebuilt (on scene changes, not on ordinary renders now). **Recommendation:** in Plan 04 or 06, check whether `resolveOrreryTap`/`orderContactTargets` need more than `{id, uid}`. If not, pass `memberIdentities` instead.
3. **The focus-offscreen check scans once per frame while someone is focused.** `focusEffectivelyOffscreen` (`src/logic/orrery-focus-logic.ts:124`) does one linear scan. That is O(N), not the N² defect class. **Recommendation:** low priority; switch it to `frameBodyById` when that file is next touched.
4. **Day-1 baseline defects this plan does not claim to fix** (38.7-02-SUMMARY items):
   - **#1 All Contacts / Orrery Stress SIGSEGV** (JS thread, through react-native-skia `JsiHostObject::get`): nothing here targets it, and it is a **G4 hard gate**. **Recommendation:** reproduce it on a debug build before Plan 08's spike, because the spike cannot measure All Contacts while it crashes.
   - **#2 Size 120 load blocking, #3 Choose System ANR, #4 3a touch ANR:** this plan removes the most likely mechanism (mapper restarts and full-scene serialisation on every render), plus the O(N²) setup, lookups and per-point projection. Whether that is enough is device-only, under G4/G5 at Plan 08/16.
   - **#5 idle UI-thread busy:** not addressed. It belongs to D-49's ambient clock (G6).
   - **#6 "Unavailable System" after a cold start:** Plan 04.
5. **Satellite derivation is still O(rows × members) per frame.** Plan 10 owns it, as the plan states.
