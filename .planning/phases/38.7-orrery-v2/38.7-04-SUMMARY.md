# Phase 38.7 Plan 04: OrreryTextService, Hermes-safe initials and the cold-restore System name Summary

**Every Orrery label, caption and initials Paragraph now comes from one cached, hard-capped OrreryTextService. It shares one builder per font provider, refuses admission before shaping, and disposes an entry only after the UI echoes a generation that no longer draws it. Tier and visibility reach it through UI reactions and SharedValues, never React state. On Hermes, initials are now real ("Ellie Brown" → "EB"). A cold start into a custom System shows its real name.**

## Accomplishments

### Task 1 (tracer): OrreryTextService end to end

**The service** (`resources/orrery-text-service.ts`)
- **Tunables at the top of the file:** cap 1,200, reserve 32, re-key bound 3 generations, initials minimum radius 7 px, report interval 250 ms, warm budget 256.
- **Builders:** one ParagraphBuilder per font provider, reset before every build.
- **Cache key:** provider, role, scale, width, font size, ink, family, weight and text, joined with U+0001. LRU order comes from Map re-insertion.
- **Entry states:** pinned, warm and retired, all counted against the cap.
- **Admission before shaping:** a request that cannot fit returns null and builds nothing.
- **Owner lifecycle:** `acquire` replaces an owner's pins at a given generation and epoch. `confirmEchoed` ignores stale epochs. `release` retires every pin and ends the epoch, and `confirmReleased` completes it.
- **Housekeeping:** `trim` (cap plus warm budget), `clearUnheld` and `stats`.
- **Retries:** `onCapacityFreed` re-runs queued work whenever capacity actually frees, from any owner's echo or release.

**The publisher**
- **Priority order:** focused labels, then cluster labels, then visible labels (identity and above only), then initials of photo-less bodies by projected radius, then initials of photo-path bodies. Captions are prepared at the detail tier only.
- **Budget:** a budgeted prefix, so normal requests stay under cap − reserve.
- **Replacements:** same-slot replacements, and slots dropped by a fallback generation, may use the reserve.
- **Fallback generation:** drops superseded pins off-screen first, then lowest priority.
- **Writes:** each spec is written only when its signature changes. An unchanged re-publish writes nothing.

**OrreryWorld (the legacy shim)**
- Holds the label and initials spec SharedValues and one publisher per instance.
- **Inputs:**
  - Scene inputs arrive through an effect.
  - The tier arrives through a `level` reaction and runOnJS, on change only.
  - Visibility and initials eligibility come from a frame reaction. That reaction is throttled to 250 ms, has a trailing UI `setTimeout`, and sends only when a key set changes.
- **Echo:** a spec reaction calls UI `requestAnimationFrame`, then runOnJS, then a UI round trip, then `confirmEchoed`.
- **Unmount:** release, then `setTimeout(0)`, then a UI round trip plus one frame, then `confirmReleased` and `clearUnheld`.
- **Labels:**
  - Rendered as stable nodes per labelable body; each reads paragraph, box and text width from the spec.
  - The allocation input is the spec's plain `measured` list, so unadmitted labels are never candidates.
- **Bodies:** OrbitBody and SunBody read their initials Paragraph by body key. Font size is quantised to 0.5 px through `orbitBodyInitialsLayout` / `sunBodyInitialsLayout`. A body without an entry draws the plain swatch.
- **Tap worklet (carried in from 38.7-03):** captures `memberIdentities` instead of `members`.

**Worklet scan:** `readdirSync(…, { recursive: true })` now asserts that `resources/orrery-text-service.ts` is scanned.

### Task 2: Hermes-safe initials (D-33)

`firstGrapheme` iterates code points. It keeps a regional-indicator pair together and absorbs `\p{M}`, U+FE00–FE0F, U+20E3, skin tones, tag characters and ZWJ + next code point. `orreryInitials` uses it when Segmenter is absent and never returns the full name.

### Task 3: Custom System name after a cold restore

`resolveName` (optional) is called for custom Systems after load, concurrently with persistence. It is guarded by `active` and the generation. A thrown error or `undefined` keeps today's fallback. OrreryScreen wires it to `readSystemsCatalog` (no new SQL).

## C4-L1: does a recorded SkPicture own its drawParagraph contents? (installed @shopify/react-native-skia 2.6.2)

**Yes, the finished picture owns what it painted. The recorder command does not.**

1. **The picture owns its text blobs.**
   - `JsiRecorder::play` (`cpp/api/recorder/JsiRecorder.h:55-90`) replays the commands into a fresh `SkPictureRecorder` (`:70-73`). It then calls `finishRecordingAsPicture()` (`:80`) and swaps the result into the view's picture (`:84`).
   - `ParagraphCmd::draw` (`cpp/api/recorder/Drawings.h:887-893`) paints the paragraph into that recording canvas.
   - skparagraph paints through `ParagraphPainter::drawTextBlob(const sk_sp<SkTextBlob>&, …)` (`cpp/skia/modules/skparagraph/include/ParagraphPainter.h:46`). `SkTextBlob` is reference-counted (`SkNVRefCnt`, `cpp/skia/include/core/SkTextBlob.h:42`), and the recorded `SkPicture` is immutable and replayable on its own (`cpp/skia/include/core/SkPicture.h:33-34`).
   - So a finished picture holds its own references to the shaped text, not to the `SkParagraph`.
   - Together with the `sk_sp<SkPicture> picture = _picture` capture in `RNSkPictureView::performDraw` (`cpp/rnskia/RNSkPictureView.h:63-65`), an in-flight native draw is safe after a dispose.
2. **The command keeps the paragraph.**
   - `ParagraphCmdProps` holds a `shared_ptr<JsiSkParagraph>` (`Drawings.h:867-868`), and every replay calls `getObject()`. That call throws on a disposed object (`cpp/api/JsiSkHostObjects.h:181-185`).
   - Replays happen on every animated-value change (`src/sksg/Container.native.ts`: the mapper runs `applyUpdates` and then `play`). A first frame is also played after every React-commit `visit`, using the values read at visit time (`Convertor.h:83-94`).
   - Disposal is therefore safe only once no recorder can replay a command that references the paragraph. That is exactly what the echo, round-trip and unmount sequencing above gates.

The finding allowed both disposal paths to ship.

## Deviations from Plan

### Auto-fixed / scope-adjacent (all tested)

1. **[Rule 2 - memory bound] Labels above overview are prepared only for visible bodies.**
   - Focused and cluster labels are prepared at any tier.
   - The plan gated by tier only. At All Contacts that would shape ~1,000 labels in one JS turn on the identity crossing and squeeze initials out of the budget.
   - Visibility rides on the same throttled UI report as initials eligibility. **Commit:** `e3ac4c13`
2. **[Rule 2 - use-after-free] Extra UI round trip before `confirmEchoed`, and a deferred unmount confirm.**
   - **Echo:** a React-commit Skia redraw reads SharedValues synchronously on JS but plays its first frame later on UI. The echo is therefore re-queued behind it on the FIFO JS→UI queue.
   - **Unmount:** `Canvas` unmount does not stop its container mapper (`NativeReanimatedContainer.unmount` only sets a flag). The unmount confirm therefore waits for `setTimeout(0)`, then the UI round trip, then one frame, which orders it after the stopMapper jobs queued by the same commit. **Commit:** `e3ac4c13`
3. **[Rule 2 - memory] `ORRERY_TEXT_WARM_MAX_ENTRIES` (256).** With the plan's "trim while over the cap" rule alone, `trim` would never free anything (admission keeps the cache at or under the cap). **Commit:** `e3ac4c13`
4. **[Rule 1 - lifecycle] Only `setScene` (re)mounts the publisher.** Otherwise a late tier or visibility report after unmount re-pinned entries for a dead owner, which would leak capacity forever. Tested. **Commit:** `e3ac4c13`
5. **[Rule 2] `onCapacityFreed` on the service.** "Retry when capacity frees" now covers another owner's release or echo (V2 and the warm cache share the singleton), not only this publisher's own echo. **Commit:** `e3ac4c13`
6. **Per-instance owner ids** (`orrery-world:N`) instead of the literal `"orrery-world"`. Two simultaneously mounted worlds can then never confuse each other's pins.
7. **1,000-body assertion.** The test asserts `built ≤ eligible visible bodies (photo-less + photo-path) + focused/cluster labels`. A separate tight-cap test proves photo-less before photo-path, largest first. The plan wrote "eligible photo-less count". Photo-path initials are still prepared at the lowest priority, because they are the failed-photo fallback.
8. **Capture-guard test location.** It lives in `orrery-frame-mapper.test.ts`, outside `files_modified`, because it reuses Plan 03's compile-and-extract machinery.
9. **Test-harness changes in `orrery-render.test.tsx`:**
   - effects run synchronously;
   - UI reactions are recorded and flushed by `flushUi()`;
   - fake timers and a `requestAnimationFrame` stub;
   - the builder mock gained `reset` and `dispose`;
   - the identity-tier label test now flushes reactions, because labels are tier-lazy.
   - The native-ellipsis/Unicode assertion is unchanged and passes.
10. **Tracer gate.** Task 1's `<verify>` was re-run end to end (32 files / 308 tests + tsc, all green). Per the owner's standing direction and `autonomous: true`, execution continued without a human-verify stop.

**Total deviations:** 5 auto-fixed (Rules 1-2), 1 naming choice, 1 test-interpretation note, 3 test-structure notes. None is architectural and no owner-bucket item was touched.

## Deferred / surfaced items (plain language, with recommendations)

1. **Will this fix the All Contacts / Orrery Stress crash (Day-1 defect #1, SIGSEGV)? Probably not on its own. I expect it to remove the biggest known cause, but I can't promise the crash is gone.**
   - **Why it may help a lot:**
     - Main built about 3,000 Paragraphs plus ~1,000 builders on every OrreryWorld render at that size (2 per labelled body + 1 initials + 1 builder each). It never disposed any of them.
     - That is real native memory, plus several GiB of reported pressure per render.
     - A null-pointer dereference under native memory exhaustion fits the crash, as does the one trace through `JsiHostObject::get`.
     - Now at most 1,200 Paragraphs can ever be alive, and the All Contacts overview builds only around (focused label + initials of visible bodies ≥ 7 px).
   - **Why it may not be enough:**
     - The crash was not reproduced or symbolised on a debug build, and most traces were inside Hermes.
     - Other per-body costs remain at that size: the photo SkImages, and ~1,000 label nodes each with now ~10 derived values (the 4 new ones re-run only on a publish).
     - The 30-60 s scene-load blocking from the baseline is untouched.
   - **Recommendation:** before Plan 08's spike, build this commit and switch to All Contacts / Orrery Stress on the 6 Pro, then on the 3a. If it still crashes, take a debug build with a symbolised trace.
2. **Device smoke for the new text path, soon.**
   - Paragraphs now travel inside SharedValues, and the echo depends on UI `requestAnimationFrame`/`setTimeout` and Reanimated's FIFO queue. Vitest cannot prove these.
   - **Recommendation:** in the same device pass, check that names, captions and initials appear and update on zoom, focus and theme change. Also check that logcat shows no `Attempted to access a disposed object`.
3. **The hard cap of 1,200 is generous** (up to ~1.2 GiB of reported pressure in the worst case).
   - With visibility gating, real use should need far fewer.
   - **Recommendation:** read `stats()` in Plan 08's spike at All Contacts, then tune the cap to measured need plus headroom (probably 300-500).
4. **Hermes behaviour is proven only on Node.**
   - The `\p{M}` regex already ships on Hermes (`knowledge-search.ts`).
   - Case mapping of accented initials (é → É) on Hermes is untested.
   - **Recommendation:** include an accented and an emoji name in the device smoke.
5. **The same disposal hazard exists today for photos.** `use-orrery-photo` disposes SkImages in an unmount effect cleanup with no UI round trip. Skia's canvas unmount does not stop its mapper. No crash has been seen.
   - **Recommendation:** Plan 07's per-layer ledger should apply the unmount ordering used here to images too.
6. **Legacy label node count.** The shim keeps one label node (+ caption) per labelable body, matching main. **Recommendation:** none here; Plan 07 deletes these components, as planned.
