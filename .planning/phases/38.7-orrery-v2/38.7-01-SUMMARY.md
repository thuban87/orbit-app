## Deferred / surfaced items (for the owner, plain language)

1. **Tab return can't time a perfectly instant redraw.** The detector compares the Orrery's canvas to its blank first frame. If a future V2 build draws the full scene in the very first frame the Orrery appears, the result is `no-canvas-change` with a saved strip, not a number. This doesn't affect today's baseline: main takes about 5 s to reload. The method freezes at the first baseline number, though. **Recommendation:** keep it as is. If V2 ever hits this, the hand-checked strip proves an instant return, which already meets the ≤ 1 s target. Decide this before Plan 02 records its first number only if you want an explicit rule for that case.
2. **Touch-window clock proof needs one physical tap.** Neither phone's production `dumpsys input` shows event times. The fallback (clock identity) is proven by the owner's first tap in the Plan 02 session. The runbook makes that the first validation step. **Recommendation:** none needed; this is informational.
3. **All Contacts recordings will show the phone's other contacts.** All Contacts on the test phones includes the owner's existing test contacts, so screen recordings and frame strips at All Contacts will show their names and photos. These stay under `$HOME/orbit-art/38.7/` per the threat model (T-38.7-01-03) and are never uploaded. **Recommendation:** fine as is. Keep those artefacts out of the repo.
4. **FYI:** the 3a's "last ANR" input state records an earlier Orbit "not responding … waited 5002 ms for MotionEvent". That is consistent with the known Choose System ANR todo (2026-09-29), which D-52 already absorbs. Plan 02 measures it.
