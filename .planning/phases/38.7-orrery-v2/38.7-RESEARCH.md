## Summary

The dossier (`docs/dossier/milestone-2/phase-38.7-orrery-v2-dossier.md`, D-01..D-58) is the binding contract. Its grounding claims hold on today's `main`. `src/` is byte-identical to the dossier's grounding commit `34920925`: `git diff --stat 34920925 HEAD -- src` is empty. I re-opened every cited file:line. All five defects plus the stale-camera bug are present exactly as described. Four line refs drift by a few lines. I also found **six items the dossier does not list**, which change the plan:

1. A second fresh-object prop that churns the labels memo (`focusedRelationById = {}`, which OrreryScreen never passes).
2. An O(N²) label allocator running every UI frame.
3. The `publish` closure serialising the whole scene to the UI thread.
4. Polaris, a live feature with its own tap behaviour that V2 must redraw.
5. A non-recursive worklet-order scan that will silently skip any V2 subfolder.
6. Today's ADR-149 contrast proof tests only the brightest extremum.

See "Dossier grounding check".

The work has a strict dependency spine:
- **Day-1 baseline (D-56).** Measure **today's unmodified main**. It must come before any defect fix lands, or it stops being a baseline of main. It needs a dev seed (Size 5/10/20/32/120 plus ~1,000 All Contacts) and measurement scripts, then the owner's gate lock.
- **D-52 defect fixes.** Pure TS, checked by vitest. They can be written in parallel with the baseline but must merge after it is captured.
- **Logic changes:** drift removal, the camera model, size, semantics and moons.
- **Renderer foundation, opening with the D-44 tilted-ring spike on both phones.** The spike must be measured at **All Contacts (~1,000 rings)**, not just Size 120. Lab A's default method was only ever exercised at ≤ 120 bodies. Its per-ring cost is N `makeShader` + `drawVertices` calls on every camera frame. Lab B's ring field is O(1) in ring count and survived 800.
- **Then:** visual layers → focus/HUD → switch → themes/contrast/Preview → tab-return cache → the device and release sign-off.

**Primary recommendation:**
- Plan by affected area along the seams in "Natural plan seams".
- Put the baseline capture and owner gate lock first, then the D-44 spike checkpoint (at Size 120 **and** All Contacts, both phones) before any visual-layer plan.
- Treat these as phase-wide gates: `npx tsc --noEmit`, `npm run check:colors`, vitest, and the orphaned-test-consumer sweep (orrery-render, frame-mapper, accent allowlist, use-orrery-photo, surface contrast).

## Project Constraints (from CLAUDE.md)

- **Owner-bucket stops.** Never reverse an ADR or HANDOFF decision unasked. Every ⚠ SUPERSEDES item is already owner-ruled. Anything new that weakens a control (for example the `IDENTITY_ZOOM` cap, the "SkImage never cached" rule, ADR-149 opacity) is an owner stop unless the dossier covers it.
- **Never push.** Never run `git worktree`. Commit in place on `main`.
- **Review the code, not the diff.** Read every writer and consumer. The graph cannot see TS→SQL edges.
- **Plan sizing** (non-negotiable; quoted for the planner):
  - Group by affected area.
  - Split only on a different area, a hard ordering, a different verification path (device vs vitest), an owner checkpoint, or a plan too big for one executor.
  - Two hard gates: splitting an agreed plan, and a >25% plan-count jump.
- **Local-first.** No network on any render or read path. Bundled assets only. No telemetry.
- **All colours via theme tokens**, including Skia draw calls and SkSL uniforms. `npm run check:colors` is the gate.
- **Animation.**
  - Skia render loop; never `setState` per frame. Reanimated for gestures.
  - All animation pauses on `useIsFocused === false` and on AppState background.
- Tunable constants go at the top of their service file.
- Use `formatLocalDate()`, never `toISOString().split('T')[0]`.
- Portrait-locked: `app.json:6` `"orientation": "portrait"`, `app.config.ts:69` `orientation: "portrait"`.
- **Device.**
  - Resolve the target with `emu-connect` + `adb devices -l`; never hardcode a phone.
  - Perf claims are valid only on a physical phone, release build.
  - Never `apt install adb`.
  - Orbit Metro runs on :8082 with `adb reverse tcp:8081 tcp:8082`.
- **Graphify.** `npm run graph:ask` only; never build the graph.
- **Memory-derived rules that apply here:**
  - Worklet forward-ref hazard.
  - `globalThis.crypto` is absent in Hermes.
  - Android `elevation` on a translucent bg paints opaque.
  - Run `tsc` in every post-merge gate.
  - Orphaned test consumers break `tsc`.
  - No real AI calls on devices.
  - No Drive uploads without approval.
  - Debug-first iteration, then ONE release build.
  - Surface deferred items immediately.
  - Code review before the device pass.
  - Use the UI-safety-gate false positive workaround (`--skip-ui`; the dossier is the design contract).
  - Do not run plan-review convergence from a Fable session.

## Architectural Responsibility Map

The Android app is a single tier with no backend. "Tiers" here are the runtime threads and layers that own each capability.

| Capability | Primary tier | Secondary tier | Rationale |
|---|---|---|---|
| Scene read (members, status, Systems) | SQLite DAO / services (JS thread, async) | — | Unchanged; no new SQL (scope Out). |
| World placement (rank→ring, ts→angle, drift removal) | Pure logic `src/logic/orrery-world-logic.ts` (JS, at load) | — | Camera-independent world (ADR-077). |
| Camera model, projection, hit-testing, label tiers | Pure worklet logic `src/logic/orrery-camera-logic.ts`, `orrery-frame.ts`, `orrery-label-logic.ts` (UI thread) | JS for Home/framing calls | One frame feeds draw + hits (drawn == tappable). |
| Switch choreography / camera interpolation | Pure worklet logic + screen-owned runtime SharedValues (UI thread) | JS publishes scene | Survives canvas unmount (ADR-170). |
| Rendering (sky, rings, bodies, sun, reticle, warp) | Skia pictures recorded on the UI thread from SharedValue specs | JS prepares immutable specs | D-43: React commits never restructure the tree. |
| Text shaping (labels, initials) | `OrreryTextService` (JS thread) | UI thread draws prepared Paragraphs | Paragraph build is JSI and native; must be cached/disposed (Defect 3). |
| Photos | Photo resource cache (JS, async decode) | UI thread draws SkImage | 38.6 D-11/D-41 derivative rules; D-58 bound. |
| HUD, focus card, cluster panel, a11y companion sheet | RN views (JS/UI) over the canvas | reads `camera.frame` | Canvas exposes nothing to a11y. |
| Platform choices (SurfaceView, frame-rate hint, Mali flags, bake path, DPR) | `OrreryRenderHost` capability interface | — | D-46 portability seam. |

### Pattern 1: Stable imperative picture tree (D-43)
**What:** `<Canvas>` holds a fixed handful of `<Picture picture={sv}/>` nodes whose pictures come from `useDerivedValue(() => createPicture(...))`.
- Inputs are SharedValues only: `frame`, specs, the ambient tick, focus/switch state.
- JS writes new immutable specs to SharedValues on data change; React commits never add or remove Skia nodes.
- Use bounded `saveLayer` only while fading. Never a `layer` per item. Today's `OrbitBody.tsx:115` puts `layer` on every body, which is the A1 dead end.

**When:** the whole V2 canvas and the D-57 Preview.
**Source:** Lab A `A:src/components/orrery/lab/LabScene.tsx:540-556`, read this session. It is five `<Picture>`s (`below/sun/above/reticle/top`). Measured release idle main thread went ≈92% → 15–16% (`audits/LAB-A-AUDIT.md` §7). The docs describe Pictures as "immutable" lists of commands for "a variable number of drawing commands each frame" `[CITED: wcandillon.github.io/react-native-skia/docs/shapes/pictures]`.

### Pattern 2: Ambient clock + base bake with disposal (D-49)
**What:**
- Ambient time is a primitive: `floor(clock/33.3)*33.3`, or `-1` under reduced motion. An unchanged primitive never propagates.
- The base (sky + grid + rings without pulses) is rasterised to an offscreen surface once the scene has been still for N ticks; ambient-only frames blit it.
- **Dispose the previous snapshot when replacing it.** Lab A leaks ≈18 MB per settle (`LabScene.tsx:432`, read this session: `const image = surface.makeImageSnapshot();` with no dispose of the prior image).
- Size the bake surface at device pixels, and dispose the surface on unmount via `runOnUI` (Lab A `:291-301`).
- D-49 also requires that idle not drive the panel at 120 Hz. Quantising alone does not stop the per-vsync frame callback, so spike the stop-between-ticks option (Alternatives table).

### Pattern 3: Camera model (D-45/D-47/D-48)
Today, verified:
- `HOME_CAMERA.tilt = 0` (`:60-67`);
- `MAX_TILT = Math.PI / 3` (`:72`);
- `clampCameraPose` clamps tilt to `[0, MAX_TILT]` (`:244`) **and always overwrites `focalDistance = deriveFocalDistance(bound)`** (`:248`);
- `deriveFocalDistance = max(256, (1+√2)·extent·sin(MAX_TILT)/0.45)` (`:91-100`), telephoto;
- `projectFrame` re-derives the clamp bound from the existing focal using `sin(MAX_TILT)` (`:497-504`).

V2 needs:
- `HOME_PROFILE = {tilt, lensShift, fitRule}` and a separate `MAX_USER_TILT`;
- a dolly focal (Lab C `labFocalDistance = 720/zoom`, `C:orrery-camera-logic.ts:75-80`) with re-derived depth clamp and near-plane guards;
- min on-screen size and near clamp applied **inside `projectFrame`**, so `radius`, `hitRadius` and the label gap agree;
- `semanticLevel` fed by projected body size (Lab C `effectiveLabelZoom`);
- `tapIntent` re-keyed off projected size.

Callers to re-test at 0°/45°/62°:
- `OrreryScreen.tsx:328`, `:709-716`, `:952-961`, `:999`;
- `orrery-session-logic` restore clamp;
- `panCamera`, `anchorCameraPose`, `frameBodies`, `tryUnprojectToWorldPlane`;
- reorder's `ringRadius / zoom` recovery (`orrery-reorder-logic.ts:72-73`). It assumes projected `ringRadius = world × zoom` (`orrery-camera-logic.ts:531`). Keep that invariant, or switch reorder to world radii.

### Pattern 4: Text service (D-46, Defect 3)
- One builder per font provider (`reset()` per use).
- A cache keyed `providerId|role|scale|width|ink|text`.
- `sweep(liveSet)` only **after** the UI thread has re-recorded without the old Paragraph.
- In the imperative renderer, specs travel JS → SharedValue → UI recording asynchronously. Gate the sweep on a generation echo from the UI (for example the picture mapper writes `lastDrawnSpecGeneration`), not on React commit alone.

Source: Lab C `C:src/components/orrery/orrery-text-cache.ts:33-101`, read this session (Code Example 3).

### Pattern 5: Authored Orrery tokens (D-51)
- Add an Orrery sub-palette to `ThemePalette` (`src/theme/theme-types.ts`).
- Author it in the **only** palette constructor, `src/theme/theme-presets.ts`, for the four package×mode palettes. `grep rogueExtinguished:` finds palette literals only in `theme-presets.ts` and the type.
- SkSL gets colours only as `float4` uniforms built from tokens.
- Blend rule keyed from the theme store's resolved mode, never luminance:
  - dark → plus/screen allowed;
  - light → src-over with ink tokens.

### Pattern 6: Moon bump / pips (D-31/D-54)
- `deriveSatelliteBodies` returns `[]` at `level === "overview"` (`orrery-satellite-logic.ts:31`).
- V2 adds an overview "bump" descriptor per parent with ≥ 1 qualifying moon. It is drawn on the parent's rim, non-interactive (a tap goes to the parent), and satellite-styled.
- Lab A stack pips are ring-coloured dots. Detect stacks with an angular/spatial index (not Lab A's O(n²) `findStacks`).
- The split threshold sits at the identity tier (projected-size based, D-47).
- Keep `resolveSatelliteTap` parity, and the ADR-105 limits: unlinked only; a non-member sun gets no moons.

### Pattern 7: Contrast proof (D-28/D-55)
Today's proof (`surface.test.ts:885-925`) composites the overlay tint (`ORRERY_OVERLAY_TINT_OPACITY` galaxy 0.91 / standard 0.87, `surface.ts:176-179`) over **only the brightest** of `textPrimary` + `starPalette`. ADR-169 requires **both extrema**.

Content that can sit under a docked card:
- photos (arbitrary pixels: treat as pure black and pure white);
- white initials glyphs (Lab B's 4.42:1 worst case);
- the sky, nebula and stars.

The lever (D-55) is an occlusion dim of drawn content inside the card rect toward the sky base. The proof is therefore:

`worst(textSecondary over composite(tint, α, dim(P, d)))` for `P ∈ {black, white, sky extrema, star tokens}`, in all four palettes. The dim factor `d` is a token/tunable. Card opacity never changes.

### Pattern 8: Tab-return warm cache (D-58)
**Two lifecycles:**
- The canvas, clock and GPU surfaces still unmount on blur and background (`OrreryScreen.tsx:610`, `:1048`).
- A module-level bounded LRU (Paragraph entries, photo SkImage derivatives, baked sky image) survives blur. It has:
  - caps by count and bytes;
  - release on AppState background, on memory pressure, and after an idle timeout;
  - every eviction disposes.

**Finding:** the tab-return latency is not only resource rebuild. `useFocusEffect` sets `sessionReady=false` and awaits `hydratePreferences` **and** a full `useSystemStore.getState().reload()` (SQL) before remounting (`:426-448`, `:1048`). Meeting "tab return ≤ 1 s" may need the canvas to mount on the retained snapshot while the reload runs (see Open Q2).

### Anti-Patterns to Avoid
- **Per-item `layer`/saveLayer, or declarative per-body Skia components.** Main's current pattern (A1 dead end).
- **Clock-captured derived values that return fresh objects.** They redraw at display rate even under reduced motion.
- **Strokes, dashes, ovals, `DashPathEffect` or `JOIN_ROUND` under a perspective CTM on Mali.** Today's ring uses `DashPathEffect` (`ProjectedOrbitRing.tsx:45-47`) on CPU-projected polylines.
- **GPU fbm/hash noise in `half`/mediump.** CPU-bake the nebula.
- **Mutating scratch state inside a mapper's picture callback.** Lab A trails do this; rewrite.
- **Re-rendering the renderer on photo arrival** (Lab B `photoVersion`).
- **Disposing a Paragraph or SkImage that may still be drawn.** Native use-after-free; `use-orrery-photo.ts` header documents the SkImage variant.
- **Lab B's visual-only FLOOR.** It is rejected by D-48.

## Common Pitfalls

### Pitfall 1: Baseline taken after fixes
**What goes wrong:** the "Day-1 baseline of today's main" silently measures the fixed code.
**How to avoid:** the baseline plan builds the release APK from a commit that adds only the dev seed and scripts (no `src/components/orrery` or `src/logic/orrery-*` changes). Record that commit hash in the baseline doc. Defect-fix plans may be written in parallel but merge after capture.

### Pitfall 2: Fixing captures but not every fresh prop
Both `clusterIds` (`OrreryScreen.tsx:1063`) and `focusedRelationById` (`OrreryWorld.tsx:176` default) are fresh every render. `focusKey = JSON.stringify(...)` (`:209-213`) is harmless. Also `resources` must stay referentially stable between switches.
**Warning sign:** a frame-mapper restart or label rebuild on unrelated screen renders, such as opening Choose System or count updates.

### Pitfall 3: Paragraph/SkImage use-after-free
Sweeping on React commit is not enough when the UI thread records asynchronously. Gate the sweep on a UI-confirmed spec generation.

### Pitfall 4: Choosing the ring method at Size 120 only
Lab A was measured at 40/32/3 bodies. All Contacts on the test phones is ~1,000 rings. One contact per ring: `ringRadius = ringInner + index × ringGap`, `orrery-world-logic.ts:127`. That gives an extent of ≈34,000 world units at Balanced spacing.
**How to avoid:** the D-44 spike measures pan/pinch/Recenter presents and switch stall at **Size 120 and All Contacts on both phones**, plus idle CPU, with the ring-density fade (Lab C) in place.

### Pitfall 5: SurfaceView idle pins 120 Hz
`<Canvas opaque>` on Android selects SurfaceView (`[CITED: wcandillon.github.io/react-native-skia/docs/canvas/overview]`). Lab A measured "idle refresh vsyncRate=120.00 Hz" and 32% main-thread CPU (`audits/LAB-A-AUDIT.md` §6–7). Main today is a **TextureView** (`OrreryCanvas.tsx:193`, no `opaque`).
**Consequence:** V2 can be *warmer* than main unless the ambient clock stops between ticks. D-40 is a hard gate, and D-49 says to report to the owner if pulses can't meet it.

### Pitfall 6: Drift removal side effects
- With no push, decayed bodies sit on their ring. The collision test (`:96-99`, `:111-118`) then sees different reference radii, so some `nudgeAngle`s change (angle shifts ≤ 1° / 4 units). Pin the tests to the new values deliberately.
- Reorder's `drift` (`orrery-reorder-logic.ts:73`) becomes ≈0; remove the field or keep it zero-tolerant.
- Switch shed/capture uses `Math.hypot` of positions (`orrery-switch-choreography.ts:270-271`, `:303`, `:335`); that is now equal to `ringRadius`.

### Pitfall 7: 62° is silently clamped to 60°
`clampCameraPose` (`:244`). Raising `MAX_TILT` changes `deriveFocalDistance` and thus **every** pose's perspective. Split Home tilt from max tilt, and move focal off `MAX_TILT`.

### Pitfall 8: Tap-to-Profile and focus zoom regress under a dolly

> ⚠ SUPERSEDED (2026-10-02) by CONTEXT D-60: a tap never opens Profile; Profile opens only from the focus card. The tap-to-Profile parts of this pitfall, of the D-47 summary line above and of the D-47 validation row below are historical.

Under the dolly, `zoom` stops meaning magnification. Re-key both to projected size. D-47 owner-visible amendment: the focus zoom may exceed the cap.

### Pitfall 9: Worklet forward reference
A worklet calling a same-file worklet defined later is `undefined` on Hermes. Vitest cannot catch this (fix f979263). Define helpers above callers, and **extend the scan to any V2 subfolder** (non-recursive `readdirSync`, `orrery-worklet-order.test.ts:209-216`).

### Pitfall 10: Hermes gaps
- `Intl.Segmenter` is absent (Defect 4).
- `globalThis.crypto` is absent. Orrery files have no crypto use today; use `seeded()`.
- Vitest runs Node, which has both, so every Hermes-path test must stub them.

### Pitfall 11: Pips vs moon bumps at 62°
The vertical squash (cos 62° ≈ 0.47) creates more co-angular stacks. Test a dense, tilted System with satellites on. Keep the two marks visually and semantically distinct.

### Pitfall 12: SurfaceView semantics
"Punches a hole through the window, so parent transforms, clipping … do not apply" `[CITED: Skia canvas docs]`. Effects:
- RN overlays (glass cards, header) still composite **above** it, which is what D-39 needs.
- Navigation transition animations and parent opacity will not apply to the canvas content.
- Glitches are possible during the Profile push before blur unmounts the canvas `[ASSUMED]`. Verify on device.

### Pitfall 13: Switch jank sources
- O(N²) setup (`orrery-switch-choreography.ts:361-370`);
- React resource churn at settle (`prune` → `setResources`, `use-orrery-switch-runtime.ts:243-249`), which is fine only if the renderer does not re-record on resource commits;
- photo re-decodes;
- per-frame LUT/texture rebuilds (if the ring field wins).

Reduced motion keeps the 180 ms path (`REDUCED_SWITCH_DURATION_MS`, `:26`).

### Pitfall 14: Contrast proof blind spots
Photos and white initials under the card are the worst pixels, not the sky (Lab B 4.42:1 in Standard Dark). Light themes need the **dark** extreme. Accent is user-selectable (8 curated accents); the reticle uses `accent` (a Skia paint, allowlisted), not text.

### Pitfall 15: Warm cache vs 38.6 rules
`use-orrery-photo.ts` documents "SkImage objects are never cached" (38.6 D-41 ownership). D-58 explicitly authorises a **bounded** cache. Record it in the new ADR citing ADR-170 and 38.6 D-11, and re-measure with the 38.6 fixed d11 method:

### Pitfall 16: adb cannot drive everything
- There is no multi-touch: pinch and two-finger tilt cannot be injected with `adb shell input`.
- TalkBack swipes become camera input.
- `adb input swipe` pan rate is input-injection-bound (Lab A: 63 presents, 16.6 ms median gap).

### 4. Hermes-safe initials fallback (D-33) `[ASSUMED: written for this research; ranges are Unicode facts, verify with tests]`
```typescript
const ZWJ = 0x200d;
const isMark = (s: string) => /^\p{M}$/u.test(s);                 // \p{M} already ships on Hermes in this repo
const isVariation = (cp: number) => (cp >= 0xfe00 && cp <= 0xfe0f) || cp === 0x20e3;  // VS, keycap
const isSkinTone = (cp: number) => cp >= 0x1f3fb && cp <= 0x1f3ff;
const isTag = (cp: number) => cp >= 0xe0020 && cp <= 0xe007f;     // subdivision flags
const isRegional = (cp: number) => cp >= 0x1f1e6 && cp <= 0x1f1ff;
export function firstGrapheme(word: string): string {
  const cps = Array.from(word);                                    // code points, never UTF-16 units
  if (!cps.length) return "";
  let out = cps[0], i = 1;
  if (isRegional(cps[0].codePointAt(0)!) && cps[1] && isRegional(cps[1].codePointAt(0)!)) return cps[0] + cps[1];
  while (i < cps.length) {
    const cp = cps[i].codePointAt(0)!;
    if (isMark(cps[i]) || isVariation(cp) || isSkinTone(cp) || isTag(cp)) { out += cps[i++]; continue; }
    if (cp === ZWJ && cps[i + 1]) { out += cps[i] + cps[i + 1]; i += 2; continue; }
    break;
  }
  return out;
}
// orreryInitials: Segmenter when present, else firstGrapheme per word (≤ 2), uppercase (toUpperCase is grapheme-safe for these).
```
