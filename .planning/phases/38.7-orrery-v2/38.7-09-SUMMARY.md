# Phase 38.7 Plan 09: Environment and orbit look (sky, grid, rings, pulses) Summary

**The V2 Orrery's environment layer: an authored token sub-palette for all four themes, a painted sky with one neutral nebula bake per package/mode/size and a per-System tint applied at draw time, thin sun-lit status rings, a Lab C-style plane grid and Lab B-style orbit pulses. The owner set the grid to "weaker", the pulses to "as in Lab B" and the All Contacts sky to untinted.**

## Performance

- **Duration:** about 4 h of wall-clock time across sessions, including the Task 4 checkpoint and the lab-anchored redo
- **Completed:** 2026-10-03
- **Tasks:** 5 (Task 4 was the owner checkpoint)
- **Commits:** 8

## Accomplishments

- D-51: every Orrery colour is a named `ThemePalette` token authored for all four palettes. The reticle and instrument tokens follow the user's accent. Colours reach SkSL only as numeric uniforms, and the blend mode is keyed from the resolved theme mode.
- D-07/D-08/D-36/D-50: painted sky. The nebula is baked once per (package, mode, size bucket) as a neutral image, and a System change only moves the draw-time tint, so it never triggers a bake. The tint index is FNV-1a over `systemRefId` across at least 12 hue buckets. Drift and parallax run on the shared ambient clock, and the sky is still under reduced motion.
- D-11: thin, sun-lit world-plane rings. The solid / dashed / faded / faint-trace status ladder is kept. World-plane only (D-64), so `ring-field.ts` was not touched.
- D-09: the plane grid is drawn in the baked base. At opacity 0 it is not drawn at all.
- D-10/D-37: orbit pulses are ring-shader arcs in their own ambient picture. They are never baked, they look the same for every status, and there are none under reduced motion or at budget or intensity 0.
- Task 5: the rulings were applied and recorded, and the pulses were made cheaper (below).

**2. [Rule 1 - Bug] The first-frame cover lifted before the layers were recorded**
- **Found during:** Task 3 device pass

- **Fix:** the cover lifts only once the layers are recorded and the surface has presented.
- **Files modified:** src/components/orrery/v2/OrreryV2Canvas.tsx, OrreryV2Canvas.test.tsx

**3. [Rule 2 - Missing critical] New `first-frame.ts` and `shaders.test.ts`**
- `first-frame.ts` (with its test) isolates the first-surface-frame watch from the canvas.
- `shaders.test.ts` compiles the SkSL through CanvasKit, so a shader compile error fails in vitest and not first on the device.
- **Commits:** 9d8020bd, 6d63201f

**4. [Surfaced item 2, done in Task 5] Cheaper pulses (engineering only, no change to the look)**
- **Issue:** every ambient tick re-ran the eligible-ring scan, which walks every body, builds a `bodyKey` string per body and allocates arrays. That was the extra GC, and budget 40 makes it worse.
- **Fix:** `pulseRings(frame, ringSpecs)` (draw-plane.ts) returns the eligible radii, the opacity × density fade and the homography. The canvas derives it in its own `useDerivedValue`, which reads only `frame` and `ringSpecs`, so it re-runs only when one of them changes (that is, per frame/spec, not per tick). `drawPlanePulses` takes the precomputed rings and reuses one `RingLine` across slots.
- **Test:** `OrreryV2Canvas.test.tsx` › "an ambient tick reuses the eligible-ring scan; a frame or ring-spec change re-runs it". All existing pulse tests stay green. The draw-plane placement test now reads `PULSE_SPEED` rather than a literal 0.3. Its "rests between travels" check applies only when travel is shorter than the cycle. When the pulse always travels, it instead checks that the envelope fades to 0 at the hand-over.
- **Files modified:** draw-plane.ts, draw-plane.test.ts, OrreryV2Canvas.tsx, OrreryV2Canvas.test.tsx
- **Commit:** c392b42c
