## ADR draft (record at KB extraction — do not create the ADR file in this plan)

Title: "Orrery keeps a bounded reusable resource cache across tab blur (clarifies ADR-170)". Status: Accepted (Phase 38.7, D-58, owner 2026-10-02). Context: ADR-170 retires settled switch resources so memory never grows with the number of switches; ADR-048/077 keep one unmountable ambient clock; tab return was slow in production and every lab because the canvas unmounts on blur and every return rebuilt photos, text and sky. Decision: two lifecycles. The active render lifecycle (canvas, ambient clock, GPU surfaces including the base bake) stops and releases on blur and background exactly as before. A separate reusable cache (decoded Orrery photo derivatives, OrreryTextService Paragraphs, CPU-baked sky/nebula images) survives an ordinary tab blur, bounded by explicit byte and count caps with LRU eviction, and is released on app background, after an idle timeout since the last visit, and on a platform memory warning; disposal never touches an object a recorded picture still references. Consequences: tab return reuses resources; memory stays within 38.6 D-11's fixed-method limit (measured, Plan 15); ADR-170 stays fully in force. Cites ADR-170, ADR-048, ADR-077 and 38.6 D-11. Key files: `src/components/orrery/resources/orrery-warm-cache.ts`, `orrery-text-service.ts`, `orrery-photo-cache.ts`, `src/components/orrery/v2/nebula-bake.ts`, `src/screens/OrreryScreen.tsx`.
