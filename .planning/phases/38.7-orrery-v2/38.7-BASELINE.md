## Tracer

Pixel 6 Pro, release build, Orrery at Home on `Size 120`. Runbook §10.1 layer probe and the end-to-end sample:

| Check | Result |
|-------|--------|
| Layer probe during an adb pan (`--probe-layers 6`) | one candidate: `VRI-com.bwales.orbit/com.bwales.orbit.MainActivity#46635` (window layer, as expected for today's TextureView canvas). The full `--list` has no Orbit SurfaceView layer. |
| `sf_sampler.py --seconds 12` with 5 adb swipes (`tracer-pan.json`) | layer `VRI-…MainActivity#46635`; vsync 8.33 ms (120 Hz); **9 presents in 12 s; median presents/s 0.0** (1-s bins); intervals p50 8.34 ms / max 8.41 ms (the presents come in short bursts at the 120 Hz vsync); 25 polls, 0 holes, 0 poll errors |
| Cross-check, same window | `dumpsys gfxinfo` frame count +5 (window frames, UI/render thread) |
| Cross-check, screenrecord of one 1.5 s adb swipe | 2 frames in 6 s: the first frame and one update ~1 s after the swipe ended (screenrecord writes frames only on change) |
| Cross-check, stepped `input motionevent` DOWN/MOVE…/UP (each call ~1 s apart) | one on-screen frame per injected MOVE (frames at 2.96, 4.17, 6.54, 7.75 s): the pan does render live, once per input event (`adb-motionevent-check.mp4`) |
| Idle, 8 s, no touch (`tracer-idle.json`) | **0 presents**: today's Orrery draws nothing at rest |

Reading: the sampler, gfxinfo and screenrecord agree, so the measuring stick works end to end on the release build. Main's pan
redraws once per input event (stepped motionevents prove it), but an `input swipe` produces no visible frames until after
the gesture (a 576 px swipe shifts the scene a few dozen px). adb pan is therefore an injection-bound secondary number (runbook §1). The pan/pinch gates come from the
owner's real touches (Task 3).
