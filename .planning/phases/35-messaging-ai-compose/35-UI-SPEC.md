# Phase 35 — UI Design Contract

> Visual and interaction contract for Messaging & AI Compose. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a refactor phase, not greenfield.** Compose, Things to Remember, and the assist banner/confirmation already exist on disk. This contract reuses Orbit's ESTABLISHED design system (custom theme tokens in `src/theme/`, semantic primitives in `src/components/ui/`) verbatim. It invents no new scale, no web framework, no shadcn. Every value below is a real token pulled from `src/theme/tokens/` — cite the token, never a hex.
>
> **Decision ground truth:** `docs/dossier/milestone-2/phase-14-messaging-ai-compose-dossier.md` (2026-09-01 amendment overrides older text) + planning-notes + ADR-078 / ADR-079 + CONTEXT D-01..D-11. Nothing here reverses a `[DECIDED]`/`[REJECTED]` item or an ADR; a contract that seemed to require it would be an owner escalation, not a spec choice.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom theme tokens in `src/theme/`) |
| Preset | not applicable (React Native / Expo, Android-first) |
| Component library | none — Orbit primitives in `src/components/ui/` (`AppText`, `Button`, `GlassSurface`, `Sheet`, `Modal`, `ConfirmDialog`, `ChromeScrim`) |
| Icon library | internal icon registry (`@/components/icons/icon-registry`); sizes via `ICON_SIZE` |
| Font | Inter (body/label/caption) + Space Grotesk (display/heading), loaded via `src/theme/fonts.ts` — no web fonts, no CDN |

**Mode-aware theming (non-negotiable, carried from Phases 23 / 31 / 31.1):**
- Every colour resolves through `useTheme().colors[token]`. No hex literals anywhere, including Skia. `npm run check:colors` enforces this.
- Package × mode: galaxy (dark-first) / standard (light-first). Values live only in `theme-presets.ts`.
- Glassy cards (`GlassSurface`) render translucent only when the background art tone matches the mode; opaque otherwise. Never combine Android `elevation` with a translucent background (paints an opaque dark rect) — use the iOS shadow props `GlassSurface` already applies.
- `ChromeScrim` provides readability behind chrome text/controls floating over a system background.

**Refactor debt to correct while here (from STATE.md UI-REVIEW warnings + current `ComposeScreen.tsx`):** the existing Compose surface hand-rolls `Pressable` + raw `fontSize`/`fontWeight` and colours `accent` where `accentText` belongs. New/rebuilt Compose UI MUST speak in `AppText` roles and `Button` roles (`button-roles.ts`), not hand-rolled text/buttons, and use the tertiary `accentText` link tone for text-only actions — never the fill `accent` on text.

## Spacing Scale

Declared values from `src/theme/tokens/spacing.ts` — `SPACING`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | icon gaps, inline padding |
| sm | 8px | compact element spacing, section gaps |
| md | 12px | dense row inner padding, action-row gaps |
| base | 16px | default screen padding, element spacing |
| lg | 24px | between conceptual groups |
| xl | 32px | major section breaks |
| 2xl | 48px | page-level spacing |

Exceptions: `md = 12` is an intentional grid-aligned step (documented in `spacing.ts`) — dense row padding where 8 is too tight and 16 too loose. The **44px minimum touch target** (`MIN_TOUCH_TARGET`, `button-roles.ts`) is a target-size FLOOR, not a spacing token; every interactive control in this phase (mode switch, Add to AI / Added ✓ toggle, Choose this, Try Again, Cancel, Copy, Transmit, Subject copy, Things to Remember entry, Message Focus removal) pads up to at least 44×44.

Principle (from `spacing.ts`): compact WITHIN components, generous BETWEEN conceptual groups. The composition editor is visually primary; reference/context must not consume the initial viewport (dossier §A/§B).

## Typography

From `src/theme/tokens/typography.ts` — `TYPOGRAPHY`. Five semantic roles over exactly four sizes and two weights. Screens consume ROLES via `AppText role="…"`, never raw sizes.

| Role | Family | Size | Weight | Line Height | Colour token |
|------|--------|------|--------|-------------|--------------|
| display | Space Grotesk | 28px | 600 | 34 (1.2) | textPrimary |
| heading | Space Grotesk | 20px | 600 | 25 (1.25) | textPrimary |
| body | Inter | 16px | 400 | 24 (1.5) | textPrimary |
| label | Inter | 14px | 600 | 20 (1.4) | textPrimary |
| caption | Inter | 14px | 400 | 20 (1.4) | textSecondary |

Phase-35 role assignment:
- Contact name in the Compose/Research header → **heading** (identity, present on both sides — dossier §J keeps the same header for orientation).
- Message body editor input + AI suggestion text + chosen-draft text → **body** (16/24, the reading size; do not shrink for AI panels — the current screen's 13–15px AI panels are refactor debt).
- Email Subject field + section labels ("Avoid", "Message focus · N", "Things to Remember · N") → **label**.
- Fuel/knowledge metadata, age, restrained helper/feedback lines, Off-Limits caption → **caption**.
- `Did you send it?` prompt heading and the AI review-surface heading → **heading**.

`lineHeight` is absolute px derived from the multiplier, so OS text scaling reflows (THEME-07). Never set `allowFontScaling={false}` or clamp reflowable content; large-text reflow keeps the editor + completion actions reachable (dossier §X) rather than preserving a fixed geometry.

## Color

Mode-aware semantic tokens (`ThemePalette`, `src/theme/theme-types.ts`); concrete values live in `theme-presets.ts` and resolve at render per package × mode (galaxy-dark / standard-light + the two light/dark counterparts). Express the 60/30/10 split by ROLE, not by a fixed hex.

| Role | Token(s) | Usage in this phase |
|------|----------|---------------------|
| Dominant (60%) | `background` | screen background of Compose side and Research side |
| Secondary (30%) | `surface`, `surfaceElevated` (+ `GlassSurface` tint), `border` / `borderStrong` | the message editor field, Subject field, knowledge/research cards, AI review surface container, Message Focus chips, the `Did you send it?` panel |
| Accent (10%) | `accent` (fill) + `onAccent` (label on fill); `accentText` (link/text tone) | see reserved-for list below |
| Destructive | `danger` (fill) + `onDanger` (label + `warning` glyph) | destructive confirmation only — the `Discard changes` action on the shell's unsaved-draft dialog |

**Accent reserved for (explicit — never "all interactive elements"):**
- `accent` FILL + `onAccent` label — the single highest-emphasis completion action per surface: **Transmit** (Compose side); the **adaptive AI action** (`Draft with AI` / `Rewrite with AI`) primary; **Choose this** primary on each AI suggestion; **Yes, log interaction** primary on the Did-you-send-it panel. When no destination exists and Transmit is unavailable, **Copy becomes the sole primary** and takes the accent fill (matches the existing `copyEmphasis` resolver).
- `accentText` LINK tone (text-only, `Button` tertiary role) — `Make this an email` / `Make this a text` mode switch, the **Subject copy** affordance, `Add a phone number` / establish-primary-destination prompts, `Things to Remember · N` entry, `Try Again`, and the `Add to AI` action label.
- A **restrained selected highlight** for `Added ✓` / selected Message Focus chips — a low-emphasis accent-tinted surface/border, NOT the full fill (dossier §O "restrained selected highlight").

Non-accent secondary/tertiary actions use the `Button` secondary (surface + `border`) or tertiary treatment: **Copy** (when not sole primary), **Not yet**, **Cancel**, `Keep editing`. The `AI needs attention` notice is restrained (caption/label on `surface`, no accent CTA styling) — it is a repair route, not a marketing nag (D-07, dossier §L).

AA contrast for accent/onAccent/accentText/onDanger is pre-tuned per palette in `theme-presets.ts` (the galaxy-dark `onDanger` pair is a recorded owner-flag, never auto-retuned). Do not introduce a new colour to satisfy contrast — if a required pairing fails AA, that is an owner escalation.

## Copywriting Contract

All copy below is locked by the dossier (§C/§E/§F/§G/§H/§J/§L/§N/§O/§P/§R/§S/§T) and CONTEXT D-04..D-10. Verbs are specific; empty/error states name the next step.

| Element | Copy |
|---------|------|
| Primary CTA (Compose) | **Transmit** (hands off to the external app; never claims Orbit delivered — dossier §F) |
| Secondary completion | **Copy** → restrained feedback **`Message copied`**; Subject affordance feedback **`Subject copied`** (dossier §E/§H; no dialog, no clipboard history) |
| Mode switch | **`Make this an email`** / **`Make this a text`** (dossier §C) |
| Email field label | **`Subject`** (own lightweight copy affordance; main Copy copies the body only — dossier §E) |
| Things to Remember entry | **`Things to Remember · {count}`** (populated count; dossier §J) |
| AI adaptive action | **`Draft with AI`** (empty editor) / **`Rewrite with AI`** (editor has meaningful text) — dossier §P |
| AI review actions | **`Choose this`** (per suggestion) · **`Try Again`** (replaces the three) · **`Cancel`** — dossier §R/§S/§T |
| Rewrite review | shows the current/original text for comparison + a clear **keep-the-original** path; editor untouched until Choose this (dossier §R) |
| Add to AI | action **`Add to AI`** → selected reads **`Added ✓`** (tap again removes); summary **`Message focus · {count}`** (empty Message Focus not shown) — dossier §O |
| Off Limits presentation | differentiated **`Avoid`** group; visible to the human, never exposes `Add to AI`, never Message Focus (dossier §N, ADR-078) |
| Send confirmation | heading **`Did you send it?`** · **`Yes, log interaction`** · **`Not yet`** (dossier §G). Copy never triggers this. |
| AI Needs Attention | restrained **`AI needs attention`** repair notice, replacing (not hiding) the AI actions; routes toward Phase 36 repair; NOT a setup/configure nag (D-07, dossier §L) |
| Empty state — Research | show ONLY populated conversation-relevant groups; **no empty-section prompts, no data-completeness admin, no add/edit** (dossier §K). Reaching Research with nothing populated shows a compact "nothing to remember yet" caption, not Profile's empty-state scaffolding. |
| Empty state — Message Focus | not rendered when empty (dossier §O) |
| No-destination state | Compose stays usable for drafting + Copy; **Transmit unavailable with an accessible explanation** (e.g. `No phone number for texting — copy your message instead` / establish-a-primary prompt) — dossier §D. Not a blocking error. |
| AI error / failure | concise, non-provider-detail recovery — preserves the manual draft; offers **`Try Again`** and **`Cancel`**; never a provider-troubleshooting screen (dossier §T, D-07). Map sanitized error codes to short lines (timeout/rate-limited/etc.), never raw provider text. |
| Destructive confirmation | shell's unsaved-draft contract: **`Discard changes`** / **`Keep editing`** — used on Back/Cancel with a meaningful draft (dossier §I). `Discard changes` uses the destructive (`danger`/`onDanger` + `warning` glyph) treatment. |

Copy discipline: `Transmit` never says "Sent" or "Delivered"; `Not yet` is not "Don't log" (D-05) — the app-global assist banner + pending sheet retain their own `Don't log` dismissal path (see below).

Removing the banner, removing the dismissal path, or restamping is an owner escalation.
