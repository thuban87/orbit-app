<objective>
Add the third routing tap (endpoint selection when a channel has multiple actionable endpoints, primary emphasized) and wire the existing Compose 'Send' into the shared assist-creation model so a text sent from Compose participates in the return-confirmation lifecycle without writing an interaction at Send time.

Purpose: Completes the ≤3-tap Reach Out contract for multi-endpoint contacts and unifies Compose's Send with Reach Out's handoff-then-confirm model (the alternative — Compose writing directly — is the exact inconsistency the dossier forbids).
Output: `EndpointSelector.tsx`, the router's selector wiring, and the additive Compose→assist seam.
</objective>

<decisions>
- **Task 2 (Compose Send→assist) is RETAINED in Phase 21 per Cluster AC `[DECIDED]`.** Dossier Cluster AC
  ("Text Compose", line 573+) is `[DECIDED]` and places Compose's Send→(create pending assist)→launch
  native→confirm-writes-the-interaction flow in this phase; it is not deferred to M2 Phase 12. The
  dossier Cross-Milestone note (~line 756) concerns *ownership of Compose's Copy/Send/Cancel UX* passing
  to M2 Phase 12 — whose Send MUST map to this same handoff-to-native + assist-creation model, never a
  direct interaction write. That UX-ownership seam is flagged for owner confirmation; it is NOT a
  Phase 21 scope change and does not remove Task 2 from this plan.
- **21-03 is intentionally independent of 21-04's settings DAO wiring (same-wave, no `depends_on`).**
  Plan 04 is the WRITER of the `interactionAssistEnabled` settings DAO key (`COLUMN_OF`
  → `interaction_assist_enabled`); Task 2 here only READS the flag. To avoid serializing Wave 3, Task 2
  reads the raw `interaction_assist_enabled` column directly (defensively defaulting to enabled=1) rather
  than the DAO key, so 21-03 and 21-04 can execute in parallel. Once Plan 04 lands the DAO key, the swap to
  `getAppSettings().interactionAssistEnabled` is performed by a TRACKED, acceptance-gated task in 21-06
  (Wave 4) — not left as an untracked "later touch-up" — so this transitional raw read does not persist as a
  second read path (Addresses review finding #4). The swap lands in Wave 4 (not 21-04) because ComposeScreen
  is a Wave-3 file owned by this plan; no `depends_on` edge from 21-03 is required.
- **Compose Send and the Reach Out router share ONE handoff implementation (Addresses review HIGH-2).**
  The review flagged two divergent handoffs (Plan 02's `performReachOut` sending an empty SMS body vs a
  Plan 03 direct `createPendingAssist` + `SMS.sendSMSAsync(phone, draft)`) — one loses the draft, one
  duplicates failure logic. Resolution: `performReachOut` takes an optional `messageBody?` (default `''`);
  Compose calls the SAME helper with `messageBody: draft`, so create-pending-assist-before-launch,
  `markAssistFailed`-on-throw, and the per-channel Alert live only in `performReachOut`. Compose keeps its
  `sending` in-flight latch around the call and its Copy button unchanged; the Send-failure Alert becomes
  the shared UI-SPEC Text copy (its title already matches Compose's "Couldn't open your messages app"),
  and the Copy button remains the on-screen fallback — a deliberate, minor consolidation of the two
  previously-distinct error strings in favour of one shared handoff path.
</decisions>
