<objective>
Wire Interaction Assist into the three shared subsystems whose runtime state the phase touches — Phase 20's merge (reparent the assist to the survivor), purge (cascade-remove the assist), and the widget (Message→Contact deep-linking into the shared router) — including the untrusted-deep-link allow-list and the purged-target fail-safe. This is the phase's cross-phase correctness core: a missed reparent silently breaks merge redirect, and a loose allow-list is a spoofable-intent security hole.

Purpose: The dossier's revision log promoted merge/purge wiring from a "planning detail" to a named cross-phase constraint precisely because shipped Phase 20 code has no survivor pointer — the assist must be moved during the merge or redirect fails. The widget swap is a bounded, intentional supersession of Dossier 12's Message action.
Output: the merge reparent addition (+ tests), the purge-cascade guard test, the `orbit://reach/<id>` allow-list + WidgetNavIntent + discriminated guard, the widget label/URI swap, the Profile `openReachOut` param, and the purged-target "no longer available" navigation.
</objective>

<decisions>
- **Archived widget-reach policy (Addresses review finding #4 + Claude LOW — archived vs purged).** The
  refactored guardWidgetIntent reports WHY an intent was denied. For the new `orbit://reach/<id>` intent:
  reason `missing` (purged / merged-without-redirect / absent) → the fail-safe "This contact is no longer
  available." → Dashboard; reason `archived` → SILENT drop (no purged message), matching the existing
  widget Profile policy and CRUD-05 ("archived hidden everywhere"). We deliberately do NOT newly enable
  initiating a Reach Out to an archived contact from a stale widget tile: opening an otherwise-hidden
  archived profile would contradict CRUD-05, and archived contacts are already absent from the favourites
  grid the widget renders. Cluster Z's "archived → still loggable" is a CONFIRMATION guarantee (a pending
  assist on a contact that becomes archived stays confirmable via the app-global banner) and is honored on
  that path, unaffected by the widget-initiation guard. The reviewer's alternative (allow archived
  reach-initiation) is an owner-flippable product call, recorded here — not silently taken.
- **The discriminated-guard refactor preserves every existing widget outcome.** guardWidgetIntent changes
  from `WidgetNavIntent | null` to `{ ok: true, intent } | { ok: false, reason }`; WidgetLinkingGate and
  any other caller map `ok`→navigate and every `reason`→their existing drop, so the Phase-12 Profile /
  Compose / Favourites intents behave byte-for-byte as before. Only the REACH gate branch reads the reason
  (missing→message+Dashboard; else silent drop).
</decisions>
