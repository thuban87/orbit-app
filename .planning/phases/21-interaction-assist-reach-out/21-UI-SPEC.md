# Phase 21 — UI Design Contract

> Visual and interaction contract for the Reach Out router, the app-global Interaction Assist
> banner, the return-confirmation actions, the pending-queue review surface, the Settings toggle,
> and the widget `Contact` label swap. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a React Native / Expo (Android-first) app, not a web project.** shadcn/Tailwind/Radix do
> not apply. Every colour MUST resolve through `useTheme().colors.*` (`src/theme/theme-presets.ts` is
> the ONLY file where a hex literal may appear — CLAUDE.md / `npm run check:colors`). Spacing and
> typography are inline `StyleSheet` values following the established codebase idiom catalogued below;
> there is no numeric spacing/type token layer to import. Do not invent a scale — match the idiom.

## Spacing Scale

The codebase has no spacing token module; values are inline `StyleSheet` numbers. Declared scale below
is the **observed established idiom** (verified by histogram over `src/`). Match it exactly.

| Token (conceptual) | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight inline gaps, chip padding |
| sm | 8px | Compact element spacing, section inner `gap` |
| md | 12px | **Default** card/panel `padding`, action-row `gap`, header `gap` |
| lg | 16px | Screen `padding`, section `gap`, row padding |
| xl | 24px | Section breaks, modal horizontal inset |

Exceptions (established, non-4-multiple values in the idiom — reuse rather than "correct"):
- **10px** — card interior `gap` and prompt-box padding (`fuelCard`, `aiPromptBox`).
- **14px** — button/row vertical padding and back-pill horizontal padding (`option`, `backBtn`).
- **2px** — inter-row `gap` in the banner list (`BirthdayBanner`).
- **Touch targets: 44px `minHeight`/`minWidth`** on every tappable control (route buttons, endpoint
  rows, banner actions, the `⋯`-style triggers). This is mandatory, not optional.
- Card/sheet `borderRadius`: 8 (buttons/inputs), 10 (interior cards), 12 (banner/sheet). `borderWidth: 1`
  with `colors.border`.

## Typography

No type token layer; declare the **observed established role set**. Weights `400 / 600 / 700` are all
three in active use across `src/` (137× 600, 68× 700, 23× 400) — this app uses three weights, and the
contract preserves that rather than forcing two. All colours via `useTheme().colors.*`.

| Role | Size | Weight | Line Height | Colour token | Where |
|------|------|--------|-------------|--------------|-------|
| Meta / section-heading / helper | 13px | 700 (heading, uppercase, `letterSpacing 0.5`) / 600 (meta+helper) | ~1.3 | `textSecondary` | banner sub-count, "Primary" marker, Notes label, error/helper lines |
| Body | 15px | 400 | 21px (~1.4) | `textPrimary` | banner question text, note input, endpoint labels |
| Action / row-label | 16px | 700 (button) / 600 (row label) | ~1.25 | button: `background` on accent / `accent` on outline; label: `textPrimary` | route buttons, confirmation buttons, Settings row label |
| Title / heading | 24px | 700 | ~1.25 | `textPrimary` | modal/section title, banner heading when standalone |

Do not introduce new sizes. Panel/secondary body may use 14px/lineHeight 20 (matching `aiPanelText`).

## Color

60/30/10 over the shipped `space-dark` dark palette (`src/theme/theme-presets.ts`). Dark-only this
milestone (`light` falls back to `dark`). All values are token references — never inline the hex.

| Role | Token (value) | Usage |
|------|---------------|-------|
| Dominant (60%) | `background` (#0B0E1A) | Screen background, modal scrim (@ 0.85 opacity), text-on-accent |
| Secondary (30%) | `surface` (#141828) / `surfaceElevated` (#1D2235) | Banner card + endpoint rows on `surface`; router sheet on `surfaceElevated`; borders via `border`/`borderStrong` |
| Accent (10%) | `accent` (#6C8CFF) | See reserved-for list below |
| Destructive | `danger` (#E5484D) | Failed-handoff error TEXT only, and OS-rendered destructive `Alert` (no token needed) |

**Accent reserved for (explicit — never "all interactive elements"):**
- The **primary-emphasis route button** and the **primary phone/email endpoint** (filled `accent` bg,
  `background` text) — the dossier's "primary is visually emphasized" (Cluster B). Secondary/distinct
  endpoints are accent-**outline** (`background` bg, `accent` border, `accent` text).
- The confirmation **"Yes"** primary action button (filled accent). "No answer" and "Don't log" are
  border-outline `textSecondary` (NOT accent, NOT danger — they are neutral, not destructive).
- The Settings toggle **`Switch` track-on** (`trackColor.true: accent`, `thumbColor: surfaceElevated`)
  — matches every existing Settings switch.
- The **"{N} more pending"** count and the **Notes expander** disclosure affordance may use `accent`
  as a lightweight link/disclosure colour (matches `addNumberText`), otherwise `textSecondary`.

**Explicitly NOT accent / NOT danger:**
- "Don't log" and "No answer" are non-destructive → neutral outline (`border` + `textSecondary`).
- Toggling Interaction Assist OFF (which silently clears the pending queue) is NOT styled destructive
  and gets NO confirmation dialog — "off means off" is immediate (Cluster G). It is a normal `Switch`.
- Status tokens (`statusStable/Wobble/Decay`, `rogue`) are NOT used by any Phase 21 surface — the
  banner and router carry no status ring.

## Copywriting Contract

Copy is largely fixed by the dossier's `[DECIDED]` clusters. `{name}` = contact display name,
`numberOfLines={1}` truncated. Route/entry label is the one open owner-taste item (see note).

| Element | Copy |
|---------|------|
| Primary CTA — profile entry | **"Reach out"** (owner-taste: dossier Cluster A permits `Reach out` OR `Contact`; recommended `Reach out` on the profile, with the **widget action fixed at `Contact`** by Cluster AF — flag for owner confirmation, do not silently diverge the two) |
| Router route buttons | "Call" · "Text" · "Email" (only routes with an actionable stored method are rendered/enabled) |
| Endpoint-selector heading | Call/Text → "Choose a number" · Email → "Choose an email" |
| Primary-endpoint marker | "Primary" (small `textSecondary` chip beside the emphasised endpoint) |
| Banner question — Call | "Did you reach {name}?" |
| Banner question — Text | "Did you text {name}?" |
| Banner question — Email | "Did you email {name}?" |
| Call confirmation actions | "Yes" · "No answer" · "Don't log" |
| Text/Email confirmation actions | "Yes" · "Don't log" |
| Multiple-pending indicator | "{N} more pending" (e.g. "4 more pending") |
| Pending-queue review surface title | "Pending confirmations" |
| Notes expander (collapsed control) | "Add a note" |
| Notes input placeholder | "Optional note…" |
| Settings toggle label | "Interaction Assist" |
| Settings toggle helper | "Ask me to log calls, texts and emails started from Orbit." (Cluster G) |
| Empty state — Reach Out (no actionable methods) | **No copy — the action does not render at all** (Cluster A: no dead entry point; hide, never show an empty modal) |
| Empty state — pending-queue review (all resolved) | Heading "You're all caught up" · body "No confirmations waiting." (surface is reachable only while ≥1 pending; this covers the last-item-resolved frame) |
| Error state — failed Call handoff | `Alert`: "Couldn't start the call" / "No app on this device can place calls." |
| Error state — failed Text handoff | `Alert`: "Couldn't open your messages app" / "No app on this device can send texts." (mirrors existing Compose copy) |
| Error state — failed Email handoff | `Alert`: "Couldn't open your email app" / "No app on this device can send email." |
| Error state — widget/deep-link target purged | "This contact is no longer available." → route to Dashboard, never crash or retarget (Cluster AB navigation half) |
| Destructive confirmation | **None.** No Phase 21 action is destructive-with-confirm: "Don't log" writes nothing; toggle-OFF clears pending silently and immediately; failed handoff writes nothing. There is no delete/purge affordance in this phase. |

**Copy invariants (from the dossier — do not soften into delivery claims):**
- Text/Email "Yes" is **user attestation, never delivery verification** — never render "Delivered",
  "Sent", "Read", or "Received" (Cluster J / AJ). "Yes" = the user says they contacted the person.
- The banner is **non-modal and persistent**; the Android Back button **passes through it** (Cluster H)
  — it is NOT a Back-dismissible transient layer. It clears only on resolve / its own dismiss / expiry.

## UI Considerations

Applicable state considerations resolved: 8 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Reach Out entry — no actionable phone/email | ✅ covered | Action does not render (Cluster A). See Copywriting "Empty state — Reach Out". |
| empty | pending-queue review — last item resolved | ✅ covered | Renders "You're all caught up" / "No confirmations waiting." See Copywriting. |
| zero-one-many | endpoint routing depth | ✅ covered | 0 methods → route disabled/hidden; exactly 1 endpoint for the chosen channel → launch directly (2-tap); ≥2 endpoints → show endpoint selector with primary emphasised (3-tap max, Cluster B). |
| partial | single actionable phone backs both Call AND Text | ✅ covered | `contact_methods.is_actionable` is phone/email-granular, not channel-granular (Cluster A/D) — any actionable phone enables both Call and Text; a landline is offered as textable. No per-endpoint call-vs-text gating. |
| overflow | ≥6 pending assists | ✅ covered | Queue capped at 5; banner surfaces the newest eligible assist + "{N} more pending"; oldest prunes (Cluster M/P). |
| overflow | ≥25 hr old / expired assist | ✅ covered | Expired assists never surface in the banner or write an interaction (Cluster N). |
| error | native handoff launch failure / no compatible app | ✅ covered | Per-channel `Alert` copy above; assist marked `failed`, never becomes a pending prompt (Cluster F). |
| error | deep-link target merged/purged | ✅ covered | Merged → redirect to survivor (data layer, Cluster AA); purged deep-link → "This contact is no longer available." → Dashboard (Cluster AB). |
| long-text | long `{name}` in banner question / route modal / endpoint row | 🧪 backstop | `numberOfLines={1}` truncation on all name-bearing rows (BirthdayBanner idiom); held-out visual UI-state check with a long name + a long optional note in the expander. |
