<objective>
Ship the durable Interaction Assist data spine and prove the phase's central architectural risk end-to-end at the data layer: a confirmed assist logs an outbound interaction at the ORIGINAL handoff time through the existing authoritative writer (`recordTouchpoint`), never a bespoke `interactions`/`last_contact` write. This is the TRACER — it wires storage → assist DAO → the single-writer recency path and is fully node-verifiable before any UI expansion (the native handoff and banner are device-UAT-only, so the honest "verified before expansion" proof lives here).

Purpose: The #1 correctness hazard in this phase (per CLAUDE.md) is a second writer of `contacts.last_contact`. Proving the confirmation path routes through `recordTouchpoint` — with cap-5, 24h/15s eligibility, and merge/purge durability semantics all expressed as DATA, not timers — de-risks every later slice.
Output: migration 014 (new `interaction_assists` table + `interaction_assist_enabled` settings column), `interaction-assist-dao.ts` (create-before-handoff, resolve→`recordTouchpoint`, dismiss, fail), `interaction-assist-read.ts` (eligible-queue query + route derivation), and `src/logic/assist-eligibility.ts` (pure ≥15s/≤24h/newest+count).
</objective>
