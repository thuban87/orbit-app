**allow_ai, custom-field scope/history/group, and the custom_field_value_history timeline now export, reconcile, restore (merge + replace-all + clean), and validate within the live backup format 4 — with scope-aware pair validation and safe defaults for older backups. No version bump.**

## Accomplishments

- Export now emits `memories.allow_ai`, `custom_field_defs.scope`/`history_retained`/`field_group`, and every `custom_field_value_history` row (uid + contact/def uid joins), additive within the already-live format 4.
- `custom_field_value_history` is a first-class mergeable + tombstone entity: registered in `MergeableEntityType`, an insert-if-missing `ENTITY_POLICIES` entry with both parents, and wired into every restore map — `entities`, `tableOf`, `tombstoneEntity`, `incomingRows`, `localRows`, the INSERT…ON CONFLICT branch, the replace-all delete inventory, and the replace-all tombstone reset — plus `TOMBSTONE_ENTITY_TYPES` for restore validation.
- `memories.allow_ai` and the three custom-field def columns restore under both modes with safe old-backup defaults (`allow_ai=0`, `scope='global'`, `history_retained=0`, `field_group=null`).
- `assertCompleteIncomingPairs` is scope-aware: only global-scope defs require the full contact×def pair matrix; contact-scoped defs (Plan 05) are exempt while still parent-validated.
- Pre-phase format-4 backups parse end-to-end via `parseBackupManifest` — the absent value-history array is normalized to `[]` (no `4→4` forward migration), never added to `requiredArrays`.
