### `src/db/migrations/016-*.ts` (migration, table DDL + data-move)

**Analog:** `src/db/migrations/007-tombstones.ts` (pure table+column DDL) and `006-normalize-custom-field-values.ts` (data-move with integrity guard).

**Table-creating migration shape** (`007-tombstones.ts:20-27, 85-110`) — `CREATE TABLE` exported as a named const, `version` field matches the file number, `apply(exec, deps)` runs each statement in migration order; the runner owns the per-step transaction. New tables must carry `uid TEXT UNIQUE` + `id INTEGER PRIMARY KEY` (merge identity, ADR-056):
```typescript
export const CREATE_TOMBSTONES = `
CREATE TABLE tombstones (
  id          INTEGER PRIMARY KEY,
  entity_type TEXT NOT NULL,
  entity_uid  TEXT NOT NULL,
  deleted_at  TEXT NOT NULL,
  UNIQUE(entity_type, entity_uid)
);`;
// additive column idiom:
export const ADD_DATA_REVISION = `ALTER TABLE app_settings ADD COLUMN data_revision INTEGER NOT NULL DEFAULT 0;`;

export const migration007: Migration = {
  version: 7,
  async apply(exec: SqlExecutor, _deps: MigrationDeps): Promise<void> {
    await exec.execAsync(CREATE_TOMBSTONES);
    await exec.execAsync(ADD_DATA_REVISION);
    // …one execAsync per statement, in order…
  },
};
```
Register in `MIGRATIONS` in `src/db/database.ts` (analog line 53) and bump `TARGET_VERSION` to 16 (or the highest new number). **Never edit a shipped migration 001–015** (forward-only, irreversible in production).

**Data-move / integrity-guard shape** (`006-normalize-custom-field-values.ts:15-30`) — for the share-capture carry-over (KNOW-14) and ADR-030 `source='ai'` retirement (D-10), model on migration 006's recognizable, bootstrap-safe integrity error class rather than silently coercing:
```typescript
export const MIGRATION006_INTEGRITY_CODE = "migration-006-integrity-failure";
export class Migration006IntegrityError extends Error {
  readonly code = MIGRATION006_INTEGRITY_CODE;
  constructor(reason: string) { super(`Migration 006 integrity failure: ${reason}`); this.name = "Migration006IntegrityError"; }
}
```
Treat every migration as irreversible: no assumed start state (a user may jump v1→v16 in one update), atomic per-step. Extend `full-chain.test.ts` and add `016-*.test.ts`.

### `src/db/memories-dao.ts` (DAO writer, CRUD)

**Analog:** `src/db/fuel-dao.ts` — this is the closest structural sibling (typed per-item rows on a contact).

**Imports pattern** (`fuel-dao.ts:32-35`):
```typescript
import { inWriteTransaction } from "@/db/transaction";
import { bumpDataRevisionCore } from "@/db/data-revision-dao";
import { insertTombstoneCore } from "@/db/tombstones-dao";
import type { SqlExecutor } from "@/db/types";
```

**Core/wrapper split** (`fuel-dao.ts:131-152` core, `:255-264` wrapper) — every mutating DAO exposes a non-mutexed `…Core(exec, …)` that assumes BEGIN is open, plus a standalone wrapper owning exactly one `inWriteTransaction`. Multi-row fan-outs compose Cores inside ONE outer transaction — **never nest the non-reentrant mutex** (deadlock; Pitfall 2, hit on Phases 3/8/13):
```typescript
export async function addFuelCore(exec: SqlExecutor, input: NewFuelItem): Promise<number> {
  const result = await exec.runAsync(
    `INSERT INTO fuel (uid, contact_id, kind, label, text, url, created_at, source, modified_at)
     VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?)`,
    [input.uid, input.contactId, input.kind, input.label ?? null, /* …all ?-bound… */ input.now],
  );
  return result.lastInsertRowId;
}
export function addFuel(exec: SqlExecutor, input: NewFuelItem): Promise<number> {
  return inWriteTransaction(exec, async () => {
    const id = await addFuelCore(exec, input);
    await bumpDataRevisionCore(exec);   // marks DB dirty for backup nudge — inside the txn
    return id;
  });
}
```

**Both-keys scoping + assertOneChange** (`fuel-dao.ts:109-121, 165-197`) — every mutation is scoped by BOTH `id` AND `contact_id` and asserts exactly one row changed; a mismatched pair changes 0 rows → loud rollback, never silent cross-contact corruption. Every value is `?`-bound; only static column names are literal text (T-07-01).

**Soft-delete note (KNOW-09):** Memory delete is a soft-delete (set a `deleted_at`-style column), NOT the hard `DELETE` in `deleteFuelCore:228-250`. Reuse that method's tombstone-then-mutate ordering shape (`insertTombstoneCore` before the write) for the *permanent* delete path in the Trash sweep; the soft path is an UPDATE.

**Provenance (KNOW-08):** replace `fuel.source`'s bare string (`fuel-dao.ts:52`) with structured provenance columns — do not carry the string idiom forward.

### `src/db/memories-read.ts` (DAO read choke point + AI-egress fragment)

**Analog:** `src/db/fuel-read.ts` — the canonical "single read choke point with in-SQL exclusions" pattern (Research Pattern 2).

**One read module per domain; access-control predicates live IN the SQL as a reusable exported fragment, never a UI `.filter()`** (`fuel-read.ts:133-135`):
```typescript
export const RANKED_FUEL_EXCLUSIONS = `kind != 'off_limits'
     AND source != 'ai'
```

### `src/services/memory-trash-sweep.ts` + `memory-history-sweep.ts` (launch hooks)

**Analog:** `src/services/field-sweep.ts` — the canonical `registerSweepHook` launch-sweep (Research Pattern 4). **Nothing watches a timestamp; no background timer** (D-11).

**Registration + idempotent hook** (`field-sweep.ts:83-133`, hook registered via `registerSweepHook` at `launch-sweep.ts:45`):
```typescript
export const QUARANTINE_WINDOW_DAYS = 30; // single top-of-file tunable (owner-fixed)
export function registerFieldSweep(getExec: () => SqlExecutor, now: () => string = localNow): void {
  registerSweepHook(async () => {
    const exec = getExec();
    const windowModifier = `-${QUARANTINE_WINDOW_DAYS} days`;
    // (a) BARE candidate SELECT narrows the set (datetime('now','localtime', ?), strict `<`)
    // (b) per-item DIRECT call to the mutex-owning writer in its OWN try/catch —
    //     NEVER re-wrap in withMutex/inWriteTransaction (non-reentrant → permanent hang, HIGH-1)
    await inWriteTransaction(exec, () =>
      exec.runAsync(`DELETE FROM field_history WHERE created_at <= datetime('now','localtime', ?)`, [windowModifier]));
  });
}
```
Trash-expiry permanent-delete runs here (past the retention window); the retention window is a single top-of-file tunable, and the empty-state copy must match it (no promised timer, UI-SPEC E2). Re-run must be safe (a re-scan finds nothing still-stale). The candidate scan is a bare read that only narrows; the authoritative check happens again under the lock (TOCTOU-safe — a restore between scan and delete survives).

## Shared Patterns

### Serialized writes — core/wrapper split + non-reentrant mutex
**Source:** `src/db/fuel-dao.ts:131-152` (core) + `:255-264` (wrapper); fan-out precedent `capture-dao.ts`.
**Apply to:** every new writer (memories, relationships, current-state history, value-history, AI-permission, soft-delete/restore).
`…Core(exec)` assumes BEGIN open and opens no transaction; the wrapper owns exactly one `inWriteTransaction` and calls `bumpDataRevisionCore(exec)` inside it. Compose Cores in ONE outer txn for fan-outs; **never nest the mutex** (deadlock).

### In-SQL access-control fragment (never a UI filter)
**Source:** `src/db/fuel-read.ts:133-135` (`RANKED_FUEL_EXCLUSIONS`), reused by `dashboard-read.ts:212,237` with a parity test.
**Apply to:** the Memory/search read layer and the AI-egress read. Off-limits exclusion + explicit per-item AI-permission predicate (default OFF) live in SQL as reusable exported fragments. Never infer AI eligibility from kind/type/location (D-08). Off Limits stays a separate control (D-09).

### Merge identity + local timestamps
**Source:** `newUid()` per durable row (every writer); `localDateTime()`/`formatLocalDate()` (`src/utils/dates.ts`), never `toISOString()`.
**Apply to:** every new table (`uid TEXT UNIQUE`) and every timestamp column.

### Launch-sweep for time-based cleanup
**Source:** `src/services/field-sweep.ts:83-133`; `registerSweepHook` at `launch-sweep.ts:45`.
**Apply to:** Trash expiry + history retention. Idempotent hook, single top-of-file window tunable, bare candidate scan → authoritative re-check under lock, per-item try/catch, `inWriteTransaction` for the delete. No timer (D-11).

### One parser per FieldType, sort via `sortExpr()`
**Source:** `src/db/field-parsers.ts:44-91`; `src/db/field-sort.ts:29-40`.
**Apply to:** the three new custom-field types. Exhaustive `Record<FieldType,…>`; never coerce a failing value; never interpolate an identifier into ORDER BY.
