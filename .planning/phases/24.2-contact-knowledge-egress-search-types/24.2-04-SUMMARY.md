# Phase 24.2 Plan 04: Expanded Custom-field Types Summary

**Ten custom-field types with exhaustive, non-destructive URL/email/phone parsing and matching React Native input keyboards.**

## Accomplishments

- Expanded `FieldType` from seven to ten members and its exhaustive parser record to ten entries, retaining Photo.
- Added permissive read-time URL, email, and phone validators that flag implausible data without coercing, clearing, or rewriting successful raw TEXT values.
- Added URL, Email, and Phone picker options, plus explicit value-input dispatch arms that request `url`, `email-address`, and `phone-pad` keyboards through the shared text widget.

## Files Created/Modified

- `src/db/field-parsers.ts` / `src/db/field-parsers.test.ts` — implements and proves ten parsers, including raw-TEXT preservation for the three new types.
- `src/components/FieldDefForm.tsx` — offers all ten field types, including Photo and the three additions.
- `src/components/FieldValueInput.tsx` — explicitly dispatches each new type to TextFieldWidget with its native keyboard hint.
- `src/components/field-widgets/types.ts` / `src/components/field-widgets/TextFieldWidget.tsx` — introduces and forwards the optional `keyboardType` contract.

## Decisions Made

- URL accepts no-whitespace scheme URLs (including `mailto:`) and conventional dot-host or localhost-with-port forms; email requires exactly one `@` and a dotted domain; phone needs at least three digits plus phone-plausible characters.
- Validators preserve passing URL, email, and phone strings byte-for-byte; failed values return `{ ok: false }` so the existing tap-to-fix state remains responsible for recovery.
- `photo` is retained intact; the picker grows from seven to ten options rather than replacing any existing type.
