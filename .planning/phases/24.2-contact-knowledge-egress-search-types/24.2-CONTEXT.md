## Phase Boundary

**Split note (2026-09-03, owner-approved):** the original single Phase 24 was split at the migration seam. **24.1** built the additive knowledge model, storage/DAO layer, and the "Things to Remember" UI. **24.2** (this phase) makes that model searchable, AI-permissioned, richly typed, and portable, and runs the milestone's **destructive data-move**.

**24.2 scope (KNOW-10…16):** bounded local typo search over the eligible set (no FTS5); opt-in-per-item AI permission behind two gates (default OFF) with Off Limits kept separate; the expanded custom-field type set (Text, Long Text, Number, Date, Yes/No, URL, Email, Phone, Choice) with global/per-contact definitions and optional value history via a new additive value-history table; imported phone-Contacts notes as their own AI-off Memory type; migration of existing share-sheet captures onto the new model with no data loss; and full backup/restore coverage. Includes **migration 017** (destructive data-move) and the **new superseding ADR that retires ADR-030**.

This phase adds a backup entity/tombstone but does **not** bump `BACKUP_FORMAT_VERSION` (currently 3; Phase 36 owns the v4 bump).

### Phase-specific constraints
- **D-06 (ADR-001 ESCALATE trip-wire):** Any plan relaxing `UNIQUE(contact_id, field_def_id)` or `custom_field_values.uid UNIQUE` reverses ADR-001 → stop and ask. History-retained custom fields get a **new additive value-history table** (R-08 resolution) — `field_history` is destructive-op-only, unread, pruned at 30 days and excluded from backup, so it cannot host a value timeline. Route every custom-field sort/filter through `sortExpr()`; `custom_field_values.value` stays raw TEXT and is never rewritten to satisfy a type; failing values are flagged, not coerced.
- **D-07 (ADR-031 ESCALATE trip-wire, R-10):** Typo tolerance is **TypeScript scoring over the already-filtered eligible set** — prefix/substring plus edit distance ≤ 1 per term (≤ 2 for terms of six or more characters). **No FTS5, no new search index**; FTS5 would reverse ADR-031 → stop and ask. This phase exposes the corpus and its searchability metadata; the Dashboard Data phase consumes it. Internal metadata is never searched.
- **D-08 (E-05):** Build the sibling **per-item AI permission model** for knowledge items — it does not exist today. Per-item permission defaults **OFF**, behind two gates (AI globally enabled, then per-field/per-item); AI-enabled items show the sparkle icon; type-level defaults affect newly created items only. **Group Notes are never sent — no toggle, no exception.** The egress exclusion lives in SQL (fuel-read.ts `RANKED_FUEL_EXCLUSIONS` pattern), never a UI filter. The per-interaction "Allow AI" toggle is owned by other phases, not here.
- **D-09 (E-05 trip-wire):** The Off Limits transmission outcome is recorded in the dossier and `docs/decisions/`. Check for a superseding ADR before changing `fuel-read.ts`'s exclusions; absent one, the SQL-level exclusion stands (ADR-050, ADR-036, ADR-078). Off Limits stays a **separate** control from AI permission, and when sent to AI carries the semantic "avoid mentioning this topic".
- **D-10b (R-01 resolutions):** Share-sheet capture rows migrate onto the new model as default-type Memories with **no data loss**; the **ADR-030 AI-proposed-fuel path is retired** by this migration and needs a **new superseding ADR** written as part of the phase (next free ADR number — verify head on disk; ADR head is currently ADR-080).
- **D-12 (R-08 trip-wire):** A per-contact **scope** column is additive, but the seeding writers change — ADR-013 / HANDOFF §14 specify "one global definition row per field, seeded for every contact". Enumerate **every writer** of the custom-field tables before altering seeding (RESEARCH.md inventory: `contacts-dao.ts` seeding + `field-ddl.ts`). Going from 7 to 10 `FieldType` members is additive; ADR-014 requires **one parser per type** — never pairwise converters.
