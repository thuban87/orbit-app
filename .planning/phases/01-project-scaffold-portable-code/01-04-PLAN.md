<objective>
Port the plugin's AI provider layer (`AiService.ts`) into `src/services/`, swapping its sole Obsidian
coupling (`requestUrl`) for `fetch` with explicit `response.ok` handling, replacing the unported
`../settings` type import with a minimal local interface, and — per the owner's CONTEXT decision —
OMITTING the local/LAN provider entirely so the four cloud providers (OpenAI, Anthropic, Gemini,
custom HTTPS-only) are all that lands. This is FND-04: the highest-value single port. It must compile
and typecheck standalone — it is DORMANT this phase, wired to no screen.

Purpose: Land the AI transport correctly now, with the one genuine trap handled: Obsidian's
`requestUrl` returned a pre-parsed `.json` PROPERTY, while `fetch` returns a `Response` whose
`.json()` is an async METHOD — a mechanical `requestUrl(`→`fetch(` swap that misses this returns
`[object Promise]`/`undefined` at runtime with NO compile error. The port is verified by structural
greps AND mocked-fetch behavioural tests (greps prove the property→method shape; tests prove the
ok-guard is placed BEFORE the parse), because the bug typechecks silently.

**Owner decision (CONTEXT.md 2026-08-14 — enforce, do not reverse per HANDOFF §4):** the local/LAN
provider is OMITTED entirely from the port. Drop its class, drop its registration, exclude its id from
the `AiProvider` union, and land NO cleartext (non-HTTPS) transport path in `src/`. This enforces the
`[REJECTED]` mobile-local-AI decision in the code itself, not merely a comment. The cross-AI review
surfaced this as an owner-bucket conflict; the owner resolved it toward the later, more specific mobile
decision. Re-adding that provider is a decision reversal, not a bug fix.
Output: `src/services/ai-types.ts` (local settings interface + provider union), `src/services/AiService.ts`
(ported, fetch-based, 4 providers, dormant), and `src/services/AiService.test.ts` (mocked-fetch tests).
</objective>
