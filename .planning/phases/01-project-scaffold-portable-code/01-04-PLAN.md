<objective>
Port the plugin's 540-line AI provider layer (`AiService.ts`) into `src/services/`, swapping its
sole Obsidian coupling (`requestUrl`) for `fetch` with explicit `response.ok` handling, and
replacing the unported `../settings` type import with a minimal local interface. This is FND-04:
the highest-value single port (all five providers behind one interface). It must compile and
typecheck standalone — it is DORMANT this phase, wired to no screen.

Purpose: Land the AI transport correctly now, with the one genuine trap handled: Obsidian's
`requestUrl` returned a pre-parsed `.json` PROPERTY, while `fetch` returns a `Response` whose
`.json()` is an async METHOD — a mechanical `requestUrl(`→`fetch(` swap that misses this returns
`[object Promise]`/`undefined` at runtime with NO compile error. The port is verified by structural
greps, not just typecheck, because the bug typechecks silently.
Output: `src/services/ai-types.ts` (local settings interface) and `src/services/AiService.ts`
(ported, fetch-based, dormant).
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-01 | Tampering / DoS | AiService fetch response handling | medium | mitigate | Explicit `if (!response.ok) throw` before every `await response.json()` (LOCKED). `fetch` — unlike the old Obsidian helper — never throws on 4xx/5xx, so an unchecked non-ok body would be parsed as success. Also retain the existing response-shape optional-chaining guards. |
| T-1-02 | Information disclosure | API key in logs | medium | mitigate | Port `logger.ts` usage as-is; do NOT log settings objects or request bodies that carry a key. Full redaction is AI-04 (Phase 14) — this plan must simply not introduce a leak. |
| T-1-04 | Information disclosure | Cleartext egress via http:// custom endpoint | low | accept | Out of scope this phase — the custom-endpoint UI is not wired. HTTPS-only enforcement lands when the endpoint field is built (Phase 14). No egress is possible now (service dormant). |

The provider boundary exists in code but is dormant (no caller). T-1-01 is mitigated in this port;
T-1-04 is accepted as latent because no egress path is reachable until Phase 14.
