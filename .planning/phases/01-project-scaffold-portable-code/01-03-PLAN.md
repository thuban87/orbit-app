<objective>
Build the theme-token infrastructure and a persisted Zustand store, then render the app's themed
home shell — the Walking Skeleton's single real UI interaction. This is FND-05: a `useTheme()`
provider where colour values live in exactly one presets file, a Zustand+persist store scaffold,
and a home screen that draws entirely from theme tokens (no hardcoded colour anywhere). After this
plan the app opens to a themed shell locally; plan 01-05 proves it on the Pixel.

Purpose: Establish the token architecture the entire app (including future Skia draw calls) reads
from, and prove the Zustand persistence pattern once. Colour values are load-bearing: CLAUDE.md
forbids any hardcoded colour outside the theme module.
Output: `src/theme/{theme-types,theme-presets,theme-provider}.ts(x)`, `src/stores/theme-store.ts`,
and a themed `App.tsx`.
</objective>

The theme module must export at least:
- `ThemeMode = "light" | "dark" | "system"`
- `interface ThemePalette { background; surface; surfaceElevated; accent; textPrimary; textSecondary; border; borderStrong }` (all `string`)
- `THEME_PRESETS: Record<ThemePresetId, ThemePreset>` where a `ThemePreset` carries at least a `dark` palette
- `ThemeProvider(props: { children }): JSX.Element`
- `useTheme(): ResolvedTheme` — returns `{ colors: ThemePalette; mode }`; when called outside a provider it resolves the default preset's palette (never returns null, never a bare hex)
The store must export `useThemeStore` (Zustand) persisted under the key `orbit-theme`.
</interfaces>
