<objective>
Prove the cross-machine build/deploy loop ONCE (FND-01): commit → rsync the source to the `droid`
Windows desktop → `expo prebuild --clean` + `gradlew.bat assembleRelease` over SSH → pull the
STANDALONE APK back → `adb install` on the wired Pixel 6 Pro → launch → confirm the THEMED home shell
rendered. This is the Walking Skeleton's end-to-end proof (scaffold → build → install → app opens to a
themed shell on real hardware — there is no DB round-trip this phase and no backend ever). Several
steps are owner-gated and MUST be gated behind a blocking checkpoint — an agent may not invent the
package id, set up the SSH host, or tap the on-device USB-debug prompt.

**Why a RELEASE build for the one-time proof (review HIGH fix):** a plain `assembleDebug` APK ships NO
embedded JS bundle — it loads JS from a Metro server, so launching it with no Metro/`adb reverse`
renders the RN "could not connect to development server" red screen, exactly at the human-verification
step (quest-board `apps/mobile/ANDROID_BUILD_GUIDE.md:213-222` documents this by name). A `release` APK
bundles JS at build time and runs standalone — the cleanest possible "it installs and opens" evidence,
with this Linux box removed from the runtime path. `gradlew.bat assembleRelease` on an Expo-prebuilt
project is signed by the prebuild-generated debug keystore by default, so it installs without extra
keystore setup (production signing is a later, separate concern). The day-to-day debug+Metro iteration
loop (with `adb reverse tcp:8081`) is ALSO documented in the runbook for later phases.

**FND-01 requires the physical Pixel 6 Pro.** PROJECT.md/CLAUDE.md make the wired Pixel the FND-01
proof target; the desktop emulator is ONLY a weaker launch smoke test (no perf/native-render claims)
and does NOT close FND-01 — an emulator-only run leaves FND-01 OPEN pending the physical device.

Purpose: FND-01 — the single most important risk in this phase is not the code, it is proving the
loop works. After this plan the pipeline is documented as a repeatable runbook for every later phase.
Output: the owner-confirmed package id written into `app.config.ts`, and
`docs/runbooks/desktop-build-pipeline.md`.
</objective>
