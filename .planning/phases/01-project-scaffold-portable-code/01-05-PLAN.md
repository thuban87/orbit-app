<objective>
Prove the cross-machine build/deploy loop ONCE (FND-01): commit → rsync the source to the `droid`
Windows desktop → `expo prebuild` + `gradlew.bat assembleDebug` over SSH → pull the APK back →
`adb install` on the wired Pixel 6 Pro → launch → confirm the themed home shell rendered. This is
the Walking Skeleton's end-to-end proof (scaffold → build → install → app opens to a themed shell
on real hardware — there is no DB round-trip this phase and no backend ever). Several steps are
owner-gated and MUST be gated behind a blocking checkpoint — an agent may not invent the package
id, set up the SSH host, or tap the on-device USB-debug prompt.

Purpose: FND-01 — the single most important risk in this phase is not the code, it is proving the
loop works. After this plan the pipeline is documented as a repeatable runbook for every later phase.
Output: the owner-confirmed package id written into `app.config.ts`, and
`docs/runbooks/desktop-build-pipeline.md`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| This Linux box ↔ droid (Windows) over SSH | Source is rsync'd to the owner's own desktop over an authenticated SSH/Tailscale link; the build runs there |
| droid/box → Pixel 6 Pro over adb (USB) | Debug APK installed on the owner's physical device via the local adb server |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-05 | Spoofing / Tampering | SSH first-connect to droid (trust-on-first-use) | medium | mitigate | The owner accepts the host key at the bring-up checkpoint (Task 1) over an authenticated Tailscale link to a machine he controls; not a public host. rsync excludes `.git`/`node_modules`; no secret is transmitted (the repo holds none this phase). |
| T-1-SC2 | Tampering | `npm install` on droid during the build | high | mitigate | Same pinned, legitimacy-audited stack as plan 01-01 (see RESEARCH Package Legitimacy Audit) — install resolves the same lockfile; no new packages introduced at build time. |

No user content and no API key exists to leak this phase (AiService is dormant, DB is Phase 2). The
transport is the owner's own two machines over an authenticated link.
</threat_model>
