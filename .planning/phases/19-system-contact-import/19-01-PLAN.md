<objective>
Ship migration 012 (the durable import-session schema), the session DAO/read chokepoint, and the canonical row state-transition contract that make an accepted picker result survive process death — the load-bearing durability spine for IMP-04 and the shared vocabulary every later plan writes against.

Purpose: Every later plan drives review/import from Orbit's own rows, never from the temporary picker grant. Without durable session tables, an atomic accept, a single-source-of-truth state-transition table, and non-mutexed row cores first, resume is impossible and the completion summary is uncomputable.
Output: `import_sessions` + `import_session_rows` at v12, a full session write DAO (mutexed writers + non-mutexed cores), a node-tested read chokepoint (raw counts + four summary buckets), and the documented transition table.

Schema (authoritative — additive only, no contacts rebuild):
- `import_sessions`: id, uid UNIQUE, mode CHECK('single','bulk'), status CHECK('pending','complete','discarded') DEFAULT 'pending', batch_category_id → categories(id) (NULL = Uncategorized), batch_tracking_enabled INTEGER DEFAULT 0 (bulk = Unbound), phone_region TEXT (durable effective phone region captured at acceptance for canonical normalization on resume), total_rows, created_at, modified_at.
- `import_session_rows`: id, uid UNIQUE, session_id → import_sessions(id) ON DELETE CASCADE, external_contact_id TEXT (opaque lookup key), source_payload TEXT (JSON: name, methods[], birthday), photo_rel_path TEXT nullable (app-owned DOCUMENT-DIR staged file — never a cache path), row_status CHECK('pending','imported','linked','skipped','failed','needs_review') DEFAULT 'pending', match_outcome TEXT nullable ('already_linked'|'probable'|'possible'|'new'|'needs_review'), matched_contact_id → contacts(id) ON DELETE SET NULL (the single FK-tracked best/recommended candidate), candidates_json TEXT nullable (JSON array of the ordered advisory candidate list from plan 05 — `[{contactId, signals, recommendation}]`; advisory, NOT FK-tracked, so the review UI tolerates a candidate contactId that no longer resolves), contact_id → contacts(id) ON DELETE SET NULL, failure_reason TEXT, photo_failed INTEGER DEFAULT 0 CHECK(0,1), created_at, modified_at, UNIQUE(session_id, external_contact_id).
- Indexes: `idx_import_session_rows_session` ON (session_id, row_status); `idx_import_sessions_status` ON (status).

Why candidates_json AND matched_contact_id both exist (cycle-2 HIGH 2): matched_contact_id is the single FK-tracked recommended contact (nulled if that contact is deleted); candidates_json is the durable full advisory set the review grid/interrupt renders from without re-scoring. Persisting the list keeps the "stored, not recomputed on read" contract while letting a 2+-candidate needs_review row show every candidate after resume.

## Canonical row state-transition table (single source of truth — document verbatim in import-session-dao.ts)
| Event (who fires it) | row_status | match_outcome | contact_id | Writer (single transaction) |
|----------------------|-----------|---------------|-----------|-----------------------------|
| accepted (acquire, plan 04) | pending | NULL | NULL | acceptImportSessionWithRows |
| deterministic already-linked (driver 06 / single-interrupt 07) | skipped | already_linked | NULL (matched_contact_id set) | **resolveAlreadyLinked(Core)** — both columns in ONE UPDATE |
| import as new (importer, plans 06/07/11) | imported | new | set (ATOMIC w/ contact create) | importContactRecord resolveRow / createContactFullCore composition |
| link to existing (user, plans 07/11) | linked | probable\|possible | set (ATOMIC w/ link write) | linkExistingContactToRow |
| ambiguous deferred (driver, plan 06) | needs_review | probable\|possible\|needs_review | NULL (matched_contact_id + candidates_json set) | **deferNeedsReview(Core)** — all columns in ONE UPDATE |
| user Skip (review, plan 07) | skipped | (prior outcome or NULL) — NEVER already_linked | NULL | markRowStatus |
| import failure (driver, plan 06) | failed | (prior) | NULL | markRowStatus |
| photo-only failure (plan 10) | (unchanged: stays imported) | (unchanged) | (unchanged) + photo_failed=1 | markRowPhotoFailed |

The two multi-column transitions (already-linked, ambiguous-deferred) MUST be written by their composed single-transaction writer — never by two sequential single-column mutexed writers, which reopens the crash-window count-miscount (cycle-2 HIGH 1). After the last row on any path resolves, the caller invokes finalizeSessionIfTerminal to complete the session when no pending/needs_review rows remain (cycle-2 HIGH 4).

The four completion-summary buckets derive from this table:
- imported = row_status IN ('imported','linked')  (photo_failed rows stay here — Cluster F)
- alreadyInOrbit = match_outcome='already_linked'
- needReview = row_status='needs_review'
- failedOrSkipped = row_status='failed' OR (row_status='skipped' AND (match_outcome IS NULL OR match_outcome <> 'already_linked'))
