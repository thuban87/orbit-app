<objective>
Ship migration 012 (the durable import-session schema) and the session DAO/read chokepoint that make an accepted picker result survive process death — the load-bearing durability spine for IMP-04.

Purpose: Every later plan drives review/import from Orbit's own rows, never from the temporary picker grant. Without durable session tables first, resume is impossible.
Output: `import_sessions` + `import_session_rows` at v12, a full session write DAO, and a node-tested read chokepoint for resume counts.

Schema (authoritative — additive only, no contacts rebuild):
- `import_sessions`: id, uid UNIQUE, mode CHECK('single','bulk'), status CHECK('pending','complete','discarded') DEFAULT 'pending', batch_category_id → categories(id) (NULL = Uncategorized), batch_tracking_enabled INTEGER DEFAULT 0 (bulk = Unbound), total_rows, created_at, modified_at.
- `import_session_rows`: id, uid UNIQUE, session_id → import_sessions(id) ON DELETE CASCADE, external_contact_id TEXT (opaque lookup key), source_payload TEXT (JSON: name, methods[], birthday), photo_rel_path TEXT nullable (app-owned staged file), row_status CHECK('pending','imported','linked','skipped','failed','needs_review') DEFAULT 'pending', match_outcome TEXT nullable ('already_linked'|'probable'|'possible'|'new'|'needs_review'), matched_contact_id → contacts(id) ON DELETE SET NULL, contact_id → contacts(id) ON DELETE SET NULL, failure_reason TEXT, photo_failed INTEGER DEFAULT 0 CHECK(0,1), created_at, modified_at, UNIQUE(session_id, external_contact_id).
- Indexes: `idx_import_session_rows_session` ON (session_id, row_status); `idx_import_sessions_status` ON (status).
</objective>
