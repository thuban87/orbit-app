<objective>
Close GAP D (IMP-01 regression, device-discovered in the 19-17 UAT attempt): the dashboard is
untouchable everywhere except the Add-contact FAB. Root cause is `AddSpeedDialFab.tsx`: its `scrim`
is an `absoluteFill` `AnimatedPressable` with a hardcoded `pointerEvents="auto"` that is **always
mounted**. The scrim only animates its *opacity* (0 when collapsed) — but in React Native an
opacity-0 view still captures touches — so the invisible full-screen scrim blankets the entire
dashboard, swallowing every touch (firing a no-op `setExpanded(false)`). Only the FAB button, drawn
*after* the scrim in JSX (hence above it in z-order), stays reachable. The two collapsed option
Pressables (Import/Create) sit invisibly over the FAB region and can likewise steal nearby taps.

This is a Phase-19 regression: `AddSpeedDialFab` and its scrim were introduced in `57acb93`
`feat(19-04): add contact import speed dial`, after Phase 15's UAT proved the same dashboard was
tappable on this Pixel. No automated gate caught it — there is no test over the FAB/scrim and the
1,694-test node suite is render-free, so a pointer-blocking overlay is invisible to it. The device
UAT is the only surface that observes it, and it did.

The fix: the scrim (and the collapsed option Pressables) must stop intercepting touches while the
speed dial is collapsed. Since `expanded` is a reanimated shared value that never triggers a
re-render, mirror it into React state and drive `pointerEvents` off that state, through a single pure
helper so the collapsed→"none" invariant is unit-testable render-free (the ContactCard `ringVisual`
idiom the vitest config documents).

Purpose: restore dashboard operability — the import entry point and everything around it — without
weakening the speed dial's expand/collapse behavior.
Output: a pure `speedDialScrimPointerEvents` helper + its render-free test, and `AddSpeedDialFab`
rewired so the scrim/options are inert when collapsed and interactive when expanded.
</objective>
