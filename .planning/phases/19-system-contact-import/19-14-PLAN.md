<objective>
Close GAP C.1 (IMP-04, part of failed verifier truth 4): `use-import-leave-guard.ts:13` decides
whether to discard the session with `rows.some((row) => row.contactId === null)`. Resolved
already-linked and user-skipped rows legitimately carry a null `contact_id`, so this predicate
treats them as unresolved work; on route replacement (e.g. Skip → navigate to ImportComplete) the
guard calls `discardSession`, which marks the session `discarded` and deletes those resolved rows —
destroying the completion-summary evidence and flipping a just-completed session to discarded.

Fix: define "unresolved" by `row_status` — the enum values `pending`, `needs_review`, `failed`
(the exact set `finalizeSessionIfTerminal` uses in import-session-dao.ts:395). The guard discards
ONLY when at least one such row exists. When every row is resolved (`imported`, `linked`,
`skipped`), the guard does nothing, the session stays intact, and `finalizeSessionIfTerminal`
completes it with correct counts.

Purpose: Restore the durable/resumable completion contract — a finished single/bulk review keeps
its resolved skips and links and reports the right summary.
Output: A pure, node-tested unresolved-rows predicate wired into the leave guard.

**Why this needs no DAO change:** with the corrected predicate, the guard returns early on an
all-resolved session, so `discardSession` is never called there and the resolved rows are never
deleted. `discardSession` still runs (unchanged) only when unresolved work is genuinely being
abandoned; there its existing behavior is correct.
</objective>
