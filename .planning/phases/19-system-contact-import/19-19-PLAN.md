<objective>
Close GAP E (IMP-01 launch blocker, device-discovered in the 19-17 UAT): the Phase-19 import picker
does not launch from the app on the real Android 17 Pixel. The native module
(`OrbitContactPickerModule`) fires `android.provider.action.PICK_CONTACTS`; the device's system picker
`com.android.contactspicker/.ContactsPickerActivity` exists and handles that action (and classic
`android.intent.action.PICK` with `vnd.android.cursor.dir/contact`), and `am start` from shell launches
it — but the APP's `startActivityForResult` falls through to `com.android.intentresolver`'s
"No apps can perform this action."

Root cause: **Android 11+ package-visibility filtering.** orbit (targetSdk 36) declares `<queries>`
for VIEW/SEND/OPEN_DOCUMENT/GET_CONTENT/etc. but NOT for any contact-pick intent, and no
`QUERY_ALL_PACKAGES`. So `com.android.contactspicker` is invisible to the app and the intent resolves
to nothing. Shell (`am start`) is exempt from visibility filtering, which is why it launches and the
app does not — the classic shell-works/app-fails signature. 19-12 corrected the picker ACTION but not
the visibility declaration the app needs to see the picker.

The fix: add a `<queries>` block to the local picker module's (currently empty) AndroidManifest.xml —
the idiomatic, co-located place, since this module is what launches the picker. It merges into the app
manifest at build. Scope the query to the contact-pick intent(s) only; do NOT add READ_CONTACTS or
QUERY_ALL_PACKAGES (the module's whole design is permissionless snapshotting).

Purpose: make the system contact picker reachable from the app so the entire Phase-19 import feature
is operable on-device.
Output: a merged `<queries>` declaration; a rebuilt debug APK on which the app launches the real
ContactsPickerActivity. This is a NATIVE change → requires `expo prebuild --clean` + `assembleDebug`
on droid + reinstall (not a JS fast-refresh).
</objective>
