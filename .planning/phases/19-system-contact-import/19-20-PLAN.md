# Gap Plan 19-20 — Android-17 picker intent fix

## Why (root cause, verified on-device)

Full analysis: `19-ANDROID17-PICKER-ROOTCAUSE.md`. In short:

- The Android-17 system picker `com.android.contactspicker/.ContactsPickerActivity` is a
  **router**. On launch it runs `ContactsViewModel.handleIntent(action, type, extras, callingPkg)`;
  if that returns true it renders its own Compose picker UI, otherwise it forwards the intent to a
  user "preferred" activity — and when none exists it builds a chooser that **excludes itself**,
  yielding an empty chooser ("No PreferredActivity Found" → "No apps can perform this action").
- Disassembly (`dexdump` of the pulled system APK) + a faithful on-device repro (driving orbit's
  real import; the forward fires ~7 ms in, before the ViewModel logs anything) showed `handleIntent`
  was returning false because orbit set the "use the system picker" flag under the **wrong namespace**:
  `android.provider.extra.USE_SYSTEM_CONTACTS_PICKER`, while the trampoline reads
  `android.intent.extra.USE_SYSTEM_CONTACTS_PICKER`. The flag defaulted to false → forward → dead end.
- Device-state remediations are proven dead: `pm clear com.android.contactspicker` (tested, no change);
  no other `PICK_CONTACTS` handler exists to set as a default; multi-user/profile is irrelevant.
  An OS update is **not** required.

## Change

`OrbitContactPickerModule.kt`:
1. `EXTRA_USE_SYSTEM_CONTACTS_PICKER` → `android.intent.extra.USE_SYSTEM_CONTACTS_PICKER` (the fix).
2. On the multi-select path, set `android.provider.extra.PICK_CONTACTS_SELECTION_LIMIT = 100`
   (defensive hardening; the trampoline's undocumented default of 50 was already valid).

No new permission, no `READ_CONTACTS`, no `QUERY_ALL_PACKAGES` — the permissionless-snapshot design
(HANDOFF / Phase-19) is preserved. Native change: requires `expo prebuild` + `assembleDebug`.

Complementary to — not a substitute for — Phase 19.1 (ADR-002 older-Android `ACTION_PICK` path).

## Verification (all satisfied)

- **Build**: `assembleDebug` on `droid` → BUILD SUCCESSFUL.
- **On-device (Pixel 6, raven/17)**: after `install -r`, drove orbit's real "Import from Contacts":
  top activity became `ContactsPickerActivity` (its own UI, not the intentresolver chooser); the
  native multi-select picker rendered with checkboxes, Search, Favorites, real contacts, and the
  privacy banner "Orbit will only have access to info from the contacts you select". No dead-end.
- **Regression gate**: `npm test` (vitest) green; native-only change, no TS touched.
