# Phase 19 — System Contact Import — UI Design Contract

> Visual and interaction contract for Phase 19's net-new import surfaces. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker. This app is a mature React Native / Expo,
> Android-first, portrait-locked application (18 phases shipped). This spec fits the EXISTING
> `src/theme` token system and reuses shipped `src/components` / `src/screens` patterns — it invents
> no new design system. Every value below was read out of shipped code, not assumed.

---

## Scope of this contract

Phase 19's net-new user-facing surfaces (numbered per the orchestrator scope brief):

1. Entry points — a multi-option Add affordance on the dashboard, plus a "Contacts Integration" Settings section.
2. Single-contact import-review screen (reviewed before any write).
3. Bulk import setup (shared batch defaults; batch category override; **no** per-person checkbox list).
4. Bulk duplicate-review **card-grid workspace** — designed as a **reusable contract** (Phase 20 reuses it).
5. Confidence-ladder presentation (advisory outcomes; **no raw numeric scores**).
6. Single duplicate-resolution interrupt.
7. Chunked large-import progress screen.
8. Import completion summary/report screen (bridges to the Unbound-contacts screen).
9. Resume / Discard prompt for a durable resumable session.
10. Unsupported-platform state.

## ⚠ Code-grounded corrections the planner must honor

1. **There is no multi-option FAB today.** `HomeScreen.tsx` (lines 652–663) renders a **single** `+` FAB whose `onPress` is `navigation.navigate("Create")` — it goes straight to create with no menu. Dossier Cluster A's phrasing "the dashboard already uses a multi-option FAB" is **not** true against shipped code. Phase 19 therefore **adds** the multi-option behavior: tapping `+` opens a small action sheet (`Create manually` / `Import from Contacts`) rather than navigating directly. Reuse `OverflowMenu`'s Modal-sheet-over-scrim treatment; do not add a new FAB library.
2. **No central spacing or typography token module exists.** Spacing and font sizes are inline per-`StyleSheet`. The scales below are the **de-facto shipped** values distilled from real screens — match them; do not introduce a divergent scale.
3. **No dedicated "caution/warning" colour token exists.** `rogue` (amber) and `statusWobble` (gold) are *orbit-status* tokens, `danger` (red) is *destructive-action only*. The confidence ladder must NOT borrow any of these to color-code match outcomes (that would conflate identity confidence with orbit status / destruction). See Color + Confidence Ladder below.

## Spacing Scale

De-facto scale distilled from shipped screens (`HomeScreen`, `ContactCard`, `UnboundContactsScreen`, `CreateContactScreen`). Canonical steps are multiples of 4; the shipped exceptions are documented, not to be "cleaned up" this phase.

| Token (conceptual) | Value | Usage (as shipped) |
|-------|-------|-------|
| xs | 4px | Micro gaps in a text stack (`rowText` gap, trailing gap) |
| sm | 8px | Compact control/list gaps (`sortControl` gap, list `gap: 8`) |
| md | 12px | Card/row inner padding, avatar↔text gap (`card padding: 12`, `gap: 12`) |
| lg | 16px | Screen padding, section spacing (`root padding: 16`, `content padding: 16`) |
| xl | 24px | Screen title size / large section breaks / empty-state top margin (`marginTop: 24`) |
| 2xl | 32px | Reserved for major layout breaks (FAB glyph size) |

**Documented shipped exceptions (allowed, do not refactor):** `2` (name↔fuel micro gap), `10` (dashboard list row gap, card/input `borderRadius`), `14` (footer/row vertical padding, sheet-option padding), `28` (FAB bottom offset / circular radius). Corner radius convention: **10** on cards/inputs/chips/rows, **12** on modal sheets, circular for the FAB/avatars.

**Touch targets:** every interactive element is **≥44px** in the tapped dimension (`minHeight: 44` / `minWidth: 44`). This is non-negotiable and already universal in shipped code — the card grid's cards, bulk-action buttons, and resume/discard buttons all inherit it.

## Color

All values are `space-dark` dark-palette tokens (`theme-presets.ts`). Consume via `useTheme().colors.*`. **Never** write a hex literal in a screen/component/Skia call (`check:colors` gate + CLAUDE.md).

| Role | Token → value | Usage |
|------|---------------|-------|
| Dominant (60%) | `background` `#0B0E1A` | Screen roots, FAB glyph-on-accent text, active-segment label text |
| Secondary (30%) | `surface` `#141828`, `surfaceElevated` `#1D2235` | Cards, rows, inputs, picker shells (`surface`); modal sheets + category chips (`surfaceElevated`) |
| Accent (10%) | `accent` `#6C8CFF` | See reserved list below |
| Destructive | `danger` `#E5484D` | Destructive-action emphasis ONLY (see Copywriting: Discard) |
| Borders | `border` `#2A3048`, `borderStrong` `#3C4568` | Default 1px borders; `borderStrong` on active/selected outlines |
| Text | `textPrimary` `#E6E9F5`, `textSecondary` `#8B93B0` | Primary content; labels/helpers/secondary lines |

**Accent (`#6C8CFF`) is reserved for, and ONLY for:**
- primary CTA fills (`Import`, `Resume import`, `Link to Existing` when it is the recommended primary, `Done`),
- the selected/active state of a `SegmentedControl` or choice-pair (e.g. Bound/Unbound, batch category chip),
- the favourite star (existing `★`),
- pressed-state link text (`Your week` / `Backup`-style text links),
- the pull-to-refresh / progress spinner tint.

Accent is **never** applied to every interactive element, never to advisory/ambiguous match outcomes, and never to the overflow `⋯` trigger.

**Confidence-ladder colour rule (locked):** match outcomes are **advisory**, not identity or destruction, so they are rendered **without a semantic hue** — a `surfaceElevated` chip with a leading `13px/600 textSecondary` outcome word (see Confidence Ladder). Do NOT color-code outcomes with `danger`, `rogue`, `statusWobble`, or `accent`. If the owner later wants a caution hue for "Manual review required", that is a **new token addition** and an owner decision — flag it, do not inline a hex.

## Confidence Ladder — user-facing presentation (Cluster H)

Five outcomes map from the internal weighted evidence model. **Raw scores are never shown.** Each outcome renders as a labeled chip (`surfaceElevated` bg, `textSecondary` label, radius 10) plus an advisory recommendation line (`15px/400 textSecondary`). Colour carries no outcome meaning.

| Internal outcome | User-facing label | Advisory recommendation copy | Default action offered |
|------------------|-------------------|------------------------------|------------------------|
| deterministic / already linked | `Already in Orbit` | "Already linked to this contact." | (skip in bulk; not offered as new) |
| probable match | `Probable match` | "Looks like someone you already have." | Recommend **Link to Existing** |
| possible match | `Possible match` | "Might be someone you already have." | Recommend **Review** (no auto-pick) |
| no meaningful match | `New person` | "No match found — import as new." | Recommend **Import as New** |
| manual review required | `Needs review` | "Needs a closer look before linking." | **Manual Review Required** (never auto-accepted in bulk) |

Locked behavior: recommendations are advisory (never an automatic identity decision); `Needs review` candidates are **excluded** from any "apply recommendation in bulk" action.

## Screen-by-screen interaction contract

### 1. Entry points
- **Dashboard `+`:** tapping opens an action sheet (OverflowMenu idiom) with two rows: `Create manually` → `Create` route; `Import from Contacts` → import entry. (Replaces today's direct-to-Create navigation.)
- **Settings:** add a `Contacts Integration` section (reuse `settings.section` / `sectionHeading` idiom, `13px/600 textSecondary` heading) with one row now: `Import contacts`. Phase 20 maintenance rows land in this same section later — leave room, add nothing else this phase.

### 2. Single-contact import-review screen
- Header idiom (Back + `24px/600` title "Import contact"). Reuses the create-form field stack **verbatim in order**: name (editable; required if source lacks a usable name — Cluster O), Orbit participation (Bound/Unbound choice-pair), Category (Picker; defaults to Uncategorized), Frequency (`FrequencyPicker`, shown only when Bound), method selection + primary (`ContactMethodsEditor`), birthday, photo preview.
- Primary CTA: `Import` (accent fill). Nothing is written until this tap (Cluster D).
- If a strong single candidate exists, this screen defers to the duplicate interrupt (#6) before create.

### 3. Bulk import setup
- After the system picker returns N selections, show a lightweight setup — **not** a per-person list. Show: selection count ("N contacts selected"), the two locked defaults as read-only affordances (`Unbound`, `Uncategorized`), and a single batch **Category override** control (Picker or a chip set in the accent-selected idiom). One primary CTA: `Import N contacts`.
- Explicitly **no** per-person checkbox/exclusion list (Cluster E).

### 4. Bulk duplicate-review card grid (REUSABLE — Phase 20 too)
- `FlatList numColumns={2}`, single portrait column of pairs. Each candidate **card**: `Avatar` + name (`15px`) + the confidence-ladder chip + a one-line evidence hint (`13px textSecondary`). Card is `surface` bg, `border`, radius 10, `≥44` tap height.
- **Tap** a card → detail inspector (candidate + its Orbit match evidence, still no raw score). **Long-press** → enter multi-select mode (selected cards get a `borderStrong`/accent outline, matching the shipped selected-idiom). In multi-select, a bottom action bar offers `Link to Existing`, `Import as New`, `Skip`, and `Apply recommendation` (the last excludes `Needs review` cards).
- Ambiguous candidates never block: safe imports proceed; unresolved cards remain in the grid.
- Build as a standalone component with a generic item/action contract so Phase 20's reconciliation reuses it unchanged.

### 5. (covered by Confidence Ladder above)

### 6. Single duplicate-resolution interrupt
- One strong candidate: a focused card showing incoming vs. existing, two buttons — `Link to Existing` (recommended → accent), `Import as New` (secondary → `surface`/`border`).
- Multiple credible candidates: list the candidate cards; actions `Choose this one` (per card), `Import as New`, `Skip`. Orbit does not pre-pick (Cluster I).

### 7. Chunked large-import progress screen
- One logical import with overall progress. A determinate progress line/bar (accent tint) + `"Importing… X of N"` (`15px`), plus an incremental sub-status ("Photos may finish after contacts"). No spinner-only screen. Never expose chunk internals as separate imports (Cluster S).

### 8. Import completion summary
- Header "Import complete". Four count rows (reuse `footerEntry` idiom): `Imported (n)`, `Already in Orbit (n)`, `Need review (n)`, `Failed / skipped (n)`. Actions: `Review possible matches` (→ card grid, shown only when need-review > 0), `View Unbound contacts` (→ `UnboundContacts` route — the locked bridge), `Done` (accent). 

### 9. Resume / Discard prompt
- On app return with a durable pending session, present a non-dismissable-by-tap-outside prompt (Modal sheet idiom): heading "Resume your import?", body explaining unresolved items are saved. Buttons: `Resume import` (accent), `Discard import` (**danger** — this discards pending review state; already-committed contacts stay committed, state this in the body).

### 10. Unsupported-platform state
- Where import would launch, show the calm empty/disabled state: heading `Contact import unavailable`, body `Contact import requires Android 17 or later.` (verbatim, Cluster B). The rest of Orbit stays fully usable; do not disable the Add flow's `Create manually` row.

## Open dependencies for the owner (NOT resolved here)

These are recorded, not decided — surfacing per the orchestrator brief. They are owner-bucket calls (risk/scope/product), not researcher calls.

1. **iOS picker scope conflict (unresolved, do not design around it).** Dossier 19 Cluster B has a `[DECIDED]` "iOS uses the native privacy-preserving contact picker" line, but PROJECT.md / REQUIREMENTS.md line 200 / HANDOFF §11 defer iOS for v1, and the ROADMAP makes no scope choice. **This spec designs Android-first only.** No iOS-specific screen is specified. The only place iOS would materially change this contract is the entry-point/picker wrapper and the unsupported-state copy; if the owner rules iOS in-scope, the entry points (#1) and unsupported state (#10) need an iOS variant. **Owner decision required before planning finalizes the picker layer.**
2. **Multi-option FAB introduction.** Adding the Add-menu changes a shipped interaction (the `+` FAB currently goes straight to Create). This is a small UX change but it alters existing behavior — confirm the action-sheet approach (vs. a speed-dial FAB) is acceptable. Recommended: the OverflowMenu Modal-sheet idiom (already in the app), not a new FAB animation library.
3. **Caution hue for "Needs review".** The advisory ladder deliberately uses no semantic colour. If the owner wants "Needs review" visually distinguished by hue, that is a new theme token (owner-tunable seed like `rogue`/`statusWobble`), not an inline colour — a token addition to `theme-presets.ts`.
