# Phase 9 — UI Design Contract

> Visual and interaction contract for the Compose Screen & SMS Handoff (CMP-01/02/03).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This phase adds NO new visual language.** The compose screen must read as native
> to an app with 8 shipped phases. Every value below is lifted from the existing
> `src/theme/` tokens and the shipped screens (`ContactProfileScreen`,
> `ArchivedContactsScreen`, `FuelEditor`, `RankedFuelLine`). Reuse verbatim; invent
> nothing. All colours resolve through `useTheme().colors.*` — `check:colors`-gated,
> zero hex literals outside `src/theme/theme-presets.ts`.

## Spacing Scale

The shipped system is **4px-based with a few 2px-granular exceptions that already
exist in production**. Reuse these exact values — do not "normalise" 10/14 to the
nearest 8-multiple (that would silently restyle every shipped screen).

| Token | Value | Usage (as shipped) |
|-------|-------|--------------------|
| xs | 4px | Pill/helper gaps (`offLimits` gap) |
| sm | 8px | Section inner gap, action-row gap, count/emptyState gap |
| — | 10px | Row internal gap, input vertical padding (**shipped exception, keep**) |
| md | 12px | Card/row padding, header gap, button/refine gap, kind-trigger padding |
| — | 14px | Back-button horizontal padding (**shipped exception, keep**) |
| lg | 16px | Screen padding (`content`), screen-level section gap, sheet option padding |
| — | 20px | Draft/secondary button horizontal padding (**shipped exception, keep**) |
| xl | 24px | Screen title / avatar-glyph size, modal horizontal inset |

**Border radius tokens (shipped):** 8px (buttons/inputs), 10px (cards/rows/strips), 12px (panels/sheets), 999px (pills).
**Touch-target minimum:** `minHeight: 44` (and `minWidth: 44` for icon-only) on every Pressable — a hard, shipped invariant. Applies to Send, Copy, Back, and the add-number affordance.

Exceptions: the 10/14/20 values above are pre-existing in shipped screens and are the contract, not deviations. No new spacing values are introduced this phase.

## Typography

The shipped system uses **three weights (400 / 600 / 700)**, not two. This is a
deliberate, 8-phase-consistent decision recorded across every screen. The template's
"2 weights max" guideline is **superseded by the shipped design system** — reducing
to two weights would reverse a recorded decision and is an owner taste call, not a
researcher/executor call. Declared as-shipped:

| Role | Size | Weight | Line Height | Where (shipped precedent) |
|------|------|--------|-------------|---------------------------|
| Display / screen title | 24px | 700 | default | Contact name in header (`title`) |
| Body / input text | 15px | 400 | ~21px (1.4) | Draft `TextInput`, read-only fuel text, `RankedFuelLine`, inputs |
| Primary button label | 16px | 700 | default | "Send" / "Log contact" (`logContactText`) |
| Secondary / link label | 16px | 600 | default | "Copy", "Add a phone number" (`addDetailsText` idiom) |
| Section heading | 13px | 700 | default, `textTransform: uppercase`, `letterSpacing: 0.5` | "YOUR MESSAGE" / "CONVERSATIONAL FUEL" (`sectionHeading`) |
| Meta / helper / kind label | 13px | 600 | ~18px (1.38) | Fuel age, kind label, no-phone helper (`age`/`helper`/`pillText`) |

Weights: `"400"` (body/reading), `"600"` (labels, secondary actions, meta emphasis), `"700"` (titles, primary CTAs, section headings). No italics. No custom letter-spacing except the section-heading `0.5`.

| Secondary (30%) | `surface` | `#141828` | Draft input, read-only fuel cards, disabled-button fill |
| Elevated | `surfaceElevated` | `#1D2235` | (Reserved — modals/sheets; not required this phase) |
| Accent (10%) | `accent` | `#6C8CFF` | **See reserved-for list below** |
| Text primary | `textPrimary` | `#E6E9F5` | Draft text, fuel text, contact name |
| Text secondary | `textSecondary` | `#8B93B0` | Section headings, meta, helper copy, Back label, placeholder, disabled labels |
| Border | `border` | `#2A3048` | Input/card/Back-button outlines |
| Border strong | `borderStrong` | `#3C4568` | (Reserved — emphasis outline; not required this phase) |
| Destructive | `danger` | `#E5484D` | **Not used this phase** — compose has no destructive action |

**Accent (`#6C8CFF`) reserved for — explicit list, nothing else:**
1. The **Send** button fill (filled-accent primary: `backgroundColor: accent`, label `background`, when a phone number + SMS capability exist).
2. The **Copy** button (accent-outline secondary: `borderColor: accent`, label `accent` — the "Restore" idiom).
3. The **"Add a phone number"** affordance (accent text-link — the "Add details" idiom).
4. The **"Message"** entry button added to `ContactProfileScreen` (filled-accent primary).
5. The transient **"Copied"** confirmation label (accent, ~2s), see Interaction States.

Accent is NOT applied to body text, fuel text, section headings, the read-only fuel cards, or the Back control.

## Screen Layout — `ComposeScreen`

Root: `ScrollView`, `backgroundColor: colors.background`, `contentContainerStyle: { padding: 16, gap: 16 }` — identical to `ContactProfileScreen`/`ArchivedContactsScreen`. `headerShown: false` (each screen owns its Back chrome, shipped since 04-01). testID `compose-screen`.

Top-to-bottom order:

1. **Header row** (`flexDirection: row, alignItems: center, gap: 12`)
   - **Back** pill — `border` outline, radius 8, `paddingH 14 / paddingV 8`, label `textSecondary` "Back". testID `compose-back`, `accessibilityLabel: "Back"`. **Semantics differ from a normal Back:** it navigates to the **dashboard (Home)**, never a stack pop to the profile (CMP-02). Android system Back must do the same — override to route Home (navigation reset or `navigate("Home")`; mechanism is Claude's discretion per CONTEXT).
   - **Avatar** — reuse `Avatar` with `contactId` + `cacheBust={modified_at}` + `size={64}` (recyclingKey correctness, not decoration).
   - **Contact name** — `flex: 1`, 24/700, `textPrimary`. testID `compose-name`.

2. **Fuel reference section** — heading + read-only full-fuel list. Placed **above** the draft so the talking points are visible while composing ("fuel visible → send", HANDOFF §6). testID `compose-fuel`.
   - Heading: "CONVERSATIONAL FUEL" (13/700 uppercase, `letterSpacing 0.5`, `textSecondary`) — the shipped `sectionHeading`.
   - Read-only list: **all fuel kinds EXCEPT `off_limits`**, `off_limits` excluded **in-query** (never fetched, never rendered — the never-transmitted invariant, HANDOFF §14 / FUEL-02). Reuse/extend `getRankedFuel`'s in-query exclusion per CONTEXT; a new "full fuel minus off_limits" projection is acceptable.
   - Each item = a **read-only card** mirroring `FuelEditor`'s row chrome (`surface` bg, `border`, radius 10, padding 12, gap 10) but with **static `Text`, no `TextInput`, no edit/delete/confirm affordances**: a kind label (13/600 `textSecondary`, human copy "Recent"/"Topic"/"Fact"/"Gift idea"), the fuel `text` (15/400 `textPrimary`), the optional `label` (13/600 `textSecondary`) when present, and the age via the shipped `formatFuelAge(created_at, now)` (13/600 `textSecondary`). testID `compose-fuel-item-{index}`.
   - Editing fuel is **not** offered here (stays on the profile `FuelEditor`).

3. **Draft section** — heading + editable message field. testID `compose-draft`.
   - Heading: "YOUR MESSAGE" (`sectionHeading` idiom).
   - Multiline `TextInput`, **opens blank** (no template, no persistence, no greeting — CONTEXT): `surface` bg, `border`, radius 8, `paddingH 12 / paddingV 10`, 15/400 `textPrimary`, `lineHeight ~21`, `multiline`, generous `minHeight` (≥120px so several lines are visible without scrolling; larger than `FuelEditor`'s 44 multiline min). Placeholder "Write your message…" in `textSecondary`. testID `compose-draft-input`.

4. **Action row** (`flexDirection: row, gap: 12, justifyContent: flex-end` — the shipped `draftActions`/`refineActions` idiom). Contents depend on phone/SMS capability — see the state matrix.

5. **Reserved AI-Suggest slot (Phase 14)** — leave layout room directly above the draft or in the action row for a future "AI Suggest" control. **Do not build it this phase**; note the slot so Phase 14 slots in without a re-layout (CONTEXT deferred).

### Entry point — `ContactProfileScreen` "Message" button (CMP-02, decision #4)

Add a **"Message"** button to the profile's primary action stack, rendered **directly above "Log contact"**. Filled-accent primary (the "Log contact" idiom: `backgroundColor: accent`, `borderColor: accent`, radius 8, `minHeight 44`, padding 12, label 16/700 `background`). testID `contact-profile-message`, `accessibilityLabel: "Message {name}"`, `onPress: navigation.navigate("Compose", { contactId })`.

> Owner taste note (flagged, not decided here): this places **two** filled-accent primary buttons ("Message" and "Log contact") in the same stack. Both are legitimately primary paths. If the owner wants explicit hierarchy between them, demoting one to an accent-outline is a visual/taste call — do not change `Log contact`'s shipped styling without owner direction.

## Interaction States — Send / Copy capability matrix

`contacts.phone` is the number source (via `getContactHeader`/`getContactForEdit`). Device SMS capability comes from `expo-sms` `isAvailableAsync()`. **Neither Send nor Copy ever sends silently; neither needs `SEND_SMS`.**

| Condition | Send control | Copy control | Add-number affordance |
|-----------|--------------|--------------|-----------------------|
| **Phone present AND SMS available** | **Shown, filled-accent primary.** Label "Send". `expo-sms.sendSMSAsync(phone, draft)` opens the default SMS app pre-filled. testID `compose-send`. | **Shown, accent-outline secondary.** Label "Copy". `expo-clipboard.setStringAsync(draft)`. testID `compose-copy`. | Hidden |
| **No phone number** (CMP-03) | **Hidden** (not a dead disabled control — the add-number affordance takes its place, so the surface never shows an inert primary). | **Shown, promoted to filled-accent primary** (Copy is the guaranteed handoff; with Send gone it becomes the sole primary). | **Shown** — accent text-link "Add a phone number" → `navigation.navigate("Edit", { contactId })` (the "Add details" route/idiom). testID `compose-add-number`. |
| **Phone present BUT SMS unavailable on device** (e.g. no telephony) | **Hidden**, with a `textSecondary` helper "This device can't send texts — copy your message instead." | Shown, promoted to filled-accent primary. | Hidden |

> Send-vs-hidden decision (CONTEXT grants this to Claude's discretion): **hide** Send when it cannot function, rather than disable-with-hint. Rationale — the no-phone case is resolved by a concrete next step (add-number affordance) and the SMS-unavailable case by a one-line helper, so a permanently-inert accent button is never worth the visual weight. Copy is always present and always works, preserving the guaranteed handoff on every branch.

### Copy feedback
On a successful `setStringAsync`, show a transient **"Copied"** confirmation for ~2s (accent, inline beside the Copy button or replacing its label), then revert. Toggle via a single `setState` + `setTimeout` — **not** a per-frame animation (CLAUDE.md: never drive animation from React state). testID `compose-copied`. No blocking `Alert` on success.

### Send behaviour
`sendSMSAsync` opens the composer and returns `{ result: "sent" | "cancelled" | "unknown" }`. On Android the result is effectively **`unknown`** — the app cannot know whether the text was actually sent (this is exactly why Copy is the guaranteed handoff). **Do not** render a "Message sent!" confirmation or write any interaction/log row from a Send. Compose **never marks a contact contacted** (logging stays a separate, explicit profile action).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Entry button (profile) | **Message** |
| Primary CTA — send | **Send** |
| Secondary CTA — copy | **Copy** |
| Copy success (transient) | **Copied** |
| Draft placeholder | **Write your message…** |
| Draft section heading | **YOUR MESSAGE** |
| Fuel section heading | **CONVERSATIONAL FUEL** |
| Fuel empty state (contact has no non-`off_limits` fuel) | **No fuel yet.** (secondary line, when helpful) *Add some on their profile.* — 13/600 `textSecondary`, mirrors `FuelEditor`'s "No fuel yet". testID `compose-fuel-empty`. |
| No-phone affordance | **Add a phone number** (accent link) |
| SMS-unavailable helper | **This device can't send texts — copy your message instead.** |
| Load error | **Couldn't load this contact** / *Please go back and retry.* (native `Alert`, shipped idiom) |
| Copy error | **Couldn't copy** / *Please try again.* (native `Alert`) |
| Send-launch error (composer failed to open) | **Couldn't open your messages app** / *Your message is ready to copy instead.* (native `Alert`; Copy remains available) |

**Destructive confirmation:** none. This phase has **no destructive action** — no delete, no irreversible write. Compose only reads fuel, edits an in-memory draft, and hands off. `danger` token is unused here.
