<objective>
Build the single, entry-agnostic compose surface and wire the profile entry into it — the complete
vertical slice that lets a user go profile → Message → see fuel + type a draft → Send or Copy → Back
to the dashboard. This delivers CMP-01/02/03 end-to-end for the profile entry point and leaves the
screen self-fetching on `{ contactId }` alone so Phases 11/12/14 can open it with just a contact id.

Purpose: This is the "compose screen is one surface, built once" cross-phase commitment (ROADMAP
constraint). Fuel is visible here — not in notification text — and Copy is the guaranteed handoff
while Send is best-effort. The access-control invariant (off_limits + unconfirmed AI never on a
transmittable surface) is load-bearing and structural.

Output: `src/screens/ComposeScreen.tsx`, the additively-registered `Compose` route, and the profile
"Message" button.
</objective>

<phase_goal>
**As a** user who is overdue with someone, **I want to** open one screen that shows me what to talk
about and lets me fire off a text — or copy it — in a tap, **so that** the gap between "you're
overdue with X" and the message actually being sent collapses.

After this plan a real user can do exactly that from a contact's profile.
</phase_goal>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (compose UI) → OS SMS app | The draft body + recipient cross into the OS default SMS app via an Android `ACTION_SENDTO` intent (expo-sms). Untrusted-to-trusted handoff — user-visible, never silent. |
| client (compose UI) → OS clipboard | The draft crosses into the system clipboard via expo-clipboard. |
| SQLite → compose UI (read) | Fuel + header (incl. phone) read into a transmittable surface. This is the access-control boundary: private rows must never cross it. No network on this read path. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-01 | Information disclosure | ComposeScreen fuel read | high | mitigate | off_limits AND unconfirmed source='ai' fuel NEVER reach the compose surface — structurally via `getRankedFuel`'s in-query `RANKED_FUEL_EXCLUSIONS` (kind != 'off_limits' AND source != 'ai' AND non-blank).
