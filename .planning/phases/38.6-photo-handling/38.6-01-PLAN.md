<objective>
Prove on the real phone that a changed photo shows everywhere without renaming any file (D-01, D-19, D-21). Build the thinnest production path: the ownership layer publishes a display revision when it writes a photo's bytes, and `Avatar` renders the canonical photo through a display source that carries that revision, with an in-memory-only image cache. Then drive the Pixel 3a to replace a contact's photo twice and confirm the Profile, Contacts List and Contacts Grid follow, before and after a restart.

Purpose: the stale photo is an image-cache bug, not a data bug. expo-image on Android turns a `file://` source into a raw model before it reads `cacheKey` (`node_modules/expo-image/android/.../records/SourceMap.kt:133-135`), and each contact's photo is overwritten at the same path. The owner ruled (D-21) that filenames stay identity-derived (38.2 D-09 / ADR-021 / ADR-158), so the fix must change the URI, not the name, and it relies on Glide internals that only a device can confirm (research Pitfall 1, assumption A1).

Output: the display-revision primitives, the rewired `Avatar`, a reusable screenshot probe, and `38.6-SPIKE.md` naming the strategy 38.6-03 builds on.
</objective>

## Owner stop (only if both strategies fail in Task 2)

Return this as a checkpoint:decision with gate blocking-human. Never default it.

- **Decision:** how to make a changed photo show everywhere, now that neither URI-level fix works on the device.
- **Context:** both filename-preserving fixes failed on the Pixel 3a (evidence in `38.6-SPIKE.md`). The remaining known fix is a new filename per photo write. That reverses 38.2 D-09 ("no filename-policy change … any plan that needs a different naming scheme stops and asks"), ADR-021's rejected alternative "random per-file names" and ADR-158's rejected "change to random photo filenames", and D-21. The half that dies is "identity-derived canonical filenames", which today let purge and definition-delete derive a deleted row's photo path. Choosing it means a replan of the photo path helpers, restore canonical and pending names, the staging-session matcher, merge destination checks and purge/definition-delete derivation.
- **Options:**
  - (a) Approve versioned filenames per write (amend 38.2 D-09 / D-21) — fixes D-01; large replan of the ownership layer.
  - (b) Keep filenames; try explicit global image-cache eviction after every write (expo-image `Image.clearMemoryCache()`), accepting a brief reload of every visible image — no naming change; unproven.
  - (c) Keep filenames and accept stale photos until a restart — D-01 stays unmet.
