# Phase 38.6 Plan 09: More Photo Surfaces (D-25 F-1..F-3) Summary

Three surfaces that ask the user to pick or confirm an existing Orbit contact now show that contact's photo, or initials when it has none, through `Avatar`:

- **Import duplicate choices (F-1):** Duplicate review's "Choose an existing contact" sheet, and Import review's "We found someone who might already be in Orbit." choices.
- **Home assist banner (F-2).**
- **Update from Contacts (F-3):** the "keep Orbit photo" option is now a 96 photo card beside the phone's "Contacts photo" card.

Every photo is the stored RELATIVE path from a read the screen already made, so the plan adds no SQL. F-4, F-5 and the reconcile header are unchanged.

## What was built

- **Task 1 (tracer, TDD), RED `43e41a6` then GREEN `a30c18b`:**
  - `resolveExistingContactChoices` is pure. It takes the candidates and a header reader, reads every header concurrently, drops any contact that no longer exists, and returns the candidate fields plus `name` and `photo`, in input order.
  - `DuplicateReviewScreen.choicesForRow` and `ImportReviewScreen.onImport` both call it with `getContactHeader`.
  - `ExistingContactChoiceSheet` is the old Duplicate review `Modal`, moved into the new component. Each choice is now a row: Avatar 40 first, then the name and hint. Its label is "<name>, <hint>", and it is disabled while writing.
  - `LinkExistingChoiceButton` is the old Import review choice, moved into the new component. It keeps the same accent/surface fill and the same `onAccent`/`textPrimary`/`textSecondary` text. It gains the Avatar, `accessibilityRole="button"` and the label "<primary>, <name>".
  - Import as New, Skip, the title and `styles.duplicateChoice` stay in the screen.
  - `CandidateChoice.photoUri` was never set by anything. It is replaced by `photo`. `CandidateItem.photoUri` is a different field and is unchanged.
  - Tracer gate: the task's full verify command was re-run and passed before Task 2. The plan is autonomous, so there was no human-verify stop.
- **Task 2 (TDD), RED `9a69486` then GREEN `f3dfba2`:**
  - `AssistBanner`: a `questionRow` holds Avatar 40 (`newest.contact_photo`, `contact_name`, `contact_id`), then the question. The question keeps `numberOfLines={1}` and gains `flex: 1`. The hooks, the early return, the M56 pending-count block, `AssistConfirmation`, the root props and the root/banner styles are all unchanged. That includes the existing root `elevation`, which this plan did not touch.
  - `PhotoChoice`: the keep Pressable is built once as `keepOption`:
    - With `keepPhoto`, it renders after the option cards inside the ScrollView. It uses the 124 `styles.option` card, Avatar 96, a text with `numberOfLines={3}`, and the label "<label>: No meaningful change — keep Orbit photo".
    - Without `keepPhoto`, it renders below the ScrollView exactly as before.
    - The M47/M48 blocks are verbatim.
  - `ReconcileDetailScreen`: `ScanState.orbitPhoto` comes from the existing contact read (`contact.photo`). It is passed as `keepPhoto={{ photo: scan.orbitPhoto, name: scan.contactName, contactId }}`. The header, the missing-source branch and M26 are untouched.
  - Source checks in `photo-surfaces-render.test.tsx` pin two things: the Reconcile wiring, and that `MergeConflictsScreen` has no `keepPhoto`.
