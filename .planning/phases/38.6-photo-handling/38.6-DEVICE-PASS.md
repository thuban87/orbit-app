**Mechanism (from the code and the two measurements).** The settled excess is not Skia texture size: at +70 s both sets are within the limit (Graphics +2.4 %, GL +3.3 %), so the drawn textures match. What differs between the sets is the manipulator. The 512 JPEG set never runs it, because a ≤512 master goes straight to `Skia.Data.fromURI` + `MakeImageFromEncoded` (a deferred decode; the texture is uploaded only when drawn). The 1024 WebP set ran it for every photo on every cold start, because the 512 copy lived only in memory. `ImageManipulator.manipulate` loads through `expo-image-loader` → Glide 5.0.5 `asBitmap()` with no transform. Glide's `DecodeJob.getOptionsWithHardwareConfig` then enables `ALLOW_HARDWARE_CONFIG`, and `HardwareConfigState` allows it on API ≥ 29 (checked in the cached `glide-5.0.5.aar` bytecode). So each 1024 master was decoded into a HARDWARE Bitmap, a GPU-backed graphics buffer of about 4 MiB. `Bitmap.createScaledBitmap` on a HARDWARE source returns another HARDWARE bitmap of about 1 MiB. Neither is recycled: `ImageRef`/context `release()` only drop the JS reference, so the buffers stay until the Java GC collects the Bitmap objects. That matches what was measured: about +102 MiB GL at 20 s for 50 photos, gone by 70 s with no interaction, plus Native Heap +7 % for the software copies. With the copy on disk, the manipulator runs once per photo per byte change. Every later cold start or return visit takes the baseline's path.

**For the re-measure (same fixed method).** Copies are made on the first Orrery open after a photo is written. That first open still has the one-time transient, and so does a reopen after Android clears the cache dir under storage pressure. So after the Merge restore of the WebP set: open the Orrery once, wait until every planet shows its photo plus about 70 s, then force-stop and start the measured runs. Run 1 would otherwise measure the generation, not a normal cold start. Optional check with `run-as`: `ls cache/orrery-photo/` should list one directory per >512 master the Orrery has shown (at least the 50 fixtures), each with one `<size>-<mtime>.jpg`. The JPEG baseline set creates no copies, because its masters are ≤512.
