## How it was derived

| Scan | Command |
|---|---|
| Every Avatar render site | `grep -rln "<Avatar" src --include=*.tsx` (then `grep -rn` for the line and the `photo=` prop of each site) |
| Forced initials | `grep -rn "photo={null}" src --include=*.tsx` |
| Raw expo-image photo sites | `grep -rln "from \"expo-image\"" src --include=*.tsx` |
| Direct resolved-URI readers | `grep -rn "resolvePhotoUri" src` (non-Avatar render paths: orrery Skia, widget) |
| Name-only surfaces | `grep -rln "contact_name\|contactName\|displayName\|\.name}" src/screens src/components`, then each hit opened and read. Hits that print a category, memory type, system, field label or model name (not a contact) are dropped. |

Legend for **Today**: *real photo via Avatar* = the stored relative path reaches `Avatar`, which renders through
`usePhotoDisplay` (display revision, D-01); *real photo via raw image* = a resolved `file://` URI in a raw
`expo-image` / Skia image; *initials only* = an Avatar with `photo={null}` although a photo could exist;
*text only* = the contact is named, no avatar at all.

Buckets (D-14): **Existing** = shows an existing Orbit contact → real photo. **Pre-import** = shows a phone contact
before import → phone photo already shown, no change (D-13/D-14). **Text-only (D-14)** = named by D-14 to stay text only.
