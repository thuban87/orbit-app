<objective>
Save every new photo as one square WebP master up to 1024 px (D-10, D-13), keep the file names (D-21), leave existing masters alone while every reader handles the mixed library (D-12), and keep working memory flat where a bigger master would raise it: the Skia orrery's textures and the widget's transient decodes (D-11).

Purpose: the Profile photo doubles and the lightbox goes full screen, so the 512 JPEG master looks soft. The owner reversed `07-photos.md` Cluster B's 512 JPEG size knowing it costs ≈2.5–3× storage and backup size (D-10). Three encoders hardcode 512 JPEG q0.75 today (`photo-pipeline.ts:41,44`, `import-photo.ts:16-17`, `reconcile-photo.ts:12-13`), and the import/reconcile paths also upscale and distort a non-square thumbnail. expo-image surfaces already decode at display size, but the Skia orrery decodes full size into a GPU texture, so it needs a gate.

Output: `master-encode.ts`, three rewired encoders, the orrery hook, a sequential widget render, and mixed-library tests.
</objective>
