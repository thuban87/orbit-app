# Phase 38.2 Plan 15: Measured Backup Ingress Ceiling Summary

Physical Pixel measurements informed an owner-approved 100 MiB cap; both native ingress and the JS reader now reject larger backup files before restore preview.

## Performance

- **Completed:** 2026-09-24
- **Tasks:** 3
- **Files modified:** 11 production, test and documentation files

## Accomplishments

- The debug-only probe exercised the production read, envelope check and restore-preview path on schema-valid synthetic files. Plain files near 8, 16, 32, 64 and 96 MiB reached ready preview; the 101,907,032-byte candidate was the largest successful one. A 123,825,650-byte real-exporter fixture failed at the Pixel's 256 MiB Java heap growth limit after copying. The complete observations and limitations are in [38.2-15-MEASUREMENT-DRAFT.md](./38.2-15-MEASUREMENT-DRAFT.md).
- Native share and pick copying count bytes actually read from the provider and reject a stream above 104,857,600 bytes, deleting the partial copy. The JS restore reader checks its owned cache file size before `.text()` and deletes it on rejection. The existing screen catch shows the safe failure state without applying restore.
- The owner approved the 100 MiB ceiling, existing 30-second no-progress stall deadline, and no total acquisition deadline on 2026-09-24. The owner expressly accepted that some larger backups Orbit itself can export will be rejected until a lower-memory restore design ships.

## Measurement and decision evidence

| Synthetic exporter population | No photos, plain | One contact photo, plain | Contact and custom-field photos, plain |
|---|---:|---:|---:|
| 500 contacts | 160,150 B | 20,639,150 B | 41,217,248 B |
| 2,000 contacts | 634,650 B | 82,550,650 B | 164,864,749 B |
| 5,000 contacts | 1,585,650 B | 206,375,650 B | 412,163,749 B |

The no-photo encrypted envelopes were 213,783, 846,451 and 2,114,451 bytes respectively. The photo-rich encrypted cases exceed the existing approved 8 MiB ciphertext profile. On the Pixel, the 101,907,032-byte plain candidate reached preview in 2,611 ms with observed Hermes heap maximum 150,961,352 bytes and process PSS 1,324,460 KiB; its isolated parse took 250 ms. The 123,825,650-byte exporter fixture failed before preview with Java OOM. These are point-in-time sampled maxima, not continuous peaks or a guarantee for other devices or JSON shapes.

First picks of unique synthetic Drive files recorded 5,032 ms acquisition plus 238 ms copy at 82,550,650 bytes, and 9,579 ms acquisition plus 1,184 ms copy at 412,163,749 bytes. The larger file failed during preview after successful copy. No controlled link throttle was available; the draft labels 1/5 Mbps figures EXTRAPOLATED. A fresh export of the Pixel's own data failed through the existing export UI, so its export-size measurement is BLOCKED; only prior cache-file sizes were read. The owner chose the resource bound despite this incomplete evidence and the known rejection tradeoff.
