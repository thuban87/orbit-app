## Safe partial observations

- `emu-connect status`: physical `device` topology and authorized Pixel; `adb devices -l` contained exactly one `device` line. This proves target selection only.
- `adb shell dumpsys package com.bwales.orbit` showed `DEBUGGABLE` and `versionName=1.0.0` for the initially installed APK; `run-as` listed `orbit.db` plus WAL. This establishes that debug inspection is available and existing data must be preserved.
- `adb shell content read --uri content://com.bwales.orbit.rnwidget.imageprovider/widget_1_mode_light.png` returned `Could not find provider` on the fresh release APK as well as the initially installed APK. This is a partial RG-001 denial check; the final release manifest was separately inspected.
- UI trees were captured under `/tmp/orbit-38-2-*.xml` without committing private visible text. The unsaved Add Contact form was discarded; no photo URL flow was invoked. No PASS is inferred from screen navigation.
- `dumpsys appwidget` listed two installed `OrbitFavourites` launcher widgets with nonzero `views_bitmap_memory` (5,652,368 and 2,929,808 bytes) after a fresh release install and reboot. Visual screenshots also showed photos/initials; resize, mode switch and explicit refresh remain untested.
- `run-as com.bwales.orbit ls cache` listed `ImageManipulator`, `photo-dl`, `backup-exports` and other cache namespaces before this UAT's photo flows. It is a baseline only; no before/after derivative-lifetime assertion is made.
- RG-004's first dev-menu pass sent only `{ "probe": "synthetic" }` and the literal bearer token `synthetic-probe-only` to `https://httpbin.org`; POST to `/drip` and `/bytes` returned HTTP 405. The corrected pass used GET with only `X-Orbit-Probe: synthetic-only`. `httpbin.org` supplied delay/drip/status cases, and `speed.cloudflare.com` supplied the >1 MiB response. A temporary bearer header caused Cloudflare HTTP 401 during debugging; it was removed, the JS bundle reloaded, and the oversized case then produced `response_too_large`. No contact data or provider credential was transmitted. Truncated-body device proof remains open.
- Fresh release APK `adb install -r` returned `Success` without clearing app data. With `adb reverse tcp:8081` removed, a force-stopped cold launch displayed the Digest screen from the embedded JS bundle, with no development-server error (`/tmp/orbit-38-2-release-screen.png`). After reboot, the same existing launcher widget still displayed photos and initials; the old image authority remained absent. The Pixel was reconnected with `emu-connect` after reboot.
- Fresh debug APK also installed with `-r`; `adb reverse tcp:8081 tcp:8082` was restored. The RG-002 ingress checks used only files this session created under the app's own cache. A 128-byte control proved that the synthetic `file://` URI actually reached the native copier. The 101 MiB trial then showed a safe error and no remaining copied `restore-share-*` file; a WAL-aware read of `orbit.db`, `orbit.db-wal` and `orbit.db-shm` returned revision 369 both times. The app's real contact rows were not inspected or printed. Full provider behavior is still open.
