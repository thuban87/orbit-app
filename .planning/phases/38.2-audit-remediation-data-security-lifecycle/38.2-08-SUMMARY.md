# Phase 38.2 Plan 08: Restorable and Authoritative Merge Summary

**Merge now completes global custom-field pairs, plans against the state it commits over, and persists deletion evidence even when no live row changes.**

## Accomplishments

- Added two-pass SQL pair completion: `pair:` plus uppercase UTF-8 hex components for stable identity, then `pairx:` fallback only where an arbitrary existing wire UID occupies the deterministic slot. Quarantined global definitions and archived contacts are included; contact-scoped definitions are excluded. Existing values stay untouched.
- Moved local rows, tombstones, settings, conflict checks, photo delete-candidate reads, and writes under one `inWriteTransaction`. The unchanged incoming-pair guard and verified Replace-all safety snapshot still run before it. Media bytes stage first under a registered session, with unused files cleaned afterward.
- Applied novel tombstones, including tombstone-only Merges, and bumped `data_revision`; equal-second deletion continues to win. Background reconciliation now skips active or post-pass sessions and checks fresh template rows under the per-UID finalization lock before canonical deletion.
- Preserved safe existing pending photo filenames. A valid punctuation-bearing photo UID uses a disposable collision-free staging slot; committed avatar master filenames still follow ADR-021 and D-09.

## Decisions Made

None. The implementation follows D-21, D-23, ADR-056, ADR-112, and D-09.

An equal UID for independently created contacts or definitions is **not** detected as an identity collision: ADR-056 treats equal UIDs as one logical row, and deterministic pair UIDs follow that conflated identity. Distinct value UIDs for one `(contact, definition)` pair and distinct definition UIDs for one `col_name` fail closed as `incompatible-destination`. `newUid()` normally mints a 122-bit v4 UUID; where Hermes lacks `globalThis.crypto`, its pre-existing fallback uses `Math.random`. That entropy choice is outside this plan.

**1. [Rule 1 - Bug] Restore's definition collision check read the wrong property**
- **Found during:** Task 1 real roundtrip collision test.
- **Issue:** Reconciliation checked `col_name`, while both manifest and local restore projections use `colName`, so a duplicate natural key reached SQLite's UNIQUE constraint instead of returning `incompatible-destination`.
- **Fix:** Accept either projected property in the collision key.
- **Files modified:** `src/backup/reconciliation.ts`.
- **Verification:** Real exporter/parser/apply collision test and backup suite passed.

**2. [Rule 1 - Bug] Arbitrary photo wire UIDs could not name a safe pending file**
- **Found during:** Task 2 manifest-only staging.
- **Issue:** The backup parser accepts nonempty punctuation-bearing UIDs, but the recovery staging path allowlist rejects punctuation. Over-staging could reject a valid avatar-bearing manifest before conflict planning.
- **Fix:** Keep safe UID staging names, and use a collision-free per-manifest slot only for unsafe UIDs. Canonical ADR-021 paths remain unchanged.
