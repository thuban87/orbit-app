# Phase 38.2 Plan 12: Ordinary Photo Ownership Summary

Contact merge now copies chosen absorbed bytes to survivor-derived paths through a committed recovery journal, while purge and definition deletion journal every derived path before deleting its database identity.

## Accomplishments

- Merge holds Plan 06's canonical locks from source settlement and staging through transaction commit, finalize and absorbed-path cleanup. The DAO rechecks the absorbed UID, photo reference, custom value identity, adoption precondition and source generation; navigation supplies only a photo choice.
- Post-commit finalize and delete failures leave recoverable journal work and still resolve the committed merge so the UI navigates to the survivor. Tests cover same-path crop contention, ID reuse, pending restore bytes, failed finalize replay, newer second merge, and delete retry.
- Purge enqueues main, stored-safe and every custom-definition derived path in its transaction. Definition drop/expiry enqueues every value owner's derived path regardless of current field type; the reference predicate protects shared or still-referenced bytes. Type changes do not rewrite raw TEXT or delete files.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Reject reused absorbed identities even when no photo stages**
- **Found during:** post-task merge review.
- **Issue:** A stale UI route could read an absorbed ID, then merge a newly created contact reusing that ID if no photo transfer existed to trigger transfer identity verification.
- **Fix:** Pass the pre-lock absorbed UID and main reference into the merge transaction and reject mismatches.
- **Files modified:** `src/db/merge-dao.ts`, `src/services/photos/merge-photo-rehome.ts`, and their tests.
- **Verification:** Targeted merge tests and TypeScript check passed.
- **Committed in:** `3123740`.

**2. [Rule 2 - Missing Critical] Drain stored safe purge paths immediately after commit**
- **Found during:** final purge-adapter review.
- **Issue:** The adapter initially selected only paths derived from the purged integer ID, leaving a journaled safe stored path until the foreground drain.
- **Fix:** Process all committed delete intents through the reference-checking owner; this also picks up the purged row's stored path, and unrelated intents remain safe and idempotent.
- **Files modified:** `src/services/photos/purge-photo-cleanup.ts` and its tests.
- **Verification:** Stored-path regression, targeted purge tests, TypeScript and Biome passed.
- **Committed in:** `78e8516`.
