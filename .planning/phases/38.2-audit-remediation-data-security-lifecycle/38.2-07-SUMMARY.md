## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Consuming a superseded share now clears the winning generation.**
- **Found during:** Task 1 request-ownership review.
- **Issue:** A waiter attached to share A could receive share B but leave B marked as unconsumed, allowing a second consume.
- **Fix:** The registry clears the current share when it resolves waiting consumers and transfers file ownership to JS.
- **Files modified:** `BackupIngressRequests.kt`, `BackupIngressRequestsTest.kt`.
- **Verification:** Share A→B JVM test checks that B is delivered and no share remains pending.
- **Committed in:** `35c2b64`.

**2. [Rule 1 - Bug] Successful picked files remain owned by JS after module destruction.**
- **Found during:** Task 1 destroy-path review.
- **Issue:** Keeping a completed pick as the registry's current pick would let a later destroy delete a file already returned to JS.
- **Fix:** Clear the registry's pick reference on successful handoff.
- **Files modified:** `BackupIngressRequests.kt`.
- **Verification:** JVM ingress suite and native compilation pass.
- **Committed in:** `35c2b64`.
