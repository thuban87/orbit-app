# Phase 38.4 Plan 06: Editor Control Accessibility Summary

**Six editor controls now follow the shared control contract. RelationshipEditor's switches use theme colours, and the visibility row always reads "Hide from Profile", so it agrees with the switch's name and with ON = hidden (D-20). The custom-field dropdown and the Fuel kind picker announce their current value. Their selected option has a selected state and a filled `select` glyph, so it no longer depends on colour, and a stored value that is no longer an option is still shown. The Last-spoke date segment announces the chosen date. The touchpoint form shows and announces its date/time as `Mon D, YYYY, h:mm AM` while keeping full stored precision. Its duration chips now meet the 44dp floor without overlapping hit areas (RG-030 `ui-accessibility/AUD-UIA-003`, `AUD-UIA-005`, `AUD-UIA-006`; RG-038 `ui-accessibility/AUD-UIA-018`; D-07, D-20).**

## Accomplishments

- **Task 1 (tracer):** Both `RelationshipEditor` switches now have `trackColor={{ false: colors.border, true: colors.accent }}` and `thumbColor={colors.surfaceElevated}`. The visibility row's body text was the ternary `"Show on Profile" : "Hide from Profile"` and is now the constant "Hide from Profile", the same wording MemoryEditor uses. The caption and the update handler are unchanged. The tracer verification passed end to end before any other task started.
- **Task 2:** `selector-a11y.ts` now holds the dropdown's out-of-list prepend with the same behavior: prepend when missing, no duplicate, the caller's array is not mutated. It also adds `selectorAccessibilityValue`.
  - **DropdownFieldWidget:** the trigger has `accessibilityValue`. Options have `accessibilityState={{ selected: isSelected }}` and a filled `select` glyph, and the selected label uses `colors.accentText` instead of the fill token.
  - **FuelEditor KindPicker:** the trigger label is "Kind" with the current kind as its value, and options get the same selected treatment.
  - **TriStateLastSpoke:** "Pick date" carries `accessibilityValue={{ text: value.date }}` once a date is chosen. The segments use `MIN_TOUCH_TARGET` and vertical-only hitSlop. The muted "Not yet" treatment is unchanged.
- **Task 3:** `TouchpointRefineForm` renders `formatDateTimeMinuteOrFallback(value.occurredAt)` as the visible date/time and as its `accessibilityValue`. The "Correct date and time" label is kept. The native picker seed (`parseLocalDateTime(value.occurredAt)`) and the stored value are unchanged. The `chip` style went from `minHeight: 40` to `MIN_TOUCH_TARGET`, with the same padding and radius and no hitSlop. The row's `gap: 8` keeps neighbouring chips from overlapping. The form's consumers (LogInteraction, EditInteraction, GroupLog, EditGroupEvent, ParticipantOverrideEditor) get this automatically and need no layout change: each chip only grows 4dp in height.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - A11y correctness] Fuel kind trigger label no longer repeats the value**
- **Found during:** Task 2
- **Issue:** The plan said to keep the trigger's `Kind: <kind>` label and add `accessibilityValue`. TalkBack would then read the kind twice ("Kind: Topic, Topic").
- **Fix:** The label is now "Kind" and the value is `kindLabel(value)`. This is the pattern 38.4-04 set for MemoryEditor's TypePicker. No test or consumer depended on the old label.
- **Files modified:** src/components/FuelEditor.tsx
- **Commit:** cc54a31

**2. [Rule 2 - RG-030 verification expectation] TriStateLastSpoke overlapping hitSlop**
- **Found during:** Task 2
- **Issue:** The three segments sit 8dp apart and each had `hitSlop={8}`, so neighbours' hit regions overlapped by 8dp. RG-030 prohibits overlapping hit areas.
- **Fix:** hitSlop is now `{ top: 8, bottom: 8 }`, and `minHeight` is `MIN_TOUCH_TARGET` (still 44). The contract test fails on numeric hitSlop here.
- **Files modified:** src/components/TriStateLastSpoke.tsx
- **Commit:** cc54a31

**3. [Scope note] Task 1 acceptance grep `Show on Profile` = 0 not met by design**
- **Issue:** One "Show on Profile" remains, at `RelationshipEditor.tsx:139`. It is the label of the saved-row action Button that unhides a hidden relationship, which is a correct and separate action, not the switch-row text D-20 targets. Removing it would take away the only unhide path from the row list.
- **Resolution:** The switch-row ternary is gone and the contract test asserts that. The row button is kept.
