<objective>
Gap closure for owner ruling **D-46** (2026-09-27, `OA-C3`): the Off Limits edit button on a contact's Profile opens the **new** Off Limits entry editor, the one reachable through FAB → Update Contact → Off Limits. It no longer opens the Fuel editor (titled "Off Limits", with a Kind picker listing Recent/Topic/Fact/Gift idea/Off-limits).

**What is live (verified on disk at planning; re-verify):**
- **Profile → editor.** `ContactProfileScreen.tsx` `routeKnowledgeChild` (~:229) and `routeKnowledgeAction` (~:250) both navigate to the `OffLimitsEditor` route. That route is registered in the Dashboard, Digest, Events, Orrery and Settings stacks.
- **The old editor.** `OffLimitsEditorScreen.tsx` renders the general `FuelEditor` (with its `KindPicker`) behind `createOffLimitsEditorController`.
  - The controller filters reads to `off_limits`, forces the kind on add and edit, validates the edit/delete id against the scoped collection (`allowedId`), and reloads.
  - Choosing "Topic" in the Kind picker still saves an off-limits row. The picker is misleading, not unsafe.
  - This is **ADR-150's recorded choice** ("Off Limits uses a scoped `FuelEditor` wrapper"). D-46 changes its editor-UI half by owner ruling and keeps its safety half.
- **The new editor.** `UpdateContactScreen.tsx` `OffLimitsFocusedEditor` (~:391-510): topic rows (tap to edit, Remove), a multiline "Off-limits topic" field, and an Add/Save `PrimaryButton`, inside the screen's `EditorFrame` (title + Cancel + error). `UpdateContact` is registered **only** in the Dashboard stack, so rerouting the Profile to it would jump tabs from Digest/Events/Orrery/Settings.
- **Fuel is not retired.**
  - ADR-081 retired only AI-proposed fuel.
  - Off Limits items are `fuel` rows.
  - `FuelEditor` is also used by `CreateContactScreen.tsx` (~:777) and `EditContactScreen.tsx` (~:1661), both kind-scoped to `off_limits` (ADR-131).
  - Display-side fuel consumers remain: `RankedFuelLine` (ContactCard), `fuel-kind-label.ts`, `fuel-read.ts`, the Dashboard `FUEL_LINE` and search.

**Approach (planner call under D-46):**
- Extract the Update Contact editor body into a shared presentational `OffLimitsEntryEditor`.
- Render it in `OffLimitsEditorScreen` through the existing controller, and in Update Contact's `OffLimitsFocusedEditor` through its existing write code.
- The route name, its params and the Profile routing code are unchanged.

Plan against the dossier (D-01); cite D-46 / `OA-C3` in commits (D-02).
</objective>
