<objective>
Gap closure for owner ruling **D-44** (2026-09-27, `OA-C1`; a follow-on to RG-008 `ui-accessibility/AUD-UIA-013`).

**Owner report:** AI Data Permissions says "AI can currently access information from 1 contact · 3 items", but the list below shows several contacts, for example Abbe Vallen (1 item) and Allison Phoenix (3 items). "The numbers aren't matching the results."

**Cause (verified on disk at planning; re-verify):**
- `buildPermissionSummaryCopy` (`src/screens/ai-permissions-logic.ts` ~:106-135) computes the access line from the UNFILTERED **enabled** items. That is correct, and it is Plan 04's AUD-UIA-013 fix.
- The list (`AIPermissionsScreen.tsx` ~:114-123) shows every item once "Enabled only" is off, enabled and disabled alike. The "Review existing…" link turns it off (~:246-249).
- Each contact header shows only `{group.items.length} items · Review` (~:350-356), with no enabled count.
- `isPermissionFilterActive` counts only type, Enabled only and search. So with type "All", no search and Enabled only off there is no "Showing N of M" line at all.
- The result: nothing on screen says that the list includes items AI cannot access, so "1 contact · 3 items" looks wrong next to a longer list.

**Fix:** make every number on the screen reconcile, and say what each one counts.
- The access line keeps its meaning and its copy (Plan 04 / D-17).
- A **list line** always describes the rows below. It replaces the conditional "Showing N of M" line.
- Each **contact header** states its AI-accessible count.

Exact copy is planner discretion under D-44, and the owner reviews it on the device (Plan 17). Plan against the dossier (D-01); cite D-44 / `OA-C1` in commits (D-02).
</objective>
