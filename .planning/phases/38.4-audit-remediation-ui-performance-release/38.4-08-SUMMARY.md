# Phase 38.4 Plan 08: Contact & Review Accessibility + Registered Fonts Summary

**List rows and Grid cards now announce the search or line-three context they display, after the identity summary. Duplicate/Reconcile review cards announce name, chip, evidence and failure copy, expose `selected` state, and offer a Select/Deselect action. Contact renderers now resolve fonts to the registered `Inter-Regular`/`Inter-SemiBold` keys through the shared `resolveFontFamily`.**

## Accomplishments

- `buildRowAccessibilityDescription` takes an optional `context`. It appends the trimmed context as one final part, and only when the context is non-blank. `buildSearchRowContext` builds that context from the match explanation plus the snippet in quotes, and only from what is displayed.
- `ListRow` now computes its label after the search explanation and snippet are derived. It passes the search context in search mode and `line3.text` outside it. `GridCard` passes the search context only. Normal Grid still announces no line three (38.1).
- `resolveFontFamily` moved from `AppText.tsx` into `typography.ts` and is now exported. `AppText` imports it, with no behavior change. The six `fontFamily: TYPOGRAPHY.x.family` sites in ListRow/GridCard now resolve to registered keys. Sizes, line heights and truncation are unchanged.
- A new pure helper, `candidate-card-a11y.ts`, builds the review-card accessibility props. `CandidateCardGrid` spreads its result on the card. `onAccessibilityAction` maps `toggle-selection` to `toggleSelection(item)`. While selecting, a filled/outline `select` glyph shows selection without relying on the border. The failure copy is one shared constant, so the rendered and announced copy cannot drift.
- Updated the system docs (dashboard row steps 6-7, Card step 5, and the Changelog; reconciliation review step 6 and the Changelog).
