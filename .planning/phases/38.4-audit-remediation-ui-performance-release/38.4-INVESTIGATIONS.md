### RG-039 remediation (Task 2) — before/after

**Change** (`src/components/UniversalFab.tsx`): the scrim and the action-rows container carry `importantForAccessibility={open ? "auto" : "no-hide-descendants"}` and `accessibilityElementsHidden={!open}`. The FAB carries `accessibilityState={{ expanded: open }}`. The scrim and each row also carry `accessible={open}` and `focusable={open}`. `open` flips synchronously at the start of `openDial`/`closeDial`, so the closing animation is already semantically hidden. Keyboard hiding, contextual routing, the measured bottom offset, `restoreFabFocus`, opacity and `pointerEvents` are unchanged.

**Deviation found on device (Rule 1).** The first fix pass used the plan's props plus `focusable={open}`. It stopped ENTER from invoking a hidden row (`rg039-fix-enter-interim.*`: focus on hidden Group Log `#b8`, ENTER left the screen on Digest). But the seven hidden views stayed keyboard focus stops (`VFE......`, steps 8–12 in the interim `rg039-fix-tab-closed.log` run). In RN 0.86 `ReactViewManager.setFocusable(false)` only removes the click listener. It deliberately leaves `isFocusable`, which `setAccessible(true)` sets and Pressable defaults on. Adding `accessible={open}` clears native focusability while closed.

**Side finding (not RG-034, deferred).** At font_scale 2.0 InteractionDetail's `Sheet variant="detail"` clips its Edit/Delete row. They are absent from the a11y dump (`rg034-B-detail-sheet.xml`) and unreachable by touch. The long-body dialog was therefore opened by keyboard: TAB to the clipped Delete (native `#844`/`#1e4e`), then ENTER. Logged in `deferred-items.md`.

### Treatment (Task 3; planner discretion per D-04 / CONTEXT)

`ConfirmDialog.tsx` plus the new pure `src/components/ui/confirm-dialog-layout.ts` (`confirmActionsFit`):
- The title, message and warning glyph sit in a `ScrollView` (`flexGrow: 0, flexShrink: 1`). The card and overlay content wrapper are `flexShrink: 1` and padded by the safe-area insets plus `SPACING.lg`, so the card never outgrows the window and the actions never scroll away.
- The actions render first in a wrapping row (`flexWrap: "wrap"`, each choice `maxWidth: "100%"`) to read each choice's natural width. If Cancel + gap + confirm fit the row (1 dp rounding tolerance), the **original single right-aligned row** is kept. Otherwise both choices **stack full-width** in reading order (Cancel, then confirm). The actions component sits inside the overlay, so it re-measures on every open.
- `dismissable={!destructive}` is unchanged (ADR-086). All consumers' props are unchanged.

A first pass that only wrapped produced a right-aligned staircase, and it also wrapped the baseline dialog. Logging the measured widths explained why. The baseline content box is 296 dp, but Cancel 89.1 + gap 8 + confirm 211.3 = 308.4 dp, so the old row was really 12 dp wider than the card content (the padding overrun above). With the measured treatment, this dialog on the 3a now stacks full-width even at default text. On a 411 dp phone (Pixel 6 Pro: content box ≈315 dp) the row is kept. The fit/stack decision is unit-tested in `confirm-dialog-contract.test.ts`.
