# Phase 38.4 Plan 11: FAB closed-dial semantics, FAB glyph role foreground, and large-text ConfirmDialog, all driven by device evidence

**Both investigation gates came back CONFIRMED on the Pixel 3a, and both are now fixed and re-verified on the device.**
- **RG-039:** with the FAB dial closed, its invisible actions were keyboard-reachable and invokable. The closed dial is now hidden from accessibility and from keyboard focus, and the FAB exposes its expanded state.
- **RG-034:** at maximum text scale, ConfirmDialog crushed Cancel into an unlabelled ~17 dp sliver off the card. It now keeps both choices readable and on-screen, with the ADR-086 destructive non-dismissal intact.
- **D-20 rider:** the FAB glyph now uses `onAccent`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Stale debug APK native layer**
- **Found during:** Task 1, first launch.
- **Issue:** the redbox read `Cannot find native module 'OrbitBackupShare'`.
- **Fix:** installed droid's newest debug APK with `install -r`. It was built after the last native commit, and its native sources were MD5-verified against HEAD.
- **Files modified:** none (device only).

**2. [Rule 1 - Bug] RG-039 plan props alone left the keyboard exposure in place**
- **Found during:** Task 2, device re-run.
- **Issue:** `importantForAccessibility` + `focusable={open}` stopped ENTER from invoking. The seven hidden views were still keyboard focus stops, because RN 0.86 `setFocusable(false)` keeps `isFocusable`, which `accessible` sets.
- **Fix:** added `accessible={open}` to the scrim and the rows. The contract test was extended.
- **Result:** closed-dial TAB now goes Settings → FAB with no hidden stops, and the rows are `V.E......` natively.
- **Commit:** `8706cd6`.

**3. [Rule 1 - Bug] The plan's `flexWrap` treatment produced a right-aligned staircase and wrapped the default-text dialog**
- **Found during:** Task 3, post-fix device check.
- **Fix:** measure-then-decide. The dialog keeps the original row when both choices fit (1 dp tolerance) and otherwise stacks them full-width in reading order. The decision is a pure, unit-tested `confirmActionsFit` in a new file, `confirm-dialog-layout.ts`, which is not in the plan's file list.
- **Commit:** `1a7d2ae`.

**4. [Scope] Long-body consumer switched from CategoryManagement to InteractionDetail**
- **Why:** CategoryManagement's AnchoredMenu would not open under adb injection. InteractionDetail has the next-longest body.
- **How it was reached:** its Delete trigger is clipped by a separate Sheet defect (deferred), so the long-body dialog was opened by keyboard: TAB to the clipped Delete, then ENTER.

## Visible change to flag

The Pixel 3a's default-text "Delete permanently?" dialog now shows **stacked full-width** Cancel / Delete permanently instead of a row. The old row was 308 dp in a 296 dp content box, so it already overran the card padding. On the 6 Pro (411 dp) the row is kept. This is planner discretion under D-04. It is listed here because it changes how the dialog looks on narrow phones.
