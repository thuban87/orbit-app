# Phase 38.4 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Source: `38.4-RESEARCH.md` §Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest 4.1.10, node environment, with the `node:sqlite` harness `src/db/__testkit__/node-sqlite.ts` |
| **Config file** | `vitest.config.ts` |
| **Quick run command** | `npx vitest run <touched test files> && npx tsc --noEmit` |
| **Full suite command** | `npx vitest run && npx tsc --noEmit && npm run check:colors && npx biome check src` |
| **Estimated runtime** | quick about 30 s; full about 4–6 min |

---

## Sampling Rate

- **After every task commit:** the touched test files plus `npx tsc --noEmit`. Vitest passing does not mean tsc is clean.
- **After every plan wave:** the full suite command, including `check:colors`.
- **Before `/gsd-verify-work`:** the full suite must be green, then the targeted device pass (Plan "final gate").
- **Max feedback latency:** about 60 s per task.
