# Phase 38.4 Plan 14: 38.3 Loose Ends W2, A-WR-05 and O-3 Summary

**Digest and Profile no longer read on a backgrounded shell tick (one shared `isForegroundVisible` rule over synchronous `AppState.currentState`). ## Contacts freeze (Plan 19 hint)

I found no conclusive cause in the code I read. This is the path a Population, Filter, or Sort selection takes:

1. `DashboardControlRow.tsx:97-163` sets `pending` and calls `useDashboardQueryStore.getState().setPopulations/setFilters/setSort`.
2. That runs `updateAppSettings` in `inWriteTransaction` and bumps `data_revision`, then the store's `set(...)` (`dashboard-query-store.ts:97-136`).
3. HomeScreen's `useShallow` `query` changes (`HomeScreen.tsx:420`), so `reload` gets a new identity (`:902-905`).
4. `useFocusEffect` re-runs and calls `reload("focus")` once, which is one full 9-query read plus line-3 enrichment (`:742-878`).
5. The read publishes with fade start 0, re-animating the whole result list.

As far as I can see, nothing in that chain loops, and the scheduler issues exactly one read per selection. Two leads for Plan 19:

- **The write never settles.** If `inWriteTransaction` waits behind another held write, `pending` stays true and every control ignores taps (`if (pending) return`). That looks like a freeze even though the JS thread is free. Check whether the JS thread is actually blocked (Perf Monitor) or the controls are just latched.
- **The panel stays open during the read.** A slow `listDashboardPopulation` / `composeDashboardSearch` read on a large dataset, combined with the full-list fade, would be JS-thread work. The Anchored panel is still open over it.

This plan's change adds `reload` to `toggleFavourite`'s deps, so `toggleFavourite` also changes identity on a query change. The `CardGrid` prop already re-renders on that change, and this is not a plausible freeze cause.
