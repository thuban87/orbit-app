# Phase 38.4 Plan 04: Truthful AI Configuration Presentation Summary

**All four Memory hosts now take AI availability from the ADR-135 master (`isAiMasterEnabled`) instead of the retired `aiProvider` field. The AI Data Permissions screen reports actual access from the unfiltered enabled items and describes a filtered view in a separate "Showing N of M" line, and prints no count at all when no successful read backs it. The model picker reads each lane's saved model read-only and marks it visibly and for screen readers, including manual ids. The Memory, ThingsToRemember and AI-screen controls touched here (RG-030) now have accessible names, themed switches and 44dp targets.**

## Accomplishments

- `src/logic/ai-enablement.ts` adds `isAiMasterEnabled(settings)`. `MemoryScreen`, `ThingsToRememberScreen`, `EditContactScreen` and `PostLogNoteEditor` all call it. A source-scan test fails if any of them brings back the `aiProvider` comparison. Load paths are unchanged apart from the predicate, and nothing new writes (D-17).
- `MemoryEditor`:
  - "Pin memory", "Mark outdated" and "Hide from Profile" have accessible names, and all four switches use the themed track/thumb tokens (AUD-UIA-004, AUD-UIA-003). The "Allow AI" switch keeps its disabled semantics.
  - The kind trigger exposes the current kind as `accessibilityValue`.
  - Options carry `accessibilityState.selected` and show a filled `select` glyph, so the selected kind is not marked by colour alone (AUD-UIA-005).
- `ThingsToRememberScreen`'s "Show hidden items" switch is themed. It already had a matching accessible name.
- `buildPermissionSummaryCopy()` returns three lines:
  - `accessLine`: from the enabled, unfiltered items.
  - `showingLine`: only when a type filter, Enabled only, or a search is active.
  - `emptyLine`.

  All three are null when the load failed or hasn't finished. The screen renders only these lines, and `summarizePermissionView(filtered)` is gone from the screen. "Review existing…" has `minHeight: MIN_TOUCH_TARGET` and no hitSlop (AUD-UIA-013, AUD-UIA-006).
- `markRememberedModel()` matches trimmed ids by exact string equality. `currentModelRowId()` returns the saved id when it is a manual id, or when its card is hidden by the current view.
- `AIModelPickerScreen` reads `getAiConnection(getExecutor(), lane).rememberedModel` read-only; a missing row or a read error means no mark and no write.
  - The current card shows a "Current model" caption. Its Choose button is announced as selected, with the hint "This is the current model".
  - A manual id, or a saved model whose card is hidden, gets an announced "Current model: <id>" row.
  - More Info has a model-specific label and expanded state, and meets 44×44 without hitSlop (AUD-UIA-020, AUD-UIA-006).
- `docs/systems/ai-suggestions.md` now covers the master predicate, the totals-vs-view summary and the saved-model marker: new key files, How-It-Works steps 5–6, Gotcha 12, and a 38.4 Changelog row that cites RG-008.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Button primitive could not carry a selected state**
- **Found during:** Task 3
- **Issue:** The plan requires `accessibilityState={{ selected: true }}` and an announcing hint on the current card's Choose control. That control is the shared `Button`, which exposed neither.
- **Fix:** Added optional `selected?: boolean` and `accessibilityHint?: string` to `Button`'s common props. When `selected` is omitted, `accessibilityState` keeps its exact previous shape.
- **Files modified:** src/components/ui/Button.tsx
- **Commit:** 2149d46

**2. [Rule 1 - Bug] Empty-state and pending-load copy made false access claims**
- **Found during:** Task 2
- **Issue:** Before the first read landed, and after a failed read, `items` was `[]`. The screen then printed "AI can currently access information from 0 contacts" and the empty card "AI can't access any contact information yet." Neither claim was backed by a read, and the empty card also appeared when a filter hid existing enabled items.
- **Fix:** A `loaded` flag gates all counts: `loadFailed` is `!loaded || error !== null`, as the plan requires ("no count when error is set"). `emptyLine` separates "no access" from "No information matches these filters." Counts are also hidden after a default-toggle or bulk-update error, since those set `error` too.
- **Files modified:** src/screens/AIPermissionsScreen.tsx, src/screens/ai-permissions-logic.ts (+ tests)
- **Commit:** 60a24bf

**3. [Rule 1 - Bug] More Info announced an expansion of nothing on direct lanes**
- **Found during:** Task 3
- **Issue:** Direct-lane cards always have `context: null`, so More Info toggled nothing. With the new expanded state it would have announced an expansion that reveals no content.
- **Fix:** More Info renders only when `card.context` exists. On OpenRouter it is unchanged apart from the a11y and size fixes.
- **Files modified:** src/screens/AIModelPickerScreen.tsx
- **Commit:** 2149d46

**4. [Rule 3 - Blocking] MemoryEditor node test broke on the new Icon import**
- **Found during:** Wave gate (full vitest)
- **Issue:** `MemoryEditor.test.ts` mocks RN primitives. The new `Icon` import pulled in `@expo/vector-icons` JSX, which Rolldown cannot parse in node.
- **Fix:** Added `vi.mock("./icons/Icon", ...)`, following the file's existing mock pattern.
- **Files modified:** src/components/MemoryEditor.test.ts
- **Commit:** 859e0e6

**Additions within scope:** `isPermissionFilterActive()` and `currentModelRowId()` are small pure helpers extracted so the screen rules can be unit-tested. The copy is now singular-aware ("1 contact · 1 item").

**Total deviations:** 4 auto-fixed (2 Rule 1, 2 Rule 3). **Impact:** all presentation-only. No DAO write path, migration, `aiProvider` field or `AiService` changed.
