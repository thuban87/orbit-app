# Phase 38.4: UI Consistency, Accessibility, Performance & Release Polish - Research

**Researched:** 2026-09-26 (HEAD `6e7f4e4`)
**Domain:** Remediation sweep for React Native 0.86 / Expo SDK 57 (Android). Covers the SQLite access path, the Reanimated/Skia resource lifecycle, the theme contrast proof, accessibility semantics, Expo CNG config plugins and launcher assets.
**Confidence:** HIGH for the code-grounded findings. MEDIUM for the native/merger behaviour and the upstream expo-modules-core fix status.

## Summary

Every covered group was re-grounded against the code on disk at HEAD `6e7f4e4`. All of them are still present. The re-grep turned up four scope additions the grounding map missed:
- **RG-037** has **7** duplicate-Back Settings children, not 4. About, Contacts and Interactions also carry an in-body Back next to the `ShellAppBar` child Back.
- **RG-038** has an extra raw timestamp: `RestorePreviewScreen.tsx:294` renders "Source date: {preview.exportedAt}" (a `localDateTime()` string with seconds).
- **RG-030** has an extra unthemed Switch in `ThingsToRememberScreen.tsx`.
- **RG-029** needs `ShellAppBar`'s own Back label changed. It uses `textSecondary` (`ShellAppBar.tsx:118`), and after D-15 that becomes the *only* Back on Settings children.

The most important finding is a **hard stop under D-12**. The corrected proof checks the darkest pixel for dark foregrounds. `textPrimary` passes it on every Standard asset (worst 5.49:1 on Dusk), so `textSecondary` can move to an existing token. But in the **Standard Light glassy regime** (card and chrome tint `surface @ 0.5`), several foregrounds the current proof already asserts have no existing hue-preserving token that passes over Dusk/Mesh:
- the status hues: `statusStable`/`statusWobble`/`statusDecay`/`rogue`, from 1.67 to 2.45:1 against a 3.0 floor;
- every curated accent's `accentText` (1.99–2.58:1 on Dusk);
- `danger`-as-text (2.24:1 on Dusk and 4.32:1 on Paper, against a 4.5 floor).

D-12 says: "If no existing token passes without retuning a protected hue, **stop and ask**." This is OWNER-ESCALATION #1, and it must be resolved before the RG-029 plan can finalize its proof.

The other high-value findings:
- **RG-028.** Verified with real migrated-schema `EXPLAIN QUERY PLAN` via `node:sqlite`. Today the plan is `SCAN i USING COVERING INDEX idx_interactions_recency` plus `SCAN ge`. With `CREATE INDEX … ON interactions(occurred_at)` / `group_events(occurred_at)` plus half-open range predicates, it becomes `SEARCH i USING INDEX … (occurred_at>? AND occurred_at<?)`.
- **RG-040.** `android.blockedPermissions` puts `tools:node="remove"` in the **main** manifest. The main manifest is higher priority than library manifests, so it also strips React Native's own debug-library `SYSTEM_ALERT_WINDOW`. The correct authored mechanism is a local config plugin that deletes the permission from the main manifest and writes a `src/release/AndroidManifest.xml` remove marker.
- **RG-041.** Expo resizes `foregroundImage`/`monochromeImage` edge-to-edge (`resizeMode: 'cover'` to 108dp) and adds no padding, so the safe-zone fit must be baked into the committed derivative. Pillow 10.2.0 is present on this box.
- **W3/O-1.** This matches a known upstream Android expo-modules-core GC race, expo/expo#49799, fixed by PR #50513 (merged 2026-09-23). The fix appears to be unreleased, and the installed version is `expo-modules-core@57.0.11`.

**Primary recommendation:**
- Use 12 subsystem-bundled plans in 3 waves: 9 disjoint plans in Wave 1, the Workstream I and launcher/manifest plans in Wave 2 (they touch files owned by Wave 1 plans), and the final gate plus device pass in Wave 3.
- Resolve OWNER-ESCALATION #1 before the RG-029 plan executes.

## Project Constraints (from CLAUDE.md)

- **Read HANDOFF.md / ADRs. Do not reverse `[DECIDED]` items.** Reversing a recorded decision is the owner's call, even when the trigger is technical.
- **Never push.** Commit locally only. **Never run `git worktree`** (`workflow.use_worktrees: false`). State this in every spawned agent's prompt.
- **Review the code, not the diff.** Planner, checker and reviewer prompts must require reading full files and every writer of shared tables. For RG-028 that means `interactions`/`group_events`: `recency-dao.ts`, `group-events-dao.ts`, `restore-apply.ts`, `benchmark.ts`, migration 025 and `ai-permissions-dao.ts`, all read this session.
- **Local-first.** No network in read paths. No telemetry. Nothing in this phase adds network.
- **Migrations:** `PRAGMA user_version` pattern; forward-only; never edit a shipped migration; derive head+1 from disk (runbook `docs/runbooks/sqlite-migration-pipeline.md`).
- **All colours through theme tokens** (`npm run check:colors` scans `src` + `App.tsx` `*.ts/*.tsx`; `/theme/` paths exempt). `app.json`'s `#1A2F8A` is outside the scan and is config, not a component literal.
- **Animation:** never drive animation from React state. Worklet helpers must be defined **above** the worklets that call them in the same file (memory: worklet forward-ref hazard, `f979263`).
- **Tunable constants go at the top of their file.** Heatmap min/max cell bounds and the icon fit margin belong there.
- **Dates:** use `formatLocalDate()` / the shared formatters; never `toISOString().split('T')[0]`.
- **Graphify:** never `graphify build` / `$gsd-graphify build`. `npm run graph:ask -- governs <file>` is fine.
- **Build pipeline:** APKs build on `droid` over SSH, transported by tar-over-ssh (never git push), per `docs/runbooks/desktop-build-pipeline.md`. Debug-first iteration, and ONE release build at the end (memory).
- **Device:** use `~/.local/bin/adb` and read the serial from `adb devices` (currently `1A071FDEE002BU`, Pixel 6 Pro, Android 17). Orbit Metro runs on :8082, and the device-side remap is `adb reverse tcp:8081 tcp:8082`. The debug build `com.bwales.orbit` holds test data. **Do not** build `com.bwales.orbit.uat`. **Never trigger a real AI provider call** during device work without clearing it with the owner.
- **Gates:** vitest passing does not mean tsc is clean. Run `npx tsc --noEmit` + `npm run check:colors` in every post-merge gate. Orphaned test consumers of a reshaped contract break tsc (the schema-head literal tests below).
- **No AI attribution** in commits.

## Common Pitfalls

### Pitfall 1: The endpoint-only contrast check falsely passes mid-tone hues
**What goes wrong:** status and accent hues can sit inside the asset's composite-luminance range. Both endpoints pass while an interior pixel gives about 1:1.
**How to avoid:** assert that the foreground luminance lies outside [L(compDark), L(compBright)], and that both endpoints pass.

### Pitfall 2: Orphaned schema-head literal tests
**What goes wrong:** `full-chain.test.ts:87`, `029-…test.ts:22,28`, `030-…test.ts:25` and `category-identity-audit.test.ts:220-223` pin 30. Registering 031 breaks them, and `category-identity-audit` source-scans `database.ts` text.
**How to avoid:** update all of them in Plan 01. Run `npx tsc --noEmit` and the full vitest suite.

### Pitfall 3: Worklet forward reference
**What goes wrong:** a new `"worklet"` helper defined below its same-file caller is `undefined` on the Hermes UI thread and crashes. vitest stays green.
**How to avoid:** define callees first. Use the babel production-transform harness test, and add the optional ordering scan.

```js
// @ts-nocheck
const fs = require("node:fs");
const path = require("node:path");
const { withAndroidManifest, withDangerousMod } = require("expo/config-plugins");
const OVERLAY = "android.permission.SYSTEM_ALERT_WINDOW";
const RELEASE_MANIFEST = `<manifest xmlns:android="http://schemas.android.com/apk/res/android" xmlns:tools="http://schemas.android.com/tools">
  <uses-permission android:name="${OVERLAY}" tools:node="remove"/>
</manifest>
`;
module.exports = (config) => {
  config = withAndroidManifest(config, (cfg) => {
    const perms = cfg.modResults.manifest["uses-permission"] ?? [];
    cfg.modResults.manifest["uses-permission"] = perms.filter(
      (p) => p.$?.["android:name"] !== OVERLAY,
    );
    return cfg;
  });
  return withDangerousMod(config, ["android", async (cfg) => {
    // Repo-proven form (plugins/withWidgetBootReceiver.js:119-123): projectRoot is the repo root.
    const dir = path.join(cfg.modRequest.projectRoot, "android/app/src/release");
    await fs.promises.mkdir(dir, { recursive: true });
    await fs.promises.writeFile(path.join(dir, "AndroidManifest.xml"), RELEASE_MANIFEST);
    return cfg;
  }]);
};
```
