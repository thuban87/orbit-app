# Phase 38.4 Plan 05: Backup/Restore Presentation Summary

**Filled Backup and Restore actions now label with their ADR-084 role foreground: `onAccent` on accent fills, and `onDanger` on the Replace-all danger fill. Each of the five backup passphrase fields has a persistent visible label. The restore source date renders at minute precision in 12-hour AM/PM with a neutral fallback for foreign values. A source-scan contract test locks all three (RG-029 `ui-accessibility/AUD-UIA-002`, RG-036 `ui-accessibility/AUD-UIA-014`, RG-038 `ui-accessibility/AUD-UIA-018`; D-07, D-12, D-14).**

## Accomplishments

- **Role foregrounds (Tasks 1-2).** The Backup passphrase "Continue to preview backup / Try passphrase again" button, Restore Preview "Choose file again" and Restore Result's return button used `colors.textPrimary` on an accent fill. They now use `colors.onAccent`. The Restore Preview apply label is `mode === "replace-all" ? colors.onDanger : colors.onAccent`, which mirrors the fill ternary `mode === "replace-all" ? colors.danger : colors.accent`.
- **Galaxy Dark limitation (recorded, not changed).** Galaxy Dark `onDanger` `#FFFFFF` on `danger` `#E5484D` measures about 3.91:1, below AA-normal. This is the ADR-084 owner-accepted value (`theme-presets.ts:51-56`). The Replace-all label uses it as the designated foreground, and no hue was retuned (D-12).
- **Source date (Task 2).** `Source date: {preview.exportedAt}` became `Source date: {formatDateTimeMinuteOrFallback(preview.exportedAt)}`. An Orbit export stamp such as `2026-09-26 14:05:38` renders `Sep 26, 2026, 2:05 PM`. Midnight renders `12:00 AM` and noon `12:00 PM`. Empty, whitespace, ISO-`Z`, prose and out-of-range values all render `Unknown time`. All of these fixtures are in the contract test.
- **Passphrase labels (Task 3).** An `<AppText role="label" importantForAccessibility="no">` sits directly above each secure input: Passphrase, Confirm passphrase, Current passphrase, New passphrase, Confirm new passphrase. Each label is an unconditional sibling of its input, so it stays visible before entry, after entry and while the error text shows. The inputs keep `secureTextEntry`, `accessibilityLabel`, testIDs and handlers. The encryption, passphrase-store and re-encryption code is byte-identical: the diff adds only the label elements, one import, the lint directive and one formatter re-wrap.
- **Contract test.** `backup-presentation-contract.test.ts` has 19 cases. The region matcher was mutation-checked: reverting any one label (Backup, Restore Result, or the Replace-all `onDanger` branch) to `textPrimary` fails exactly one case.
- **Docs.** `docs/systems/backup-restore.md` gained an encryption step 4 for the visible labels, a source-date note in the restore step, a new "Filled-action foregrounds" section that records the Galaxy Dark limitation, and a 38.4 Changelog row.

## Decisions Made

- The source date shows the formatter's neutral fallback, not the raw foreign string. This was the planner's call and it matches D-07.
- The Galaxy Dark `onDanger`/`danger` pair stays as it is (see Accomplishments).
- `AppText` is imported from the `@/components/ui` barrel. `BackupSettingsScreen.tsx` takes the file-level `biome-ignore-all lint/a11y/useValidAriaRole` directive that `AIPersonalizationScreen.tsx` and `GroupLogScreen.tsx` already use, because `AppText`'s `role` is a typography prop, not an ARIA role.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical functionality] Backup settings filled actions used `colors.background` on the accent fill**
- **Found during:** Task 3, while reading `BackupSettingsScreen.tsx` in full
- **Issue:** Save schedule (~:586), Turn on encryption / Set a new passphrase for future backups (~:672) and Save encryption change (~:796) labelled accent fills with `colors.background`. This is the same misrole class AUD-UIA-002 describes: primary buttons that bypass the shared `onAccent` foreground. ADR-084 does not guarantee `background` contrast against `accent`. Neither Plan 16 nor the RG-029 inventory owns these three sites; the plan named only Backup, Restore Preview and Restore Result.
- **Fix:** All three labels now use `colors.onAccent`. The contract test asserts the three settings fills, and rejects both `textPrimary` and `background` as fill labels. This enforces ADR-084 and D-12 rather than reversing them. It is a foreground-only change with no hue retune.
- **Files modified:** `src/screens/BackupSettingsScreen.tsx`, `src/screens/backup-presentation-contract.test.ts`
- **Commit:** `ea703fa`. That commit left "Save schedule" wrapped over three lines; the Biome re-wrap to one line landed in `d358ab2`.

**2. [Rule 1 - Bug] Contract label matcher could not follow formatter line-wrapping**
- **Found during:** Task 2 GREEN
- **Issue:** Biome wraps the Replace-all label's ternary style across lines, and the Task 1 matcher only handled single-line `<Text style={{ color: X }}>`.
- **Fix:** Made the matcher whitespace- and trailing-comma-tolerant. Mutation checks confirmed it still fails on a reverted token.
- **Commit:** `752496c`
