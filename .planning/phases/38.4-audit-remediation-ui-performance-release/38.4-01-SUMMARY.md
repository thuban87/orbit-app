# Phase 38.4 Plan 01: Bounded Your Week Reads Summary

**Migration 031 adds `occurred_at` indexes on `interactions` and `group_events`. All three Your Week reads now use a half-open range plus the original `date()` residual. On the real migrated schema they SEARCH the new indexes instead of scanning lifetime history, and a legacy-SQL oracle test shows their results are unchanged (RG-028, `performance/AUD-PERF-004`).**

## Accomplishments

- `src/db/migrations/031-your-week-occurred-at-indexes.ts`: `YOUR_WEEK_INDEX_SCHEMA_VERSION = 31` and `migration031` (two plain `CREATE INDEX` statements). It is registered in `MIGRATIONS`, and `TARGET_VERSION` now equals it.
- Query plan before and after (captured on the migrated schema):
  - before: `SCAN i USING COVERING INDEX idx_interactions_recency` for each interaction sub-select, and a full scan of `ge`
  - after: `SEARCH i USING INDEX idx_interactions_occurred_at (occurred_at>? AND occurred_at<?)` and `SEARCH ge USING COVERING INDEX idx_group_events_occurred_at (...)`
- Date counts: 4 binds became 8. Day read: 2 binds became 6. Metrics: 6 binds became 12. Every bound is still a `?` parameter.
- Parity oracle: the pre-RG-028 SQL lives only in `your-week-read.test.ts`. The test compares the new and legacy reads over 6 windows and 15 single days using the edge-case fixture.
- Mutation check (temporary, not committed): swapping the upper bound for `<= date(?)` made 5 of the 10 Your Week tests fail. The proofs catch this.
- Each schema-head literal was updated in the same commit: full-chain, 029, 030 (now `TARGET_VERSION`), and the category-identity-audit pins, which now expect `YOUR_WEEK_INDEX_SCHEMA_VERSION` and `migration031` while keeping `migration030` and `BACKUP_FORMAT_VERSION = 7`.
- Docs: `digest.md` gains the predicate contract, both index names, migration 031, the accepted timezone-suffixed edge, Gotcha 9 and a Changelog row. `persistence-core.md` gains migration 031 in the layer table, the key-files table, related systems and the Changelog.
