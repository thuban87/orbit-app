# Phase 38.4 Plan 02: Settled Orrery Resource Retirement Summary

**Completed Orrery switches now compact the UI-thread choreography to destination bodies only (`settleSwitchChoreography` in the `finish` worklet), and settled publications replace the React resource list, so departed bodies stop being projected and rendered after a switch settles (RG-027, `performance/AUD-PERF-001`). A TypeScript-checker source scan guards every Orrery module against the Hermes same-file worklet forward-reference crash.**

## Accomplishments

- `settleSwitchChoreography(transition)` ("worklet", at line 416, after `beginSwitchChoreography` at 348) rebuilds a completed switch from its destination bodies with intensity 0, preserving generation and reducedMotion. Sampling it at progress 1 matches the opacity>0 world of the original sample exactly. The empty case gives zero entries. Shared keys keep their key and geometry.
- In `use-orrery-switch-runtime.ts`, `finish` assigns `transition.value = settleSwitchChoreography(transition.value)` after the generation check and before `runOnJS(prune)`. A babel production transform confirms the closures: `finish` captures `settleSwitchChoreography`, and `settleSwitchChoreography` captures `beginSwitchChoreography`, which is defined earlier.
- `nextOrreryResources(current, scene, isSwitch)` and `pruneOrreryResources(current, scene)` are now exported pure helpers. `publish` and `prune` delegate to them. The prune keeps its generation check.
- Cardinality proofs (pure helpers plus the hook harness) cover:
  - A→B→C completed switches
  - repeated same-System removals
  - an interrupted switch followed by a refresh
  - reduced-motion completion, both when published reduced and when toggled mid-switch via the reaction
  - the empty world
  - a stale driver completion, which never compacts a running switch

  In every case each retained resource belongs to the latest scene generation, and the number of choreography entries equals the number of resources after each settle.
- `orrery-worklet-order.test.ts` has an inline fixture with 4 deliberate forward references (top-level function, const arrow, nested `.map` worklet, hook-local `useCallback`). The scanner reports exactly those 4 and does not flag the exempt deferred and plain-JS cases. It passes on the two target files and on all other Orrery modules.
- `docs/systems/orrery.md`: added a "Settled resource retirement" paragraph, a "Worklet order guard" paragraph and a 38.4 Changelog row.

## Deviations from Plan

### Auto-fixed / scope adjustments

**1. [Rule 2 - Missing verification] Hook-level tracer test added in Task 1**
- **Found during:** Task 1
- **Issue:** The plan's Task 1 tests covered the pure `settleSwitchChoreography` only. Nothing proved that the `finish` worklet actually compacts `transition.value`, and the plan only required a grep for that. The repo has no react-test-renderer.
- **Fix:** Added a single-render harness to `orrery-switch-runtime.test.ts`. It stubs React hooks, runs Reanimated worklets synchronously, and has `withTiming` record its completion callback. Task 1 then asserts compaction, visual parity and prune through the real hook, and asserts that a stale-generation completion never compacts a running switch. The plan listed this file under Task 2 only, so it was touched one task earlier than planned.
- **Commit:** 2b040c7

**2. Scope of the order scan**
- The plan made scanning other orrery files optional. I included every `src/logic/orrery-*.ts` and `src/components/orrery/*.ts(x)` non-test module in a standing test case. All were clean, so there is no pre-existing finding to report to the owner.

### Behavioral note (not a deviation, recorded for review)

- Suppose a body departed in A→B (it was invisible, opacity 0, at the end of B) and it reappears in a later B→C switch.
  - **Before:** it was classified `retained` from an invisible source.
  - **Now:** B's choreography was compacted, so it is classified `entering`. That is the designed capture treatment for a body not displayed in B.
- Hit authority and label exclusions are unaffected. `projectAnimatedFrame` / `projectSwitchChoreographyFrame` already mark opacity-0 bodies `visible: false, interactive: false`.
