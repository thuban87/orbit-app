# 38.4 W3 Investigation — expo-sqlite `ERR_USING_RELEASED_SHARED_OBJECT` under shell-tick fan-out (W3/O-1, D-10, D-25)

Plan 15. Investigation first: the race was driven on the Pixel 3a and counted before any fix was considered.

## Probe

`src/__dev__/uat-probes.ts` adds the dev-menu item **"UAT: shell-tick fan-out ×20"**. It sits inside the existing
`if (!__DEV__ || registered) return;` guard and lazily `require`s `@/stores/shell-refresh-store`. It calls
`bumpShellRefresh()` 20 times at a fixed 150 ms interval and logs only `uat-probe fan-out start 20` / `uat-probe fan-out end 20`.

**Measurement marker (deviation, see SUMMARY):** so the fan-out could be counted, `ContactProfileScreen.tsx` now emits a
content-free `Logger.debug("contact-profile", "profile snapshot read", <trigger>)` on every Profile read, with trigger
`shell` / `focus` / `foreground` / `local`. It follows the same pattern as Home's `dashboard read bundle` marker. It is
visible only at debug level (the Logger default is `off`) and carries no id or name.

## Procedure

1. Profiles mounted in four different tab stacks, each confirmed from the dump by its `More actions for <name>` header (`chk2-*.xml`):
   - **Contacts** → list row → Profile (Alex Treyger)
   - **Events** → `ZZUATW3Group` → participant `ZZ-UAT-RG034` → View profile → Profile (**reached through an event participant**)
   - **Digest** → Horizon row → Profile (Alex Sheaffer)
   - **Orrery** → Contacts in this System → Open Profile → Profile (Abbe Vallen)
   - Settings has no archived or contacts list that opens a Profile on this data (Contacts & Relationships hub checked, `s2.xml`), so Orrery supplied the fourth stack.
2. Returned to the **Settings** tab, so all four Profiles were mounted but hidden. This is the O-1 shape.
3. Dev menu → **Enable debug logging** (`uat-probe logger level debug`).
4. `scratchpad/w3/measure.sh`: start `adb logcat -v threadtime -T 1` to a file (a delta from "now"), then fire the probe through the dev menu (`keyevent 82` → tap the item located by `uiautomator dump`) N times. After each run, wait for its `fan-out end` marker plus 8 s, then capture the Metro pane and keep the segment from that run's `fan-out start` line to the end. The segments are summed, because the pane's scrollback (2000 lines) cannot hold the whole session.
5. Counted on both channels: `shared object that was already released|ERR_USING_RELEASED_SHARED_OBJECT`, `failed to load Profile snapshot`, and the shell-trigger Profile reads.

The main run delivered 800 = 200 × 4, so every tick re-read all four hidden Profiles. Each probe run of 20 ticks took about
22–32 s against a nominal 3 s. The JS thread was saturated by the fan-out (a `top` sample during the warm-up run showed the app process at 136 % CPU),
which is a heavier load than one O-1 tick. ART GCs ran inside the windows (6 in the main run, 2 in the supplement). Hermes
GC is not logged, so it cannot be timed against individual reads.

## Outcome: **BOUNDED**

0 released-shared-object errors in 200 ticks with 4 mounted Profiles (800 hidden-Profile shell reads). Also 0 in the
100-tick supplement with Home reading alongside 3 hidden Profiles. Both counts hold on both channels. The race was not
reproduced on the Pixel 3a.

Limits on this bound:
- The source of the race is upstream (expo/expo#49799), and it is timing- and GC-dependent. O-1 happened on a different device (Pixel 6 Pro) and package, right after a bulk Undo write. Zero in 1,100 reads bounds the rate on this hardware; it does not prove the race is gone.
- The probe drives reads only. O-1's tick also followed a write burst (bulk Undo). Writes use the same `prepareAsync` path, but the probe does not generate them.

## Task 2 — mitigation branch taken

**No JS mitigation: not reproduced in 200 ticks with ≥4 Profiles. The upstream race remains (expo#49799). D-25 not triggered.**
The plan makes both mitigation (A) (deferring shell ticks for hidden, unfocused Profiles) and mitigation (B) (a
single-retry wrapper for classified released-object reads) conditional on REPRODUCED. Neither was applied.
`docs/systems/profile.md` and `docs/systems/persistence-core.md` are unchanged.

Final outcome: **BOUNDED**.
