### Data layer (read in full, every writer)

- **`import_sessions` writers:** `insertImportSessionCore` validates the lifecycle with `assertSessionLifecycle`. `setSessionBatchDefaults` validates first, then inside `inWriteTransaction` counts rows with `row_status <> 'pending'`, and when any exist it rejects a differing effective lifecycle with `ImportBatchLifecycleLockedError`, writing nothing. The remaining writers are `completeSessionCore`, `discardSession`, `reassignImportSessionsCategoryCore` (category only, from `categories-dao`) and the Replace-all table wipe in `restore-apply.ts:1296`. None can write an unvalidated lifecycle.
- **`import_session_rows` writers** (the DAO transitions, `import-photo-retry`, the resume sweep, `purge-dao`): none touches lifecycle or cadence.
- **Create seam:** `importContactRecord` validates the lifecycle and spreads it after the input, so a caller cannot override it. It has 2 callers: the driver passes `sessionBatchLifecycle(session)`, read once per pass from the session only, and `import-acquire` passes the reviewed single choice. `combineCluster` takes the lifecycle that setup has just persisted. DuplicateReview "Import as new" uses `sessionBatchLifecycle(session)`. The contacts CHECK from migration 011 is the final backstop.
- **Run guard (D-74):** `withImportRun` marks the session synchronously, before the first await, and releases it in `finally`. `runImportBatch` wraps every pass (ImportProgress and ImportComplete Retry). ImportProgress follows a pass already in flight, and otherwise starts one with no intervening await, so there is no check-then-start window. Its `beforeRemove` listener blocks leaving while a pass is driven or active. The stopped setup's Discard refuses while a pass runs (`BulkImportSetupScreen.tsx:389`). ImportComplete Retry surfaces an `ImportRunActiveError` rejection as its failure notice.
