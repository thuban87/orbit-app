# Phase 38.4 Plan 07: Shared Minute Timestamps for Remaining Consumers Summary

**The new `formatTimeMinute`/`formatTimeMinuteOrFallback` pair in `src/utils/dates.ts` shares its clock renderer with `formatDateTimeMinute`. History date-detail rows, Digest day-detail rows (visible text and TalkBack labels) and the Group Event Detail "When" field now show 12-hour minute-precision time instead of 24-hour string slices or raw storage.**

## Performance

- **Duration:** ~6 min
- **Started:** 2026-09-26T19:29Z
- **Completed:** 2026-09-26T19:35Z
- **Tasks:** 2 (1 tracer + 1 auto, both TDD)
- **Files modified:** 8 (1 created)

## Accomplishments

- Added `formatTimeMinute` (throws on unparseable, like `formatDateTimeMinute`) and `formatTimeMinuteOrFallback` (returns "Unknown time"). Both parse through `parseLocalMs` and render through a private `clockOf` → `formatMinuteClock(…, TIME_FORMAT)`. `TIME_FORMAT` stays module-private and no 12/24-hour preference was added.
- Proved all fixtures: 00:00 → 12:00 AM, 12:00 → 12:00 PM, 23:59:59 → 11:59 PM, 09:05:59 → 9:05 AM, 09:06:00 → 9:06 AM. The T-separated and minute-only stored forms are also covered. For every fixture, `formatDateTimeMinute` ends with the same clock text.
- `DateDetailSheet`: deleted the `slice(11, 16)` `timeOf` helper. All 3 row captions and all 3 row accessibility labels (interaction, lifecycle, knowledge) now use `formatTimeMinuteOrFallback`.
- `DigestDayDetail`: deleted the slice helper. Both row captions and both row accessibility labels now use `formatTimeMinuteOrFallback`. A render test proves the shared fixtures and the malformed fallback reach both text and labels.
- `GroupEventDetailScreen`: "When" now shows `formatDateTimeMinuteOrFallback(event.occurredAt)`. The edit flow still receives the stored value.
- `docs/systems/interaction-history.md`: documents the time-only helper, the clock fixtures and a table of covered consumers, including the Plan 05, 06 and 12 riders. Plan 12 is marked as not yet landed. Added a 38.4 Changelog row.
