# Phase 38.4 Plan 13: Release-only overlay permission removal + Orbit launcher identity Summary

Release builds now drop `SYSTEM_ALERT_WINDOW` through a local config plugin that deletes it from the main manifest and writes a `src/release` remove marker; debug keeps its copies. **1. [Rule 1 - Bug] `--check` printed "ok" for a derivative that had just failed the pixel comparison**
- **Found during:** Task 2 negative test
- **Issue:** The safe-radius branch printed `ok` whenever the extent passed, even after a stale-pixel failure had been recorded for the same file. The exit code was already correct (1).
- **Fix:** `ok` is printed only when that derivative recorded no failure.
- **Files modified:** scripts/fit-launcher-icons.py
- **Commit:** 8b3abcf

**2. [Execution choice] droid prebuild in a throwaway sibling directory instead of the main droid tree**
- The runbook's clean reset would have wiped `C:\Users\bwales\projects\orbit-app` and any APKs another agent or Plan 17 might rely on. A separate `orbit-app-p13` directory gave the same clean-prebuild evidence without touching that tree, and it was deleted afterwards.
