## Needs owner (D-48), resolved by D-60

The owner kept the pair, so this is recorded for later reference.

**What would have to be true to remove the pair:** Orbit's backup intake (`orbit-backup-document-picker`, both `pickBackupDocument` and `captureBackupShare`) would have to accept only `content://` sources, or the owner would have to accept the edge case. That edge case is Android 7–9 + a manual "Files and media" grant + a pre-Android-7-targeting file manager handing over a raw `file://` path. With a scheme guard in place, every audit row becomes an unconditional "no". The removal would then be `android.blockedPermissions` for both entries (safe for debug too), proven by the introspect gate, a clean prebuild and Plan 17's aapt2 dumps.
