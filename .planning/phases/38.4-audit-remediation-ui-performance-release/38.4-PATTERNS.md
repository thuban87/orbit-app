### Theme-token variant pattern (D-24 Standard-Light-only darker variants)

**Analog:** `src/theme/theme-presets.ts:263-296`, the `standard.light` palette block. It is the only place Standard Light hues live, so a Standard-Light-only variant is an edit or addition here and nowhere else. Galaxy and Standard Dark live in sibling blocks and stay untouched.
```ts
    // STANDARD LIGHT (authored Plan 03) — ... deeper accent/status hues retuned for AA ...
    light: {
      background: "#F2F3F6",
      surface: "#FFFFFF",
      accent: "#4453B0",
      onAccent: "#FFFFFF",
      accentText: "#3C4AA0",
      textPrimary: "#1B1E26",
      textSecondary: "#565D6B",
      danger: "#B21D22",
      onDanger: "#FFFFFF",
      rogue: "#96591A",
      statusStable: "#1E7D5A",
      statusWobble: "#836612",
      statusDecay: "#B33A22",
```
- Per-accent `accentText` comes from `src/theme/accents.ts:63-91`. Each accent has `light: { fill, onAccent, text }`, and `applyAccent` (`:131-139`) writes `accentText: tone.text`. A Standard-Light glass-only accent-text variant therefore needs either a new tone field or a new palette key; `theme-types.ts` holds the palette type. That is planner discretion. Colour literals are allowed only under `src/**/theme/**` (`scripts/check-colors.sh` header).
- Surface-scoped override mechanism: `src/theme/theme-provider.tsx:13` `export const ThemeContext = createContext<ResolvedTheme | null>(null);` and `:69` `<ThemeContext.Provider value={theme}>`. `GlassSurface`/`ChromeScrim`/`ShellAppBar` re-provide a memoized `{...theme, colors: {...colors, textSecondary: colors.textPrimary, /* + D-24 variants */}}` only when `package==='standard' && mode==='light'` and the background is not `none`.

**Proof analog:** `src/theme/tokens/surface.test.ts:32-38` (the `TEXT_FGS`/`STATUS_FGS` lists) and `:179-208`:
```ts
const composite = alphaComposite(tint, slot.brightestPixel, cardTintOpacity(pkg, mode, "presentation"));
assertForegroundsAA(composite, palette, `${id} @ ${pkg}/${mode} ${regime} card`);
```
Add `slot.darkestPixel` (a new declared field on `BackgroundAssetSlot`, `backgrounds.ts:~38-45`, beside `brightestPixel`). Composite both, and assert that the luminance lies outside the interval (Pitfall 1). Any narrowing of the lists gets an inline written justification (D-24).
