## Deviations from Plan

### Process

**1. [Owner instruction] Release build cut before the device pass finished.** The orchestrator relayed the owner's
instruction to cut and deliver the one release build immediately. It was built from `805e95c` (no source change since the
review fixes) and delivered with a dated name. The standalone-launch check and the debug reinstall ran at the end of Task 3.
No later finding triggered a rebuild (owner: record and report instead).

**2. [Orchestrator instruction] Checkpoint commit of all rows run** (`2c40ff6`), then commits every few rows.

**3. [Scope guard wording] D-16 "unchanged since 3866df8" is not literally true.** `6407fb1` (the D-63 owner ruling)
changed three widget glyph colours in `widget-render.tsx`. RG-032 (accessible names) is untouched. Recorded in the UAT
"Scope guards".

**4. [Evidence method] Accessibility hiding judged on `uiautomator dump --compressed`.** The default dump includes views that
are not important for accessibility, so it still lists the screen behind the open dial. The compressed dump (what
accessibility services see) lists only the dial.

**5. [Evidence method] JS console evidence from the Metro pane.** `adb logcat -s ReactNativeJS` held only 11 lines. The
D-61 check used a before/after capture of Orbit's Metro pane (tmux `orbit:2.0`).

**6. [Test data] New device-local fixtures.** The existing ZZ-Sheet / ZZ-UAT-G2 fixtures match each other by name and land in
Duplicate Review, which adb cannot resolve. Seven distinctly named null-account ContactsProvider fixtures (raw ids 1008–1014)
were created for the D-57 runs.

No feature code was changed (Plan 17 prohibition). No real AI provider request was made, the Pixel clock was not changed,
and the phone's Contacts app was not used.

## Device-found defects and out-of-scope findings (plain language, with recommendations)

- **G1-f (FAIL, Plan 18):** at the largest text size, "Make this a group interaction" hides behind the keyboard and its
  Cancel button falls off the screen edge. → Stack the two buttons when they don't fit and keep the sheet above the keyboard.
- **DEFECT-1 (pre-existing):** after Quick Log → Add Note → Create Memory Instead → Edit Memory, the editor is cut off even at
  normal text size on the 3a, so its "Allow AI" switch and Save are unreachable. → Put the Edit Memory body in a ScrollView.
- **OOS-3 (Phase 40):** at the largest text size several non-sheet layouts clip (Contacts selection actions, the Settings
  phone-region value, "Poss ible match", the "View profile" button). → List for Phase 40's large-text reflow.
- **OOS-4 (pre-existing, 37.1):** Contacts → Select → Set Category offers only "Uncategorized". → One-line guard in
  `CategoryChoiceSheet` (apply the uid exclusion only when given) plus a test.
- **OOS-5 (pre-existing):** a single-contact import with edits shows "Leave import?" right after tapping Import; the
  contact is already created. → Mark the guard as leaving before the post-commit navigation.
- **OOS-6:** the debug build shows a "VirtualizedLists nested in ScrollView" error on the layout editor (debug only).
- **OOS-7:** tab buttons' spoken names include the icon glyph. → Owner TalkBack check; add `tabBarAccessibilityLabel` if
  needed.
- **OOS-8:** a Profile's Orbit Status sheet shows "Last interaction: 2026-09-27 16:38:58" with seconds. → Use the shared
  minute formatter.
- **Observation:** a Light/Dark change takes about 5 s to repaint on debug and 1.5–2.9 s on release.
