<assumption_delta_decision>
Detector fired (`chosen`/pluralization): this phase converts a single `ai_provider`/`ai_model` config
into three connection lanes with exactly one active.

- **Primary noun (now):** "AI connection" (a lane: openrouter | openai | anthropic | google | custom),
  distinct from "selected model" (dossier §J — connection identity ≠ model identity).
- **Decision: PROMOTE.** Replace the singular `ai_provider`/`ai_model` primary with the multi-connection
  model: `ai_connections` rows (defs, one per lane, each with `remembered_model`) + an
  `app_settings.ai_active_connection` pointer + `ai_enabled`. The legacy single-provider columns
  (`ai_provider`/`ai_model`/`ai_custom_*`, migration 004) are demoted to legacy/back-compat read only
  and are NOT the primary going forward.
- **The GENERATION PATH is promoted, not left alongside (review HIGH #1).** ComposeScreen currently
  resolves generation through the legacy singular settings — `service.getActiveProvider(s)` off
  `s.aiProvider` (`ComposeScreen.tsx:390`, `AiService.ts:599-601`) and the model off
  `s.aiProvider === "custom" ? s.aiCustomModel : s.aiModel` (`:392`, `:398`). Task 3 rewires this to
  resolve the provider id (lane) + model + custom endpoint from the ACTIVE CONNECTION and to gate on
  `ai_enabled`. Leaving generation on `AiSettings.aiProvider` while the new store exists is the exact
  add-alongside failure mode this delta forbids: the app would "test green" on the new store yet still
  generate through the old singular config.
- **Rationale:** the dossier requires one-active-of-many with inactive configs retained and a
  per-connection remembered model. Add-alongside (keep single `ai_provider` and bolt on a table) is the
  documented failure mode: a non-primary lane can be stored but never confirmed as the default. Promotion
  is the correct move.
- **Invariant test (accepted, Task 3):** every saved connection round-trips its remembered model through
  activate → switch-away → reactivate; exactly one connection is active at all times; and the
  `ai_active_connection` pointer is either empty or references an existing row (a dangling pointer →
  Needs Attention, never Ready).
</assumption_delta_decision>
