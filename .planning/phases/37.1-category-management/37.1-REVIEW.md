## Warnings

### WR-01: Three claimed consumer integration tests exercise no consumer code

**File:** `src/screens/category-catalog-consumer-refresh.test.ts:55-103`

**Issue:** The suite labels each case as Create, Edit, or Import Review, but every iteration calls the same local `runWiredConsumerRace()` helper. That helper instantiates only `createCategoryCatalogRefreshCoordinator`; it never imports, renders, or invokes any of the three screens. Consequently, deleting the hook from one screen, wiring the wrong commit callback, or regressing that screen's stale-selection update would leave all nine nominal per-consumer tests green. `category-consumer-contract.test.ts` adds source-string presence checks, but those do not prove lifecycle behavior. This materially overstates regression coverage for the exact cross-screen gap this plan closed.

**Fix:** Add one behavior-level harness per real screen (or extract each screen's category publication adapter and import it directly). Drive initial/focus reads out of order and assert that the screen-specific category state and selected ID publish only the newest catalog. Keep the coordinator unit tests once; do not repeat them under three consumer names.

### WR-02: Manager copy contradicts the locked UI contract

**File:** `src/screens/CategoryManagementScreen.tsx:52,667-681`

**Issue:** The owner-approved UI spec locks the save error to **“Couldn’t save this category. Your changes weren’t applied.”**, the empty state to heading **“No categories yet”** plus body **“Add a category to organize your contacts. Uncategorized is always available.”**, and the Uncategorized explanation to include **“Uncategorized is always available and can’t be renamed or deleted.”** The implementation instead says “Please try again,” collapses the empty state into “No categories yet. Add one when you’re ready,” and omits the permanence clause from the Uncategorized explanation. These are not stylistic alternatives: the missing save copy fails to tell users whether a failed mutation changed durable data, and the missing Uncategorized copy hides a product invariant.

**Fix:** Replace `SAVE_ERROR` and render the exact locked heading/body strings as separate elements; restore the complete locked Uncategorized explanation. Add exact-copy assertions to `CategoryManagementScreen.test.tsx` so later readback/error work cannot drift them again.
