# Phase 37.1 — UI Design Contract

> Visual and interaction contract for Category Management. Generated by gsd-ui-researcher and approved by gsd-ui-checker.
>
> **Ground truth:** `docs/dossier/milestone-2/phase-37.1-category-management-dossier.md`, with `HANDOFF.md` (including its Phase-16 supersession note) and Phase 37 `37-CONTEXT.md` D-03 as upstream constraints. Owner rulings on 2026-09-15 lock global visible System-name uniqueness, all-contact counts, complete delete fallout, import-default reassignment, manager hierarchy, anchored overflow, two-line names, Orrery expansion state, exact copy, success feedback, and permanent/no-undo deletion. ROADMAP's older `field_history`-style wording is superseded for this phase and must not be carried into the UI or interaction contract.
>
> Categories remain a one-category-per-contact taxonomy. `Uncategorized` is the permanent `NULL` fallback, not a category row. All data and search stay on-device; no network dependency enters any category read or mutation path.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — mature bespoke React Native / Expo design system in `src/theme/` and `src/components/ui/` |
| Preset | not applicable — React Native app; shadcn gate does not apply |
| Component library | Orbit primitives: `AppText`, `Button`, `GlassSurface`, `Sheet`, `ConfirmDialog`, `Snackbar`, `Icon`, `ShellAppBar`; React Native `ActivityIndicator`; `react-native-reorderable-list` for drag reorder; one reusable themed anchored-menu primitive introduced by this phase |
| Icon library | local semantic `@/components/icons/icon-registry`; use `sort` for the drag handle, `overflow` for the row menu, `search` for catalog search, and `warning` for destructive confirmation |
| Font | Space Grotesk for display/heading and Inter for body/label/caption, resolved through `AppText` and `TYPOGRAPHY` |

**Reuse-first contract.** Category Management extends the Phase-37 Settings language. Do not introduce another card, modal, picker, menu-icon, button, text, or confirmation family. Add/Rename use the shared compact `Sheet`; used-category fallout/reassignment uses the shared expanded `Sheet`; the final irreversible step uses `ConfirmDialog`. The one admitted primitive addition is a reusable themed anchored menu because the owner explicitly chose a row-end popover rather than a sheet for overflow actions. Extend the existing shell `Snackbar` to permit an actionless message; do not build a category-only toast. Ordinary selectors share category ordering/search logic rather than forking screen-local behavior.

## Spacing Scale

Phase usage whitelist: **4, 8, 16, 24, 32, 48, 64px**. Existing project tokens remain the source where they match; the project's extra dense-spacing token is excluded from this phase.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps and compact inline separation |
| sm | 8px | Menu-item and compact control gaps |
| base | 16px | Screen side padding, sheet field gaps, row horizontal padding, default component spacing (`SPACING.base`) |
| lg | 24px | Separation between manager list, Add CTA, and Uncategorized information |
| xl | 32px | Major section separation and empty-state breathing room |
| 2xl | 48px | Empty/error-state vertical spacing |
| 3xl | 64px | Page-level breathing room where the viewport allows it |

Exceptions:

- Every drag handle, overflow control, collapsible-section header, menu action, and category option has a minimum 44×44 touch target. This is a touch floor, not a spacing token.
- The locked category-row order is **drag handle → category content (name plus neutral assigned-contact count) → overflow icon at the far right/end**. The overflow icon must never be placed adjacent to the drag handle.
- No other spacing values may be introduced. Use 8px for dense internal gaps, 16px for row/form padding, and 24px between conceptual groups.

## Color

All values are `ThemePalette` token keys resolved through `useTheme()`; no hardcoded color or opacity literals.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `background` through the existing shell-level background host | Settings route and the field behind selector overlays; preserve the active theme/background composition rather than painting a new opaque screen layer |
| Secondary (30%) | `surface` / `surfaceElevated` via `GlassSurface` and shared overlay primitives | Category rows, menus, sheets, search fields, grouped Orrery selector sections, Uncategorized information |
| Accent (10%) | `accent`, `accentText`, `onAccent` | Primary Add/Save actions, selected reassignment/category options, active search/focus treatment, selected Orrery System row |
| Destructive | `danger`, `onDanger` | Delete action and final destructive confirmation only; paired with the semantic `warning` glyph |

Accent is reserved for:

- the single primary action on a surface: **+ Add Category**, **Add category**, **Save name**, or **Review deletion**;
- the selected category/reassignment radio or checkbox state;
- the selected Orrery System row and focus treatment already established by the selector;
- text-link treatment where an established tertiary action is required.

Drag handles, overflow icons, collapsed-section chevrons, ordinary category names, counts, and `Uncategorized` use `textPrimary`/`textSecondary` and border tokens, not accent. `danger` never decorates a normal category row; it appears only after the user opens the overflow action surface and in the explicit confirmation.

**Visual hierarchy is locked.** The full-width filled **+ Add Category** button directly above the manager list is the primary visual anchor. The ordered category list is the secondary visual mass. The separated Uncategorized block is tertiary information: lower-contrast supporting copy, no drag/action affordances, and no treatment that competes with the primary CTA or editable rows.

## Surface Inventory & Interaction Contracts

### 1. Settings reachability and manager shell

- Activate the reserved `CategoryManagement` route in the Settings stack and replace the inert reservation with a live **Categories** row in `Settings → Contacts & Relationships → Relationship Structure`, immediately after **Custom Fields**.
- The route is a child Settings screen with `ShellAppBar` title **Categories**, visible Back control, Android Back parity, bottom clearance, the existing shell-level theme/background treatment, and a vertically scrolling body.
- Initial load is an on-device SQLite read. While the first read is unresolved, render React Native `ActivityIndicator` with `color={colors.accent}`, centered in the remaining content region below `ShellAppBar` (`flex: 1`, centered axes, 24px content padding). Show no visible loading text. Give the progress control accessibility label **Loading categories** and busy/live semantics. Reorder, rename, add, and delete refresh the same committed list without replacing it with this initial-loading state.
- If the initial read fails, replace the progress control with the locked load-error copy and **Try again** button in the same centered content region. Do not render the empty state or enable Add against an unknown catalog.
- The full-width filled **+ Add Category** button is immediately above the ordered list. It is the primary visual anchor, remains reachable with zero, one, or many categories, and must not scroll behind shell chrome.

### 2. Category manager list and Uncategorized fallback

- Real categories render in canonical `display_order`; never alphabetize them. New categories append at the end.
- Each populated row uses exactly this left-to-right layout: **44×44 labeled drag handle → flexible category-content column → 44×44 overflow icon pinned to the far right**. The content column contains the category name, limited to two visual lines then ellipsized, followed by neutral secondary text **{N contact/contacts}** with correct singular/plural grammar. Counts include every assigned contact, including archived and Unbound contacts. The full category name remains the accessible label and appears untruncated in Rename/Delete surfaces.
- The overflow icon opens the owner-approved themed anchored popover beside that far-right icon. It contains **Rename**, accessible reorder actions, and **Delete**. It is not adjacent to the drag handle and must not migrate to the row's left edge.
- The whole row is not a navigation target. Tapping the name does nothing; mutation begins only through the labeled handle or overflow actions.
- After the real-category list, render a visually separated, non-draggable tertiary-information block titled **Uncategorized**, its neutral secondary **{N contact/contacts}** count (including archived and Unbound contacts), and the approved body copy. It has no overflow menu and cannot be renamed, reordered, or deleted.
- Zero real categories is valid. In that state show the locked empty copy plus the Add CTA and the informational Uncategorized row; do not reseed or imply that categories are required.

### 3. Add and Rename sheets

- Add and Rename are the owner-approved shared **compact bottom `Sheet`** flows, never dedicated screens and never native unthemed alerts.
- Add title: **Add category**. Rename title: **Rename category**. Both contain one labeled text field, **Category name**, and one action-specific secondary action plus one primary action. No generic secondary label is permitted.
- Add begins empty and uses secondary **Discard new category** and primary **Add category**. Rename pre-fills the complete current name, selects/focuses the field, and uses secondary **Keep current name** and primary **Save name**.
- Trim leading/trailing whitespace, normalize to Unicode NFC, require non-whitespace content, allow Unicode, and cap the trimmed value at **100 characters**. Reject case-insensitive duplicates across categories and reject visible-name collisions with built-in or custom Systems using **That name is already used by a System.** The edited category is excluded from category duplicate matching, so capitalization-only rename is valid.
- Validation is inline, tied to the input, announced to assistive technology, and does not dismiss the sheet. Use:
  - blank: **Enter a category name.**
  - too long: **Category names can be up to 100 characters.**
  - duplicate: **A category with this name already exists.**
  - built-in/custom System collision: **That name is already used by a System.**
- Disable duplicate submits while saving. Do not optimistically close; dismiss only after the canonical transaction commits. On failure keep the typed value and show the locked Save error.
- After a committed Add or Rename, show the existing shell snackbar for its established 6-second auto-dismiss interval (**Category added.** / **Category renamed.**) and make the matching polite accessibility announcement. Success snackbars have no action, do not reserve empty action space, and use the declared Label/Caption typography rather than a new raw text size.

### 4. Reorder

- Long-pressing the left drag handle starts reorder; dragging elsewhere in the row never does.
- The handle has accessible name **Reorder {category name}** and hint **Long press and drag to reorder categories**.
- Reorder persists on drop and normalizes all real-category positions to a contiguous sequence. While saving, keep the dropped visual order and prevent a second reorder; on failure restore the last committed order and announce the locked Save error.
- Drag cannot be the only method. The trailing overflow menu also exposes **Move earlier** and **Move later** as applicable; omit/disable Move earlier for the first row and Move later for the last row. These actions persist the same canonical order and announce the new position, for example **{name}, position {N} of {total}**.
- `Uncategorized` never participates in reorder and remains visually last.

### 5. Overflow action menu

- Introduce one reusable themed anchored-menu primitive, not a Category-specific absolute-position hack. It accepts an anchor ref/measurement, visible state, close callback, menu items, and preferred alignment; it renders through an overlay/portal above scrolling content using `GlassSurface` at `density="dense"` plus existing theme surface, border, text, danger, and radius behavior. Preserve `GlassSurface`'s package-specific treatment: its existing iOS Galaxy glow is allowed, and Android adds no `elevation` or new shadow treatment.
- The far-right icon uses semantic `overflow`, accessible name **Options for {category name}**, and `accessibilityState.expanded` while its menu is open. Measure the icon in window coordinates at open time and again after viewport/layout changes.
- Prefer placement below and end-aligned to the anchor. Clamp the menu within 16px viewport/safe-area edges; flip above when the space below is insufficient; if neither direction fits, constrain the menu height and make its items scroll without moving the anchor.
- Menu order: **Rename**, **Move earlier** (when applicable), **Move later** (when applicable), a separator, then **Delete** last with danger text/icon semantics. Every item is at least 44px high. Omit inapplicable move actions rather than leaving unexplained disabled rows.
- Only one anchored menu may be open. Opening another closes the first. Outside tap or Android Back closes this non-destructive popover without executing an action and restores accessibility/keyboard focus to the originating overflow control. Selecting an item closes the popover before opening its next Sheet/Dialog.
- The popover is modal to assistive technology while open: background descendants are hidden, initial focus moves to the first menu item, each item has role `menuitem`, and the menu exposes an accessible label tied to the category. Escape/Back behavior and focus restoration are mandatory.
- Long category names never determine menu width or push the anchor off-screen; the full name remains in accessible labels and subsequent sheets/dialogs.

### 6. Delete and reassignment

- Deletion is immediately permanent after confirmation. There is no undo, history, recoverable snapshot window, quarantine, or recovery UI. The explicit fallout preview and final destructive confirmation are the only safety gates.
- First calculate fallout from the current database snapshot. The lightweight unused path is allowed only when there are **zero contacts and zero dependent category references** (pending import defaults, custom-System rules, category-System preferences/overrides, profile category presentation, persisted Dashboard filters, and any additional audited durable references).
- **Unused path:** open `ConfirmDialog` directly. Title/message use the locked copy **Delete {name}? This can’t be undone.** Confirm label **Delete category**; secondary label **Keep category**. The dialog is destructive and therefore does not dismiss on scrim tap or Android Back.
- **Used path:** open the owner-approved expanded/detail `Sheet`. It must:
  - name the category in the heading;
  - show separate conditional count rows, omitting zero rows, for affected contacts (including archived and Unbound), pending bulk-import defaults, custom Systems/rules, category-System settings/overrides, and Profile presentation assignments; never enumerate contact names or private record contents;
  - show **Move contacts to** as a single-select control, defaulted to **Uncategorized**, followed by every other real category in canonical order; the category being deleted is absent. Pending bulk-import defaults move to this same transaction target;
  - explain that only the affected category rule/reference is removed from each custom System, unrelated rules stay intact, an emptied invalid System becomes **Needs Attention**, and presentation is not transferred to the reassignment target;
  - preserve the selected target when **Keep category** returns from the final confirmation to the sheet; never remember it beyond this transaction.
- The detail sheet's primary continuation CTA is exactly **Review deletion**. Its secondary action is **Keep category**. Choosing Review deletion opens the final shared destructive `ConfirmDialog`; its confirm label is **Delete category** and secondary label is **Keep category**. The message states the selected reassignment target plus summarized dependent cleanup. No mutation occurs before this confirm.
- During commit, disable the confirm action and keep the overlay present. Success closes the destructive overlays to reveal the updated manager. Failure leaves the category and every dependent record unchanged, returns to the sheet/dialog state, and shows the locked Save error.
- Treat the expanded sheet as a preview, not an authority snapshot. Immediately before the final transaction, re-read the category, reassignment target, and all dependency counts. If either category disappeared, the target is no longer valid, or fallout changed while the overlays were open, perform no mutation, refresh the preview, preserve the target when still valid (otherwise fall back to Uncategorized), and announce the locked Save error. The transaction itself uses the revalidated dependency set.
- If no other real category exists, the reassignment list contains only Uncategorized. Deleting the last real category is valid.
- After a committed deletion, show the existing shell snackbar for its established 6-second auto-dismiss interval with **Category deleted.** and a matching polite accessibility announcement. It has no Undo or other action and does not reserve empty action space.

### 7. Shared ordinary category selector behavior

- One shared ordering/filter model governs Add Contact, Edit Contact, Bulk Import setup/review, Dashboard bulk Set Category, Dashboard category filters, and any other category consumer found by the execution-time audit.
- `CATEGORY_SEARCH_THRESHOLD = 12`: at 0–12 real categories, render the complete canonical-order list without search; at 13 or more, render the same complete list with local case-insensitive search/filter. This threshold changes presentation only and is not a category maximum or user setting.
- Preserve each ordinary surface's established small-catalog control. At 13+, route single-select choices through one shared themed expanded category-choice `Sheet` with a labeled search field and complete scrollable results. `Uncategorized` is always a distinct last option, never a synthetic row inserted into `display_order`; replace existing **No category** copy with the canonical **Uncategorized** label.
- Multi-select category surfaces (Dashboard filters and System Builder rules) retain their established container but add the same search field at 13+. Search filters visible options only; selections hidden by the query remain selected. Show a persistent **{N} selected** count when filtering. Dashboard category filters include the null **Uncategorized** option last; System Builder exposes real category UIDs only because Uncategorized has no category-System identity.
- Clearing search restores the complete canonical list. A no-match query shows **No categories match “{query}”.** without clearing the current selection.
- With zero real categories, single-select controls and the Dashboard category filter still expose Uncategorized. Real-category-only consumers such as System Builder rules and Profile category-presentation assignment show neutral **No categories available** copy. Consumer surfaces never add inline Create/Rename/Delete affordances; management remains centralized in Settings.
- Dashboard bulk **Set Category** includes Uncategorized as the final choice. Profile category-presentation managers expose only real categories because there is no Uncategorized presentation-assignment row.
- Any selector open across a category mutation must refresh on focus/open and resolve a deleted selection safely to Uncategorized/null rather than showing a stale name.
- Profile Layout and Background assignment managers use this same complete/searchable category model for their category-override lists; long catalogs must not create an unbounded column of buttons.

### 8. System Builder category rule

- The Category rule family always exposes the entire current category set in canonical order. It uses checkbox semantics because a custom System may reference multiple categories.
- At 13+ categories, place a labeled **Search categories** field above the full option list. Filtering never clears hidden selections; the header retains **{N} selected** awareness.
- Rename updates the visible label through UID identity without changing the stored selection. Delete removes only that UID rule. If meaningful rules or explicit include overrides remain, the System continues normally; otherwise preserve it and show the canonical **Needs Attention** state.
- No chips, nested category-management modal, arbitrary cutoff, or Add Category action is introduced here.

### 9. Orrery System selector grouping

- Preserve the current anchored `GlassSurface` selector, existing selection semantics, counts, Empty/Needs Attention indicators, Manage Systems row, close behavior, accessibility focus management, and bounded scrolling.
- Replace the flat catalog with exactly three independently collapsible sections in this order: **Built-in**, **Categories**, **Custom Systems**.
- Each section header is a 44px disclosure control with `accessibilityState.expanded`; it shows a neutral item count and a semantic chevron. The section containing the selected System starts open. Other expansion state is session-only and is not persisted.
- Ordering inside Built-in and Custom Systems remains the existing canonical catalog ordering. Categories use `display_order` and never alphabetize.
- Empty Categories and Custom Systems sections remain visible. Their bodies show **No category Systems** and **No custom Systems** respectively, with no creation affordance.
- On each selector open, only the group containing the selected System starts expanded; the other two start collapsed. User expansion changes last only for that open selector session and reset on the next open. No expansion preference is persisted.
- Renaming a category updates the category-System label without changing selection. Deleting the selected category System closes any stale session selection through the existing missing-System fallback and resolves to the canonical safe System; no blank or crash state.
- Do not add selector search, favorites, recents, top-level truncation, or broader picker redesign in this phase.

### 10. Mutation feedback, synchronization, and privacy

- Category mutation commits before success is shown. Refresh manager rows, open selectors, Dashboard filters/results, Profile category presentation, Systems Management, System Builder, and Orrery catalog through existing focus/revision mechanisms; do not require app relaunch.
- Rename preserves stable ID/UID relationships everywhere; only visible text changes. Delete commits reassignment, dependent cleanup, and order normalization atomically or rolls everything back.
- Add/Rename reject visible-name collisions with all built-in and custom Systems, preserving the existing cross-kind System-name uniqueness contract and preventing ambiguous Orrery labels.
- The delete transaction reassigns all affected contacts and pending import defaults to the chosen target; removes matching custom-System category rules; removes the generated category System's preferences/overrides; falls back a persisted active selection to All Contacts; removes category Profile presentation; removes the category from persisted Dashboard filters; normalizes category order; writes durable category deletion evidence for merge restore; deletes the category; and bumps `data_revision` exactly once. A failure in any step rolls back every step.
- Durable category tombstones are backup/merge reconciliation evidence only. They are not exposed as history, Undo, recovery, or a snapshot window. Merge restore respects newer deletion evidence; replace-all restore deliberately reproduces the selected backup's exact category set and order, including zero categories, without reseeding.
- Success snackbars use the existing shell host and established 6-second auto-dismiss interval, expose their text through a polite live region, and never offer Undo or another action. Submit errors preserve typed input, chosen reassignment target, and the last committed list/order.
- Do not expose contact names, System rule values, profile data, or backup contents in delete analytics/copy. Counts are sufficient.
- No network request, telemetry, analytics, or cloud lookup is permitted. All category management and search works offline.

### 11. Consumer integration matrix

| Consumer | Identity and order contract | Mutation response |
|----------|-----------------------------|-------------------|
| Add Contact / Edit Contact | Persist numeric category ID or `NULL`; show real categories in `display_order` plus Uncategorized last; use searchable choice sheet at 13+ | Rename changes visible text only; a deleted/stale value resolves to Uncategorized and never submits a dead ID |
| Bulk Import setup and review | Persist the selected real-category ID or `NULL` in the import session; expose the complete ordered/searchable catalog | A deleted category's pending default moves atomically to the deletion target chosen in the used-delete flow |
| Dashboard category filter | Persist numeric category IDs plus the explicit null/Uncategorized choice; maintain canonical order and local search | Remove deleted IDs from saved filters before refreshing results; a filter that becomes empty uses the established unfiltered behavior |
| Dashboard bulk Set Category | Persist selected real-category ID or `NULL`; Uncategorized is the final choice | Reject a stale/deleted target and refresh the chooser; committed assignment updates list/card labels through the existing store revision path |
| Contact list/card/search and Profile summary | Category display is a live join by stable ID; never cache category names as identity | Rename appears everywhere after revision refresh; delete shows target label or Uncategorized without stale text |
| Profile Layout / Background category presentation | Persist numeric `category_id` locally and serialize category UID for portable backup identity; complete ordered/searchable real-category catalog | Rename preserves assignment; delete removes the deleted category's presentation assignment and does not transfer it to the reassignment target |
| Systems Management / System Builder | Category Systems and category rules use stable category UID; rule choices follow `display_order`, real categories only | Rename preserves membership/rules; delete removes only matching rules and generated-System preferences/overrides, retaining custom Systems in valid or Needs Attention state |
| Orrery selector / active System | Category Systems use stable UID and manager order within the Categories group | Rename preserves selection; deleting the active category System uses the existing safe All Contacts fallback and leaves no blank selection |
| Backup export / merge import | Serialize category UID, name, order, references, and deletion evidence; never infer identity from display name | Merge honors newer tombstones; visible success occurs only after the full local transaction commits |
| Replace-all restore | Restore the backup's exact category taxonomy, order, assignments, and presentation identity, including an intentionally empty taxonomy | Remove live categories absent from the selected backup; do not preserve extras and do not reseed defaults |

Every consumer reads through its store/service/DAO boundary; no screen issues inline category SQL. A consumer that cannot resolve a stored identity must show its safe fallback rather than a blank label, crash, or invented category.
