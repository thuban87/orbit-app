## Top 3 Priority Fixes

1. **Accent fill token used as link/text color (Color, 8 sites)** — WARNING. `ThingsToRememberScreen` (lines 494, 509, 537, 606, 621), `MemoryEditor` (251, 408), `MemoryCard` (115) set `color: colors.accent`. The contract (UI-SPEC "Color" → "Tertiary/link affordances use `accentText` … never the `accent` fill") reserves `accent` for fills; `accentText` is the per-palette, separately AA-tuned link tone drawn on `background`. Using the fill hue as text risks failing the Phase-23 contrast gate on some of the four packages × two modes, and is a direct contract deviation. **Fix:** replace these `color: colors.accent` text usages with `colors.accentText` — or, better, route them through `Button role="tertiary"` (which already resolves `accentText`).

2. **Primary "Add memory" CTA is under-emphasized and hand-rolled (Color + Visuals)** — WARNING. `MemoryEditor` renders the surface's primary action as an outlined `Pressable` with accent *text* (line 245-254) instead of the contract's accent-*filled* primary (`role="primary"` → `accent` fill + `onAccent` label). The sibling `RelationshipEditor` correctly uses `<Button role="primary" label="Add key person">` (line 111) — so the same surface ships two different primary treatments. The Save button (MemoryEditor 423-445) also hand-rolls the fill and uses `colors.background` as the on-accent label instead of the AA-tuned `onAccent` token. **Fix:** use the `Button` primitive (`role="primary"`) for "Add memory" and Save; delete the hand-rolled fill/label token choices so `onAccent` is honored.

3. **`ContactPicker` + `Snackbar` bypass the type/spacing scale (Typography + Spacing)** — WARNING. Both render raw `Text` with hardcoded `fontSize` (18/16/15/13) and `fontWeight` ("700"/"600") — off the sanctioned 4-size/2-weight `TYPOGRAPHY` scale — and hardcoded px spacing (16/12/8/24/20). `ContactPicker` is opened in-flow from the relationship editor (UAT flow 2). The UI-SPEC "Reuse-first mandate" expects `AppText` roles + `SPACING`/`RADII` tokens. **Fix:** migrate these two shared primitives to `AppText` roles and `SPACING`/`RADII`. (Colors are already tokenized — no `check:colors` violation.)

## Detailed Findings

### Pillar 1: Copywriting (3/4)
Contract adherence is strong and mostly verbatim:
- Empty states match exactly: "Nothing to remember yet" + body (ThingsToRemember 455-459); "Recently Deleted is empty" (RecentlyDeleted 85); "No earlier entries" (MemoryHistory 167).
- Soft-delete snackbar "Moved to Recently Deleted" + Undo (ThingsToRemember 314-322) matches the reversible, non-`danger` contract.
- Permanent-delete dialog "Delete permanently?" / "This memory can't be recovered." with a destructive `ConfirmDialog` (RecentlyDeleted 107-116) — the single `danger` action, as specified.
- Provenance captions ("Added by you" / "Imported from Contacts" / "From a shared capture", MemoryEditor 23-27) are detail-view only, per dossier §L.
- Provisional "Memory" label routed through `PROVISIONAL_MEMORY_LABEL` (single-source constant) — honors D-11.

Minor deductions:
- **Redundant "Not set"** — a current-state field with no value renders the *value* as "Not set" (ThingsToRemember 480) AND the caption as "Not set" (483). The contract's caption slot is for a "most recent" hint; showing "Not set" twice reads as a bug. Use an empty/omitted caption when unset.
- Recently Deleted expiry copy substitutes "after {N} days" for the contract's "after they expire" — this is **acceptable and correct** per D-11 (copy must match the real launch-sweep window), noted only for the record.

### Pillar 2: Visuals (3/4)
- **Focal point is weak.** The primary "Add memory" action is styled as an outlined text link (accent text on a bordered pill), so the surface has no visually dominant primary. See Priority Fix 2. On a knowledge surface whose whole job is capture, the capture affordance should be the strongest element.
- **Markers render as plain text**, not pills — "Pinned" / "Outdated" are `caption`-in-`textSecondary` text (MemoryCard 58-79). This is a11y-safe (not color-only) and within the compact-card intent, but visually flat; the contract's pill treatment would read better. Not a blocker.
- **Overflow backstop is honored structurally** — the marker row `flexWrap`s (MemoryCard 152-158) and each marker keeps a 44×44 target (151). Pinned+Outdated co-occurrence reflows; no color-only encoding.
- Blank optional metadata consumes no space (MemoryCard 82-120 conditionally renders each field) — matches the "omits blank metadata" partial-state contract.

### Pillar 3: Color (2/4)
No hardcoded color literals anywhere in the audited files (grep for hex/rgb: NONE) — the `check:colors` gate holds, and every color resolves through `useTheme().colors.*`. The score is driven entirely by **semantic token misrole**, which the gate does not catch:
- **`accent` (fill token) used as text in 8 sites** (see Priority Fix 1). The theme defines a deliberate three-token accent overlay — `accent` (fill), `onAccent` (foreground on fill), `accentText` (link tone on background), each AA-tuned separately (theme-types.ts 41-74). Using `accent` as a text color on `background` is exactly the misuse the contract calls out by name.
- **`onAccent` bypassed** in the MemoryEditor Save/Add-memory filled button — label uses `colors.background` (MemoryEditor 440) rather than `onAccent`, defeating the token that exists specifically to guarantee ≥4.5:1 on the accent fill.
- Destructive coloring is correct and isolated: only the permanent-delete path routes through `danger`/`ConfirmDialog`. Soft-delete and "Delete" (relationship) use neutral/`textSecondary`, per contract.
- Outdated/hidden de-emphasis via `opacity: 0.68` + `textSecondary` (MemoryCard 49; RelationshipEditor 90) — matches the color-free de-emphasis idiom.

### Pillar 4: Typography (3/4)
- The three phase **screens** and `MemoryCard`/`MemoryEditor`/`RelationshipEditor` consume `AppText role="display|heading|body|label|caption"` correctly — role-driven, never raw sizes. Header hierarchy (display title → heading group headers → body values → caption metadata) matches the contract table.
- **`ContactPicker` (lines 251-302) and `Snackbar` (60-74) hand-roll raw `Text`** with `fontSize` 18/16/15/13 and `fontWeight` "700"/"600" — outside the 4-size (28/20/16/14) / 2-weight (400/600) scale, and off `AppText`. `ContactPicker` is reachable in this phase's relationship-link flow (UAT flow 2). See Priority Fix 3.

### Pillar 5: Spacing (3/4)
- Phase screens and the memory/relationship editors pad and gap on `SPACING` tokens throughout (all multiples of 4) — no arbitrary spacing in the primary surfaces.
- **Radii token-category confusion:** several places set `borderRadius: SPACING.sm` / `SPACING.md` (ThingsToRemember styles 645-667; MemoryEditor 456-508) or literal `8`/`12` (RecentlyDeleted 123-129; MemoryHistory 205-215) instead of the dedicated `RADII` map the contract names. Numerically equivalent today, but it couples radius to the spacing scale and drifts from the `Button` primitive, which correctly uses `RADII[v.radiusToken]`.
- **`ContactPicker`/`Snackbar` hardcode px** (16/12/8/24/20/2/56/112) rather than `SPACING`/`RADII`. Same two-file cleanup as Priority Fix 3.

### Pillar 6: Experience Design (4/4)
State coverage is complete and, unusually, device-verified rather than asserted:
- **Empty:** all three surfaces render the contract empty copy (calm, no error styling).
- **Error:** `ContactPicker` handles load failure (`failed` → "No contacts yet"/"No matching contacts", 72-77, 165-168). Local reads can't meaningfully fail elsewhere, per the SPEC blanket dismissal; the type-parser error state is 24.2-scoped.
- **Loading:** `ContactPicker` shows an `ActivityIndicator` on its (contacts-list) read; the knowledge reads are synchronous SQLite per the read-path rule — no spurious spinners.
- **Undo:** soft-delete + relationship-delete both fire a snackbar with a working Undo (ThingsToRemember 314-322, 392-400); UAT flows 1a/1b confirm restore and that relationships are Undo-only (never in Recently Deleted).
- **Confirm-before-destroy:** permanent delete gates on `ConfirmDialog` with a Cancel path; UAT flow 5 confirms Cancel-then-confirm behaves.
- **History semantics:** promote-to-current preserves the displaced value as an earlier entry (UAT flow 6).
- **Long-text/overflow backstops:** `numberOfLines={2}` truncation on card value/note (MemoryCard 83, 89) with full text on drill-in; marker row reflows.
- Known non-app harness artifact (IME occluding "Save current value") is documented in UAT, not an implementation defect.
