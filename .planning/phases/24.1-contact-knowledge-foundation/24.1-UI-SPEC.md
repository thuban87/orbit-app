# Phase 24 — UI Design Contract

> Visual and interaction contract for the Contact Knowledge Foundation phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform:** React Native / Expo (Android-first, portrait-locked). There is **no web design system, no shadcn, no Radix/base-ui**. The design system is the Orbit **theme-token system** established in Phase 23 (`src/theme/`), consumed through `useTheme().colors.*`. Every colour in this contract is a **token name**, never a hex literal — the `npm run check:colors` gate rejects raw colour values anywhere in `src/`, including Skia. This spec therefore reuses the existing token vocabulary rather than declaring new palette values.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (RN app — Orbit theme-token system, not shadcn) |
| Preset | not applicable |
| Component library | none — Orbit shared primitives in `src/components/ui/` (`AppText`, `Button`, `Modal`, `Sheet`, `ConfirmDialog`, `GlassSurface`) + `Icon`/`StatusGlyph` |
| Icon library | Ionicons via `@expo/vector-icons`, addressed **only** through the semantic registry `src/components/icons/icon-registry.ts` (D-05 — one icon source, never a raw Ionicons name in a screen) |
| Font | `Space Grotesk` (display/heading) + `Inter` (body/label/caption), bundled; remapped in `AppText` |

**Reuse-first mandate.** These surfaces are compositions of existing primitives. The Memory / Things-to-Remember editor is a sibling of `src/components/FuelEditor.tsx` (typed items, per-item pill, Off-Limits marker, parent-owns-persistence + `load()` posture). Custom-field value inputs reuse the type→widget map in `src/components/field-widgets/` (the `FieldWidgetProps` controlled-over-TEXT contract). Dropdowns/pickers reuse the zero-dependency `Pressable + Modal + FlatList` idiom (`DropdownFieldWidget`, `KindPicker`). Do not introduce a new picker/list library.

## Spacing Scale

Uses the existing `SPACING` token map (`src/theme/tokens/spacing.ts`) verbatim — all values are multiples of 4. Do **not** invent per-screen spacing.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, pill inner padding, metadata gap |
| sm | 8px | Compact element spacing, chip gaps |
| md | 12px | Dense row inner padding (grid-aligned; the intentional "compact within components" step) |
| base | 16px | Default element spacing, card padding |
| lg | 24px | Section padding, group separation between Things-to-Remember groups |
| xl | 32px | Layout gaps between major surface regions |
| 2xl | 48px | Major section breaks |

Exceptions: **44px minimum touch target** (`MIN_TOUCH_TARGET`, `button-roles.ts`) is a target-size floor, **not** a spacing token — every tappable Memory row action, pin toggle, AI toggle, visibility override, and restore/delete control pads up to ≥44×44 even when its glyph is 16–20px. Radii come from the separate `RADII` map (`sm 8 / md 12 / lg 16 / xl 24 / pill 999 / full 9999`); cards use `md`/`lg`, pills use `pill`, avatars/circular icon buttons use `full`.

| heading | 20 | 600 (Space Grotesk) | 25 (1.25) | textPrimary | Things-to-Remember **group** headers (Featured/current, then grouped detail) |

| caption | 14 | 400 (Inter) | 20 (1.4) | textSecondary | Provenance line, meaningful-date, "most recent" hint, Off-Limits helper, outdated marker, deleted-timestamp |

## Color

RN token system — the 60/30/10 discipline maps onto the existing `ThemePalette`. **All four theme packages × modes (galaxy/standard × light/dark)** resolve these tokens; nothing here is a fixed hue. Functional content must meet the AA-equivalent contrast the Phase-23 gate enforces.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `background` | Screen background behind the Things-to-Remember surface, Recently Deleted list, drill-in backlist |
| Secondary (30%) | `surface` / `surfaceElevated` | Memory cards, field-group containers, picker sheets (`surfaceElevated`), relationship rows |
| Accent (10%) | `accent` / `onAccent` / `accentText` | See reserved-for list below |
| Destructive | `danger` / `onDanger` | Permanent-delete confirm affordance only (see Copywriting) |

**Accent reserved for (explicit — never "all interactive elements"):**
- The one **primary** action per surface — the "Add memory" primary `Button` (role `primary` → `accent` fill + `onAccent` label).
- The **Confirm / Save** primary in a Memory editor, and the **Restore** primary in Recently Deleted.
- The **selected** state inside a picker (kind/type/relation-type option renders in `accent`, matching `KindPicker`).
- **Tertiary/link** affordances use `accentText` (the accent-as-link tone), e.g. "View all", "Open link", drill-in chevron label — never the `accent` fill.

**Status, AI, and Off-Limits colour rules (do not invent tokens):**
- The **AI-enabled sparkle** is tinted `accentText` (a positive, in-theme emphasis), never `danger`. AI-off items show **no** sparkle (absence is the off state) — never a red/negative marker.
- **Off Limits is NOT a danger/destructive colour.** Off Limits is a *state*, not an *action* (mirrors the `rogue`-vs-`danger` distinction already documented in `theme-types.ts`). Render it as a distinct **caution** using `borderStrong` outline + a pill (`border` outline, `textSecondary` text), the established `FuelEditor` off-limits treatment — visible by default, never hidden, never `danger`.
- **Outdated / inactive** Memories read as de-emphasized via `textSecondary` + reduced opacity over `border`, never a new "muted" hex — the same colour-free de-emphasis idiom `ContactCard` uses for neutral status.
- **Type-parser error/flagged** custom-field values (a value that fails the target type's parser after a type change — never coerced or cleared, ADR-014/D-06) render as an **error state on the profile** composed from `accent + borderStrong` emphasis (the documented "tap-to-fix" idiom; there is deliberately **no dedicated error token** — the owner may add one at a future gate, do not invent one here).

## Copywriting Contract

> **⚠ TERMINOLOGY FLAG (D-11 / R-01) — read before treating any "Memory" string as final.** The **surface name "Things to Remember" is [DECIDED]** and safe to use. The **type name "Memory"** is the dossier's kept working name (R-01: "'Memory' is the type name Phase 3 keeps") but is an **open owner reconciliation item**, and the **default/general built-in Memory type name is explicitly unresolved** and "needed before Phase 13 planning," not this phase. Every user-facing string below that contains the word **"Memory"** is therefore **provisional** — the planner must treat the label as a single-source constant (one copy module), not hardcode it per screen, so a later rename is a one-file edit. Rows depending on the *default type name* are marked 🧪 backstop and must not be invented here. This is a flag, **not** a blocker: the phase's schema/model is buildable with "Memory" as the provisional label.

| Element | Copy |
|---------|------|
| Primary CTA (Things to Remember) | **"Add memory"** *(provisional label — see flag)* |
| Section grouping | Featured/current information first, then grouped detail; groups are **visually grouped, not one feed** (dossier §G). Group headers use type/group display names from the **central registry**, not hardcoded per screen |
| Repeatable-group summary cap | Show ~3 items per repeatable group, then **"View all"** (tertiary, `accentText`) → drill-in backlist (dossier §J; master-handoff "caps repeatable summaries around three items") |
| History-aware field (Last Talked About / Current Location) | Profile shows only the most recent value; a **"most recent"** caption + a drill-in affordance to the full backlist; backlist entries offer **Edit** and **Make current** (promote-back-to-current, dossier §E) |
| Empty state — Things to Remember | Heading: **"Nothing to remember yet"** · Body: **"Add birthdays, gift ideas, key people, and anything worth bringing up next time."** *(provisional wording; calm, no error styling)* |
| Empty state — Recently Deleted | Heading: **"Recently Deleted is empty"** · Body: **"Deleted memories appear here and are removed automatically after they expire."** (expiry copy must match the launch-sweep retention window the plan sets — no promised timer, D-11) |
| Empty state — drill-in backlist | **"No earlier entries"** |
| Error state — type-parser flag | Inline on the item: **"This value doesn't match the {type} format — tap to fix."** The value is **preserved and shown**, never coerced or cleared (D-06) |
| Off-Limits marker | Pill: **"Off limits"** + caption **"A topic to avoid bringing up."** — the **new avoid-topic semantic** (dossier §N), NOT the legacy `FuelEditor` copy "Never shared with AI, never shown at a glance" (that wording predates this phase's model and must be updated where Off Limits now surfaces). Off Limits stays **visible by default** |
| AI-enabled marker | Sparkle glyph + accessible label **"Shared with AI"**; AI-off items carry no marker and an accessible label is only needed on the toggle control itself |
| Per-item AI toggle | Label **"Allow AI to use this"**, default **OFF**, disabled/greyed with helper **"Turn on AI in Settings first"** when the global AI gate is off (two-gate model, D-08) |
| Provenance (detail view) | Lightweight caption, e.g. **"Added from Contacts app"** / **"Added by you"** / **"From a shared note"** — detail/edit views only (dossier §L) |
| Destructive confirmation — delete a Memory (soft) | **Low-emphasis, reversible, no scary dialog.** Action **"Delete"** moves the item to Recently Deleted; a brief confirmation/snackbar **"Moved to Recently Deleted"** with **Undo**. This is soft-delete (dossier §I) — it is NOT styled `danger` |
| Destructive confirmation — permanent delete (Recently Deleted) | **"Delete permanently?"** · body **"This memory can't be recovered."** · destructive `Button` (role `destructive` → `danger` fill + `onDanger` label + reserved `warning` glyph). This is the ONE `danger`-styled action in the phase |
| Mark outdated | **"Mark outdated"** (keeps the item, de-emphasized) / inverse **"Mark current again"** — never a delete (dossier §I) |
| Pin | **"Pin"** / **"Unpin"** |
| Visibility override | **"Hide from Profile"** / **"Show on Profile"** — caption clarifies **"Presentation only — this doesn't hide it from search or AH."** i.e. it is **not** a privacy rule (dossier §G) |

## UI Considerations

State-coverage probe over 8 described surfaces (E1 Things-to-Remember · E2 Recently Deleted · E3 history drill-in backlist · E4 Memory card · E5 custom-field value widget · E6 per-item AI toggle · E7 kind/type/relation picker · E8 repeatable-group summary). 54 raw candidate considerations; resolved below as **7 covered (explicit) · 3 backstop · 1 unresolved**, with two documented blanket dismissals.

**Blanket dismissals (grounded in project rules — apply to every surface above):**
- **`loading`** — N/A for all read surfaces. Reads are on-device SQLite and render synchronously; CLAUDE.md forbids any blocking network call on a read path, so there is no async/skeleton/spinner state to design. (The one *label*-resolution wrinkle that looks loading-shaped — the unresolved default-type name — is captured as its own backstop row below, not a data-loading state.)
- **`populated`** — the nominal populated state **is** the primary design contract above (Design System / Typography / Color / Copywriting). Not re-specified here.
