# Phase 24.1: Contact Knowledge Foundation — Model, Storage & UI - Context

**Gathered:** 2026-09-02 (split from Phase 24 on 2026-09-03; shim — phase pre-discussed externally, the dossier is the decision record)
**Status:** Ready for planning

<domain>
## Phase Boundary

**Split note (2026-09-03, owner-approved):** the original single Phase 24 was split at the migration seam into **24.1** (this phase) and **24.2**. 24.1 builds the additive knowledge model, its storage/DAO layer, and the unified "Things to Remember" UI. 24.2 owns the destructive data-move (migration 017 + the ADR retiring ADR-030), egress/AI-permission, bounded search, the expanded custom-field type set + value history, imported notes, and backup coverage.

**24.1 scope (KNOW-01…09):** Define and build Orbit's durable contact-knowledge model as **additive schema only** — typed Memory items from one central application-owned registry (plus a user-labelled generic Custom type), structured relationships, current-state history (Last Talked About, Current Location) with backlist + promote-to-current, and per-item notes/links/dates/pinning/outdated/visibility-override/provenance — with soft-delete + Recently Deleted (launch-sweep expiry, never a timer), all presented in the unified "Things to Remember" surface. This is the foundation 24.2 and later phases consume.

This phase was fully interrogated outside GSD (milestone-2 dossier process, amended per the 2026-09-01 cross-dossier audit). The dossier in canonical_refs is the authoritative decision record; this CONTEXT.md is a shim pointing at it, not a substitute.
</domain>

## Implementation Decisions (24.1-tracked)

### Ground truth and process
- **D-01:** Read the phase dossier (canonical_refs) IN FULL before planning. Where present, its dated "Amendment — audit resolutions 2026-09-01" section overrides older text. [DECIDED] and [REJECTED] items are settled: reopening one, or reversing any Accepted ADR or HANDOFF.md entry, is an owner decision — stop and ask, never "fix" it.
- **D-02:** Read the phase planning-notes file (canonical_refs) as a binding appendix: every REPLAN finding must be reflected in the plan, and every trip-wire is a stop-and-ask. This dossier's audit outcomes live in the planning notes as owner resolutions of 2026-09-01, which are therefore load-bearing.
- **D-03 (this phase's migration):** 24.1 ships the milestone's **largest additive migration**. Never assume a migration number — verify head+1 against `src/db/migrations/` and `TARGET_VERSION` in `src/db/database.ts` on disk at plan time (numbers drift every schema phase). 24.1's migration is **additive only** (new tables/columns; no destructive data-move — that is 24.2). Strictly ordered, forward-only, must assume no particular starting state. All new durable preferences are `app_settings` columns added to `PORTABLE_SETTINGS_KEYS`, never AsyncStorage.

### Phase-specific constraints
- **D-04 (R-01 REPLAN):** The Contact Knowledge model is **almost entirely unbuilt** — no type registry, no Custom type, no notes/dates/pinning/visibility/outdated flags, hard DELETE instead of soft-delete, `source` is a string only, **no relationships table at all** (Phase 8/Orrery's assumed "existing structured relationship model" does not exist), no Last Talked About or Location history, and no per-item AI permission. Plan against the code on disk, not the assumed model.
- **D-05 (ADR-028 ESCALATE trip-wire):** A **Custom type with a user label** is compatible only while the kind set stays application-owned. **User-created system types would reverse ADR-028 → stop and ask the owner.** Users get flexibility via the Custom type only. Memory types come from one central application-owned registry (display, cardinality, history behavior, searchability, AI defaults, presentation).
- **D-10a (R-01 resolutions):** This phase **owns the Recently Deleted / Trash surface** (reassigned from a possible Phase 15 owner — no longer an orphan). *(The share-sheet capture migration and the ADR-030 AI-proposed-fuel retirement move to 24.2 with migration 017.)*
- **D-11 (R-01 trip-wires):** Nothing watches a timestamp — Trash expiry and history retention run as a **launch sweep**, never a background timer (analog: `registerSweepHook`). And confirm **"Memory" as final terminology with the owner** before naming schema after it; the default/general built-in Memory type name is an open reconciliation item needed before the Rapid Capture phase plans — build with a single-source provisional constant and surface the final name as `human_needed`.

### Claude's Discretion
- Everything the dossier marks [DERIVED], plus open implementation details that do not touch a [DECIDED] item, an ADR, or a HANDOFF.md entry.

### Cross-phase guardrails (informational — enforced here, implemented in 24.2)
These constrain 24.1 but are not implemented as 24.1 plan work; do not relax them:
- **[informational] ADR-001 (D-06 guardrail):** 24.1 does not touch the custom-field storage model. Do not relax `UNIQUE(contact_id, field_def_id)` or `custom_field_values.uid UNIQUE`; `custom_field_values.value` stays raw TEXT routed through `sortExpr()`. The additive value-history table and the `scope` column belong to 24.2.
- **[informational] Off Limits / AI egress (D-08/D-09):** per-item AI permission and the Off Limits SQL exclusion are built in 24.2. 24.1 must not send any Memory to AI; Group Notes are never sent under any state.
