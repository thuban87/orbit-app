### Resolved failure — targeted Profile edit affordance

**Reproduction (physical Pixel, no UI-only inference):**

1. Open synthetic `UAT Ada` from Contacts.
2. Expand `Things to Remember` using its separately exposed header target.
3. Dump the accessibility tree: `Edit Things to Remember` is an enabled, clickable Button at `[1171,1486][1325,1640]`.
4. Tap its center (`1248,1560`) once through the physical-device adb transport.
5. The screen remains `contact-profile-screen`; the edit destination does not appear. The section remains expanded, proving this isolated tap did not merely trigger the adjacent collapse action.

Source inspection confirms the intended owner route exists (`ThingsToRemember` for memories; `MemoryHistory`, `OffLimitsEditor`, and `Edit` for the other targeted owners), but the real Pixel tap does not reach the expected destination. Two reversible, uncommitted in-class attempts — elevating the existing action and substituting the shared icon-only Button — did not alter the result and were reverted. No speculative source change remains.

**Diagnosis and fix:** The header action passed the top-level `"things-to-remember"` layout ID into the child-only knowledge router. It was a valid accessible target but matched no child route, so its press was a no-op. Commit `39ab1c7` maps the header action to the `memories` child owner and centralizes the child-to-editor destination contract; regression tests invoke the rendered press and prove it resolves to `ThingsToRemember`.

**Physical retest:** PASS — after force-stopping and relaunching the debug build, I opened `UAT Ada`, tapped the same enabled `Edit Things to Remember` target at `[1171,1486][1325,1640]`, and observed the full `Things to Remember` editor with its Back action. The resulting UI dump is retained locally at `/tmp/orbit-381-profile-edit-pass.xml`.

**Disposition:** RESOLVED / PASS for the targeted affordance. The phase remains unverified until the remaining matrix and backstops below are completed.
