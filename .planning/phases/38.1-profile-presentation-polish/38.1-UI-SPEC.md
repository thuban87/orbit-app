# Phase 38.1 — UI Design Contract

> Visual and interaction contract for the Profile & Presentation Polish phase. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Authoritative product contract is the dossier** (`docs/dossier/milestone-2/phase-38.1-profile-presentation-polish-dossier.md`)
> and the enforced guards D-01..D-08 in `38.1-CONTEXT.md`. This UI-SPEC translates §B–§L into
> concrete token/interaction contracts; where a dossier decision and an instinctive design choice
> conflict, the dossier wins. Everything below is expressed against the EXISTING theme-token system —
> this phase adds **one** new named token treatment (Orrery overlay) and otherwise reuses tokens
> already on disk. No schema, no `BACKUP_FORMAT_VERSION` bump (D-02).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (React Native / Expo; no shadcn, no `components.json`) |
| Preset | not applicable |
| Component library | Project-native primitives (`src/components/**`) over React Native; `AppText`, `Icon`, `GlassSurface`, `Button`, `ConfirmDialog` |
| Icon library | Existing in-repo `Icon` primitive resolving through `ICON_SIZE` tokens (no new icon set; §C keeps current glyphs) |
| Font | `Space Grotesk` (display/heading), `Inter` (body/label/caption) — both already loaded via `AppText` |

**Colour rule (CLAUDE.md, non-negotiable):** every colour resolves through a `ThemePalette` token via
`useTheme().colors[key]` — including Skia draw calls. No hex literals outside `src/theme/**`
(`accents.ts`, `theme-presets.ts`, and the `surface.ts` composite helper are the only sanctioned
literal homes; `check:colors` enforces the location exemption). The new Orrery overlay treatment
(D-04) is a token in `src/theme/tokens/surface.ts`, AA-proven in `surface.test.ts` — never a component
hex.

**Theme axes (ADR-087):** two independent axes — art **package** (galaxy | standard) × appearance
**mode** (dark | light) = four combos. Every AA/contrast claim below states which combo(s) it covers.
Standard and Galaxy keep identical information architecture and interaction semantics (§M).

## Spacing Scale

Declared values (source of truth: `src/theme/tokens/spacing.ts` — all multiples of 4; `md=12` is an
intentional grid-aligned step for dense row inner padding). **Do not introduce new spacing values in
this phase** — compose from these tokens only.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps; the tight consistent gap BETWEEN the three Orrery nav controls (§C) |
| sm | 8px | Compact element spacing; edit-icon inset from heading (§G) |
| md | 12px | Dense row inner padding |
| base | 16px | Default element/section spacing |
| lg | 24px | Section padding; Most Recent → Previous block separation (§F) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |

Exceptions: **44×44px minimum touch target is a floor, not a spacing token.** It binds the three
icon-only Orrery controls (§C "size means icon plus appropriate padding/touch target, not a tiny
intrinsic-icon box") and every heading-level Profile edit icon (§G). The visible square may present at
the design size, but the tappable hit area must reach 44×44 (use hitSlop where the visual is smaller).

## Typography

Source of truth: `src/theme/tokens/typography.ts` — exactly 4 sizes, exactly 2 weights, 5 semantic
roles. Screens consume ROLES (via `AppText`), never raw sizes. This phase adds no new roles.

| Role | Size | Weight | Line Height | Family | Colour token | Usage in 38.1 |
|------|------|--------|-------------|--------|--------------|---------------|
| Display | 28px | 600 | 34px (1.2) | Space Grotesk | textPrimary | Not introduced by this phase |
| Heading | 20px | 600 | 25px (1.25) | Space Grotesk | textPrimary | The single owning section heading per Profile section (§D) |
| Body | 16px | 400 | 24px (1.5) | Inter | textPrimary | Knowledge values (the Most Recent value, Previous items) (§F) |
| Label | 14px | 600 | 20px (1.4) | Inter | textPrimary | `MOST RECENT` / `PREVIOUS` subsection labels (§F); Grid card name row (§L) |
| Caption | 14px | 400 | 20px (1.4) | Inter | textSecondary | Dates under each knowledge item; Grid recency row (§L); minute-precision timestamps (§K) |

**Heading-ownership rule (§D/§E, drives D-07):** a section heading uses the **Heading** role and is an
**identifier only** — no appended current value, count, metadata, or empty-state copy. Parent
containers (`ProfileModuleHost`) own the section heading; nested renderers
(`ThingsToRemember`/`knowledge-presentation`) must not repeat a heading their container already
supplied. Content state (value, "nothing yet", counts) lives in the body using Body/Caption roles.

## Color

All values are palette TOKENS (`src/theme/theme-types.ts`), resolved per package×mode at render — no
hex here. The "60/30/10" split maps onto Orbit's token roles:

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `background` (+ the selected background art beneath the veil) | App/screen backdrop; the Orrery canvas itself |
| Secondary (30%) | `surface` / `surfaceElevated` | Content cards, Profile module cards, sheets, Orrery overlays' tint base |
| Accent (10%) | `accent` (fill) / `onAccent` / `accentText` trio | See reserved-for list below (per-package configurable via `ACCENTS`; default galaxy=nebula-blue, standard=slate-indigo) |
| Destructive | `danger` fill + `onDanger` foreground | Unbind lifecycle action + any meaningful record deletion confirmation (§G/§H) |

Accent reserved for: **edit-icon affordances at heading level (§G)**, the **active/selected state of an
Orrery nav control (§C) if a pressed/active state is shown**, and **existing primary actions inside the
reused editors (§G)**. Accent is NOT applied to section headings, knowledge values, timestamps, Grid
rows, or the Orrery overlay surface tint. Status hues (`upcoming`/`wobble`/`decay`) are DISTINCT from
`danger` and are not repurposed here.

**Orrery overlay surface (D-04 — the one new token this phase adds):**
- Add a **new named surface treatment** to `src/theme/tokens/surface.ts` for Orrery floating overlays,
  AA-proven in `surface.test.ts` against the **actual Orrery backdrop** (not the generic asset set).
- It must render **translucent in ALL FOUR package×mode combos** — including the mismatched combos
  (galaxy-in-light, standard-in-dark) where ordinary content cards fall back to the opaque density
  band. The Orrery canvas is a controlled render surface, not mismatched wallpaper, so the overlay
  stays glassy everywhere while remaining opaque enough for effortless text/control readability
  (§B: "readable but still reveal the orrery behind them").
- It **must NOT fork `GlassSurface`** or spawn a parallel component family (ADR-087) — it is a new
  token treatment routed through the existing `surface.ts` token API, riding on top of ADR-115's
  independent-tokenized-layers model (not an ADR-115 reversal).
- It **must NOT change `CARD_GLASS_OPACITY`** (galaxy `0.05` / standard `0.5`) or ordinary
  content-card opacity. Today the overlays render via `GlassSurface density="dense"` →
  `cardTintOpacity()` → near-transparent galaxy `0.05` (the §B legibility complaint); the fix
  decouples them onto the new treatment, it does not retune the shared card constant.
- Exact tint opacity value is Claude's discretion (D-04), **tuned on-device against the Orrery** and
  AA-proven; do NOT expose a user opacity control (§P deferral).
- Apply the treatment consistently across the named overlays: `OrreryControls`, `OrrerySystemSelector`,
  `OrreryFocusContext`, `OrreryClusterPanel`, `OrreryViewOptions` (and comparable overlays).
  `OrreryContactsSheet` does not use `GlassSurface` today — verify at plan time whether it needs the
  treatment for consistency (§R item 1).

## Copywriting Contract

Reuse existing copy where it already exists; do not invent new strings beyond what a decision requires.

| Element | Copy |
|---------|------|
| Primary CTA (§F/§G Profile knowledge) | Heading-level **edit icon** (accessible name `Edit {section name}`, e.g. "Edit Things to Remember") — replaces the removed full-width/row `Manage` affordance; opens the existing editor for the WHOLE collection, not just the latest item |
| Temporal subsection labels (§F) | `MOST RECENT` (latest) and `PREVIOUS` (older) — Label role; shown only when records exist |
| Empty state heading (§D/§F) | Section heading stays an identifier only, e.g. `Things to Remember` — NEVER `Things to Remember · Nothing added yet` (remove the appended metadata class; do not make the inference smarter — D-07) |
| Empty state body (§F) | Neutral in-body empty state (e.g. `Nothing added yet`) rendered in the section BODY, not the heading; with zero records show the neutral state, never empty `MOST RECENT`/`PREVIOUS` subsection shells |
| Single-record state (§F) | Show `MOST RECENT` only; omit the `PREVIOUS` subsection entirely (do not render an empty `PREVIOUS`) |
| Error state | No new network/error surfaces in this phase (local-first read paths, no new fetch). Editor-level validation reuses existing editor error behavior; no new error copy introduced |
| Destructive confirmation — Unbind (§H) | `Unbind contact` moves from the Profile body into the Profile **overflow menu**, presented as a lifecycle/destructive-style action (NOT equated with deletion). Preserve the EXISTING confirmation dialog and lifecycle behavior verbatim (ADR-062 / ADR-118) — placement-only move |
| Destructive confirmation — record delete (§G) | Meaningful record deletion inside a reused editor uses normal confirmation (`ConfirmDialog`, `danger`/`onDanger`); ordinary edits require NO confirmation |

**Timestamp format (§K / D-08):** all explicit user-facing timestamps display through the **minute**,
defaulting to **12-hour** — `Sep 19, 2026, 7:14 PM` (never `7:14:37 PM`, never raw
`YYYY-MM-DD HH:MM:SS`). Route through **one shared minute-precision formatter added beside
`formatLocalDate` in `src/utils/dates.ts`**, reading the format from a single source so a future user
12/24h toggle is a one-line add (the toggle itself is DEFERRED to a candidate 38.2 — it needs an
`app_settings` migration, out of scope for D-02). Do NOT add a 9th ad-hoc `HH:MM:SS` builder. Known
offenders to reformat: `src/db/profile-history-read.ts:73` → Profile "Last Interaction" tile
(`RelationshipOverview.tsx`), and Interaction Detail "When" row (`interaction-detail-logic.ts:96` →
`InteractionDetail.tsx:168`). **Relative-time strings ("Yesterday", "5d ago", "2 hours ago") are
UNAFFECTED and stay as-is.** Stored/internal precision is unchanged. Use `formatLocalDate()` / the
shared formatter — never `toISOString().split('T')[0]` (UTC off-by-one hazard, CLAUDE.md).

## Interaction Contracts (phase-specific)

These are the interaction rules the executor must implement; they are additive to the token contracts
above and are all locked by the dossier + D-NN.

**Orrery navigation controls (§C):** replace the single combined card
(`OrreryControls.tsx:89-142`, containing Contacts / Recenter / Reset-north) with **three independent,
equally-sized square controls**, tightly grouped with a consistent `xs` (4px) gap. Remove visible
button text; keep the current icons. Each uses the new Orrery overlay surface treatment. Each keeps its
existing explicit accessible name — `Contacts in this System`, `Recenter Orrery`, `Reset north` (a11y
labels already present; preserve them). Square size = icon + padding reaching the 44×44 touch floor.
Keep icons unless label removal reveals a genuine comprehension problem during UAT (§C/§P).

**Profile editing affordances (§G / D-06):** remove applicable full-width/row-level `Manage`
affordances; add an **edit icon beside the relevant subsection/row heading** (accent-tinted, ≥44×44
hit target). Separate view from edit: tapping content uses its normal view/detail behavior; tapping the
edit icon enters editing. The edit icon manages the **whole collection**, not just the displayed/latest
item. Editing stays on **dedicated screens** (no inline full-editor expansion on Profile). Wire thin/
broken routes to the **existing** editors with no new model/fields — specifically **Off Limits' edit
affordance reuses `src/components/FuelEditor.tsx`** (today reachable only from `EditContactScreen`; it
currently mis-routes to `ThingsToRememberScreen`, which has zero off-limits handling). Reuse mechanism
(extraction vs navigation) is Claude's discretion at plan time (D-06).

**Contact binding lifecycle (§H):** remove the prominent `Unbind contact` button from the Profile body
(`ContactProfileScreen.tsx:379-396`); add it to the Profile overflow menu (`profileOverflowEntries()`).
Preserve existing confirmation + lifecycle semantics (placement-only; ADR-062/ADR-118). For an already
Unbound contact, KEEP the meaningful Bind experience on the Profile body (binding requires
configuration and communicates lifecycle state).

**Relationship Overview width toggle (§I / D-05):** the existing compact/wide (`set-size`) toggle in
`ProfileLayoutEditor.tsx:149-164` (for `orbit-status` + `last-interaction`) is **KEPT**. The §I/§P
"no manual width controls" wording means no NEW controls. Orphan-stretch is **visual-only** — it fills
a would-be-blank half-row and never overrides the user's explicit compact/wide choice or a card's
semantic size.
