<domain>
## Phase Boundary

A bounded, post-Phase-38 presentation-contract pass across four surfaces — **Orrery**, **Contact
Profile**, **Interaction History**, and **Contacts** — so Phase 39 Onboarding teaches the cleaned-up
product. It corrects presentation regressions and interaction friction, makes existing Profile
knowledge genuinely editable **using the current data model**, and closes with a bounded audit for
the same defect classes established here.

It does **not** add new relationship-domain concepts, new knowledge fields, or a schema/backup-format
change, and it does not broadly redesign Profile, Contacts, Orrery, or History. The named work is:
Orrery overlay legibility + three uniform icon-only nav controls (§B/§C); Profile heading ownership +
false empty-state fix + module-semantics classification (§D/§E); Most Recent/Previous temporal
knowledge with a five-item Profile preview (§F); heading-level edit affordances reaching functional
editors (§G); Unbind moved to overflow (§H); Relationship Overview orphan-stretch + centered content
(§I); vertical Year heatmap (§J); app-wide minute-precision timestamps (§K); Contacts Grid excerpt
removal (§L); bounded cross-app audit + physical-device UAT (§N/§O).

**Trigger to plan:** Fired. Owner-approved 2026-09-19 to run before Phase 39. Plan against the dossier
as the authoritative contract.

<decisions>
## Implementation Decisions

These D-NN are the cross-cutting **enforced guards** and **owner rulings** that must reach plan-phase.
They do not replace the dossier — read it in full first.

### Contract & scope
- **D-01:** The authoritative product contract is
  `docs/dossier/milestone-2/phase-38.1-profile-presentation-polish-dossier.md`. Plan against it, not
  against this shim.
- **D-02:** **No schema and no backup-format change in 38.1** (no migration, no
  `BACKUP_FORMAT_VERSION` bump). The phase reuses the existing data model only. Discovering a
  migration need here is a **stop-and-confirm**, not a licence to add one. — **Reversibility:**
  one-way — a shipped migration is irreversible in production (data-layer rule); this guard exists to
  keep one out of a polish phase.
- **D-03:** Do **not** decompose one-plan-per-bullet. Group changes by coherent ownership per dossier
  §Q (the ~6-group shape is guidance, not a mandated plan count). Do not opportunistically redesign
  Profile/Contacts/Orrery/History while polishing (§P deferrals hold).

### Orrery surface (owner ruling — §B/§C)
- **D-04:** Orrery floating overlays get **their own semantic surface treatment**, added as a **new
  named token treatment in `src/theme/tokens/surface.ts`** and **AA-proven per `surface.test.ts`**
  against the actual orrery backdrop. It must **stay translucent in ALL theme/mode combinations**
  (including mismatched package/mode — the orrery canvas is a controlled render surface, not
  mismatched wallpaper), decoupled from ordinary content-card opacity. It must **NOT** fork
  `GlassSurface`/spawn a parallel component family (ADR-087) and must **NOT** change the ordinary
  content-card `CARD_GLASS_OPACITY` values (galaxy `0.05` / standard `0.5`). This rides *on top of*
  ADR-115's independent-tokenized-layers model; it is not an ADR-115 reversal. Owner decided
  2026-09-19 with the ADR-087/ADR-115 tension surfaced. — **Reversibility:** reversible (token +
  test).

### Relationship Overview width (owner ruling — §I/§P)
- **D-05:** **Keep** the existing compact/wide (`set-size`) toggle in
  `src/components/profile/ProfileLayoutEditor.tsx:149-164` (for `orbit-status` + `last-interaction`).
  Dossier §I "do not add manual width controls" / §P "[DEFERRED] manual width controls" mean **no
  NEW controls** — the already-shipped one is retained. **Orphan-stretch is visual-only:** it changes
  a card's *occupied* width to fill a would-be-blank half-row (dossier line 167), never its semantic
  size, and never rewrites the user's explicit compact/wide choice; centered content (§I) makes a
  stretched compact card read as intentional. The planner must **reconcile the dossier §I/§P wording**
  to record that this control exists and is kept. Owner decided 2026-09-19.

### Profile editing (owner ruling — §G/§O)
- **D-06:** Thin/broken heading-level edit routes are wired to the **existing** editors — no new
  editor, no new model. Specifically, **Off Limits' edit affordance reuses the existing
  `src/components/FuelEditor.tsx`** (today reachable only from `EditContactScreen`); it currently
  mis-routes to `ThingsToRememberScreen`, which has zero off-limits handling. Apply the same
  "reuse the existing editor for the whole collection" rule to the other §G affordances. Owner decided
  2026-09-19.

### Profile heading metadata (grounded guard — §D)
- **D-07:** The false "Nothing added yet" heading/caption is a confirmed bug at
  `src/components/profile/ProfileModuleHost.tsx:106-116` (the `things-to-remember` case returns the
  baked `PROFILE_MODULE_EMPTY_SUMMARIES` string unconditionally, never inspecting `knowledge.data`
  counts — unlike the correctly-conditional `contact-methods` case). Per dossier §D, **remove this
  class of heading/caption metadata** (headings become identifiers only; content state lives in the
  body). Do **not** merely make the empty-state inference smarter. The metadata is a heading (`role=
  "heading"`) + caption (`role="caption"`) pair, not one concatenated string — fix targets the
  caption/summary computation and the parent-vs-nested duplicate headings (`ProfileModuleHost.tsx`
  vs `ThingsToRemember.tsx` / `knowledge-presentation.ts`, identical label strings).

### Timestamps (owner ruling — §K)
- **D-08:** App-wide explicit timestamps display through the **minute**, **defaulting to 12-hour**
  (`Sep 19, 2026, 7:14 PM`). Route through **one shared formatter in `src/utils/dates.ts`** that
  reads the format from a **single source** (so a future user toggle is a one-line add). Do **not**
  add another ad-hoc `HH:MM:SS` builder — 8+ already exist (see code_context). Known offenders:
  `src/db/profile-history-read.ts:73` → Profile "Last Interaction" tile
  (`RelationshipOverview.tsx`), and the Interaction Detail "When" row
  (`interaction-detail-logic.ts:96` → `InteractionDetail.tsx:168`). Relative-time formatters
  ("Yesterday", "5d ago", "2 hours ago") are **unaffected** (§K) and stay as-is. Stored/internal
  precision is unchanged. The dossier's `7:14:37 PM` example is illustrative — the real offender is
  the raw 24-hour `YYYY-MM-DD HH:MM:SS` string, so this is a **reformat**, not just seconds-stripping.

### Claude's Discretion
- Exact Orrery overlay tint value (D-04): I pick and AA-prove it, tuned on-device against the orrery.
- Off Limits edit-route reuse mechanism (D-06): lowest-risk reuse of `FuelEditor` (extraction vs
  navigation), confirmed by research/planning.
- Plan decomposition/grouping (D-03): mine, within dossier §Q guidance.
</decisions>
