# Phase 38.10 Plan 21: Section Add FAB on the memory-type section editors (G2, D-131) Summary

**On the Memories, Thought of Them and Gift Ideas section editors, the solid Add now sits at the top, above the entries. When it scrolls off, a Reanimated overlay morphs it into a bottom-left FAB showing the page's icon with a small +. Scrolling back up reverses it, and a tap scrolls to the top and opens the add form there. The FAB hides while a form is open, while the keyboard is up and before the read loads. It reports its presence to a store that plan 23's snackbar reads.**

## Accomplishments

- **`section-add-fab-logic.ts`** (node-tested). It holds the tunables at the top: `MORPH_DURATION_MS = MOTION.slow`, `FAB_HIDE_HYSTERESIS = 8`, `MORPH_APPEAR_FRACTION = 0.1`, `FAB_PLUS_SIZE "sm"` and `FAB_ICON_SIZE "lg"`. The worklets come in dependency order: `lerp`, `clamp01`, `morphFrame`, `fabTargetAfterScroll`, `snapOnPause`, and none of them calls a worklet declared below it. A source-order test pins that order. The file also has the plain helpers `fabSuppressed`, `fabA11yProps`, `sectionFabBottomOffset`, `sectionFabClearance` and `sectionFabIcon`. `sectionFabIcon` returns null for Imported (D-35).
- **`SectionAddFab.tsx`**:
  - `useSectionAddMorph({ loaded, formOpen, focusedRoute })` keeps the scroll position, the three measured boxes (bar, viewport, root), the target and the progress in shared values. Its `useAnimatedScrollHandler` runs on the UI thread and calls one `applyTarget` worklet, declared above both of its callers. That worklet starts `withTiming` (duration 0 under reduced motion) and calls `runOnJS(setFabShown)` only when the target changes.
  - Suppression covers three cases: the read has not loaded, a form is open, or the keyboard is up (`keyboardDidShow`/`Hide`, as UniversalFab does). Suppression is mirrored to the UI thread through `runOnUI`, and the target is re-evaluated from the last scroll position.
  - Pausing: on `useIsFocused() === false` or an `AppState` other than active, the morph runs `cancelAnimation` and snaps to `snapOnPause(target)`.
  - Presence: `register(ownerId)` runs only while the FAB is shown on a focused screen. Unregister happens on hide, blur and unmount.
  - `<SectionAddFab>` is one absolute `Animated.View`. Its frame comes from `morphFrame(progress, barRect clamped to the viewport top, fabRect)`. It uses the `accent` fill with an `onAccent` ring of `FAB_BORDER_WIDTH`, an `onAccent` label, page icon and +, and no elevation. The Pressable's accessibility and touch props come from `fabA11yProps(fabShown)`.
- **Icon registry:** seven names in the new "Section Add FAB (38.10 D-131)" block: section-memories (book), section-thought-of-them (chatbubble-ellipses), section-gift-ideas (gift), section-key-people (people), section-off-limits (ban), section-last-talked-about (chatbubbles) and section-current-location (location). All seven glyphs are verified present in the installed Ionicons glyph map. `pin` is not added here; plan 24 owns it.
- **`section-fab-store.ts`**: `useSectionFabStore`, `selectSectionFabPresent`, `registerSectionFab` and `unregisterSectionFab`. Registering is idempotent, and unregistering an unknown id is a no-op.
- **Geometry:** `FAB_SIDE_INSET = 20` in use-bottom-clearance.ts. UniversalFab's two `right: 20` literals now use it, with no visual change.

## Decisions Made

- `addPlacement` sits in the shared pure `cardEditSlots`. With "top" and a removed edited row, the form still goes last, matching the "end" fallback.
- `fabTargetAfterScroll` also returns 0 while the bar is unmeasured (bottom ≤ 0), so the FAB cannot flash on first render.
- The morph's start rect is the bar's live rect clamped to the viewport's top edge. On the way back the overlay therefore lands where the returning bar actually is.
- The hint "Scrolls to the top and opens the add form." is a proposal (this plan only), listed for plan 19's wording re-check.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `useSectionFabClearance` lives in `SectionAddFab.tsx`, not `use-bottom-clearance.ts`**
- **Found during:** Task 1
- **Issue:** The hook needs `useSafeAreaInsets` from react-native-safe-area-context. `fab-clearance-contract.test.ts` imports `use-bottom-clearance.ts` directly in the node env with no mock, and that import would pull react-native into node.
- **Fix:** The pure `sectionFabClearance()` is in section-add-fab-logic.ts, and the hook `useSectionFabClearance(focused = true)` is in SectionAddFab.tsx. use-bottom-clearance.ts holds `FAB_SIDE_INSET` plus a comment pointing to the hook. **Plan 22 should import `useSectionFabClearance` from `@/components/SectionAddFab`.** Plan 22's contract checks only for `useSectionFabClearance(`, so it is not affected.
- **Commit:** `bcb47293`

**2. [Rule 2 - Correctness] An unmeasured Add bar never shows the FAB**
- **Found during:** Task 1
- **Issue:** Before the bar's first layout its bottom is 0, so `scrollY ≥ 0` would show the FAB at once.
- **Fix:** `fabTargetAfterScroll` returns 0 when `barBottom ≤ 0`. A unit case covers it.
- **Commit:** `bcb47293`

**3. [Design detail] The hook takes `{ loaded, formOpen, focusedRoute }`, not `{ suppressed, focusedRoute }`**
- **Why:** Task 2's `fabSuppressed({ loaded, formOpen, keyboardUp })` needs the separate inputs, and the hook adds `keyboardUp` itself. Plan 22 wires `loaded` and `formOpen` the same way.

**4. [Design detail] `morphFrame` also returns `overlayOpacity`**
- **Why:** At progress 0 the overlay sits on the bar's rect (at the viewport top). Without a 0 there it would cover content while the real bar is on screen. It also takes no touches and is hidden from accessibility.

No decision was reversed. D-130 is kept: the solid Add, card edit mode, and held controls are unchanged. D-35 is kept: Imported has no bar and no FAB. D-68 is kept: the empty state is still text only.
