# Phase 38.10 Plan 24: Pinned in Both, Hide from Profile Switched Off, Edit Contact Most-Recent Cards Summary

**Pinned items show in Pinned and their own section with a pushpin icon; Hide from Profile is switched off with one constant (the flag is kept in storage, ignored for display, and a hidden Allow-AI memory becomes Message Focus eligible per D-142); Edit Contact shows each current-state field's most recent entry above See all; long accordion headings wrap.**

## Accomplishments

- **One switch (D-134).** `HIDE_FROM_PROFILE_ENABLED = false` at the top of `memory-registry.ts`. `resolveVisibility` and `resolveRelationshipVisibility` return "show" first while it is false, and the old rule stays below it. Every display reader goes through these two helpers, so this one change makes every item show on the Profile, Compose Research, the Dashboard knowledge line, Contacts search and the Orrery moons. I re-grepped this: no SQL filters on `hidden`; the only SQL that touches it is the DAO writers and projections.
- **Pinned in both (D-133).** `readProfileKnowledge` no longer drops pinned rows from Key People or the memory sections. Pinned stays uncapped (D-112). `profileMemoryRow` needed no change: it already takes the first match across Pinned and the sections (verified in `contact-profile-logic.ts:159`).
- **Pushpin (D-133).** There is a new `pin` icon (Ionicons `pin` / `pin-outline`; both glyphs verified present).
  - Profile `KnowledgeCard`: shows the pin next to the sparkle, and its label ends ", pinned". `memoryItem` no longer adds "Pinned" to `metadata`.
  - `MemoryCard`: the "Pinned" text becomes the icon, inside the same marker with the label "Pinned memory".
  - `RelationshipEditor`: rows show the icon in an accessible marker labelled "Pinned", in both row layouts.
- **No Hide controls anywhere (D-134).** The following are gated on the constant, with their JSX kept:
  - `MemoryEditor`: the Hide from Profile row and its caption, plus the `onShowOnProfile` pass-through.
  - `MemoryCard`: Show on Profile and the hidden-row dimming.
  - `RelationshipEditor`: the hidden dimming and secondary text, Show on Profile, the Hide row with its caption, and Use default visibility.
  - `SectionEditorScreen`: the `onShowOnProfile` prop.
  - The Profile's Show hidden button.

  Drafts keep the stored `hidden`, and saves send it back unchanged (tested in both editors). The move confirm drops "its Hide from Profile setting" and returns null when that was the only dropped field.
- **Compose Research (D-142).** Hidden memories and key people now list. A hidden memory with Allow AI on is `aiEligible` through the same SQL-gated membership as any memory. There is no hidden-specific guard, and nothing else widens.
- **Edit Contact (D-135).** `getCurrentStateValues` is read into its own `mostRecent` state on focus (including the first focus) and after a save that keeps the form open. It never enters `form`, the baseline or the dirty signature. Each section shows a small surface/border card above See all, with the value capped at 2 lines and the date in `textSecondary`. Current Location gains "See all" (label "See all Current Location entries"), which opens `MemoryHistory` with `fieldKey: "current_location"`.
- **Accordion (O15).** `AccordionSection` titles now take `flex: 1` and wrap. The header row is top-aligned with a 12 px gap, so the +/− stays at the top right. A single-line title is unchanged, because the heading's 25 px line already fills the header's 20 px inner minimum.

## Deferred items for the owner

These are observations for the plan-19 Task 3 device re-check, not defects fixed here:

1. **Pinned rows take section slots first.** The repeatable sections show 3 items, and the memory/relationship reads order `pinned DESC`. A section with 3 or more pinned items therefore shows only pinned items, the same ones as in Pinned, with View all for the rest. This follows directly from D-133. Whether the section should show unpinned rows first is a visual/product call.
2. **TalkBack on editor pin markers.** In card edit mode, RelationshipEditor's "Pinned" marker and MemoryCard's "Pinned memory" marker sit inside an accessible Pressable labelled "Edit …". TalkBack may not reach them separately; MemoryCard already had this nesting. Profile cards carry ", pinned" in their own label, but editor rows do not. Worth a TalkBack pass at the re-check.
3. **The Profile entry sheet no longer says "Pinned".** It listed `metadata`, which held the word. Its Unpin action still shows the state. Proposal: leave it as is.
4. **A cross-table move still drops the stored `hidden`, now with no confirm line.** This is by D-134 design, and the DAO is unchanged. If Hide from Profile ever returns, a moved entry that was hidden comes back visible. This is relevant only to the D-71 keep-or-drop decision.
