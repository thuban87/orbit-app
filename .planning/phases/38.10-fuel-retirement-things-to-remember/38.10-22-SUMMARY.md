# Phase 38.10 Plan 22: Section Add FAB on Key People, Off Limits and the history page (G3, D-131) Summary

**The Off Limits editor, the Key People editor and the Last Talked About / Current Location history page now have the solid Add at the top, above the entries and the empty-state text, whether or not there are any entries. When the Add scrolls off, it morphs into plan 21's bottom-left FAB with the page's icon: no-entry, people, chat or map pin. A tap on the FAB scrolls to the top and opens that page's add form there. A textual contract pins all four page types and the FAB component.**

## Accomplishments

- **OffLimitsEditorScreen:**
  - The root View now measures itself with `onRootLayout`. The body is an `<Animated.ScrollView>` with the morph's scroll handler and viewport layout, `scrollEventThrottle={16}`, and the same `scrollRef`/`innerViewRef` pair from `useFirstErrorReveal()`.
  - The solid `off-limits-editor-add` (role primary, `ADD_OFF_LIMITS_ITEM`) is the first loaded child, inside the measured bar View. It shows whether or not there are rows, and it is held while a form is open or a save runs. The add form renders in its place.
  - The EmptyState lost its `action`. The scroll content ends with `paddingBottom: useSectionFabClearance(focusedRoute)`.
  - `<SectionAddFab icon={sectionFabIcon("off_limits")}>` renders last. Its press is held while saving or while a form is open; otherwise it scrolls to y 0 and opens the add form.
  - The intro line ("Keep topics here…") stays above the Add. It is page copy, not an entry.
- **RelationshipEditor:**
  - It has an optional `addPlacement` ("end" by default), which it passes through `relationshipEditorSlots` to the shared `cardEditSlots`. With "top", the add slot comes first and the editor renders no Add of its own. A new key person's form opens in that first slot, and an in-place edit keeps its row's index.
  - `RelationshipEditorHandle.openNew()` is added. It is the existing `openNew`, which returns early while `busy`.
  - The draft-state report now carries `adding`, which is in the effect's dependencies. The field is optional on `RelationshipDraftState`.
  - Add/Edit Contact and Update Contact do not pass the prop, so they are unchanged.
- **KeyPeopleEditorScreen:**
  - It has the same wiring as the section editor: the top `key-people-editor-add` bar ("Add key person", role primary) is hidden while adding and held while a form is open or a save runs. It calls `editorRef.current?.openNew()`.
  - The screen passes `addPlacement="top"` and uses the section-FAB clearance. `<SectionAddFab icon={sectionFabIcon("key_people")}>` scrolls to the top, then calls `openNew()`.
  - The empty text now says "above".
- **MemoryHistoryScreen:**
  - The body is an `<Animated.ScrollView>` with the morph handler. It keeps `paddingBottom: bottomClearance` from `useBottomClearance()`, because it is a tab page (D-52).
  - `memory-history-add` (label `historyAddLabel(fieldKey)`) now shows at the top whether or not there is a Most Recent entry. Before this plan it showed only when there was one. The add form replaces it as before.
  - The EmptyState lost its `action`.
  - The FAB is `sectionFabIcon(historyFabSection(fieldKey))` with `focusedRoute: false`. It therefore sits above the in-flow tab bar, on the universal FAB's baseline on the opposite side.
- **memory-history-logic:** `historyAddLabel` returns `Add ${historyTitle(fieldKey)}`, the string the page already showed. `historyFabSection` maps the two field keys to their `sectionFabIcon` keys.

## Decisions Made

- The two focused editors compute `focusedRoute` with `isFocusedWorkflow(route.name)` and pass it to `useSectionFabClearance`, copying SectionEditorScreen. The history page passes `focusedRoute: false` explicitly, with a comment saying why.
- The Off Limits and history FAB presses re-check `savingRef.current || form !== null`, since the FAB is already hidden in those states. The Key People FAB relies on `openNew()`'s own busy guard. A form open there already hides the FAB.
- The hint "Scrolls to the top and opens the add form." is the same on all four pages. It is plan 21's proposal (PLAN-MAP §6.3), up for plan 19's wording re-check.

## Deferred items for the owner

These are observations for the plan-19 Task 3 device re-check, not defects fixed here:

1. **The empty state while adding is not uniform across the four pages.** On an empty Key People page, as on the section editors (plan 21 item 1), "No key people yet / Use Add key person above…" stays visible above the open add form. On Off Limits and the history page, the empty state hides while the add form is open. Each page keeps its own existing rule. Making them match is a visual call. My recommendation is to hide the empty state while adding everywhere.
2. **The history page's two FABs on one baseline need device eyes**, as does the morph on the three new pages. The offsets come from plan 21's `sectionFabBottomOffset({ focused: false })`. Whether they really share the universal FAB's baseline above the in-flow tab bar is visible only on device.
