# Phase 38.10 Plan 08: Sharing data layer and resume-prompt gate Summary

**A share is now saved the moment a person is picked, as an AI-off Thought of Them memory with its link, through one atomic DAO that bumps the data revision once per write. Create-plus-share is one transaction, chip moves keep the share's origin, Undo deletes only the share's own rows, and both resume prompts stay hidden while a share is in progress.**

## Accomplishments

- `capture-dao.ts` rewritten on the new homes. There are no imports from the retired DAO:
  - `shareToContacts`: one independent Thought of Them memory per person. Value is the share text, or the link when the text is blank. The link stays in `url`, provenance is `share`, Allow AI is 0. Rows come back in input order.
  - `createContactAndShare`: re-checks the cadence guard, then runs `createContactFullCore` and the share memory in one transaction. The contact and the share get the same `created_at`. `createContactFullCore` writes `created_at` from the passed `now` (`contacts-dao.ts`, the contact INSERT binds `input.now` twice), so plan 11's D-100 guard can rely on it.
  - `moveShareRows`: Gift Ideas / Memories / Thought of Them are type changes. Last Talked About is dated today from the move's own local stamp. Every call passes `carryEntryDate: false`, so a hop through Last Talked About leaves no meaningful date.
  - `undoShareRows`: guarded by `assertShareUndoRowsCore`, deletes with tombstones.
  - `setShareRowsAllowAi`: memories only.
  - `applyShareNote`: the note leads, recomposed through `resolveCapturePayload`.
  - `shareRowsMatchCreatedContactCore`: for plan 11.
- `NEW_CONTACT_DEFAULT_INTERVAL_DAYS` (30, monthly) added. CaptureScreen's inline create reads it.
- CaptureScreen's four write sites now call the new DAO. `writtenRows` is `ShareRowRef[]`, and the retired-DAO import and `INLINE_CREATE_INTERVAL_DAYS` are gone. There is no UI change. The plan-07 stale widget comments are reworded.
- Resume prompts:
  - `resolveActiveResumePrompt` takes `{ suppressed }`.
  - `AppShell` calls `useShareIntentContext()` and a boolean `useFocusedRouteStore` selector at the top, above `if (error) {`. Neither is inside JSX or behind `||`.
  - It computes `suppressed = hasShareIntent || onCapture` after the early returns.
  - The resumable state is kept, so the prompt comes back after the share.
- capture-logic: comments and type docs are fuel-free. No behaviour change.

## Deviations from Plan

1. **[Rule 2 - Hardening] `ShareContactInput` is name-only.**
   - The plan has `createContactAndShare` re-check both `createContactFull` guards.
   - The input type is `Pick<CreateContactFullInput, "uid" | "name" | "intervalDays" | "methodDrafts">`, and the wrapper builds the core input from those fields only. A first interaction therefore cannot reach the create, so the future-date guard has nothing to check. The cadence guard is re-checked as written.
   - Why: capture is never a touchpoint (D-12), and a share-created contact must own nothing but its share (D-106).
   - The CaptureScreen contract test also asserts there is no `firstInteraction` in the call. Commit `ef240ee9`.
2. **[Rule 2 - Fail closed] Empty or contentless input is refused.**
   - `shareToContacts` rejects an empty pick list and a share with neither text nor link.
   - `createContactAndShare` refuses the same before it creates a contact.
   - Both are tested. Commit `ef240ee9`.
3. **[Plan wording] One resolution feeds both prompts.**
   - The plan says to pass `{ suppressed }` to both `resolveActiveResumePrompt` calls.
   - AppShell now calls it once with `{ suppressed }`, and both prompts read that result. The behaviour is the same, and the two calls cannot drift apart. Commit `634256ac`.
4. **[Note] No-op wrappers do not bump.**
   - `moveShareRows` does not bump when every row is already in the chosen section.
   - `setShareRowsAllowAi` does not bump when it only receives Last Talked About rows.
   - In both cases nothing is written. Every writing call still bumps exactly once, as the tests assert.

**Total deviations:** 3 small hardening or wording changes, plus 1 note. **Impact:** no scope growth.
