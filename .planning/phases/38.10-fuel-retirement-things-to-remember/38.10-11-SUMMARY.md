# Phase 38.10 Plan 11: Share screen UI Summary

**A share is still saved the moment a person is picked. A confirmation card then lets the user move it between Thought of Them, Gift Ideas, Last Talked About and Memories, undo it, add a note or allow AI, and it waits while touched or busy. Undo of a share-created contact removes the contact too, unless it already has other details. The face grid is replaced by the app's list picker, with always-visible search and "New contact" first.**

## Accomplishments

- **capture-dao (data layer):**
  - `moveShareRowsCore` is the non-transactional move. `moveShareRows` keeps its signature and behaviour.
  - `moveShareRowsWithAi` runs the move, reads the stored Allow AI and bumps the revision, all in one transaction (G-U1, c4). A failed read rolls the move back.
  - `undoCreateContactAndShare(exec, contactId, rows, now, { onPurgeExtensions })` runs in one transaction:
    - it checks the share rows first (refuses with `ShareUndoRefusedError`);
    - it runs the "created with" match **before** the delete (G-U2);
    - it deletes the share rows;
    - it purges the contact only if the rows matched and `shareContactIsUntouchedCore` passes;
    - it bumps the revision once;
    - the post-commit cleanup runs only when the contact was removed.
  - This is the only non-test file containing `requireArchived: false` (grep checked).
- **share-card-logic (pure, 45 tests):**
  - The card reducer: chips, the D-99 switch rule, single-flight writes with committed refs, and five timer holds (touching, a pending write, the note editor, a discard prompt, the app not active).
  - The auto-close timer controller and the seq- and app-state-guarded finish callback.
  - The share sequence (`advanceShareSequence`, `isLiveShareIntent`) and the payload snapshot (`takeShareSnapshot`, `captureViewPayload`).
  - `runShareWrite`, `shouldPublishShareResult`, `shareListLocked` and `shareScreenAfterUndo`.
  - The section labels come from the registries. Also here: `confirmationLabel`, `createdLabel` and `undoResultSnackbar`.
- **ShareConfirmationCard:**
  - Chips in D-77 order.
  - Undo, Add note (the note field submits with `onSubmitEditing`), `OrbitSwitch` Allow AI (only `disabled` is passed) and Done.
  - Touch-to-pause, an AppState listener, and the `discardOpened` / `discardClosed` ref handle.
  - It reports `onNoteStateChange` to the screen for Back.
  - It sits above the keyboard or the system bar, using the screen's `sheetKeyboardLayout` lift or the bottom inset.
- **CaptureScreen:**
  - Render-time share sequence and snapshot. The same render resets search, multi-select, the note mirror, the New-contact sheet and the mounted card.
  - The card and the embedded list are keyed on `seq`.
  - Every write goes through `runShareWrite` with the one `isCommittingRef` latch.
  - `armAutoReturn` / `returnTimer` are deleted, and so is the `notifyWidgetDataChanged()` call (plan 08 carry-in).
  - "Nothing to save" and the preview strip read the snapshot.
  - Undo returns to the unlocked list, reloads the rows and shows the Undo snackbar.
  - `buildShareUndoPurgeCleanup` composes import-staging, photo and notification cleanup, each in its own try/catch.
  - The Back order is unchanged. The note discard prompt holds the card timer.
- **ContactPicker:** `ContactPickerList` is extracted. The modal wraps it, so the 9 consumers compile and behave as before.
  - New optional props: `rows`, `loading`, `keepSourceOrder`, `leadingAction`, `tapToSelect`, `multiSelectEntry` ("Select several" or a long-press; exit with "Cancel"), `searchResetKey`, controlled `searchText` / `multiSelect`, `disabled`, `confirmErrorLabel` and `style`.
  - The list never dismisses anything and never touches the shell transient.
- **Glossary:** `ALLOW_AI` and `ADD_NOTE` are pinned in the contract, and the card reads them from the glossary.

## Deviations from Plan

1. **[Plan wording] `moveShareRowsCore` returns `{ rows, moved }`.**
   - Both wrappers bump only when something moved. This keeps plan 08's no-op rule.
   - A real move, the only kind the card sends (a tap on the selected chip is a no-op), bumps exactly once, as tested.
2. **[Plan wording] `ShareScreenUndoState` has no `writtenRows` / `savedLabel` fields.**
   - The written rows and the names the label is built from live on the mounted card object, so `card: null` clears both.
   - The D-120 test asserts the card is gone, and with it the rows and the label.
3. **[Rule 2 - Security, T-38.10-35] `filterPicker` gained `allowArchived`.**
   - Archived contacts stay hidden even on a search match when the host supplies the rows. The read already excludes them.
   - Tested. Commit `d1eac6a4`.
4. **[Rule 2] An extra ownership test (this plan only).** Every column named like a contact id must be in `SHARE_UNDO_OWNERSHIP`. It backs up the FK-derived set-equality test.
5. **[Rule 2] More blocking cases than the plan lists.** On top of the plan's list there are tests for an edited contact row, a custom-field history row, a value for a contact-scoped definition, and the orrery sun reference.
6. **[Additive props] `ContactPickerList` takes `style` and `confirmErrorLabel`.**
   - `style` keeps the modal sheet's content-sized layout; the embedded list passes flex 1.
   - With `confirmErrorLabel`, Capture's failed multi-select shows "Couldn't save" rather than "Couldn't add those contacts".
7. **[Plan 08 carry-in] Widget refresh calls dropped.** The three `notifyWidgetDataChanged()` calls were removed when the screen was rebuilt.
8. **[Note] Card writes go through the screen's actions.**
   - The card calls screen-provided async actions (`ShareCardActions`). Each one runs `runShareWrite` with the shared latch and the `seq` check.
   - The card settles its reducer from the returned outcome. A stale result is ignored, and a busy latch counts as a failed write.

**Total deviations:** 2 wording or shape changes, 3 small hardening additions (items 3 to 5), 1 additive prop pair, 1 carry-in and 1 note. **Impact:** no scope growth.
