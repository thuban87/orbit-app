## Accomplishments

### History page (`MemoryHistoryScreen`, `memory-history-logic`)

**Rows and order**
- `groupHistoryRows` takes rows in the one SQL order and splits them into Most Recent and Previous. The order is never re-derived in JS.
- Both groups use the same `HistoryRowModel` (`dateLabel`, `pressAction`, `canEditDate`, `canMove`) and the same `HistoryRow` component. `rows` (Most Recent included) is what `openEditTarget` resolves `editId` against (c10 C-05).
- `historyRowDate` = `formatDisplayDateOrFallback(entry_date ?? created_at)`, date only. The old `formatDateTimeMinuteOrFallback(created_at)` is gone (CU-04).

**Adding and editing**
- Add and edit use one `HistoryEntryForm`: the D-66 `EntryTextField` (Enter saves) plus `EntryDateField`, which defaults to today with `maxDate` today (D-101). Save also checks `isPickableEntryDate`.
- A linked entry shows its date read-only, and its date is never sent to `editHistoryEntry` (D-41). Text edits go through `editHistoryEntry`, which handles note propagation and the Group Note copy detach (D-117).
- `openAdd` opens the add form. `editId` opens that entry's form once per navigation after the read (D-107).

**Linked entries (D-107)**
- A tap runs `getLinkedInteractionRefCore`, then `linkedEntryRoute`, and goes to `EditInteraction`, `EditParticipant` or `GroupEventDetail`. If the interaction is gone, the page reloads.
- Long-press, and the "Edit" screen-reader action, open the form.
- There is no Pin here (D-21/D-22).

**Delete and Move**
- Delete: `deleteCurrentStateEntry`, then "Deleted <Title> entry for <name>" with Undo, which calls `undoCurrentStateEntryDelete`. A successful Undo shows "<Title> entry restored for <name>".
- Move: shown only when `canMoveFrom(fieldKey)`, so only on Last Talked About (F-U12). It goes through `MoveEntrySheet`, whose `onMoved` / `onMoveUndone` re-read the list.

**Links and page chrome**
- A stored URL is shown with an "Open link" action through `openMemoryLink` (D-24).
- `useContactHeader` + `ShellAppBar` with `backDisabled={saving}`.
- `useDiscardKeepGuard`: the open form is the sub-editor, and the save ref holds Back.
- ScrollView with `ref` + `innerViewRef`, `useKeyboardCentering`, `KeyboardCenteringProvider`, and `bottomSpacer` last. `paddingBottom: bottomClearance` is kept (FAB clearance contract).
- `EmptyState` with an "Add <Title>" action. The title comes from the Profile module registry. There is no Make current and no Allow AI switch.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - 38.9 D-30] History page Delete is in the open form, not a button on the row card**
- **Found during:** Task 1.
- **Issue:** The plan says "Delete stays a row action on both kinds". The 38.9 destructive rule (`docs/systems/ux-standards.md:48-55`, D-19) keeps destructive actions off list cards, and plan 15's Off Limits editor put Delete in the open form for the same reason.
- **Fix:** Delete is a tertiary button in each entry's edit form. That form opens on tap for an unlinked entry, and on long-press or the "Edit" screen-reader action for a linked one, so Delete is reachable on both kinds. Move stays a visible button on the card because it is not destructive.
- **Commit:** `b41bca8a`

**2. [Rule 2 - ADR-168 / 38.3 RG-035] Gated reads with Retry**
- The history page had a plain load that showed an empty list on a failed read. It now uses `runGatedRead`, with loading and Retry, like the other 38.10 editors.
- Update Contact's Memory editor uses the same pattern. Task 3 asked for this; it is listed here because the history page change was not in the plan.
- **Commits:** `b41bca8a`, `5b6a3e54`

**3. [Rule 2 - D-11] Update Contact Off Limits writes through the plan-15 controller**
- The plan named the DAO functions. Routing them through `createOffLimitsEditorController` adds D-11's re-read before every edit and delete and keeps Undo scoped to this contact, which applies the T-38.10-48 mitigation in full.
- **Commit:** `5b6a3e54`

**4. [Rule 1 - Bug] The saved-effect guard was outside `if (savedTick > 0)`**
- **Found during:** Task 2 verify.
- **Issue:** `editor-cancel-contract` slices the source around the literal `if (savedTick > 0)`. My first version read `if (savedTick > 0 && !leftRef.current)`, so the slice came back empty and the test failed. Behaviour was correct.
- **Fix:** the guard moved inside the branch.
- **Commit:** `c4d1671e`

**5. [Rule 2 - D-35] MemoryAddScreen never fixes the type to Imported**
- `fixedType` is set only when `canAdd(type)`, so a `type: "imported"` route param shows the normal picker instead of creating an Imported memory.
- **Commit:** `75014522`

**6. [Design within the plan] Closing the add-only draft leaves the screen**
- **Issue:** On an add-only form, the guard's sub-editor close (Back on a clean draft) and the form's Cancel would leave an empty page that needs a second Back.
- **Fix:** an effect leaves (bypass + `goBack`) once the draft closes without a save. The effect is gated on the loaded phase, so a failed re-read shows Retry and does not leave. The guard wiring the contracts pin is unchanged.
- **Commit:** `75014522`

**7. [Design within the plan] Open Profile uses `push`**
- In React Navigation 7, `navigate("Profile", …)` could pop back to a different contact's Profile lower in the stack. `push` always opens this contact's Profile.

**8. [Wording] Update Contact current-state label**
- It now reads "Most Recent: …" through `HISTORY_MOST_RECENT` (was "Most recent: …"). The plan asked for the label to come from the read's order; the capital matches the Profile.

**9. [Process] Tracer gate**
- `auto_advance` is false. The plan is `autonomous: true` and was dispatched as an autonomous sequential run. The tracer verify passed after the commit and before Task 2, as in plans 09-16.

**Total deviations:** 9 (3 Rule 2, 1 Rule 1, 1 Rule 2 type guard, 2 design choices, 1 wording, 1 process).
