# Phase 38.10 Plan 04: Backup format 8, v7 conversion and fail-closed restore Summary

**Backup format 8 with Off Limits, links and AI-lock markers; a v7 converter that reuses migration 033's mapping and uid allocator and is proven row-equal to it; and a restore that never raises allow_ai, keeps lock markers sticky, and repairs interaction links without deleting a row or tripping the link UNIQUE indexes.**

## Accomplishments

- `BACKUP_FORMAT_VERSION` is 8. The manifest carries `offLimits[]` and no legacy array. Memories and current-state entries carry `interactionUid`, `linkSource` and `groupNoteCopy`. Current state also carries `entryDate`, `entryTime`, `url` and `fromShare`, and has no `isCurrent`. Interactions carry `noteAiLocked`. The two new AI-default settings travel and default to 0 for a v7 file.
- `convertV7ToV8` (FORWARD_MIGRATIONS[7]) does RESEARCH 2.3 steps 1–7 through `mapLegacyFuelRow` and `allocateLegacyUids`. Its time source is the file's own `exportedAt`, falling back to `1970-01-01 00:00:00` for an odd shape. It never draws a fresh uid.
- Export writes the new homes, links and markers. A soft-deleted memory or key person goes out as a tombstone, merged with any existing tombstone (later `deletedAt` wins).
- Restore changes:
  - `off_limits` is a mergeable entity.
  - The local snapshot SQL now compares like with like.
  - Interactions are resolved by uid after the interactions pass. A missing interaction becomes NULL, never a parent block.
  - `normalizePlan(plan, manifest)` replaces the dead `isCurrent` fix-up with the D-103 retained-lock pass and the ordered link pass:
    - step 0: Group Note origin evidence;
    - step 1: owner check;
    - step 2: dissolved or blank source;
    - step 3: the D-95 collapse, which unlinks losers and never deletes them.
  - Link slots are released before the child upserts.
  - A post-pass converges linked text, dates and `MIN(allow_ai)`, and locks every Group Note copy.
- The equivalence test runs one fixture table through both routes: migration 033, and the converter plus Replace-all restore. The rows match by uid, collisions included.

## Behaviour change (as the plan asks)

On a Merge conflict, memories and interactions now keep `MIN(local, incoming)` for `allow_ai`. Before this plan, the incoming value overwrote the local one, so a restore could turn AI permission back on. The old comment near the interactions upsert, which claimed the arm forced 0, has been rewritten. Note: RESEARCH 2.5 says ADR-117's text promises "the merge arm forces 0". MIN narrows the old code but is not "always 0". RESEARCH left that gap out of scope, and this plan implements MIN as written.

## Known path difference (not a converter/migration mismatch)

Replace-all restore runs `clearReplacedLiveTombstones` (existing code). It deletes any tombstone whose uid matches a live row of the same type. Suppose a v7 file holds a legacy row and a legacy tombstone with the same uid. Migration 033 keeps the older tombstone beside the live row, but the converter plus Replace-all drops it. Last-writer-wins gives the same result either way, because the row survived it. The equivalence fixture therefore puts the collided legacy tombstone on a uid with no legacy row (`tx`), and this note records the difference. The plan-01 SUMMARY records no other intentional difference.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing validation] Link shape and allowAi range in the v8 validator**
- **Found during:** Task 1
- **Issue:** The plan listed the D-95, D-102 and D-103 rejects. Without a link-shape check, a linked row with a null or unknown `linkSource` would pass parsing and then fail migration 033's CHECK inside the restore transaction.
- **Fix:** `interactionUid`, when set, must be a non-empty string with a `linkSource` of `note` or `group_note`. `allowAi` must be null, absent, 0 or 1 on memories and interactions. A legacy contentless Off Limits row is still accepted.
- **Files:** `src/backup/backup-schema.ts`
- **Commit:** `32b6bd8a`

**2. [Rule 1 - Correctness] Winning live rows clear a local soft-delete stamp**
- **Found during:** Task 2
- **Issue:** The plan said to stop writing `deleted_at` from the wire. Dropping the column from the upsert entirely would leave a local soft-deleted row hidden after a newer live incoming copy won. Before this plan, that copy revived the row.
- **Fix:** On conflict, the upsert sets `deleted_at = NULL` (a format-8 row is always live). The wire `deletedAt` is never read.
- **Files:** `src/backup/restore-apply.ts`
- **Commit:** `43278796`

**3. [Rule 3 - Blocking] Converter row checks**
- **Found during:** Task 1
- **Issue:** The format-7 validator used to reject a bad or duplicated legacy row. After conversion, a duplicate would have turned into two rows in one home.
- **Fix:** The converter rejects them with `BackupSchemaError`.
- **Commit:** `32b6bd8a`

**4. [Plan text vs disk] phase-17-integration needed no edit**
- Plan 01 had already added `["off_limits","off_limits"]` and the `tombstones` non-mergeable entry. The `:168` legacy seed runs at v6 and migrates through 033. That is still valid, and plan 18 allowlists the file. The `["fuel","fuel"]` covered entry stays, as the plan says.

**5. [Workflow] Tracer gate run autonomously**
- The tracer's verify is a vitest run. Under the owner's standing direction to run autonomously, it was re-run and passed before the expansion tasks, and no checkpoint was raised.
