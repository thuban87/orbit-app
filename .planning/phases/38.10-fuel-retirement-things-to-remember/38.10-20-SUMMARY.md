# Phase 38.10 Plan 20: Card edit mode on the section pages (G1, D-130) Summary

**The four section page types (memory-type section editors, Off Limits, Key People, Last Talked About / Current Location history) now open a card's form in place of that card, with a pencil on every card, Move and a red Delete only in edit mode, the Open link kept, and a solid Add. MemoryEditor, RelationshipEditor and OffLimitsForm get this through an opt-in `cardEditMode`, so their other hosts are unchanged.**

## Accomplishments

- **MemoryEditor** has an opt-in `cardEditMode`. `memoryEditorSlots` puts an open edit's form at the edited card's index. That form has Move (only when the host passes `onMove`) and a destructive Delete in a header row at its top, plus the stored Open link above the fields. The bottom Delete is not rendered in this mode. Resting cards get no `onMove`, and every card gets `onEditPress`. While a form is open, the other cards and the Add are held. Move goes through `onCancelRequest(closeThenMove)`, so the dirty-aware Discard prompt runs first. A new `formRef` prop lets the host scroll the form into view.
- **MemoryCard** has an optional iconOnly `edit` pencil at the far top right of the header, after the markers. It is held with the card. The default label is `Edit <type> memory`.
- **SectionEditorScreen** passes `cardEditMode`, `formRef` and `addButton={{ label: sectionAddLabel(type) }}` (the solid Add). It now uses `useFirstErrorReveal` refs and reveals the `editId` form once. `canMove(type)` still gates `onMove`, so Imported shows Delete only.
- **OffLimitsForm** has an opt-in `cardEditMode`: Open link, Move and a destructive Delete at its top, and no bottom tertiary Delete. It also takes a `formRef`.
- **OffLimitsEditorScreen**: rows are Pressables labelled "Edit Off Limits item", with a pencil, and no Edit or Move buttons. The edit form renders in the row's place, and its Move runs `requestClose(() => { closeForm(); setMoveRow(row); }, formDirty)`. The add form and the solid Add are where they were. An `editId` form is revealed once.
- **MemoryHistoryScreen**: `HistoryRow` has a pencil and no longer has Move or the `onMove` prop. `renderRow` renders `HistoryEntryForm` in place of the row instead of under it. That form shows Open link, Move (Last Talked About only) and a destructive Delete at its top; the bottom Delete is gone. An `editId` form is revealed once.
- **RelationshipEditor** has an opt-in `cardEditMode` and a `relationshipEditorSlots` helper. Rows are Pressables labelled `Edit <name>`, with a pencil and no "Edit" button. The form opens in the row's place with a destructive Delete at its top and no bottom Delete. There is no Move. Rows and the Add are held while a form is open. Show on Profile on hidden rows is unchanged (plan 24 owns D-134).
- **KeyPeopleEditorScreen** passes `cardEditMode` and `formRef`, reveals the `editId` form once, and keeps `busy={saving}`.

## Decisions Made

- `card-edit-slots.ts` holds one generic pure helper. `memoryEditorSlots` and `relationshipEditorSlots` are thin wrappers around it (see Deviations).
- An edited row that is missing from the current rows keeps its form at the end. This matches the pre-plan layout, so a typed draft never disappears.
- Pencil labels are proposals for plan 19's wording re-check (this plan only): memory cards `Edit <type> memory`, Off Limits `Edit Off Limits item`, history `Edit <title> entry`, Key People `Edit <name>`.

### Auto-fixed Issues

**1. [Rule 3 - Blocking/structure] New shared file `src/components/card-edit-slots.ts`**
- **Found during:** Task 1
- **Issue:** The plan has `relationshipEditorSlots` "mirror" `memoryEditorSlots`. Two hand-copied versions of the same order rule could drift.
- **Fix:** One pure generic `cardEditSlots` in a new file, with both named helpers as wrappers. This file is not in the plan's `files_modified`.

**2. [Rule 2 - Correctness] Off Limits edit-form fallback**
- **Found during:** Task 2
- **Issue:** Rendering the edit form only in its row's place would hide an open form, and the draft in it, if a reload removed that row.
- **Fix:** If the edited row is no longer among the rows, its form renders after them.
- **Commit:** `09fbb359`
