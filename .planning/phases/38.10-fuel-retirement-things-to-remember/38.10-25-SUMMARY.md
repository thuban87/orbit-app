### Auto-fixed Issues

**1. [Rule 3 - Blocking] `entryNoun` also accepts a per-type function**
- **Found during:** Task 2.
- **Issue:** Update Contact's memory editor has no fixed type. Its type picker lives inside MemoryEditor, so the host cannot know "its type picker's current type", as the plan asked.
- **Fix:** `entryNoun?: string | ((type) => string)` (`MemoryEntryNoun`).
  - The open form names its draft's type, so it follows the picker.
  - The closed outlined Add names the type a new entry starts as. On Update Contact that is general, so it reads "Add Memory".
  - Add/Edit Contact's Memories sections also keep the type picker, so they pass the function too. For the default type the result is the plan's "Memory".
  - The fixed-type sections pass a string.
- **Commit:** `d40bd978`

- In add mode, the label is "Add <noun>" so the spoken name matches the visible text. The plan named only the visible text.
- The edit mode's "Save memory" is kept, as the plan says.
