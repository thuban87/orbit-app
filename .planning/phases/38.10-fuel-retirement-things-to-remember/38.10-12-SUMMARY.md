# Phase 38.10 Plan 12: Logging UI (Also save to) Summary

**"Also save to" now works on Log Interaction, the Add Note sheet and Group Log. A one-section chip row (None by default) saves the note to a section as a linked entry in the same transaction. History tags the interaction row with the section. The Add Note sheet has lost its separate memory path. On all three editors that can change an existing note (Edit Interaction, Edit Participant, Edit Event's participant editor), clearing a linked note is refused with an inline error that names the section. A note moved into Off Limits shows its Allow AI switch locked off with the reason, and Settings → AI never enables a locked item.**

## Accomplishments

- `also-save-to-logic.ts` (pure) holds the one destination rule. Every surface saves to `effectiveAlsoSaveTo(note, chosen)`. Every note-change handler runs `alsoSaveChoiceAfterNoteChange`, so a blanked note resets the picker to None. The picker is disabled while the note is blank.
- `AlsoSaveToPicker`:
  - chips use `chipTone("primary", …)` and theme tokens;
  - each chip is announced as "Also save to <section>";
  - disabled chips are dimmed.
- **Log Interaction:**
  - With a section and a non-blank note, the save uses `recordTouchpointWithLinkedEntry`; otherwise it uses `recordTouchpoint`.
  - A success snackbar names the channel and the person, plus the section when one was saved.
- **Add Note sheet (D-42, F-18):**
  - Removed: the memory path, its follow-up editor, the "Memory saved" view, the AI master read and the three-button row.
  - The buttons are now one row, Cancel then Save.
  - A save with a section uses `saveNoteWithLinkedEntry`; one without uses `editTouchpointFull`, as before.
  - An empty Save still closes and writes nothing.
  - A successful save now shows a snackbar.
- **Group Log:**
  - The picker sits under the Group Note.
  - `createGroupEvent` receives `effectiveAlsoSaveTo(groupNote, chosen)`.
  - No Allow AI switch was added.
- **History:** each linked section shows as a plain-text tag inside the interaction row's single Pressable. The tag is not separately accessible. Its section names join the row's existing label, which keeps `formatTimeMinuteOrFallback` (W-6).
- **Clearing a linked note on the edit screens (Q4):**
  - Edit Interaction, Edit Participant and Edit Event's per-participant editor check before saving: a blank own note that has a `note`-linked entry shows a `FieldError` under the note and nothing is saved.
  - The check runs after `beginInFlight`, inside the guarded save.
  - `LinkedNoteBlankError` from the DAO maps to the same error.
  - On Edit Event, the error renders inside the participant Sheet.
  - The Group Note is not checked (D-113).
- **Edit Event's "Save participant"** is now single-flight on its own `participantSavingRef` and is drawn disabled while held.
- **Edit Interaction (D-103):** a note moved into Off Limits shows Allow AI off and disabled, with `aiLockReason("off_limits")` in the caption slot.
- **Settings → AI (D-102, D-103):**
  - A locked row shows its reason under the value.
  - Enable selected drops locked items, and is disabled when only locked items are selected.
  - Disable still covers locked items.

## Deferred Items

- **Group Log still saves silently.** It shows no success snackbar. The 38.9 D-39 feedback rule says it should name whom; this plan's Group Log task did not ask for one. Recommendation: plan 17 or 19 adds "Logged <event title> with N people", or the owner rules it out. Either way it is new wording.
- **Clearing a note whose only link is a trashed memory shows a fallback message.** `getLinkedEntriesCore` skips soft-deleted memories, but the DAO's blank refusal (`propagateInteractionEditCore`) does not. So the pre-check passes, the DAO refuses, and the inline error reads "…also saved to another section…". The save is still refused (fails closed). This is the same root cause as plan 10's deferred item: a trashed linked memory keeps its link. Plans 13 and 17 own the hard-delete rebuild.
- **PostLogNoteEditor no longer soft-deletes anything.** Its memory path, including `deleteMemory`, is gone, so the carry-in concern no longer applies to this file. `ThingsToRememberScreen` and `MemoryScreen` remain (plans 13 and 17).
- **The Q4 error does not scroll into view.** Save shows the `FieldError` under the note but does not scroll or focus to it (`useFirstErrorReveal`): the shared form exposes no note ref. On Edit Interaction the note sits mid-form above Save, so it is normally on screen. Recommendation: wire the reveal if device testing shows it hidden.
- **The participant Sheet can close while its save runs.** Its scrim/Back is not held during "Save participant". The save still completes or fails safely, and the button is single-flight. This was pre-existing; noted only.
