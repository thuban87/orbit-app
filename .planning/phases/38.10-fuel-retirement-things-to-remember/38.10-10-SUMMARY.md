# Phase 38.10 Plan 10: Linked notes data (Also save to, Group Log copies, History tags) Summary

**A note saved to a section is now one text in two places. The interaction owns the text: edits move through the single interaction writer from either side, and one Allow AI switch covers both rows. Group Log gives each participant a linked, permanently AI-off copy of the Group Note. That copy detaches when someone edits it, when the Group Note is cleared, or when the event is detached or dissolved. Settings → AI reports and clamps the D-102 and D-103 locks and lists label-only memories. History tags a linked interaction with its section.**

## Accomplishments

- `linked-entry-dao.ts`, made only of cores and importing no other DAO:
  - D-95 slot check across both tables (soft-deleted memories still hold a slot);
  - inserts that mirror the two existing add cores;
  - propagation from the interaction side, with the Q4 blank refusal;
  - the clamped single switch;
  - Group Note copy propagation, D-113 detach and date follow;
  - reads for History and for linked taps.
- `editTouchpointFullCore` propagates text, date, time and the stored, clamped allow_ai to the `note`-linked entry in the same transaction. Unchanged rows are not restamped.
- Entry-side edits:
  - A `note` link goes through `editInteractionNoteCore`, which leads into `editTouchpointFullCore`.
  - A `group_note` copy whose text changes is detached first (D-117), so nothing outside the group-events DAO writes `group_events`.
- `setMemoryAllowAiCore` sets the interaction partner. A Group Note copy throws `GroupNoteAiLockedError` and an Off Limits lock throws `InteractionNoteAiLockedError`.
- Settings → AI:
  - Each item has a `locked` value.
  - Locked refs are clamped to 0 in SQL, so a locked ref is a no-op that still matches its row.
  - Enable counts skip locked items.
  - The interaction-side partner sync copies the stored, clamped value.
  - Label-only memories are listed, with the type's display name as their value.
  - The source fence now forbids SQL against `off_limits` and `group_events` (`FROM|JOIN|INTO|UPDATE`) and no longer names the dropped term.
- `updateGroupEventCore` is extracted. It does not bump; the wrapper bumps once, only when something changed. It is the only writer of the Group Note.
