# Phase 38.10 Plan 15: Off Limits editor and Key People editor Summary

**Off Limits now has a dedicated editor on the `off_limits` table, with no fuel editor left in it. It shows each item's full text and any link with Open, deletes at once with Undo, moves items through the shared move sheet, and opens a given item's form from `editId`. Every write is re-checked against the contact's own rows first (D-11). The add/edit form is one shared `OffLimitsForm`, now also used by the inline Off Limits section on Add/Edit Contact, so the two forms cannot drift. Key People has its own editor screen and `KeyPeopleEditor` route in every stack. The shared key-person editor now shows live linked names, uses the D-66 field for its note, opens an entry from `editId`, and no longer needs the restore prop.**

- Start 2026-10-13T21:44Z, end 22:04Z: 20 min, 3 tasks, 3 commits.
- 21 files: 2 created, 17 modified, 2 deleted (the draft adapter and its test).

## Accomplishments

**Task 1 (tracer): Off Limits editor, `8715bd87`**
- **Controller** (`off-limits-editor-controller.ts`):
  - `OffLimitsEditorDao` is now `{ list, add, edit, delete, undo }` over `listOffLimitsForContact`, `addOffLimits`, `editOffLimits`, `deleteOffLimits` and `undoDeleteOffLimits`.
  - Before every edit and delete it validates the id and re-reads the contact's rows; an id that is not one of them throws `OffLimitsScopeError` before any write (D-11). `list()` also drops any row whose `contact_id` is not this contact.
  - `onDelete` returns the snapshot. `onUndo` refuses a snapshot whose `contact_id` is another contact's.
  - Every successful write calls `onChanged` (the screen re-reads). A failed add or edit resolves false and calls `onError(error, op)`, so the form keeps its draft.
  - Pure snackbar builders: `offLimitsDeletedSnackbar`, `offLimitsRestoredSnackbar`, `offLimitsAddedSnackbar`, `offLimitsSavedSnackbar`.
- **Adapter:** `off-limits-draft-adapter.ts` and its test are deleted; nothing else used them.
- **`OffLimitsForm`:**
  - The text is an `EntryTextField` (D-66). It has an optional label and, when `showLink` is on, an optional link checked through `isValidLinkInput` (which applies `isValidHttpUrl`) with a `FieldError` (G-13).
  - Save is disabled while the entry has no content or the link is invalid. It is single-flight while an async save runs (G-15). Text is trimmed only at Save, through plan 14's `normalizeOffLimitsForm` (`normalizeEntryText`).
  - It takes no keyboard prop. It shows Delete only when the host passes `onDelete`, and reports `onDirtyChange` for the Back guard.
- **`OffLimitsInlineEditor`** (plan 14's component) now renders `OffLimitsForm` with `showLink={false}`. Its props, handle, draft-state reports and held-delete behaviour are unchanged.
- **`OffLimitsEditorScreen`:**
  - The ADR-168 gated read (loading, Retry) through `controller.list()`.
  - `useContactHeader`, a child `ShellAppBar` with `backDisabled={saving}`, and `useDiscardKeepGuard` with the open form as the sub-editor.
  - The ScrollView has `ref` and `innerViewRef`, plus `useKeyboardCentering`, `KeyboardCenteringProvider`, and `bottomSpacer` last.
  - An empty list shows `EmptyState` with an "Add Off Limits Item" action (glossary `ADD_OFF_LIMITS_ITEM`). Otherwise a solid "Add Off Limits Item" follows the rows.
  - Rows show full text, label, and a stored URL with "Open link" through `openMemoryLink` (D-24), plus Edit and Move. No AI control and no sparkle.
  - Delete is in the edit form and happens at once, with an Undo snackbar and then a confirming snackbar.
  - Move opens `MoveEntrySheet` (`off_limits` ref, section `off_limits`); `onMoved` and `onMoveUndone` re-read the list.
- The tracer verify (12 tests) passed right after the commit and again before Task 2.
