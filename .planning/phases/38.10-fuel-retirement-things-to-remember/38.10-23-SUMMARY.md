# Phase 38.10 Plan 23: Snackbar restyle (G4, D-132, D-140) Summary

**Notices are now accent pills with `onAccent` text. Destructive results and errors use an inverted warning pill with the warning glyph, and errors keep their assertive alert. On the root host the pill is left-aligned at about 80% width when only the universal FAB is on screen, and centred at about 60% when a section FAB is present. In both cases the width is clamped so the pill never covers a FAB lane. O5 is fixed: with no action, the text no longer runs into the pill's right edge.**

## Accomplishments

- **Kinds:** `SnackbarKind` is now `"success" | "warning" | "error"`. The store's 6-second auto-dismiss is unchanged (38.9 D-04), and a test pins it for a warning message.
- **Look (`snackbarPresentation`):** it returns palette keys only, never colours.
  - success: `accent` fill and outline; `onAccent` label and actions; no glyph; polite.
  - warning: `textPrimary` fill and outline; `background` label and actions; `background` warning glyph; polite.
  - error: the same paint as warning (`WARNING_LOOK`, D-140); assertive with the `alert` role (D-72).
- **Snackbar.tsx:**
  - It paints the fill, outline, label, glyph and both action labels from the look. `colors.accentText` and `colors.surface` are gone.
  - The glyph stays hidden from TalkBack.
- **Geometry (root host only):**
  - `snackbarLayout` reads the window width, the presence of `useShellObstacleStore` `rects["shell-fab"]` (UniversalFab publishes it only while it shows) and `selectSectionFabPresent`.
  - Universal FAB only: the pill is left-aligned and `min(round(0.8·W), W − 16 − 84)` wide.
  - Section FAB present: the pill is centred and `min(round(0.6·W), W − 2·84)` wide. 84 is `FAB_SIDE_INSET + FAB_SIZE + SNACKBAR_FAB_GAP`.
  - Neither FAB, and every overlay host: unchanged geometry.
  - On every phone width the clamp is what applies. At 393 px the pill is 293 px (about 75%) with the universal FAB only, and 225 px (about 57%) with a section FAB.
  - The overlay keeps `pointerEvents="box-none"` and `collapsable={false}`.
  - The label wraps (it has no `numberOfLines`).
- **O5:** `snackbarPadding(hasAction)` gives right padding of `SPACING.base` when there is no action, and 0 when there is one, because the action's own padding closes that side.
- **Destructive sites changed to `warning`** (12 sites in 10 files, all wording unchanged):
  - the delete on the section editor, history page, Off Limits editor and Key People editor;
  - Update Contact's key-person, memory and Off Limits deletes;
  - `showDeleteUndo` in Systems (both labels);
  - Category delete, through `categoryResultKind` (add and rename stay `success`);
  - the three `undoResultSnackbar` results;
  - HomeScreen's bulk Quick Log Undo ("Undid N logged …") and "Removed N contacts from Favorites", through `commitBulkOutcome(label, kind = "success")`.
- **Contrast (pinned in snackbar-host.test.ts):** for success, warning and error, in all four package × mode palettes and with every curated accent:
  - the label on its fill is at least 4.5;
  - the action tone equals the label tone;
  - the glyph on the fill is at least 3.0.
  - The old danger-on-surface loop was removed because no kind uses a `surface` fill any more.
- **RG-029:** M59 and M60 are now `obsolete — removed by 38.10 Plan 23 (acb1e464)`. The done-row pin went from 50 to 48, and the comment and the `it(...)` title were updated.

## Decisions Made

- **The warning look is the plan's proposal, unchanged:** an inverted `textPrimary` pill. It is still the owner's look check at plan 19 (D-132 leaves the look open).
- **The error look follows D-140:** the same paint as warning, built from one shared `WARNING_LOOK` constant so the two cannot drift apart. A test pins that error and warning have identical paint and that success differs.
- **Category kind:** `categoryResultKind(operation)` maps delete to warning and everything else to success. `reconcilePendingCategoryMutation` passes it to `publishSuccess(label, kind)`. The test's `it.each` table now carries the kind.
- **Label growth:** `flexGrow: 1` on the label puts the action at the right end of a fixed-width pill, which is the usual snackbar layout. Content-sized pills (overlay hosts, and the root host with no FAB) are unchanged.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The glyph tone key is `glyphTone`, not `glyph: { tone }`**
- **Found during:** Task 1
- **Issue:** The repo-wide accent foreground role contract (`accent-foreground-role-contract.test.ts`, 38.4 D-63 / ADR-084) treats any `tone: "background"` property as "a label on an accent fill painting the page background". The warning glyph sits on the inverted `textPrimary` fill, not on an accent fill, so the finding was a false positive. That contract's allowlist is deliberately limited to the owner's D-63 graphic tints and Skia paints, and a test enforces the limit. Widening it would have weakened an owner-ruled control, so I did not.
- **Fix:** I renamed the key to `glyphTone`, which matches the other `fillTone`/`labelTone`/`actionTone`/`borderTone` keys. The contract and its allowlist are untouched. The real pairing (glyph on fill ≥ 3.0, label on fill ≥ 4.5) is pinned in `snackbar-host.test.ts`.
- **Files modified:** snackbar-host.ts, Snackbar.tsx, snackbar-host.test.ts, Snackbar.test.tsx
- **Commit:** `3415609e`

**2. [Ordering] The RG-029 M59/M60 update came right after Task 1, not inside Task 3**
- **Found during:** Task 1
- **Issue:** Task 1 removes `accentText` from the Snackbar action labels. `accent-text-glass-contract.test.ts` would therefore have stayed red across Task 2's commits.
- **Fix:** I recorded the obsolete rows (with Task 1's sha, `acb1e464`) and the 50 → 48 pin in a separate follow-up commit straight after Task 1. The content is exactly what the plan describes, following the 623a4715 precedent, with nothing amended.
- **Commit:** `87d7b5e1`

**3. [Detail] Task 1's interim error look kept today's caption tone**
- In Task 1 the error branch kept a `surface` fill, a `textSecondary` label (AppText's caption default, so nothing changed visibly) and an `accentText` action. Task 3 replaced it with the D-140 look as planned.
