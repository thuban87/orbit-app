## 1. Ordering decision (fuel and `is_current` drop)

**Chosen: a sequential schema block, not a shim and not one parallel wave.**

| Wave | Plans | Purpose |
|---|---|---|
| W1 | 01 | Migration 033 |
| W2 | 02 | Knowledge DAOs |
| W3 | 03 | Current state and move DAO |
| W4 | 04–08 | Retarget every remaining SQL consumer: backup, merge/purge, AI, search/glance, sharing data |

- **Why:** tsc cannot see SQL, and about 81 tests migrate to `TARGET_VERSION` (RESEARCH Pitfall 1). Nothing between "033 lands" and "every SQL consumer is retargeted" can pass vitest.
- **Why not one wave:** the earlier draft put all of this into one wave. Research showed that needs cross-plan file edits: plan 01's union changes break tsc in purge-dao, fuel-dao, memories-dao, MemoryEditor and backup-schema. Same-wave plans may not share files. Sequential waves make the real dependencies explicit (`depends_on`) and let a later wave touch an earlier wave's files.
- **Gate rule (W1–W3 and inside W4; derived from RESEARCH Pitfall 1; "this plan only"):**
  - each plan leaves `npx tsc --noEmit` and its own touched tests green;
  - other suites may be red until W4 ends;
  - the full post-merge gate (`npx tsc --noEmit && npm run check:colors && npx vitest run`, memory `tsc-in-post-merge-gate`) is first required green **after W4**, and after every later wave.
- **Temporary TS surface, until plan 18:**
  - `fuel-dao.ts` and `fuel-read.ts` become an **Off Limits-only shim** with no fuel SQL:
    - edits and deletes reach `off_limits` only;
    - adds route by kind through `legacy-fuel-mapping`;
    - `listFuelForEditor` reads `off_limits` in the old row shape.
  - The capture callers are retargeted for real in plan 08, so the shim never has to guess a table from an id.
  - The soft-delete, restore, purge and expire functions stay until plan 18 (option A from plan-02 research).
- **Reversibility:** D-54's `DROP TABLE fuel` is a one-way door the owner already accepted (CONTEXT D-54). Plan 01 rates it `one-way`, records that acceptance and adds no new checkpoint.
