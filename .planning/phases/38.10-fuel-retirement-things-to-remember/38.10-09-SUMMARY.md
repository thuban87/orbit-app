# Phase 38.10 Plan 09: Contact-form data layer and the shared entry field Summary

Add/Edit Contact aggregates now write Off Limits through the off-limits cores, dated Last Talked About / Current Location entries through `addCurrentStateEntryCore`, and hard-delete held memory / key-person / Off Limits deletes at Save with a single revision bump. ## Deviations from Plan

**1. [Tracer gate, process] The tracer was not stopped at an interactive checkpoint.**
- Config has `auto_advance: false`. The plan is `autonomous: true`, the orchestrator dispatched it as an autonomous sequential run, and the tracer's `<verify>` is an automated vitest run.
- I re-ran it end to end after the commit (176 tests passed) and then went on to the expansion tasks, rather than returning a human-verify checkpoint on a passing automated test.

**2. [Rule 2, robustness] `rowSignature` ignores keys whose value is `undefined`.**
- Without this, a draft carrying `provenance: undefined` or `kind` would read as an edit.

**3. [Rule 2, correctness] Off Limits drafts are reduced to content fields before diffing.**
- They are no longer filtered by `kind`. EditContactScreen still writes `kind: "off_limits"` onto its rows until plan 14, and an extra key must not make an untouched row read as edited.
- Every row in this table is Off Limits (D-11), so there is nothing left to filter.

**4. [Rule 1, robustness] The hook's blur-clearance callback skips when a newer entry field is focused.**
- Moving between two entry fields fires a blur measure and a focus measure. The stale blur must not shrink the new field's spacer.

**5. [Plan detail] The ScrollView is measured through `getNativeScrollRef()`.**
- RN's ScrollView TS type has no `measureInWindow`. The runtime ref is the host instance, but the typed path is the native-ref getter.

**Total deviations:** 5 (1 process, 4 auto-fixed). **Impact:** none on scope. The plan count is unchanged.
