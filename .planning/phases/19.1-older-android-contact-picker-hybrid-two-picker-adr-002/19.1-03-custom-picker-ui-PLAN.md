<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Full Contacts Provider → summary list (native) | The whole address book is read for the browsable list; must minimize what is materialized and never egress it. |
| Selected lookupKeys → full read | Only user-selected contacts get full-field + full-photo reads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19.1-09 | Information disclosure | Whole-book contact PII materialized/leaked | high | mitigate | Summary read holds only lookupKey/name/one method/thumbnail on-device; no network, no content log; full read scoped to the selection (D-06, D-10). |
| T-19.1-10 | Information disclosure | Contact photos over-staged to app cache | low | mitigate | List uses lazy expo-image thumbnails; only selected contacts' full photos are staged to app-private cache at read time. |
| T-19.1-11 | Denial of service (perf) | Large book janks the JS thread | low | mitigate | Virtualized FlatList + lazy photos + two-tier read; perf validated on the physical Pixel 3a (plan 19.1-05), never the emulator. |

No network, no external API, no new package installs (reuses installed expo-image + toolchain); no supply-chain gate applies.
</threat_model>
