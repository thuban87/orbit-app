## Synthetic Fixture Protocol

Use a local/device-only Contacts storage location. Do not attach any fixture to an owner
account or sync provider. Every value below is intentionally synthetic.

| Fixture key | Required shape | Synthetic data convention | Purpose |
| --- | --- | --- | --- |
| `fixture-birthday` | One birthday and one anniversary event | Display label `Orbit Fixture Birthday`; use `+1-555-0101`, `fixture-birthday@example.com`, and distinct synthetic calendar values | D-03 birthday-only gate and run-as storage read |
| `fixture-nameless` | Organization only; no structured name | Organization `Orbit Fixture Organization`; no name, phone, email, photo, or birthday | D-12 bulk skip versus single-review behavior |
| `fixture-name-only` | Structured name only; no methods or photo | Display label `Orbit Fixture Name Only`; no phone, email, photo, or birthday | G3/F11 two-query browse/search regression |
| `fixture-slash-birthday` | Canonicalizable slash-format birthday | Display label `Orbit Fixture Slash`; a synthetic unambiguous day-first slash date such as `13/04/2031` | D-13/G1 single-review canonicalization |
| `fixture-bad-birthday` | Genuinely unparseable birthday | Display label `Orbit Fixture Bad Date`; ambiguous or invalid synthetic date | D-13 review error, not silent drop |
| `fixture-linked` | A fixture imported once, then selected again | Reuse a synthetic fixture after its first successful import | D-14b terminal completion exit |

### Fixture creation and reset

1. Before creating fixtures, confirm the Contacts account/storage shown by the device is a
   local test-only store and not an owner account.
2. Create the six fixture shapes above in the device Contacts UI, using only the exact
   `Orbit Fixture …` labels and synthetic `example.com` / `+1-555-01xx` values.
3. Capture no screenshots until the visible rows contain only synthetic fixtures. If an owner
   contact is visible, do not capture it; navigate or crop so it cannot appear.
4. For the large-book case, import a generated VCF whose entries are named
   `Orbit Load 0001` through `Orbit Load 1000`, have at most synthetic `+1-555-02xx` values,
   and contain no photos. Retain the VCF locally only. Reset by deleting all contacts whose
   name begins `Orbit Load `, then confirm the count is zero before a repeat run.
5. For the >900 selection case, use the same 1,000-entry synthetic load fixture. Reset any
   Orbit import sessions and app data only after the evidence has been recorded; do not touch
   non-fixture contacts.

### Separate empty-book pass

The empty-book assertion must not share the populated fixture state. Use a separate Android
user/profile with no contacts, or use this reset sequence: locally retain the synthetic-fixture
VCF, delete only contacts whose names begin `Orbit Fixture ` or `Orbit Load `, verify the
Contacts app is empty, run the empty-book assertion, then re-import the synthetic VCF and
recreate the organization-only fixture. Do not clear a provider/account that could remove an
owner contact.
