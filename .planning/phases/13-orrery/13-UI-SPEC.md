# Phase 13 — UI Design Contract (Orrery)

> Visual and interaction contract for the two-view Skia "solar system". Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a Skia render-surface phase, not a form/list phase.** The standard template dimensions (spacing / typography / colour / copy) below govern the *chrome* — the orrery screen header, the view toggle, the Settings-side controls, and the empty state. The **canvas contract** (geometry, render layers, morph, ring vocabulary, star palette, interactions) is carried in the phase-specific sections after the standard six. Both are binding.

## Spacing Scale

Chrome spacing (Settings rows, header, view toggle, empty state) reuses the repo's shipped scale. Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/label inline gaps |
| sm | 8px | Compact gaps (chip row gap, empty-state gap) |
| md | 16px | Screen padding, section padding (matches every screen root) |
| lg | 24px | Swatch-row breathing room |
| xl | 32px | Major section break |

**Inherited chrome exceptions (carried from shipped screens — do not "fix"):** `10`, `12`, `14` px appear in the shipped row/chip idiom (`borderRadius: 10`, `padding: 12`, `paddingHorizontal: 14`, `gap: 12`) and in the segmented-control this phase reuses. Match the existing rows verbatim; consistency with the shipped Settings/FilterChipRow chrome outranks the 4-multiple ideal for these inherited primitives.

**Touch-target exception:** every tappable control (toggle segment, star swatch, sun-picker row, Settings row) keeps `minHeight: 44`. On the canvas, planet hit-testing pads to a ≥44px-diameter target (see Interaction Contract).

**Canvas geometry is NOT spacing.** Orbit radii, planet/sun sizes and drift are computed layout constants in device px (see Canvas Geometry), tuned at the top of their module — they are exempt from the spacing-token scale.

## Color

The app ships one dark preset (`space-dark`, dark-only) in `src/theme/theme-presets.ts` — the **single place** a hex literal may appear. All values below resolve through `useTheme().colors.*`, **including inside Skia draw calls** (P1: Skia accepts runtime token/HSL strings — proven by `CropPhotoScreen`). No hex anywhere else, canvas included.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `background` | `#0B0E1A` | Canvas `<Fill>`, screen background — the orrery is mostly deep space |
| Secondary (30%) | `surface` / `surfaceElevated` | `#141828` / `#1D2235` | Settings rows, inactive toggle segment, starfield mid-tones |
| Accent (10%) | `accent` | `#6C8CFF` | see reserved list |
| Destructive | `danger` | `#E5484D` | not used this phase (no destructive action) |

**Accent (`#6C8CFF`) reserved strictly for:**
- the **active** view-toggle segment (filled-accent chip idiom — dark `background` label on accent fill);
- the **selected** star-swatch indicator (ring/check around the chosen self-sun colour);
- the **ring_seq radial-drag** live preview highlight (the ghost ring the dragged planet snaps to);
- the pressed/active state of the dashboard header **Orbit** button.

Accent is **NOT** a status colour and **NOT** a star colour — it must never tint a planet, ring, or the sun.

### Status colours (existing — reused verbatim, never recomputed)
The orrery reads status from `src/db/status.ts` (`STATUS_SQL`, `ROGUE_K = 3`) and colours from the shared tokens already consumed by the dashboard card and the widget. One source of truth.

| Status | Token | Value | Planet body | Orbit ring (extends `contact-card-ring.ts`) |
|--------|-------|-------|-------------|---------------------------------------------|
| stable | `statusStable` | `#45B98A` | full-colour photo/swatch | **solid**, width 2, opacity 1 |
| wobble | `statusWobble` | `#E8C15C` | full-colour | **dashed**, width 3, opacity 1 |
| decay | `statusDecay` | `#E56A52` | full-colour + drift-outward | **faded**, width 4, opacity ~0.7 |
| rogue | `rogue` (ring) + new `rogueExtinguished` (body) | `#E0904A` / *new* | **cold / extinguished** desaturated-dark body | **faint trace**, width 1–2, opacity ~0.3 |

The ring progression `solid → dashed → faded → faint-trace` is the existing §7 vocabulary; drift-outward "simply goes further" for decay, and furthest (bounded) for rogue.

### New theme tokens this phase adds to `space-dark.dark` (infrastructure seeds — owner-tunable, mirroring the `avatarSwatches` / `gravityTiers` discipline)
All are **design-pass seeds** (13-CONTEXT `<deferred>` — exact hexes are the owner's §12.4 taste call); ship these as the tunable default.

1. **`starPalette: string[]`** — the ~6 curated self-sun star colours, **ordered, stable** (reordering restyles every self-sun; never reorder without accepting that). Astronomy-grounded spectral spread:
   - `#F2C14E` — gold (**default self-sun**, warm gold/yellow, Sun-like)
   - `#E8944A` — amber
   - `#D96B7C` — rose-red (deliberately nudged off `statusDecay #E56A52` so it never reads as a status)
   - `#A98BE0` — violet
   - `#5CC6F0` — cyan (deliberately nudged off `accent #6C8CFF`)
   - `#DCE6FF` — ice-white
2. **Self-sun default** = `starPalette[0]` (`#F2C14E`). Migration 003's `self_sun_colour` default writes this token value.
3. **Relationship "muted" palette** — desaturated (NOT greyscale, NOT single-neutral) versions of the three live status hues, the colour endpoint the morph fades toward. Same hue, low saturation:
   - `mutedStable` `#7A9E92`
   - `mutedWobble` `#C4B98F`
   - `mutedDecay` `#C79285`
   (rogue stays extinguished/cold in **both** views — no separate muted rogue.)
4. **`rogueExtinguished`** — the cold, dark, desaturated planet-body fill for a rogue contact, distinct from decay's colour and from the warm `rogue` amber (which stays the ring + in-app label hue). Seed: `#3E4A6B` (cold blue-grey, dark). The rogue **ring** keeps `colors.rogue` amber at faint-trace opacity; the **body** uses this.

**Contract:** self-sun glow = the picked `starPalette` token; a **contact-occupied** sun glows that contact's *status* colour (unchanged from 01-data — the user pick applies to the self-sun only).

## Canvas Contract (phase-specific)

### Canvas Geometry — top-of-file tunable constants (device px; owner/planner-tunable)

| Constant | Seed | Meaning |
|----------|------|---------|
| `SUN_RADIUS` | 30 | Central star disc radius |
| `SUN_GLOW_RADIUS` | 54 | Glow radius; **pulses** ±~10% (see Ambient) |
| `RING_INNER` | `SUN_RADIUS + 28` | Innermost orbit radius (rank 0) |
| `RING_GAP` | 34 | Radial gap between successive `ring_seq` ranks |
| `PLANET_RADIUS` | 16 | Planet photo-circle radius |
| `HIT_RADIUS` | 24 | Hit-test radius (≥44px-diameter tap target) |
| `DRIFT_MAX` | bounded to `min(cx, cy) − PLANET_RADIUS − 8` | Furthest drift; rogue clamps here to stay on-screen + tappable |
| `MORPH_MS` | 500 | View-morph duration (ease-in-out) |

- **Sun** at canvas centre `(cx, cy) = (screenW/2, canvasH/2)`. No orbit ring. Renders the occupant's photo/initials (self profile photo, or the assigned contact's) clipped in a circle, wrapped in a coloured glow: self → picked `starPalette` token; contact → that contact's status colour.
- **Orbit radius** = `RING_INNER + rank × RING_GAP`, where `rank` is the contact's position by `ring_seq` (radius = closeness, the **shared axis** — fixed and identical in both views). If ranks overflow the viewport, compress `RING_GAP` proportionally (planner detail; keep furthest ring on-screen).
- **Angle (status view)** = interval progress from `PROGRESS_SQL` mapped to a top-anchored sweep (§7: top arc carries the first half of the interval, bottom arc the second; 0 at 12 o'clock, clockwise). Exact piecewise angle↔time math lives in a pure `*-logic.ts` module (deferred to planning).
- **Drift:** a decayed body's *drawn* radius = ring radius + `drift(progress)`, a bounded outward push growing with `progress`; rogue = the furthest, clamped to `DRIFT_MAX`.
- **Never-contacted excluded** (`last_contact IS NOT NULL`) — they never appear.

### Render layers (z-order, bottom → top)

1. `<Fill color={colors.background}>` — deep space.
2. **Starfield** — subtle animated twinkle (cheap shader or low-opacity star dots in `textSecondary`/`textPrimary`/`starPalette` tones). Ambient, animated.
3. **Orbit rings** — one stroked ring per contact, style by status (solid/dashed/faded/faint-trace table above), colour via token.
4. **Planets** — `useImage(absoluteFileUri)` photo clipped to a `<Circle>` (`fit="cover"`), fallback = themed `avatarSwatches` swatch + initials (Paragraph API, bundled font), with the status-coloured body treatment; rogue body = `rogueExtinguished`.
5. **Sun** — glowing occupant disc at centre, pulsing glow.
6. **Empty-state prompt** — an RN `<View>` overlay (not Skia): heading + body copy above, when zero orbiting contacts (sun still renders in layer 5).

### Two-view Morph

- A single Reanimated **`morph` shared value**: `0` = Status view (default on open), `1` = Relationship view.
- Driven by the **segmented control** (Status ｜ Relationship) via `withTiming(target, { duration: MORPH_MS, easing: Easing.inOut })` — one tunable constant.
- In `useDerivedValue` worklets, per body `interpolate()`:
  - **Angle:** Status progress-angle ↔ Relationship even aesthetic spread (rings already separate everyone by radius, so relationship angle is free — even spread seed; light grouping is a deferred aesthetic call).
  - **Colour:** full status saturation ↔ muted (`interpolateColor` full-token ↔ `muted*` token). Rogue interpolates toward its cold `rogueExtinguished` in both.
  - **Radius:** **fixed** — never interpolated (shared axis).
- The morph is **event-driven and self-terminating** — it does **not** need pause-on-blur (only the ambient layer does).

### Ambient layer (animated) + pause-on-blur

- **Starfield twinkle** (subtle) + **slow sun pulse** (glow radius/opacity oscillate, ~2–4s period). Bodies do **not** animate — they are placed by timestamp math on focus and sit still.
- **Pause = unmount `<Canvas>`** when `!(useIsFocused && AppState === 'active')` (P2: the Skia/Reanimated clock has no pause arg; gating derived values only hides motion). This is the required mechanism.
- Perf/battery claims are **physical-Pixel-only** (the orrery is a Skia render-loop feature; the emulator cannot assess it).

### Interaction Contract

| Gesture | Result |
|---------|--------|
| **Tap a planet** | Coordinate hit-test (`(x−cx)²+(y−cy)² ≤ HIT_RADIUS²`, nearest wins on overlap) → navigate to that contact's Profile. The orrery is a launcher. |
| **Tap the sun** | If a contact occupies it → open that contact's Profile; if self → no-op. |
| **Drag a planet radially** | Live-preview the target ring (accent ghost-ring highlight); on **release**, snap to the nearest rank and commit `ring_seq` through a single transactional writer. Angular component is ignored during the drag. |
| Long-press | **Unused** — owner explicitly rejected long-press (accident-prone, collides with radial drag). Do not add sun-assignment here. |

- Gesture composition: `Gesture.Race(tap, pan)` — a stationary touch opens the profile; movement past a small threshold activates the radial drag. Both first hit-test the planet under the touch-down point.
- The `last_contact` single-writer DAO is **untouched**; only `ring_seq` (per contact) and the two app-level settings are written, each via a transactional writer.

### Settings-side controls (new, in `SettingsScreen`, following the shipped row idiom)

Both reuse the shipped row chrome (`surface` fill, `border`, `borderRadius 10`, `padding 12`, label 16/600, helper 13/400) and write to `app_settings` via the DAO (new **migration 003** adds `sun_contact_id` nullable [NULL = self] + `self_sun_colour`).

1. **"Your star"** — a horizontal row of the ~6 `starPalette` swatches rendered as circular ≥44px targets (mirrors the Phase-5 avatar-swatch discipline); the selected swatch carries an `accent` ring/check. Writes `self_sun_colour`. Mirrors the "Your photo" self pattern already in Settings.
2. **"Sun / centre"** — a row opening a picker listing **your favourites first, then all contacts, plus "Me"** (NULL = self). Writes `sun_contact_id`. This is ORR-06's "assign the sun" relocated to Settings by owner decision — **not** an orrery gesture (record so it is never mis-flagged as an ORR-06 gap; the half of ORR-06 that stays on the canvas is the `ring_seq` radial drag).
