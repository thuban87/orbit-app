## Render architecture — MANDATORY component decomposition (H1, addresses review concern: Rules of Hooks)

The one proven Skia surface in the repo (`CropPhotoScreen`) has exactly ONE unconditional `useImage`. The orrery renders a DYNAMIC list of bodies (one per orbiting contact), and 13-07 adds a per-body `useDerivedValue` (morph) and a `useClock`-driven ambient loop. React's Rules of Hooks forbid calling a hook inside a `.map()` over that dynamic list — the hook count would change with the contact count and crash. This structure is NOT left to executor interpretation; it is a required decomposition into keyed child components:

- **`OrreryCanvas` (`src/components/orrery/OrreryCanvas.tsx`)** — the conditionally-mounted `<Canvas>` subtree. It owns the ambient/clock hooks (`useClock` lands here in 13-07) so that UNMOUNTING it truly stops the render loop (pause-on-blur, Pitfall 4). OrreryScreen renders `{visible ? <OrreryCanvas …/> : null}`; the clock hook is never in OrreryScreen itself.
- **`OrbitBody` (`src/components/orrery/OrbitBody.tsx`)** — ONE planet, keyed `<OrbitBody key={contact.id} …/>`. It owns exactly one `useImage` (the contact photo) and its per-body `useDerivedValue`s (morph position/colour, added in 13-07). OrreryScreen's `.map()` returns `<OrbitBody/>` ELEMENTS only — it calls no hook inside the map.
- **`SunBody` (`src/components/orrery/SunBody.tsx`)** — the centre sun: owns the sun photo `useImage` and any sun-glow/pulse derived hooks (pulse added in 13-07). Rendered once (not in a map).

OrreryScreen owns only screen-level hooks (theme, focus effect, the read state, the measured-canvas metrics, gesture objects) — a fixed hook count independent of contact count. This section is threaded into 13-07 (which adds the per-body morph `useDerivedValue` to OrbitBody and `useClock` to OrreryCanvas), so the same boundary holds when motion lands.
