# Phase 5 — UI Design Contract

> Visual and interaction contract for the Photos pipeline: system-library picker + pasted-URL path,
> an in-app Skia crop, and a deterministic themed-initials fallback avatar. One 512×512 JPEG master
> reused by contacts, the self record, and custom `photo` fields. Generated by gsd-ui-researcher,
> verified by gsd-ui-checker.
>
> **Authority:** every decision below traces to `docs/dossier/07-photos.md` (7 questions, 3 rounds,
> no `[OPEN]` items), `docs/dossier/INDEX.md` `[photos → *]` rows, `HANDOFF.md` §14.3/§14.8/§4, and
> REQUIREMENTS `PHOTO-01…05`. This is a **React Native / Expo** app — the shadcn gate does not apply
> (no `components.json`, not React web). The design system is the project's own theme-token
> architecture in `src/theme/`.

## Spacing Scale

The project does **not** use a strict 8-point scale; 28 completed plans have established a de-facto
scale that mixes 4-multiples with 10/12/14. This phase MUST match the existing scale for visual
consistency — do not impose a foreign 8-point grid.

| Token | Value | Usage (as already used in `src/`) |
|-------|-------|-----------|
| xs | 4px | Tightest inline gaps |
| sm | 8px | Compact element gaps (`gap: 8`), section body gaps |
| — | 10px | Vertical control padding (`paddingVertical: 10`) — de-facto, keep |
| md | 12px | Card/control padding (`padding: 12`), row gaps (`gap: 12`), horizontal control padding |
| — | 14px | Button horizontal padding (`paddingHorizontal: 14`) — de-facto, keep |
| lg | 16px | Screen content padding (`padding: 16`), major gaps (`gap: 16`) |
| xl | 24px | Wide horizontal padding for prominent controls (`paddingHorizontal: 24`) |

Radius: `borderRadius: 8` is the app default (buttons, cards, inputs); `10`/`12` for larger surfaces;
`999` for pills. **Avatars are circular: `borderRadius = size / 2`** (full circle), matching the
plugin's round profile photos and the orrery "planet" framing (HANDOFF §7).

**Touch targets:** interactive controls keep `minHeight: 44` (established by `ContactProfileScreen`'s
`addDetails`). The photo-action buttons, crop confirm/cancel, and URL submit MUST honour 44px.

Exceptions: the 10px and 14px values are pre-existing de-facto steps, retained deliberately — not new
deviations introduced by this phase.

## Typography

Declared to match the de-facto scale already in `src/` (derived from a scan of all screens/components):
sizes 13 / 15 / 16 / 24 dominate; 18/22/32 are one-offs to avoid. Weights in use are `600` and `700`,
with body copy at the RN default (`400`).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Label / secondary | 13px | 600 | 1.4 | Section headings (uppercase), captions, the "Rarely responds" label, helper text under the URL field |
| Body | 15px | 400 (default) | 1.5 | Descriptive copy, error text, dialog body |
| Action / button | 16px | 600 | 1.2 | Photo-action buttons ("Add photo" / "Change photo"), crop "Use photo", "Add from URL" |
| Heading / title | 24px | 700 | 1.2 | Screen title (crop screen header) — matches `ContactProfileScreen` title |

**Avatar initials** are the one size-driven exception: the initials glyph scales with the avatar
diameter at **~40% of diameter**, weight `700`, colour = the on-swatch text token (below). It is not a
fixed point size because the same `Avatar` component renders at grid, profile-header, and sun sizes.

Weights: this phase uses `400` (body default), `600` (semibold emphasis), `700` (titles + initials) —
the exact set the rest of the app already uses. No new weight is introduced.

## Color

All values resolve through `space-dark` theme tokens (the only shipped preset — infrastructure, not a
finished palette; final visual design is the owner's call per HANDOFF §7). No hex may appear outside
`theme-presets.ts`, **including in Skia draw calls on the crop canvas and in the initials avatar**.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (60%) | `background` | `#0B0E1A` | Crop screen backdrop, photo-section background |
| Secondary (30%) | `surface` / `surfaceElevated` | `#141828` / `#1D2235` | Photo-action button surfaces, URL input field, crop-frame scrim, the crop mask (dim over the non-selected region) |
| Accent (10%) | `accent` | `#6C8CFF` | See reserved-for list below |
| Destructive | `danger` | `#E5484D` | "Remove photo" action + its confirmation button ONLY |
| Borders | `border` / `borderStrong` | `#2A3048` / `#3C4568` | Field/button borders, crop-frame outline |
| Text | `textPrimary` / `textSecondary` | `#E6E9F5` / `#8B93B0` | Copy per typography roles |

**Accent reserved for:** the primary photo CTA ("Add photo" / "Change photo" text-link or filled
action) and the crop "Use photo" confirm button. NOT for the crop frame, NOT for the URL field
border, NOT for "Remove". (Matches the app convention: accent = the single primary action per surface.)

### Avatar swatch set (PHOTO-04 — net-new token, the core Color deliverable)

The plugin's `hsl(hash(name) % 360, 65%, 45%)` is **barred** by CLAUDE.md (free hue, no theme token,
won't restyle on theme change). Replace with a **finite themed swatch set**:

- **Add `avatarSwatches: readonly string[]` to `ThemePalette`** (`theme-types.ts`) and populate it in
  every preset's palette (`theme-presets.ts`) — dark now, light when authored. This keeps swatches
  inside the single colour-literal file and makes them restyle with the theme, exactly like every
  other token.
- **Count: 8 swatches** (recommended). Finite palette is the accepted trade (dossier Cluster C) —
  enough for glance-ability across the grid/orrery without an infinite-hue carve-out.
- **Deterministic pick:** `index = abs(hash(name)) % avatarSwatches.length`, reusing the plugin's
  existing hash (`str.charCodeAt` rolling `((hash<<5)-hash)`) but indexing the swatch array instead of
  producing a hue. Same person → same swatch, stable across sessions and surfaces (card, profile, sun).
- **On-swatch text:** add a single companion token **`avatarSwatchText: string`** (one readable
  foreground used on ALL swatches) OR guarantee each swatch has ≥4.5:1 contrast with `textPrimary`.
  Recommended: one dedicated `avatarSwatchText` (e.g. a near-white) so the initials are always legible
  regardless of which swatch is picked. The initials glyph MUST use this token, never a raw colour.
- **Empty name → blank swatch, no initials** (dossier "Decisions made without you"): render a neutral
  swatch (recommend index 0 or a dedicated neutral) with no glyph.
- **Recommended starter hex** (infrastructure default, owner-tunable like the rest of `space-dark` —
  deep-space-harmonised, muted, distinguishable on `#0B0E1A`): these are a seed, not a taste ruling —
  the owner may retune. `#5B6CB8`, `#4E8A8A`, `#8A6BB0`, `#B07A5B`, `#5B9E6B`, `#B05B7A`, `#9E9E5B`,
  `#5B8AB0`. Paired `avatarSwatchText: #F2F4FB`.

This same swatch fallback extends to the self record and to custom `photo`-field values (dossier
`[photos → fields]`).

## Component & State Inventory

The Avatar and photo-picker flow are the phase's UI surfaces. Each state is a contract the executor
must implement and the auditor will check.

### `Avatar` component (render surface — reused everywhere)
Renders a contact/self photo OR the themed-initials fallback. `expo-image` with
`contentFit="cover"`, `cachePolicy="memory-disk"`, `recyclingKey={contactId}` in grids (dossier).
Circular (`borderRadius = size/2`). Resolves the stored **relative** filename to `file://` at render
(never a network URL — no network on any read path).

| State | Contract |
|-------|----------|
| Has photo | `expo-image` renders the resolved `file://` master, cover-fit, circular. |
| No photo | Themed swatch (deterministic) + initials (`~40%` diameter, `700`, on-swatch text token). |
| Empty name | Blank neutral swatch, no glyph. |
| Load failure (`onError`) | Fall back to the themed-initials avatar (mirrors the plugin's `onError`). |

### Photo source picker (edit-only — never on the create form, dossier / 06-crud Cluster A)
Two entry points on the edit surface / self record / custom `photo` widget:

| State | Contract |
|-------|----------|
| No photo yet | Primary CTA "**Add photo**" (accent). Below/secondary: "**Paste image URL**" affordance. |
| Choosing source | "**Choose from library**" launches `launchImageLibraryAsync` (`mediaTypes: ['images']`, NO camera, NO runtime permission — Android 13+ system Photo Picker). Result is `{ canceled, assets[] }`. |
| Picker canceled | Silent — return to prior state, no error, no toast. |
| Has photo | "**Change photo**" (accent) + "**Remove photo**" (danger). |
| URL entry | A themed text input (`surface` bg, `border`) + "**Add from URL**" submit (44px). Placeholder: "https://…". |

### In-app Skia crop (net-new, no plugin predecessor — dossier flags it as build, not port)
Resolves the deferred interaction-model question: **pan + pinch-zoom over a fixed 1:1 (square)
viewport; no rotation in v1.** The master is 512×512 square, so the crop frame is a fixed centred
square; the user pans/zooms the image beneath it to frame the face.

| Aspect | Contract |
|--------|----------|
| Canvas | `react-native-skia` `Canvas`; the picked/downloaded raw image drawn with a pan/zoom transform. Backdrop `background`; the region outside the square masked with a `surface`-derived dim (token, not a raw colour). |
| Gesture | `react-native-gesture-handler` pan + pinch → **Reanimated shared values** (translate x/y, scale). The Skia transform reads shared values via `useDerivedValue` / `useValue`. **Never drive the transform from React `setState`** (CLAUDE.md render-loop rule) — per-frame `setState` re-renders the JS tree and will crawl. |
| Zoom bounds | Clamp scale so the image always covers the square (no empty gutters); clamp pan to image edges. |
| Frame | Fixed centred square with a `borderStrong` outline; 1:1 only. |
| Confirm | "**Use photo**" (accent, 16/600) → export the cropped square region → downscale to 512×512 JPEG q~0.75 via `expo-image-manipulator` `manipulate()` → copy from cache to `Paths.document`. |
| Cancel | "**Cancel**" (secondary text) → discard, no file written. |
| Header | "**Position photo**" title (24/700). |
| Focus/background | The crop is a focused modal screen with no ambient/looping animation, so the "pause on blur / AppState background" rule is satisfied by construction — but if any idle animation is added, it MUST pause on `useIsFocused === false` and on AppState background. |

### Save / write pipeline (infra, UI-observable outcomes)
- Both picker and URL paths converge on ONE 512×512 JPEG master under `Paths.document` (copied out of
  the evictable cache — mandatory, or avatars silently vanish). Stored as a **relative filename**
  resolved to `file://` at read (never absolute).
- **Replace/remove deletes the old file inline, non-undoable** — no `field_history` for binaries.
- Filename scheme is uid-based (planning detail), not name-based.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (no photo) | **Add photo** |
| Primary CTA (has photo) | **Change photo** |
| Secondary source entry | **Paste image URL** |
| Library launch label | **Choose from library** |
| URL submit | **Add from URL** |
| URL field placeholder | `https://…` |
| Crop screen title | **Position photo** |
| Crop confirm | **Use photo** |
| Crop cancel | **Cancel** |
| Empty state (no photo) | No separate copy — the themed-initials avatar IS the resting state; the "Add photo" CTA is the only prompt. |
| Error — invalid URL | **That doesn't look like an image URL.** Check the link and try again. |
| Error — download failed | **Couldn't fetch that image.** Check your connection or try a different link. |
| Error — unsupported / decode failed | **That image couldn't be used.** Try a JPEG or PNG. |
| Error — save/copy failed | **Couldn't save the photo.** Please try again. |
| Picker canceled | (silent — no message) |
| Destructive confirmation | **Remove photo?** — "This deletes the photo from this device and can't be undone." Confirm: **Remove** (danger) · Cancel. |

**Voice:** matches the app's existing terse, plain-language error style (e.g. "Couldn't load this
contact", "Couldn't archive"). Problem first, then the recovery step. No jargon, no exclamation beyond
none.

## Interaction Contracts (summary the executor must honour)

1. **No camera, no runtime permission** — library only via the system Photo Picker. Config hardening:
   `cameraPermission: false`, `microphonePermission: false` in the picker config plugin so
   `CAMERA`/`RECORD_AUDIO` never enter the manifest.
2. **URL is a one-time WRITE path** — `fetch` the pasted URL once, content-type→extension, downscale
   to the local 512px master. The end state is always a local file. **No network on any read path.**
3. **Crop gestures via Reanimated shared values only** — never React state per frame.
4. **All colours via tokens**, including the Skia crop canvas and the initials avatar. `check:colors`
   must stay green.
5. **Portrait-locked** — the crop screen is portrait; do not add rotation handling.
6. **Replace/remove/purge delete files inline** — non-undoable; purge also deletes custom
   `photo`-field files (wired via the existing `onPurgeExtensions` post-commit adapter from Phase 4).
