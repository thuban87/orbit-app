<objective>
Deliver the core capability: pick a contact photo from the library, frame it in the in-app Skia crop, and see it saved and rendered.

Phase Goal (user story): **As a** user, **I want to** set a contact's photo from my library and frame their face **so that** the person I'm reaching out to is instantly recognisable.

This is the first fully-wired photo slice. `PhotoSourcePicker` is the single, genuinely target-kind-aware edit affordance (Add/Change/Remove) for ALL three photo targets — contact, profile/self, and customField — owned in full by this plan so no later plan re-touches its file in the same wave (Plan 06's URL submit and Plan 08's custom-field widget only USE it). It launches the Android 13+ system Photo Picker via `launchImageLibraryAsync({mediaTypes:['images']})` — no camera, no runtime permission — and, on a pick, navigates to `CropPhotoScreen` with the raw cache URI, a serializable target descriptor, and (for a customField target only) a serializable `requestId` correlation key. `CropPhotoScreen` is the repo's first Skia render-loop surface: pan + pinch over a fixed 1:1 viewport, transform driven ONLY by Reanimated shared values read into Skia via `useDerivedValue` (never `setState` per frame — CLAUDE.md), all draws tokenised. "Use photo" computes the source-pixel rect (Plan 04 geometry), runs the Plan 04 pipeline, then dispatches by target kind (contact → `setContactPhoto`, profile → `setProfilePhoto`, customField → persist the file only and carry `requestId` for Plan 08's crop-success publish) and pops back so the avatar refreshes on focus. "Remove photo" switches on `target.kind`: contact → `clearContactPhoto`, profile → `clearProfilePhoto`, customField → clear the form value via an `onValueChange(null)` callback — each deleting the correct derivable file inline (non-undoable), never dereferencing a missing contactId.

Purpose: PHOTO-01 (library pick + Skia crop) + the replace/remove half of PHOTO-05.
Output: `CropPhotoScreen.tsx`, `PhotoSourcePicker.tsx`, the `CropPhoto` route, and the photo section in `EditContactScreen`.
</objective>
