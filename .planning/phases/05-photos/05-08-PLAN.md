<objective>
Complete the goal's third reuse: make the custom `photo`-type field functional through the exact same pipeline.

Phase Goal (user story): **As a** user, **I want to** attach a photo to a custom `photo` field on a contact **so that** any picture-shaped detail I define reuses the same framing, storage, and cleanup as the main avatar.

The dossier `[photos → fields]` locks that a custom `photo` field "reuses this exact pipeline verbatim" — it was never dropped from the §14.8 type set, and the current `PhotoFieldWidget` is an explicit deferred placeholder pointing at this phase. This plan replaces it with a real widget: it renders the value via `<Avatar>` and drives the already-target-kind-aware `<PhotoSourcePicker>` (built in Plan 05 — this plan USES it, it does NOT edit PhotoSourcePicker) with a `{kind:'customField', contactId, colName}` target, passing `onValueChange={onChange}` so the picker's customField Remove clears the field value. The file is persisted at the derivable `avatars/cv-${contactId}-${colName}.jpg` path by the crop pipeline; because the field VALUE is written by the edit form's existing upsert on Save (not a dedicated DAO), the widget sets the field value to that derivable relPath once the crop succeeds. The crop-success correlation is concrete: PhotoSourcePicker navigates to `CropPhoto` with `requestId = customFieldPhotoRelPath(contactId, colName)`; this plan EDITS `CropPhotoScreen`'s customField branch to `publishCropResult(route.params.requestId, true)` after persist; the widget consumes it on focus via `consumeCropResult(customFieldPhotoRelPath(contactId, colName))` (the same re-derived key) and calls `onChange(customFieldValueForTarget(contactId, colName))`. Photo is edit-only, so on the create form (no contactId) the widget stays a disabled placeholder. Purge cleanup for these files already exists (Plan 07 reads surviving photo defs).

Purpose: the custom-field reuse of PHOTO-01 + the custom-field files half of PHOTO-05.
Output: real `PhotoFieldWidget.tsx`, a pure `photo-field-logic.ts` (+ test), and the transient `photo-result-store.ts`.
</objective>
