# Phase 38.5: Background Art & Text-on-Art Contrast - Research

**Researched:** 2026-09-28
**Domain:** Bundled background art (asset model slot × mode), WCAG contrast proofs over composited art, per-combination surface treatments (React Native / Expo, token-only theming), Codex image loop
**Confidence:** HIGH for the code/asset model, proofs, persistence and fallback paths (all read on disk this session). MEDIUM for the re-sign-off tooling (the v2 generator is not in the repo). LOW for any numeric art/opacity values that the owner has not signed yet (tagged `[ASSUMED]`).

## Summary

The phase has no external library work. Everything it needs is already in the repo: a pure background resolver (`src/theme/backgrounds.ts`), one shell `BackgroundHost` that draws the art plus a density veil, a token-only surface module (`surface.ts`) with a both-extrema contrast proof (`surface.test.ts`), a Pillow extrema validator (`scripts/measure-background-extrema.py`), and the brief's per-pixel checker (`check_art.py`). The phase changes three things. (1) The asset model goes from one asset per slot to one asset per slot × resolved mode, with no schema change: `app_settings.galaxy_background` / `standard_background` keep the slot id, and `ThemeProvider` already exposes the resolved `mode`. (2) A new bare-text proof (P-1) composites the `BackgroundHost` veil over each variant's declared extrema. (3) A small pure per-combination treatment table drives the five v2-marked components (List rows, Card entries, count label, Contacts header, Digest header) and the D-10 foreground.

The most important finding: **cutting slot ids is not safe by render-time fallback alone.** `resolveBackground` does fall back to the package default for an unknown id (`backgrounds.ts:216-221`). But backup restore writes settings through `updateAppSettingsCore`, which runs `validateAppSettingsPatch`, which calls `assertBackgroundId` against `BACKGROUND_SLOT_IDS` and **throws** on an id that is no longer listed (`app-settings-dao.ts:1185-1195, 1314-1317, 1481`; `restore-apply.ts:1610-1612, 1779`). If Deep Space, Nebula or Mesh are simply removed from `BACKGROUND_SLOT_IDS`, restoring any backup that stored one of them aborts the whole restore. The fix is code-only and needs no migration: keep the cut ids as a *retired* accepted set that the DAO accepts and the resolver maps to the package default, and hide them from the picker. The picker also needs a fix: today it highlights the raw stored id (`SettingsAppearanceScreen.tsx:438-439`), so a stored retired id would leave no tile selected.

Second finding: the **D-24 figure "27/294 ≈ 9.2%" mixes counting units.** 27 counts `danger` over the 318 bare-plus-mixed sites; 294 counts bare sites only. The consistent figures are 24/294 = 8.16% (bare only) and 27/318 = 8.49% (bare plus mixed), both MEASURED this session from the CSV. 8 of the 27 danger rows no longer match their cited line (106 `src` commits since `738ae12`), so P-6 re-verification is real work, not a formality. The 10% line sits close: with 24 bare danger sites, the result flips to "strict" if the verified bare denominator falls below 240.

**Primary recommendation:** Plan 01 re-verifies the site list and fixes the D-24 band before any Codex brief. The Codex art loop and the blocking art sign-off come next. The slot × mode asset model, retired-id safety, the veil-regime extrema and the bare proof land with the approved art. A DEV-only treatment-override harness then renders the D-27 re-sign-off sheet (JSON schema identical to v2). The treatment table and component wiring build from the signed v3 JSON. ADR-177 is written last.

### Pattern 5: D-10 / D-26 foreground (one per combination × component)

## Common Pitfalls

### Pitfall 1: Restore aborts on a retired background id
**What goes wrong:** a backup with `galaxyBackground: "galaxy-nebula"` fails to restore after the cut.
**Why it happens:** `updateAppSettingsCore` validates through `assertBackgroundId`, which throws on ids outside `BACKGROUND_SLOT_IDS`.
**How to avoid:** use the retired-id set (Pattern 1) and add a restore-level test.
**Warning signs:** a `restore-apply`/`restore-roundtrip` test using an old fixture throws "must be null or a known background slot id".

### Pitfall 2: E-1 silently extends to bare text
**What goes wrong:** the bare proof passes red `danger` over bright Galaxy art even when D-24 ≥ 10%.
**Why:** the E-1 exclusion has no `treatment` scope (`surface.test.ts:89-99`).
**How to avoid:** scope E-1 to `card`/`chrome`, and add a bare-scoped entry only on the D-24 < 10% outcome, citing a 38.5 inventory row.

### Pitfall 3: Mode-blind proof and extrema loops
**What goes wrong:** the GL pale variant is tested under GD glass (fails), or its declared bounds are widened by other-mode regimes.
**How to avoid:** iterate `(slot, mode, variant)`; filter regimes by package **and** mode; update the regime sync guard.

### Pitfall 4: A fallback latch that persists across a mode switch
**What goes wrong:** a decode failure on the light file keeps showing solid after switching to dark.
**Why:** `selectionKey` omits the mode (`background-host-model.ts:27`).
**How to avoid:** include the mode in the key and add a `background-host-model.test.ts` case.

### Pitfall 5: `check:colors` false failure on table values
**What goes wrong:** `"transparent"` in a component file fails the gate.
**How to avoid:** use `seeThrough` naming; keep literals under `src/theme/`.

### Pitfall 6: Visible-features art breaks existing card proofs
**What goes wrong:** a star at L\* 100 in the declared `brightestPixel` fails the Galaxy Dark 0.05-glass card, chrome and List proofs, not just the bare proof.
**How to avoid:** declare text-bearing extrema under the owner-accepted allowance, validate the allowance in both Python checkers, and tell the owner the allowance also applies under see-through entries.

### Pitfall 7: Picker shows no selection
**What goes wrong:** a stored retired id matches no tile while the default renders.
**How to avoid:** derive the selected tile from the resolver.

### Pitfall 8: Shared components changed globally
**What goes wrong:** D-28 is violated through `ShellAppBar`, `ChromeScrim` or `GlassSurface`.
**How to avoid:** use opt-in props; add tests showing the default props keep today's opacity for all other consumers.

### Pitfall 9: Orphaned tests and `tsc`
**What goes wrong:** changing `BackgroundSlotId` or the `resolveBackground` signature breaks 9 files, tests included (Pattern 1 list).
**How to avoid:** change them in the same plan, and run `tsc --noEmit` plus `check:colors` in the post-merge gate.

### Pitfall 10: Line-number drift in cited artifacts
**What goes wrong:** plans cite stale lines. `GridCard.tsx:216` is now `:222`; `HomeScreen.tsx:1608` (count) is now `:1627`; `HomeScreen.tsx:1729` (header) is now `:1757`. `ListRow.tsx:175` and `DigestScreen.tsx:239` are still correct [VERIFIED].
**How to avoid:** cite symbols and test IDs (`dashboard-header-count`, `dashboard-list-row-*`, `dashboard-grid-card-*`), not only line numbers.

### Pitfall 11: The D-11 WATCH outliers checked only generally
**How to avoid:** add explicit, separate device and proof rows for Galaxy Light, Standard Dark and Dusk (both modes) on the Digest: headings, Up Next, Horizon (incl. the `accentText` "more" link), Your Week (incl. the `danger` load error at `YourWeekSection.tsx:312`).

### Pitfall 12: The Standard Light glass variants were tuned to old Dusk
`STANDARD_LIGHT_GLASS_*` were derived against "Dusk's darkest composite `#94939A`" (`glass-foregrounds.ts:79`). Over pale new art they are over-dark but still pass. **Do not retune them** (D-28, ADR-169). The proof still asserts them.

```typescript
// src/theme/backgrounds.ts — sketch, not final. Slot ids other than those quoted in
// theme-option-ids.ts:45-55 are [ASSUMED] placeholders pending owner naming.
export interface BackgroundVariant { source: () => number; brightestPixel: string; darkestPixel: string; }
export interface BackgroundAssetSlot { package: ThemePackage; variants: Record<ResolvedMode, BackgroundVariant>; }

export function resolveBackground(pkg: ThemePackage, slotId: StoredBackgroundId | null, mode: ResolvedMode): ResolvedBackground {
  if (slotId === NONE_SLOT_ID) return { kind: "solid" };
  const id = slotId !== null && isActiveSlot(slotId) ? slotId : PACKAGE_DEFAULT_SLOT[pkg]; // NULL, retired, unknown → default
  const v = BACKGROUND_SLOTS[id].variants[mode];
  return { kind: "asset", slotId: id, mode, source: v.source, brightestPixel: v.brightestPixel, darkestPixel: v.darkestPixel };
}
```

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Tampered/old backup with an unknown background id aborts restore (DoS of restore) | Denial of service | Retired-id acceptance + resolver fallback; test it |
| Tampered id renders the wrong package's art | Tampering | `resolveBackground` returns any known asset id regardless of package (`backgrounds.ts:216-228` has no package check). The picker only writes own-package ids. Optional hardening: treat a cross-package id as unknown → default `[recommendation]` |
| Art pipeline leaks user data to an external model | Information disclosure | Codex prompts contain only the art brief and bands; never app screenshots with contact data (test data is synthetic, but keep the rule) |
| Codex writes outside its intended output | Tampering | `-C` scratch dir outside the repo, named outputs only, `git status` check after each run (D-14 practice) |
