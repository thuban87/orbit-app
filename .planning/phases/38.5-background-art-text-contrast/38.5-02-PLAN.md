<objective>
Change the background asset model from one asset per slot to one asset per slot × resolved mode (D-23), without changing a pixel yet (D-13). Every slot gains `variants.light` and `variants.dark`. Both point at today's file until 38.5-05 wires the owner-approved art. The resolver, the host, the picker preview, the extrema script and the card/chrome proofs all become mode-aware.

Purpose: separate light and dark art per background is the owner's fix direction (D-03 / 38.4 D-39). The resolver, the fallback latch, the picker and the proof chain must understand variants before the new art can be wired. Doing this on today's art keeps the change reviewable and visually inert.

Output: the mode-aware manifest and resolver, a mode-keyed fallback latch, a resolver-derived picker selection, and a variant-aware extrema script and proof loop.

<assumption_delta_decision>
- Primary noun: the **slot × mode variant** (`BACKGROUND_SLOTS[slot].variants[mode]`). It replaces the single per-slot asset; a slot is now a pair of variants.
- Promote vs add-alongside: **promote (replace)**. The single-asset fields (`source`, `brightestPixel`, `darkestPixel`) move into each variant. No parallel single-asset path is kept. D-23 fixes one stored pick per package that follows the mode, so a dual model would only create a second truth for the proof chain to drift from.
- Invariant tests (this plan):
  - every slot resolves a variant for both modes (`backgrounds.test.ts`);
  - `measure-background-extrema.py` exits 2 on a missing variant block.
- The retired-id invariant (retired ids resolve to the package default) lands with the lineup change in 38.5-05.
</assumption_delta_decision>
</objective>
