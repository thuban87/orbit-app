## Project Constraints (from CLAUDE.md)

- **Read the code, not the diff.** Planners and reviewers read the full files of the History subsystem (listed in §Code Inventory) and every consumer of a retired symbol, tests included.
- **Never `git worktree`.** Commit in place. Never push.
- **Local-first.** No network on any read path. The phase adds no network, telemetry or egress. Logger lines stay content-free (the existing `Logger.error(LOG_SCOPE, "failed to read contact history")` idiom).
- **Theme tokens only.** No hex, `rgb()`, `hsl()` or quoted named colour outside `src/**/theme/**` (`scripts/check-colors.sh`). The highlight tint must be an existing token, for example `accent` at a numeric `opacity`.
- **Animation is never driven by React state per frame.** Use Reanimated shared values (`useSharedValue` / `withTiming` / `useAnimatedStyle`), the precedent in `HomeScreen.tsx:700-735` and `AnchoredPanel.tsx:105-120`. It pauses or ends when unfocused or backgrounded, and reduced motion is respected.
- **Use `formatLocalDate()` for dates**, never `toISOString().split('T')[0]`. Slicing a *local* `YYYY-MM-DD` string (for example `date.slice(0, 4)` for the year) is fine. That is not UTC slicing.
- **Tunable constants go at the top of their owning file:** chunk size, initial count, highlight duration, tint opacity.
- **Queries go through DAOs**, never inline in components. No schema change, no migration (head 032), no backup format change (7).
- **Plan sizing:** group by affected area. There are two owner gates only: splitting an agreed plan, and a jump of more than 25% in plan count. See the seam proposal below.
- **Worklet forward-reference hazard** (owner memory). A worklet that calls a worklet defined later in the same file is undefined on device under Hermes, and vitest cannot catch it. Define helpers above their callers.
- **Orphaned test consumers break the project-wide `tsc` gate** (owner memory). Grep every consumer of a removed symbol, tests included, and put each in the plan that removes the symbol.
- **Post-merge gate per plan:** `npx vitest run`, `npx tsc --noEmit`, `npm run check:colors`. vitest passing does not mean tsc is clean.
- **Device:** never hardcode a device serial; use `emu-connect` and `adb devices`. The 6 Pro is the device; the 3a gets an end smoke only. Run Metro on :8082 with `adb reverse tcp:8081 tcp:8082`. Iterate on DEBUG builds and cut one release build at the end. Make no real AI calls.

## Summary

The phase is a **presentation-layer replacement inside one mounted component tree**. The tree is `ContactProfileScreen` (plain `ScrollView`) → `ProfileModuleHost` (the `profile-history-anchor` View, then `ProfileSection` inside a `GlassSurface`) → `HistorySection`. The canonical read `readContactHistory` already returns everything the stream needs, so **no new DAO query is required**: all interactions with the group title/note joined, all lifecycle events, and all retained knowledge changes, each with a local `date` and full timestamp. The read is unbounded and re-runs on every Profile revision. Grouping, counts, month dots, chunking, empty-target resolution and nearest-record lookup are pure in-memory derivations over that one `ContactHistory` object. They belong in a new node-testable `.ts` helper module in the `history-section-logic.ts` style.

The risky parts are **mechanical, not data**:
1. Scrolling the *outer* Profile ScrollView to a day group nested about eight Views deep, after a year expansion or chunk load has rendered it.
2. A 5 s highlight fade that must hold under reduced motion. Reanimated's default `ReduceMotion.System` would instead make it vanish instantly.
3. Retiring `DateDetailSheet` without breaking three source-text contract tests. One of them pins an exact 21-block `<Sheet>` floor.
4. Archiving the Rolodex so that `tsc` actually ignores it. This repo's `tsconfig.json` includes `**/*.ts(x)`, `docs/` included, and a local `exclude` *replaces* Expo's inherited one.

None of these needs a new package.

**Primary recommendation:** Keep `readContactHistory` unchanged. Add a pure `history-stream-logic.ts`, built model-first and node-tested, and render the stream as chunked plain Views. Relocate the `DateDetailSheet` row renderers into stream row components. Extend `createHistoryRevealScroll` with a `scrollWithinHistory(offsetY)` entry, fed by `measureLayout` of a target View relative to the `profile-history-anchor` View. Drive the highlight with a Reanimated shared value and an explicit `ReduceMotion.Never` hold path. Page Cycles by reusing `HistoryDayState.refDate` through a pure wrapper around the unchanged `cycles()`.

## Architectural Responsibility Map

All tiers are on-device (local-first, no backend).

### Data: what the read already gives the stream

`[VERIFIED: src/db/history-read.ts:38-97, :144-156]` The record shapes are quoted verbatim:

- `HistoryInteractionRecord`: `id`, `occurredAt` ("Local wall-clock `YYYY-MM-DD HH:MM:SS`"), `date`, `channel`, `direction`, `connected`, `quality`, `note`, `duration`, `allowAi`, `groupEventId`, `groupTitle`, `groupNote`, `groupLinked`.
- `HistoryLifecycleRecord`: `id`, `occurredAt`, `date`, `type`, `detail`.
- `HistoryKnowledgeRecord`: `id`, `fieldKey`, `date`, `createdAt`, `value`, `isCurrent`.
- Interactions SQL is `ORDER BY i.occurred_at DESC, i.id DESC` with `LEFT JOIN group_events AS ge ON ge.id = i.group_event_id`. Events are `ORDER BY occurred_at DESC, id DESC`. Knowledge rows are pre-sorted by `createdAt` desc, then registry field order, then id desc (`:276-288`).

What follows from that:

- **Grouping** (year → month → day) comes straight from each record's `date`, a local `YYYY-MM-DD`. Year = `date.slice(0,4)` and month = `date.slice(0,7)`. These slice a local string, not UTC.
- **Collapsed-year count (D-35):** count `interactions` whose `date` starts with the year. Group children are counted once and parents never appear (D-01), because parents are not `interactions` rows.
- **Month dots (D-52):** a `Set<"YYYY-MM">` over all three families.
- **Empty target (D-21):** a `Map<date, records[]>` over all three families. A date or span is empty when it has no key in range.
- **Picker years (D-18):** from the minimum `date` year across families (or the current year) through the current year.
- **Nearest before/after (D-17):** a binary search, or a linear scan, over the merged, sorted list.
- **Group scope:** a group-linked child is one ordinary interaction row with `groupLinked === true` and `groupTitle`. The InteractionDetail scope prompt and conversion are unchanged. **No new read query is needed.** Paging is in-memory chunking over the already-loaded arrays. The read stays unbounded (Claude's Discretion: "unbounded unless measurement says otherwise").

The timestamps share one format. `localDateTime()` writes `` `${formatLocalDate(date)} ${hh}:${mm}:${ss}` `` (`src/db/database.ts:115-120`), and a prefilled Log writes `` `${prefillDate} 00:00:00` `` (`LogInteractionScreen.tsx`). Cross-family string comparison is therefore chronological for app-written rows. Guard parse failures with `parseLocalMs` in a try/catch fallback.

### Pattern 1: A model-first stream with deterministic ordering

**What:** One pure function converts `ContactHistory` plus `today` into a renderable model, and one pure reducer manages the view state. The component is a thin renderer.

**Ordering (D-18):** sort by timestamp descending, then family rank (interaction 0, lifecycle 1, knowledge 2), then `id` descending. Key each record `` `${family}-${id}` ``. This matters because interaction ids and event ids are independent sequences and can collide (noted in `TimelineRow.tsx`'s IDENTITY comment).

**Chunking (D-39):** use a per-year `shown` record count, starting at `INITIAL_VISIBLE = 20` and growing by `CHUNK = 20`. **Snap a cut to the end of the day that contains the cutoff record**, so a day never splits across a Show older boundary (Pitfall 8).

**View state:** `{ openYears: Set<number>; shown: Map<number, number> }`. Initialise it to only the current year open, with shown = 20 (D-34, D-62). It lives in HistorySection `useState`, is never persisted (D-18), and is never reset by a re-read (D-31).

### Pattern 2: Relocating the rows (D-22)

Move `SheetRow` (`DateDetailSheet.tsx:203-302`) and the `CHANNEL_ICON` / `EVENT_ICON` maps (`:53-67`) into the stream rows, with these deltas:

- Note `numberOfLines={2}`, not 1 (D-41).
- Add the restrained group-title label when `groupLinked && groupTitle` (D-16). The whole row stays one Pressable (D-42).
- No duration (D-46), no sparkle (D-45), no `onLongPress` (D-44).
- Lifecycle rows stay a non-pressable `View` with `tone="textSecondary"` (D-40).
- Knowledge rows keep the `edit` icon, field label, time, and value at `numberOfLines={1}` (D-43).
- Every visible time and every row a11y label goes through `formatTimeMinuteOrFallback` (ADR-152; the contract test moves with it).
- Each row component calls `useTheme()` itself, so glass-scope reads resolve inside `ProfileSection`'s GlassSurface (`glass-scope-read-contract.test.ts`).

### Pattern 3: Scroll-to-target through the existing reveal plumbing

`createHistoryRevealScroll` already tracks `hostY` (the host root inside the ScrollView content) and `historyY` (the `profile-history-anchor` View inside the host), and it already defers to the first expanded layout `[VERIFIED: src/profile/module-host-model.ts:90-118]`.

Add one entry, `scrollWithinHistory(offsetY)`, which calls `scrollTo(hostY + historyY + offsetY)`. `ProfileModuleHost` gives the anchor View a ref and passes HistorySection a callback, `requestHistoryScroll(node: View)`. That callback runs `node.measureLayout(anchorRef.current, (_x, y) => scroller.scrollWithinHistory(y))`. The screen's existing `onRequestScrollTo` then applies `profileScrollTargetY` (the app-bar offset) and `animated: !reducedMotion`, which covers D-23's "not animated under reduced motion".

`measureLayout` takes a **ref** to the ancestor. The node-handle variant is "obsolete with the new architecture" `[CITED: reactnative.dev/docs/legacy/direct-manipulation]`. The repo precedent at `CreateContactScreen.tsx:258` uses `findNodeHandle`. Prefer the ref form.

**Timing:** a reveal that expands a year or grows chunks must measure *after* the target lays out. Store `pendingScroll = { key, gen }`. Have the target DayGroup's `onLayout` call back. Measure once, then clear. This is the same deferral idea the reveal controller uses for an expanding History.

### Pattern 4: Highlight fade without per-frame React state (D-53, D-54, D-23)

On a jump, set HistorySection state once: `highlight = { keys: Set<dayKey>, gen }`. Each highlighted DayGroup renders a small `HistoryHighlight` overlay: an absolutely positioned accent bar (`colors.accent`) on the left plus a fill (`colors.accent` at `HIGHLIGHT_TINT_OPACITY`, numeric). Its `opacity` is a shared value:

- **Normal:** `opacity.value = 1; opacity.value = withTiming(0, { duration: HIGHLIGHT_FADE_MS })` with `HIGHLIGHT_FADE_MS = 5000`.
- **Reduced motion:** `withDelay(HIGHLIGHT_FADE_MS, withTiming(0, { duration: 0 }), ReduceMotion.Never)`. **Do not rely on the defaults.** With the OS setting on, `ReduceMotion.System` makes `withTiming` "return the `toValue` immediately" and makes `withDelay` "initiate the next animation immediately" `[CITED: docs.swmansion.com/react-native-reanimated/docs/guides/accessibility/]`. The highlight would vanish at once, violating D-54.
- **Unfocused or backgrounded** (CLAUDE.md animation rule, `canAnimate = isFocused && appActive` precedent): set it to the end state.

After the fade, clear `highlight` state once (a `runOnJS` completion or one `setTimeout`), so a later revision re-read never replays it. For screen readers, call `AccessibilityInfo.announceForAccessibility("Showing <full date with year>")` once per jump (precedent: `ImportProgressScreen.tsx:71`). Do **not** put `accessibilityLiveRegion` on highlighted rows; it would re-announce and steal focus (D-23).

### Pattern 5: The Jump-to-date picker (D-48..D-52, D-17)

The pure model is `pickerModel({ monthsWithRecords, earliestYear, today, year })`. It returns 12 cells, each `{ month, hasRecords, disabled: future }`, plus the stepper bounds.

`JumpToDateSheet` is a `Sheet` with variant `compact` and the default `scrollBody`. It needs no ScrollView of its own, so no `scrollBody={false}` opt-out. The 3×4 grid uses ≥44dp month buttons. The dot is a small View (`colors.textPrimary`) plus `accessibilityLabel` "March 2026, has records" (D-49). The selected month gets an `accent` border. Future months get `accessibilityState={{ disabled: true }}`.

**Preselection (D-50):** at open time, measure the rendered month headers with `measureInWindow`. Pick the last header at or above the viewport top; if none (the user hasn't scrolled into the stream), use the current month. Because Jump is not sticky (D-32), this usually resolves near the stream top. That is expected, not a bug.

A month jump scrolls to the month header with **no highlight**. Neither D-17 nor the mockup highlights month jumps.

### Pattern 6: Cycles paging on the existing day state (D-25, D-26)

Reuse `HistoryDayState.refDate` as the **end date of the displayed cycle page**:

- `pagedCycles({ intervalDays, trackingEnabled, count, today, refDate })` calls the unchanged `cycles({ …, now: refDate })`, then re-flags `isCurrent = (refDate === today && index === count-1)`. `cycles()` always flags the last block (`cycles.ts:92-97`), which is wrong on a past page.
- Prev: `historyDayAfterPrev(day, addDays(blocks[0].start, -1))` (stops following).
- Next: `ref = min(addDays(lastEnd, count*interval), today)`, following when `ref === today`.
- `canGoNext = refDate < today`.

Intensity already follows the displayed span (`HistorySection.tsx:336-349`), so D-26's shared window is automatic.

**Change `onPresetChange` to also reset the day state.** Today only lens change does (`HistorySection.tsx:273` vs `:291-312`). D-26 says a preset change returns to the current page.

Rollover while paged back keeps the page put, through the existing `advanceHistoryDay` (D-04).

### Pattern 7: Keeping the user's place (D-31, D-62)

HistorySection stays mounted across Detail, Edit, Log and MemoryHistory, because the Profile screen stays mounted and the section stays expanded. View state therefore survives the revision re-read on its own.

1. Never render a loading placeholder over a loaded stream during a re-read. `historyReadStateOnStart` already keeps the loaded data (`history-section-logic.ts:137-141`). Swapping in "Loading history…" would collapse content height and clamp the ScrollView offset.
2. On opening a record, remember `anchorDay`. After the next publication, if `anchorDay` no longer exists, run `nearestDay(model, anchorDay)` and scroll to it once through Pattern 3.
3. A fresh visit means a new screen mount, which means fresh state (D-62). Collapsing the section unmounts HistorySection, so state resets there too; that is acceptable under D-18's transient rule.

### Anti-patterns to avoid

- **A nested vertical ScrollView, FlatList or SectionList for the stream.** The mockup's inner 560px scroll box (`.stream { max-height: 560px; overflow-y: auto }`) is a mockup artifact. In the app the stream scrolls with the Profile.
- **Deciding emptiness from `HeatmapCellTarget.count`.** It is interaction-only; use the all-family day index (D-21).
- **Prefilling the span end for an empty span or month** (the current bug at `HistorySection.tsx:485, :509`). Use the undated route (D-28).
- **`new Date("YYYY-MM-DD")` for weekday labels.** It parses as UTC and shifts the day in negative UTC offsets. Use `new Date(y, m-1, d)` from local parts, as `window.ts:74-77` does. The mockup's `new Date(k + "T12:00")` is browser-only shorthand; do not port it.
- **Calling `new Date()` in render for Today/Yesterday.** Use `HistoryDayState.today`, which advances on mount and revision (ADR-165).

## Don't Hand-Roll

| Problem | Don't build | Use instead | Why |
|---|---|---|---|
| Offset of a deeply nested View inside the ScrollView | Summing `onLayout` y through every wrapper | `View.measureLayout(anchorRef, …)` plus the `createHistoryRevealScroll` host and history offsets | Wrappers change (GlassSurface, paddings), and the sum silently drifts. |
| The fade timer | `setInterval`/rAF with per-frame `setState` | Reanimated `withTiming` / `withDelay` on a shared value | CLAUDE.md rule; it runs on the UI thread. |
| Reduced-motion detection | A new AccessibilityInfo subscription | `useReducedMotion()` (`src/theme/use-reduced-motion.ts`) | Live-updating. Reanimated's own hook reads only at boot (header comment there). |
| Minute times | Slicing `HH:MM` from the stored string | `formatTimeMinuteOrFallback` / `formatDateTimeMinuteOrFallback` | ADR-152, and the timestamp contract test forbids `.slice(11,`. |
| Local dates | `toISOString().split('T')[0]` | `formatLocalDate`, and local-component `Date` construction | CLAUDE.md; this has caused a prior bug. |
| Date windows and paging math | New calendar arithmetic | `buildWindow` / `prevWindow` / `nextWindow`, `cycles()`, the `addLocalDays` pattern | Already tested across DST, leap years and month ends. |
| Bottom sheet | A custom Modal | `Sheet` (`src/components/ui/Sheet.tsx`) | Keyboard, safe area, scroll cap, large-text reach (ADR-174). |
| Read races | Ad-hoc flags | `createLatestRequestAuthority` (already in HistorySection) | An older read can never publish over a newer one. |

**Key insight:** every hard piece here (dates, sheets, reduced motion, read authority, reveal scroll) already has a tested house primitive. The new work is composition plus one pure model module.

## Common Pitfalls

### Pitfall 1: The archived Rolodex is still type-checked, or `node_modules` gets type-checked
**What goes wrong:** archived `.tsx` files under `docs/` compile, and break the tsc gate later when a symbol they import (for example `HistoryDateMarker`) changes. Or a hand-written `exclude: ["docs/archive"]` silently drops Expo's `node_modules`/`android`/`ios` excludes.
**How to avoid:** use the full re-listed `exclude` (Archive Mechanics step 2) and verify with `--listFilesOnly`.
**Warning signs:** tsc gets slower, or reports errors in `node_modules` or `docs/archive`.

### Pitfall 2: The highlight vanishes instantly under reduced motion
**Why:** Reanimated's default `ReduceMotion.System` skips delays and jumps `withTiming` to its end value `[CITED: Reanimated accessibility guide]`.
**How to avoid:** use an explicit `ReduceMotion.Never` on the hold path (Pattern 4). Device-check it with Remove-animations ON. Surface that confound at the top of any hands-on instructions (owner memory: surface test confounds first).

### Pitfall 3: Measuring before the target exists, or measuring against a flattened View
**What goes wrong:** after "expand year + load chunks", the target is not laid out yet, so `measureLayout` fails or returns stale values. Separately, the Fabric View flattener can collapse a measure-only View.
**How to avoid:** trigger from the target's `onLayout` (Pattern 3). Give measured Views (anchor, DayGroup, month header) `collapsable={false}` `[ASSUMED: precaution, not observed]`. Keep the measure best-effort with an `onFail` no-op, as in the `CreateContactScreen` precedent.

### Pitfall 4: A cycle span or empty-month neighbours that cross a year boundary
**What goes wrong:** a cycle can straddle Dec–Jan (any interval > 1 day can, and a 365-day cadence always does). Expanding only one year leaves part of the span unrendered and unhighlighted.
**How to avoid:** the target resolver returns **all** years touched by the span, and chunk growth runs until the span's *oldest* record is rendered. The scroll goes to the newest record (D-20).

### Pitfall 5: The empty-day note survives a lens or page change (a regression of the old card bug)
**How to avoid:** clear the note in `onLensChange`, `onPresetChange`, `onPrev`, `onNext` and `onCellPress`, and on ✕ (D-55). Keep the clearing rules in a pure reducer and unit-test them.

### Pitfall 6: The Jump sheet reads the glass palette
**Why:** HistorySection is rendered inside `ProfileSection`'s `GlassSurface`. A Sheet host that calls `useTheme()` above `<Sheet>` gets glass tones inside an opaque sheet. `overlay-host-theme-contract.test.ts` pins `const { colors } = useUnscopedTheme();` for such hosts.
**How to avoid:** `JumpToDateSheet` reads `useUnscopedTheme()` above its `<Sheet>`. Replace the `DateDetailSheet` entry in that test's `HOSTS` with `JumpToDateSheet` (and the empty-state host if it is a sheet; the note is not).

### Pitfall 7: The Sheet-consumer floor drops below 21
**What goes wrong:** `sheet-consumers-contract.test.ts` asserts `blocks.length >= 21`, and today there are exactly 21 `<Sheet` blocks (counted with the test's own scan this session). Deleting `DateDetailSheet` makes it 20. Its `EXPECTED_OPT_OUTS` is an **exact set** that includes `src/components/history/DateDetailSheet.tsx`.
**How to avoid:** in the plan that deletes DateDetailSheet, either add the Jump sheet in the same plan or lower the floor to 20 with a dated comment. Always drop the file from `EXPECTED_OPT_OUTS`, and do not add the Jump sheet there (it has no own scroll container).

### Pitfall 8: Show older splits a day, or a jump renders half a day
**Why:** the mockup slices by record count and calls `ensureVisible` with the *first* record index of the day (`history-stream-mockup.html:292-296`).
**How to avoid:** snap the visible count to the end of the day that contains the cutoff record and the target's oldest record.

### Pitfall 9: The no-cadence fallback writes the global lens
**What goes wrong:** in fallback, the segmented control shows Month as selected. `SegmentedControl` calls `onChange` even for the already-active segment (`onPress={() => onChange(option.value)}`), so tapping the visually selected "Month" would persist `history_lens = 'month'` for **every** contact.
**How to avoid:** in fallback mode, treat `onLensChange(effectiveLens)` as a no-op. An explicit tap on Cycles sets a per-mount flag that shows the existing unavailable text (D-27). That text is the existing `"Cycles need a set frequency for this contact."` at `ActivityHeatmap.tsx:432`.

### Pitfall 10: Place lost on return from Edit, or anchoring fights the user
**How to avoid:** no loading swap during re-reads (Pattern 7). Re-anchor only when the anchor day disappeared. Do not re-scroll on every revision; Profile focus produces a revision every time (ADR-165).

### Pitfall 11: Fixing the lens truncation regresses Home, AI Personalization and Your Week
**Why:** `SegmentedControl` is shared, so changing its default padding or font size restyles three other surfaces.
**How to avoid:** add an opt-in prop (for example `density="compact"`: smaller `paddingHorizontal`, possibly a smaller font) and use it only in `ActivityHeatmap`.
**Sizing note:** the section-body width on a ~393dp phone is about 329dp after the 2×16 content padding and the 2×16 section padding. That leaves about 50dp of label width per segment at today's 12dp padding, too narrow for "Cycles" at 16sp/600 `[ASSUMED: glyph-width estimate]`. Verify "read in full at default text size" on both phones (D-24).

### Pitfall 12: The ActivityHeatmap render test mocks `useState`
**Why:** `activity-heatmap-render.test.tsx` mocks `useState: () => [measuredWidth, vi.fn()]`. Any new `useState` inside `ActivityHeatmap` would receive the measured width.
**How to avoid:** keep D-25/D-27 state in HistorySection and pass props. Update that test for the Cycles nav row: it is now present for cycles, and next is disabled on the current page.

### Pitfall 13: Hermes worklet forward reference
**How to avoid:** keep `useAnimatedStyle` callbacks self-contained inside `HistoryHighlight`. If a helper worklet is needed, define it **above** its caller. This cannot be caught by vitest, so the per-plan device smoke must exercise a highlight.

### Pitfall 14: An orphaned contract test breaks tsc or vitest mid-phase
**How to avoid:** the plan that deletes `DateDetailSheet.tsx` also edits `overlay-host-theme-contract.test.ts`, `sheet-consumers-contract.test.ts` and `timestamp-consumer-contract.test.ts`. In the timestamp test, the DateDetailSheet entry pins `minCalls: 6` and "exactly 3" `accessibilityLabel` template literals. Retarget it to the new rows file. If the new rows file has more templated labels (group title, day label), rewrite the "exactly 3" assertion as "every *row* label carries the formatter", not a count.
