## Deviations from Plan

- **The release build reused the DEBUG build's droid tree.** The release came from the same transported tree and clean
  `CI=1` prebuild (same HEAD; no source change in between), rather than a second clean reset. The orchestrator later
  rebuilt it arm64-only for delivery.
- **The tap time came from calibration, not touch markers.** `show_touches` does not mark adb-injected taps, so the
  release tap instant came from comparing framestats and video (about 1.01 s ± 0.07 s into each recording). The plan
  allowed "tap to first changed frame"; the method is documented in DEVICE-PASS.
- **Two checks went beyond the plan.**
  - Check 8 was re-run on RELEASE to tell a debug-only timing effect from a real bug. It fails intermittently there too.
  - A second 5e landing was taken mid-year, because the first target sat at the end of the page.
- **The Task 4 settings re-check could not run.** The preferred phone was unplugged on 2026-10-09, and the fallback
  phone was never touched. The last full check, at the end of Task 2, showed every setting restored. The `adb reverse`
  rule must be set again when the phone is reattached. Orbit Metro is still on :8082.

**Total deviations:** 4, all process. No scope change and no source change.
