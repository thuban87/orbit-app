## Fixed Issues

### CR-01: Records added above the user drop the last rendered day, so the place is lost (D-31 / D-62)

**Files modified:** `src/components/history/history-stream-logic.ts`, `src/components/history/history-stream-logic.test.ts`, `src/components/history/HistorySection.tsx`
**Commit:** 442966b9
**Status:** fixed: requires human verification (logic change; check it in the device pass)
**Applied fix:** Count bump pinned to a boundary. This is the review's option (b), using a sort-position boundary.
- **New pure helper `streamStateOnModelChange(state, prev, next)`.** For each open year, it takes the oldest record rendered under the previous model. In the new model, it sets the year's request to the number of records that sort at or before that position.
  - Because the boundary is a sort position and not a key, it still holds when the boundary record itself is deleted or redated.
  - It never shrinks a request and never touches a collapsed year.
  - It also covers the initial chunk, so a Log from the Profile + button no longer pushes out the first page's last day.
  - The `shown` shape (year → count) is unchanged, so the reveal, Show older and every existing test keep working.
- **`HistorySection` applies the helper while rendering**, using React's "adjust state when a prop changes" pattern with `pinnedModel` state. The re-render with pinned state replaces the stale one before anything commits. An effect would have committed one frame with a shorter slice, and the ScrollView could clamp during it.
- **New `isDayRendered(state, model, day)`.** The D-31 anchor effect now also re-reveals the anchored day and scrolls to it when the day still exists but is no longer rendered (a safety net behind the pin). `streamState` was added to that effect's deps; the effect is still guarded by the history identity check.
- **Tests (written RED first).** Added 7 `streamStateOnModelChange` cases and 4 `isDayRendered` cases. The review's regression test is included: one record per day, Show older, add a record today, and the previously last-visible day is still rendered. It also asserts that the raw count-only slice drops that day, which proves the scenario actually exercises the defect. Other cases: the initial chunk, an expanded older year, no change, a delete above, deletion of the boundary record, and a collapsed year.

### WR-03: On a new-year rollover, the year the user was browsing collapses

**Files modified:** `src/components/history/history-stream-logic.ts`, `src/components/history/history-stream-logic.test.ts`
**Commit:** 212002a1
**Status:** fixed: requires human verification (logic change)
**Applied fix:** The review's `useEffect` was adapted:
- **Where the fix lives.** The carry-over is inside `streamStateOnModelChange`, which already runs before commit on every model change. A `useEffect` would have committed one frame with the year collapsed.
- **What it does.** When `next.currentYear > prev.currentYear`, the previous current year is added to `openYears`. Its `shown` entry is keyed by year and carries over.
- **Fresh visits are unchanged.** A fresh mount still opens only the current year (D-34/D-62; the Q-23 rejection is untouched).
- **Tests.** Three cases, RED first: the year stays open with its chunks, no other year opens, and nothing changes within the same year.

### IN-10: On Jan 1 the seed breaks Sparse's "three different years" shape

**File:** `src/__dev__/history-seed-spec.ts:462`
**Reason:** Not trivial, and the scope said to leave it unless trivial. The review's clamp would date the dinner today. That conflicts with the seed's documented rule that group events are strictly before today (the comment at that line), which `history-seed-spec.test.ts` ("dates every group event strictly before today") enforces. The alternative is to document Jan 1 as an unsupported seed day. Both choices are left for later. Dev-only.
**Original issue:** On Jan 1, `c.ago(Math.max(1, Math.min(c.todayIndex, 12)), …)` dates the group dinner to Dec 31 of the previous year, so both of Sparse's group interactions fall in the previous year.
