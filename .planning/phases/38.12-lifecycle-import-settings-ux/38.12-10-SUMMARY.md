# Phase 38.12 Plan 10: Check Linked Contacts Stops Re-asking Summary

**Check linked contacts now remembers every kind of resolution: grid and detail share one memory loader and one classify entry (all links merged, region override ?? device). Reviewed, unchanged fields are filtered out. Photos compare by the phone's fingerprint and are remembered on Keep Orbit. Impossible phone birthdays are never offered. A missing source kept as is stays quiet until it reads again. Card completion is recorded by one DAO.**

## Accomplishments

- **One memory read (D-45).** New `src/db/reconcile-memory-read.ts`:
  - `loadReviewMemory` merges snapshots across every active link and takes the region from `phoneRegionOverride ?? device`.
  - `classifyLinkedContact` is the single classify entry for the grid and the detail.
  - `scanLinkedContacts` builds the grid's cards and their counts.
  - The SELECTs the two screens ran inline moved here.
  - The detail used to read only the first link's memory and passed no region to Apply. It now uses the shared read, and its Apply passes the scan's region. The grid's bulk apply also passes the region now.
- **Filter, not suppress.** `actionableReconcileFields` drives cards, counts, chips, bulk eligibility and the detail list. The classifier output is unchanged, and `reconcile-diff.test.ts:49-55` is kept.
- **Photo memory (D-45, convergence c4 E-4).**
  - The photo comparable is the sorted join of every option, as for name and birthday: `""` for none, the value itself for one.
  - Keep Orbit writes it inside the apply transaction, from both the detail and bulk keep-orbit.
  - Use phone's photo writes it post-commit through `recordReviewedPhoto`.
  - A zero-option field remembers on the diff's read link ids.
  - Every source photo is staged, so each option previews and promotes its own photo.
- **Fingerprint comparison (D-132).** A source photo's value is `photoFingerprint || staged hash`. `thumbnailTempUri` copies from reconcile reads are discarded.
- **Impossible birthday.** An unreadable phone birthday yields no option. With no valid option left, no birthday field is emitted.
- **Missing source.**
  - Keep as is writes 'source' memory with the card status. The grid's bulk Keep Orbit on such a card does the same.
  - A kept missing link is skipped.
  - When the link reads again its 'source' memory is deleted through the locked `deleteReviewedSnapshot`, so a later disappearance prompts again.
- **Disposition DAO (D-50).** `setCardCompletionDispositionCore` replaces the grid's in-screen UPDATE. The detail Apply now records a disposition, and a partial card records none. The `reconcileCompletionCounts` doc comment now describes what the code does.

## Deferred / out-of-scope items

1. **Staged photo copies from the detail screen wait for the launch sweep.** The detail stages a copy of each phone photo when it opens. Copies the person does not use stay in the reconcile staging folder until the next launch clean-up sweep removes them. This was already true for the single copy before this plan; now there can be one per linked photo.
   - Separately, and also pre-existing: the detail uses the same staging file name as the grid's card for the same contact and link, so Use phone's photo deletes the file the grid card points at. The grid never uses that file, so nothing breaks.
   - Recommendation: leave as is, or clean the detail's unused copies when it closes. Small; fits a reconcile plan such as 38.12-19.
2. **Check complete can count one card twice.** A bulk Keep Orbit on a missing-source card is counted under both "Source missing" and "Kept Orbit values". This behaviour is unchanged by this plan.
   - Recommendation: only change it if the owner wants those counts to be exclusive. It belongs with whichever plan owns the Check complete wording (D-55 area).
3. **Older pending checks.** Cards saved before this change carry no `missingLinkIds` or `sourceLinkIds`. A bulk Keep Orbit on such an older missing-source card does not remember it, so it returns once. There is no installed base (owner memory "No installed base"), so the risk is negligible. No action recommended.
