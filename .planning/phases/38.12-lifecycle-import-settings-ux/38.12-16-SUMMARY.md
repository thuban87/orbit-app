# Phase 38.12 Plan 16: AI Settings Children Summary

**AI personalization sections now drag and keep their actions in an anchored ⋯. Writing Style has a Custom segment, shows its guidance box only while a choice is custom, and its estimate matches what is sent. Every control locks during a save. AI Data Permissions hides photo fields and can never turn one on. Its captions follow their switches, and "Review existing…" scrolls to the list. AI Preview reads in plain words and shows the contact's own part first. The bytes sent are unchanged.**

## Accomplishments

- **Section list (Task 1, tracer; D-86, D-120).** The page is one `ScrollViewContainer`. Sections render in a `NestedReorderableList`, following the ProfileLayoutEditor precedent. Each row has:
  - a drag handle (long-press);
  - the section title;
  - the Send-to-AI switch;
  - an anchored ⋯ with Rename / edit, Replace from file, Move up, Move down, and Delete section (last, danger, with a separator before it).

  The adjustable-only sort icon and the inline Move buttons are gone. A drag and Move up/down both go through one reorder write. The new order shows at once, a failure restores the old order, and two reorders can never overlap. The section text now spans the full card width below the title row. Opening the page with no `focus` already shows the top, so the D-126 hub entry (38.12-15) needs nothing here.
- **Writing Style (Task 2; D-87, D-127 UI half, D-88).**
  - Each choice offers its presets plus a "Custom" segment, so a custom choice never leaves a preset highlighted.
  - The guidance box shows only while a choice is custom. Its caption names those choices, e.g. "Tone is set to use custom guidance:". That caption is the one place the page says "use custom guidance".
  - Hiding the box keeps the stored text, and Save still writes it.
  - `personalizationEstimateSource` counts the guidance only while a choice is custom, matching the `resolvePrompt` gate. This was the fold from 38.12-05 deferred item 1.
  - While a save runs, the style choices, the guidance box, both section forms, Import, Add, and every section row (handle, ⋯, switch) are all held.
- **AI Data Permissions (Task 3; D-86, D-88, D-28, D-129, D-138).**
  - The custom-field review query excludes `d.type = 'photo'`.
  - The custom-field setter writes `share_with_ai = CASE WHEN type = 'photo' THEN 0 ELSE ? END`, so a stale ref can never enable a photo field. The enable impact never counts one either.
  - All five default rows (including 38.10's Gift Ideas and Thought of Them) show a caption that follows the switch: "New items start with Allow AI on." or "… off."
  - "Review existing…" sets the filter and scrolls the page to the review card.
  - A list emptied by a filter now says "No items match this filter." The empty-library text appears only when there are no items at all, or when Enabled only is on and nothing is enabled.
- **AI Preview (Task 3; D-89, D-88, D-27).**
  - Page copy and section titles use plain words: "Orbit's instructions", "About this person", "Your style", "Memory 1", "Your context 1", "How the AI should answer", and so on.
  - The contact card comes first, as the copy says, and shows the contact's exact payload blocks.
  - With no contact chosen, the card shows an explicit "No contact chosen" message instead of hiding by name. A contact named "Example contact" now gets its card.
  - `resolvePrompt` is untouched. The byte-identity test passes, and every section shown is still an exact slice of the payload.
- **Shared card (Task 3; D-119).** AI Permissions, AI Preview and AI Personalization now draw their cards with `SettingsSectionCard` (plain surface) instead of `GlassSurface`.

## Deviations from Plan

**1. [Rule 3 - Blocking] SegmentedControl gained an optional `disabled` prop**
- **Found during:** Task 2
- **Issue:** D-88 requires the Writing Style choices to lock during a save, but the shared `SegmentedControl` had no disabled state.
- **Fix:** Added an optional `disabled` prop (default false), so existing callers are unchanged. A held row dims to 0.5 (the switch's disabled dim), ignores presses, and announces disabled.
- **Files modified:** src/components/SegmentedControl.tsx
- **Commit:** b0b06226

**2. [Rule 1 - Bug] Section switches held with `busy` + handler guard, not `disabled`**
- **Found during:** Task 2
- **Issue:** OrbitSwitch draws a disabled switch Off (D-26). Using `disabled` would make every section look turned off for the length of each save.
- **Fix:** The row passes `busy` to the switch, and the screen's `onToggle` ignores presses while a save or reorder runs.
- **Commit:** b0b06226

**3. [Rule 1 - Bug] Reorder made single-flight and optimistic**
- **Found during:** Task 1
- **Issue:** A drop with no immediate data update snaps the row back until the re-read. Two quick reorders could also compute from a stale order.
- **Fix:** Added a `reordering` state plus ref. The new order shows at once, a failure restores it, and the re-read happens after commit. Helpers `reorderSectionUids` / `orderSectionsByUid` were added to ai-personalization-logic.ts (tested). The plan listed that file only under Task 2's fold.
- **Commit:** 91bb1f77

**4. [Scope note] Extra test files touched**
- `ai-permissions-screen-contract.test.ts` and `ai-personalization-logic.test.ts` were not in the plan's file list. They pin the new caption, scroll and card contract, and the reorder and estimate helpers.
- `EXAMPLE_PREVIEW_CONTEXT` moved from AIPreviewScreen into settings-ai-logic.ts, so the screen no longer names "Example contact" (acceptance criterion).

**Total deviations:** 3 auto-fixed (1 blocking, 2 bugs) plus 1 scope note. **Impact:** no change to what is sent, and no recorded decision touched.

## Deferred / out-of-scope items

1. **The Custom Fields screen can still save `share_with_ai = 1` on a photo field through its own writer.** `updateFieldShareWithAi` (`src/db/field-defs-dao.ts:147`) has no photo guard. A type change into photo also keeps the old flag. Nothing is sent, because the 38.12-05 payload filter drops photo fields, and FieldDefForm (38.12-07) always saves 0 for a photo. This plan's photo clamp covers only the AI Data Permissions writer, as planned. Recommendation: add the same `CASE WHEN type = 'photo' THEN 0` clamp to `updateFieldShareWithAi` and the type-change path in a later field plan. It is low risk, since this is a second guard behind the payload filter.
2. **The inline section edit form is titled "New personalization section".** This predates the plan. Editing an existing section shows that label. Recommendation: label it "Edit section" when editing (a one-line copy fix), wherever the owner wants it.
