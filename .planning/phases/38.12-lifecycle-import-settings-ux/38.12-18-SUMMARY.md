# Phase 38.12 Plan 18: Restore Pages Summary

**Restore preview and Backup restored are now focused pages. The preview compares people on each side, names Replace once ("Replace all") and shows the real backup time. The restore shows its steps, and the result counts people, including those it moved to the Bin. The restore routes take a host param Phase 39 can pass.**

## Accomplishments

- **Focused pages (D-114).** RestorePreview and RestoreResult are in the focused-route set, so the tab bar and the + hide on both. The FAB clearance contract requires focused-only screens not to pad for the +, so both pages now pad by the bottom safe-area inset instead of `useBottomClearance`.
- **Steps (D-69).** The preview passes `onProgress` to `applyRestore`. The busy card's title is `restoreProgressLabel(step)`: "Making a safety backup…" or "Restoring contacts…".
- **People on the result (D-59, D-140).**
  - The result shows "Contacts on this phone before: N" and "Contacts restored: M".
  - For Replace all only, it adds "Contacts removed: K".
  - When K people moved to the Bin, it adds "K contacts moved to the Bin".
  - `RestorePeopleCounts` gains `movedToBin`: this phone's not-in-Bin people that the backup has in its Bin. It is read before any write, like the other counts, and is 0 for Merge.
  - The result route no longer carries row totals.
- **Preview (D-60, D-61, D-66).**
  - The preview shows "This phone: 12 contacts · Backup: 40 contacts".
  - The Replace all confirm now reads: "This replaces the 12 contacts on this phone with the 40 in the backup." It then gives the safety-backup sentence. It stays destructive and non-dismissable.
  - Every Replace label reads "Replace all": the mode option, the Apply button, the confirm title ("Replace all?"), the confirm button and the background note.
  - The mode is chosen with `OptionSelectRow` and `OptionSheet`. Merge is preselected, and the selected mode's description sits below the row.
  - The source date goes through the new `formatSourceTimeMinuteOrFallback`, which uses `parseIsoUtcMs` for "Z" and millisecond stamps.
- **Navigation (D-67, D-68).**
  - "Choose file again" and the expired-preview Back now call `popTo("Backup", { host })`, so Settings stays beneath Backup.
  - Backup, RestorePreview and RestoreResult read `route.params.host`, typed `RestoreHost` (FlowHost minus profile) and defaulting to settings. SettingsStack no longer injects host props.
  - BackupScreen passes its host to RestorePreview, and RestorePreview passes it to RestoreResult.
  - Each helper is an exhaustive switch with a `never` default.
  - Settings returns to the Settings hub ("Return to Settings"). Digest returns through `finishFlow({ kind: "digest" })` ("Return to Digest").
  - The `backup-tab` host, `BackupStackParamList` and `BackupScreenProps` are deleted.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Focused pages cannot use the + clearance**
- **Found during:** Task 1
- **Issue:** Once the two routes are focused, `fab-clearance-contract.test.ts` requires their screens not to call `useBottomClearance`.
- **Fix:** Both pages pad by `useSafeAreaInsets().bottom + 16`. The result render test mocks safe-area instead of the clearance hook.
- **Files modified:** RestorePreviewScreen.tsx, RestoreResultScreen.tsx, restore-result-render.test.tsx
- **Commit:** 732e8361

**2. [Rule 1 - Bug] A bare `popTo("Backup")` would drop the host**
- **Found during:** Task 3
- **Issue:** StackRouter's POP_TO replaces the target route's params unless `merge` is set (checked in `node_modules/@react-navigation/routers/src/StackRouter.tsx`). A digest-hosted Backup would fall back to settings, and its next restore would return to Settings.
- **Fix:** `navigation.popTo("Backup", { host })`. The plan's acceptance grep `popTo("Backup")` therefore does not match the literal text. `popTo("Backup"` does. A render test pins the call for both hosts.
- **Commit:** 0b58128a

**3. [Rule 2 - Missing critical] A digest return would leave the result on the Settings stack**
- **Found during:** Task 3
- **Issue:** `finishFlow({ kind: "digest" })` pops only `FLOW_ROUTE_NAMES` routes. The restore routes were not in that set, so Backup restored would still be on Settings the next time the user opened it.
- **Fix:** Added RestorePreview and RestoreResult to `FLOW_ROUTE_NAMES` in `flow-host.ts`, a file outside the plan's list. No existing flow stack holds them, so import, check and merge endings are unchanged. `flow-host.test.ts` passes.
- **Commit:** 0b58128a

**4. [Rule 2 - Missing critical] The mode row needed a locked state**
- **Found during:** Task 2
- **Issue:** The old radios were disabled while a restore applies (WR-1). `OptionSelectRow` had no disabled state.
- **Fix:** Added an optional `disabled` prop. It sets `accessibilityState.disabled`, Pressable `disabled` and 0.6 opacity. Other callers are unaffected. The row's press also goes through `applyRun.acceptsModeChange()`, and the sheet's pick goes through `selectMode`.
- **Commit:** a3d023dc

**5. [Rule 3 - Blocking] Source-contract tests pinned the old screen text**
- **Found during:** Task 2
- **Fix:** Two tests were updated to the new structure:
  - `backup-restore-logic.test.ts` (radio lock contract): now 2 `disabled={applying || modeLocked}` sites, `onSelect={selectMode}` and the gated row press.
  - `backup-presentation-contract.test.ts` (source date formatter name).
- **Commit:** a3d023dc
