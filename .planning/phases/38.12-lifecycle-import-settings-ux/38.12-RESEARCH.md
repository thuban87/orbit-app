## Summary

The dossier is accurate on the nine items, with seven things it does not say that change the plan:

1. **D-47 / D-102 "with its label" needs native work.** The contacts bridge sends no labels. `PickedMethod` is `{ type, value }` only (`modules/orbit-contact-picker/index.ts:9-12`), and all three Kotlin readers emit `mapOf("type" to "phone", "value" to value)` (`OrbitContactPickerModule.kt:194, 272, 438`). The reconcile classifier even says so: "Android's current PickedMethod bridge provides no source label at all" (`reconcile-diff.ts:98-100`). So there are no labels to "drop" today. Carrying a phone label needs `DATA2`/`DATA3` reads in `OrbitContactPickerModule.kt`, the same file D-118 changes, so it fits the same native plan.
2. **D-129 misses the actual AI payload builder.** `readSharedFields` (`src/db/ai-context-read.ts:194-219`) sends every `share_with_ai=1` custom value raw. It has no type filter, so a photo field's stored path goes to the provider today. The CONTEXT site list names only Research and Merge (`profile-knowledge-read.ts:258-275`, `compose-research-read.ts:294`). Add `def.type !== "photo"` at `ai-context-read.ts:200`. This narrows what is sent, as D-129 decided.
3. **A migration 034 is needed beyond D-45.** "Ask once" for paused checks and imports (D-105, D-111) needs a durable marker. No key-value table exists, and the session tables have no free column (`012-import-sessions.ts:14-28`, `013:8-16`), so it takes an `ADD COLUMN`. With D-45's missing-source memory, and an optional D-96 legacy repair, the phase has 1–3 schema changes. I recommend putting them all in one migration owned by one plan. Head is 033 (`033-knowledge-homes.ts:53` `KNOWLEDGE_HOMES_SCHEMA_VERSION = 33`; `database.ts:71` `TARGET_VERSION = KNOWLEDGE_HOMES_SCHEMA_VERSION`). `full-chain.test.ts:96` pins `expect(TARGET_VERSION).toBe(33)`.
4. **Indefinite snooze: use a sentinel date.** A `snooze_until` sentinel (`'9999-12-31'`) is honoured by every one of the ~18 existing snooze readers as written, because SQL `date('9999-12-31')` and `isSnoozed()` both treat it as a future date. It needs about 6 changed sites. Adding `reminders_off` to every reader needs about 30 (§1).
5. **D-118 changes Check linked contacts too.** `readContactsByLookupKeys` is used by both import and reconcile (`index.ts` `readAllContacts(keys)` → `readContactsByLookupKeys`). It currently prefers the `DATA15` thumbnail blob and falls back to `openContactPhotoInputStream(…, true)` (`OrbitContactPickerModule.kt:451-455, 473-479`). Reversing that order changes every reconcile photo hash once. D-118 also amends ADR-181 :18, "Imported phone photos stay at the native picker's thumbnail size (D-22)", which the CONTEXT supersession table does not list (Owner-bucket flags).
6. **D-116 has two traps.**
   - Pruning deletes anything `isOwnedAutomaticBackup` matches (`backup-service.ts:718-725`). If automatic backups share the manual-export prefix, a manual export the user saved in the backup folder could be pruned.
   - Re-encrypt names its replacements `automaticBackupFilename(now + index + 1)`, unique by millisecond (`backup-service.ts:445-449`). A minute-precision name collides. SAF then renames the file to `… (1).json`, which no longer matches the owned pattern.
7. **D-104's "Review matches keeps its own" has nothing to keep.** `DuplicateReviewScreen` offers `["link", "import-new", "skip"]` only (`DuplicateReviewScreen.tsx:354`). After D-104, `"apply-recommendation"` has no consumer except `ReconcileGridScreen.tsx:453` (being removed) and `reconcile-selection.ts:11`.

**Primary recommendation:** Use the sentinel for indefinite snooze. Put all schema changes in one migration 034 owned by one plan. Add one `flow-host` navigation module plus a `returnTab` Profile param. In each reshaping plan, find every consumer of the reshaped contract, tests and pinned counts included.

## 2. Reconcile re-prompt (D-45, D-47, D-102)

### Root causes confirmed (VERIFIED)
1. **Reviewed fields never filtered.** Both classifiers return `outcome: "unchanged-since-review"` (`reconcile-diff.ts:187-197, 273-286`). The grid keeps any card with `diff.fields.length > 0` (`ReconcileGridScreen.tsx:273`) and counts them in `unresolvedCount` (`:300-302`). The detail screen renders every field.
2. **Grid and detail read memory differently.**
   - Grid: `Object.assign({}, ...snapshots)` over all links, `effectivePhoneRegion: settings.phoneRegionOverride` (`ReconcileGridScreen.tsx:252-271`).
   - Detail: `snapshots[0] ?? {}` (first link only) and **no** `effectivePhoneRegion` (`ReconcileDetailScreen.tsx:209-227`). Its `applyReconcileSelections` call also passes no region (`:355-357`).
   - Method memory is the region-dependent `serializeMethodFamily(…, effectivePhoneRegion)` (`reconcile-diff.ts:102-123`). So a detail-written snapshot never equals the grid's serialization for national-format numbers. That is the "national-number case".
   - Neither uses the device region (Settings uses `phoneRegionOverride ?? getDeviceRegion()`, `SettingsContactsScreen.tsx:127-128`).
3. **Keep-Orbit photo never remembered.** `writeReviewedSnapshots` returns early for every photo selection (`reconcile-apply.ts:106`). Only Use-phone writes the photo hash, post-commit (`ReconcileDetailScreen.tsx:366-374`). A grid "Keep Orbit" over a photo field therefore re-prompts every time. The photo classifier also compares the Orbit **path** with the source **hash** (`reconcile-diff.ts:150, 224`), so equality never holds without memory.
4. **Impossible phone birthday.** Classified as a normal option. At apply it marks the field stale (`reconcile-apply.ts:185-188`), so no snapshot is written (`:277-281`) and the card stays `partial`.
5. **Missing source.** `omittedCount > 0` always returns a missing-source diff (`reconcile-diff.ts:318-334`). "Keep" only marks the card terminal (`ReconcileDetailScreen.tsx:259-281`). The next scan creates a new card.
6. **Detail Apply writes no disposition; a partial grid card does.** The grid writes `completionDisposition` with in-screen SQL (`ReconcileGridScreen.tsx:401-409`). Detail Apply never does, so `reconcileCompletionCounts` (`reconcile-session-read.ts:200-244`) cannot count it.

**Recommendations [this research only]:**
- **Keep a distinct automatic prefix** (`orbit-auto-YYYY-MM-DD-HHMM…`). `isOwnedAutomaticBackup` gates deletion (`backup-service.ts:718-725`). If automatic and manual names shared `orbit-backup-`, any manual export the user saved into the backup folder would match and could be pruned or re-encrypted. If the planner reads D-116's single example literally as one prefix for both, that is a data-loss risk, an owner question (Owner-bucket flags).
- **Uniqueness:** re-encrypt writes N replacements in the same run with `now + index + 1` ms names (`:445-449`). Minute precision collides, and SAF providers typically append ` (1)` (LIKELY, provider behaviour, not verified). The result fails the owned regex and orphans the file. Include seconds plus a collision suffix (`-2`, `-3`) in both new patterns, and parse it.
- **New patterns:**
  - Auto: `^orbit-auto-\d{4}-\d{2}-\d{2}-\d{4}(?:\d{2})?(?:-\d+)?\.json$`
  - Manual: `^orbit-backup-\d{4}-\d{2}-\d{2}-\d{4}(?:\d{2})?(?:-\d+)?\.json$`
  - Keep the old patterns ORed in at all four TS sites and in Kotlin `STAGED_NAME`.
  - Parse local names as local time (`parseLocalMs` style) for prune/expiry; keep the old UTC parse for old names.
- **DST:** a local name repeats an hour on fall-back day. The suffix covers collisions. Retention compares ages, so a one-hour skew is harmless.
