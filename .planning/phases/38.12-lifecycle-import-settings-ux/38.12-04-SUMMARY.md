# Phase 38.12 Plan 04: Backup File Names and Content-Only Intake Summary

**Backup names now come from one module. New files get local-time names (`orbit-backup-2026-10-17-0930.json` for manual exports, `orbit-auto-2026-10-17-0930.json` for automatic backups) built with `formatLocalDate`. A name that collides within one run gets `-2`, `-3`. Pruning and re-encryption still match the old epoch-ms and UTC names but never touch a manual export. Native intake now rejects any pick or share link that is not `content://`.**

## Accomplishments

- `src/backup/backup-file-names.ts` is now the only place backup file names are built or matched. It keeps `AUTOMATIC_BACKUP_PREFIX = "orbit-auto-"` and adds `MANUAL_BACKUP_PREFIX = "orbit-backup-"`. Names use local time (`formatLocalDate` + HHMM, never `toISOString`). The ownership and staged-export matchers accept both the old and the new shapes, plus the collision suffix. `backupNameTimestampMs` reads new names as local time, old automatic names as UTC and old manual names as epoch ms.
- `auto-backup-policy.ts`: the duplicated UTC regexes and parsers are gone. `filesToPrune` and `isExpiredAutomaticBackup` use the shared matcher and parser. `isExpiredAutomaticBackup` now checks ownership explicitly before parsing.
- `backup-service.ts`:
  - **Automatic write:** gives the file a readable name, suffixed if the folder already has that name.
  - **Re-encryption:** replacement names are unique across the folder and across the run. This replaces the old `now + index + 1 ms` trick.
  - **Prune and re-encrypt source list:** both use `isOwnedAutomaticBackupName`, so a manual export saved in the folder is never pruned or rewritten.
- `saf-storage.ts` `ownedAutomaticUris` uses the same matcher.
- `share-export.ts`:
  - **Naming:** a staged export gets a readable name, suffixed when another export already has that name in the staging dir.
  - **List and retire:** the list filter and stale retirement use `isStagedManualExportName` / `backupNameTimestampMs`, falling back to `modificationTime` as before.
- **Kotlin:**
  - `STAGED_NAME` accepts `orbit-backup-(\d+|\d{4}-\d{2}-\d{2}-\d{4}(-\d+)?)\.json`, the same set as the TS matcher. The parent-directory check is unchanged.
  - `BackupIngressRequests.submit` fails any source that does not start with `content://` (case-insensitive) before opening it.

## Decisions Made

- **Minute precision:** names use HHMM with a `-N` suffix, as the plan's patterns say. RESEARCH §7 had suggested optional seconds; the plan's narrower pattern wins, and Kotlin mirrors it exactly.
- **Automatic write lists once:** it lists the folder once before writing, both for the suffix check and for pruning afterwards. If that listing fails, the suffix check is skipped and the verified write still goes ahead. This matches the old rule that "listing/pruning failure never negates a verified write". Pruning still runs on its own listing after the write.
- **Rejected intake:** a rejected non-`content://` source goes through the same branch as the existing cap/destroyed failure. It supersedes the earlier request, completes `failed = true` (shown as "not a backup"), and settles share waiters.
