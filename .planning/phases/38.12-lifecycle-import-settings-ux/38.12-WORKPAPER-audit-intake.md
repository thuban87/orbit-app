### 4A. Lifecycle: archive / restore / bind / unbind / delete / favourite / snooze / mute

**Shared facts [CODE]:**
- The lifecycle column is `contacts.tracking_enabled`. `interval_days` is the dormant cadence: CHECK in migration `011:37`, and per ADR-062 it is never cleared once assigned.
- Archive is `contacts.archived_at`. An archived contact can still be Bound (`tracking_enabled = 1`).
- Most Profile gating checks only `lifecycle.kind` (`ContactProfileScreen.tsx:398, 554, 614`). An archived contact is therefore treated as a live Bound one.
- `"Archived"` is registered in both `DashboardStack.tsx:63` and `SettingsStack.tsx:238`. `UnboundContacts` is registered in DashboardStack only (`:64`).

**H-01 · High · Archived list never refreshes; stale rows fail Restore and Delete forever**
- **Cause [CODE]:**
  - `ArchivedContactsScreen.tsx:121-123` loads in a mount `useEffect`, never on focus.
  - The `doRestore` catch (`:134-137`) and the `doPurge` catch (`:189-191`) show "Please try again." and do not reload.
  - `restoreContact` (`contacts-dao.ts:959-986`, `WHERE … archived_at IS NOT NULL` at :966, throws at :969-973) and `purgeContact` (`purge-dao.ts:361-379`, throws if not archived at :375-378) both refuse correctly, so no data is harmed.
- **New detail [CODE]:**
  - ADR-080 keeps each tab's stack mounted, so the Contacts-tab and Settings-tab Archived instances can both be alive. An action in one leaves the other stale.
  - A Merge restore writes `archived_at` (`restore-apply.ts:746`) and does the same.
  - `rows` starts `[]` with no loading state (`:107`), so "No archived contacts" flashes before the first load.
  - Header comments `:2, :11-12` and `contacts-dao.ts:891-892` are stale.
- **Audit fix still right:** yes.
  - `useFocusEffect` load, as `UnboundContactsScreen.tsx:43-65` does with a cancel flag.
  - Reload in both catch blocks, so a no-longer-archived row disappears.
  - Add a loading state.
- Supersedes D-35 (report §4.1; assignment "No action").
- **Standard:** X-04 dialogs (both error alerts are native `Alert.alert`). No 39 link (D-30).

**H-17 · M · Archived rows truncate the name next to two large buttons; unlike Unbound rows**
- [CODE]:
  - `numberOfLines={1}` name (`ArchivedContactsScreen.tsx:263`) inside a row with two bordered buttons (`:269-290`).
  - No avatar. `archived_at` is selected (`contacts-dao.ts:994`) but never shown.
  - No search. The list is a plain `ScrollView` + `map` with no virtualization.
- **Recorded constraints [DOC]:**
  - ADR-018: "destructive UI uses the owner-approved `danger` theme token"; Delete must keep `danger`.
  - ADR-018: "restore and permanent deletion live only in Settings' Archived contacts list". Moving the actions to "a row menu" keeps them on this list, so that is fine. Moving them "to the Profile" (the audit's alternative) does not; see §5 R1.
- **Candidate shapes:**
  - (a) Unbound-style row (avatar + name + archived date), with Restore and Delete permanently behind a row ⋯ or a row sheet.
  - (b) Keep inline buttons but stack them under a full-width name.
  - Add search with the same reset rule as H-27.
- **Standard:** X-03 destructive rule (never the loudest control at rest), X-35 list rows, X-14 date formatter.

**H-18 · M · Restore gives no feedback and does not say where the person went**
- [CODE]:
  - `doRestore` (`:125-140`) only reloads and pushes the widget.
  - Restore also skips `reconcileSchedule`. When the next reconcile runs was not traced.
  - The snackbar primitive exists: `snackbar-store.ts:5-22`, with `action` and `secondaryAction` and 6 s auto-dismiss.
- **Candidate:** a snackbar such as "Restored · Unbound contacts" or "Restored · Contacts", from `tracking_enabled`, with an "Open" action.
  - An **Undo** on Restore would call `archiveContact`. That is allowed: ADR-018 says "archive is reversible from the profile" and puts no limit on where archive happens.
- **Standard:** X-05 feedback primitive (38.9).

The Profile favourite toggle (`:397-414`) has no widget push either, against `docs/systems/contacts.md:138`. Treat this as a correctness side-fix [CODE; impact on widget timing INFERRED].

**D-06 + H-24 · M/L · Archived Profile: no Restore; offers Archive (errors), Snooze and Unbind (which works); star works; Overview says "Stable"**
- **Cause [CODE]:**
  - `profileOverflowEntries` (`contact-profile-logic.ts:264-281`) has no archived input. The screen passes only `snoozed`, `bound`, `hasFreeformLayout` and `hasContactPresentationOverride` (`ContactProfileScreen.tsx:695-700`).
  - `archiveContactCore` requires `archived_at IS NULL` (`contacts-dao.ts:922`) → "Couldn't archive" (`ContactProfileScreen.tsx:446-447`).
  - `unbindContact` / `bindContact` have no `archived_at` guard (`contact-lifecycle-dao.ts:66-92, 117-121`). Snooze has none either (`snooze-dao.ts:106`). Favourites have none (`favourites-dao.ts:39-44, 75-77`).
  - The status read guards only `trackingEnabled === 0 || last_contact === null` (`contact-status-read.ts:53-75`).
  - `resolveProfileStatus` has no archived input (`profile-metrics.ts:152-183`).
- **Is the audit's fix still right?** Partly.
  - Dropping Archive, Snooze and Unbind when archived, disabling the star, and an "Archived" status/banner are all enforcement-safe.
  - The audit's **"Restore" button or overflow entry on the Profile reverses ADR-018** ("restore and permanent deletion live only in Settings' Archived contacts list"), re-affirmed by ADR-080 :18 and :43 ("would weaken ADR-018's single destructive surface") → **§5 R1, owner.**
- **Candidate shapes:**
  - (a) An Archived banner with "Open Archived contacts" (keeps the single home).
  - (b) Banner + Restore on the Profile (reversal).
  - Plus an archived input to `profileOverflowEntries` (Edit + presentation entries only).
  - Plus DAO guards: refuse bind, unbind, snooze and favourite when archived. That is defence in depth [INFERRED] and changes DAO contracts, so tests must be updated.
  - Plus an archived arm in `resolveProfileStatus` / the status read.
- **Standard:** X-23 unifying direction (the banner is closest to right). No 39 link.
