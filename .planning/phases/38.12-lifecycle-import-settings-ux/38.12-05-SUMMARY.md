# Phase 38.12 Plan 05: AI Egress Narrowing Summary

**The prompt now sends the custom guidance text only when a Writing Style choice is custom, sends Orbit's own instruction paragraphs as unbroken lines, and never includes photo-type custom fields in the AI payload or Compose Research. The preview is still the exact string that is sent.**

## Performance

- **Duration:** about 7 min

- **Completed:** 2026-10-17T19:42:30Z
- **Tasks:** 2
- **Files modified:** 9

## Accomplishments
- `writingStyleBlock` emits `Custom guidance: …` only when `[tone, length, directness]` includes `"custom"`. Otherwise there is no guidance line and no "None available" placeholder. The stored guidance text is untouched (D-127).
- `STATIC_INSTRUCTION`, `DEFAULT_STYLE_NOTE` and the rewrite, adjust and message-focus instructions go through a new `instructionParagraph()` helper that joins source lines with one space. Paragraph breaks (`"\n\n"`) stay, and the wording is unchanged. DATA blocks are not touched (D-128).
- `resolvePrompt` still builds one string that serves as prompt, inspector display and payload, so byte identity holds by construction. The existing byte-identity test passes unchanged (D-27).
- `readSharedFields` drops photo-type definitions before any value is read. `readPopulatedCustomFields` excludes `d.type <> 'photo'` in SQL. `readComposeResearch` re-checks the type. A photo path therefore cannot reach the provider directly or through Message Focus. Compose's send-time intersection also re-reads `readComposeResearch` (`ComposeScreen.tsx:453`). (D-129)
- The Profile's own custom-field read (`readCustomFields` / `readProfileKnowledge`) is unchanged and still shows photo fields, and a test proves it.

## Decisions Made
- Guidance that is not sent is also not bounded or disclosed, so it creates no truncation notice when no choice is custom.
- The photo filter in `readSharedFields` sits at the existing definition filter, which the plan allowed as an alternative to SQL. It runs before `getValuesForContact`, so no photo value is ever queried. The shared `listDefs` DAO was left alone.
- `readPopulatedCustomFields` is used only by Compose Research outside tests (verified by grep), so the SQL exclusion goes there and no `excludeTypes` option was needed. The Research mapping keeps a one-line type guard as a second check.

Recommendation: fold this into 38.12-16, which already owns that screen and the D-127 UI half (hiding the guidance box), and count the guidance only while a choice is custom.

After D-129, turning it on for a photo field does nothing, which could mislead the user. RESEARCH §8 raised hiding it only as "[this research only]". Hiding or disabling a control is a UI/product call for the owner. Recommendation: hide the switch for photo-type fields.
