# Phase 38.12 Plan 08: Review matches list + per-person sheet Summary

**Review matches is now a one-column list whose tap opens a titled bottom sheet (Link / Import as new / Skip / Cancel) that settles one person through the existing latched writes, with phone/email matches first, below-"possible" candidates dropped, and the pending link queue cleared on every close.**

## Accomplishments

- `ReviewMatchesList`: one-column FlatList. Each row shows the incoming person, "Might be: <Orbit name> (+N)" and the evidence for that named contact. A tap calls `onInspect`; long-press enters multi-select; the bulk bar shows "N selected" and Link / Import as new / Skip as buttons on the bar (filtered by `isBulkActionAvailable`). There is no RegisteredModal and no "Choose action" chooser (D-107, c2 B-4). Accessibility reuses `buildCandidateCardAccessibility` / `CANDIDATE_SELECTION_ACTION`, the same contract as Reconcile.
- `MatchChoiceSheet`: a `detail` Sheet titled with the incoming person. It lists the candidates as radio rows (select glyph, Avatar, name, evidence; label = name + evidence) in the sheet's own scroll body. Link is enabled once a candidate is picked; Import as new, Skip and Cancel are also there. Every control is held while a write is in flight. Nothing is preselected, and a pick is tied to the person, so it never carries over to the next queued person.
- `DuplicateReviewScreen` (A-2):
  - A tap sets `currentLink` to that row with an empty queue.
  - The sheet is driven by `currentLink`, so it serves both a single tap and the bulk-bar "link" queue.
  - Link calls the existing latched `chooseLink`. "Linked <incoming> to <Orbit name>" shows inside `onWritten`, so only after the write commits.
  - Import as new and Skip call `resolveAction(action, [currentLink.item])`. "Imported <name>" or "Skipped <name>" shows only when that row did not fail, and then the sheet advances or closes.
  - Cancel, scrim and Back clear both `currentLink` and `linkQueue` (D-52).
- `resolveExistingContactChoices` gained an explicit `REVIEW_MATCH_CHOICES` option: phone/email evidence first, each group in the stored score order, and nothing below "possible". Candidates it drops are filtered out before any header read. `choicesForRow` computes this list once, and the row's "Might be", its evidence line and the sheet all read it (c2 B-10, c3 D-3).
- `ExistingContactChoiceSheet` removed. `LinkExistingChoiceButton` kept for Import review.
- Reconcile is untouched: `ReconcileGridScreen.tsx` and `CandidateCardGrid.tsx` have no diff. The a11y source contract is narrowed to Reconcile, and ReviewMatchesList is pinned to the same helper.

## Decisions Made

- **Empty candidate list on a row:** no "Might be" line. The evidence line shows the neutral "Needs a closer look" hint instead of being left out. The sheet then says "No Orbit contact to link to." and still offers Import as new and Skip.
- **Import review unchanged:** `ImportReviewScreen.tsx:321` calls `resolveExistingContactChoices` with no option, so it still gets every live candidate in input order. It does not share the Review matches path.
- **Close is held during a write:** Cancel, scrim and Back do nothing while a latched write is in flight. Otherwise `chooseLink`'s `onWritten` could reopen the sheet on the queue entry it captured before the close (mitigates T-38.12-19).
- **The strength filter reads the scorer's own ladder:** it uses `candidateEvidenceStrength`, exported from `duplicate-evidence.ts`, rather than a copy of the weights.
- **Wording I chose (Claude's Discretion; the owner sees it at the device check, D-04/CONTEXT copy list):**
  - Snackbars: "Linked <incoming> to <Orbit name>", "Imported <incoming>", "Skipped <incoming>"
  - Sheet caption: "Might be one of these Orbit contacts"
  - Empty sheet: "No Orbit contact to link to."
  - Bulk buttons: "Link" / "Import as new" / "Skip"

## Deferred / out-of-scope items

1. **Bulk Import as new / Skip shows no success message.** Picking several people and pressing Import as new or Skip on the bar shows a message only when something fails. D-04 says every silent write gets a confirming message naming the person. This plan only covered the one-person sheet. Recommendation: add one combined message (e.g. "Imported 3 people") in 38.12-21, which already owns DuplicateReview's import follow-up. It is a few lines.
2. **"Phone matches first" changes nothing for today's stored data.** A phone or email match always scores 75 or more and a name-only match at most 25, and stored candidates are already sorted by score. So the new ordering only matters if a stored list is ever out of order. If the device check (N-02 / H-02 fixture) still shows a phone match missing or out of place, the cause is elsewhere: for example the contact's header no longer exists, or the match was never recorded. No action now; this note is for whoever reads the device result.
