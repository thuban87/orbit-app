# Phase 38.12 Plan 20: Profile Merge, Per-Person Phone Check, Value History and Template Save Summary

**The Profile ⋯ now offers "Merge with another contact…" for any live person and "Check with phone Contacts…" for a linked one. Both open in the tab the Profile is in, and a merge ends on the survivor's Profile there. The ⋯ sheet fits its content, has a Close, and is titled "More actions". A custom field's "View history" opens a real read-only history screen in every tab. Saving a layout template returns to the list with a snackbar. In Check linked contacts, pre-ticked values no longer move Orbit's primary unless the person tapped that field (D-144).**

## Deferred / out-of-scope items

1. **How D-144 counts a tap.** It works per field, as the plan's fold states. Any tap on a phones/emails field lets that field's first remaining pick become primary, including unticking a default.
   - Example: Orbit has A, the phone adds B and C, and the person unticks C. B then becomes primary.
   - A stricter reading is also possible: only a value the person ticked on themselves elects. The catch is that with every value pre-ticked, choosing a primary would need an untick and a re-tick.
   - Recommendation: keep per-field and watch it at the 38.12-26 device check. Your call if you want the stricter rule.
2. **Two spellings of the merge label.** The detail screen's own merge link reads "Merge with another contact" with no ellipsis (`ReconcileDetailScreen.tsx`). The new ⋯ entry has the ellipsis.
