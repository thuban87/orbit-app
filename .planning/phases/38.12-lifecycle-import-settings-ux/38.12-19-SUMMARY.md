# Phase 38.12 Plan 19: Check Linked Contacts Applies What You Tap Summary

**Check linked contacts now applies exactly the phone values you pick, each with the phone's label (Mobile/Home/Work/Main/custom). The first pick becomes primary and the old primary stays as a secondary; nothing is deleted. Bulk "Use Contact Values" adds every number with its label and leaves the primary alone. Apply returns to where the check started with a snackbar. The detail screen shows Orbit's numbers one per line, every choice looks selectable, the flow has one name, counts say "contacts", "Apply recommendation" is gone, and the four developer labels are plain words. The flow host now travels through every reconcile screen.**

## Accomplishments

- **Labels (D-47).** `pickedMethodLabel` maps the phone's raw TYPE/LABEL onto Orbit's set. Phone: 2 Mobile, 1 Home, 3 Work, 12 Main. Email: 1 Home, 2 Work, 4 Mobile. A custom TYPE uses its own text, trimmed. Anything else is Other. No code means no label.
  - Options keep the canonical key as their value, so memory and equality are unchanged.
  - Options now also carry `rawValue` and `label`. Labels never enter the family serialization, which is tested.
- **Picks (convergence c3 D-1, c4 E-5).**
  - Phones and emails take several picks. Name, birthday and photo stay single choice.
  - Additive phone/email fields open with every value picked. Conflicts open with nothing picked.
  - Tapping Orbit clears the picks, and removing the last pick falls back to Orbit.
  - An emptied list blocks Apply and never reaches the builder.
- **Primary (D-102).**
  - A detail pick sets `electPrimary`. Apply makes the first pick (in display order, not tap order) the primary of its type. Every other method of that type becomes a secondary.
  - A pick that already exists in Orbit flips that same row to primary; no duplicate is added.
  - Seeded ∪ additions is always passed, so no tombstone is written (tested).
  - Bulk never elects.
- **Detail (D-48).**
  - A successful Apply goes back and shows "Updated <name> from phone Contacts", or "Kept Orbit values for <name>" when nothing was taken.
  - Apply is disabled after success and while it runs.
- **Readable Orbit side (D-47).** Phones/emails diffs carry `orbitMethods`. The Orbit option shows them one per line ("Mobile · (312) 555-0111"), and source options show the phone's own value with its label.
- **Selection look (D-48).** Every FieldChoiceGroup row shows an empty radio (single) or checkbox (multi) before a tap. A chosen row fills in accentText with an accent border.
- **Counts, name (D-46, D-49, D-141).**
  - Check complete counts with `plural(n, "contact")`, and its buckets are exclusive.
  - The detail and the grid are both titled "Check linked contacts".
- **Host (D-110, A-1).** `host` is forwarded:
  - Grid → ReconcileComplete and Grid → ReconcileDetail.
  - Detail → SurvivorSelect from both merge entries; the second keeps `secondContactId`.
  - Complete → Grid ("View unresolved").
- **D-104.** Removed:
  - the `apply-recommendation` bulk action, with its `BulkAction` and `ReconcileBulkMode` members, its label and the `recommendationExcludes` prop;
  - the orphaned test cases for them.
- **D-103.** "Not in phone Contacts", "Needs your choice", "Link to a different phone contact" and "Unlink from phone contact" are glossary constants used at every site.
  - The unlink action keeps its danger colour and scrim.
  - The glossary contract pins the values, and `docs/systems/glossary.md` records them.
- **Staging fold (38.12-10 deferred item 1).** The detail stages under `detail-contact-N-link-M` and never touches a grid card's file. It deletes its unpromoted copies when it closes or re-reads.

## Decisions Made

See `key-decisions` in the frontmatter. In plain words:

- **New look for every choice row, Merge conflicts included.** Each row shows an empty radio or checkbox before a tap. FieldChoiceGroup is the one shared conflict control, so Merge conflicts get the same look.
- **New copy: "Kept Orbit values for <name>".** It is the snackbar for a detail Apply that took nothing from the phone. Saying "Updated" there would not be true.
- **Phone values are now stored as the phone wrote them.** "Use Contact Values" stores `(312) 555-0122` instead of the E.164 key. This follows the plan's `value: rawValue ?? value`.

## Deferred / out-of-scope items

1. **A no-tap Apply can change which number is primary.** On an additive phones field, every phone number is picked by default, as the plan specifies (c4 E-5). The first one in sorted order becomes primary (D-102).
   - Example: Orbit has A (primary) and B, and the phone has A, B and a new C. If B sorts before A, pressing Apply without tapping makes B the primary.
   - Nothing is lost, and the old primary stays as a secondary. But the person never asked for that change.
   - Recommendation: when nothing was tapped, keep Orbit's primary, so only an actual tap elects a new one. It is small, but it is a behaviour choice, so it is your call. Worth watching for at the 38.12-26 device check.
2. **Phone numbers the phone stores in an invalid form are never offered.** This was already true before this plan. A source number that does not normalize (for example `+1 555 000 1111`) produces no option, so it cannot be added or picked.
   - Recommendation: leave as is unless you have seen this on a real phone.
3. **Unused grid actions.** `CandidateCardGrid` still declares `link`, `import-new` and `skip`. Review matches moved off the grid in 38.12-08, so only Check linked contacts uses it now.
   - Recommendation: remove them in a later cleanup. They are harmless.
4. **`docs/systems/contact-reconciliation.md` still says "Unlink source".** It appears in its ADR-179 line and changelog, and the doc does not yet describe the new apply semantics.
   - Recommendation: the 38.12 KB extraction syncs this together with recording D-103 as amending ADR-179, as the plan states.
5. **The Settings → Contacts & Relationships row "Check linked contacts"** (`settings-contacts-model.ts:147`) is still a literal, not the new `CHECK_LINKED_CONTACTS` constant. Same text; this plan does not own that file.
   - Recommendation: switch it whenever that file is next touched.
