# Phase 38.12 Plan 11: Merge picker, complete summary and photo-field fixes Summary

**Merge now starts from a searchable shared contact picker with the launching person first and no Bin contacts, survives text in a photo field, reads its conflicts through a DAO that shows photo fields as photos, lists every table it moves, and carries the flow host to the summary.**

## Performance

- **Tasks:** 3
- **Files modified:** 19

## Accomplishments

- SurvivorSelect step one embeds the shared `ContactPickerList` (always-visible search) with `excludeContactId={first}` and `allowArchivedSearch={false}`, over a live-only `listPickerContacts` read. The header ✕ Cancel leaves before anything is chosen. The launching person is shown as a fixed "Merging" card above the list. Loading shows a spinner and "Loading contacts…". A failed read shows an `EmptyState` with "Try again". Neither is ever shown as the empty list (D-43, D-99).
- The `secondContactId` entry from Reconcile's "Review merge" still goes straight to "Which contact survives?". It never mounts the picker or reads the list, and Back still leaves to Reconcile (L-5).
- `host` (default `settings`) is passed SurvivorSelect → MergeConflicts → MergeImpactSummary, so `finishFlowOnProfile` ends a Profile-started merge on the survivor's Profile (D-110).
- Text in a photo-type field no longer breaks a merge. `mergeContactsWithPhotoOwnership` only rehomes values that pass `isStoredPhotoPath`. `mergeContacts` treats a non-path value in a photo field as an ordinary custom value: it moves to a survivor with no value, wins over a blank survivor value, and wins when chosen. It is never coerced or cleared (D-131, T-38.12-26/27).
- `readMergeConflictData` (new `src/db/merge-conflicts-read.ts`) replaces the screen's three in-screen queries. Each custom conflict carries a `kind`. A photo-type field holding two stored photos renders as a `PhotoChoice`. Text renders as text choices, and a stored path never shows as its file path (D-44 DAO rule, D-129).
- `MergeImpactCounts` now covers all 11 tables in `mergeContacts`' reparent list. The summary renders one `plural()` line per non-zero count (D-44).

**MergeImpactCounts field → table → merge-dao reparent list (`src/db/merge-dao.ts:513-525`, the `for (const table of [...])` block):**

| Field | Table | Count rule |
|---|---|---|

Also not listed: third-party `relationships.linked_contact_id` repoints (`merge-dao.ts:491-494`), which change other people's Key People rather than moving rows.

## Decisions Made

- I used `ContactPickerList` rather than the modal `ContactPicker`. A picker that is the whole screen should not be a dismissable sheet over an empty screen, and the list is the shared picker's body (D-43 "reuses ContactPicker"). Cancel is the house header ✕ (38.9 D-59), the same affordance MergeImpactSummary uses.
- The error action reads "Try again" (the house EmptyState convention, e.g. GroupEventsScreen) rather than the plan's "Retry".
- A photo field holding a stored photo on one side and text on the other is shown as text choices, with the photo side reading "Photo". The plan defines only two kinds, and `PhotoChoice` cannot show text. Either choice merges correctly: a chosen absorbed photo is still rehomed.
- Every summary line now shows only when its count is non-zero, following the plan's behaviour line. The four original lines used to show "0 …".
