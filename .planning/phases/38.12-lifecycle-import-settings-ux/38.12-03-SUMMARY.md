# Phase 38.12 Plan 03: Host-aware flow endings Summary

**Import, Check linked contacts and merges now finish where they were started (Settings → Contacts & Relationships by default) through one `flow-host.ts` module, instead of a root reset that wiped every tab's history; "View contact" opens a Contacts-tab Profile whose Back returns to Settings.**

## Accomplishments

- `src/navigation/flow-host.ts`: `FlowHost` (`settings` | `profile` with the launching route key | `digest`), `DEFAULT_FLOW_HOST`, `finishFlow`, `finishFlowOnProfile`, `exitFlow`, `openContactFromFlow`, and `returnFromProfileToTab`. The settings host pops to `SettingsContacts`. When the current stack has no `SettingsContacts` (the merge routes are also registered in the Dashboard, Digest, Events and Orrery stacks), it pops to that stack's root and logs a warning instead of sending an action nothing handles (A-1).
- The Profile takes a new `returnTab` param, and `openProfileInContactsTab` sets it. When it is set, header Back, system Back and leaving after Move to Bin switch to the host tab without adding a history entry, then pop the Profile off the Contacts stack while that tab is hidden.
- Four flow endings now go through the host: Import complete, Import review (single import and link: a "Imported <name>" or "Linked <phone name> to <Orbit name>" snackbar with a View action), Check complete, and the merge summary. No flow screen imports `reset-intents` any more. The root-reset builders stay for ComposeScreen, widget-linking and notification-gate.
- Every import, check and merge route now declares an optional `host` param. This plan only reads it at the four endings; later plans pass it along between screens.

## Decisions Made

- flow-host gets the tab navigator from `navigation.getParent()` (the tab navigator is the root, ADR-146), not from `navigationRef`. That keeps the module importable from node tests, like `tab-entry.ts` and `tab-history.ts`.
- `finishFlowOnProfile` replaces the launching Profile with `Profile(survivor)` and keeps everything below it. The launching Profile is matched by route key, never by name. If that key is missing, it keeps the routes below the first flow route and logs a warning.
- A digest-host ending switches to Digest without adding a history entry, then pops every flow route (`FLOW_ROUTE_NAMES`) off the Settings stack.
- "View contact" on Import complete does not end the flow first. Back from the Profile therefore returns to the Settings tab as the user left it, which is the Import complete screen. Import review's View action comes after the flow has already ended, so Back lands on Contacts & Relationships. Both match D-110's "Back from it returns to Settings".
- The link snackbar's "phone name" is the name in the review form (`name.trim()`). If that is empty, the label is "Linked to <Orbit name>". The View action's accessibility label names the person.

**1. [Rule 3 - Blocking] `useBackActsAsDone` gained an `enabled` flag (file not in the plan's list)**

- **Issue:** The plan calls for system Back "via useBackActsAsDone with the same handler" only when `returnTab` is set. A hook cannot be called conditionally, and calling it unconditionally would capture every Profile's Back.

- **Files modified:** src/navigation/back-acts-as-done.ts

- **Files modified:** src/navigation/back-acts-as-done.test.ts
