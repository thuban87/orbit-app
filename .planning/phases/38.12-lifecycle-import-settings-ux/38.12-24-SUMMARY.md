# Phase 38.12 Plan 24: Flagged custom values, Review now and type-change pre-flight Summary

**Flagged custom-field values are now one tap from being fixed.** One danger "Needs attention" marker on the Profile opens Edit Contact at the field, where the stored value, the problem and the expected format are shown. After a type change that flags values, a "Review now" list of the affected people is offered. All of these use one shared predicate, `isFlaggedCustomValue`, and no stored value is ever rewritten.

## Accomplishments

- **One flagged predicate (C-4).** `isFlaggedCustomValue({ type, options }, raw)` in `field-parsers.ts` is true when the type's parser fails or a dropdown value is no longer one of its options. Four places use it:
  - the Profile's flag (`profile-knowledge-read.ts`), with the same result as before;
  - Edit Contact's field error, through `customFieldValueError`;
  - `listContactsWithUnreadableValues`;
  - `preflightTypeChange`.
- **Profile marker (D-70).** The card now shows the "Needs attention" metadata line once, in `colors.danger`. The duplicate caption is gone.
  - Tapping a flagged card runs Edit for that field.
  - `editDestination` sends a custom-field Edit to `Edit { contactId, focusFieldDefId }`.
- **Edit at the field (D-70, C-5).**
  - `Edit` params are `EditContactParams { contactId; focusFieldDefId? }` in all five param lists.
  - The Custom Fields section moved into `edit-contact-custom-fields.tsx`.
  - `useFocusFieldReveal` expands the section after hydration. It then waits for the target row's `onLayout` and calls the form's `reveal` once per opened field.
  - `FieldValueInput` gains `error`: the problem and the expected format, in danger, under the widget, which still shows the stored text.
- **Review now list (D-121).**
  - `listContactsWithUnreadableValues` returns live contacts (not in the Bin) with a flagged value, ordered by name. It is read-only.
  - The `CustomFieldReview { fieldDefId }` screen is registered in the Settings stack. Each row shows Avatar, name and stored value, and opens Edit at the field.
  - The list reloads on focus and shows "Nothing left to fix" when empty.
- **Type change (B-5, D-121, D-24, D-139).**
  - `preflightTypeChange` takes `{ type, options }` and classifies with the shared predicate, so text "Gold" → dropdown ["Platinum"] flags 1.
  - Every caller passes the object: `CustomFieldsScreen`, `field-type-change.test.ts` and the 006 migration test.
  - After an applied change that flagged values, a "Review now" / "Later" offer opens `CustomFieldReview`.
  - The §14.4 summary stays the only confirmation, and at 0 it drops the "need your input" clause (D-139).
- **Photo Allow AI clamp (D-129, D-138, mid-phase fold).**
  - `updateFieldShareWithAi` writes `CASE WHEN type = 'photo' THEN 0 ELSE ? END`.
  - `applyTypeChange` to photo sets `share_with_ai = 0` in the same UPDATE as the type. Values are untouched.
