# Phase 38.12 Plan 17: Backup Now and Backup Page Fixes Summary

**"Back up now" on the backup warning card runs the automatic backup's own write-verify-health function (now shared with the launch sweep). Also on the Backup pages: an export choice with Cancel, a passphrase show/hide, registry icons, titles that match their links, section routing, the real folder name and kept-backups count, and the shared Settings rows/cards.**

## Accomplishments

- `runAutomaticBackupNow` holds what the sweep hook used to do after its gate: the same verified snapshot, the same three health writes and the same skipped-photo record. The sweep keeps its gate and its hook id/requires and calls it. The warning card's Back up now calls it with no gate, shows a snackbar, then reloads health, so a successful backup clears the warning.
- `chooseAutomaticBackupFolder` is now the one folder chooser. Backup settings uses it, and so does the warning card's "Choose a folder", which opens the SAF picker in place.
- Export asks through a themed `choose()`: Export readable JSON / Export encrypted / Cancel. Cancel, Back and the scrim export nothing.
- The restore passphrase field has an eye button: "Show passphrase" / "Hide passphrase", hidden by default and hidden again on each new file.
- All six text glyphs are now registry icons (new keys: backup-export, backup-restore, backup-privacy, show-secret, hide-secret; plus the existing forward and close).
- The Backup page is titled "Data & Backup". The hero link and the Backup settings title both read "Backup settings". Backup settings reads `route.params.section` and scrolls to that section once it has laid out.
- The folder name comes from the tree URI at display time ("Orbit" instead of "Selected backup folder"). The hero counts the owned automatic backups in the folder after it has drawn: 0 when there are none, and no count until the listing finishes.
- Backup settings' folder, Open backup folder, interval and retention are SettingsRows in an "Automatic backups" card, and Encryption sits in its own section card. On the Backup page, the Encryption entry is the shared SettingsRow.

## Deferred / out-of-scope items

1. **Google Drive folder names will not read well.** For device storage, the name derived from the URI is the real folder name (e.g. "Orbit"). For a Drive folder, the URI only holds an opaque id (something like `acc=1;doc=encoded=…`), so following the plan's rule the page would show that id. A real Drive name needs a native display-name lookup (DocumentsContract), which is a native build. My recommendation: check on the device pass whether the test phone's backup folder is on Drive. If it is, add the native lookup to a later native plan.
2. **The pre-restore safety backup records no health** (`RestorePreviewScreen.createPreRestoreSnapshot`). It writes a verified automatic snapshot but leaves the health row as it was, so the card can still say "needs attention" afterwards. This is pre-existing and may be intended (its own docstring treats it as a safety copy, not a scheduled backup). Not changed here. Flagging it in case the owner wants it to count.
