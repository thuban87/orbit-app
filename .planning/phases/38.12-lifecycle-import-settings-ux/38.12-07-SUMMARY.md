# Phase 38.12 Plan 07: Management Lists Pattern Summary

**Custom Fields and Systems now use the Categories pattern (drag handle plus a ⋯ menu, destructive item last). Custom Fields copy reads correctly: plural counts, "kept until <date>", "has values for N contacts", and type labels instead of raw type ids. Photo fields have no Allow AI switch. The System builder opens on its Members page from Manage Members and uses one reset label. Category delete is a single confirm.**

## Accomplishments
- Custom Fields: active fields sit in a `ReorderableList`. A drag end and Move up / Move down both call `reorderFields` over the full order (active first, quarantined after). Edit, Move up, Move down and Delete-or-Quarantine (decided by the field's data) live in an `AnchoredMenu`. Quarantined rows have a ⋯ with Restore. No inline buttons remain.
- Custom Fields copy:
  - The type-change and options-change summaries agree in number ("1 needs" / "4 need") and keep the §14.4 sentence.
  - Quarantined rows read "<Type> · kept until <date>", computed from `quarantined_at` + `QUARANTINE_WINDOW_DAYS`.
  - The confirm says why the action differs: "has values for N contacts" or "has no values". The count comes from the new `countFieldValues` read.
  - The stale ALTER-TABLE header comment now describes the migration 006 / ADR-001 model.
  - Lists show `FIELD_TYPE_LABELS`, and the placeholder reads "e.g. Favorite coffee".
- Photo-type definitions hide "Share with AI suggestions" and always save `share_with_ai = 0` (D-129).
- Systems: the button row is replaced by a ⋯ menu, ordered as plain actions, then Move up/down, then Delete or Reset Membership Changes last as danger. The `system-<id>-<action>` ids ride on the menu items. The inline rename keeps its Cancel / Save name.
- System builder:
  - The decorative circles are removed and the Fill stays.
  - Manage Members passes `initialPage: "members"`.
  - The builder and the Systems menu share `RESET_MEMBERSHIP_CHANGES` and one confirm.
- Categories:
  - Delete is one destructive, non-dismissable `ConfirmDialog`. It shows plain counts ("2 people move to Uncategorized."), the Move-to chooser, and a Show details toggle with the full breakdown.
  - One Cancel leaves the dialog, and an empty category gets a one-line body.
  - Back and the scrim are inert.
  - Menu items now read Move up / Move down.

## Decisions Made
- The builder route param is **`initialPage: "members"`** (the plan asked for the name to be recorded). Back from the Members page still steps to Definition first, under the recorded 38.9 D-14/D-69 builder rule.
- The reset label and confirm wording live in `orrery-system-logic.ts`, because the builder test already mocks that module and the builder should not import a screen. The confirm title became "Reset membership changes?" to match the one label.
- Systems ⋯ order: plain actions, then moves, then the destructive action. Reset Membership Changes is treated as destructive because its confirm is destructive (D-06).
- Category delete keeps the target chooser inside the single confirm. To support that, `ConfirmDialog` gained an additive `children` slot; every other caller is unchanged.
- The placeholder uses American "Favorite": the plan's example "Favourite" would fail the glossary contract (38.9 D-49).
