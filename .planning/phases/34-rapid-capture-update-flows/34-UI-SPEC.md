# Phase 34 — UI Design Contract

> Visual and interaction contract for Rapid Capture & Update Flows (Add Contact, Quick Log,
> detailed Log Interaction, Update Contact) plus the Edit Contact and Memory-editor seams they
> touch. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a React Native / Expo app, not web.** There is no shadcn (web-only) and no component
> registry. The design system is the project's own theme-token layer in `src/theme/` — every value
> below is expressed as an existing token, and this phase MUST NOT introduce new hardcoded colour,
> size, or spacing literals. The `npm check:colors` gate blocks hex/named colour literals in `src/`.
> All colour resolves at render through `useTheme().colors.*` (CLAUDE.md, non-negotiable).
>
> **Scope note:** the design system already exists and is shipped. This contract does NOT re-specify
> tokens — it declares which existing tokens this phase's new/modified surfaces must consume, and the
> interaction/copy contracts the four flows must honor. Most primitives already exist:
> `Button`/`button-roles`, `AppText`, `TouchpointRefineForm` (channel/direction/connected/tone/note/
> Allow-AI/duration), `TriStateLastSpoke`, `MemoryEditor`, `Snackbar`, `SegmentedControl`,
> `FrequencyPicker`, `ContactPicker`, `Icon`. Compose these; do not clone them.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (project `src/theme/` token system — shadcn is web-only and N/A to React Native) |
| Preset | not applicable |
| Component library | React Native core + `src/components/ui/*` primitives (`Button`, `AppText`, `Modal`, `Sheet`, `ConfirmDialog`, `GlassSurface`) |
| Icon library | in-repo semantic `Icon` over `icon-registry` (four sizes via `ICON_SIZE`, tone via theme token) — no external icon package |
| Font | Space Grotesk SemiBold (display/heading) + Inter Regular/SemiBold (body/label/caption), bundled locally (`src/theme/fonts.ts`); degrades to system font, no network |

Design mode: theme is package (`galaxy` / `standard`) × mode (`light` / `dark` / `system`).
Every surface in this phase must render correctly in all four resolved palettes. Never assume a dark
background. (Theme-merge into a single Dark/Light switch is PARKED — do not build against it here.)

## Spacing Scale

Declared values come from `src/theme/tokens/spacing.ts` — consume the token, never a raw px.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, error-text top gap |
| sm | 8px | Compact element spacing, control-group `gap`, segment gaps |
| md | 12px | Dense row inner padding, field vertical padding, chooser row padding |
| base | 16px | Default element spacing, screen/section padding, form field gaps |
| lg | 24px | Between conceptual groups / accordion sections |
| xl | 32px | Major section breaks |
| 2xl | 48px | Page-level spacing |

Exceptions:
- **`md = 12` is a sanctioned pre-existing deviation** from a pure 8-point scale (documented in
  `spacing.ts`: grid-aligned, real need for dense row inner padding where 8 is too tight and 16 too
  loose). This is the established project scale — do not "fix" it to 16, and do not introduce new
  off-scale values.
- **44px minimum touch target** (`MIN_TOUCH_TARGET`, `button-roles.ts`) is a target-size FLOOR, not a
  spacing token. Every tappable control in these flows (segments, chooser rows, Save/Done, Add Note,
  Show More, More Options, icon-only) pads up to ≥44×44 even when its glyph/label is smaller.

## Typography

Roles come from `src/theme/tokens/typography.ts` — exactly 4 sizes, exactly 2 weights, 5 semantic
roles. Screens consume the ROLE via `AppText`, never a raw fontSize/fontWeight.

| Role | Size | Weight | Line Height | Family | Colour token | Usage in this phase |
|------|------|--------|-------------|--------|--------------|---------------------|
| display | 28px | 600 | 34 (×1.2) | Space Grotesk | textPrimary | Screen title (Add Contact / Log Interaction / Update <Name>) |
| heading | 20px | 600 | 25 (×1.25) | Space Grotesk | textPrimary | Accordion section headers, Memory-editor title |
| body | 16px | 400 | 24 (×1.5) | Inter | textPrimary | Field values, note/multiline text, chooser row primary text |
| label | 14px | 600 | 20 (×1.4) | Inter | textPrimary | Field labels, segment labels, button labels |
| caption | 14px | 400 | 20 (×1.4) | Inter | textSecondary | Helper text, provenance, "no interaction created" hints, muted metadata |

Line heights are absolute px derived from the multiplier, NOT fixed clamps — OS text scaling still
reflows (THEME-07). Accessibility (dossier §AJ): accessible name must match the visible label;
accordion expanded/collapsed state announced; Tone/selection/error state never conveyed by colour
alone (pair colour with text/shape/`accessibilityState`).

## Color

Colour is a 2-package × 2-mode token system, not a fixed 60/30/10 palette. The 60/30/10 intent maps
onto token ROLES below; the concrete hexes live only in `theme-presets.ts` and resolve per active
theme. This phase adds ZERO colour literals.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (~60%) | `background` | Screen background under every flow |
| Secondary (~30%) | `surface` / `surfaceElevated` | Field backgrounds, accordion bodies, chooser rows, note editor, snackbar/sheet surfaces; `border` / `borderStrong` for outlines and selected-segment emphasis |
| Accent (~10%) | `accent` (fill) / `onAccent` (on-fill text) / `accentText` (link/text tone) | See reserved-for list below |
| Destructive | `danger` (fill/emphasis) / `onDanger` (on-fill foreground) | Destructive-action buttons AND inline validation/error TEXT only |

Accent reserved for (never "all interactive elements"):
- The single **primary Save** action per form (`Button` role `primary`: `accent` fill + `onAccent` label).
- The **selected/active segment** of a segmented choice (channel, direction, Tone, tri-state last-spoke) — `accent` fill + `background`/`onAccent` label, following the shipped `SegmentedControl` / `TriStateLastSpoke` idiom.
- **Text-only / link affordances** use `accentText` (`Button` role `tertiary`): Add Note, Create Memory Instead, Edit Memory, Show More, More Options, Update Contact "Done", snackbar action.
- Active/checked state on inline multi-controls (e.g. the ✓ on a selected choice).

Explicit non-accent rules:
- **Allow AI toggle** is an ordinary `Switch` on `surface`, NOT accent-emphasised — it must not read
  as a recommended/on-by-default control (see privacy contract below).
- **"Not yet"** last-spoke segment stays muted (`surface` + `borderStrong` + `textSecondary`), never
  accent-filled even when selected — the never-contacted backlog case reads honestly, and muting is
  deliberately NOT `danger` (it is a valid, non-error choice).
- **Tone** never uses status hues; Positive/Neutral/Negative are selection segments, not
  `statusStable`/`statusDecay`. Omitted Tone shows no selection (not a "Neutral" fill).
- Validation/error copy renders in `danger` TEXT (mirrors `TriStateLastSpoke` / `TouchpointRefineForm`
  future-date rejection), not a full red surface.

## Copywriting Contract

Locked strings already shipped in the codebase are marked (locked) and MUST be reused verbatim, not
re-authored.

| Element | Copy |
|---------|------|
| Primary CTA — Add Contact | **Save** (form-level, may live in the app bar; routes to the new Contact Profile on success) |
| Primary CTA — Log Interaction | **Save** (writes the interaction; completion returns to the origin-aware target Profile) |
| Primary CTA — Quick Log | (no form CTA — Quick Log writes immediately; feedback via snackbar) |
| Update Contact — session exit | **Done** (`tertiary`/accentText; each item's inner Save returns to the chooser, Done ends the session) |
| Progressive disclosure — Add Contact | **Show More** (reveals advanced enrichment sections) |
| Progressive disclosure — Log Interaction / Memory editor | **More Options** (Duration lives here; Memory label/metadata lives here) |
| Quick Log success feedback | **Logged** with **Undo** action (locked snackbar contract — truthful only on real persistence success) |
| Quick Log post-log note affordance | **Add Note** → small editor exposing **Create Memory Instead**; after a basic Memory, offer **Edit Memory** |
| Allow AI toggle label | **Allow AI** (helper caption: "Let AI use this note's text. Off by default.") |
| Empty state — Update Contact chooser | (never truly empty — built-in actions always present: Last Talked About, Key People, Current Location, Memory, Off Limits, Contact Method, Contact Frequency, Custom Fields. If the contact has no applicable named custom fields, simply omit those rows; the generic **Custom Fields** row remains.) |
| Empty state — new contact, no interactions | Last-spoke defaults to **Today**; choosing **Not yet** creates no interaction. Caption: "Not yet — no interaction is recorded." |
| Error — save failure | **Couldn't save** / **Please try again.** (locked; form state preserved, never shows completion, exposes Retry where recoverable) |
| Error — future last-spoke date (Add Contact) | **That date is in the future. Pick today or earlier.** (locked, `FUTURE_DATE_MESSAGE`) |
| Error — future interaction date/time (Log Interaction) | **That time is in the future. Pick now or earlier.** (locked, `FUTURE_DATETIME_MESSAGE`) |
| Error — malformed optional field | Field-level actionable text; reveal + focus the containing accordion section (dossier §AD). Do not silently drop entered content. |
| Destructive confirmation | This phase authors no destructive delete flows. Discard-unsaved uses the shell dirty-state prompt: **Discard changes** / **Keep editing** (only after meaningful edits; an unchanged form exits with no prompt). |

### Owner-pending naming — DO NOT FABRICATE (flagged, D-11 / carried-forward)

Two naming decisions are the owner's and are UNRESOLVED. The planner/executor must NOT invent either;
surface them for the owner before locking copy.

1. **"Log Interaction" vs "Log Contact"** (D-13-184, taste call). The dossier §AN normalizes *toward*
   **Log Interaction**, so this spec uses "Log Interaction" as the provisional label — but the final
   choice is the owner's. FLAG at plan time.
2. **Default/general built-in Memory type name** (D-13-060 / D-RM-056 / D-13-190). The registry ships
   a PROVISIONAL label **"Memory"** (`PROVISIONAL_MEMORY_LABEL`, `memory-registry.ts:10`;
   `DEFAULT_MEMORY_TYPE_KEY = "general"`). Rapid Memory capture must request the registry's designated
   default type by key, never hardcode a type ID or a display name in the Quick Log / editor UI. The
   final display name is an owner reconciliation blocker — FLAG, do not rename inside the plan.

## Privacy contract (non-negotiable — CAPT-10 / D-04 / ADR-078)

- The per-interaction **Allow AI** toggle is placed **with the Note field** and ships **default OFF**
  (`allowAi: 0`), initialized from Phase 36's new-items-only type default. It is a per-interaction
  gate, survives save, and stays editable via canonical Edit Interaction.
- Shipping default-ON, or routing a **Group Note** through this toggle, is a decision reversal and a
  widening of AI egress — STOP AND ASK (owner-bucket). Group Notes are never transmitted to AI under
  any Allow-AI value, including group-linked children.
- No network on any read path. The toggle is the only thing that makes a note *eligible* for the
  explicitly-invoked AI feature; it does not itself transmit anything.

## UI Considerations

State coverage for the shape-rooted UI states these flows produce. Empty/error COPY lives in the
Copywriting Contract above; this table covers state behavior and references those rows.

Applicable state considerations resolved: 5 covered, 3 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| partial | Add Contact name-only | ✅ covered | Name is the only required field; Save persists with Category/Frequency/methods/photo absent and routes to the new Profile (CAPT-01). |
| empty | Add Contact never-contacted | ✅ covered | Last-spoke defaults Today; "Not yet" creates NO interaction (not a null-date row) — see Copywriting empty-state row (CAPT-02, ADR-016). |
| error | Save failure (all four flows) | ✅ covered | Renders "Couldn't save / Please try again.", preserves form state, never shows completion, exposes Retry where recoverable (CAPT-14, dossier §AE). |
| error | Future date/time entry | ✅ covered | Locked `FUTURE_DATE_MESSAGE` / `FUTURE_DATETIME_MESSAGE` in `danger` text; prior selection kept; backdating older dates allowed with no age warning (CAPT-07/W). |
| error | Validation reveals section | ✅ covered | A blocking error reveals + focuses the containing accordion; field-level actionable text (CAPT-14, dossier §AD). |
| overflow | Update Contact chooser with many custom fields | 🧪 backstop | Named custom fields surface directly; chooser may rank/search/group/collapse rather than an unbounded flat wall (dossier §Z). Exact threshold is tuning — held-out UI-state test that many-field chooser stays bounded and scrollable. |
| long-text | Long contact name / long note / long custom-field name | 🧪 backstop | Titles, chooser rows, and preview strips must truncate or wrap without breaking layout in all four palettes and at large OS text scale (dossier §AJ reflow). |
| zero-one-many | Update Contact repeated-update session | 🧪 backstop | After each inner Save, return to the chooser with the same contact targeted; a subtle recent-success indication, not a rigid checklist; Done exits (CAPT-12, dossier §AA). |
| loading | Preselected-contact resolution / DAO read | ⚠ unresolved | Preselection skips the picker when the invoking context identifies a contact (CAPT-13); the transient loading treatment while resolving the target is a planner assumption — no shipped pattern is mandated here. |
