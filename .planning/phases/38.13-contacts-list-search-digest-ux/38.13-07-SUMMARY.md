# Phase 38.13 Plan 07: Unbound search rows, plain search labels, honest search state and card width Summary

**Unbound people on the Contacts list now carry an "Unbound" chip, a neutral ring, a dimmed off star whose tap explains "Bind {name} to make them a Favorite." and a card menu without Snooze or Favorite, all through one HomeScreen star gate. Search rows use plain labels (Name, Phone, Email, Category), hide a snippet that repeats the name, announce only what they show, and render search mode only for the term their results belong to ("Searching…" while a newer term is read). Cards keep normal width on a short last row and show "Never Contacted" on one line.**

## Accomplishments

- **D-59 / ADR-233 (Task 1):**
  - `isUnboundRow` keys only on `trackingEnabled === 0`, never on search mode, so the Never Contacted opt-in's Unbound rows (`NOT_CONTACTED_INCLUSIVE_WHERE`) get the same treatment as Unbound search results (review R1-14).
  - `favouriteTapOutcome`: Bound → "toggle", Unbound → "explain", no row → "ignore" (review R2-04).
  - ListRow and GridCard take `unbound`. The chip uses `UNBOUND` from the glossary, testIDs `dashboard-list-row-unbound-{id}` / `dashboard-grid-card-unbound-{id}`. The description reads "Unbound" in place of the status label and "Not favorite".
  - The star draws off (Icon `default`, tone `textSecondary`) at opacity 0.5, with `accessibilityHint = unboundStarExplanation(name)`. A dormant favourite rank never draws it on.
  - CardGrid and the List renderItem pass `unbound={isUnboundRow(item)}`. CardContextMenu drops Snooze and Favorite when `unbound`.
  - HomeScreen: `rowsByIdRef` (a Map rebuilt by `useMemo` over the published rows), one `onFavouriteTap` with deps `[toggleFavourite]`. The List star, `CardGrid onToggleFavourite` and the card-menu star all call it. "explain" shows the notice pill (`kind: "success"`) and writes nothing.
  - `toggleFavourite` now calls `scheduler.request("favourite")` (what `reload` did) with deps `[favouriteStore, scheduler]`, so it and `onFavouriteTap` keep one identity across Population/Filters/Sort/search changes (review R5-01). `reload` and its deps are unchanged.
- **D-37 / D-51 (Task 2):**
  - `formatSearchExplanation(null)` = "Name"; an identity match reads its own `fieldLabel`; other kinds keep their section labels. The "Identity" label is gone (the label table no longer has an identity key).
  - `searchSnippetToShow` hides a snippet equal to the name (case and surrounding spaces ignored) or blank. The `?? 1` default count is gone.
  - `buildSearchRowAccessibilityDescription`: `Name. [Unbound.] explanation · "snippet".` Search mode has no category, recency, favourite or status parts. **The status glyph stays visible in search mode but is not in the search-mode description (D-51 built as written; not a regression).**
- **D-44 (Task 2):** both read outcomes carry `searchTerm` (the trimmed term the read was issued for). `publishDashboardRead` calls `setSearchTerm` right after `setRows` on ok, and beside `setError(true)` on error, so "Searching…" never sticks after a failure (review R1-15). HomeScreen keeps `publishedSearchTerm`. `const term = publishedSearchTerm` drives `isSearchMode`, the empty-state gate and the search EmptyState (`term={term}` pin intact). `searching = searchText.trim() !== publishedSearchTerm`, and while it is true the header shows "Searching…" in place of the count with the rows still visible (D-02). The fade half of D-44 is 38.13-08.
- **D-32 / D-33 (Task 3):** GridCard's root is `width: geometry.cardWidth, flexGrow: 0, flexShrink: 1, minWidth: 0` (was `flex: 1`); height still stretches across the row. `formatCardRecency(null)` = "Never Contacted"; the card description keeps "No interactions yet".

## Deferred / out of scope (for the orchestrator to bring to the owner)

1. **An Unbound card with no interactions reads "Unbound" (chip) and "Never Contacted" (recency) together (low).** This only happens in Card view for an Unbound person shown by the Never Contacted opt-in or a search. The description is correct ("No interactions yet", status "Unbound"), but the two visible words may read as conflicting. A possible alternative for Unbound cards is ADR-233's Unbound-list wording "No contact logged". That is a wording call, so I did not make it. Worth a look in the plan-11 device pass.
2. **"Searching…" shows only when the count header shows (low).** While the first load's skeleton or the error state is up, `headerCount` is null and there is no header, so "Searching…" does not appear either. Rows and the error copy behave as before.
3. **"Searching…" is not announced to TalkBack (low, informational).** It is a plain text change in the header, with no live region. Its text is read when focused.
4. **`DashboardRow.isAllContacts` still unused (informational, from 38.13-03).** This plan did not use it: the Unbound marker comes from `trackingEnabled` only.
5. **Device checks for plan 11:** the chip at the start of List line 2 and above the Card explanation (truncation on narrow cards), the dimmed star over the art, the Unbound notice pill, a lone last-row card's width, and "Searching…" while typing.
