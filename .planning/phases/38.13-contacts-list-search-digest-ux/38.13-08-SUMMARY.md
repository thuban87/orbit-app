# Phase 38.13 Plan 08: List-view memo + windowing, row swipe close, TalkBack actions, post-commit fade, hidden favourite deferral and the D-82/D-83 additions Summary

**The Contacts List now renders through a memoised swipeable row host fed only scalar props (line 3 as two strings, time as the read's local day) and id-taking callbacks whose identity never changes with the query, and the List FlatList is windowed with the 38.13-01 B5 values (5 / 8 / 5) as tunables at the top of HomeScreen.tsx. A swiped row closes once its action fires, List rows offer Quick Log / Log Interaction / Edit Contact TalkBack actions that each do what they are named for, the result fade's start is applied only after the new rows commit, and a favourite read is deferred while Home is hidden. Empty Birthdays / Never Contacted / Snoozed states offer "Show Active Contacts", Unbound cards with no interactions read "No contact logged", and the panels' dead `disabled` prop is gone.**

## Accomplishments

- **D-55 / D-81 F1 (Task 1, tracer):** `const SwipeableListRow = memo(function SwipeableListRow({…}))`. Its props are `contactId, name, photo, categoryLabel, lastContact, snoozeUntil, status, searchResult (search mode only), listDay, isFavourite, line3Text, line3IconName, unbound` plus `onOpenProfile, onFavouriteTap, onSwipeRightAction, onEditContact, onQuickLog, onLogInteraction, openRowRef`. The host rebuilds ListRow's `line3` object with `useMemo` over the two strings and passes `now={listDay}`. `renderListRow` is a `useCallback` over the maps, `isSearchMode`, `listDay` and the stable handlers; it builds no per-row closures. `listExtraData` (overlay, maps, search mode, day) is the FlatList's `extraData`. The favourite tap reaches 38.13-07's `onFavouriteTap` gate as `onFavouriteTap(contactId, !isFavourite)`.
- **D-55 / D-81 F2 (Task 1):** `LIST_WINDOW_SIZE = 5`, `LIST_INITIAL_NUM_TO_RENDER = 8`, `LIST_MAX_TO_RENDER_PER_BATCH = 5` near the top of HomeScreen.tsx, set on the List FlatList. No `getItemLayout`; `removeClippedSubviews` stays at its Android default. F3 and F4 are not built (D-81), so swipe, the swipe tint, the fade and view mode are unchanged.
- **D-25 (Task 2):** the host's `onSwipeableOpen` fires the right-swipe or Edit action, then calls `swipeableRef.current?.close()`. `openRowRef` is cleared by the existing `onClose` (ReanimatedSwipeable fires `onSwipeableClose` when the close spring finishes). The host still has no `useState`.
- **D-26 (Task 2):** ListRow gains `onQuickLog` and offers `quick-log` "Quick Log", `log-interaction` "Log Interaction", `edit-contact` "Edit Contact" (GridCard's pattern), each dispatching only to its own handler. HomeScreen's preference-routed function is now `onSwipeRightAction` and is used only for the right swipe. The TalkBack Quick Log runs `logQuickly`; Log Interaction runs `openLogInteraction` (`navigateDashboardContactAction(contactId, "LogContact")`).
- **D-44, fade half (Task 3):** the `setFadeStart` sink now sets `publishedFadeStart` state (same publish batch as the generation bump) and never writes `resultProgress`. The fade effect applies the start only when `resultGeneration > lastAppliedGenerationRef.current` (then records it), as `withSequence(withTiming(start, { duration: 0 }), toFullOpacity)`, or settles at 1 when it cannot animate. A focus, app-state or reduced-motion re-run with no new generation only animates or settles toward 1, as before (review R1-02).
- **D-52 (Task 3):** `"favourite"` is in `DEFERRABLE_WHILE_HIDDEN`. The scheduler's source doc, the `setFadeStart` sink doc and `toggleFavourite`'s comment now say a favourite read is deferred to the next focus read while Home is hidden or backgrounded, and that the Profile star (38.12) is a separate toggle outside this scheduler. `dashboardFadeStart("favourite", …)` is still 1.
- **D-82 (Task 4):** `SHOW_ACTIVE_CONTACTS_LABEL` = `Show ${AXIS_DEFAULT_LABELS.population}` ("Show Active Contacts") is the `actionLabel` of all three population copies. HomeScreen's `onShowActiveContacts` calls `setPopulations(getExecutor(), [])`, which is the same write the Population panel's Active row makes, so filters are kept. A failure shows "Couldn't show Active Contacts" with Retry, in the shape of the Clear filters action. Filter-empty still has only Clear filters.
- **D-83 (Task 4):** in GridCard, an Unbound card with `lastContact === null` uses `unboundRowSubtitle(null)` ("No contact logged") for both the visible line and the description. Bound cards keep "Never Contacted" on the card and "No interactions yet" in the description (D-33).
- **A3 (Task 4):** `disabled` is removed from PopulationPanelContent, FilterPanelContent and SortPanelContent, together with their `disabled={…}` and `accessibilityState` uses. A grep, tests included, found no caller passing it.
