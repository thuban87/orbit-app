# Phase 38.13 Plan 06: Overlooked from one predicate, retired rogue-only read, birthday avatars Summary

**The Digest's Overlooked section is now everyone who needs attention (nearing decay, decaying, rogue; snoozed and Unbound people excluded) minus the three Up Next shows. It comes from the one `NEEDS_ATTENTION_WHERE` predicate the Contacts drill also uses, and a real-SQLite test proves the section and its link open the same set. The rogue-only read and its unused Drifting/Gone-quiet split are gone, and Horizon birthday rows now show the contact's avatar.**

## Accomplishments

- **D-61, one predicate:** `readUpNextCandidates` now filters on `c.archived_at IS NULL AND ${NEEDS_ATTENTION_WHERE}`. The rows are the same as before, because the old inline predicate was the same condition. The Dashboard needs-attention filter reads the same constant (38.13-03).
- **D-61, Overlooked derived:** `readDigestData` makes four reads, not five. `DigestLoadedBody` computes `overlooked = dedupOverlooked(data.upNextCandidates, upNextIds)`. HorizonSection takes that list ready-made (`readonly UpNextCandidateRow[]`). Its own dedupe and the `upNextIds` prop are removed, so there is exactly one dedupe (Pitfall 10). PREVIEW_CAP 3, the empty rule and the "See everyone needing attention →" drill row are unchanged. `runDigestDrillThrough` is untouched (D-62).
- **Agreement test (T-38.13-16/17):** on the full migration chain, seeded with wobble, decay and rogue Bound people, a snoozed rogue, an Unbound person with a cadence and an old last contact, and a stable person. The ids from `listDashboardPopulation({ populations: [], filters: { "needs-attention": ["on"] } })` equal the `readUpNextCandidates` ids as sets. Up Next plus Overlooked covers that set with no overlap. The snoozed and Unbound people are in neither.
- **D-61/D-68, retirement:** deleted `readOverlooked` and `OverlookedRow` from `digest-read.ts`, and `splitOverlooked` and its `HasReason` input from `digest-logic.ts`, along with their test blocks. Both file headers no longer describe a rogue-only Overlooked. The store snoozed-rogue case and the indefinite-snooze "Digest Overlooked leaves it out" case now get Overlooked from `readUpNextCandidates`. The indefinite-snooze case seeds three more-overdue people to fill Up Next, so the trio really lands in Overlooked.
- **D-48:** `BirthdayCandidate` gains `photo` and `listBirthdayCandidates` selects it. There is no migration and no other query change; the Contacts consumer `resolveBirthdayWindow` reads only `id` and `birthday`. Horizon birthday rows render `Avatar` (size 40) inside the neutral ring, then the name and the date tag. The testID, the "{name}, {tag}" label and the press target are all kept.
