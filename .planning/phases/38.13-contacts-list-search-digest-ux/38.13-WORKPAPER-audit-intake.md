### 4.0 A-X01 / A-X02 List-view investigation (do first; owner R4)

**What is established [AUDIT/ART].** Data set: about 1,016 visible contacts. Debug and release builds of `05b85252`.
- Card view stays at about 344–411 MB PSS on release.
- Switching to List jumps to about 1.6 GB, and returning to card does not give the memory back.
- Five sort pairs in List climb 1,176 → 1,672 MB. `RUNNING_CRITICAL` trim does not reclaim it.
- On debug, native OOM crashed the app 4 times. The crash stack is `libworklets.so worklets::AsyncQueueUI::push` ← `WorkletRuntime::schedule` ← `scheduleOnUI` on `mqt_v_js` (`retest/R1-debug-crash-full-logcat.txt:3953-4006`).
- Release did not crash.
- Taps land 1.98 s late in fresh List view vs 0.20 s in card view (release, screenrecord).
- **Views count:** 23,982 in List after 5 sort pairs vs 1,401 in card (`retest/R1-rel-list-after5pairs-meminfo.txt:42`, `R1-rel-M9-full-meminfo.txt:42`; orchestrator verified). That is about 23.6 native views × 1,016 rows.
- Idle List memory is flat over 30 s, so growth is per event, not a render loop.
- Not established: the cause, release behaviour under longer use, and scaling with contact count (the 100-contact set was never measured) (NON-UX-FINDINGS).

**What is unique to List [CODE]:**
- **Per-row RNGH `ReanimatedSwipeable`.** `SwipeableListRow` is at `HomeScreen.tsx:326-411` (Swipeable at `:377-409`). Per row, RNGH 2.32.0 creates about 9 `useSharedValue`, 3 `useAnimatedRef`, 3 `useAnimatedStyle` and **2 `GestureDetector`s**. It renders both action panels on every render.
- **Orbit's per-row additions.** A `swipeTranslation` shared value (`:337`). `SwipeTranslationMirror` with `useAnimatedReaction`, always mounted inside `renderLeftActions` (`:310-324`, `:384-392`). Two `SwipeActionSurface` views. In see-through themes, `SwipeRowTint` `useAnimatedStyle` (`ListRow.tsx:70-93, 253-258`). Card view has none of this (`CardGrid.tsx:121-169`, `GridCard`).
- **Re-render fan-out.** `renderItem` is an inline arrow (`HomeScreen.tsx:1936-1968`). Neither `SwipeableListRow` nor `ListRow` is `React.memo` (orchestrator grep: no `memo(` in either file). Handlers are new closures per render.
- **Native calls per re-render.** RNGH `GestureDetector` runs `useEffect(..., [props])` with new props every render, so each HomeScreen render makes a native `updateGestureHandler` call for each detector on each mounted row.
- **FlatList props.** None of `windowSize`, `initialNumToRender`, `maxToRenderPerBatch`, `getItemLayout` or `extraData` is set (`:1933-1985`). The defaults are 10 / 10 / 21.
- **List-only line-3 read.** `readLine3Candidates` over all row ids runs only in List view outside search (`HomeScreen.tsx:870-897`; `dashboard-knowledge-read.ts:162-233`). On the audit DB it returns very little.
- **Shared with card, so not the List-specific cause.** `expo-image` avatars with file paths (`Avatar.tsx:81-93`). Ionicons glyphs. One unpaged read of every row (`dashboard-read.ts:380-411`). The theme scopes. The result fade (`HomeScreen.tsx:718-735`).
