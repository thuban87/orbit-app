## Deviations from Plan

1. **[Rule 3 - Blocker] Tap marker.** SELinux denies the shell write to `/dev/input` on the Pixel 6 Pro, so a real-touch `sendevent` dot was impossible. `tap_latency.py` instead injects a 100 ms press with `input touchscreen swipe x y x y 100` while Pointer location is on, and reads touch down and touch up from the Pointer location bar in the video (one time base). Latency is measured from touch up, when onPress fires. The audit measured from the `date` stamp, so its figures include roughly 50 ms of input dispatch. The prior Pointer location value is restored after each run. Commit 0edb92f4.
2. **[Orchestrator instruction] Two phones attached.** The Pixel 6 Pro and the Pixel 3a were both attached, so Task 1's automated check `adb devices | … | wc -l = 1` cannot pass (it prints 2). Both scripts resolve the phone by model and pass `-s <serial>` on every adb call. The 3a was never touched.
3. **[Comparability] The view was reset before measuring on the ~100 set.** The phone was on Active Contacts with the "Needs attention" filter (59 shown). It was reset to All Contacts with no filter (89 shown), matching how the audit counted its 1,016.
4. **[Method] Migrations ran on the release launch.** The phone's own debug APK (pulled to `apks/phone-debug-2026-10-18.apk`) was installed only so run-as could copy the three DB files. The baseline release was then installed with `install -r` and launched, and the migrations ran on that launch. This needed no Metro. The count was confirmed at 1,016.
5. **[Rule 2 - Added check] Scroll curve.** I added `--curve scroll` to `list_memory.py` so the windowing recommendation could be checked against mount and unmount churn while scrolling. Commit bf2540a6. I also amended that commit's message (my own, unpushed) so it matches its contents.
6. **[Harness] FINDINGS.md not written.** The subagent harness refused a `Write` of `untracked/artifacts/38.13/01/FINDINGS.md` ("Subagents should return findings as text"). I did not route around it. The full FINDINGS text is in the executor's handback to the orchestrator, and the key content is above. The Task 2 automated check `test -s …/FINDINGS.md` fails until the orchestrator saves that text there.
7. **Phone settings.** I turned on `stay_on_while_plugged_in` (`svc power stayon usb`) without reading its previous value, and set it back to 0, the Android default, at the end. `show_touches` was set to 1 for one trial and restored to 0. `pointer_location` was on during each M7 run and restored to unset (null).

**Total deviations:** 7 (1 blocker workaround, 1 added check, 5 method or process notes). **Impact:** every plan figure was measured. The only gap is the FINDINGS.md file itself (#6).
