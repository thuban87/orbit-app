# Phase 38.13 Plan 10: Bulk frequency through FrequencyPicker, sized bulk Set Category sheet, contact picker title and keyboard, Unbound List wording Summary

**Bulk Change Contact Frequency now opens a compact sheet with the Profile's FrequencyPicker. It starts on Monthly (30 days) and resets on every open. Continue is blocked while a Custom… entry is invalid, and the existing confirm still comes before any write. The bulk Set Category sheet opens at the size its list needs: compact up to 5 rows, detail up to 10, expanded beyond that. It does this through an opt-in `size` path on OptionSheet that no other caller uses. The contact picker's title names the action that opened it at all eight callers. The picker is lifted above the keyboard and capped to the room left, using the 38.9 sheet keyboard layout. Unbound List rows with no interactions read "No contact logged".**

## Accomplishments

- **D-39 (Task 1, tracer):**
  - New `BulkFrequencySheet`: a compact `Sheet` with an `AppText` heading "Change Contact Frequency" and a `FrequencyPicker` (`testID="bulk-frequency-picker"`).
  - The value state starts at `BULK_FREQUENCY_START_DAYS = FREQUENCY_DAYS.Monthly`. A primary `Button` "Continue" (`bulk-frequency-continue`, a11y "Confirm frequency") has `disabled={!valid}`, with `valid` coming from `onValidityChange`.
  - Each time the sheet opens (a render-phase visible false→true edge), the value and validity are reset and an open counter that keys the picker is bumped. This also clears the picker's own Custom… text and unit.
  - HomeScreen lost the raw days `TextInput`, `frequencyDraft`, `frequencyError`, its inline `Sheet`, and four styles, together with the now-unused `FieldError`, `Sheet` and typography imports. `onContinue` sets the existing `{ kind: "frequency" }` confirm with the held claim, and `onCancel` closes the sheet and releases the claim, as before.
- **D-71 / D-78 (Task 2):**
  - `option-sheet-logic.ts` has `OPTION_SHEET_COMPACT_MAX_ROWS = 5` and `OPTION_SHEET_DETAIL_MAX_ROWS = 10` at the top, plus `optionSheetVariantFor(count)`.
  - `OptionSheet` takes an optional `size?: "compact" | "detail"`. With no size, it renders the unchanged `<Sheet … variant="expanded">` block. With a size, it renders a second block, `<Sheet … variant={fitsCompact ? "compact" : "detail"} scrollBody={false}>`. That block is a shrinkable root, and its FlatList (`flexGrow: 0, flexShrink: 1`) is the only scroll.
  - Both blocks render one hoisted `renderOption` row.
  - `CategoryChoiceSheet` has `sizeToContent` (default false). It computes `optionSheetVariantFor(model.rows.length)` from its own unfiltered rows, Uncategorized included. It passes `size` for compact or detail and nothing for expanded.
  - HomeScreen's bulk Set Category passes only `sizeToContent`.
- **D-70 / D-43 (Task 3):**
  - `contact-picker-chrome.ts` provides `contactPickerTitle(title, isMultiSelect)` and `contactPickerKeyboardFrame(...)`.
    - The frame is built on `sheetKeyboardLayout({ variant: "expanded", … })`.
    - With the keyboard down, it returns `{ lift: 0, maxHeight: "82%", minHeight: 260 }`.
    - With the keyboard up, it returns the layout's lift and `maxHeight = min(layout size, 82% of the resting window)`. `minHeight` shrinks to that cap.
  - `ContactPicker`:
    - an optional `title` prop on the base props;
    - `keyboardDidShow` / `keyboardDidHide` listeners;
    - `onLayout` on the modal root, which records the tallest height as the resting height (the CaptureScreen pattern);
    - the lift applied as the root's `paddingBottom`, and the cap and floor applied to the sheet.
    - The safe-area top inset plus `SPACING.lg` is the top clearance, as in `Sheet`.
  - Callers:
    - UniversalFab: "Quick Log: choose contact" or "Log Interaction: choose contact". It keeps the title while the picker fades out.
    - LogInteractionScreen: "Log Interaction: choose contact".
    - GroupLogScreen: "Group Log: choose contacts".
    - EditGroupEventScreen and GroupEventDetailScreen: "Add participants: choose contacts".
    - AIPreviewScreen: "AI Preview: choose contact".
    - RelationshipEditor: "Key People: choose contact".
    - ProfileTemplateManager: "Profile Layout: choose contact".
- **D-84 (Task 4):** ListRow's recency is `unboundRowSubtitle(null)` ("No contact logged") when `unbound && lastContact === null`, which is the source GridCard's D-83 uses. Otherwise it is `formatListRecency`. The same value feeds the visible meta line and `buildRowAccessibilityDescription`. No props were added, so the memoised host's scalar-prop contract holds (`home-list-host-contract.test.ts` passes).
