# 23-08 — In-app Appearance settings (entry point)

## Why

Phase 23 built the theme engine but shipped **no in-app entry point** to change it
(the in-app switcher was deferred by an agent, not an owner decision). Without it the
theme system is not user-usable — every axis change needed a DAO write + relaunch.
Owner directive (2026-09-03): add the entry point NOW, wiring **only** the axes that
have a real in-app consumer today; do not wire anything with no consumer.

## Scope — consumer-gated (owner instruction)

**IN** (resolve through `ThemeProvider` app-wide today — live-preview verified in
`theme-provider.tsx:40-63`, which subscribes to package/mode/accent from the store):
- **Package** — Galaxy | Standard
- **Appearance mode** — Light | Dark | Follow System (per active package)
- **Accent** — the 8 curated accents + package Default (per active package)

**OUT** (no app-wide consumer yet — wiring would do nothing visible):
- Background picker — `BackgroundHost` is not mounted in any production screen
  (only the dev harness). Excluded.
- Glass surfaces / status-glyph adoption — no production consumers. Not touched.

## Design

A new **"Appearance"** section at the top of `SettingsScreen`, matching the existing
section/row pattern (`styles.section` / `styles.sectionHeading` / `styles.row`, all
theme-token styled, no colour literals — `check:colors` clean).

Each control does two things on change:
1. **Live preview** — call the `useThemeStore` setter (provider re-renders instantly).
2. **Persist** — call the screen's existing `persist()` helper → `updateAppSettings`
   (durable `app_settings` columns; validated; survives restart / restore).

Current selection reflected from `useThemeStore` (package, galaxyMode/standardMode,
galaxyAccent/standardAccent) + `useTheme().mode` for swatch fill.

Controls:
- **Package**: two selectable chips. On select → `setPackage(pkg)` + `persist({ themePackage: pkg })`.
- **Mode**: three chips. On select → `setModeForActivePackage(mode)` + `persist({ galaxyMode | standardMode })`.
- **Accent**: "Default" chip + 8 colour swatches (fill = `ACCENTS[id][mode].fill`). On
  select → `setAccentForActivePackage(id | null)` + `persist({ galaxyAccent | standardAccent })`.

## Tasks

1. **theme-store**: add `setAccentForActivePackage(accent: AccentId | null)` (writes the
   active package's accent field; mirrors `setModeForActivePackage`). Interface + impl.
2. **SettingsScreen**: add the Appearance section (package/mode/accent chips + swatches),
   reading selection from `useThemeStore`, wiring live setter + `persist()` per control.
   Reuse token styles; add minimal chip/swatch styles.
3. **Verify**: `npm run check:colors` (no literals), `tsc` clean, existing theme suites
   still pass. Device UAT on the Pixel 3a: change each axis → whole app restyles live →
   cold-start → selection restored (persistence).

## Non-goals / guardrails

- No migration (columns exist since 015). No AsyncStorage (D-08/D-09 — persist via DAO).
- No new colour literals; all through theme tokens.
- Does NOT reverse the deferred *screen-adoption* of glass/backgrounds/status-glyph —
  those still land in the rebuild phases; this only adds the settings entry point for
  the axes already live.
