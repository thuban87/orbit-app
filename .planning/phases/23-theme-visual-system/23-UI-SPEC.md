# Phase 23 — UI Design Contract

> Visual and interaction contract for Orbit's cross-app visual constitution. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase establishes REUSABLE VISUAL PRIMITIVES — a theme engine, semantic
> token system, icon registry, status glyphs, reduced-motion hook, and modal/button hierarchy.
> It does NOT redesign individual screens; later renderer phases (24–36) consume these contracts.
> Because the phase is broader than one screen, this spec adds phase-specific contract sections
> (Theme Architecture, Radii/Geometry, Surface & Glass, Motion, Icon Registry, Status Glyphs,
> Reduced Motion, Modal/Button Hierarchy, Orrery Exception, Persistence & Schema) beyond the base
> template. All values marked *(discretion)* are Claude's proposed concrete defaults per the dossier's
> Claude's-Discretion grant (fonts, token values, timings, backgrounds, accents) — owner may retune.

| Property | Value |

## Theme Architecture (phase-specific)

**Two independent axes yielding all four combinations (D-10, THEME-01):**

| Axis | Values | Notes |
|------|--------|-------|
| Theme package | `galaxy` \| `standard` | Galaxy = dramatic deep-space, glass-forward. Standard = soft-modern, flatter, quieter. Share layout/IA/density — only decorative treatment differs. |
| Appearance mode | `light` \| `dark` \| `system` | `system` tracks the OS scheme **live** via `useColorScheme()`. Ships from the start. |

- **First launch default: `galaxy` + `system`** (D-10).
- One semantic component API across both packages — no parallel Galaxy/Standard component families (dossier §B [DERIVED]).
- **Four palettes must be authored this phase**: Galaxy Dark, Galaxy Light, Standard Dark, Standard Light. The `light` palette that is optional today (`ThemePreset.light?`) becomes **required** — the `resolvePalette` dark-fallback stops being load-bearing once light palettes exist.
- **No wrong-theme flash (D-10, THEME-03):** theme-critical prefs (package, mode, per-package accent + background) must be read from `app_settings` and resolved **before the main UI renders**. The provider must gate first paint on that read (a short themed/neutral splash is acceptable; a flash of the wrong palette is not).
- **Live preview (THEME-03):** package/mode/accent/background changes restyle the whole tree immediately (the provider already re-renders from store state — extend to the new axes).
- **Per-package memory (D-11 / dossier §D, THEME-03):** switching packages restores that package's last-used mode, accent, and background.

## Spacing Scale

Declared values (multiples of 4). Principle (dossier §J): **compact within components, generous between conceptual groups.**

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, tight glyph offsets |
| sm | 8px | Compact element spacing within a component |
| md | 12px | Row inner padding, control gaps |
| base | 16px | Default element spacing |
| lg | 24px | Section padding, separation between conceptual groups |
| xl | 32px | Major layout gaps |
| 2xl | 48px | Major section breaks / presentation screens |

Exceptions:
- **Minimum touch target 44×44px** (Android a11y / dossier §Q) — a target-size floor, not a spacing token. Icon-only buttons pad up to 44 even when the glyph is 24.
- User-controlled density is **out of scope** — density is fixed "moderate" (dossier §J, deferred list).

## Radii & Geometry (phase-specific)

Orbit intentionally embraces a **very rounded** visual language (dossier §I — the orbit/planet/ring metaphor). Rounding must still preserve hierarchy — not everything looks identical.

| Token | Value | Usage |
|-------|-------|-------|
| radius.sm | 8px | Chips, inputs, small controls |
| radius.md | 12px | Buttons, list rows |
| radius.lg | 16px | Cards, sheets |
| radius.xl | 24px | Full-screen modal top corners, large containers |
| radius.pill | 999px | Pill buttons, filter chips, FAB label |
| radius.full | 9999px | Avatars, status rings, circular icon buttons |

**Cards (dossier §K):** cards are considered overused — do NOT wrap everything in a card. Use cards only for meaningful conceptual units; prefer flatter sections + dividers + headers otherwise. Exported constraint `[theme → Dashboard/Profile/Settings]`: do not restore pervasive card-boxing.

## Typography

Five semantic roles (dossier §H mandates display / heading / body / label / caption). Roles are font-family-remappable per theme without screen rewrites. Sizes respect system text scaling and **reflow before truncation or shrinking** (THEME-07). *(All values discretion.)*

| Role | Family | Size | Weight | Line Height |
|------|--------|------|--------|-------------|
| Display | Space Grotesk | 28px | SemiBold (600) | 1.2 |
| Heading | Space Grotesk | 20px | SemiBold (600) | 1.25 |
| Body | Inter | 16px | Regular (400) | 1.5 |
| Label | Inter | 14px | SemiBold (600) | 1.4 |
| Caption | Inter | 13px | Regular (400) | 1.4 |

**Weights: exactly two — Regular (400) and SemiBold (600).** No other weights ship this phase.

**Text scaling contract (THEME-07):** honor OS font scaling broadly; layouts reflow (wrap / grow height / stack) rather than truncate or shrink font size. Utility/forms may stay tighter; presentation screens may be more expressive (dossier §H — hierarchy is screen-dependent).

## Color

Orbit is dark-first today; this phase authors all four palettes. The 60/30/10 split below is stated on the **Galaxy Dark** reference palette (the shipped `space-dark` values) — the same role structure repeats across all four palettes with luminance/saturation retuned for contrast.

| Role | Value (Galaxy Dark ref) | Usage |
|------|-------------------------|-------|
| Dominant (60%) | `background #0B0E1A` | App background / behind-content surface |
| Secondary (30%) | `surface #141828`, `surfaceElevated #1D2235` | Sections, sheets, elevated containers |
| Accent (10%) | per-package accent (default Galaxy `#6C8CFF`) | See reserved list below |
| Destructive | `danger #E5484D` | Destructive actions only (never a status) |

**Accent reserved for** (dossier §C — controls + restrained decorative highlights, never "all interactive elements"):
active nav/tab state · the FAB · toggles / sliders / switches · selected/checked control state · text links · focus rings · small decorative highlights.
Accent is **separate from the owner/star color** (`starPalette`, already a distinct token — dossier §C, THEME-02).

| Name | Hex | Notes |

| Slate Indigo | `#5566B5` | **Standard default** (calmer) |
| Aurora Teal | `#3FB8B0` | |
| Plasma Violet | `#9B7BE0` | |

**Validation gate (dossier §C/§Q [DERIVED], THEME-11):** every curated accent must meet AA-equivalent contrast for its on-accent foreground and for accent-as-text-link in **all four** theme/mode combinations, or it is dropped from the palette. Each theme package ships a default accent (Galaxy → Nebula Blue, Standard → Slate Indigo).

### Status / semantic hues (THEME-08, dossier §L)

Stable semantic hue **families** across themes (recognizable Stable/Wobble/Decay/Rogue; luminance/saturation may vary per theme for contrast). Already tokenized: `statusStable #45B98A`, `statusWobble #E8C15C`, `statusDecay #E56A52`, `rogue #E0904A`, plus muted-morph endpoints and `rogueExtinguished`. **Color is never the only status cue** — every status also carries a distinct glyph (§ Status Glyphs) and border weight. Status hues are STATES, distinct from `danger` (an ACTION).

**Token rule (D-06, non-negotiable trip-wire):** every colour resolves through theme tokens **including inside Skia draw calls**. The icon registry and status glyphs must NOT hardcode colour. `theme-presets.ts` remains the single file where a hex literal may appear (`npm run check:colors` enforces this).

## Surface & Glass Treatment (phase-specific)

Semantic surface tokens carry treatment per package (dossier §F, THEME-05):

| Concept | Galaxy | Standard |
|---------|--------|----------|
| Surface identity | glass-forward: translucency, blur, luminous borders, subtle glow, layered depth | cleaner/flatter: opaque surfaces, softer shadows, plain borders |
| Dense content (forms/settings) | more opaque readable surfaces even within Galaxy | already opaque |
| Focused forms | themed background retained, content on mostly-opaque readable surface | same |

- **Surface opacity varies by content density (THEME-04):** presentation screens may show more background; dense forms use more opaque surfaces. **Readability wins.**
- **Blur degrades gracefully (dossier §F [DERIVED], `[theme → performance]`):** the semantic requirement is a glass-*like* surface, not mandatory expensive rendering. If `expo-blur` is added, it must fall back to a semi-opaque tinted surface token when the device/platform can't afford real blur. Blur is a decorative effect carrying no required meaning.
- Backgrounds stay **fixed while content scrolls** (THEME-04).

## Motion Tokens & Reduced Motion (phase-specific)

Semantic motion tokens *(timings discretion)*:

| Token | Value | Usage |
|-------|-------|-------|
| motion.fast | 120ms | Taps, toggles, chip selection |
| motion.base | 200ms | Panel/sheet open, crossfades |
| motion.slow | 320ms | Full-screen transitions, morphs |
| motion.ambient | very slow (e.g. 8–30s loops) | Galaxy ambient drift / twinkle only |
| easing.standard | `Easing.inOut(ease)` | Default |
| easing.decelerate | `Easing.out(ease)` | Enter |

**Reduced-motion hook (D-05, D-07, THEME-06) — first-class deliverable:**
- A reusable hook (e.g. `useReducedMotion()`) reads the OS reduced-motion preference (`AccessibilityInfo.isReduceMotionEnabled()` + `reduceMotionChanged` subscription) and exposes it app-wide.
- **Must be readable from the Skia render loop WITHOUT per-frame `setState` (D-07 trip-wire).** Expose the value as a Reanimated shared value (or equivalent worklet-readable primitive) so the render loop reads it without re-rendering the React tree each frame. **Animation is never driven from React state.**
- When reduced motion is ON: nonessential motion **stops or simplifies** — Galaxy ambient drift/twinkle halts, decorative transitions collapse to instant/crossfade, Orrery drift/inertia/twinkle stop while manual camera control remains. Essential feedback (e.g. focus, state change) may remain.

## Icon Registry (phase-specific — THEME-09, D-05)

**First-class deliverable.** No registry exists today; screens currently render raw emoji/text glyphs (`✕`, `◎`, `⚙`). This phase introduces the single semantic seam.

Contract:
- A centralized registry maps **semantic icon names** (e.g. `close`, `settings`, `favorite`, `search`, `back`, `add`, `message`, `call`, `edit`) → a base-family icon component. **Screens/business logic import semantic names only** — never a third-party icon name directly (dossier §M [DERIVED], exported constraint `[theme → icon usage]`).
- **State variants** supported: outline/filled, active/inactive, selected/unselected (dossier §M). Default state may be outline, active state filled (native to Ionicons pairs).
- Icons draw through theme tokens — **no hardcoded colour** (D-06). Size resolves through an `iconSize` token set (e.g. 16 / 20 / 24 / 28).
- Later custom Orbit icon family swaps in **at the registry mapping only** (deferred; do NOT build the custom family now — dossier §M [DEFERRED]). Never fork a second icon source (D-05).
- Existing raw-glyph usages should route through the registry where practical (planner's call on scope), but the registry existing and being the mandated path for new work is the deliverable.

## Status Glyphs (phase-specific — THEME-08, D-05)

**First-class deliverable.** Status today is colour + border weight only. This phase adds **distinct silhouette glyphs** — not recolored copies of one icon (dossier §L). Mix celestial metaphor with familiar severity cues. Every glyph resolves colour through tokens (D-06) and renders via the icon registry or a Skia-tokenized path.

| Status | Hue token | Glyph silhouette *(discretion)* | Border weight (redundant CVD channel, existing) |
|--------|-----------|--------------------------------|-------------------------------------------------|
| Stable | `statusStable` | steady planet with a calm full orbit ring | 2 |
| Wobble | `statusWobble` | planet on a tilted/off-center ring (caution) | 3 |
| Decay | `statusDecay` | waning/fading crescent with an alert notch ("act now") | 4 (thickest) |
| Rogue | `rogue` (ring) / `rogueExtinguished` (body) | comet / broken-orbit streak (off-trajectory) | 3 |
| Neutral (unevaluated) | `border` @ 0.5 opacity | faint hollow / dotted ring ("no status yet") | 2 |
| Snoozed | neutral | crescent moon (snooze), neutral border | — |

Consumers (dashboard List/Card, Profile, Orrery, widget) read one shared glyph + hue source — never a second status source. State must be readable **without colour** (glyph + text label + border weight are the redundant channels).

## Modal / Sheet & Button Hierarchy (phase-specific — THEME-10)

**Modal/sheet variants** (shared radius language, scrim, safe-area, spacing, typography, drag handles — dossier §O):

| Variant | Use |
|---------|-----|
| Compact sheet | short pickers / small option lists |
| Detail / half-height sheet | detail views, medium forms |
| Full-screen modal | full workflows / editors |
| Confirmation dialog | yes/no + destructive confirmations |

Scrim uses the existing idiom: `colors.background` at opacity (never a colour literal). Sheets use `radius.xl` top corners and a themed drag handle where relevant.

**Button hierarchy** (formal, dossier §P):

| Role | Treatment |
|------|-----------|
| Primary | filled accent, on-accent text (highest emphasis, one per surface) |
| Secondary | tonal/outline on surface, textPrimary |
| Tertiary / text | text-only, accent or textPrimary |
| Destructive | `danger` fill/border **plus** a non-color cue (warning glyph + explicit confirmation dialog) — distinct beyond colour (THEME-10, dossier §P) |
| Icon-only | 44px min target, semantic registry glyph, accessibilityLabel required |

## Orrery Visual Exception (phase-specific — THEME-12, dossier §R)

The Orrery follows the active theme **package** but is an intentional visual exception: it may use a specialized immersive visualization background (not the ordinary selected background), stronger glow, edge-to-edge rendering, more motion, fewer opaque surfaces, and custom control overlays — **while still resolving through shared tokens and honoring accessibility** (D-06, contrast, reduced motion). Exported constraint `[theme → Orrery]`.

## Persistence & Schema (phase-specific — THEME-13, D-08, D-09)

Theme prefs become **durable, backup-portable `app_settings` columns** — replacing the AsyncStorage `orbit-theme` key (which is not in the backup).

- **Columns** (final names are the plan's call): active theme package; and **per-package** appearance mode, accent, background (Galaxy + Standard each remember their own — dossier §D). Owner/star color stays its own separate setting (already `selfSunColour`).
- **Migration number:** verify **head+1** against `src/db/migrations/` and `TARGET_VERSION` in `src/db/database.ts` **on disk at plan time** — `TARGET_VERSION` was `14` on 2026-09-03 (latest `014-interaction-assists.ts`), so the new migration is expected to be `015`, **but the plan must re-verify, never assume** (numbers drift every schema phase). Forward-only, irreversible on unreachable devices.
- **Every new key added to `PORTABLE_SETTINGS_KEYS`** (`src/backup/backup-schema.ts`) so the Phase 36 backup format-v4 bump carries them (D-09).
- **Migrate the existing `orbit-theme` AsyncStorage value** into the new columns (read-once-then-clear vs. one-time import is the plan's call, D-08).
- Restore before first render (no wrong-theme flash — D-10).

This is a primitives phase — the Appearance settings surface and its copy are owned by **Phase 37 (Settings)**; onboarding first-run copy by **Phase 39**. Most CTA/empty/error strings are therefore N/A here. What this phase owns is behavioral/visual copy contracts:

| Element | Copy |
|---------|------|
