# Phase 32 — Interaction History & Insights — UI Design Contract

> Visual and interaction contract for the Contact Profile History section (Activity Heatmap, Intensity,
> Rolodex History Browser, shared period/date Detail Sheet, Interaction Detail, canonical Edit Interaction
> route, hard-delete confirmation, group-linked routing). Generated by gsd-ui-researcher, verified by
> gsd-ui-checker.
>
> **Platform reality — read first.** Orbit is a **local-first React Native / Expo Android app,
> portrait-locked**, NOT a web app. This is not a shadcn project. Every colour resolves through
> `src/theme/` tokens — there is **no hardcoded colour anywhere, including in Skia draw calls**
> (`npm run check:colors` enforces this). Two theme PACKAGES (`galaxy` / `standard`) × Light/Dark/
> Follow-System give four palette slots; a spec that names one hex is wrong. Below, "colour" means a
> **token key** on `ThemePalette`, resolved at render via `useTheme().colors[key]`.
>
> This contract REUSES the existing design system. It invents no new spacing/typography/radii/icon scale.
> The only genuinely new visual primitives are the **heatmap saturation ramp** and the **history marker
> treatments** (see "New Tokens Required"), both of which must be seeded per-palette in `theme-presets.ts`
> like every other seed token (`gravityTiers`, `avatarSwatches`, `starPalette`).

## Color

**Contract:** every value below is a **token KEY** on `ThemePalette` resolved through `useTheme().colors[key]`.
There is no 60/30/10 hex split to declare — Orbit's four palettes already encode that balance. What this
section fixes is **which token plays which role** in the History surfaces, and **what accent is reserved for**.

| Role | Token key | Usage |
|------|-----------|-------|
| Dominant surface (60%) | `background` | History section background; wheel backdrop |
| Secondary surface (30%) | `surface` / `surfaceElevated` | Context card, Detail Sheet, Interaction Detail card, wheel row plates, cells' resting plate |
| Accent (10%) | `accent` (fill) / `accentText` (link/on-bg) / `onAccent` (on fill) | see reserved list |
| Destructive | `danger` fill + `onDanger` foreground | Delete confirm control only |
| Body / secondary text | `textPrimary` / `textSecondary` | figures vs metadata |
| Structure | `border` / `borderStrong` | cell borders, current-cycle outline, wheel selection frame, dividers |

**Accent reserved for (explicit — never "all interactive elements"):**
1. Primary CTA fill: **Log interaction** and **Save changes** buttons (`accent` fill + `onAccent` label).
2. The **active** lens segment in the `SegmentedControl` (shipped filled-accent idiom).
3. The **heatmap saturation ramp** — the per-palette `heatmapScale` ramp is authored in the package's accent hue family (see New Tokens Required). This is the count encoding; it is the single accent use that carries data.
4. The **wheel's centered/selected date** emphasis and the selection frame's inner accent hairline.
5. **Links / tertiary actions** (`See details`, `View Group Event`) use `accentText`.
6. The **Allow-AI sparkle** indicator uses `accentText` tone at `icon-size sm`, restrained (nothing rendered when OFF).

**Never conveyed by colour alone (hard requirement, dossier §AA / §G / §R, CLAUDE.md):**
- **Current cycle** is distinguished **structurally** — a `borderStrong` outline / corner marker **plus** an accessible `Current cycle` label. NEVER a second hue (no blue-for-current). §G is explicit.
- **Heatmap count** is exposed on every cell as an accessibility label (`"{date/range}, {n} interactions"`); the saturation ramp is a supplementary visual encoding, not the sole channel.
- **History markers** distinguish record type by **silhouette**, not hue: interaction-bearing = **filled dot**; lifecycle-only = **outline/ring dot**; both/multiple = filled dot + numeric count. Counts/types are exposed to assistive tech regardless of marker.
- **Interaction vs lifecycle vs knowledge rows** in the Detail Sheet read by **semantic icon** (distinct silhouette) + text label, never colour alone.
- **Status/Intensity** hues (`statusStable/Wobble/Decay`, `rogue`) keep their existing meanings; **Intensity stays neutral** (`textPrimary` figure + `textSecondary` caption) and MUST NOT borrow a warning colour — more-than-intended contact is not "too much" (`IntensityLine.tsx` contract).

## New Tokens Required

These are the only new visual primitives. Seed them per-palette in `theme-presets.ts` (the sole colour-literal file), authored to pass the accessibility/contrast tests like `gravityTiers`/`starPalette`. Add to `ThemePalette` in `theme-types.ts`. Every consumer reads them via `useTheme().colors.*` — no literals in Views or Skia.

| Token | Type | Contract |
|-------|------|----------|
| `heatmapScale` | `readonly string[]` (length 5, ascending) | Ordered count-saturation ramp. Index 0 = empty/zero-count cell (a faint themed plate, distinct from `surface` "no-data"); indices 1..4 = rising interaction-count levels in the package accent-hue family. ORDER-STABLE. Indexed by a pure `heatmapLevel(count, lens)` bucket helper. Galaxy authors a luminous ramp; Standard a flatter neutral ramp (dossier §K / §P). |
| `heatmapCellEmpty` | `string` | The zero-count cell fill when it must read as "no activity" distinctly from an out-of-range/placeholder cell. May equal `heatmapScale[0]`; separate token so Month leading/trailing blanks (`surface`/transparent) never collide with a real zero-count day. |
| `markerInteraction` | `string` | Filled history-marker dot (interaction-bearing dates). |
| `markerLifecycle` | `string` | Outline/ring history-marker (lifecycle-only dates). Distinct silhouette AND token, but silhouette is the primary cue. |

**Threshold buckets (implementation tuning — dossier §K "example direction", tune on the Pixel):**
- Day-oriented lenses (7 Days / Month / Year): `0 / 1 / 2 / 3+` → levels 0,1,2,3 (caps at `heatmapScale[3]`).
- Cycle lens: `0 / 1 / 2 / 3 / 4+` → levels 0..4 (uses full ramp).

One ramp, two threshold tables. Exact counts are Claude's Discretion per D-32 CONTEXT; keep them in a single tunable constant object at the top of the bucket helper.

## Surface Contracts

Each surface's visual + interaction contract. All reached from the Profile History section (replacing the old vertical timeline, `TimelineRow`/`timeline-read`).

### 1. Activity Heatmap
- **Render:** plain RN `View` cells (static, count-only) styled from `heatmapScale` — **no Skia render loop, no animation** (dossier §D, RESEARCH A5). This sidesteps the worklet-forward-ref hazard entirely.
- **Lenses** via `SegmentedControl`: `Cycles` (default) · `7 Days` · `Month` · `Year`. Last lens + cycle-count preset persist globally in `app_settings` (`history_lens`, `history_cycle_count`), not per-contact, not AsyncStorage.
- **Cycles:** one block per current-frequency cycle; presets 5/10/15/20 (default 10) → 5-column arrangements (5×1/5×2/5×3/5×4); newest/current bottom-right; read left-to-right, top-to-bottom. Current in-progress cycle: `borderStrong` structural outline/corner marker + `Current cycle` a11y label — never a second hue.
- **7 Days:** rolling last 7 days, today rightmost. **Month:** true weekday alignment; leading/trailing non-month positions render as blank placeholders (use `heatmapCellEmpty`/transparent, NOT a real zero-count fill). **Year:** GitHub-style dense daily grid (weeks as columns, weekdays as rows), month labels.
- **Navigation:** prev/next window controls; future dates blocked (today is max).
- **Tap:** opens the small context card FIRST (never the big sheet directly).
- **A11y:** every cell exposes date/range + count; usable without colour.

### 2. Intensity
- Extends `IntensityLine` or a new `IntensityChart`; larger bar/time-series than the compact Profile Relationship Overview tile.
- Reads the **same shared window** as the Heatmap (change lens/period → Intensity re-renders same window). No prediction/forecasting.
- **Neutral colour contract:** `textPrimary` figure, `textSecondary` caption; never a warning hue. Consumes `computeContactIntensity` — guards nullable cadence (returns unavailable for no-cadence contacts; do not divide by null).

### 3. Rolodex History Browser
- Three synchronized wheels: **Month / Day / Year**; Day is primary axis; scrolling Day rolls Month/Year at boundaries; Month/Year independently adjustable; invalid dates clamp (Aug 31 → Feb → 28/29); future dates not browsable (today = max).
- **Animation:** Reanimated + `react-native-gesture-handler` only. Galaxy MAY add restrained Skia glow/depth; Standard is a flatter neutral roller; **identical mechanics across themes**. ~2–3 neighbor rows above/below fade/scale with distance; selected row strongest.
- **Worklet-forward-ref hazard (MEMORY, fix f979263):** define helper worklets ABOVE their callers — Hermes undefined-on-device crash vitest cannot catch. UAT on the physical Pixel.
- **Markers:** eventful dates marked before selection — filled dot (interaction) vs ring (lifecycle-only) vs filled+count (multiple); silhouette-primary; counts/types exposed to a11y; no channel/quality in the marker.
- **Drawer** beneath the wheels summarizes the selected date (interaction + event counts incl. lifecycle); `See details` / `Log interaction`. **Scrolling/selecting NEVER auto-opens the detail sheet.**
- **Reduced Motion** (`useReducedMotionShared`): simplifies wheel depth/inertia/decorative transitions WITHOUT removing date navigation. Wheel columns support non-gesture adjustment (a11y).

### 4. Cell/date context card
- Small anchored card (not a sheet). Populated: date/range + count + `See details`. Empty: date + `0 interactions` + `Log interaction`. **Interaction-count-only** — lifecycle events are never mentioned here (D-10). This card alone opens the shared Detail Sheet (via `See details`).

### 5. Shared period/date Detail Sheet (`Sheet` variant `detail`)
- One canonical sheet reused by Heatmap and Browser. Interleaves three record families **chronologically** with **semantic icons** (not separate sections):
  - **Interactions** — editable/deletable; row shows channel/type icon, time, direction (where relevant), Tone (where present), duration (where present), one-line note preview. Tap → Interaction Detail.
  - **System lifecycle events** — read-only/inspectable (Archive/Restore/Snooze/Unsnooze + new **Bind/Unbind**); concise state-change summary. Add `bind`/`unbind` labels to `TimelineRow` `EVENT_LABELS`.
  - **History-aware knowledge changes** — editable per their owning Knowledge model (not forced into the immutable lifecycle model); tap → that model's detail/edit flow.
- May expose `Log interaction` for backfill; **no multi-select / batch edit / batch delete** (Phase 32 boundary).
- Group-linked children appear as **ordinary interaction rows once**; the Group Event parent is never a second row; optional compact `Group event` badge where space allows.

### 6. Interaction Detail (`Sheet` variant `detail` or `compact`)
- Compact, complete inspection — **no blank fields** (omit absent ones): channel/type, date/time, direction, connected state, Tone, optional duration, note/context.
- **Allow-AI sparkle:** restrained `sparkle` semantic icon in `accentText`, `icon-size sm`, shown ONLY when that interaction's `allow_ai` is ON; **nothing rendered when OFF** (D-04). Default is OFF.
- Exposes `Edit` and `Delete`. For group-linked children: restrained `Group event` badge, Group Event title, shared Group Note (distinct field, never concatenated into the participant note), participant note separately, and `View Group Event`. Standalone overflow may expose the conversion seam.

### 7. Canonical Edit Interaction route (`src/screens/EditInteractionScreen.tsx`, new)
- Focused route (headerShown:false convention; own Back chrome; canonical unsaved-change behavior). Wraps the existing `TouchpointRefineForm` value shape + `editTouchpointFull` (the sole recency writer — never a set-based `UPDATE interactions`).
- Edits all editable fields: date/time, channel/type, direction, connected, **Tone**, note, optional **duration** (presets 5m/15m/30m/1h/2h/Custom; entry in min/hr, stored nullable seconds), and **Allow AI** toggle.
- **Rejects future dates** (`rejectFutureOccurredAt`), saves through the single-writer spine, refreshes derived consumers (heatmap buckets, Intensity, Last Interaction, Status, Gravity) automatically.
- Primary action is a `Save changes` Primary button (`accent`/`onAccent`).

### 8. Hard-delete confirmation
- `ConfirmDialog` destructive variant: `danger` fill + `warning` glyph + `onDanger` label + no scrim-dismiss (explicit choice required). Copy per the Copywriting Contract. Names the derived-metric consequences. NO trash/quarantine subsystem (D-11). Deleting a group-linked child removes only that participant's interaction (routes through `deleteTouchpoint`).

### Group-linked routing (cross-cutting, D-05/D-10)
- Editing a group-linked interaction first presents the **scope prompt** (`Edit individual interaction` / `Edit Group Event`) — no hybrid editor. Individual routes to the participant override editor (participant-overridable fields only: Channel, Tone, Duration, Direction, Connected, participant note, **Allow AI**); group routes to the Phase 33 Edit Group Event flow. Group-linked timestamps are event-owned (no participant-level timestamp editor here). Group Event parents never increment heatmap counts / Intensity / Last Interaction / Status / Gravity, and never double-count.

## Motion & Animation Contract (RN reality)

- Static surfaces (Heatmap, Intensity, context card, Detail Sheet, Interaction Detail) use **no render loop** — plain RN Views / Reanimated layout transitions at most.
- The **only** genuinely animated surface is the Rolodex wheel (Reanimated + Gesture Handler; optional Galaxy Skia glow).
- **Never drive animation from React `setState` per frame** (CLAUDE.md / HANDOFF §7) — write Reanimated shared `.value` instead.
- **Pause all animation** on `useIsFocused === false` and `AppState` background (conditionally mount the Skia `<Canvas>` only when measured AND focused/foregrounded, per the Orrery pattern).
- Reduced Motion via `useReducedMotionShared()` (worklet) — simplify wheel depth/inertia, never remove navigation.
- Durations from `MOTION` tokens (`fast 120` / `base 200` / `slow 320` ms); ambient rate from `MOTION.ambient` (rad/s) if a Galaxy glow drifts.

## Accessibility Contract (hard requirement — HIST-18, dossier §AA)

History must be **fully usable without colour, wheel gestures, or marker iconography.**

| Requirement | Contract |
|-------------|----------|
| Heatmap without colour | Every cell exposes `{date/range}, {n} interactions`; saturation is supplementary |
| Current cycle | Textual `Current cycle` semantics + structural outline (not a hue) |
| Wheels without gesture | Month/Day/Year expose selected value and support non-gesture adjustment |
| Markers without icon reading | Expose actual record counts/types to assistive tech |
| Non-wheel path | Drawer provides a conventional action path to details/logging |
| Detail rows without icon reading | Expose semantic type, date/time, metadata textually |
| Reduced Motion | Simplifies wheel depth/inertia; navigation intact |
| Functional contrast | All functional text/controls meet AA-equivalent in every package × mode (the four palettes already prove this; new `heatmapScale`/marker tokens must be authored to pass the palette contrast tests) |
| Touch targets | 44px floor on all controls; dense heatmap cells are a11y-labelled to compensate for sub-44px visuals |
