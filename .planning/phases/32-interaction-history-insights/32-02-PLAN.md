<objective>
Two backup/restore integrity workstreams on the shared events/interactions tables: (1) add the two missing lifecycle event types — `bind` and `unbind` — as immutable, insert-only events produced inside the existing bind/unbind write transactions, so the shared Detail Sheet (Plan 07) can render a complete lifecycle history (Archive/Restore/Snooze/Unsnooze/Bind/Unbind) per HIST-10; and (2) close the D-06 restore backdoor — remap legacy interaction quality/channel values on restore-apply ingest so a pre-Phase-32 backup restored onto a v25 device does not silently miscount AI-context/digest.

Purpose: Today `bindContact`/`unbindContact` change `tracking_enabled` but write NO event, so the relationship's bind/unbind moments are invisible in history. Separately, migration 025 rewrites on-device rows only at schema-upgrade time; the restore-apply writer of `interactions` is a SEPARATE writer that today inserts backed-up quality/channel verbatim — a legacy backup would reintroduce good/fine/hard onto a migrated device and re-open Pitfall 1 via the backdoor. Both are backup/restore integrity for the migrated schema; consolidating them here keeps restore-apply single-owned (no same-wave overlap with Plan 01).
Output: extended EventType union, in-transaction bind/unbind producers, a restore round-trip proof, and the restore-side vocabulary remap consuming Plan 01's shared map.
</objective>
