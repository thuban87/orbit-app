## Phase Goal

**As a** person tending my relationships, **I want to** keep several links per contact and tap to open them, **so that** their LinkedIn, Instagram, and personal site are one tap away.

**This slice (Plan 07):** the contact_links CRUD DAO + the links editor, integrated into the edit form. After this plan a user adds/edits/removes several links on a contact and taps one to open it.

<objective>
Build the `contact_links` child-table CRUD DAO and the repeatable LinksEditor, and wire links into the edit form's assembly + UI. The table already exists (migration 1) — this is DAO + UI only.

Purpose: CRUD-04 (many links, add/edit/remove, optional label, ordered, tappable). Per CONTEXT Area 2: optional label, no autocomplete (deferred), open as web URL via `Linking` try/catch, insertion order via `display_order` (no drag UI — deferred).

**Review updates (reviews-mode):** two findings land here. (1) The link-open scheme check becomes a POSITIVE allowlist `/^https?:\/\//i` (not a `://`-substring test), so `file://`, `intent://…`, and `javascript://…` are stripped-and-reprefixed to https rather than handed to the OS as typed. (2) Link persistence uses ONE model — editor DRAFT state + a seeded-vs-current diff applied on "Save changes" via a single `applyLinkDiff` transaction — so links share the edit form's all-or-nothing-on-cancel semantics (commit a38c763) instead of the ambiguous "on save OR immediately per row" the prior plan left open.
Output: `contact-links-dao.ts` (wrappers + cores + applyLinkDiff), `LinksEditor.tsx`, links integrated into `getContactForEdit` + `EditContactScreen`.
</objective>

| T-04-02 | Tampering (SQL injection) | contact-links-dao | high | mitigate | Every value `?`-bound; no interpolated identifier; mutations both-key scoped with assertOneChange |
| T-04-09 | Elevation (malicious scheme) | link open | medium | mitigate | POSITIVE allowlist `/^https?:\/\//i` — only http/https open as typed; any other scheme (`file://`, `intent://…`, `javascript://…`) is stripped and re-prefixed `https://`, so a `://`-bearing hostile scheme is NOT handed to `Linking.openURL` as typed (the earlier `://`-substring test would have passed them through). `Linking.openURL` in try/catch; no `canOpenURL` probe. | T-04-03 | Tampering (mis-scoped mutation / partial link save) | update/remove link + applyLinkDiff | medium | mitigate | Each mutation scoped by (id, contact_id) + assertOneChange; `applyLinkDiff` runs the whole diff in ONE transaction so a mid-diff failure rolls back all link changes (no partial link state). Metadata + links are two transactions by design; partial-save handling keeps the user on the form with the draft intact when the links half fails. |
