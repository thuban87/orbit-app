<objective>
Owner-gated on-device verification: the one thing that cannot be proven node-side — that the
WEEKLY trigger fires correctly and survives reboot on the physical Pixel — plus the screen's
render/interaction UAT.

## Phase Goal (user story)
**As a** person tending my relationships, **I want to** actually receive the Sunday
notification and land on a correct "your week" screen on my phone, **so that** the feature
works in the real app, not just in tests.

Purpose: DGST-01's weekly-fire + reboot persistence is device-only (RESEARCH Pitfall 2 /
Assumptions A6/A7 — the emulator cannot validate timing per CLAUDE.md, and pre-57 repeat
bugs #34782/#30577 exist). This plan is a dedicated checkpoint (no code) per the
"checkpoints get their own plan" rule.

Node gates (full `npm test`, `tsc --noEmit`, `check:colors`, biome) are re-run by the
orchestrator before this checkpoint; this plan verifies only what a device can.

## Rig (project memory + CLAUDE.md)
- Build the RELEASE APK on `droid` (desktop) via the desktop-build-pipeline runbook; transport
  by rsync/scp (NEVER git push). Release is the clean verification path (debug+Metro has an
  intermittent expo-sqlite flake).
- `emu-connect device` (physical Pixel; auto-falls back only if absent). Resolve the serial
  from `adb devices` — never hardcode. Metro on orbit's port if a debug channel is needed.
- Drive with `uiautomator dump` for exact bounds + the locked testIDs (adb tap can
  false-negative small RN Pressables — verify against code first).
</objective>
