workflow. Add ONE new edit path to the single-writer DAO (`editTouchpointFull`) that updates every
editable column and ALWAYS recomputes recency (idempotent MAX → one path, no forgotten recompute),
build the refine form with Android's unavoidable two-dialog date+time entry, and wire refine/edit
plus a confirmed, unrecoverable delete onto the timeline.

unrecoverable), LOG-04 (the connected axis is written here), LOG-06 (future reject on edit).

Output: `editTouchpointFull` + tests; `touchpoint-refine-logic.ts` (pure date+time chaining) + test;
`TouchpointRefineForm.tsx`; edit/delete affordances on `TimelineRow` + wiring on the profile.

CRITICAL — do NOT add a second edit path or a second last_contact writer. `editTouchpointFull` is a
composition inside ONE `inWriteTransaction`, calling `recomputeLastContactCore` (never nesting the
non-reentrant mutex). The redundant Phase-2 `editTouchpoint` (occurred_at + connected only, with NO
future-date guard) is REMOVED — it has no production caller on disk (verified: only its own
definition, the recency-dao.ts:343 doc-comment, and `recency-dao.test.ts` reference it; the refine UI
routes exclusively through `editTouchpointFull`), so the guarded full path becomes the ONE
interaction-edit path. (Review #1 resolution.)

FLAGGED (Review #1 resolution — surface to owner at the pre-execution pause, do NOT block):

or invert a recorded decision. If the owner would rather keep the narrow path, the fallback is to add
`rejectFutureOccurredAt(input.occurredAt, input.now)` as a pre-transaction reject to `editTouchpoint`
