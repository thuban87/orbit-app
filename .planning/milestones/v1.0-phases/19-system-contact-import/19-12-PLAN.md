  <action>
    In the `pickContacts` AsyncFunction, the code assigns `pendingPickPromise = promise` and then
    calls `appContext.throwingActivity.startActivityForResult(intent, PICK_CONTACTS_CODE)` with no
    guard (lines 82–83). If that launch throws synchronously (no resolving activity, activity lost),
    `pendingPickPromise` stays non-null forever, so every later call rejects with
    `ContactPickInProgressException` and the picker is permanently "busy". Wrap the
    `startActivityForResult` call in a try/catch: on a thrown exception, clear `pendingPickPromise`
    back to null and reject the `promise` with a coded exception (reuse `CodedException`/the module's
    exception style; do not surface a raw provider path or stack into JS — consistent with the
    module's existing OnActivityResult catch that resolves empty rather than leaking details). Keep
    the pending-promise assignment BEFORE the launch (so a real activity result still finds it), but
    ensure the catch path fully resets the pending state. Leave the existing SDK gate, the
    already-in-progress guard, and the intent construction unchanged.
