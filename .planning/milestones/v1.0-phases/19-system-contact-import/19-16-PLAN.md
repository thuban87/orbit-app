<objective>
Close GAP C.2 (IMP-04, part of failed verifier truth 4; the PII-retention gap): after a successful
master-photo import, `import-photo.ts` never clears the session `photo_rel_path` or deletes the raw
staging source, and `contact-import-resume-sweep.ts` `reconcileOrphanStagedPhotos` then treats
every non-discarded row with a `photo_rel_path` as live — including completed successful imports —
so raw staged contact photos persist indefinitely as duplicate on-device PII.

Fix (three parts, one subsystem — the import photo lifecycle):
1. Add a durable DAO writer that retires a row's staging reference (`photo_rel_path → NULL`).
2. On successful master persistence, retire the reference and delete the raw staged file;
   preserve the staged input ONLY on a retryable failure.
3. Make the launch resume-sweep's notion of "live" staging status-aware — only unresolved/retryable
   rows (pending, needs_review, failed) retain staging; imported/linked/skipped rows do not.

Purpose: Honor the local-first / minimal-PII posture — a raw system-contact photo copied into
staging must not outlive the import that consumed it. This CLOSES a privacy gap; it does not weaken
any recorded decision (photo failures still never invalidate a contact; retryable inputs are still
kept for Retry).
Output: A staging-retirement DAO writer, retirement wired into the shared post-commit photo seam
(all three callers), a status-aware resume-sweep, and node tests for retire, retryable-preservation,
and sweep liveness.

**Wave-2 dependency:** this plan edits `source-consolidation.ts` (add the row id to its photo call),
which plan 19-15 also modifies — hence `depends_on: [19-15]`.
</objective>
