# Phase 12 — UI Design Contract

> Visual and interaction contract for the Android home-screen widget (WDG-01/02/03) and the
> `ContactCard` status-ring upgrade. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is NOT a React Native screen.** The widget renders as native `RemoteViews` via
> `react-native-android-widget`: the component tree is rasterised **off-screen to a single PNG on
> disk** and displayed with transparent tap-rectangles overlaid (dossier Findings). Every contract
> below is expressible in RemoteViews-feasible primitives — `FlexWidget` layout, `ImageWidget`
> (base64 `data:` avatars, `radius` for rounding), `TextWidget`, and reserved/non-reserved
> `clickAction`. There is **no arbitrary CSS, no live view, no text input, and no real long-press**
> (a tap is one click). Nothing here specifies anything RemoteViews cannot render.

## ⭐ Status Colour Palette — OWNER-APPROVED (2026-08-16)

> **THIS SECTION WAS THE PHASE'S PRIMARY OWNER DECISION, now RESOLVED.** The owner reviewed a rendered
> swatch and **approved all four hexes exactly as proposed** on 2026-08-16 (`stable #45B98A`,
> `wobble #E8C15C`, `decay #E56A52`, `rogue #E0904A` unchanged). The `#F07A3D` decay alternative was
> considered and declined. These are now the locked, shared app-wide status tokens.

**What this locks:** `stable` / `wobble` / `decay` become **shared app-wide theme tokens this phase**,
joining the existing `rogue` token in `ThemePalette` (`src/theme/theme-types.ts`) and seeded in every
preset (only `space-dark` ships today — `src/theme/theme-presets.ts`). The widget bitmap **and** the
dashboard `ContactCard` both consume them; Phase 13 (orrery) inherits the same four — one source of
truth. This **retires** `ContactCard`'s opacity-only placeholder (OD-1) and satisfies WDG-01's "each
avatar carrying its status colour."

**Proposed token names** (three net-new flat tokens, mirroring how `rogue`/`danger`/`accent` are flat
tokens — not an array):

| Status | Proposed token | Proposed hex | Meaning (from `status.ts` buckets) |
|--------|----------------|--------------|-------------------------------------|
| stable | `colors.statusStable` | **`#45B98A`** | `< 80%` of interval elapsed — healthy, in orbit |
| wobble | `colors.statusWobble` | **`#E8C15C`** | `80–100%` — approaching due, caution |
| decay  | `colors.statusDecay`  | **`#E56A52`** | `> 100%` — overdue, the "act now" state |
| rogue  | `colors.rogue` (EXISTING, unchanged) | `#E0904A` | escaped orbit / "Rarely responds" — faded, drifted out |

### Rationale (per colour)

- **`statusStable` = `#45B98A` (teal-green).** Reads unambiguously as "good / healthy orbit." Hue
  ~156° sits far from `accent` (`#6C8CFF`, ~226°), so a stable ring never reads as a UI-chrome accent.
  Teal-leaning (not a pure 120° green) on purpose: it keeps a blue component that survives red-green
  colour-blindness better than a pure green. Brighter/more saturated than the muted `gravityTiers`
  green (`#5B9E8A`) so *status* pops louder than *gravity*. Contrast on `background` `#0B0E1A` ≈ **7.7:1**.
- **`statusWobble` = `#E8C15C` (gold).** The classic "caution / approaching" yellow-gold. Clearly
  *yellow*, not orange, which is what separates it from `rogue`'s amber. Lightest of the four (draws a
  soft "keep an eye on this" glance without alarm). Contrast on background ≈ **10.9:1**.
- **`statusDecay` = `#E56A52` (coral red-orange).** The hottest, most attention-grabbing ring — this is
  the core-loop's target state ("collapse the taps between overdue and message sent"). Deliberately
  **orange-shifted** off the `danger` token (`#E5484D`) so a decay *status* is not confused with a
  destructive *action* (the two rarely co-locate, and CLAUDE.md keeps status ≠ action). Contrast on
  background ≈ **5.2:1**.
- **`rogue` = `#E0904A` (UNCHANGED).** Already owner-approved (2026-08-15). In the orbital metaphor a
  rogue contact has *escaped* orbit — cold, drifted, no longer in the normal loop (ORR-04 renders it as
  a cold/extinguished body + faint ring). So the heat peaks at **decay** (red-orange, actionable) and
  *fades* to amber at rogue, rather than climbing to red — an intentional break from a naive green→red
  ramp. Amber stays distinct from `accent` blue and `danger` red.

### Distinguishability & colour-blind safety

- Hue ladder: stable ~156° · wobble ~43° · rogue ~28° · decay ~10°. The three warm states share the
  40°-wide warm band, but (a) a contact is in **exactly one** state at a time, (b) lightness varies
  (wobble lightest → decay/rogue mid), and (c) **status is never conveyed by colour alone** — see the
  redundant non-colour channel below. All four clear WCAG 3:1 for non-text UI on `#0B0E1A`.
- **Redundant, non-colour encoding is mandatory** (accessibility + CVD): the ring's **border weight
  escalates** with overdue-ness (stable thinnest → decay thickest), and on the `ContactCard` the
  existing `accessibilityLabel` (`"Stable"` / `"Wobbling"` / `"Decaying"` / `"Rogue"` / `"Not yet
  contacted"`) is retained so uiautomator UAT asserts the band without colour inspection. The widget
  bitmap carries the border-weight channel and the always-present name label; the rich rogue treatment
  (cold body, faint ring) is Phase 13's job, not the widget's.

### One alternative considered

A truer red decay (`#E5504D`) for maximum "urgent" punch — **rejected** for near-collision with the
`danger` token (`#E5484D`); chose the orange-shifted coral to keep status and destructive-action reds
separable. (If the owner wants more separation from `danger`, a clearly-orange decay `#F07A3D` is the
fallback.)

## Spacing Scale

Declared values (all multiples of 4). Applies to widget tile layout and the `ContactCard`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Ring-to-avatar gap, glyph-to-label gap |
| sm | 8px | Compact intra-tile spacing, button padding |
| md | 12px | Tile inner padding, avatar↔text gap (matches existing `ContactCard` gap/padding=12) |
| lg | 16px | Grid cell gutter, section spacing |
| xl | 24px | Empty-state vertical rhythm |

Exceptions: **Minimum tap target 48dp** for every widget tap rectangle (whole-tile mark region,
name+chevron profile region, each action button) and the Settings "Add widget" button — Android
touch-target floor. This governs the *tap rectangle*, not the visible glyph size.

## Typography

RemoteViews text is `sp`; the app card is `px`. Two weights only: regular (400) + semibold (600),
matching the existing `ContactCard` (name 400 / snippet 600).

| Role | Size | Weight | Context |
|------|------|--------|---------|
| Tile name label | 13sp | 600 | Widget contact name (1 line, ellipsised tail) |
| Tile fuel line | 11sp | 400 | Larger-tile ranked fuel preview (1 line, ellipsised) |
| Action button label | 11sp | 600 | Quick mark / Log contact / Message |
| Empty-state heading | 15sp | 600 | "Choose favourites" |
| Empty-state body | 12sp | 400 | Prompt subtext |
| Card name (existing) | 15px | 400 | `ContactCard` — unchanged |

Line height: single-line labels throughout (widget tiles do not wrap); empty-state body 1.4.

## Color

The widget and card inherit the `space-dark` palette (dark-first). 60/30/10 split:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0B0E1A` (`background`) | Widget tile field behind the grid; card list background |
| Secondary (30%) | `#141828` (`surface`) / `#1D2235` (`surfaceElevated`) | Tile/card surface; the faint pill behind the name+chevron profile region |
| Accent (10%) | `#6C8CFF` (`accent`) | See reserved list below |
| Destructive | `#E5484D` (`danger`) | Not used on the widget or by the status ring — status ≠ destructive action |

Accent (`#6C8CFF`) reserved for: the **open-profile chevron glyph** (`›`), the empty-state star glyph,
and the favourite marker on the `ContactCard` (existing OD-2 `★`). **Not** for status (status uses the
palette above), **not** for generic button fills. Status colours are a semantic set, counted outside
the 60/30/10 chrome budget (they colour the ring only, a small fraction of pixels).

Every colour — including inside the rasterised bitmap — resolves through a theme token. No hex literal
anywhere except `theme-presets.ts` (CLAUDE.md / `check:colors`).

| Element | Copy |
|---------|------|
| Primary CTA (Settings) | **"Add Orbit widget"** |
| Larger-tile action 1 | **"Mark"** (glyph `✓`) — headless Quick mark, no undo, `source='widget'` |
| Larger-tile action 2 | **"Log"** (glyph `✎`) — deep-links to the full log flow |
| Larger-tile action 3 | **"Message"** (glyph `✉`) — deep-links to the in-app Compose screen |
| Empty state heading | **"Choose favourites"** |
| Empty state body | **"Pick who you want to keep close — they'll show up here."** (whole tile → Manage favourites) |
| Add-widget fallback | **"Your launcher can't add it automatically — add Orbit from your home screen's widget menu."** |

Copy notes:
- Glyphs are the *decorative* leading mark; the **text label is the source of truth**. If the

- Button labels are shortened from the decided action names (Quick mark → "Mark", Log contact →
  "Log") purely for tile width; semantics are unchanged.

## Component Inventory & Widget Layouts

All layouts are `FlexWidget` trees rasterised to one PNG. "Planet" read = circular avatar +
coloured orbit **ring**; no gradients/glow/starfield (not RemoteViews-feasible cheaply). Flat ring
only, token-coloured.

### Small tile (default size) — clean mark-grid

Per contact cell (target ~6 favourites at default size; exact max per resolution is a **device
spike**, dossier — do not hardcode):

```
┌─────────────┐
│   ( o )      │  ← circular base64 avatar (ImageWidget radius = size/2),
│   status     │    wrapped by a FlexWidget with borderWidth = status weight,
│   ring       │    borderColor = status token
│  Name  ›     │  ← name (13sp/600, 1 line, ellipsised) + chevron "›" (accent),
│              │    seated on a faint surfaceElevated pill = the profile tap region
└─────────────┘
```

- **Ring border weight (redundant status channel):** stable `2px` · wobble `3px` · decay `4px` ·
  rogue `3px`. Colour carries the primary signal; weight is the CVD/redundancy backup.
- Avatar circular; missing photo → themed swatch + initials (see Missing-photo fallback).
- Fuel line is **absent** on the small tile (03-fuel: fuel only at the larger size — a decided
  privacy/clutter boundary; do not add it here).

### Larger tile — adds fuel + actions

Per contact row:

```
┌──────────────────────────────────────────────┐
│ ( o )   Name                    [✓] [✎] [✉]   │
│ ring    fuel line (11sp, 1 line) Mark Log Msg │
└──────────────────────────────────────────────┘
```

- Left: avatar + status ring (as small tile).
- Middle column: name (13sp/600) over the ranked fuel line (11sp/400, `off_limits` excluded — the
  same ranked projection as card/notification, FUEL-03).
- Right: three compact action buttons in a row (glyph over 11sp/600 label), each a ≥48dp tap
  rectangle. Buttons use `surfaceElevated` fill + `textPrimary` label; glyph tint = `textSecondary`
  except **Message** whose glyph may use `accent` to signal the primary "send" intent.
- One **resizable** widget re-renders small↔large on `WIDGET_RESIZED` (preferred over two picker
  entries — dossier "Decisions made without you" #2). The design supports the split either way.

### Empty-state tile — "Choose favourites"

Single centered prompt tile (no grid):

```
        ☆                 ← outline star glyph, accent
  Choose favourites        ← 15sp/600, textPrimary
  Pick who you want to      ← 12sp/400, textSecondary
  keep close — they'll
  show up here.
```

- Whole tile → `OPEN_URI orbit://…` deep-link to the shared **Manage favourites** screen (an empty
  widget becomes onboarding for the feature it depends on — dossier Cluster F).

## Interaction Contract

RemoteViews taps are single clicks. §6's "long-press = profile" becomes **two tap regions per small
tile** (owner chose "name label + chevron"; dossier Cluster B — a *mechanism* change, not a reversal).

| Surface | Region | Action | Wiring |
|---------|--------|--------|--------|
| Small tile | **Whole tile / avatar** (biggest hit-area) | Headless **mark-contacted**, no undo | non-reserved `clickAction` → `WIDGET_CLICK` headless task (30s budget) → `recordTouchpoint` (`source='widget'`, `connected=true`, `direction='outbound'`, `channel='unspecified'`, `quality=null`) |
| Small tile | **Name label + chevron `›`** (on the faint `surfaceElevated` pill, ≥48dp) | Open profile | reserved `OPEN_URI` → `orbit://contact/{id}` → React Navigation; "Back → dashboard" via JS synthetic back-stack (not `TaskStackBuilder`) |
| Larger tile | **"Mark"** button | Headless Quick mark (same as small-tile mark) | as above |
| Larger tile | **"Log"** button | Open full log flow | `OPEN_URI orbit://…` deep-link |
| Larger tile | **"Message"** button | Open in-app **Compose** screen | `OPEN_URI orbit://…` → `Compose: { contactId }` (the same surface the decay notification opens) |
| Empty tile | Whole tile | Open Manage favourites | `OPEN_URI orbit://…` |

**Profile-region legibility without a real long-press:** the name+chevron region is demarcated by a
faint `surfaceElevated` pill *behind* the name and the `accent` `›` chevron, visually separating it
from the surrounding mark-contacted region. The chevron is the universal "opens elsewhere" affordance;
the pill gives the tap rectangle a visible edge so the user learns two targets exist. The mark region
keeps the larger, borderless remainder of the tile (protecting the no-undo action's hit-area from the
profile target — dossier rejected "avatar=mark / name-half=profile" for stealing too much of the tile).

### "Add Orbit widget" button (Settings)

- **Placement:** a standard settings row/button in `SettingsScreen` under a "Home screen" grouping (or
  the general block if no such group exists) — Settings-only, no onboarding surface this phase.
- **Affordance:** a full-width settings row, label **"Add Orbit widget"**, leading a grid/widget glyph
  (`▦`, `textSecondary`), trailing chevron consistent with other Settings rows.
- **Behaviour:** `requestPinWidget`; on unsupported launchers / API < 26 it returns false → show the
  fallback copy inline or as a toast (no crash, no dead button).

## Missing-photo Fallback (rendered into the bitmap)

Reuse the existing deterministic scheme — **do not invent a second one**:

- `index = swatchIndex(name)` → `colors.avatarSwatches[index]` as the circle fill (8 muted deep-space
  hues); initials via `getInitials(name)`; glyph colour = `colors.avatarSwatchText` (`#F2F4FB`).
  (Same helpers the `Avatar` component uses — `src/components/avatar-initials.ts`.)
- Rendered as a filled circle (`ImageWidget`/`FlexWidget` `radius = size/2`) with centred initials, so
  the fallback is a "planet" identical in silhouette to a photo avatar, carrying the same status ring.
- Empty name → neutral swatch (index 0), no glyph (matches `Avatar`).
- The base64 pipeline (net-new this phase) downscales the 512px master → tile-thumb → base64 `data:`
  URI within the RemoteViews bitmap-memory ceiling (device spike); **never** a `file://` or `http(s)`
  source. This spec fixes the *appearance*, not the encoder (planning owns the pipeline).

## `ContactCard` Upgrade (retire the OD-1 opacity placeholder)

Once the shared tokens exist, `src/components/ContactCard.tsx` (lines ~106–116) changes from
opacity-as-signal to real colour:

- **Ring colour** by status: `stable → colors.statusStable`, `wobble → colors.statusWobble`,
  `decay → colors.statusDecay`, `rogue → colors.rogue`, `null` (never-contacted) → `colors.border`
  (neutral).
- **Opacity** is no longer the signal: `1.0` for all four real statuses; the never-contacted neutral
  ring stays visibly faint (e.g. `0.5` over `border`) so "no status yet" still reads as absence, not a
  band.
- **Border weight** adopts the same redundant escalation as the widget (stable `2` → decay `4`, rogue
  `3`) for CVD backup — a small change to the existing `styles.statusRing.borderWidth`.
- **`accessibilityLabel` retained** exactly (`statusLabel()` already emits "Stable"/"Wobbling"/
  "Decaying"/"Rogue"/"Not yet contacted") — uiautomator UAT keeps asserting the band without colour.
- OD-2 (`accent` `★` favourite) and OD-4 (category chip) are untouched by this phase.

This is the single on-card visual change; the card's LOCKED content contract (08-UI-SPEC) is otherwise
unchanged.

## Accessibility & Freshness Notes

- **Status is never colour-only:** ring colour + escalating border weight + (on the card)
  `accessibilityLabel` + the always-present name. The widget's rich rogue styling is deferred to the
  orrery (Ph13); on the widget rogue is the amber ring, distinguished from decay by hue and weight.
- **Rendered status is "as-of-last-render"** (DECIDED freshness model, Cluster E): the widget cannot
  run timers, so a tile can lag reality by up to ~a day of decay between app opens. This is acceptable
  — decay is measured in days and the widget is a glance aid, **never the sole route** (Android 15
  force-stop greying already guarantees a re-push on launch/boot). The design must not imply real-time
  freshness (no "live"/timestamp affordance on the tile).
- **Tap safety:** the no-undo mark gets the largest, most stable rectangle; the profile target is a
  distinct ≥48dp pill. Static manual rank (never status-reordered) keeps positions stable for muscle
  memory on the un-undoable action.
