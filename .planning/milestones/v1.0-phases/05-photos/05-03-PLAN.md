<objective>
Ship the first user-visible capability: every photo-less contact gets a distinctive, deterministic themed initials avatar, and the reusable `Avatar` component renders a real photo when one exists.

Phase Goal (user story): **As a** user, **I want to** glance at a contact and recognise them by a stable colour + initials (or their photo) **so that** my list of people is scannable even before I add photos.

This is the resting state of the whole feature — it renders before any picker exists, so it is genuinely shippable on its own. `avatar-initials.ts` ports the plugin's initials + rolling hash VERBATIM but indexes the themed swatch array instead of producing a free HSL hue (barred by CLAUDE.md / check:colors). `Avatar.tsx` is the one component reused by the profile now and the grid/orrery/widget later; its has-photo branch resolves the stored RELATIVE path to `file://` via `photo-storage` (never a network URL — reads stay local).

Purpose: PHOTO-04 (deterministic themed initials fallback, no free HSL, no hardcoded colour).
Output: `avatar-initials.ts` (+ test), `Avatar.tsx`, Avatar wired into the profile header (with `photo` added to the header read).
</objective>

It is imported by every photo WRITE site in 05-05/05-08 (which call `bumpPhotoCacheBust` right after a set/clear) and read by `Avatar`. Rationale for a per-write token over `modified_at`: `modified_at` is second-resolution (`database.ts` `localDateTime` → `YYYY-MM-DD HH:MM:SS`), so two replaces within one wall-clock second reuse the same stable path AND the same `modified_at` → the same cache key → a stale decode. A per-write monotonic token guarantees a distinct key even for a same-second replace. (Note: the store is in-memory; after a restart there is no revision for a key, so `Avatar`'s key falls back to `photo#modified_at`, which is a FRESH key not previously cached — forcing a clean disk read of the current file bytes — so correctness holds across restart too.)
    Create `Avatar.tsx` (props: `photo: string | null` relative path, `name: string`, `contactId?: number | string`, `size: number`, `cacheBust?: string | number`). Has-photo branch: subscribe to the per-write revision with `const rev = usePhotoCacheBust(photo)` and compose a combined discriminator `bust = [cacheBust, rev].filter(v => v != null).join('#')`; render `expo-image` with `source={{ uri: resolvePhotoUri(photo), cacheKey: bust ? `${photo}#${bust}` : photo }}`, `contentFit="cover"`, `cachePolicy="memory-disk"`, `recyclingKey={bust ? `${contactId}#${bust}` : String(contactId)}`, circular via `borderRadius: size/2`; on `onError` fall back to the initials branch.
