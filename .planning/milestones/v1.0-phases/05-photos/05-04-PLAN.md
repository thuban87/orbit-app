<objective>
Build the crop math and the orchestration that turns a raw picked/downloaded image into the one 512px master — the engine every capture path reuses.

Phase Goal (user story): **As a** user, **I want to** frame a photo and have it saved as one small square master **so that** it looks right everywhere (list, profile, later orrery/widget) without wasting storage.

`crop-geometry.ts` is pure, unit-tested math (05-RESEARCH Assumption A1 — the one MEDIUM-confidence area, resolved by node tests + a single on-device visual check). `photo-pipeline.ts` orchestrates: take the ORIGINAL source URI + a source-pixel crop rect, run `expo-image-manipulator` (crop → resize 512×512 → JPEG q0.75) — NEVER a Skia screen snapshot (lossy) — then copy out of evictable cache into the document dir via `photo-storage.persistMaster`, returning the RELATIVE path. It is target-aware (contact / profile / custom-field) but does NOT write the DB — the caller supplies the persist so the DAO write stays at the call site (contact/profile write immediately; custom-field defers to the form).

Purpose: PHOTO-01 (crop) + PHOTO-03 (one 512px master, relative path).
Output: `crop-geometry.ts` (+ test) and `photo-pipeline.ts`.
</objective>
