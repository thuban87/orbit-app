## Deviations from Plan

### D-14 revoke-between-reads — code-verified, not device-driven
`pm revoke` kills the app process on Android 12 (the plan's H-C caveat), and no debug fault-injection
hook exists in the build, so the revoke-between-reads sequence is not drivable on-device. Source
confirms the contract: `importSelected()` wraps `readAllContacts` in try/catch and on rejection sets
`loadState="error"` → "Couldn't read contacts. Please go back and try again." (explicit surface, not a
silent no-op).

### Empty book — verified by equivalence
The empty state is a single FlatList `ListEmptyComponent` ("No contacts on this device") rendered
whenever the list is empty — identical for an empty book and a no-match search, with no separate
branch. Observed live via a no-match filter. A separate empty-profile pass was not run (owner accepted
this over a disruptive Guest-user switch).

### >900 chunking — accepted alternative
>900 selection was impractical on-device (couldn't reach 900 synthetic contacts; device `content`
inserts ≈6s each; no select-all). Accepted evidence: `src/logic/contact-picker-chunk.test.ts`
(">1 chunk") + a device multi-select spot-check (no cap/bind-variable error observed).

### Large-book perf — N=436 (not ~1,000)
gfxinfo over a continuous fling on the 436-contact book: 13.5% janky, 99th pct 133ms (no stall near
~500ms); GPU cheap. Caveat: gfxinfo covers the UI/render thread only; RN JS-thread jank is not
captured. ~1,000 was infeasible via the slow provider-insert path.

**Total deviations:** 4, all with documented rationale and owner-accepted; no scope expansion.
