### `OrbitContactPickerModule.kt` — new `readAllContacts` AsyncFunction (native, file-I/O)

**Analog:** the same file's `readPickedContacts()` (`OrbitContactPickerModule.kt:125-179`). ~90% reusable. The **only** structural changes: query the full provider instead of a session URI, add `DATA2` (Event.TYPE) to the projection, gate the Event branch on `TYPE_BIRTHDAY`, and **reject on read failure** instead of `resolve(emptyList())`.

**AsyncFunction + SDK-guard shape** (copy from `:63-74`):
```kotlin
Function("isContactPickerAvailable") { Build.VERSION.SDK_INT >= 37 }
// new: expose the inverse for the ≤16 path, e.g. Function("isLegacyContactReadRequired") { Build.VERSION.SDK_INT < 37 }
AsyncFunction("readAllContacts") { promise: Promise -> ... }
```

**Projection + grouping to copy verbatim** (`:126-168`) — the `linkedMapOf<String, MutablePickedContact>()`, per-mimetype `when` block, blank-filtering (`takeIf { it.isNotBlank() }`), and the `mapOf("lookupKey"…"photoTempUri")` emit (`:170-178`). Reuse `copyPhotoToCache` / `copyContactPhotoToCache` / `copyPhotoStreamToCache` / `stringAt` / `blobAt` (`:181-216`) **unchanged**.

**CHANGE 1 — projection adds DATA2** (today's projection at `:126-132` omits it):
```kotlin
val projection = arrayOf(
  ContactsContract.Data.LOOKUP_KEY,
  ContactsContract.Contacts.DISPLAY_NAME_PRIMARY,
  ContactsContract.Data.MIMETYPE,
  ContactsContract.Data.DATA1,
  ContactsContract.Data.DATA2,   // NEW — Event.TYPE, required for the D-03 gate
  ContactsContract.Data.DATA15,
)
```

**CHANGE 2 — full-provider query** (replaces the session-URI query at `:137`; full provider accepts selection args, the session URI does not — see the comment at `:135-136`):
```kotlin
context.contentResolver.query(
  ContactsContract.Data.CONTENT_URI, projection,
  "${ContactsContract.Data.MIMETYPE} IN (?,?,?,?)",
  arrayOf(Phone.CONTENT_ITEM_TYPE, Email.CONTENT_ITEM_TYPE, Event.CONTENT_ITEM_TYPE, Photo.CONTENT_ITEM_TYPE),
  "${ContactsContract.Contacts.DISPLAY_NAME_PRIMARY} ASC",
)?.use { cursor -> ... }
```

**CHANGE 3 (D-03 — the defect NOT to reproduce)** — today's Event branch at `:158-159` maps *any* Event `DATA1` to birthday with no type check. The new reader MUST gate on `Event.TYPE == TYPE_BIRTHDAY` (`TYPE_BIRTHDAY` is int constant `3`; prefer the constant):
```kotlin
ContactsContract.CommonDataKinds.Event.CONTENT_ITEM_TYPE -> {
  if (cursor.intAt(data2Column) == ContactsContract.CommonDataKinds.Event.TYPE_BIRTHDAY) {
    contact.birthday = contact.birthday ?: cursor.stringAt(data1Column)
  }
}
```
(`intAt` helper does not exist yet — add one mirroring `stringAt`/`blobAt` at `:212-216`.)

**CHANGE 4 (D-14 — the second defect NOT to reproduce)** — the 17+ path swallows read failures at `:116-121` (`catch → resolve(emptyList())`). The new AsyncFunction MUST `promise.reject(...)` on read failure. A user cancel (empty selection in *our* UI) returns `[]`; a read error rejects. This is what distinguishes them downstream — see Shared Pattern "Cancel vs. read-error".

### `use-read-contacts-permission.ts` — permission hook (NEW, request-response)

**Analog:** `src/services/notifications/permission.ts`. Copy its **shape**, not its API: a thin wrapper that (a) reads fresh every call, never caches OS permission in app state, (b) guards the OS call so a rejection returns a typed `{granted}` result instead of throwing, (c) fires at a value moment and asks once with no nag loop. Its doc-comment (`:1-15`) is the design contract to preserve.

```ts
// mirror this guarded-typed-result shape (permission.ts:32-53), but use PermissionsAndroid:
export async function getContactsPermission(): Promise<{ granted: boolean; status: string }> {
  try { const status = await PermissionsAndroid.check(PermissionsAndroid.PERMISSIONS.READ_CONTACTS);
        return { granted: status, status: status ? "granted" : "denied" }; }
  catch { return { granted: false, status: "denied" }; }
}
```
Net-new beyond the analog (D-11b): `NEVER_ASK_AGAIN` detection + `Linking.openSettings()`. **No in-repo precedent for `openSettings()`** — verify the deep-link lands on Orbit's app-info page on the 3a (A2). The priming screen (D-11c) and calm-deny state (D-11a) are screen states, not this hook.

### D-12 — nameless rows auto-terminalize as `'skipped'` (edit, NO migration)

**Analog / defect site:** `src/services/import/import-driver.ts:76-85` (verified) — `importRowAsNew` marks nameless rows `'failed'` with reason `"name-required"`. `'failed'` is in the unresolved set (`finalizeSessionIfTerminal` query `import-session-dao.ts` `row_status IN ('pending','needs_review','failed')`, verified; and `UNRESOLVED_ROW_STATUSES` `import-leave-guard-logic.ts:7-11`, verified), so the session never finalizes → resume-nag every launch.

**Fix:** change `"failed"` → `"skipped"` at `import-driver.ts:79`. `'skipped'` is a valid status (`import-session-dao.ts:26-33`, verified) and is NOT in either unresolved set → already terminal → session finalizes, nag stops, no migration. Keep `failure_reason = "name-required"` so the count stays distinguishable. Consider also terminalizing nameless rows at the acceptance seam (`acceptPickedContacts`/`import-acquire.ts:71` already computes `mapped.nameRequired` but discards it) to cover the single path too (`ImportReviewScreen.tsx:181` blocks commit on empty name → single nameless row would otherwise dead-end). Completion summary "N skipped — no name" = a read-only count keyed on `failure_reason='name-required'` (no migration). **Do NOT widen the unresolved sets** — they are the shared terminalization invariant, kept in sync by comment (`import-leave-guard-logic.ts:4-6`).

### D-13 — broaden birthday parsing; flag (don't drop) unparseable (edit, NO migration)

**Analog / defect site:** `picked-contact-map.ts:28-38` `mapBirthdayForStorage` (verified) handles only `--MM-DD` / `MM-DD` / `YYYY-MM-DD`; anything else → `null` → silently dropped, and `ImportReviewScreen.tsx:145` loads the *pre-nulled* `mapped.birthday` so a bad format shows empty and never trips the error state.

**Fix (two parts):**
1. Broaden the canonicalizer in `mapBirthdayForStorage` (`picked-contact-map.ts:28-38`) to also normalize `YYYY/MM/DD`, `MM/DD/YYYY` to the two stored shapes. **Keep `parseStoredBirthday` (`birthday-logic.ts:79-105`) strict** — it correctly rejects `02-30` via explicit `daysInMonth` checks (verified `:79-105`); broaden the *input*, never loosen this gate.
2. Flag on review: load the **raw** `snapshot.birthday` into `birthdayInput` (not the pre-nulled `mapped.birthday`) at `ImportReviewScreen.tsx:145` so unparseable values hit the existing `birthdayInvalid` state (`:174-175`, verified). Bulk path has no per-row birthday review → drop there is acceptable (birthday optional). Applies to both readers via shared `picked-contact-map.ts`.

## Shared Patterns

### Cancel vs. read-error distinction (D-14)
**Source of the anti-pattern:** `OrbitContactPickerModule.kt:116-121` (`resolve(emptyList())` on read failure) + `import-acquire.ts:161` (`if (picked.length === 0) return;`). Together, a failed read is indistinguishable from a cancel.
**Apply to:** the new `readAllContacts` AsyncFunction. Contract: **cancel = our picker screen returns `[]` (silent no-op via `routePickedImport`); read error = the AsyncFunction rejects.** The JS entry-point `try/catch` already shows "Couldn't import contacts" on rejection (`AddSpeedDialFab.tsx:78-80`, verified; `SettingsScreen.tsx` mirror). So a rejection routes to the error toast; an empty array is the correct no-op.

### Guarded, fresh-read permission wrapper
**Source:** `src/services/notifications/permission.ts:32-53`.
**Apply to:** the new READ_CONTACTS hook — fresh read every call, guard the OS call → typed `{granted}` result, ask once, no nag.

### Token-only styling (CLAUDE.md, non-negotiable)
**Source:** `AddSpeedDialFab.tsx:99-108,145-171`; palette `src/theme/theme-types.ts:29-158`.
**Apply to:** the picker screen and every permission-state view — `useTheme().colors.*` only, no hardcoded colours, row min-height 44.

### Strict birthday calendar gate (don't hand-roll)
**Source:** `isValidStoredBirthday` / `parseStoredBirthday` (`birthday-logic.ts:79-114`, verified — rejects `02-30`, handles Feb-29).
**Apply to:** D-13 — broaden the *input* canonicalizer only; route all validity through this gate. Never `new Date(y,m,d)` (silently normalizes impossible dates).

### Terminalization invariant (don't widen)
**Source:** `finalizeSessionIfTerminal` unresolved query (`import-session-dao.ts`) + `UNRESOLVED_ROW_STATUSES` (`import-leave-guard-logic.ts:7-11`) — kept in sync by design.
**Apply to:** D-12 — move rows to the already-terminal `'skipped'` status; do NOT add a status or change what "terminal" means (would need a needless irreversible migration).

### PickedContact[] boundary (unchanged)
**Source:** `modules/orbit-contact-picker/index.ts:8-19` (verified `{lookupKey, displayName, methods, birthday, photoTempUri}`).
**Apply to:** the native reader must emit exactly this; then `mapPickedContact` → `routePickedImport` → the session pipeline consume it unchanged (all picker-agnostic).
