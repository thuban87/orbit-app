# Phase 19.1 Plan 01: Tracer Legacy Acquisition Summary

**API <= 36 contact import now reads the on-device Contacts Provider into the shared import pipeline through a scoped permission, native birthday gate, and single SDK routing seam.**

## Accomplishments

- Added a full-provider Android reader that groups phones, emails, birthdays, and staged cache photos into the existing `PickedContact[]` shape.
- Scoped `READ_CONTACTS` through API 36, filtered Event rows by `TYPE_BIRTHDAY`, and rejects provider-read failures rather than silently converting them to cancellations.
- Added a token-only virtualized legacy multi-select picker, runtime permission wrapper, navigation route, and dashboard FAB dispatch through `contactImportMode()` / `startContactImport()`.

## Decisions Made

- Kept both acquisition routes on the existing `PickedContact[]` boundary so downstream import session, review, and photo staging remain picker-agnostic.
- The legacy picker obtains region and local time when the user confirms Import, allowing long-open pickers to use current settings.
- No network, telemetry, or contact-content logging was introduced; provider photos are copied to app-private cache only.
