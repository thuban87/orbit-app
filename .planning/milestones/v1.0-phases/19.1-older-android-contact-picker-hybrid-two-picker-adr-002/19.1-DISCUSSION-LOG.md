## Custom picker UX

### Multi-select interaction

| Option | Description | Selected |
|--------|-------------|----------|
| Checkbox list + Import(N) | Row checkboxes + persistent "Import (N)" button; familiar, discoverable | ✓ |
| Tap-to-toggle + count bar | Tap rows to toggle, floating count/confirm; lighter chrome | |
| Long-press to enter select mode | Tap = single, long-press = multi; Gmail-style, more gesture to learn | |

### Selection cap

| Option | Description | Selected |
|--------|-------------|----------|
| No cap | Honor the incremental pipeline (no arbitrary app-level cap) | ✓ |
| Soft warning above N | No hard limit; warn past a threshold | |
| Hard cap | Refuse past a fixed number (contradicts the no-cap criterion) | |

### Row content

| Option | Description | Selected |
|--------|-------------|----------|
| Avatar + name + primary method | Photo/initials + name + one method subtitle; virtualized | ✓ |
| Name + method count | Name + "3 phones, 1 email"; no photos | |
| Name only | Just the display name | |

### Search scope

| Option | Description | Selected |
|--------|-------------|----------|
| Name only | Filter by display name | |
| Name + phone/email | Also match method values | ✓ |

### Visual approach

| Option | Description | Selected |
|--------|-------------|----------|
| Yes to both | Avatar+name+method rows; standalone on theme tokens, decoupled from current dashboard | ✓ |
| Rows yes, revisit look | Keep rows, discuss visual direction more | |
| Reconsider row content | Change what each row shows | |

**User's choice:** Checkbox list + Import(N); no cap; avatar+name+method rows; search name+phone/email; standalone-on-tokens, decoupled from the (soon-to-be-redone) dashboard.
**Notes:** Owner initially thought "custom picker" meant Orbit connecting to a Google-provided picker UI. Clarified: below API 37 there is no rich system picker — only single-field `ACTION_PICK` (name + one phone) permissionlessly, or raw `ContactsContract` data with no UI. So the picker UI is genuinely ours. Owner accepted the added scope. Owner asked how hard a later redesign is: answered structure/data/logic is essentially free to redesign if kept decoupled from presentation, and the UI is a moderate/contained single-screen reskin because it's token-driven. Recommendation accepted: build standalone on tokens, distinct utilitarian list (a "tool," not the home view), decoupled from dashboard components changing next milestone.

## Permission-denial path

### Graceful path on deny

| Option | Description | Selected |
|--------|-------------|----------|
| Calm state + re-request | Friendly explainer + "Grant access" re-request; no fallback | ✓ |
| + single-field ACTION_PICK fallback | Also offer thin permissionless picker; separate degraded path | |
| Just close, no state | Silently return; user left confused | |

### Permanent denial ("Don't ask again")

| Option | Description | Selected |
|--------|-------------|----------|
| Deep-link to app settings | Switch to "Open Settings" → app-info permissions | ✓ |
| Explain, no deep link | Text only, manual navigation | |

**User's choice:** Calm state + re-request; deep-link to app settings on permanent denial.
**Notes:** Single-field `ACTION_PICK` fallback explicitly rejected (thin, degraded, extra code path) — not deferred.

## Carried-forward fix calls

### Nameless (name-required) rows nagging the resume prompt

| Option | Description | Selected |
|--------|-------------|----------|
| Auto-terminalize as skipped | Move to terminal "skipped" so session finalizes; report in summary | ✓ |
| Explicit user skip action | Manual Skip button; more taps, still nags until acted on | |
| Both | Auto-terminalize + manual Skip | |

### Under-inclusive birthday parsing

| Option | Description | Selected |
|--------|-------------|----------|
| Broaden parser, drop leftovers | Accept common formats incl. year-less; silently drop the rest | |
| Broaden parser, flag leftovers | Accept common formats incl. year-less; still-unparseable → review error state | ✓ |
| Drop all non-strict | Keep strict parser; silently drop everything else | |

**User's choice:** Auto-terminalize nameless rows as skipped; broaden birthday parser (incl. year-less `--MM-DD`) and flag still-unparseable ones with a review-screen error state.
**Notes:** Both live in the shared pipeline and apply to both pickers. Flag-not-drop is consistent with 19-13 and the custom-fields "flag, don't coerce" philosophy. (Carried-forward #2 read-exception-vs-cancel and #4 single-import dead-end were also captured in CONTEXT.md as fixes to apply, not discussed as forks.)
