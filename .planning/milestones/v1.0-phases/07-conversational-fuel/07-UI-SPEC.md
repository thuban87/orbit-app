# Phase 7 — UI Design Contract

> Visual and interaction contract for Conversational Fuel: the per-item fuel editor on a contact's
> profile (add/edit/delete across 5 kinds + optional label), the ONE ranked fuel line reused by every
> glanceable surface, fuel-age rendering, the `source='ai'` unconfirmed state, and the cross-contact
> name-AND-fuel search surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Authority:** every decision below traces to `docs/dossier/03-fuel.md` (23 questions, 6 rounds, no
> `[OPEN]` items — the authoritative CONTEXT for this phase), `docs/dossier/INDEX.md` `[fuel → *]` /
> `[dashboard → fuel]` rows, `.planning/ROADMAP.md` Phase 7 (goal + 3 success criteria),
> REQUIREMENTS `FUEL-01…06`, and `CLAUDE.md` non-negotiables. This is a **React Native / Expo** app —
> the shadcn gate does not apply (no `components.json`, not React web). The design system is the
> project's own theme-token architecture in `src/theme/`, and this phase conforms to the de-facto
> scale established by `05-photos/05-UI-SPEC.md` and the 28 completed plans in `src/`.

---

## Scope & Surfaces

Five UI surfaces, each a contract the executor implements and the auditor checks:

1. **Fuel editor** (profile) — a controlled repeatable list: add / edit / delete per-item rows across
   the 5 kinds (`recent` · `topic` · `fact` · `gift` · `off_limits`) + optional free label + optional
   URL. Mounts on `ContactProfileScreen` as a labelled section, following the established
   `LinksEditor` + refine-panel pattern.
2. **The single ranked fuel line** — the ONE projection (kind priority then recency, `off_limits`
   excluded **in-query**) reused by the card preview, notification, and widget. On the profile it
   renders as a highlighted "top line." The contract is **surface-agnostic plain text** — no styling
   is baked into the projection; each surface styles the string it returns.
3. **Fuel age** — `created_at` rendered as "N days/months ago" on each editor row. Drives ranking;
   never hides or destroys data.
4. **The `source='ai'` unconfirmed state** — visually distinct row treatment + a Confirm affordance.
   Excluded from AI prompts until confirmed (data behaviour); rendered so a hallucination never reads
   as user-authored.
5. **Cross-contact search** — a search input + results list matching **name AND fuel text** (`LIKE`,
   `off_limits` excluded from both query and results).

## Design System

| Property | Value |
|----------|-------|
| Tool | none (React Native / Expo — shadcn not applicable) |
| Preset | not applicable |
| Component library | React Native core primitives (`View`, `Text`, `TextInput`, `Pressable`, `ScrollView`/`FlatList`, `Modal`, `Alert`). NO new dependency this phase. |
| Icon library | none — the app uses text labels and glyphs (`Back`, `⋯`, `✕`, `+`). Do NOT add an icon library. |
| Font | System default (React Native platform font). No custom font is loaded; do not introduce one. |
| Color source of truth | `src/theme/theme-presets.ts` — the ONLY file where a colour hex literal may appear (CLAUDE.md). Every component reads `useTheme().colors.*`; enforced by `npm run check:colors`. |

**Net-new theme token: NONE.** Unlike Phase 5 (which added `avatarSwatches`), this phase introduces no
new colour concept. The `off_limits` "private" treatment and the AI-unconfirmed badge are built
entirely from existing tokens (`border` / `borderStrong` / `textSecondary` / `accent`). Do NOT add a
token, and do NOT reach for a raw colour to signal "private" or "unconfirmed."

## Spacing Scale

Conforms to the de-facto scale already in `src/` (Phase-5 UI-SPEC § Spacing). Do NOT impose a foreign
8-point grid.

| Token | Value | Usage this phase |
|-------|-------|------------------|
| xs | 4px | Tightest inline gaps (badge ↔ text) |
| sm | 8px | Row-internal gaps, section body gaps (`gap: 8`) |
| — | 10px | List container `gap` between fuel rows (matches `LinksEditor` `container.gap: 10`); vertical control padding (`paddingVertical: 10`) — de-facto, keep |
| md | 12px | Row padding (`padding: 12`), row-action gaps (`gap: 12`), input horizontal padding |
| — | 14px | Button horizontal padding (`paddingHorizontal: 14`) — de-facto, keep |
| lg | 16px | Screen content padding (`padding: 16`), major section gaps (`gap: 16`) |
| xl | 24px | Wide horizontal padding for prominent controls / modal margins |

Radius: `8` default (inputs, buttons, the kind-picker trigger); `10` for a fuel **row** card (matches
`LinksEditor` row); `12` for the larger panels/modals; `999` for pills (the off-limits and AI badges).

**Touch targets:** every interactive control keeps `minHeight: 44` (kind-picker trigger, add-fuel,
confirm/dismiss AI, delete, search submit, each result row). Icon-only affordances (`✕` remove,
Confirm/Dismiss) use `hitSlop` to reach 44 where the visual glyph is smaller, per `LinksEditor`.

Exceptions: 10px and 14px are pre-existing de-facto steps, retained deliberately — not new deviations.

## Typography

Conforms to the de-facto scale (Phase-5 UI-SPEC § Typography): sizes 13 / 15 / 16 / 24; weights 400
(body default), 600 (semibold), 700 (titles). No new size or weight is introduced.

| Role | Size | Weight | Line Height | Usage this phase |
|------|------|--------|-------------|------------------|
| Label / secondary | 13px | 600 | 1.4 | Section heading ("Conversational Fuel", uppercase), the kind label on a row, the "N days ago" age, the off-limits/AI badge text, helper copy, search-result contact sublabel |
| Body | 15px | 400 (default) | 1.5 | The fuel item **text** (the sayable content), the ranked-line string, error/dialog body, input text |
| Action / button | 16px | 600 | 1.2 | "+ Add fuel", "Confirm", search submit, primary controls |
| Heading / title | 24px | 700 | 1.2 | Search-screen title (matches `ContactProfileScreen` title) |

**The ranked fuel line** on the profile renders at **Body (15/400)** but is visually promoted by its
container (a bordered/elevated strip), not by a larger font — this keeps the projection string
surface-agnostic so the same text is legible in a notification and a `RemoteViews` widget tile.

Fuel text is **plain text, not markdown** (dossier "Decisions made without you" #4). Do NOT render or
parse `**bold**` / `##` headings — `kind` and `label` carry structure now. Multi-line entry uses a
plain multiline `TextInput` (the `TextAreaFieldWidget` posture), never a rich editor.

## Color

All values resolve through `space-dark` theme tokens (the only shipped preset — infrastructure, not a
finished palette; final visual design is the owner's per HANDOFF §7). No hex outside `theme-presets.ts`.

| Role | Token | Value | Usage this phase |
|------|-------|-------|------------------|
| Dominant (60%) | `background` | `#0B0E1A` | Screen backdrops (profile, search), modal scrim base |
| Secondary (30%) | `surface` / `surfaceElevated` | `#141828` / `#1D2235` | Fuel row cards, inputs, the kind-picker sheet, the ranked-line strip, search-result rows |
| Accent (10%) | `accent` | `#6C8CFF` | See reserved-for list below |
| Destructive | `danger` | `#E5484D` | The **Delete** confirmation button in the destructive `Alert` ONLY (OS-rendered `style: "destructive"` needs no token) |
| Borders | `border` / `borderStrong` | `#2A3048` / `#3C4568` | Row/input borders; `borderStrong` for the off-limits row outline + the AI-unconfirmed badge/row outline to make them distinct without a new hue |
| Text | `textPrimary` / `textSecondary` | `#E6E9F5` / `#8B93B0` | Copy per typography roles; `textSecondary` carries the "private"/age/badge semantics |

**Accent reserved for:** the primary **"+ Add fuel"** affordance, the **"Confirm"** action on an
AI-unconfirmed item, and the selected kind in the kind picker. NOT for the row border, NOT for the
off-limits marker, NOT for "Delete", NOT for "Dismiss" (which is `textSecondary`). One accent primary
action per surface — the app convention.

**`off_limits` visual treatment (built from existing tokens only):** an off-limits row is editable on
the profile like any other, but MUST carry an unmistakable "never shared / never glanceable" marker: a
`borderStrong` row outline plus a pill badge (`border`/`textSecondary`, 999 radius, 13/600) reading
**"Off-limits · private"** and a 🔒 glyph. It is NOT styled `danger` (danger = a destructive action,
not a privacy state) and NOT `rogue` (a contact status). This is a **visual reinforcement only** — the
security guarantee is structural (excluded in-query from every projection and from the AI resolver's
search space), never dependent on this styling.

**`source='ai'` unconfirmed treatment (existing tokens only):** a `borderStrong` row outline + a pill
badge **"Suggested by AI"** (`border`/`textSecondary`) to read as provisional, plus a **"Confirm"**
button (`accent`) and a **"Dismiss"** button (`textSecondary`). Once confirmed, the row loses the badge
and confirm/dismiss controls and renders as an ordinary item.

## Component & State Inventory

### `FuelEditor` (net-new — profile section; controlled, follows `LinksEditor`)

A controlled repeatable list mounted on `ContactProfileScreen` under a "Conversational Fuel" section
heading (13/700 uppercase, matching the existing "Timeline" heading). The parent owns the draft array
and persistence via a single DAO diff on save (mirroring `applyLinkDiff`); the component renders and
routes every add/edit/delete back up as callbacks. No DB access inside the component.

**Each fuel row** contains, top to bottom:

| Element | Contract |
|---------|----------|
| Kind picker | A `Pressable` trigger opening a `Modal` + `FlatList` of the 5 kinds (the `DropdownFieldWidget` pattern — zero new deps). Trigger shows the human kind label; selected kind is `accent` in the sheet. |
| Text | Multiline `TextInput` (`surface` bg, `border`), the sayable content, plain text. Placeholder: `What's worth saying?` |
| Label (optional) | Single-line `TextInput`, placeholder `Label (optional)`. Free text; keys nothing — prompt/notification logic keys off `kind` only. |
| URL (optional) | Single-line `TextInput`, placeholder `https://…`, `autoCapitalize="none"`, `keyboardType="url"`. An "Open" affordance reuses `LinksEditor`'s `normaliseLinkUrl` allowlist (http/https only). |
| Age | `created_at` rendered "N days/months ago" (13/600, `textSecondary`), right-aligned on the row header. Absent on a brand-new unsaved row. |
| Remove | `✕` (`textSecondary`, `hitSlop` to 44) → the permanent-delete confirm `Alert`. |

| State | Contract |
|-------|----------|
| Empty (no fuel) | "**No fuel yet**" (13/600, `textSecondary`) with "**+ Add fuel**" (accent) directly below — the `LinksEditor` empty pattern. |
| Has items | Rows rendered newest-first within the editor (display order is not ranking — see the ranked line). "**+ Add fuel**" pinned below the list. |
| Add | "+ Add fuel" appends a new row seeded with the default kind **`topic`** (dossier "Decisions made without you" #2 — never `off_limits`, never a transmitted default) and `source='user'`. |
| off_limits row | `borderStrong` outline + "Off-limits · private" 🔒 pill; helper line "Never shared with AI, never shown at a glance." Fully editable. |
| AI-unconfirmed row | `borderStrong` outline + "Suggested by AI" pill + Confirm (accent) / Dismiss (`textSecondary`). |
| Delete | Permanent-delete `Alert` (see Copywriting) — matches the touchpoint-delete copy already shipped in `ContactProfileScreen`. |

### The ranked fuel line (`RankedFuelLine` — surface-agnostic projection)

The ONE projection reused by card / notification / widget (FUEL-03). On the profile it renders as a
promoted strip above the editor.

| Aspect | Contract |
|--------|----------|
| Content | The single top-ranked item's **`text`**, as plain text — kind priority (newest `recent`, else `gift`, else `topic`, else `fact`), then recency. `off_limits` excluded **in the query**, never filtered in the UI. |
| Display | ONE line, `numberOfLines={1}`, ellipsised. Body (15/400), `textPrimary`, on a `surface`/`borderStrong` strip. No kind prefix — the kind drove ranking, not the display; keep the string clean and glance-legible. |
| Truncation | The notification path MUST ellipsise before the framework 1024-char cut (dossier `[fuel → notify]`); the *display* limit is one line. Truncation policy is a planning detail — the contract is: single line, tail ellipsis, no wrap. |
| Empty (no rankable fuel) | On the profile: render nothing (the editor's own empty state is the only prompt). The **card**'s no-fuel state is Phase-8-owned (dossier defers "what the card shows when a contact has no fuel"). |
| Unconfirmed AI | **Recommendation to the planner:** the glanceable projection should exclude unconfirmed `source='ai'` rows as well as `off_limits`, because a glance surface (card/notification/widget line) cannot carry the "Suggested by AI" affordance — an unconfirmed hallucination must never land on a glance line reading as fact. Confirmed items rank normally. (This is a query decision; recorded here so the UI contract stays coherent.) |

### Fuel age ("N days/months ago")

| Aspect | Contract |
|--------|----------|
| Format | "today" / "N days ago" / "N months ago" (and "N years ago" past 12 months). Derived from `created_at` vs now. |
| Computation | Uses local wall-clock helpers (`localDateTime` / `formatLocalDate` from `src/utils/dates.ts`) — **never** `toISOString().split('T')[0]` (CLAUDE.md — the evening UTC off-by-one). A relative-time formatter is a small planning-detail helper. |
| Rule | Age is **displayed and drives ranking only**. Nothing is ever hidden, archived, or destroyed by age (dossier Cluster C; FUEL-04). No launch sweep. |
| Style | 13/600, `textSecondary`, right-aligned in the row header. |

### `FuelSearch` (net-new minimal search surface — see Search Surface Decision below)

| State | Contract |
|-------|----------|
| Input | A themed `TextInput` (`surface` bg, `border`, 44px), placeholder "**Search names and fuel**", `autoCorrect={false}`. |
| Idle (no query) | "**Search your contacts and everything you've saved to talk about.**" (13/600, `textSecondary`). |
| Results | `FlatList` of result rows: `Avatar` + contact name (Body/`textPrimary`) + the matched fuel snippet or that contact's ranked line (13/600, `textSecondary`, single line ellipsised). Tap → `Profile`. |
| No matches | "**No matches**" (13/600, `textSecondary`). |
| Query | `LIKE` scan over name AND fuel `text`, ASCII-case-insensitive (ICU absent — dossier Cluster F). `off_limits` rows are excluded from the query, never filtered in the UI. No FTS5. |

## Search Surface Decision (the one thing to confirm — resolved from the dossier's lead)

**Decision:** Phase 7 ships a **minimal, self-contained `FuelSearch` screen** so FUEL-05 ("a user can
search across all contacts by name AND fuel text") is genuinely built and testable now. **Phase 8 owns
the final home** — INDEX `[dashboard → fuel]` records that the cross-contact fuel search *is* the
dashboard search box (name AND fuel, `LIKE`, `off_limits` excluded). Phase 8 will absorb / relocate this
query into the dashboard header; Phase 7 must therefore build the search **query + result-row rendering
as reusable units** (a DAO query + a presentational result row), not weld them into a throwaway screen.

**Entry point (Phase 7, minimal):** a "Search" row in `SettingsScreen` (low-traffic, already the home
for CRUD-05 "separate homes") OR a header affordance — either is acceptable; the executor picks the
lightest reachable mount. A new `FuelSearch: undefined` route joins `RootStackParamList`. Phase 8
relocating the box to the dashboard is expected and is **not** a reversal of this decision.

*Owner veto is cheap:* if you'd rather Phase 7 ship the query + result-row **only** (no screen) and
defer all surfacing to Phase 8, say so — nothing else in this contract depends on the screen existing.

## Interaction Contracts (the executor must honour)

1. **All colours via tokens** — the off-limits marker and the AI-unconfirmed badge use
   `border`/`borderStrong`/`textSecondary`/`accent`, never a raw "private" or "provisional" hue.
   `check:colors` must stay green. No net-new token this phase.
2. **`off_limits` is never glanceable, by construction** — excluded **in the query** that feeds the
   ranked projection and the search results, never merely hidden in the UI. The visual "private"
   marker is reinforcement, not the mechanism. `off_limits` is also absent from the AI resolver's
   search space (dossier Cluster E) — a data guarantee outside this UI contract but stated so the
   surface never implies otherwise.
3. **No network on any read path** — fuel text, age, ranking, and search are all local SQLite. The AI
   seam (proposing items, sending confirmed fuel) is a separate, explicitly-invoked path owned by the
   AI phase; this phase renders the `source='ai'` state but originates no network call.
4. **Local wall-clock dates only** — age uses `localDateTime`/`formatLocalDate`, never
   `toISOString().split('T')[0]` (CLAUDE.md).
5. **Fuel text is plain text** — no markdown parse/render; `kind` + `label` carry structure.
6. **Kind default is `topic`** on add (never `off_limits`, never transmitted) — load-bearing because
   share-sheet capture writes before the user classifies.
7. **Delete is permanent** — behind the `Alert` confirm, non-undoable; the DAO delete removes the row
   (and any future `field_history`/snapshot behaviour is a planning detail, not a UI concern here).
8. **Portrait-locked** — both the profile and the search screen are portrait; add no rotation handling.
9. **The ranked projection is written once and reused** — the profile strip, card, notification, and
   widget all consume the same query output; do not compute a second ranking in the UI.
