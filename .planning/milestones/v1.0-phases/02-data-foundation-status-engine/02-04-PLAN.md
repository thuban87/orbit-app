<objective>
Build the query-time status engine (DATA-05): status and continuous progress are computed in the
SELECT from `date('now','localtime')` and `interval_days` and NEVER stored. The three buckets
(stable/wobble/decay at 0.8/1.0) are a view over one continuous quantity elapsed÷interval; `rogue` is
a 4th threshold (>= ROGUE_K × interval) OR the "Rarely responds" non-time path. Ship the dashboard
status scan (never-contacted + archived excluded) and the newest-interaction-per-contact query that
Plan 06 benchmarks.

Reuse, do not re-derive: the 80%/100% thresholds already live in `src/types.ts calculateStatus()`, so
`status.ts` keeps ONE shared constant set to prevent drift, and the plugin's `statusOrder` sort
extends with `rogue`. Export all SQL as string constants so it is testable node-side and never rots as
a stored value.

Purpose: the same number that drives dashboard sort and (later) orrery angle, derived-never-stored.
Output: `src/db/status.ts`, `src/db/queries.ts`, and their tests.
</objective>
