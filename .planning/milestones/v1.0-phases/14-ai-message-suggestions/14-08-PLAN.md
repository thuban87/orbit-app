<objective>
Replace the raw provider catalog in the model picker with a curated, bundled frontier chat-model list per provider, so the default UX needs no API key and can never offer a dead or non-chat model. Keep dynamic discovery and free-text as advanced escape hatches, filtered to the same frontier set.

Purpose: close the 14-06 device-UAT model-handling gap — discovery listed deprecated (`gemini-2.5-flash`/`-flash-lite` → 404 "no longer available to new users") and irrelevant (tts/image/embedding/robotics/lyria) models, and required a key just to see any list.
Output: a node-tested bundled model registry + frontier filter, wired into the pure settings logic and the Settings AI section, with a device re-UAT proving the picker shows only frontier models with no key needed.
</objective>

<design_decisions>
Owner reviewed these defaults and said to proceed; they are ENCODED below. Redline any before execution — each names its alternative.

- **D-01 — Bundled curated list is the default picker (no network, no key).** The frontier chat models per provider ship as in-app TypeScript data. Local-first: the default list path makes zero network calls. *Alternative (rejected):* dynamic-only discovery — requires a key just to see models and, per UAT, still lists dead/irrelevant ones.
- **D-02 — Curation is the only reliable way to hide deprecated models.** Provider `listModels` metadata does NOT flag deprecation (the API returns `gemini-2.5-flash` with no dead marker, yet generateContent 404s), so runtime filtering alone cannot hide it. The curated allowlist is authoritative for what the picker shows. *Alternative (rejected):* filter the raw catalog at runtime — cannot detect a deprecated-but-still-listed model.
- **D-03 — Curated chips are the DEFAULT; Discover + free-text move to an "Advanced" affordance.** *Alternative (rejected):* keep Discover as the primary path (today's behavior) — key-gated and shows the junk.
- **D-04 — Discover results are FILTERED to the frontier chat set; free-text stays as the escape hatch.** Discovery (advanced, key-gated) intersects/aligns its results with the curated frontier and drops non-chat families; any model not in the curated set is still reachable via free-text so no legitimate model is permanently hidden. *Alternative (rejected):* show raw discovery results.
- **D-05 — Frontier scope = Flash / Flash-Lite / Pro-class per provider** (Gemini, OpenAI, Anthropic). Custom stays free-text only (unchanged — C4-M1). *Alternative (rejected):* full catalog.
- **D-06 — Exact current model IDs are VERIFIED at execution time against each provider's live/official current model list, not hardcoded from the planner's guess.** The registry is structured so updating is a single-list edit; the owner's device re-UAT (real keys) confirms each pinned model returns a draft (no 404). *Alternative (rejected):* bake planner-guessed IDs as final — `gemini-2.5-flash` was already dead by UAT time.
</design_decisions>

## Trust Boundaries

| Boundary | Description |
|---|---|
| bundled model registry → picker UI | In-app static data drives which model ids the user can select; it must never introduce a network read on the default path. |
| discovered id list → picker UI | Key-gated discovery results are advisory input filtered before display; they must not widen egress or leak the key. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-14-20 | Denial of service | curated registry drift | low | mitigate | Ids verified against live provider docs at execution time (D-06); "-latest"/alias ids preferred; free-text escape hatch; single-array edit to refresh. A stale id degrades to a user-visible "Couldn't draft" and a free-text retry, never a crash. |
| T-14-21 | Information disclosure | default model list path | low | mitigate | The bundled default list is pure static data with no `fetch`/I/O import (test + read-verified) — local-first; no key is needed or transmitted to see models. Discovery stays the existing key-gated advisory path; this plan only FILTERS its results, adding no new egress. |
| T-14-SC | Tampering | package installs | n/a | accept | No npm/pip/cargo install — the registry is in-repo TypeScript data and the filter is pure TS. No package-legitimacy checkpoint required for this plan. |

Security note: this plan changes ONLY which model ids are offered. It does not touch the native egress guard, the closed PromptContext allowlist, key storage (SecureStore), or any transport/redirect control. No security control is weakened.
