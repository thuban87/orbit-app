# Phase 18.1 — Contact Method Normalization: Context

Phase 18.1 is the **data-layer half** of the original Phase 18: normalize phone/email into
first-class contact methods with stable identity, per-type primaries, ordering, extensions, and
system-contact provenance foundations. It ships the **v9 data-bearing migration** and retires the
scalar `contacts.phone`/`contacts.email` columns. **All contacts remain Bound** — the Bound/Unbound
lifecycle is Phase 18.2. Streamlined Export is deferred out of the phase entirely.

## Authoritative product source

`docs/dossier/18-contact-data-normalization.md` — **read in full.** The clusters that govern 18.1:
- **A–F** — contact method types, primaries/ordering, duplicate semantics, phone/email
  normalization and validation, interaction-granularity boundaries.
- **O** — contact method schema migration (retire scalar columns; one source of truth).
- **P, Q** — system-contact linkage foundation and non-destructive refresh intent (structural
  provenance only; no picker/import UI — that is Phase 19).
- **R (method half only)** — lossless backup/restore round-trips the normalized method model.
  (The Bound/Unbound-state half of R, and the Streamlined Export bullet, are 18.2 / deferred.)

Clusters **G–N and S** (lifecycle, nullable cadence, Unbound screen, Never Contacted, favourites,
notifications/birthdays, AI, widget) govern **Phase 18.2**, not 18.1 — but reading them is useful to
understand what the 18.1 schema must leave room for.

## Migration boundary (Option A)

18.1 ships **v9** (`009-contact-method-normalization`): the data-bearing contacts rebuild that moves
scalar phone/email into normalized method/link/provenance rows. `interval_days` **stays NOT NULL**;
no `tracking_enabled` column; only `phone_region_override` is added to `app_settings`. The
nullable-cadence / lifecycle schema (v10) belongs to Phase 18.2 (`18.2-01`). This isolates the one
irreversible data-transform so it can be verified on-device in isolation before lifecycle work.
