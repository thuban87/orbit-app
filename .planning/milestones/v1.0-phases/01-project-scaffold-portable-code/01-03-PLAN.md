<interfaces>
<!-- Contracts this plan defines. Downstream plans (and App.tsx) consume these. -->
The theme module must export at least:
- `ThemeMode = "light" | "dark" | "system"` and `ResolvedMode = "light" | "dark"`
- `SystemScheme = "light" | "dark" | "unspecified" | null | undefined` — a LOCAL union declared in `theme-types.ts` that mirrors React Native's `ColorSchemeName | null` WITHOUT importing react-native (so the resolver stays node-testable). It is a SUPERSET of `ColorSchemeName`, so `useColorScheme()`'s return is always assignable to it. (Executor: confirm the installed RN's `ColorSchemeName` members against `node_modules/react-native/Libraries/Utilities/Appearance.d.ts` — RN 0.86 returns `'light' | 'dark' | 'unspecified'` — and ensure this local union remains a superset.)
- `interface ThemePalette { background; surface; surfaceElevated; accent; textPrimary; textSecondary; border; borderStrong }` (all `string`)
- `THEME_PRESETS: Record<ThemePresetId, ThemePreset>` where a `ThemePreset` carries at least a `dark` palette
- `resolveMode(mode: ThemeMode, systemScheme: SystemScheme): ResolvedMode` — PURE (no react-native import); when `mode` is `"system"`, ANY scheme value other than `"light"` (`"dark"`, `"unspecified"`, `null`, `undefined`) resolves to `"dark"` — the dark default. Param typed `SystemScheme` (NOT the narrower `"light" | "dark" | null`), so passing `useColorScheme()` in typechecks (`useColorScheme()` returns `ColorSchemeName`, whose `"unspecified"` member the narrower type rejected → TS2345). Logic form: `mode === "system" ? (systemScheme === "light" ? "light" : "dark") : mode`.
- `resolvePalette(presetId: ThemePresetId, mode: ResolvedMode): ThemePalette` — PURE; returns `preset[mode]` and FALLS BACK to `preset.dark` when that mode's palette is absent (this phase ships only a dark palette, so `resolvePalette(id, "light")` deterministically returns the dark palette — `"light"`/`"system"` are DEFINED, not undefined)
- `ThemeProvider(props: { children }): JSX.Element` — subscribes to `useThemeStore` for `mode`/`presetId`, calls `useColorScheme()` (react-native) for the OS scheme, computes the palette via `resolveMode` + `resolvePalette`, and provides it. It takes no palette props — the store is the source of truth so rehydration restyles the tree.
- `useTheme(): ResolvedTheme` — returns `{ colors: ThemePalette; mode: ResolvedMode }`; when called outside a provider it resolves the default preset's dark palette (never returns null, never a bare hex)
- `src/theme/index.ts` — a BARREL re-exporting the public theme API (`ThemeProvider`, `useTheme`, `ThemeContext`, and the types/presets) so the `@/theme` specifier resolves (the `@/*` alias maps `@/theme` to `src/theme`, which needs an `index.ts` entry — App.tsx imports `ThemeProvider` from `@/theme`).
The store must export `useThemeStore` (Zustand) persisted under the key `orbit-theme`, holding `mode`/`presetId` + setters.
</interfaces>
