# Bundled font assets — provenance & license

Every font shipped in `assets/` is bundled locally (no CDN / network font
delivery — local-first, dossier §E). All three are licensed under the **SIL Open
Font License 1.1** (SIL OFL 1.1), which permits bundling and redistribution
inside an application.

| File | Family / Weight | Version | Source | License |
|------|-----------------|---------|--------|---------|
| `Inter-Regular.ttf` | Inter — Regular (400) | 3.019 | The Inter Project Authors — github.com/rsms/inter (static TTF via `@expo-google-fonts/inter`, `Inter_400Regular.ttf`) | SIL OFL 1.1 |
| `Inter-SemiBold.ttf` | Inter — SemiBold (600) | 4.000 | The Inter Project Authors — github.com/rsms/inter v4.0 release | SIL OFL 1.1 |
| `SpaceGrotesk-SemiBold.ttf` | Space Grotesk — SemiBold (600) | 2.x | The Space Grotesk Project Authors — github.com/floriankarsten/space-grotesk (static TTF via `@expo-google-fonts/space-grotesk`, `SpaceGrotesk_600SemiBold.ttf`) | SIL OFL 1.1 |

Notes:

- `Inter-Regular.ttf` (v3.019) and `Inter-SemiBold.ttf` (v4.000) are the same
  typeface family from different upstream releases; the minor metric difference
  between the two weights is acceptable for this primitives phase and is
  owner-retunable (both are SIL OFL 1.1 Inter statics).
- These TTFs feed the RN `<Text>` pipeline via `src/theme/fonts.ts`
  (`expo-font` `loadAsync`, folded into the `App.tsx` boot ready gate). The Skia
  Orrery font pipeline (`useFonts`) is a separate system and also consumes
  `Inter-SemiBold.ttf`.
- No `.ttf` here is delivered over the network at runtime; fonts load from the
  bundled asset only.

## App icon provenance

The launcher and About artwork is **owner-supplied** Orbit art (RG-041
`release-readiness/AUD-REL-003`, owner rulings D-08 / D-21, Phase 38.4). It is
never redrawn, recoloured or hand-edited; the only processing is a geometric
safe-zone fit done by a committed script.

| File | Role | Origin |
|------|------|--------|
| `orbit-icon-foreground.png` | Source for the adaptive foreground | Owner-supplied 2026-09-26, 1254×1254 RGBA, commit `6e7f4e4` |
| `orbit-icon-monochrome.png` | Source for the themed-icon (monochrome) layer | Owner-supplied 2026-09-26, 1254×1254 RGBA, commit `6e7f4e4` |
| `orbit-icon-legacy.png` | `expo.icon` (legacy/round launcher icon, API < 26) and the About screen image | Owner-supplied 2026-09-26, 1254×1254 RGBA, commit `6e7f4e4`; used unmodified (transparent corners kept) |
| `orbit-icon-foreground-adaptive.png` | `android.adaptiveIcon.foregroundImage` | **Derived** — 1024×1024 RGBA, generated by `scripts/fit-launcher-icons.py` |
| `orbit-icon-monochrome-adaptive.png` | `android.adaptiveIcon.monochromeImage` | **Derived** — 1024×1024 RGBA, generated by `scripts/fit-launcher-icons.py` |

Why derivatives exist: Expo's prebuild resizes the adaptive foreground and
monochrome layers edge-to-edge to Android's 108dp layer with no padding, while
launcher masks only guarantee the inner 66dp safe zone. The script scales each
source so its furthest opaque pixel sits at `MARGIN` (currently **0.95**) of the
safe-zone radius, centred on a transparent canvas.

- Regenerate: `python3 scripts/fit-launcher-icons.py`
- Verify the committed derivatives match a fresh run and stay inside the safe
  zone: `python3 scripts/fit-launcher-icons.py --check`
- Tunables (`OUT_SIZE`, `SAFE_ZONE_RATIO`, `MARGIN`, `ALPHA_THRESHOLD`) sit at
  the top of the script; change `MARGIN` there, regenerate, and commit both
  derivatives together.
- The adaptive **background** is a solid colour, not an image:
  `android.adaptiveIcon.backgroundColor` = `#1A2F8A` (Deep royal) in `app.json`.
- **Splash art is not supplied.** `splash-icon.png` (and the web `favicon.png`)
  are untouched Expo scaffold files and out of scope (D-08).
